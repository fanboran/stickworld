## ⚠️ 渲染环境关键发现（批次 2/3/5 必读）

- **Polygon2D 的 uv 纹理采样在本环境坍缩为纹理平均色**（整面平涂、无笔触）。已排除：uv 越界、seed、filter、纹理内容、4/6 点几何、新建节点——均无效；`texture=null` 显示 vertex color、`make_solid` 显示纯色（即 uv 常数化）。Sprite2D 路径采样完全正常。**坍缩含 alpha 平均**：straw_thatch 稀疏笔触纹理平均后 alpha 极低（后墙几乎隐形）；thatch_layered 同走 Polygon2D 却可见（批次 4 已把三栋标准外壳的 BackWallTop 统一换 thatch_layered + 提亮乘色 `_backwall_tint()`，见 building_exterior.gd）。
- **绕过方案（已落地于 smithy_lv1）**：`smithy_lv1.gd` 的 `_make_slope_thatch_tex()`——按坡面梯形/平行四边形逐行裁剪 layered 茅草图、坡外透明，Sprite2D 显示；`RoofMain/RoofLeftGroup1` 已 visible=false 由 RoofRightSlope/RoofLeftSlope 顶替。**坡面 mask 边界必须与原 Polygon2D 几何一致**，否则盖住烟囱前桁架（第 3 轮评审的回归教训：底行右缘收进后桁架才可见）。
- **茅草纹理用 `TextureGenAPI.make_thatch_layered(w,h,seed)`**（层叠茅草束，自带金色系配色），不要用 `make_straw_thatch`（笔触太弱近似平涂）；seed 决定行色序列。原色偏暗，Polygon2D 大面使用需 >1 的提亮 self_modulate 才可读。
- **`--script` 模式 `_ready` 时序陷阱（批次 4 踩坑）**：`SceneTree._initialize()` 上下文里 root 尚未进树，`add_child` 的子节点 `_ready`（@tool 程序化装配）延迟到首帧；此时同步 `call()` 依赖装配结果的方法会全部落空（症状：首栋渲染裸壳 + `Tween started with no Tweeners`）。修复：add_child 后先 `await process_frame` 再驱动状态（见 render_interior.gd 注释；render_smithy.gd 未踩坑是因为它 call 的 set_state 不依赖 _ready 产物）。
- **程序化建节点必须刷新基类成员引用**：`Building._lookup_children` 在 `_ready` 先跑，程序化 Interior 建立在其后——基类 `_interior` 成员若不手动刷新，`_set_transparent` 里 `Interior.visible` 切换被 null 守卫静默跳过（症状：进屋态 Interior 永不可见）。building_exterior.gd `_build_interior()` 已做 `_interior = interior` 刷新。
- **16 格标准外壳的后墙被左右屋顶坡完全遮挡**（外视角）——后墙纹理只有 smithy 这类异形坡面才露出；进屋态渲染图的"黑背景"是屋脊间空隙（夜景氛围），Interior 家具对比反而突出，不按缺陷处理。
- **视觉验收渲染工具**：`tools/baking/render_smithy.gd`（单栋外观）与 `tools/baking/render_interior.gd`（批次 4，四栋进屋态：`set_state(2)` + `_set_transparent(true)`，输出 `user://interior_render_<def_id>.png`）。`godot --path stick-world --script res://tools/baking/<脚本>.gd`，非 headless。注意：① 场景默认 PLANNED 态 alpha=0.3，验收图须 `set_state(2)` 切落成态；② `--script` 模式下别引用全局类名（class_name 解析不可靠，用 duck typing）；③ 改完 .gd 先 `--import` 再渲染，否则卡死。
- **测试编排**：`run_all.sh -Match` 是**子串匹配**不是正则，多目标要循环单跑。
- **Excel 管线漂移**：`export_excel.py` 是全量重导（18 表），仓库里 `config/formations/presets.tres` 存在手写旧版 vs Excel 管线版的漂移（重导必连带刷新它，批次 4 已还原不背书）——待数据表负责人收口。

## mega_interior 接线评估（批次 4 结论：本批次不实现）

`mega_interior.tscn`（`modules/world/scenes/maps/`）实为**空 VillageMap 骨架**：`village_map.gd` 脚本 + 全套空容器（PlacementGrid/BuildingHost/EntityHost 等）+ ExitTrigger（`mega_interior_exit_trigger.gd`），无任何室内内容。

**打通 interior_mode=2（TELEPORT）的链路现状**：
- 触发侧已实现：建筑 EnterTrigger → `building.gd _on_enter_trigger_body_entered` → `EventBus.mega_interior_entered`（EnterTrigger 节点场景件仍未建，机制同 InteractionZone 可程序化补）。
- 消费侧骨架已有：`travel_handler.gd` 订阅 mega_interior_entered/exited（game_root.gd:766 注释）。
- 缺口：①map_id → 场景的注册/查找路径；②mega_interior 地图的室内内容生成（对应建筑类型的布景+工位+出口）——**主要工作量在此**；③出入口回传坐标约定。

**结论**：不实现。interior_mode=1（TRANSPARENT）已满足"进屋可见内饰"P0 观感验收；TELEPORT 依赖旅行切换 + 室内地图内容管线，建议挂靠城镇生成线（B 线，可直接复用批次 4 的 `InteriorProps` 家具库布景）或单独开一个 Pro 批次。机制层约 70% 已存在，剩余估 1 个 Pro 批次量级。
