## 一、架构总览

**主循环序**（MapBox.cs:1809 updateSimulation，每帧未暂停）：

```
MapBox.updateSimulation
├─ updateCities / updateActors / updateBuildings ← 批次系统（JobManagerBase.updateBase）
│    批 = 256 Actor 的并行与容量单元；Pre → Parallel → Post 三桶依序跑
│    Actor Post 桶执行序（编号即序）：u8 计时器 → b1 外力 → b2 已有敌 → b3 找敌(5帧跳)
│      → b4 任务校验器 → b5 寻路移动 → b6_0 决策（事件容器）→ b6 AI 行为 → b55 自然死亡(20帧跳)
│    帧内标志级联：谁真正处理了该单位就让下游全部跳过——每单位每帧最多一个行为系统干活
├─ drop_manager.update（掉落物理）
├─ 元实体族 update（cultures/clans/subspecies/languages/religions/plots）
├─ armies.update；kingdoms.update（→每王国 updateCiv：timer_action 节流后 ai.update()）
├─ diplomacy.update（外交 tick 每 2s 一拍：重排霸主+成就检查）
└─ alliances / wars（War.update 每帧） / projectiles / statuses / era
```

**三桶调度**（BatchActors.cs / JobManagerBase.cs / Batch.cs）：Pre 无 job；Parallel（可跨批并行，只读/复位类：prepare/update_timers/update_visibility/update_stats）；Post 分 u1~u10 更新域与 b1~b6 行为域。跳帧不是固定节拍而是**跑完随机歇 `randint(0,N)` 帧**（真值三档 0/5/20），均值 N/2 天然去同步；决策与死亡走**事件容器**（c_make_decision/c_check_deaths，用后 Clear）；`Config.parallel_jobs_updater` 开启时 Parallel.ForEach 跨批多线程。

**五域谁持有谁**（文字图）：

```
World.world
├─ KingdomManager ── Kingdom（king 兼职 Actor + capital + cities[] + royal_clan 王室氏族 + past_rulers≤30）
│    └─ City（leader + army + warrior_slots 岗位配额 + capture 拉锯条）——功能单元（经济/建军/出击）
│       王国 = 身份聚合（外交/战争/文化），状态几乎全派生自城市
├─ DiplomacyManager ── DiplomacyRelation[无序对键]（双向 KingdomOpinion = 观感因子求和）
├─ WarManager ── War（main_attacker/defender 可重选 + died/past 历史名单 + WarWinner 5 态）
├─ AllianceManager ── Alliance；ArmyManager ── Army（captain 旗号组，无编制语义）
└─ PlotManager ── Plot（author 个人野心 + ≤15 支持者 + progress 酝酿条：宣战/结盟/叛乱全走此）
```

## 三、对照启示（WorldBox 做法 → 本项目落点/批次）

**L1 个体层**

1. **softmax 轮盘 + 探测成本控制 → A4**（default_behavior v2）：`e^w` 轮盘替代 if/elif 优先级链与 argmax，权重即软优先级；昂贵行为加 action_check_launch +「失败也入冷却」防反复试探抖动；过滤条件先聚合快照再逐条查；「负需求压主业」（饿时工作 2→0.3）写成权重调制委托而非阈值开关。
2. **决策冷却错峰假偏移 → A1/A9**：冷却按行为 index 挂世界时刻（读档零成本）；成批出生/读档时预置 `now − rand(0, 0.5cd)` 假上次触发时刻——兵营爆兵后全员同步决策的防齐套问题直接套用；等待=写 timer 冻结整段更新，不做每帧轮询。
3. **任务=数据 + 打断元标志 → 行为机重构候选**（A4 之后）：劳作任务统一「五段式动作序列资源」`[find_target, goto, animate×N, extract, deliver]`（送货尾巴做可复用子序列），不逐个建 BehaviorBase 子类；打断用 `interruptible_by` / `immune_to_combat_preempt` 元标志替代隐含硬序（战斗抢占保留为最高层硬规则，与 WorldBox 同构）；BehResult 协议留 RestartTask/StepBack/ImmediateRun 三态位；AI 让位链（外力>敌>找敌>校验>寻路，任务挂起断点续跑）作战斗抢占实现参照。

**L3 组织层**

4. **王位继承失败分支即内容 → 组织补位引擎**：王室→领袖→分家三级 fallback，每级都是事件化终局（改朝/新王/碎国）+ 5~20s 空位期 + 日志（logNewKing/logFracturedKingdom）；补位失败不是返回 filled=false，而是产出「组织解体/城市独立」内容事件。
5. **观感因子留痕 → 上报门控 / AI 决策面板**：好感度 = 具名因子逐项求和 + results 字典留痕，UI 能回答「为什么恨你」——决策依据可解释、权重热调、面板逐项展示，上报门控（组织系统架构 §4.4）与后续外交同构复用。
6. **城池攻占 = 拉锯条 → 出征与领地循环**：capture ticks 双方拉锯（守方战士+瞭望塔回拉、攻方累积、满值触发）取代踩点判定，后果链（守军复原/归属第三方/双向民心）一次配齐；占领≠吞并。
7. **兵源=岗位配额 → 游戏循环深化（兵营招兵）**：warrior_slots 由市民岗位表派生 + 出击七成满员门槛——对照本项目「岗位表决定可招兵数」，防零星送死。

**L4 战略层**

8. **开战判定链 → 出征 AI（A2+）**：休战年限 + 实力门槛（含盟）+ 内政余量三重闸全过才宣战；目标选择「打得过+够得着+记仇冷却」取最近者；宣战 plot 的「酝酿期+中止条件」质感可作 L3 出征决议的预热阶段（决策主体不照搬，见 §四反 Top2）。

**性能线（战斗规模化 30fps）**

9. **批次桶 + 空闲队列摊销 + 随机跳帧 → 30fps 待办 C**：决策走事件队列（行为栈空闲才排队 + 每帧消费上限）替代 1/N 固定轮转——排队长度自然等于闲置单位数，接战期决策量集中可控；低频系统 `randint(0,N)` 跳帧（真值 0/5/20）避免整批共振；帧内标志级联「动过即短路下游」（移动中单位不重决策）；批 256 + 跨批并行即 Godot 多线程平移粒度。

**物品/经济线**

10. **计数袋双轨制 → town-life / inventory**：NPC 携带与城市仓库走计数袋（ItemStack 聚合近似即可，免逐件实体虚增存档与 GC），逐件实体只留玩家侧与装备；装备槽 schema（自动入槽/同槽替换/cursed 锁槽/mod_type 词缀互斥/name_templates/pool_rate）作 ItemDef 深化预留。
11. **建造决策链 → town-gen / town-life**：城市 5s 决策拍 + 单工地钳制 + 声明式建造序列表（前提链递归过滤）+ 选址布局四模式（Moonsteps/醉步即布局参数化候选）——与 town-gen 风格参数化同构；注意其选单是均匀随机无效用加权（见 §四反 Top3）。

## 四、值得复刻 Top5 与不建议照搬 Top3

**Top1 softmax 轮盘效用选优**（UBDS + DecisionsLibrary）：CoH demand 之后第二家效用打分先例，且直接给出 127 条 weight 真值定标（保命 4~5 / 主业 2~3 / 习惯 0.5~1 / 闲逛 0.2）与 weight_calculate 委托范式。→ A4 头号参照。
**Top2 决策冷却错峰系统**：读档/成批出生预置假偏移是独有巧思，比随机扰动更「物理」。→ A1/A9。
**Top3 观感因子求和留痕**（KingdomOpinion/OpinionLibrary 20 因子全资产化）：可解释决策的最低成本实现。→ 上报门控/AI 决策面板。
**Top4 继承 fallback 链 + 分家终局**（KingdomBehCheckKing）：补位失败分支本身就是内容，组织存续事件链完整（继承/叛乱/占领/改朝全有事件与日志）。→ 组织补位引擎。
**Top5 批次桶三件套**（事件容器 + 随机跳帧 + 标志级联）：单线程下把调度成本削成近似 O(单位数)。→ 30fps 线。

**反 Top1 NeuroLayer 跳层机制——文档与实现不符**：设计字段 `chance_to_go_to_next_layer` 0.3/0.2/0.1（NeuralLayerLibrary.cs:11-42）**全工程无读取点，是死数据**；真实现 = 硬编码 80% 只看最高层 / 20% 全量两层随机（跳层掷骰 × softmax 轮盘叠加，不可解释、难单测），且例外规则在打补丁（战士带攻城令强制、critical 层注册强制）。作者自己都弃用了「层递进」直觉——本项目行为集小，softmax 全量打分 + personality.demand_variance 单旋钮即可，不引入优先层。
**反 Top2 宣战/结盟=个体 Plot 无国家决策层**：外交本质是国王个人野心情节（攒进度条替你宣战），国家无意图状态、盟友被动裹挟——服务于沙盒看戏。本项目是玩家**指挥**组织的大战略，出征决议必须挂 L3 指挥链、可被玩家覆写；只取「酝酿期+中止条件」作预热阶段。
**反 Top3 建造均匀随机选单 + 军队无编制协同**：CityBehBuild 选单 `GetRandom()` 均匀随机无效用加权（大城会出违和建设）；Army 无行军命令、战士各自轮询目标区（规模化下散乱）——两者恰是本项目 L3 指挥链 / 计划层存在的理由，不可向其退化。
