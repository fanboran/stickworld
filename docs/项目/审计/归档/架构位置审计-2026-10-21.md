## 一、文件放错模块

### 1-1 core/entities 混入两个非快照逻辑件 【低】
- **证据**：`stick-world/core/entities/world_contract_initializer.gd`（265 行：worldgen 真源 JSON/bin 全量装载编排、档位/人口推导规则）；`stick-world/core/entities/world_state_serializer.gd`（361 行：八域字段级编解码）。
- **复核**：AGENTS.md 定义 core/entities =「核心实体状态快照（RefCounted）」。这两个是初始器/序列化器（行为件），非状态快照；消费方 = `core/autoload/world_state.gd:94,421-428` 与 `modules/organization/scripts/organization_manager.gd:35`（L2→core 方向合法）。
- **影响**：目录语义与内容不符，新人找"快照定义"会翻到装载逻辑；无依赖方向问题。
- **建议**：二选一——迁 `core/services/`（服务语义）并同步 AGENTS.md 口径；或维持现状、AGENTS.md 的 core/entities 描述改为"快照 + 世界模型契约编解码"。

### 1-2 武器动画音效桥挂在 world 模块根 【低】
- **证据**：`stick-world/modules/world/scripts/weapon_anim_sfx_bridge.gd`——订阅 units `WeaponMount.weapon_anim_event` 转发 `AudioManager.play_event`，自述按 `docs/技术/音频/音效触发规范.md` §10.3/§12.2 设计（自愈桥，Spine 源补数据后自动静默）。
- **复核**：桥本体是"音频域服务"而非场景图容器职责；放 world 的好处是 L3 能同时见到 units 信号与 AudioManager。文档有交代，非违规。
- **影响**：world/scripts 根目录混入一条跨域音频链路；Spine 源补上 Sound 数据后该文件即成死代码，无人记得删。
- **建议**：随 weapon-mount-split 分支落地后复核——若保留则移 `core/services/`（音频族与 audio_manager 同域）或 units；并在文件头补"退役条件"提示（已有自愈说明，补一句删除时点即可）。随 weapon-mount-split 分支变动。

### 1-3 其余疑点复核后排除（记录口径）
机器频谱扫描（他模块 class_name 引用强度 > 本模块）54 个候选中：ui_global 词高频的 ~20 个 UI 面板 = 合法 L2→L1 控件消费；construction→building_gen、units→combat/tactics/player_control、hd2d→environment/stick_rig = 文档化在册边；`damage_pipeline.gd`/`battle_sim.gd`（combat）与 `stickman_anims.gd`/`hd2d_world.gd`/`garrison_spawner.gd` 的他模块词命中经逐条核对均为**注释级引用**，非代码边。

## 三、分层违规

### 3-1 L1→L3 上行：environment → GameRoot 【中】
即 §2-4 同一事实的分层视角：environment（L1 基础设施）持有对 world（L3 组装根）的运行时上行依赖。修复同一提案（注入代替上行查找）。

### 3-2 共享词汇沉在 L2 迫使同等 L2 复制 【中（结构性）】
- **证据**：建筑落位基线的 duck 回退链权威 = `stick-world/modules/construction/scripts/placement/placement_metrics.gd`（`:22-23` 自述"真值源 = Hd2dMapBase.building_baseline_offset = 96.0"）；consumption 方 `construction_manager.gd:629`、`construction_project.gd:344` 均已收敛至此。而 `stick-world/modules/units/scripts/entity/interaction_controller.gd:260-266` `_map_building_baseline` 因 units 无出向 construction 边（不能 preload 他模块内部件）复制了同款回退链（硬编码 `96.0`/`810.0` 兜底）。
- **对照**：这正是 AR-2（world⇄world_map 共享词汇下沉 core/shared）的同构问题——placement_metrics 实为 units/construction 双消费者的共享词汇，却放在其中一个消费者的内部。
- **影响**：两处兜底数值（96.0/810.0 与 placement_metrics 的 fallback）已各自硬编码，换轨改参时会漏改 units 侧。
- **建议**：placement_metrics 下沉 `core/shared/`（或 tactics 式零出向词汇模块），units 删本地副本改引下沉件；与 AR-2 同批处理可共用机制。

### 3-3 合规结论（零命中记录）
core/*.gd 无任何 `res://modules/` 引用（扫描零命中）；L1 八模块无出向 L2 的代码边（hd2d→units、items/ui_global/fx/stick_rig 全零出向，与在册边表一致）；combat/battle_sim 与 damage_pipeline 的 units 词汇全为注释。`organization→world`、`world_map→world` 上行属在册容忍环，`expansion→world` 为同模式第 3 例（audit_deps 在册，文档未记 → 见 6-1）。

## 五、死代码/孤儿

> 方法学：按文件名 stem + class_name 双口径在全语料（.gd/.tscn/.tres/.godot/.cfg/.py/.sh）中查引用，零命中者逐条人工复核。tests/dev 与 tools/ 的零引用脚本多为 `godot --script` 手动运行的诊断/烘焙 CLI（文件头自述运行方式），**不算死代码**，已剔除。

### 5-1 tests/unit 46 个孤儿 .tscn + 清单自检盲区 【中】
- **证据**：`stick-world/tests/unit/` 下 76 个 .gd 配 46 个 .tscn（一一对应、无坏对）；运行真相 = `tests/batch_runner.gd` 的 UNIT_SCRIPTS 清单只跑 .gd（入口 `batch_runner.tscn`）；`tests/run_all.sh` 的 manifest_check 只扫 integration/smoke 目录（脚本注释自认"tests/unit 层的同类问题由 batch_runner 自检负责"，而 batch_runner 自检并不看 tscn）；`tests/README.md:59` 仍在教 `res://tests/unit/test_xxx.tscn` 手工跑法。
- **对照先例**：即 test_ai_morale 孤儿 tscn 挂死案的同型放大版（该案已清，此处余 46 个）。
- **影响**：46 个场景永不入自动跑批；若某 .gd 改为不再兼容场景挂载（如改构造签名），对应 tscn 静默挂死且无门禁拦截。
- **建议**：整批删除 46 个 tscn（batch_runner 是唯一入口），同步 tests/README.md:59 的手工跑法段；或反向补齐——manifest_check 纳入 unit 目录。删后校验 `git grep "\.tscn" tests/batch_runner.gd` 无引用即可。
