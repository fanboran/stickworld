## 〇、创始人已拍板的方向（设计基线，全部小节须贴合）

1. **按职位独立训练、独立计分**：最高指挥官计分与整场比赛胜利相关；下辖职位的计分跟执行上级命令的完成程度相关；不同任务的完成程度有不同的计分方式（排长任务 = 攻击敌某排/牵制敌某排的完成度，班长任务 = 火力组级细分命令的执行效果，士兵 = 执行分）。
2. **编制层级**：班 = 班长 + 两个火力组（火力组为最小指挥单元）；排长给各班下发不同任务目标；班长以火力组为单位细分（「一号火力组攻击 X、二号火力组攻击 Y、某人绕后斩首、其余跟随自己」）。
3. **课程从 1v1 开始**：双方各一名士兵 + 后方指挥官的定制小场景起步，先在只有几个火柴人的定制场景训练专项行为，再逐级扩编（火力组 → 班 → 排）。
4. **战场范围限定为一屏大小**。
5. **命令有粘性**：不高频翻改（v2 实测号令翻转 48~289 次/分钟是反面教材，目标 <20）。
6. **移动语义**：跟随 = 掉队超距一次性归队（已实装）；无简单绕路时攻击拦路敌人（RTS 口径，待实装）。

## 一、编制与职位模型

### 1.1 编制（是什么）

| 层 | 构成 | 指挥关系 | 现状 |
| --- | --- | --- | --- |
| 指挥官（rank 3） | 每军 1 名，后方留守 | 给排长下发任务 | v2 已有独立实体语义（±1780 后方、可被打、被斩即判负），v3 沿用 |
| 排（rank 2 排长） | 2~3 个班 + 排长 1 名 | 给各班下发**不同**任务目标 | `formation_system.create_platoon / assign_platoon_leader` 已有；排长阵亡 = 指挥链缺口到战斗结束 |
| 班（rank 1 班长） | 班长 + **两个火力组** | 以火力组为单位细分命令，可对个体下特令 | 班 8~12 人（硬顶 15）、班长阵亡组织侧免费轮转——已有；**火力组是 v3 新增层** |
| 火力组 | 4~5 名士兵【提案/待定】 | 最小指挥单元：号令以火力组为单位下发 | 游戏侧地基已落：`FormationSystem` 火力组 API（create_fireteam / get_squad_fireteams / get_fireteam_units 等组寻址，不动组织树）+ `TacticalOrders.issue` 对 ft_id 寻址（契约见 formation/api.gd）；训练件本身待实施 |
| 士兵（rank 0） | — | 执行火力组任务；个体可被班长点将特遣 | 已有 |

火力组只是班内**指挥分组**，不是组织树节点、不是编制实体：班长细分命令时按「一号火力组 / 二号火力组」寻址，组的成员划分由班长动作指定（默认对半分），战斗中组随成员阵亡收缩、不重组不跳槽。为什么这样定：火力组是命令的粒度而不是行政的单位，挂组织树会把班长免费轮转、排长缺口这些既有语义复杂化；只在 formation 侧加一个 `squad_id -> fire_teams` 映射即可支撑号令寻址与计分归组。【提案/待定】

### 1.2 职位 × 网络（怎么训）

每个职位一个网络，全项目恒定四网：

| 职位 | 网络 | 管什么 |
| --- | --- | --- |
| 指挥官 | 网络C | 全局态势 → 给每个排下发任务 |
| 排长 | 网络P | 本排态势 + 上级任务 → 给每个班下发任务 |
| 班长 | 网络L | 本班 + 火力组状态 + 班任务 → 给两个火力组细分 + 个体特令 |
| 士兵 | 网络S | 局部态势 + 组任务 → 低层战斗执行 |

同一网络在双方镜像复用（v2 自视角镜像手法继承）：faction 1 天然从左往右打，faction 2 观察取镜像，双方同一套四网即层级自博弈。训练按职位独立计分、按职位归口梯度（§四），但**同侧四网联合成队参赛**——赢了算全队的，账分开记。

## 二、任务词汇表（Task Vocabulary）

这是 v3 的地基：层级间只准用这套原子语言下达任务，每个原子带一个**可度量**的完成度函数 D∈[0,1]，D 就是排长/班长计分的直接来源。词汇必须小而完备——每个原子都能翻译成 TacticalOrders 既有号令 + 行为参数，不新造行为语义。

**词汇总表**（前六项为创始人点名的核心词汇；后两项为【提案/待定】扩展）：

| 原子 | 参数 | 适用下发层级 | 完成度定义（可度量） |
| --- | --- | --- | --- |
| **攻击** | 目标 = 敌方单位群（排/班/火力组/个体） | 指挥官→排 / 排→班 / 班长→火力组 | D = 目标群歼灭率（已击杀数 ÷ 任务下发时目标群存活数）；目标全灭 D=1；战斗结束未全灭按当前值计，超时限未达成再乘时限折减系数【提案/待定】 |
| **牵制** | 目标敌群 + 要害（己方旗/己方单位群） | 排→班为主，指挥官→排可用 | D = 牵制有效时间占比 × 要害保全（0/1）。「有效」= 目标群内任一成员与己方牵制兵力处于接战距离内、或处于被压制态——即该敌群这个时段没有自由机动。要害失守（旗易主/被护单位死亡）当期清零【提案/待定：有效判定距离取敌主武器射程 +100px】 |
| **绕后斩首** | 目标 = 敌高价值个体（指挥官/排长/班长） | 班长→个体特遣为主 | D = 目标被击杀 ? 1 : 目标血量削减率 × 0.5；特遣者提前阵亡按届时进度计。为什么班长层才有：绕后斩首是火力组级细分的典型个体特令（创始人举例原话），排以上只下「攻击」不下「斩首」 |
| **跟随** | 锚点 = 班长或指定单位 | 班长→火力组/其余成员 | D = 成员在锚点归队滞回带内的时间占比（带内 = 距锚 ≤ SETTLE_DIST 140px；超 JOIN_DIST 260px 计脱队）。**参数与 squad_cohesion 一次性归队状态机同源**——实机怎么判「掉队」，分数就怎么算 |
| **驻防** | 点 = 某旗/某坐标 + 半径 | 全层级可用 | D = 任务期间己方占据该点的时间占比（占据判定与 CapturePoint 同口径：半径内己方人数 > 敌方人数） |
| **夺点** | 点 = 某旗 | 指挥官→排 / 排→班 | D = 占领进度达成量（0~1，CapturePoint progress/100）× 0.5 + 后续己方占有时间占比 × 0.5——既要拿下来也要拿住 |
| 推进【提案/待定】 | 线/区域 | 排→班 | D = 时限内到达率（到达成员占比）；用于无旗小场景的机动专项 |
| 拦截【提案/待定】 | 目标机动敌群 + 拦截线 | 指挥官→排 / 排→班 | D = 目标群在到达其目标前被交战 ? 1 : 其推进路程被压缩的比例 |

**词汇纪律**：

- 每条任务 = 原子 + 参数，一次下发一个原子；班长对火力组的「细分」= 两个火力组各一条 + 至多一条个体特令（创始人举例结构：一号攻 X、二号攻 Y、某人绕后斩首、其余跟随自己——即 2 组任务 + 1 特令 + 缺省跟随）。
- 任务完成度按节拍累积增量（ΔD per 0.5s beat），任务被改向时旧任务 D 冻结入账、新任务重开——这是命令粘性（§四.4）与信用分配（§四.5）的共同地基。
- 词汇的翻译层：原子 → `TacticalOrders.OrderType`（ADVANCE_ALL / HOLD_POSITION / RETREAT / …）+ 目标点，映射表固定在环境侧，网络永远不直接碰号令类型。

## 四、计分函数族与信用分配

### 4.1 三族分数（是什么）

**胜局分（指挥官）**——只与整场比赛胜负相关：
`R_C = ±1 胜负主项 + 小权重态势项`。态势项继承 v2 已验证口径（存活比差、旗数差，全差分零和），权重保持在胜负主项的 20% 量级、只作塑形不盖过胜负【提案/待定：±1 + 0.2×存活比差 + 0.5×旗数差/3 直接继承 v2】。斩首终局即胜负主项立即结算（v2 语义）。

**任务完成度分（排长 / 班长）**——跟执行上级命令的完成程度相关，按任务类型用 §二词表的对应 D 函数：
- 排长总分 = 其从指挥官领到的任务 D（多任务加权平均）；「攻击敌某排」用歼灭率、「牵制敌某排」用黏住时间占比 × 要害保全——**不同任务不同函数，不做统一标量**（创始人原话口径）。
- 班长总分 = 其从排长领到的任务 D + 火力组级细分的执行效果项（两个火力组各自任务 D 的均值）。细分的执行效果单独入账的原因：班长可能领到对的任务但细分拆烂（比如牵制任务拆成两个组都去攻），这一项就是专门抓「拆得对不对」的。
- 小权重生存项（自身存活比）防送头【提案/待定】。

**执行分（士兵）**——三件【提案/待定，权重待训】：
1. 任务贴合：在组任务目标作用半径/滞回带内的时间占比；攻击类任务加「交战对象属于指定目标群」的占比；
2. 交战效能：对指定目标群造成的伤害/击杀份额；
3. 纪律：脱队时间占比罚（超 JOIN_DIST 260px）、被压空转时间占比罚（轻罚——被压不是士兵的错，重罚会让网络学会躲压制判定而不是打仗）。

### 4.2 零和与归一（怎么算）

- 指挥官胜局分：成对零和差分（r_f1 + r_f2 = 0，v2 手法继承），优势跨批标准化。
- 排长/班长/士兵的完成度分：**绝对分不零和**——完成度是「对上级命令的完成程度」，与敌人强弱解耦；优势标准化按职位分批做（同职位全部轨迹一起归一），不同职位的分数不互比。
- 为什么这样分家：零和化下层职位分数会把「敌人太强」误记成「执行太差」，梯度噪声大；绝对完成度分天然是课程可读指标（0~1，人能看懂）。

### 4.3 信用分配：延迟结算怎么折算到任务完成度

- **任务窗增量回报**：完成度按 0.5s beat 累积 ΔD，职位网络的每拍即时奖励 = ΔD（+ 士兵的贴合/纪律小项）；终局把残余 D 一次性结清。信用随任务进度即时回流，不是等终局一锤子——这是把「延迟奖励」折算成「进度流」的核心手段。
- **信用挂职位不挂个体**：班长阵亡免费轮转（组织侧语义），任务与后续信用自动由接任者继承——因为网络本来就是按职位的，个体生死不产生归因问题。这是按职位分网的制度红利，v2 单网全军时不存在这个问题也不需要解决。
- **指挥链断口的信用处理**：排长阵亡 → 该排缺口、集火号令中断，排长网此后 ΔD=0（任务冻结），班长网的任务照算（班长对已领任务仍负责）；指挥官被斩 → 全局即时判负，胜局分结算，下层任务分同时冻结。断口时间越长下层分数越难看，压力自然传导到上游职位的生存策略，不需要人为设计「保护上级」的奖惩。
- **坏任务不牵连执行者**：完成度函数只度量结果；上级把任务下烂（比如让一个火力组去牵制一个排），下层的执行分仍按「是否尽力执行了这条任务」给分（贴合 + 效能），上层为烂任务在自己那份 D 和胜负里买单。执行分与任务 D 的相关系数作为诊断观测，持续为负说明词汇或判据设计有错【提案/待定】。

### 4.4 命令粘性（<20 次/min 怎么保证）

v2 反面教材：NN 每拍 argmax 直发，实测 48~289 次/min（规划器 9~49）。v3 四层防线：
1. **任务最短保持窗**：任务下发后 ≥4s（8 拍）不准翻改，除非任务对象已消亡【提案/待定】；
2. **连续确认拍**：继承 nn_brain 已实装的 `INTENT_CONFIRM_BEATS=2` 防抖——新任务连续两拍同值才切换；
3. **翻转罚**：保持窗内强行翻改（对象消亡除外）计入负奖励（小权重）；
4. **词汇本身低频**：完成度以秒/十秒计的任务原子天然不需要每拍重选，v2 的高频翻转部分是「每拍选方向意图」这个动作设计逼出来的。
每场记录各级翻转率，**<20 次/min 是硬门**（§五升级判据、§九验收共用）。

## 七、环境保真度契约

> v2 的教训写在 rl_core README「诚实预期」：紧凑 C++ env 无弹道/格挡/HITSTOP/击退/号令节流，episode 动力学与真实战斗存在保真度差；实机诊断进一步证明压制螺旋、号令风暴这些实机链动力学才是胜负的主导项。v3 契约：**凡是改变胜负或任务完成度的实机语义，训练环境必须建模；只改观感的才可以省**。训练宿主因此定为真实 Godot 链的定制小场景（§八），紧凑 C++ env 退出正式训练。

### 7.1 必须建模的实机语义

| 语义 | 实机锚点（已实装/已修） | v3 环境建模方式 | 简化的风险 |
| --- | --- | --- | --- |
| 压制→避战链 | 近失压制半径 45px、时长 4.5s（诊断 B1 后从 80px 收窄）；被压 → 脱离/寻掩，指挥官豁免（就近还击）；压制期间不掷撤退骰 | 真实链直接运行，零抽象。跟随/牵制任务的 D 判定要把被压态算进去（被压单位不构成「有效牵制」的反例要定清楚） | 若省略：v2 已付学费——紧凑 env 训出的策略在实机被「箭雨钉全场」支配，训练最优 ≠ 实机可行（停战螺旋） |
| 一次性归队 | squad_cohesion：距锚 >260px 触发一次归队、<140px 落定（滞回）+ 0.4s 节流 + 接战优先 | 跟随任务的完成度直接用同参数度量（§二词表），**参数单一真相源** | 参数不同步则「跟随」分数与实机行为脱钩，任务分变成另一个游戏的分数 |
| 箭单体碰撞 + y 换算 | Area2D 单体命中：横向 HIT_RADIUS 25.5px、纵向容差 25.5÷k（k=sin26°≈0.438）≈58px；散布在发射端（高斯）；人群拦截（诊断实测命中的 70% 打在非锁定目标）；连射热度；插身箭随宿主当前脚线零漂移（已修） | 真实弹道运行 | 若换成「命中率掷骰」：丢掉高弧落人堆误中旁人、前排挡箭这些结构性效应，弓兵的抵近/集火/射前排战术学不出来；且掷骰模型必须先过实机对拍校准门，否则是双重抽象 |
| 格挡 | 矛 blockChance 0.35 + blockResetInterval/BLOCK_COOLDOWN；billboard 渲染链断点已修，格挡真实生效 | 真实判定直接运行 | 简化为固定减伤 → 近战 TTK 失真，矛盾推进 vs 剑兵相克这类班级战术的价值被错估，班长细分学错 |
| 号令链路与节流 | TacticalOrders（ADVANCE/HOLD/RETREAT/…）+ 训练侧节流参数（漂移重发 80px / 6 拍刷新）+ nn_brain 确认拍防抖 | 训练环境与实机**同参**：v3 任务下发走同一翻译层与节流 | 环境里直发无节流 → 网络学会高频翻号，实机粘性层再把策略掐死，训练结果作废 |
| 攻击拦路敌人（**待实装**） | 实机现状：只有友军让路（entity_motion 9k 横向绕行），无「攻击拦路敌人」 | **契约条款：实机实装该语义之前，v3 的任务词汇与士兵动作不得依赖「穿人群/攻击拦路」**——课程场景用开阔布阵规避；实装后进本契约表 | 若训练环境先自造此语义：实机行为缺失，相关任务完成度在实机不可复现（与 v2 迁移差距同型的教训） |

### 7.2 可以简化的项（及残余风险）

| 项 | 简化方式 | 残余风险 |
| --- | --- | --- |
| HITSTOP 顿帧 / 击退 / 血溅 | 不建模（表现层） | 无——不影响决策统计量 |
| 指挥链投递延迟 | 一屏内按零延迟建模 | 一屏尺度延迟可忽略；扩编出屏时须重审 |
| 体力/冲刺 | 不建模，号令词汇不含 SPRINT | 低 |
| 士气 | 保留「压制触发避战」链；士气驱动的低士气脱战分支可关闭（profile 已是开关）——但关闭与否要在训练与实机**两边一致** | 两边不一致时避战频率失配，任务 D 系统性偏移 |

### 7.3 保真度验收门

训练环境上线前过一个「语义在场门」：定制场景里脚本注入钉子局（如「弓手对密集横阵放一轮齐射」），断言近失压制触发率、命中率、格挡触发率与实机诊断基准同量级【提案/待定：基准值取诊断报告实测区间】。这替换掉 v2 的「对拍门只对观察向量」——v3 对拍的是行为统计量。

## 八、训练循环与设施复用

### 8.1 层级自博弈的组织【提案/待定】

- **跨职位联合为主**：每轮迭代抽一套编制，正反两局成对（v2 手法继承）；同侧四网联合成队，梯度按职位各自归口（§四.2）。为什么不做「同职位对打」：指挥官的价值只能在完整指挥链里体现（排长把任务拆坏，指挥官再英明也输），拆开训会学到对「完美下属」过拟合的策略。
- **对手池按整队快照建**：快照 = 四网成套（保证对手队内一致性），每 2000 轮快照、5 槽滚动（v2 参数继承）；混对手抽签继承 v2 配比：50% 军师规划器镜像 / 30% 历史池 / 20% 镜像自博弈。按职位的 handicap 天梯（对高位职位单独降档陪练）作为 v2.2 药一手法的扩展，P2 再上【提案/待定】。
- **同职位对打的用途**：仅作诊断（如班长网单独对班长网，冻结上下级为脚本，验证细分能力是否真长出来了），不进主训练循环。

### 8.2 与 v2 设施的复用关系

| 设施 | 复用方式 |
| --- | --- |
| rl_core C++ 核（rl_net/rl_trainer/rl_json） | **网络数学保留，环境不依赖**：MLP+REINFORCE+SGD 裁剪+checkpoint 契约扩展为四网一包（同一 C++ 类型按维度参数化）；rl_trainer 主循环骨架（hash 种子/正反两局/优势标准化/对手池/课程开关）继承。紧凑 rl_env 降级为超参搜索的快筛工具，不再作为训练真相源（§七契约） |

## 九、实施分期

### P0 最小可跑（1v1 场景 + 士兵/指挥官两网）

- 定制 1v1 一屏小场景（平地、无旗或单旗、±700 出生）；
- 网络S + 网络C 两网训练闭环（词表子集：攻击/驻防/跟随；计分：胜局分 + 执行分）；
- 任务翻译层（原子 → TacticalOrders）+ 号令翻转计量（<20/min 硬门首演）；
- 保真度契约 §7.1 前三项（压制/归队/箭）在场门验证；
- **前置决策项**：「攻击拦路敌人」是否在本期实装（§七契约条款——不实装则 P0 场景布阵必须避开该语义依赖）【提案/待定：建议 P0 先不依赖、P1 期实装】；
- 验收：训练产物按 nn_brain 手法装回真实链对打（对军师规划器），胜局分/执行分/翻转率三表齐。

### P1 火力组 + 班长

- formation 侧火力组分组层（班内成员子集 + 组寻址，不动组织树）——**API 已落地**（create_fireteam 组寻址 + TacticalOrders.issue 对 ft_id 下令；观察场每班劈两组：班长外按出生序对半）；
- L1 5v5 场景 + 网络L 进场；词表补牵制/绕后斩首/夺点；任务完成度分族全量上线（排长暂缺——L1/L2 没有排，班长直接领指挥官级简化任务【提案/待定：L1 指挥官直管班长一级】）；
- 整队快照对手池上线；L0→L1 升级判据跑通。

### P2 排级 + 指挥官全链

- L2 班 vs 班 → L3 排 vs 排；网络P 进场，四网联合自博弈全链；
- 排长任务词汇全量（含给各班下发不同任务目标）；按职位 handicap 天梯；密度红线校验进升级判据；
- 产物部署：四网包装入 benchmark_brains 按职位选手位，在 battle_arena 真实链验收（对军师规划器 + 对 v2 checkpoint 遗留队），交创始人实机验收。
