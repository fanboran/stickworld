# 高动态火柴人战斗动画技术

> 调研目标：分析火柴人战斗游戏（Stick Fight、火柴人大乱斗等）中高动态打击感的核心技术，提取可应用于 stick-world 的方案。
>
> 调研日期：2026-07-25

---

## 一、代表作品技术对比

### 1.1 Stick Fight: The Game（Landfall Games, 2017）

**核心方案：纯 Ragdoll 物理驱动**

- 没有关键帧动画。角色的四肢由物理引擎实时模拟
- 布娃娃系统（ragdoll physics）：每个身体部位是独立的刚体，由关节约束
- 武器后坐力直接作用于角色——开一枪把自己弹飞
- 死亡、受击、被炸飞全部是物理计算，没有两个一样的动作

**优缺点：**
- 极度不可预测 = 极大的娱乐性（"涌现式玩法"）
- 完全无法做精确的战斗连段
- 适合 party game，不适合需要精确操作的硬核格斗

### 1.2 Stickman Burst（itch.io 独立开发者, 2025）

**核心方案：骨骼关键帧 + 战斗感增强层**

技术栈：纯 Canvas 2D + 自研骨骼系统（单文件 HTML）

- 13 关节固定骨长的骨骼系统，驱动方式为关节角度
- 攻击动画为关键帧插值 + 姿态交叉渐变（cross-fade pose blending）
- 战斗感增强层：
  - Hit stop（命中停顿）：击中时画面冻结 2-5 帧
  - 衰减式镜头震动
  - 红色受击闪光边框
  - 残影（echo strikes / afterimages）
  - 粒子特效

**关键技术细节：**
- 骨骼不是自由 IK，而是角度约束（joint angle constraints）
- 攻击动画分三阶段：预备（8-12帧）→ 击中（1-2帧）→ 收招（6-8帧）
- 空中动作与地面动作共享同一骨骼，通过状态切换

### 1.3 火柴人大乱斗（Stickman: Ultimate Burst）

**核心方案：Canvas 骨骼动画 + 连击系统 + 波次挑战**

- 13 关节骨骼系统 + 关键帧插值
- 轻攻击三连 + 重攻击 + 特殊连招（J-J-K）
- 连击数越高伤害倍率越大（最高 x2.0）
- 打击感：Hit stop + 屏幕震动
- 冲刺闪避（0.6s 冷却）+ 二段跳
- 固定 60 FPS 时间步

## 二、火柴人格斗动画的核心技术栈

### 2.1 骨架驱动方式

火柴人格斗游戏一般采用**关节角度驱动**而非**IK 端点驱动**：

```
人物骨骼 = 固定长度的线段 + 可旋转的关节
├── 髋部（根节点，平移+旋转）
├── 躯干（1-2段，绕髋部旋转）
├── 大臂 → 小臂（绕肩旋转）
├── 大腿 → 小腿（绕髋旋转）
└── 头部（绕颈旋转）

每帧更新：关节角度 → 前向运动学 → 屏幕坐标
```

与 stick-world 当前的 IK 端点驱动对比：

| | 关节角度驱动 | IK 端点驱动（当前 stick-world） |
|------|------------|-------------------------------|
| 攻击动画制作 | K 角度关键帧 | K IK target 位置 |
| 实时调整 | 直接改角度 | 移动 IK target |
| 物理约束 | 内置（角度限制） | 需要额外实现 |
| 适合场景 | 格斗连段 | 行走循环 |

### 2.2 攻击动画的三段式结构

所有格斗游戏的标准框架：

```
攻击总帧数分配：
├── 预备/前摇（Anticipation）: 8-12帧（30fps下约0.3-0.4s）
│   └── 蓄力、后撤、身体反弓
├── 出击/生效（Action/Strike）: 1-2帧（0.03-0.07s）
│   └── 极速前冲，拳头/武器到达目标
├── 命中（Impact）: 触发 hit stop（2-5帧冻结）
└── 收招/后摇（Recovery/Follow-through）: 6-8帧（0.2-0.3s）
    └── 惯性延续，回到战斗姿态
```

**关键比例：前摇:出击:收招 ≈ 4:1:3**

前摇太短 = 没有力量感，像是"摸"了一下
前摇太长 = 反应迟钝，玩起来便秘
出击太快 = 看不清发生了什么
收招太短 = 动作戛然而止，虚假感

### 2.3 姿态混合（Pose Blending）

格斗游戏的连段不是"播放完动画A再播放动画B"，而是**在动画A的收招阶段就开始混入动画B的预备帧**。

```
轻攻击1 → 轻攻击2 的过渡：
帧  0-10: 轻攻击1（100%权重）
帧 11-13: 轻攻击1（60%） + 轻攻击2预备帧（40%）
帧 14-20: 轻攻击2（100%）
```

这就是连段手感流畅的核心——没有"等待上一招放完"的间隙。

## 三、打击感（Hit Feel / 打击感）的七层模型

这是网易游戏学院和中国格斗游戏开发社区总结的成熟框架：

### Layer 1: 攻击顿帧（Hit Stop / 卡肉）

**最核心的打击感技术。**

击中瞬间画面冻结，模拟现实世界中"打到东西"的阻力感。

| 攻击类型 | 冻结帧数（30fps） | 冻结帧数（60fps） |
|----------|-------------------|-------------------|
| 轻拳/快斩 | 1-2帧 | 2-4帧 |
| 中攻击 | 2-3帧 | 4-7帧 |
| 重拳/大招 | 4-6帧 | 8-12帧 |
| 终结技 | 8-15帧 | 16-30帧 |

**实现方式（Godot）：**
```gdscript
# 简单的全局时间缩放
Engine.time_scale = 0.05  # 近乎冻结
await get_tree().create_timer(hitstop_duration).timeout
Engine.time_scale = 1.0
```

更精细的做法是只冻结攻击者和被攻击者（暂停 AnimationPlayer + 速度归零），保持粒子特效和环境继续运行。

### Layer 2: 屏幕震动（Screen Shake / 震屏）

| 攻击重量 | 震动幅度 | 震动时长 | 衰减方式 |
|----------|---------|---------|---------|
| 轻攻击 | 1-2 px | 40-80ms | 线性衰减 |
| 中攻击 | 3-5 px | 80-150ms | 指数衰减 |
| 重击 | 6-10 px | 150-300ms | 先强后弱 |
| 必杀/大招 | 10-20 px | 300-500ms | 多次震动叠加 |

**关键要点：** 震动方向应与攻击方向一致（从左往右砍 → 水平震动为主）。

### Layer 3: 受击闪光（Hit Flash）

被击中瞬间，受击者变白 1-2 帧。

**实现（Godot shader）：**
```gdshader
shader_type canvas_item;
uniform bool hit_flash = false;
void fragment() {
    vec4 col = texture(TEXTURE, UV);
    if (hit_flash) {
        COLOR = vec4(1.0, 1.0, 1.0, col.a);
    } else {
        COLOR = col;
    }
}
```

### Layer 4: 击退/击飞（Knockback）

受击者的位移应与攻击力度成正比。不是播"被击退"动画，而是直接在代码里移动位置。

### Layer 5: 形变（Squash & Stretch）

命中瞬间：
- 受击者：X方向压扁，Y方向拉伸
- 攻击者：武器/拳头放大，身体前倾

火柴人格斗中常见：武器或拳头的**夸张变形**——击中瞬间拳头放大 1.5-2 倍。

### Layer 6: 残影/拖尾（Afterimages / Ghost Trails）

快速移动时在前几帧位置留下半透明残影。**这是火柴人格斗最标志性的视觉效果。**

**实现：** 在动画的前 N 帧位置渲染半透明角色轮廓。

### Layer 7: 粒子特效

击中瞬间产生火花/血花/冲击波粒子。方向应与攻击方向一致（不是对称圆形）。

## 四、对 stick-world 的应用方案

### 4.1 当前架构的局限

stick-world 使用 IK 端点驱动骨骼，适合走路/跑步等周期性动作。但如果要做格斗：
- IK target 方式制作快速连段不够灵活
- 攻击动画需要直接控制骨骼旋转角度
- 需要 hit stop、屏幕震动等反馈层

### 4.2 推荐方案：双模式混合

```
常规移动（idle/walk/run）→ IK 端点驱动（保持现有）
战斗动作（attack/hit）    → 关节角度关键帧驱动
```

**实现方式：** 在 AnimationPlayer 中，attack 动画直接 K 骨骼旋转角度（而非 IK target）。可以混合使用——部分骨骼用角度 K 帧，部分用 IK。

### 4.3 立即可加的战斗感增强

| 效果 | 实现 | 代码量 |
|------|------|--------|
| Hit stop | `Engine.time_scale` 临时归零 | 5行 |
| 受击闪白 | Shader 参数 + Tween | 8行 |
| 屏幕震动 | Camera2D offset 噪声 | 10行 |
| 击退 | 直接修改 position | 3行 |
| Squash & stretch | scale 属性 Tween | 5行 |
| 残影 | 前几帧位置的半透明 sprite 副本 | 15行 |

### 4.4 火柴人格斗的关键设计原则

1. **Pose 可读性 > 帧数**：火柴人没有面部表情和肌肉细节，pose 的清晰度决定一切。一帧好 pose 胜过十帧模糊的过渡。

2. **快-停-快 节奏**：攻击不是匀速的。"蓄力（慢）→ 出击（极快）→ 命中（暂停）→ 收招（慢）"。这个节奏本身就是打击感。

3. **不对称反馈**：攻击方和受击方的反馈不对等。攻击方挥拳时可能只有微小位移，受击方却有大幅击退+闪白+形变。反差越大越爽。

4. **武器/拳头变形**：火柴人的优势是极端简化，可以在命中帧把拳头画成 2-3 倍大，这在写实风格里不可能。
