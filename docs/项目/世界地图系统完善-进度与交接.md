- **Thread 未 join 直接销毁 = Windows 段错误**（B2 踩坑）：后台加载线程（FileAccess+PNG 解码）在节点销毁时若未 `wait_to_finish()`，Godot 4 退出阶段**直接段错误**（不是警告完事）——测试表现为 TIMEOUT。凡 `Thread.new().start(...)` 必须配 `_exit_tree()` 里 `wait_to_finish()`（`l3_map_renderer.gd` 三线程统一 join 是样板）
- **Git Bash 双引号 + Windows 反斜杠路径**：`"...\\$d"` 会把 `\$` 转义成字面 `$d`，循环建目录全建到错误路径且 cp 静默失败——从主工作区复制文件到 worktree 用**正斜杠路径** `/f/VSCode/...` + 单变量展开
- **新 PNG 入 config/ 后必须 headless --import**：运行时 `ResourceLoader.exists()` 依赖 `.import` 元数据，缺了不是报错而是**静默返回 null**（L2 地形图不显示无任何日志）；L3 走 `FileAccess` 直读不受影响
- **river_paths.json 是废弃管线产物**（B3 踩坑）：`output/locked/river_paths.json` 出自 `experiments/river_step4.py`（C 加速器 paths.bin + Catmull-Rom），与 `fractal_continent.py` 产的现役 `fractal_river_mask_8192.png` **不是同一批河**（折线采样落 mask+2px 内仅 7.2%）——文档旧口径「river_paths 现成可直接用」已废，河流矢量一律从 river_mask 骨架化提取（`river_export.py`）。顺带：该文件坐标是 8192 级非 2048
- **矢量提取质量别用像素 IoU 验收**（B3 踩坑）：折线按宽度重栅格化 vs 原 mask 的 IoU 只有 ~0.66——PIL `draw.line` 宽度是方形足迹，斜线重建恒膨胀 ~12%，属栅格化伪影不是提取跑偏。改用**忠实度双指标**：折线采样点落 mask+1px 内比率（跑偏检测）+ mask 中心带像素距折线 ≤2px 比率（漏河检测），阈值 0.97/0.95
- **L1 context 的 margin 不统一**（B3 踩坑）：出生包当年用 `--margin 15` 导出（side 798），批量 69 包用默认 45（如 label 69 side 1038）——**重算 L1 窗口别假设 margin**，side 直接读 json 的 `context_size`，原点按 legacy bbox 中心 ± side/2 重算 + l1_polygon 界内校验；今后 `world_origin` 字段已在包内可直接用
- **并行会话就地 patch 同一批 json 的共存验证**：道路（roads 字段）与河流（rivers/world_origin）两会话先后就地 patch 同 70 份 `l1_world.json`——读-改-写天然共存，但**json 改后必须重跑 `l_world_bake.gd`**（bin 不刷则运行时看不到），且提交前用 `git diff --stat` 核对改动清单是否只有自己那部分
