# Tag 驱动的系统设计锚点清单

> **定位**：落实 GDD「设计驱动转向」原则的操作工具。目标不是"再发明一套"，而是**给每个系统一个有界的设计空间**——用「服务哪个 Tag + 对标哪款游戏的做法 + 具体抄哪个机制」把"凭空想"变成"在参考系里选"。防止设计阶段因无限发散而瘫痪。
>
> **用法**：做/改任何系统时，先看本表对应行的「设计锚点」列——锚点给出可参考的成熟做法和约束范围；除非有强理由，否则不跳出锚点另起炉灶。列在「需微调」的系统按锚点重新校准。

## 二、判定口径

- **✅ 不用动**：现有设计已落在锚点内 / 是成熟良好实践
- **🟡 微调**：有机制或叙事偏向被弱化的 Tag（大战略/RTS/自动化），按锚点收敛或改写叙事
- **🔴 需补**：有明确 TODO 断链，需按锚点补实现

> 每个系统先问三句：**① 它服务哪个核心 Tag？② 对标哪款游戏的具体机制？③ 这个机制的"有界范围"是什么？** —— 三句能答出来，就不会凭空想、不会无限发散。

## 三、树状解锁系统（设计强制项）

> 树状解锁是**核心成长骨架，必须要有**（承接"增量成长/收集/构筑"Tag）。统一走"树"结构，分支主题可多样：

| 树 | 内容 | 参考 |
|---|---|---|
| 天赋树 | 火柴人个体天赋升级 | 类幸存者天赋、暗黑天赋 |
| 科技树 | 文明/科技解锁 | RimWorld 研究、文明科技树 |
| 构筑分支 | 组织/玩法构筑分支 | 构筑类游戏 build 流派 |
| 专精树 | 职业/系统专精 | ARPG 专精树 |

- **原则**：都走成熟"解锁 → 增量成长 → 收集"的树模型，不发明新概念；重**成长正反馈**与**选择感**（让玩家有"我选的分支"的构筑感）。
- 树的呈现本身也是"堆料感"来源之一（见 §四：树状 UI + 高信息密度）。

## 四、表现层方向（堆料感 / Juice）

> **目标**：让玩家感到"内容量充足、精致堆料"，别显得单薄——这也是为了凑够 Steam 宣传所需的多张各异截图。以下按**关注类别**分开，别混在一起：

### 4.1 画面后处理与氛围（视觉充盈感）

- 极光、雨天、炫光(Bloom)、屏幕空间形变、前景物体、粒子
- 在特定地方加后处理，用**简单后处理换极大画面充盈感**

### 4.2 动效与反馈（操作/事件反馈）

- 屏幕抖动 / 文字抖动（打击、事件、大数字时按需使用）
- 大数字特效：大数值用不同材质 + 华丽跳出动画
- 丰富悬浮反馈 + 清脆爽快的声音反馈

### 4.3 UI 与信息密度（屏幕充盈感）

- UI 文字密度/数量适当加大，让屏幕有充盈感

### 4.4 美术与配色（视觉辨识）

- 鲜艳大胆的配色
- 稀有度颜色：不同物品用不同颜色标定（白/绿/蓝/紫/橙…）
- 货币美术：宝石/金币花花绿绿，美术上心，带物理效果甚至反光
- 描边：材质加描边；特定场合用**彩虹描边**（稀有/高亮/选中）

**堆料感 = 以上四类叠加**，让界面/画面信息密度足够，避免"内容量太少"的观感，也凑够宣传截图。

## 五、新颖性方向（85% 法则：15.87% 新意）

> 依据 **The Eighty Five Percent Rule for Optimal Learning**（2019，《Nature Communications》）：最优学习区间 ≈ **84.13% 熟悉模式 + 15.87% 未知/新信息（预测误差）**，日常简化说"85% 旧 / 15% 新"。
> - 新信息 **> 30%**：原有认知模式断裂、难以归纳，易挫败、丧失探索动力
> - 新信息 **< 5%**：高度熟悉、缺乏认知惊喜，易倦怠
> - 新信息 **≈ 15%**：形成可填补的预测误差，激活好奇心与探索欲，投入效率峰值
> - **备注**：行业常传的"30%"是二次转述衍生结论；学术基准为 **15.87%（约 15%）**，"30%"实际指"超过会断裂"的阈值，不是推荐值。
>
> **设计含义**：不断用前所未有的新意/创意刺激玩家，但把新信息量控制在 **≈15%**——始终处在"既熟悉又有新东西"的甜区（太多新=困惑，太少新=无聊）。
