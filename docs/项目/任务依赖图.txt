# 语法:
#   线序: 泳道1, 泳道2, ...                     （从左到右）
#   任务 <id> | 名称= | 线= | 状态= | 前置=a,b | [域=] | [树=] | [位置=x,y] | [豁免=1] | [注=]
#   里程碑 <id> | ...                          （画◆；前置= 字段是依赖唯一真相源）
# 状态: 完成/待验收/进行中/可开工/阻塞/冻结/放弃
# 铁律（铁路调度模型）:
#   1. root 是唯一无前置节点（无法再前沿的任务源），一切依赖链最终到达它
#   2. 阻塞 = 前置未齐（阻塞无因 = ERROR；前置齐却标阻塞 = W 状态滞后）
#      外部依赖（美术资产/创始人窗口/音频采购）建显式门节点承载（先例 ext_art），不用"阻塞"空挂
#   3. 状态由 DAG 派生：前置全部完成 → 必须标 可开工；协调者只可派「可开工」
#      （排期先后是协调者在就绪集内的裁量，不是图的状态）
#   4. 前置 = 工作内容依赖（技术上需要什么），不是执行时间顺序——同天提交的两个任务可能互不依赖；
#      域互斥（同域文件不能并行写）是**调度约束**不是依赖，先后由协调者派活时裁决
#      （先例：main_done 巨门拆除——units/combat 工程债群不再假挂"复刻收尾"，改走域互斥调度）
#   5. 依赖保持最小：冗余边（可经其它前置传递到达）= W，假深度会误导读图与并发评估
#   6. 域= 供进行中冲突检测（合并冲突热点）；派活组合建议 = 关键路径优先 + 域互斥贪心
#   7. 本图跟随最新设计实时变化：设计推翻某成果时，同步移除/改写对应完成节点
#      （如河流追踪一版被推翻→从完成区移出，river_gen 阻塞重做）；git 顺序≠依赖
#   校验: python tools/deptask/gen.py --check   生成: python tools/deptask/gen.py
#   模块级（代码）依赖见 docs/技术/架构/模块依赖关系.md —— 与本图互补，勿混写
