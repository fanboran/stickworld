# 火柴人战斗系统最终设计文档

> 版本：v2.1 | 日期：2026-07-26
>
> 目标：在 stick-world 的 Skeleton2D + IK 架构上，实现一套灵动、可扩展、单人开发可承受的战斗与动画系统。

## 一、设计约束

| 约束 | 说明 |
|------|------|
| 单人开发 | 动画工作量必须可复用、可模板化 |
| 纯魔法战斗 | 无枪械，有法杖/弓箭/大剑等多种武器 |
| 2D 横版侧俯视角 | 类似合金弹头/城堡破坏者，地形为阶梯+斜��，不做 Z 轴深度 |

| 目标体量 | 战场同屏 50-200 个火柴人 |

## 二、动画系统设计

### 2.1 统一的 IK Target 驱动（不改变现有架构）

**所有动画都用 IK target 关键帧驱动**，包括攻击。不引入骨骼角度关键帧，不做双模式。

理由：
- IK target 驱动已经能完成攻击 pose（手前伸、脚前踏）
- 单一驱动方式避免切换接缝
- Godot 的 SkeletonModification2DTwoBoneIK 自动求解骨骼旋转

### 2.2 动作分类与数量

基于 AAA 战斗游戏的最低可行集（MVS）+ 本项目魔法/弓箭特性：

#### 基础动作（所有单位共享，8 个）

| 动作 | 时长 | 用途 |
|------|------|------|
| idle | 2.0s | 待机呼吸 |
| walk | 1.0s | 行走循环 |
| run | 0.7s | 奔跑循环 |
| dead | 0.8s | 死亡倒地 |
| hit_light | 0.3s | 轻受击（上半身后仰） |
| hit_heavy | 0.5s | 重受击（全身后退+踉跄） |
| prone_idle | — | 趴下待机（被压制/战壕中） |
| prone_move | 0.8s | 匍匐前进 |

#### 战斗动作（按武器模组分，每组 4-6 个）

| 动作 | 时长 | 用途 |
|------|------|------|
| cast_anticipate | 0.3s | 施法前摇（举杖蓄力） |
| cast_release | 0.2s | 施法释放（前推+特效触发） |
| cast_recover | 0.3s | 施法收招 |
| bow_draw | 0.4s | 拉弓蓄力 |
| bow_release | 0.15s | 射箭释放 |
| sword_swing | 0.4s | 大剑挥砍（前摇+出击+收招） |

#### 移动特技（3 个）

| 动作 | 时长 | 用途 |
|------|------|------|
| dash | 0.3s | 冲刺闪避 |
| jump | 0.5s | 跳跃 |
| land | 0.2s | 落地 |

**总计：8 基础 + 6×武器组 + 3 特技 = 17-23 个动画**

对比 AAA 标准（40-80/武器），这是极简方案，但配合程序化战斗感层足够用。

### 2.3 武器模组复用系统

**核心思路：动画按"武器类型"分组，同类武器共享一套动画。**

#### 武器类型分类

| 类型 | 代表武器 | 共享动画 | 手部 IK target 偏移 |
|------|----------|----------|-------------------|
| 法杖类 | 木杖/水晶杖/符文杖 | cast_* | 双手前伸握杖 |
| 弓箭类 | 短弓/长弓/十字弩 | bow_* | 前手握弓+后手拉弦 |
| 大剑类 | 双手剑/巨斧/战锤 | sword_swing | 双手握柄 |
| 单手类 | 短剑/匕首/魔刃 | sword_swing | 单手挥舞 |
| 徒手类 | 拳套/爪/空手 | punch_* | 拳头前冲 |

**新增武器只需：**
1. 归入一个武器类型
2. 设置该武器的手部 IK target 偏移参数（握持位置）
3. 不需要新动画

#### 实现方式

```gdscript
# weapon_config.gd
class_name WeaponConfig
extends Resource

@export var weapon_type: WeaponType  # 法杖/弓/大剑/单手/徒手
@export var hand_offset_r: Vector2   # 右手相对握持点偏移
@export var hand_offset_l: Vector2   # 左手相对握持点偏移
@export var cast_effect: PackedScene # 施法特效预制体
@export var damage: int
@export var attack_range: float

enum WeaponType { STAFF, BOW, GREATSWORD, ONE_HAND, UNARMED }
```

战斗时，IK target 的基础位置 + 武器偏移 = 最终手部位置。不同法杖只是改 `cast_effect` 和属性数值，动画完全复用。

## 三、魔法冲击波特效（Screen Space Distortion）

用户指的"透明冲击波"是 3D 游戏中常用的 **Screen Space Distortion / Refraction** 效果——冲击波本身看不见，但会让**背后的画面扭曲变形**，形成一股"空气被推开"的折射感。这在 Overwatch、Valorant 等游戏的冲击波技能中非常经典。

### 3.1 原理

```
屏幕画面（已经渲染好的所有对象）
  ↓
冲击波 Shader（CanvasLayer 上的 ColorRect）
  ├── 计算一个环形区域（内径→外径 = 冲击波厚度）
  ├── 在环形区域内，沿径向偏移 UV
  │   → 偏移后的 UV 去读 SCREEN_TEXTURE
  │   → 读到的像素被"推离"冲击波中心
  │   → 形成背景扭曲的视觉效果
  └── 可选：边缘加上色差（R/B通道偏移不同距离）
  ↓
最终输出到屏幕
```

关键：冲击波本身不是画出来的，它是**对背后画面的像素进行 UV 扭曲**。所以冲击波经过哪里，哪里的背景就会变形。

### 3.2 Godot 4 完整实现

#### Shader 文件（CC0 许可，改编自 godotshaders.com）

```gdshader
// shockwave_distortion.gdshader
shader_type canvas_item;

// 冲击波参数
uniform float radius: hint_range(0.0, 1.0, 0.001) = 0.0;    // 环的半径（0→1 = 屏幕归一化）
uniform vec2 center = vec2(0.5, 0.5);                         // 冲击波中心（屏幕归一化坐标）
uniform float strength: hint_range(0.0, 0.1, 0.001) = 0.06;  // 扭曲强度
uniform float ring_width: hint_range(0.0, 0.1, 0.0001) = 0.03; // 环的厚度
uniform float edge_softness: hint_range(0.0, 1.0, 0.001) = 0.1; // 边缘柔化
uniform float aberration: hint_range(0.0, 1.0, 0.001) = 0.4;  // 色差强度（0=无色差）

// 读取屏幕纹理（Godot 4 用 hint_screen_texture 声明）
uniform sampler2D SCREEN_TEXTURE : hint_screen_texture, filter_linear_mipmap;

void fragment() {
    vec2 uv = SCREEN_UV;

    // 修正宽高比，确保冲击波是正圆
    float aspect = SCREEN_PIXEL_SIZE.y / SCREEN_PIXEL_SIZE.x;
    vec2 corrected_uv = (uv - vec2(0.0, 0.5)) / vec2(1.0, aspect) + vec2(0.0, 0.5);

    // 当前像素到冲击波中心的距离
    vec2 dist_vec = corrected_uv - center;
    float dist = length(dist_vec);

    // 构建环形遮罩（外边缘 - 内边缘 = 环）
    float outer = 1.0 - smoothstep(radius - edge_softness, radius, dist);
    float inner = smoothstep(radius - ring_width - edge_softness, radius - ring_width, dist);
    float ring_mask = outer * inner;

    // 径向扭曲方向（从中心向外推）
    vec2 distort_dir = normalize(dist_vec);
    float distort_amount = strength * ring_mask;

    // 扭曲后的 UV
    vec2 distorted_uv = corrected_uv - distort_dir * distort_amount;

    // 色差效果：R通道多偏移一点，B通道少偏移一点
    vec2 aberration_offset = distort_dir * distort_amount * aberration;

    // 分别采样 R、G、B 通道（轻微偏移 → 色差）
    float r = texture(SCREEN_TEXTURE, distorted_uv + aberration_offset).r;
    float g = texture(SCREEN_TEXTURE, distorted_uv).g;
    float b = texture(SCREEN_TEXTURE, distorted_uv - aberration_offset).b;
    float a = texture(SCREEN_TEXTURE, uv).a;

    // 遮罩外的区域保持原样
    vec4 original = texture(SCREEN_TEXTURE, uv);
    vec4 distorted = vec4(r, g, b, a);

    COLOR = mix(original, distorted, ring_mask);
}
```

#### 场景结构

```
GameScene
├── World (你的所有游戏对象)
│   ├── 火柴人角色们
│   ├── 地面/建筑
│   └── 粒子效果
├── CanvasLayer (layer 1, 用于冲击波)

│       └── ShaderMaterial → shockwave_distortion.gdshader
└── Cameras
```

#### GDScript 驱动代码

```gdscript
# shockwave_manager.gd
extends Node2D

@onready var shockwave_rect: ColorRect = $CanvasLayer/ColorRect
var shockwave_material: ShaderMaterial

func _ready():
    shockwave_material = shockwave_rect.material as ShaderMaterial
    # 初始状态：radius=0，不可见
    shockwave_material.set_shader_parameter("radius", 0.0)

## 在屏幕坐标触发冲击波，持续 duration 秒
func trigger_shockwave(world_pos: Vector2, duration: float = 0.5, 
                       power: float = 1.0) -> void:
    # 世界坐标 → 屏幕归一化坐标（0-1）
    var viewport_size := get_viewport().get_visible_rect().size
    var cam := get_viewport().get_camera_2d()
    var screen_pos: Vector2
    if cam:
        screen_pos = cam.get_screen_transform() * world_pos
    else:
        screen_pos = world_pos
    var center_uv := screen_pos / viewport_size

    shockwave_material.set_shader_parameter("center", center_uv)
    shockwave_material.set_shader_parameter("strength", 0.06 * power)

    # 用 Tween 驱动 radius 从 0 扩散到 1.0
    var tw := create_tween().set_ease(Tween.EASE_OUT).set_trans(Tween.TRANS_SINE)
    tw.tween_method(
        func(v): shockwave_material.set_shader_parameter("radius", v),
        0.0, 1.0, duration
    )
    # 扩散结束后重置
    tw.tween_callback(
        func(): shockwave_material.set_shader_parameter("radius", 0.0)
    )
```

#### 使用示例

```gdscript
# 施展魔法时触发
func cast_fireball(pos: Vector2):
    # ... 伤害判定 ...
    shockwave_manager.trigger_shockwave(pos, 0.5, 1.0)  # 标准冲击波

func explode(pos: Vector2):
    shockwave_manager.trigger_shockwave(pos, 0.8, 2.0)  # 大爆炸：更慢、更强
```

### 3.3 两种冲击波变体

| 变体 | 用途 | 参数差�� |
|------|------|----------|
| 标准魔法命中 | 小范围扭曲 | duration=0.4, strength=0.04, aberration=0.3 |
| 大爆炸/必杀 | 大范围扭曲+色差 | duration=0.8, strength=0.08, aberration=0.6 |
| 持续性力场 | 不断脉动 | 用 sin(TIME) 驱动 radius 在 0-0.5 之间循环 |
| 热浪/热空气 | 持续微扭曲 | 用 noise 纹理而非环形遮罩，极低强度持续存在 |

### 3.4 Heat Distortion（持续性热浪扭曲）

一些场景可能需要持续性的"空气扭曲"效果（如火球飞行路径上的热浪）：

```gdshader
// heat_haze.gdshader
shader_type canvas_item;

uniform sampler2D noise_texture : repeat_enable, filter_linear_mipmap;
uniform float strength : hint_range(0.0, 0.02) = 0.008;
uniform vec2 speed = vec2(0.15, 0.08);

uniform sampler2D SCREEN_TEXTURE : hint_screen_texture, filter_linear_mipmap;

void fragment() {
    vec2 noise_uv = UV + TIME * speed;
    vec2 offset = texture(noise_texture, noise_uv).xy * 2.0 - 1.0;
    offset *= strength;

    vec2 distorted_uv = SCREEN_UV + offset;
    // 只对自身 sprite 的 alpha 区域扭曲
    vec4 distorted = texture(SCREEN_TEXTURE, distorted_uv);
    vec4 original = texture(SCREEN_TEXTURE, SCREEN_UV);
    COLOR = mix(original, distorted, texture(TEXTURE, UV).a);
}
```

这个放在火球飞行路径的 Sprite2D 上，让火球经过的区域持续有热浪扭曲。

### 3.5 物理击飞

魔法爆炸把敌人炸飞，使用物理速度而非预设动画：

```gdscript
# combat_system.gd

func apply_explosion_knockback(target: Node2D, origin: Vector2, force: float):
    var direction = (target.global_position - origin).normalized()
    # 横版游戏：主要 X 方向击退 + 少量 Y 方向上抛
    var knockback = Vector2(direction.x * force, -force * 0.4)
    
    if target is CharacterBody2D:
        target.velocity = knockback
        target.set_meta("knockback_active", true)
        # 0.5秒后恢复控制
        get_tree().create_timer(0.5).timeout.connect(
            func(): target.set_meta("knockback_active", false)
        )
```

被击飞期间：
- 角色失去输入控制
- 重力持续作用（先上抛后下落）
- 落地时播放 land 动画
- 落地位置可以有轻微随机偏移（每次都不一样）

### 3.3 为什么不加残影

用户质疑残影的必要性——**在魔法战斗游戏中残影确实不必要。**

残影（afterimage）适合：
- 近战快速连段（拳/剑的挥动轨迹）
- 高速移动角色（忍者/刺客）

魔法战斗不需要残影，因为：
- 魔法的视觉重点在**特效本身**（冲击波、粒子、光柱），不在角色身体
- 弓箭手的视觉重点是**箭矢轨迹**，不是拉弓的残影
- 大剑挥砍可以用**武器拖尾**（weapon trail）替代全身残影——只需在剑尖采样位置画线

**替代方案：武器拖尾**

```gdscript
# weapon_trail.gd — 只在武器尖端画拖尾，不是全身残影
extends Line2D

var trail_points: Array[Vector2] = []
const MAX_POINTS := 8

func _process(_delta):
    if weapon_is_swinging:
        var tip_pos = weapon_tip.global_position
        trail_points.append(tip_pos)
        if trail_points.size() > MAX_POINTS:
            trail_points.pop_front()
        points = trail_points
        # 透明度从尾部到头部递增
        for i in range(trail_points.size()):
            gradient.set_color(i, Color(1, 1, 1, float(i) / MAX_POINTS))
    else:
        trail_points.clear()
        points = []
```

## 四、2D 地形方案（基于现有代码的增量设计）

### 4.1 现有地形系统（不推翻）

当前 stick-world 的地面模型非常简单且有效：

```
VillageMap
├── ground_y = 810.0           # 地面线（火柴人站立面）
├── ground_bottom = 1080.0     # 地面底部（地图像素底边）
├── TerrainLayer               # 草地纹理（Stochastic Tiling shader + GroundPolygon）
├── TerrainBuildings            # 地形建筑（山体/悬崖/巨石, is_terrain=true 不可拆）
├── BuildMaskLayer              # 不可放建筑区域（通过 PlacementGrid 的 blockage_mask 实现）
├── GroundLine                  # 地面线可视化标记
└── ForegroundLayer             # 前景遮挡层（z_index=10）
```

**核心是 `ground_y` 一条平线 + GroundPolygon 渲染的草地平面。** 没有 TileMap，没有 tiles。

### 4.2 决策：保持平面地面，不做阶梯和斜坡

理由：
- 现有代码基于 `ground_y` 平面的 PlacementGrid（32px 竖向条带）做建筑放置
- 引入斜坡需要重写建筑吸附逻辑、碰撞检测、渲染顺序——成本大
- 战场类游戏（类似小兵步枪/英雄连）的地面本身就是近似平坦的，起伏通过**地形障碍物**而非地面高度来体现

### 4.3 地形起伏通过"地形建筑"实现

不是让地面不平，而是在平地上放置不可穿越的地形障碍：

```
世界坐标系（侧俯视）：
┌──────────────────────────────────────────┐
│  天空                                     │
│                                          │
│  ┌───┐          ┌──────┐                 │  ← 地形建筑（山体/悬崖）
│  │山 │  角色     │ 悬崖  │     角色        │     is_terrain=true
│  └───┘    →     └──┬───┘       →         │     提供碰撞和掩体
│                    │                     │
│══════════════════════════════════════════│  ← ground_y = 810
│             草地平面                      │
│                                          │  ← ground_bottom = 1080
└──────────────────────────────────────────┘
```

- **山体/悬崖** → TerrainBuildings 子节点，is_terrain=true，不可拆除
- **战壕** → 可穿越的凹陷贴图（纯视觉效果），角色走上去触发 prone 判定
- **掩体** → 小型障碍物，角色靠近时自动蹲下/贴墙

### 4.4 战壕的实现

战壕不是地面高度的变化，而是**地面上的一个标记区域**：

```gdscript
# trench_area.gd — 挂在一个 Area2D 上
extends Area2D

func _on_body_entered(body: Node2D) -> void:
    if body.has_method("enter_trench"):
        body.enter_trench()  # 触发 prone 动画 + 减小判定框

func _on_body_exited(body: Node2D) -> void:
    if body.has_method("exit_trench"):
        body.exit_trench()   # 恢复站立
```

角色进入战壕区域后：
- Y 坐标降低 20-30px（视觉上下沉）
- 碰撞判定框高度减半（更难被远程打到）
- 自动播放 prone 动画
- 移动速度降低

无需改动地面高度——这是纯粹的逻辑状态切换加视觉偏移。

### 4.5 高地优势

由于不做 Z 轴深度方向的高低差，高地优势用其他方式体现：

- 高地 = 地面上的高台区域（视觉上画一个抬高的平台贴图）
- 站在高台的角色 Y 坐标 +30px（逻辑+视觉抬高）
- 高台的**边缘**有单向碰撞——只能从低处走上去（斜坡状），不能从高处直接走下去
- 弓箭手站在高台上射程 +20%，法师射程不变

这就是"侧俯视角不做深度、但高台有战术价值"的折中方案。

## 五、视差滚动系统（前后场景移动速度分离）


### 5.1 原理

不同深度的场景层以不同速度跟随相机移动，制造立体感：

```
相机移动到最右侧时各层的偏移量：
┌─────────────────────────────────────────┐
│ 天空层 (scroll_rate=0.1)     ░░░░░░░░░ │ 几乎不动
│ 远山层 (scroll_rate=0.3)   ▓▓▓▓▓▓▓▓▓  │ 慢速跟随
│ 中景层 (scroll_rate=0.6)  ██████████   │ 中速跟随
│ 地面层 (scroll_rate=1.0) ██████████████│ 完全跟随角色
└─────────────────────────────────────────┘
```

### 5.2 Godot 实现

#### Parallax2D 节点（Godot 4 原生支持）

```gdscript
# 场景结构
GameWorld
├── ParallaxBackground
│   ├── ParallaxLayer (motion_scale=Vector2(0.1, 0.1))  # 天空
│   │   └── Sprite2D (sky_texture)
│   ├── ParallaxLayer (motion_scale=Vector2(0.3, 0.2))  # 远山
│   │   └── Sprite2D (mountain_texture)
│   ├── ParallaxLayer (motion_scale=Vector2(0.6, 0.5))  # 中景
│   │   └── Sprite2D (tree_texture)
│   └── ParallaxLayer (motion_scale=Vector2(1.0, 1.0))  # 地面（跟随角色）
│       └── TileMap (terrain)
└── 角色层（与 ParallaxBackground 同一层级，跟随相机）
```

`motion_scale` 的含义：
- `(0.1, 0.1)` — 相机移动 100px，该层只移动 10px（远处的天空几乎静止）
- `(1.0, 1.0)` — 相机移动 100px，该层也移动 100px（地面紧跟角色）

#### ParallaxLayer 的 mirroring 属性

如果背景图不够宽，设置 `mirroring` 到背景图宽度，ParallaxLayer 会自动平铺复制：

```
ParallaxLayer
├── motion_scale = (0.3, 0.2)
└── mirroring = Vector2(1920, 0)  # 每 1920px 自动平铺
```

### 5.3 竖向视差（侧俯视角特有）

由于视角是"侧俯视"，地面越靠近屏幕底部越近，越靠近地平线越远。可以用竖向视差增强：

```
地面层 (motion_scale_y=1.0)  — 完全跟随，靠近镜头
中景层 (motion_scale_y=0.5)  — 半速跟随，较远
远景层 (motion_scale_y=0.2)  — 慢速跟随，最远
```

相机上下移动时，远景几乎不动，地面跟随——这就模拟了"俯视"的立体感。

### 5.4 多层前景遮挡

前景元素（草、岩石、残垣）可以在 ParallaxBackground 之外独立渲染，`motion_scale` 设置为 `(1.2, 1.0)`（比地面更快），产生"在角色前方"的遮挡效果。

```
前景层 (motion_scale=(1.2, 1.0)) — 比地面更快 → 感觉离镜头最近
角色层                               — 正常速度
```

## 七、程序化战斗感层（完整实现）

本节包含所有必须代码实现的完整版。每个效果都是独立模块，可分别叠加。

### 7.1 Hit Stop（命中冻结）

**作用**：攻击命中瞬间，全局时间短暂冻结 3-5 帧，模拟"打到了东西"的阻力感。

```gdscript
# hit_stop.gd — 挂在全局单例或 CombatSystem 上
extends Node

func trigger(duration_sec: float = 0.066, slow_factor: float = 0.05) -> void:
    Engine.time_scale = slow_factor
    # 使用真实时间等待（不受 time_scale 影响）
    await get_tree().create_timer(duration_sec, true, true).timeout
    Engine.time_scale = 1.0

# 使用示例：
# light punch:   trigger(0.033)  # 2帧@60fps
# medium spell:  trigger(0.066)  # 4帧@60fps
# heavy爆炸:     trigger(0.100)  # 6帧@60fps
```

**性能注意**：战场上同时有多个单位时，`Engine.time_scale` 影响全局，可能导致其他单位动作卡顿。如果同屏单位超过 50，改用**逐对象冻结**：

```gdscript
# 逐对象冻结（只暂停攻击者和被攻击者的 AnimationPlayer）
func trigger_local(attacker: Node2D, target: Node2D, duration: float) -> void:
    _pause_anim(attacker)
    _pause_anim(target)
    await get_tree().create_timer(duration).timeout
    _resume_anim(attacker)
    _resume_anim(target)

func _pause_anim(node: Node2D) -> void:
    var ap := node.get_node_or_null("AnimationPlayer") as AnimationPlayer
    if ap: ap.speed_scale = 0.0

func _resume_anim(node: Node2D) -> void:
    var ap := node.get_node_or_null("AnimationPlayer") as AnimationPlayer
    if ap: ap.speed_scale = 1.0
```

### 7.2 屏幕震动（Screen Shake）

```gdscript
# camera_shake.gd — 挂在 Camera2D 所在节点
extends Node2D

@onready var camera: Camera2D = $Camera2D

func shake(intensity: float = 5.0, duration: float = 0.15, direction: Vector2 = Vector2.ZERO) -> void:
    var original_offset := camera.offset
    var elapsed := 0.0

    # 如果没指定方向，随机
    var dir := direction.normalized() if direction.length() > 0 else Vector2.RIGHT

    while elapsed < duration:
        var decay := 1.0 - elapsed / duration
        var x := randf_range(-1.0, 1.0) * intensity * decay
        var y := randf_range(-1.0, 1.0) * intensity * decay * 0.5
        # 震动方向偏重攻击方向
        camera.offset = original_offset + Vector2(x * 0.7 + dir.x * x * 0.3, y + dir.y * y * 0.3)
        elapsed += get_process_delta_time()
        await get_tree().process_frame

    camera.offset = original_offset

# 使用示例：
# shake(3.0, 0.1)       → 轻攻击微震
# shake(8.0, 0.2)       → 中攻击中震
# shake(15.0, 0.4)      → 大爆炸强震
# shake(10.0, 0.25, attack_direction)  → 带方向的震动
```

**战场多单位注意**：同屏多个爆炸时震动会叠加。需要做震动合并：

```gdscript
# 如果当前已有震动，只更新为更大的强度
var shake_remaining := 0.0
var current_intensity := 0.0

func shake_merged(intensity: float, duration: float) -> void:
    if intensity > current_intensity:
        current_intensity = intensity
        shake_remaining = max(shake_remaining, duration)
        _do_shake(current_intensity, shake_remaining)
```

### 7.5 身体微动噪声（Idle 时持续）

```gdscript
# 在 stickman_rig.gd 的 _process 中添加
var _noise := FastNoiseLite.new()
var _noise_time := 0.0

func _process(delta: float) -> void:
```

### 7.6 脚步适应地形 IK

```gdscript
func update_foot_ik_terrain() -> void:

    # 用射线检测获取脚下地面高度

    if innerfoot:
        innerfoot.global_position.y = ground_y
```

## 九、弓箭手系统

弓箭手作为"枪械变体"，动画复用 bow_* 模组。

### 6.1 弓箭动画

| 动作 | 时长 | 描述 |
|------|------|------|
| bow_draw | 0.4s | 拉弓蓄力，后手向后拉 |
| bow_aim | 持续 | 瞄准待机（上半身保持拉弓，下半身可走路） |
| bow_release | 0.15s | 松弦射箭 |
| bow_recover | 0.3s | 收弓回到战斗姿态 |

### 6.2 箭矢物理

箭矢不是即时命中，而是有飞行时间的物理实体：

```gdscript
# arrow.gd
extends RigidBody2D

var velocity: Vector2
var damage: int
var pierce: int  # 穿透次数

func _physics_process(delta):
    # 箭矢受重力影响（抛物线）
    velocity.y += gravity * delta
    position += velocity * delta
    rotation = velocity.angle()  # 箭头朝向飞行方向
    
    # 碰撞检测
    var hit = move_and_collide(velocity * delta)
    if hit:
        apply_damage(hit.collider)
        pierce -= 1
        if pierce <= 0:
            queue_free()
```

### 6.3 弓箭手 vs 法师的区别

| | 弓箭手 | 法师 |
|---|--------|------|
| 伤害类型 | 物理 | 魔法 |
| 命中方式 | 抛物线物理实体 | 即时+特效 |
| 蓄力 | 拉弓时间影响箭速 | 蓄力时间影响法术强度 |
| 视觉重点 | 箭矢轨迹 | 施法冲击波 |
| 击退效果 | 小（穿透力） | 大（爆炸力） |

## 十一、关键设计决策总结

| 决策 | 选择 | 理由 |
|------|------|------|
| 动画驱动方式 | 纯 IK target | 统一架构，无切换接缝 |
| 上下半身分离 | 不做（初期） | 复杂度高，单层状态机+快速xfade足够 |
| 残影 | 不加 | 魔法战斗不需要，改用武器拖尾 |
| 地形起伏 | 假 Z 轴 + 高度曲线 | 行业成熟方案，适配横版战场 |
| 战壕 | 高度曲线凹陷 | 角色走进凹陷=进入战壕 |
| 武器多样性 | 5类武器模组+配置驱动 | 新武器只改配置不改动画 |
| 弓箭命中 | 物理抛物线实体 | 有飞行时间，可被躲避 |
| 魔法命中 | 即时+冲击波特效 | 命中即触发视觉反馈 |
| 击退类型 | 按伤害类型区分 | 爆炸→击飞，物理→后退，火→灼烧减速 |
| 战场规模 | 50-200 单位 | 不加全局子弹时间，用局部 hit stop |
