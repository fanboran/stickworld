## 一、硬性风格规约（子代理动笔前必读）

1. **无痕**：成品文档不携带任何生产过程痕迹。禁止出现：生成方式标注、写作/更新日期、「逆向/登记/AI/基于 commit」等过程字样、变更历史叙述。**信息出现频率 = 需求频率**：低频信息至多给指针（git 历史自会记录变更），写进正文即信息错位。成品须与仓库既有文档无法区分。
2. **格式对齐既有文档**：模块 README 按 `modules/building_gen/README.md` 现行格式（`# 模块名：一句话定位` → 引言块 → `## 目录结构` 树+行内注释 → `## 依赖` → `## 开发注意事项`/扩展指引）；架构文档对齐 `docs/技术/架构/建筑管线/` 各篇风格。没有的章节不硬造。
3. **只写代码里验证过的事实**：每个断言动笔前在代码里核实（路径/类名/信号名/函数名/数值）；不确定的不写，报回调度裁决。推断性建议一律不进文档。
4. **只写交付物清单内的文件**：不改任何代码/场景/配置/AGENTS.md；不做任何 git 操作（提交由调度统一做）。
5. **遗留参照口径**：被新链路替代而保留作规格参照的旧代码，在目录树行内注释自然标注（如 `旧2D绘制链路，已被HD-2D替代，仅作规格参照`）；系统性规格缺口集中写进 C3 交付的遗留参照文档，各模块不重复展开，给指针即可。
