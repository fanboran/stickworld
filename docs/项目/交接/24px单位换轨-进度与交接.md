## §一 为什么换轨、换轨的数学本质

换轨前：1 格 = 32 世界单位，最终显示 1 格 = 32 × user_zoom(默认 0.75) = 24 设计像素——所有引擎数值都要心算 ×0.75 才是屏幕像素。
换轨后：**1 格 = 24 世界单位，zoom=1.0，脚本数字 = 屏幕设计像素 1:1**。

数学本质是**单位重定名**：所有以「世界单位」计的量 ×0.75、zoom 默认 ÷0.75，屏幕输出逐像素不变。换轨本身**不改变任何画面比例**；「建筑体加宽、出檐收窄、挑高比例」是在新轨道上做的第二步（§五）。

## §二 关键口径决策（接手必读）

1. **cards.json / props.json / nature.json / hd2d_layouts json 保持 32px/格 烘焙记账**——它们是烘焙数据格式，不随换轨迁。引擎消费一律经「格数」口径：卡片 quad 尺寸 = `units × S`（**S 保持 1/32**，含义 = 烘焙px→格），屏幕密度由相机（24px/格@zoom1）承担。⚠ 这是本次最大的认知坑：把 S 改成 1/24 会把卡片放大 1.33×（实测踩过，见 §六）。
2. **构图锚恒定**：`set_cam_zoom` 内 `h_anchor = DESIGN_HEIGHT/32`（= 33.75 **格**）是"天际线基线压屏幕下 1/3 线"的世界锚线，**格数口径、换轨不变**——动它 = 动默认构图（创始人契约：分界线压下 1/4 线）。
3. **米制锚等比继承（口径 A）**：1 引擎单位 ≈ 1.75cm；人物 rig 97.5 单位 = 1.70m（`char_sprite_3d.gd` RIG_SCALE 0.475→0.35625）；SIZE_K=1.2 **原样保留**（等比折算，屏显 117px 与旧轨一致）。门(烘焙150)/人(烘焙130) 的比例修复不在本轨，留阶段 2（SIZE_K→1.0 即恢复门比人高 15%）。
4. **2D 建筑美术体系**（building_exterior 及子类）：美术常量保持 32px/格 历史口径，**容器级 ×0.75**（`ART_CONTAINER_SCALE`，Exterior/Interior 两容器）；碰撞/触发几何不走容器——InteractionZone 常量直接换 24 口径，场景手摆的 PassageBarrier/StandPlatform 运行时一次性 ×0.75 迁移（幂等 meta `_collision_canvas_px_24`，场景文件不动）。
5. **调参表 px 值 ×0.75**（`config/balance/variables.tres` 12 项：walk/run/base_scale/spread/row_gap/arrow/knockback 等）。⚠ **Excel 源 `平衡变量.xlsx` 未同步**——下次经 Excel 管线导出会覆盖回旧值，见 §五 待办。
