# 世界地图「水陆同源」重建方案

> **用途**：创始人 2026-09-22 要求「根本性修复」，针对战略图反复出现的「色块与地图不严丝合缝」（已出现三次、每次修的都是症状）。本方案给出**口径级**的根治路径与验收线。
> **上游诊断**：`docs/项目/交接/L1战略图-邻省上下文与切省箭头-进度与交接.md` §3.0 / §3.0b（真因 + 两代图盘点，全部带实测数字）。
> **状态**：**方案 + 创始人 2026-09-22 定向（D2 用精细版 / D3 水体改矢量后处理）**；剩 D1（源流带视觉）待看 P1 对比图拍板。

---

## 一、根因一句话

**"哪里是水"在管线里被定义了三次，且各自漂移**：

| 定义者 | 依据 | 后果 |
|---|---|---|
| 地形上色 | `locked_continent_8192` + 湖/河掩膜，**另加**「源流」群系的河湖沿岸膨胀带（浅蓝 `95,160,195`，与真水同色） | 视觉水线 = 海岸线**再往内 4~11px** |
| 政治几何 | 城块/老 L1 标签场（另一条 lineage：区域 tiles → 城块生长 → 细化场） | 与上者的差 = 缝 |
| 政治渲染的「水面回贴」 | 对地形贴图做**绿-蓝差猜色**判水 | 把源流带也判成水 → 色块被挖到带内缘，而描边画在外缘 |

叠加效应：**同一条海岸线上有三条互不重合的线**（地形水线 / 色块填充边 / 描边），差 3~19px。历次修复（把回贴步长改成 1、把政治界加宽到 3px 盖缝、把邻块轴序换回来）都是在**症状层**加补丁，因此每加一层就多一条线。

## 二、目标与不变量（修复后必须成立）

| # | 不变量 | 量法 |
|---|---|---|
| **I1** | 只有**一个**水/陆真相：`locked_continent_8192`（海）× `fractal_lake_mask_8192`（湖）× `fractal_river_mask_8192`（河），三者同一次生成 run 产出 | 产物 mtime 同一批；`check_mapdata_consistency` 断言 |
| **I2** | 政治几何**严格贴陆**：`几何 ∩ 海 = 0 px` 且 `陆地 \ 几何 = 0 px`（无内缩毛边） | `geometry ∩ ocean`、`land \ geometry` 两项归零 |
| **I3** | 政治渲染**不再自己判水**：色块填充边、描边、地形水线三者**几何同源**，逐像素重合（容差 ≤1px 抗锯齿带） | 色块边界→水掩膜边界距离 p90 ≤1px |

推论：I1+I2 ⇒ 换任何一代标签场都不会破 I2（因为几何先贴陆再提轮廓）；I3 ⇒ 删掉"颜色猜水"这条口径，管线里只剩一份"水"的定义。

## 三、方案分层

### L1｜水真相前移：生成期产出「水面覆盖贴图」

> **2026-09-22 创始人定向后的修订**：本层的「水面覆盖贴图」在 **L2 落地后不再必需**——几何严格贴陆（`labels[水]=0`）时色块根本盖不到水面，地形里画的水自然原样可见。故本层降级为**可选保险**（用于"几何暂时没贴陆"的过渡期或异常包），主路径改为 **L3 的水体矢量后处理**（见下）。

- `l1_terrain_bake.py` 在同一次 run 内**同时**产出 `<pack>/l1_water_overlay.png`（RGBA：RGB = 地形像素原样、A = 掩膜判水量，8192 原生、与该包 `l1_terrain.png` 同窗口同代）。
- 运行时 `bake_water_restore()`（颜色判水 + 逐像素扫描）**整体退役**，改为直接解码这张贴图。
  - 收益：判水口径回到生成端且**只有一份**；运行时零启发式；顺带省掉每次进政治模式的像素扫描。
- 湖/河用哪一代：**必须与地形上色同一份**（当前地形用原始 `fractal_lake_mask_8192`）。若将来升级到 `audit4_refined_lake_8192`，地形与 overlay 一起重烘——纪律写进工具 CLI（不允许分两次跑）。

### L2｜几何贴陆：导出前统一后处理

- 在轮廓提取**之前**对标签场做两步（`tools/worldgen/l2_export/mesh_extract` 调用点统一接入，L1/L2/L3 导出器共用）：
  1. **贴陆**：`labels[locked_continent == 0] = 0`（含湖/河一并归 0，水面不进地块）；
  2. **回填**：陆地内的 `0` 空洞按 EDT 最近标签回填（消除内缩毛边，保证 `陆地 \ 几何 = 0`）。
- **这一步是"用精细版"的前置**：现行细化场越海 0.79%~3.22%（距陆地 p50 3px/p90 7px/max 12px，与其自身注释矛盾），**贴陆后处理一挂上就合规**，因此不必改细化脚本本身（其第 2 步注释需同步订正，避免继续误导）。修好后两代标签场都满足 I2，选哪一代只是观感取舍，不再牵动对齐。

### L3｜水体改矢量后处理：渲染不再碰像素

**创始人 2026-09-22 定向**：「后处理再画河流，用精细的」——政治模式的水体改为**声明式矢量 pass**，绘制在色块之上、描边之下：

| pass | 数据源（包内已有） | 画法 |
|---|---|---|
| 地形底 | `l1_terrain.png` | 照旧（含海；内陆水的描画被矢量 pass 覆盖/接替） |
| 色块 | tiles 多边形（L2 贴陆后） | 半透明国色，**只盖陆地** |
| **河流** | `rivers`（`river_export.py` 骨架化折线 + **EDT 实测宽**，与底图河流掩膜同源） | `draw_polyline`，宽 = `w + 1px`（多 1px 盖住底图 `gaussian_filter(0.9)` 的羽化边），色 = `MapTokens.L1_RIVER`（与地形同 token） |
| **湖泊** | `lakes` 多边形（若用精细湖光栅则**同批重提**多边形） | `draw_colored_polygon`，色 = `MapTokens.L1_LAKE` |
| 描边/轮廓/城市点 | 几何 | 照旧 |

- **收益**：① 水体与几何同一套矢量语言、同源同代；② 放大到 3× 时不再糊（贴图是 8192 原生，矢量无分辨率上限）；③ 运行时**彻底不判水**——`bake_water_restore` 整段删除，`L1_WATER_*` 四个 token 退役；④ 河湖边界与其在底图里的位置由**同一个掩膜**决定，不存在"矢量湖与贴图湖不一致"的旧顾虑（旧顾虑的前提是底图也画了湖——现在两者同源且矢量在上层）。
- 代价：政治模式多两条绘制调用（零数据增量）；河流折线是骨架化抽稀结果，边缘比底图的手绘感更"干净"（观感取向，P1 出图对比确认）。
- 纪律：河流折线宽度必须继续取自 EDT 实测（`w`），**不得改用固定像素宽**——否则与底图河带宽度不再对应，"同源"就断了。

### L4｜消除"口径可以悄悄漂移"的结构（根本性的一半）

1. **双代二选一**：`refined_city_labels_8192.npy`（现落在 `output/diag/l1_v2/`）与 `city_labels_8192.npy` 只留一份，另一份删除；湖光栅同理。
2. **产物路径归位**：`biome_labels_2048.npy` / `biome_hot_zone_2048.png` / `refined_city_labels_8192.npy` 回到脚本读取的 `output/` 下；导出器/烘培器**缺输入一律报错退出**，不再静默回退（本轮"L1 悄悄用了旧代"就是这么来的）。
3. **守门断言进测试矩阵**：新增 `tools/worldgen/check_mapdata_consistency.py`（或并入 `tests/` 矩阵，纯 Python 读产物，不需要 Godot）：
   - 逐包：`几何越海 = 0`、`陆地漏盖 = 0`、`色块边界→水掩膜 p90 ≤1px`、`l1_water_overlay` 与 `l1_terrain` 同尺寸同窗口、`neighbors/tiles/l1_polygon` 轴序自证；
   - 失败即非零退出 → 接进 `tests/run_all.sh` 的既有门禁。
   - **这条是防止"第四次复发"的关键**：把"对齐"从人工审计变成构建期断言。

## 五、决策台账（含创始人 2026-09-22 定向）

| # | 决策 | 结论 |
|---|---|---|
| **D1** | 源流（河湖沿岸浅蓝带）视觉去留 | **待创始人看图定**：P1 在出生包出「现状 / 改湿地色 / 收窄到 2~3px」三版对比图，看图拍板（默认建议：不再画成水色） |
| **D2** | 数据用哪一代 | **用精细的（创始人 2026-09-22 定向）**：城块标签场用 `refined_city_labels_8192`、湖光栅用 `audit4_refined_lake_8192`（湖多边形同批重提）。**前置 = L2 贴陆后处理**（否则精细版越海 3~12px 会把缝加宽）；地形与水体矢量须与所选湖光栅**同批重烘** |
| **D3** | 水体渲染方式 | **矢量后处理（创始人 2026-09-22 定向）**：河流 polyline（EDT 实测宽）+ 湖泊 polygon，画在色块之上；`bake_water_restore` 与 `L1_WATER_*` token 退役 |

> D2/D3 一经确定，L1 的"水面覆盖贴图"（原 L1 层）即降级为过渡期保险，主路径是"几何贴陆 + 水体矢量"。
