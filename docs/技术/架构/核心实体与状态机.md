## 实体清单

运行时状态快照类集中在 `stick-world/core/entities/`（RefCounted，不含节点逻辑）；
`WorldState`（autoload）承担实体注册表容器，序列化由 `world_state_serializer.gd` 统一负责。

| 实体 | 实现类 | 简述 | 数量级 |
|------|--------|------|--------|
| Stickman（火柴人个体） | `StickmanState` | 最小游戏单位，有特性、装备、当前任务 | 初期 5-50，帝国级 1000-10000+ |
| Building（建筑） | `Building`（modules/building_gen/scripts/building.gd，场景实体） | 从茅草屋到奇观 | 数十到数百 |
| Organization（组织） | `OrganizationState` | 五层级通用管理单元，军队/科学院/工程队/行政/商队 | 数个到数十 |
| Project（项目） | `ProjectState` | 一次军事行动/建设工程/科研课题/运输任务 | 并行数十个 |
| Region（地块） | `RegionState`（预留，尚未接入生产数据流） | 世界地图上的地理单元 | 几十到上百 |
| Resource（资源） | 无独立状态类：定义在 `config/resources/resources.tres`，运行时库存在 modules/resources/ | 食物/木材/石料/金属/黑色沥青等 | 库存追踪 |
| Technology（科技） | 无实体类（科技系统模块待重建，见 [04-科技系统.md](../../设计/系统/04-科技系统.md)） | 已获得 / 未获得（征服获得，无状态机） | 数十到上百项 |
| Battle（战斗实例） | `BattleState` | 一场实时战斗的运行时数据 | 并行 0-10+ |
| SupplyChain（物流链路） | `SupplyChainState` | 一条从产地到消费点的运输路线 | 数十条 |

各实体**状态机图**（Stickman IDLE→MOVING→WORKING/FIGHTING/FLEEING/DEAD、Building PLANNED→CONSTRUCTING→OPERATIONAL→DAMAGED/DESTROYED/UPGRADING、Organization FORMING→ACTIVE→EXECUTING/DISBANDED、Project PLANNING→EXECUTING→PAUSED/COMPLETED/FAILED、Battle PREPARING→ENGAGED→STALEMATE/ATTACKER_WIN/DEFENDER_WIN/ROUT）见 [README §4.2 状态机](../../../stick-world/modules/README.md#42-核心实体与状态机)。实体关系（Organization owns Project、Project decomposes sub_Project、Region contains Building 等）同见该节。

| `morale` | float | 0-100，影响战斗力和逃跑阈值 |

| `assigned_org` | String/null | 所属组织 ID |
| `org_rank` | int | 在所属组织中的层级(L1-L5) |
| `org_role` | String | 在组织中的角色（指挥官/士兵/研究员/工匠等） |
| `location` | Vector2 | 当前世界坐标 |
| `state` | enum | IDLE / MOVING / WORKING / FIGHTING / FLEEING / DEAD / SUMMONING |

## 二、Building（建筑）

> 实现类为 `modules/building_gen/scripts/building.gd`（`class_name Building`），是 building_gen 模块对外公共类型（契约见 [模块API契约.md](模块API契约.md)）；construction/world 经 `is/as` 与 `Building.State` 操作完工建筑。

### 属性

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | String | |
| `type` | enum | 住房/农田/工坊/矿场/兵营/学院/市场/仓库/奇观/…… |
| `tier` | int | 等级 1-5 |
| `location` | Vector2 | 世界坐标 |
| `region_id` | String | 所属地块 |
| `hp` | float | |
| `max_hp` | float | |
| `state` | enum | PLANNED / CONSTRUCTING / OPERATIONAL / DAMAGED / DESTROYED / UPGRADING |
| `construction_progress` | float | 0-1 |
| `required_resources` | Dict | {resource_id: amount} |
| `production_queue` | Array | 当前生产队列 |
| `assigned_workers` | Array[String] | 分配到此建筑的火柴人 ID |
| `assigned_org` | String/null | 所属组织（如是科学院的下属建筑） |

### 模块化扩展（B0+ 阶段，详见 [建筑模块化设计.md](建筑模块化设计.md)）

上表的 `type` 与 `tier` 在重构后由更丰富的数据组合取代：

| 新字段 | 类型 | 说明 |
|--------|------|------|
| `def` | `BuildingDef` 引用 | 定义尺寸/材质/模块/开口的配方 |
| `shell_dirty` | bool | 材质或尺寸变更后需重建节点树 |
| `modules` | Array[ModuleInstance] | 各层已加载的模块实例 |
| `layers_material` | Array[String] | 每层材质 ID（初期全统一，后期混合） |

**关系**：`BuildingDef` / `ModuleDef` / `MaterialDef` / `RoofShape` 是 **Resource**，存 `config/buildings/` 下，多个 `Building` 实例共享同一配方。

## 三、Organization（组织）- 核心实体

这是整个游戏最核心的实体，承载五层级通用项目管理系统。

### 属性

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | String | |
| `name` | String | 玩家自定义名称（"虎贲师"/"皇家科学院"） |
| `tag` | enum | MILITARY / RESEARCH / ENGINEERING / ADMINISTRATION / COMMERCE |
| `tier` | int | 自身在五层级中的层级 1-5 |
| `parent_org` | String/null | 上级组织 ID |
| `child_orgs` | Array[String] | 下级组织 ID |
| `commander_id` | String/null | 指挥官火柴人 ID |
| `personnel` | Array[String] | 该组织直属火柴人 ID 列表 |

| `current_project` | String/null | 当前执行的项目 ID |

## 五、Region（地块 / 战略图地理单元）

运行时状态类 `RegionState` 为预留容器（生产模块尚未接入，数据流落地时经 `WorldState` 的 register_* 容器启用）。战略图数据模型按 L3/L2/L1 三级粒度组织，详见 [`战略图架构.md`](战略图架构.md) §三。扩展属性：

| 补充字段 | 说明 |
|----------|------|
| `control_percentage` | 0-1，交战地块不完全控制时的进度 |
| `cultural_affinity` | Dict{culture_id: 0-1}，文化同化进度 |
| `infrastructure_level` | 0-1，道路/港口等基建水平 |

| `organizations_present` | Array[String]，驻扎的组织 |
| `battles_active` | Array[String]，正在进行的战斗实例 |

## 八、Technology（科技）

> 实体类暂未落地（科技系统模块待重建，阶段 1 随 RegionState 数据流一并实现）。设计上科技"获得即拥有"，**无状态机**。

### 属性

| 字段 | 说明 |
|------|------|
| `id` | |
| `name` | |
| `tier` | 1-5 |
| `prerequisites` | Array[String]，前置科技 |
| `unlocked` | bool，是否已获得（征服/事件获得后即 true，**无状态机**） |
| `acquire_method` | enum，CONQUEST（征服抢夺）/ EVENT（事件获取）/ RESEARCH（后期自主研究） |
| `unlocks` | Array[String]，解锁的建筑/单位/能力 |
| `assigned_org` | String/null，后期自主研究时负责的组织（Demo 阶段不用） |

### 获取机制

> **机制说明**：科技主要通过**征服获得**（打下敌国解锁其科技），获得即拥有，无 AVAILABLE/RESEARCHING 中间状态。后期帝国规模才启用自主研究机制。

| 获取方式 | 说明 |
|------|------|
| **征服抢夺** | 打下敌国/占领特定地区 -> 解锁对方拥有的科技（`unlocked = true`） |
| **事件获取** | 遗迹探索、特殊事件触发 |
| **自主研究** | 后期帝国规模，组织科学院进行研究（Demo 阶段不启用） |
