## 一、屏幕状态机

```
        ┌──────────┐
        │   BOOT   │  引擎启动 → 读配置/存档索引
        └────┬─────┘
             ▼
        ┌──────────┐   新游戏/读档    ┌──────────┐
        │ MAIN_MENU│ ───────────────▶ │ LOADING  │ ─┐
        │  主菜单  │ ◀─────────────── │  载入屏  │  │
        └────┬─────┘   退出到主菜单    └──────────┘  │
             │ ▲                                     ▼
             │ │              ┌────────────────────────────┐
             │ └───────────── │           IN_GAME          │
             │   保存并退出    │  ┌──────────────────────┐  │
             │                │  │ SCENE_VIEW 场景图     │  │
             │                │  │ STRATEGIC  战略图     │  │（Tab/M 互切）
             │                │  └──────────────────────┘  │
             │                │  其上可压 MODAL 模态栈      │
             │                └────────────────────────────┘
             └── 设置/读档/制作名单（主菜单与游戏内共用同一套界面）
```

| 状态 | 说明 | 对应 |
|------|------|------|
| BOOT | 引擎启动、autoload 初始化、存档索引扫描 | 无 UI（或 LOGO 闪屏，P1） |
| MAIN_MENU | 主菜单 | `main_menu_template.tscn` |
| LOADING | 载入屏（进度 + 提示轮换） | 规划见 03，模板待做 |
| IN_GAME | 游戏内（场景图/战略图两个视图互切） | `hud_template.tscn` 等 |
| MODAL | 游戏内压栈的模态界面（设置/组织/科技…） | 见 §三模态栈 |

**状态切换规则**：
- MAIN_MENU ⇄ IN_GAME 必须经 LOADING（世界生成/读档是耗时操作）。
- 设置、读档、确认框**两处复用**：主菜单打开与游戏内打开是同一界面实例工厂，
  仅返回去向不同。
- 退出游戏前必经确认框（有未保存进度时）。

## 二、UI 层级栈（屏内叠放秩序）

从低到高六层，每层职责单一：

```
L6 DebugLayer    F3 调试覆盖层（最高，不受模态影响）
L5 SystemLayer   Toast 通知流 / 确认框 / 载入屏（任何时候都可压顶）
L4 ModalLayer    模态栈：设置/组织面板/科技树/读档/世界地图（打开即暂停或慢速）
L3 PanelLayer    模式面板 + 上下文面板（Village/Battle/Possess；选中检视）
L2 HudLayer      常驻 HUD：顶栏/快捷栏/小地图/缩放条（不挡游戏输入）
L1 GameWorld     游戏世界（场景图或战略图画面）
```

映射到现有 `UIRoot` 槽位（[`ui_root.tscn`](../../../stick-world/modules/ui_global/scenes/ui_root.tscn)）：

| 层级 | 槽位 |
|------|------|
| L2 HudLayer | `GlobalHUD` + `HudOverlay`（角落部件：小地图/缩放条/建造按钮） |
| L3 PanelLayer | `ModePanel` + `ContextPanel` + `ResourceBar` |
| L4 ModalLayer | `ModalOverlay`（模态栈容器，后进先出） |
| L5 SystemLayer | 待加 `SystemLayer` 槽（Toast/确认框挂点，见 05） |
| L6 DebugLayer | `DebugApi` 自有 CanvasLayer（已有） |

## 三、模态栈规则

- 模态界面**压栈**而非互斥：组织面板上可再开确认框，ESC 逐层退栈。
- 同一类型的模态**只允许一个实例**（设置开两次不会叠两块）。
- 强模态（载入屏/新游戏向导）屏蔽一切输入与 ESC；弱模态（设置/读档）可 ESC 关闭。
- 打开 L4 模态时游戏**自动暂停**（可在设置中改为慢速），关闭栈空时恢复。

## 五、输入焦点秩序

1. L6 Debug 层永不抢焦点（纯绘制）。
2. L5/L4 有内容时**拦截全部输入**（模态语义）。
3. L3/L2 只消费落在控件上的事件，其余穿透给游戏世界
   （HUD 根 `mouse_filter = IGNORE`，模板已示范）。
4. **ESC 秩序**：关闭栈顶模态 → 无模态则开设置 → 附身中则先退出附身（现有约定保留）。
