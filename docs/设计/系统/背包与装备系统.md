# 背包与装备系统

> 模块位置:`modules/items/`(物品域,L1 基础设施)+ `modules/inventory/`(玩家侧,L2)
> 分支:`agent/items-domain`
>
> **物品域独立原则**:物品的定义/实例/容器/转移是独立于背包与仓储的底层系统
> (行业惯例:Valheim 统一 Inventory 容器、RimWorld ThingDef 统一原型、Factorio
> 原型统一+物流)——玩家背包、个体装备、区域仓储、尸体遗物都是**同一套容器
> 抽象的消费者**,不各自造库存结构。

## 一、是什么

- **物品域(items)**:全项目唯一的物品注册表与容器原语——`ItemDef`(定义)/
  `ItemStack`(实例)/`ItemDB`(注册表,含资源品)/`ItemContainer`(列表制容器)/
  `ItemTransfer`(容器间原子转移)。
- **玩家背包(列表制)**:**不限总物品数量,唯一上限 = 每类物品的 max_stack**
  (石料 50、铁矿石 30、金砂 20、钻石 10、绷带 99、装备 1)。背包只收:装备、
  矿物、消耗品;建造材料不进背包(实体搬运玩法,拿起占双手)。
- **装备栏 5 槽**:头/胸/腿护甲+主手武器+副手盾;弓双手锁副手(装弓自动卸盾)。
- **Hotbar 三段式**:`[主手|左键][副手|右键] │ [指派格×10] │ [F 交互][E 背包]`。
- **翻包式掉落**:击杀不掉落地物品——尸体挂遗物容器,走近按 F 翻检取物。
- **建筑交互 UI**:走近带交互区的建筑按 F 弹建筑菜单(仓库开村仓/内景进入/占位)。
- **个体 loadout 奠基**:每个火柴人有独立装备记录(StickmanState.loadout)。

## 二、怎么设计

### 2.1 键位(全表)

| 键 | 语义 | 备注 |
|---|---|---|
| **E** | 开/关背包·角色合一窗口 | 模态自动暂停 |
| **F** | 交互 | 材料/建造/资源点/翻包/建筑菜单统一入口 |
| **滚轮(附身)** | **切换武器**(循环 hotbar 武器格并换装) | 换装即切换操作方式(弓拉弓/矛投掷/杖指向) |
| **Shift+滚轮(附身)** | 缩放画面 | 创始人定稿:附身态滚轮默认给武器 |
| **滚轮(非附身)** | 缩放画面 | 战略层现状 |
| **1-9 / 0** | Hotbar 指派格直达 | 武器=装备切换;消耗品=使用 |
| 左键 / 右键(按住) | 主手攻击 / 举盾 | 09 文档 §二 |
| G | 空挥 | 不变 |
| ~~C~~ | ~~角色属性面板~~ | 属性并入背包窗口左栏 |

### 2.2 items 域(L1,modules/items/)

```
modules/items/
├── api.gd              # 契约(容器/转移/注册表只经本文件)
├── core/
│   ├── item_def.gd     # 定义:id/category/max_stack/weapon_type/two_handed/stats/icon
│   ├── item_stack.gd   # 实例:def_id + count
│   ├── item_db.gd      # 注册表(内置 GDScript 真相源;类型化导出后迁 .tres)
│   ├── item_container.gd   # 列表制容器抽象
│   └── item_transfer.gd    # 容器间原子转移
└── data/(迁移后 item_def/item_stack/item_db 归位 core/)
```

- **ItemContainer(列表制)**:`Dictionary[def_id → count]` 条目即堆;`add(def,count)`
  返回放不下的余量(超出 max_stack 的部分);`remove/count_of/has`;信号
  `contents_changed`。**无总格数/总数量概念**——容量策略只有 per-item max_stack。
- **ItemTransfer**:`move(from,to,def_id,count)` 原子转移(目标按 max_stack
  截断,余量留源容器)——翻包/村仓/发装备共用的唯一搬运原语。
- **资源品 def**:wood/stone/food 等与 `resources.resource_id` 一一映射
  (映射表在 items api)——资源品既有物品语义(可入容器)又有经济语义
  (resources float 台账);区域仓储的容器视图(RegionStorage)经映射桥接,
  **经济层 float 链路不动**(供需/价格照旧)。
- 分层纪律:items 零依赖(L1);inventory(L2)依赖 items;resources 经 items
  api 取映射,不反向。

### 2.3 玩家背包与装备(inventory 模块,L2)

- **PlayerInventory = ItemContainer + 5 装备槽 + hotbar 指派**:
  - 装备规则(不变):武器→主手/盾→副手/护甲分类入槽;双手武器锁副手;
    列表制下"背包满"不存在,装备/卸装恒可行(事务回滚分支退役)
  - **hotbar 指派**:`Array[StringName]`×10 格,存 def_id(指向而非移动);
    **只收 WEAPON/TOOL/CONSUMABLE**(护甲/材料无高频切换语义,不可指派);
    `hotbar_selected` 当前选中格
  - 换装 API:`wield(def_id)`(装备主手武器=hotbar 切换武器/数字键共用路径)
- **InventoryService 桥接**:装备→实体(weapon_type/盾/护甲聚合——既有)+
  **stats 乘子**(新):weapon_mount 加 `equip_attack_mult/equip_speed_mult`
  (默认 1.0),伤害与有效冷却计算点乘入,不碰基础值与 battle_sim 校准;
  附身解除恢复 1.0
- **存档**:背包/装备/hotbar 指派随 SaveManager 玩家数据段序列化

### 2.5 翻包系统(掉落=尸体容器)

- 单位死亡:按 weapon_type/loadout 反查 def_id 生成**遗物容器**(武器+盾,
  消耗品随机小额)挂尸体节点;有遗物的尸体延长保留(~12s,可调;翻空提前淡出)
- 交互:InteractionController 新 kind `"loot"`(走近尸体按 F)→ ContainerScreen
- 个体 loadout(奠基):`StickmanState.loadout`(main_hand/off_hand/armor×3,
  存 def_id)替代空壳 equipment 字段;spawn 时 loadout.main_hand 有值覆盖兵种
  默认 weapon_type;序列化走 extra_data;给 NPC 发装备/个体背包→后续批次

## 三、为什么这么设计

- **物品域独立**:背包/仓储/尸体/装备四类库存消费同一容器抽象——任何新库存
  场景(载具货舱/工坊仓库/商店)都是 ItemContainer 实例+转移原语,零新概念
- **列表制背包**:上限只挂在物品种类上(创始人裁决)——玩家体验是"万物皆可收",
  稀缺性由获取速度与堆叠上限表达,不由格子数表达;同时消灭"背包满"失败分支
  (装备/卸装恒可行,事务回滚复杂度归零)
- **换武器=换操作方式**:hotbar 武器格选中即装备(weapon_type 单点驱动),
  与武器专属操控(09 文档 §二)构成"玩家全能"闭环
- **翻包而非掉落**:战场不喷物品(省实体管理/拾取判定),翻包是有节奏的交互
  (走近→按 F→挑走),与建筑交互共用 ContainerScreen
- **stats 乘子不碰基准**:battle_sim 校准链以基础值为锚,装备只加乘子层,
  回归风险隔离
- **滚轮语义**(创始人定稿):附身态滚轮默认切武器(高频操作),缩放让位
  Shift+滚轮;非附身维持缩放(战略层高频)
