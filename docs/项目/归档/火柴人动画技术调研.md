## 一、Alan Becker 与《火柴人 VS 我的世界》

### 1.1 背景

Alan Becker，美国动画师，2003 年开始制作火柴人动画，2006 年在 Newgrounds 发布《Animator vs. Animation》一炮而红。2015 年发布《Animation vs. Minecraft》（AVM），YouTube 单集过亿播放。2020 年入驻 B 站（ID：火柴人AlanBecker），2021 年获百大 UP 主。

截至 2026 年，YouTube 频道 3000 万订阅、80 亿播放。团队从单人扩展到 **60+ 人**，Alan 本人已转为编剧/导演角色。

### 1.2 核心团队与分工

| 成员 | 角色 | 代表作 |
|------|------|--------|
| Alan Becker | 编剧、导演 | 整个系列 |
| Terkoiz | 动作主笔 | AVM 第1-5季战斗戏、SHOCK 系列 |
| Guz | 动画师 | AvA 第7集 |
| Oxob3000 | 动画师 | 当前主力 |
| Shruiken255 | 动画师 | 当前主力 |
| Aaron Grosic | 作曲/音效 | 全系列 |
| DJ Welch | 角色设计 | 视觉风格 |

### 1.3 生产管线（六阶段）

Alan 团队在 2026年2月的官方邮件中公布了完整流程：

1. **写作** — 情节点 → 剧本（粗粒度到细粒度）
2. **预制作** — 概念图、分镜、资产索引表
3. **构图/动态分镜** — 潦草火柴人 + 占位资产做粗版草稿，导演大量批改；同期进行资产创建和背景绘制
4. **动画制作**（核心）
   - 先做"草稿动画"——介于动态分镜和完稿之间，关键动作打磨到位
   - 另一名动画师接手"完稿"——加特效、微调、补中间帧
   - **近年大量使用 Blender 做 3D 辅助**（复杂场景和镜头运动）
5. **音频** — 音效组逐动作贴 SFX，作曲家根据动画节奏写 BGM
6. **后期** — 逐帧排查作画失误（"几百个问题"），Adobe Premiere 精剪

### 1.4 核心动画技术

**不是纯逐帧手绘。** Alan 的核心技巧：

#### Symbols（元件）+ Tweens（补间）

- 火柴人的头、躯干、四肢各自是独立的可复用元件（Symbol），存在库中
- 设好关键姿势（key pose），Adobe Animate 自动生成中间帧（Tween）
- 关键在 **key pose 的质量**，不在帧数
- Alan 的判断标准："观众能从这一帧单张画面看懂发生了什么吗？"

#### 12 条动画原则

所有动作设计的底层逻辑：

| 原则 | 应用 |
|------|------|
| **Squash & Stretch** | 落地/受击时身体压扁，反弹时拉长 |
| **Anticipation** | 出拳前先蓄力后撤，让观众有预期 |
| **Follow-through** | 动作停止后肢体惯性晃动 |
| **Easing** | 慢入慢出，没有一个是匀速运动 |
| **Arcs** | 所有运动沿弧线而非直线 |
| **Timing & Spacing** | 控制速度感和重量感 |

#### Terkoiz 的"卡帧"技巧

Terkoiz（AVM 战斗主笔）在 SHOCK 系列中大量使用卡帧——故意让某些关键帧停顿。牺牲流畅度，换打击感和力量感。这和游戏动画里的 "hit stop" 是同一原理。

## 二、对 stick-world 的启示

### 2.1 你复刻不了的东西

Alan Becker 的管线是基于 **视频动画** 的，不是 **实时游戏** 的：

- **时间成本不可比**：一集 AVM 是 60 人团队几个月的工作量
- **逐帧可控性不可比**：动画师可以精细到毫秒级控制每一帧的手绘曲线
- **后期处理不可比**：After Effects 的粒子/辉光/动态模糊在实时渲染中极贵

### 2.2 可以借鉴的东西

| Alan 的技巧 | Godot 中的等价物 |
|------------|-----------------|
| Symbols + Tweens | `AnimationPlayer` 关键帧 + 插值曲线 |
| 12 条原则 | `AnimationPlayer` 的 easing 曲线、`Tween` 节点 |
| Squash & Stretch | `scale` 属性动画（受击时 x 压缩 y 拉伸） |
| 卡帧/打击感 | 受击时 `Engine.time_scale` 短暂降速或暂停 1-2 帧 |
| 摄像机震屏 | `Camera2D` offset 噪声 |
| 冲击波/VFX | GPUParticles2D + 速度线 shader |
| 动态模糊 | Godot 4.x 内置 motion blur（后期效果） |

### 2.3 核心结论

**不要试图在实时游戏中复刻 Alan Becker 的动画质量。** 他们追求的是电影级的逐帧控制，你追求的是 60fps 实时渲染下的表现力。两个方向的技术路线完全不同。

你的正确方向：
1. 少量高质量手K基础循环（idle/walk/run/attack/dead）+ **程序化叠加层** 补充灵动性
2. 把打斗冲击感从"骨骼K帧"转移到 **后期特效**（摄像机震屏、粒子、速度线）
3. 利用 **MediaPipe 视频提取** 辅助生成基础动画，降低手K成本

## 三、2D 骨骼跟踪技术调研

### 3.1 MediaPipe Pose

Google 开源的实时人体姿态估计框架，当前事实标准。

- **33 个关键点**：包含面部、上肢、下肢、手指尖和脚趾
- **实时性能**：CPU 上 30fps 无压力
- **输出**：归一化 2.5D 坐标 (x, y, z)，x/y 是图像归一化坐标，z 是相对深度估算
- **Python 一行安装**：`pip install mediapipe`
- **关键限制**：z 坐标不可靠（单目摄像头无真实深度），侧向视角下遮挡肢体可能定位不准

### 3.2 相关开源项目

| 项目 | 功能 |
|------|------|
| [mediapipe-pose-estimation-example](https://github.com/TitorPs360/mediapipe-pose-estimation-example) | 包含 example3.py：「Create a stick figure that mimics your movements」，直接演示了骨架→火柴人的实时映射 |
| [Computer-Vision-Motion-tracking](https://github.com/Giulio-grt/Computer-Vision-Motion-tracking) | 使用 MediaPipe 做跑步姿态分析，包含 2D 骨架回放和关节角度计算 |

### 3.3 对 stick-world 的适用性

| 方面 | 评估 |
|------|------|
| 侧向行走提取 | **适用** — 只需要 x/y 坐标，不需要 z |
| 火柴人骨骼映射 | **适用** — 仅需手腕、脚踝 4 个端点，比 MediaPipe 33 点少得多 |
| 实时驱动 | **不推荐** — 延迟和抖动不适合游戏内使用，仅用于离线工具 |
| 多角度 | **不推荐** — 单目无深度，仅限侧向参考视频 |
