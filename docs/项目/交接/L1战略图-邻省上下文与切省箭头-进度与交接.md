### R4 「色块与地图严丝合缝」

第一轮落地的是**渲染侧治标**（**真因见 §3.0**，那里的审计推翻了本节的判据解释）：

1. **沿岸溢出**：地块多边形边界在地形可见水线之外——第一轮实测 median 8px / max 39px（zoom 1.15 屏幕像素）。
2. **湖河被吞**：地块多边形含地块内水体，政治覆盖层把地形里的湖/河一起染色。
3. **收敛手段 = 水面回贴 pass**：后台线程从地形贴图烘一张 RGBA 贴图（RGB = 地形原色、A = 判水量），政治模式在覆盖层之上原样贴回。
   - 判水用绿-蓝差（阈值 `L1_WATER_GB_MID=-0.06` ± `0.03` 过渡带）——**该判据把"源流"群系的浅蓝河湖沿岸带也判成水，是复审仍有缝的直接原因**（§3.0）。
   - **步长必须为 1**（`L1_WATER_STRIDE=1`）：抽样后线性过滤会把水色与邻近陆色混出一道浅带。
   - 逐字节自证：真水像素回贴后与地形**完全相同**（dev=0）。
4. **邻界缝**：地块多边形各自平滑后相邻边有 1~2px 不共线 → 政治界宽 `L1_POLITICAL_TILE_BORDER_WIDTH=3.0`（比常驻灰界 2.0 粗一档）盖住缝。

### R2b（第二轮新增）邻块多边形轴序缺陷 —— 「色块像被对角轴翻转」

**症状（创始人原话）**：「国家染色地块甚至方向反了，像是被左上右下的对称轴翻转后的效果」。

**根因**：`export_l1_view_context.py` 写邻居块时**漏了 `to_xy`**——mesh_extract 输出的环是 `(y,x)` 角点，而 L1 数据格式全仓统一 `[x,y]`（`l_world_bake.gd`「L1：原样序列化 [x,y]」、`L1TileDef._polygon_from`）。所以每包的 `neighbors[].polygons/holes` 是 `[y,x]`，渲染端按 `[x,y]` 读 → **邻块整体沿主对角轴（左上↔右下）翻转**。涂灰时只是形状不对看不出来，本轮邻省上色后立刻暴露。

**跨包确认**：抽 8 包 26 个邻块，全部「读作 `[y,x]` 才落在按全球裁窗的期望 bbox 内」（读作 `[x,y]` 全错）；全量自证 435 个可判邻块。

**修复（两层）**：
1. 导出器：`polygons/holes` 都过 `to_xy`（防再犯）；
2. 既有数据：`tools/worldgen/l1/fix_neighbor_axis_l1.py` 对 70 包逐点换序（含被启发式漏判的 3 包 l1_004/l1_034/l1_041 单独补修）→ 重烤 `l1_world.bin` 70+1 份（`l_world_bake.gd`，L2/L3 的 bin 重烤后字节不变）。
3. 同一类坑的第二处：`l3_l1.json` 的 **centroid 字段也是 `[y,x]`**（与 polygons 同序）——侧表首版照 `[x,y]` 读，导致箭头方位也沿对角轴翻转（创始人同一条反馈的另一半）。已在 `export_province_politics.py` 换序并重出侧表；`test_province_politics` 加了守门断言（出生省质心必须落在本包 context 窗口内 + 三邻省方位为东北/西北/正西）。

**验证**：修复后出生省三邻省落位 = #67 西北 / #68 正西 / #18 东北，与世界地理一致（见 §五 新图）。

### 3.0 R4 真因：**「哪里算水」被算了三遍，三个口径各画一条边**（2026-09-22 第三轮审计）

创始人复审「还是没严丝合缝」，并问「是图像的数据源没对齐吗 / 是不是某次重构出问题了」。审计结论：**图像数据源是齐的，错在"水"的定义在三个环节各一套**。

**先排除的（实测，都是零位移）**

| 判据 | 结果 |
|---|---|
| 地形贴图 ↔ 全局政治栅格（裁剪窗内） | 一致率 94~98%，平移搜索 ±3px 最优恒为 **(0,0)** |
| `l1_base.png` ↔ `l1_terrain.png` 海岸线 | 双向距离 p90 ≤2px，最优平移 **(0,0)**；两贴图在校验重叠区**逐字节相同** |
| 包几何 ↔ `l3_l1.json` 权威多边形（69 包全量） | own IoU **0.999**、质心偏移 ≤0.3px（仅 #19~#62 一簇 10~200px 偏移，是 R3 批「l1_polygon 改城块并集」的**语义差**，非错位） |
| 轴序（tiles / rivers / lakes / roads / neighbors） | 69 包全量无轴序反（换序打分全面更低）；邻块环修后 IoU 0.98~1.0 |
| 游戏渲染 ↔ 数据真值离线复刻（同变换采样逐像素比） | 中值差 3.6，>40 的像素 **1.88%**，且全部落在**描边/箭头/城市点**上——渲染忠实于数据 |

**真因（像素级定位，可复现）**

在地图坐标 `(371,285)` 一行横切（`python tools/worldgen/l1/audit_l1_fit_coast.py --labels 69` 同族判据）：

| 地图 x | 地形色 / g-b | `city_labels` | `legacy_l1` | `fractal_river_mask` | 源流群系 |
|---|---|---|---|---|---|
| 356~358 | 绿(109,143,78) 陆 | 1034 | 69 | 0 | 否 |
| **360~362** | **(76,127,150) g-b −0.09** | 1034 | 69 | 0 | **是** |
| **364~368** | **河色(46,102,140) g-b −0.149** | 1034 | 69 | **1** | **是** |
| 370+ | 海色(51,91,131) | **0** | **0** | 0 | 否 |

即：**几何（城块/省界/邻块环）走的是陆地蒙版 `locked_continent_8192` 的海岸线（x≈370）**；而**地形上色在岸线以内 4~11px 还画了一条浅蓝带**——它是 `biome_generate.apply_source` 的「**源流**」群系（河湖沿岸膨胀带，`source_band_px=1`@2048 → 8192 上 4~8px，色 `(95,160,195)`），沿这条入海河铺开，**视觉上与真水同色**（该带 g-b ≈ −0.13，与海水同号）。我第一轮的**水面回贴用绿-蓝差判水**，把这条带也判成水 → 把色块**涂掉**到浅蓝带内缘；描边仍沿几何画在外缘 → 两者之间露出 **p50 3px / p90 10px / 最大 19px** 的带（#69：边界落水点 1640 个，其中 >4px 者 610 个），这就是创始人看到的"不严丝合缝"。

> 结论一句话：**视觉水线（源流浅蓝带外缘）= 几何水线（陆地蒙版），但回贴线（颜色判水）在它内侧 → 色块边与描边错开一条浅蓝带。**

**修法（三档，按代价升序）**

| 档 | 做法 | 代价 | 效果 |
|---|---|---|---|
| **F1** | 回贴判水只认**真水色族**（海 near/far、湖 `72,116,158`、河 `46,102,140`）＋色相容差，排除源流浅蓝 `95,160,195` 及其与陆地混色 | 改 `map_renderer_tex_jobs.bake_water_restore` 一处 + 单测 | 色块回到陆地蒙版岸线，与描边重合 → 缝消失；河湖本体仍被回贴（第一轮诉求不回退） |
| **F2** | **判水改用量掩膜**：生成期把 `fractal_lake_mask\|fractal_river_mask` 按包窗口裁成 `l1_water_mask.png` 入包，运行时按掩膜 alpha 回贴，颜色口径退役 | 70 包各加一张掩膜 + 回贴读掩膜 | 彻底不猜颜色；湖河边界与地形同源（地形上色用的就是这两张掩膜） |
| **F3** | **口径收口**：源流膨胀带不再画成浅蓝（只在湖/河本体保留水色，沿岸带改陆地色或收窄到 2~3px），让"蓝=水"在全图成立 | 改 `biome_generate` + 重烘 70×2 张地形贴图（几何不动） | 地形水线 == 几何水线 == 回贴线，三源合一；L2/L3 同规则受益 |

**建议**：F1 先上（一小时级、立刻消观感），F2 随后（把颜色口径彻底退役）；**F3 需要创始人拍板一件设计口径**——「源流（河湖沿岸浅蓝带）」是要保留视觉表达，还是不再画成浅蓝？选前者就只做 F1+F2（浅蓝带会显示为"被色块盖住的浅蓝"，但与描边齐平，不再有缝）；选后者做 F1+F2+F3（"蓝=水"全图成立）。

**顺带查出的"重构对齐"遗留（供决策，不等于立即要修）**

1. **轴序是"按包族分两套"，靠 loader 各自记，不是文档错**（复查结论）：L1（出生包 + `l1_packs`）几何/河流/道路/湖 **`[x,y]`**（逐包实测：河流落水率 `[x,y]` 0.72~0.77 vs 换序 0.32~0.50，无一路反）；L2·L3 老字段 **`[y,x]`**（`l2_packs` 河流实测换序 0.82~0.92 vs 直读 0.30~0.62，确认 `[y,x]`）；`l3_l1.json` 的 polygons/centroid 亦 `[y,x]`。两套写法在 `l_world_bake.gd` 头部与 `世界地图数据流.md` 都注明了，且两个 loader 各自转序（`L1WorldData._polygon_from` 直读、`L2WorldData._to_vec2` 换序）——**实例自洽，但同一字段名两套轴序是长期隐患**（上一轮邻块环踩的就是它）。`世界地图数据流.md` §121/§126 两处备注与此一致，无需改。
2. **S1 细化场连通性断了**：`export_l1_view_context.py` 优先读 `output/l1_v2/refined_city_labels_8192.npy`，该文件实际在 `output/diag/l1_v2/`；`terrain_render.load_inputs()` 要的 `biome_labels_2048.npy` / `biome_hot_zone_2048.png` 同样只在 `output/diag/`。**导出器静默回退到未细化标签场；今天复烘地形会直接报错**——即"上一批对齐清账之后，全链没再复跑过"。
3. **L2 有海岸裁切步骤、L1 没有**：`tools/worldgen/l2_export/update_tiles_coastline.py`（按 8K 蒙版裁海岸线）只服务 L2/L1 tiles 链；L1 视图包几何直接沿用标签场（=沿用蒙版）。所以**只要地形侧口径统一（F1/F3），L1 不必重导几何**。

### 3.1 R3 残余：三岔口"灰线分叉"未完全消除

已查清的事实（都在下面命令里可复现）：

- 三块边界在交汇点**几何上严丝合缝**：`city_1036/1039/1040` 三块多边形共享同一顶点 `(330.25, 599.61)`（距 J 0.000px），近 J 边的最小线段距也 0.000px；`l1_polygon` 距 J 100px、无邻居/湖介入。
- 因此分叉**纯属渲染层**：三条闭合环各自在交汇处成折角，折角**外侧倒角沿各自方向外凸**（90° 折角外凸 ≈ 0.7×线宽），三条外凸尖并排 → 读作"分叉"。
- 已试：① 成链（`draw_polyline`，替代 `draw_multiline` 的逐段端点外伸）——**症状未消失**；② 交汇点同色补圆（`L1_JUNCTION_DOT_RATIO=0.8`，半径 0.8×线宽）——**明显减轻**（外凸尖被盖住），但交汇处仍有约 1px 的"双线重叠"感（两条相邻边界近平行进入交汇点，各自笔画略错开）。
- **候选解法（按代价升序，下会话择一验证）**：
  1. 补圆半径提到 ≥1.0×线宽并改用圆角端（把"双线重叠"也吃掉）——1 行常量，先试；
  2. 交汇点附近把重叠段**合并为单条**（构建期按顶点邻域裁掉 1~2 段）——需要几何处理，改动中等；
  3. **笔画并集**路线：`Geometry2D.offset_polygon` 把地块环外扩/内缩 w/2 求差得"描边带"，再 `clip_polygons` 求并集直绘一个多边形——几何上完美（无外凸尖、无重叠），但线宽是屏幕像素（÷zoom）→ 只能固定成**地图绝对宽**（放大时变细）或按 zoom 分档缓存；
  4. 反向：承认它是手绘折角风格，改为**圆角连接**（每段加圆点 → 视觉同 3.1.1）。

> 建议下会话把 R3 作为独立子任务派一个 agent：先按 1 试，不行就走 3（并记录 zoom 口径裁决）。

## 四、关键决策

| 决策 | 结论与理由 |
|---|---|
| 邻省色源 | 用**新烘侧表**（69 省主导政权 + 质心）而不是运行时加载 `l3_l1.json`（4MB）/8192 ID mask（67MB）；侧表 ~7KB，一次读盘 |
| 主导政权判定 | 块内政权 ID mask **众数**（去保留码 0/253/254/255；同票按 code 升序稳定取）；不做面积加权（像素众数即面积众数） |
| 方位判定基准 | **全局质心**（`l3_l1.json` 8192 尺度）：局部多边形被 context 裁切后质心偏心，会把方位带歪 |
| 「暗一阶」实现 | `Color.darkened(0.28)`，覆盖层 alpha 与本省**相同**（0.55）——"暗"落在色上，地形透出程度一致，两省才像同一张图 |
| 水面回贴口径 | 第一轮：判水 = 绿-蓝差阈值（**该判据已被 §3.0 推翻**——源流群系浅蓝带与真水同号）；**逐字节原样回贴**（不做抽样/不做矢量湖河描边——矢量湖与贴图湖边界不一致，反而制造新的"不严丝合缝"）。修正方向见 §3.0 F1/F2 |
| 切省 ESC 语义 | 切省**不改** `_drill_from_l2`（"从哪进来的"决定 ESC 行为），避免 Tab 直开切省后 ESC 误跳 L2 |
| 邻块轴序 | 以 `[x,y]` 为唯一口径（同地块/同全仓 L1 约定）；**改导出器 + 换序既有 70 包数据**，不在渲染端加"兼容读取"（否则下次重导出会双重翻转） |
| `l3_l1.json` 字段轴序 | 该文件 polygons 与 centroid **同为 `[y,x]`**（与 L2/L3 一致），消费侧一律转成 `[x,y]` 再存/再用；已在侧表导出器与测试里各留一处显式注释/断言 |
| 箭头数量与位置 | **一邻省一箭头**（表达"周围有多少邻省"），排在**地图内虚拟圆环**（锚地图坐标系、随缩放平移跟随）而不是屏幕左右——按创始人 2026-09-22 复核口径 |
| 三角体量 | 高 16 / 底 34（≈1:2）：底高接近 1 的三角形旋转后读不出朝向（第一版 22×26 实测被误读成反向） |
| 补圆 vs 并集 | 先上代价最低的补圆（外凸尖可见度最高）；笔画并集（`offset_polygon`）留作下会话候选（线宽÷zoom 口径需裁决） |
