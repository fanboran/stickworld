# 考点映射审计：stick-world × 勇仕笔试考点（2026-09-09）

> 审计方式：把《勇仕网络_客户端_押题清单》里的高频考点映射到 Godot/GDScript 等价反模式，
> 对 `stick-world/`（419 个 .gd，约 7.6 万行）做定向扫描 + 热点文件人工复核。
> 结论先行：**代码里高频踩雷区基本都躲开了（多处有注释证明是刻意设计）；
> 真正踩中的考点是 1 个（投射物无对象池），轻微 2 个。**

## 一、踩中的考点

### 1. 🔴 高频投射物无对象池（考点：Instantiate/Destroy vs 对象池，勇仕真题 Q25）

- 箭矢生命周期：`weapon_mount.gd:1001` 每次射击 `scene.instantiate()` → 命中/插地后
  `arrow_projectile.gd:106/226/242` `queue_free()`。
- 问题在"插身箭/插地箭"的存活窗口：`STUCK_LIFETIME = 4.0s` 淡出 + 爆头插身随尸体移动。
  96 人大战 + 多弓手时，同时存在"在飞 + 插地 + 插身"三类箭节点，
  Area2D 每支箭进/出物理树 = 节点分配 + 物理注册/注销的持续 churn。
- **改造方案（面试可现场讲）**：`ArrowPool`（autoload 或战斗域单例）持有
  `Array[ArrowProjectile]` 空闲栈；取 = pop + `visible=true` + 重入物理；还 = `visible=false` +
  `set_deferred("monitoring", false)` + push 栈，不 `queue_free`。插身箭绑定目标跟随逻辑不变，
  归还时清 `_registered_target`/断 `body_entered` 状态。
- 附带收益：`_ready` 里的 `body_entered.connect` 只发生一次，连接/断开开销同步消失。

### 2. 🟡 `_physics_process` 内节点查找（考点：热路径 GetComponent）

- `stickman_entity.gd:470`：死亡收口分支里 `get_node_or_null("Collider")`。
- 复核后**不是真热点**：外层有 `_dead_disable_timer >= 0.0` 门禁，每具尸体只触发一次，
  注释还写明了为什么不用 SceneTreeTimer lambda（捕获悬垂）——意识在线。
- 但模式上仍建议：这类一次性延迟操作用 `@onready` 缓存引用 + `is_instance_valid()` 判断，
  避免"热函数里出现 get_node"成为习惯。同函数 856/865/872 行的查找在 `_apply_scale()`
  （出生/变体时调用），非热路径，无需改。

### 3. 🟡 Tween 并发风险（考点：资源/动画生命周期）

- 全仓 `create_tween()` 39 处，`.kill()` 仅 4 处。Godot 4 的 tween 随节点销毁，**不泄漏**；
  但同一节点的同一属性（如 `modulate.a` 淡入淡出）被前后两个 tween 先后驱动时，
  旧 tween 未结束前会与新 tween 打架（终点值被覆盖后旧 tween 继续写）。
- 建议：对"同属性可重入"的动画（死亡淡出、受击闪白、UI 弹窗）用成员变量持有 tween，
  重入时先 `kill()`。优先排查 `fx/` 与 `stickman_entity.gd` 的受击/淡出路径。

## 二、考点巡检通过项（带证据）

| 考点（押题清单） | Godot 等价 | 项目现状 |
|---|---|---|
| 缓存 GetComponent，别在 Update 查 | `@onready` 缓存 | `stickman_entity.gd:235-237` 用 `@onready` 缓存 HealthComponent/Hitbox/WeaponMount |
| 相机跟随放 LateUpdate（时序） | 相机更新时机 | `camera_rig.gd:118/156` 相机在 `_physics_process` 且注释写明"与实体物理帧同步避免渲染重影"——是论证过的选择，非随手写 |

| 观察者/事件订阅泄漏 | signal 连接/断开 | `battle_instance.gd:427` 显式断 EventBus 防 freed 悬垂；`weapon_mount.gd` 连接前 `is_connected` 判重 |

| LOD/降频意识 | 死亡收口 | `stickman_entity.gd:458` 尸体不跑 AI/分离/击退、碰撞延迟禁用、尸体定时淡出防堆场 |
| UI 别每帧重建 | 事件驱动刷新 | `battle_panel.gd/formation_panel.gd` 重建全部由 selection/squad 变更信号触发，非每帧 |

## 三、面试弹药映射（喂给《面试防御手册》）

1. **"讲一个你自己项目的性能优化"** → 空间索引 query_neighbors 替代全场 O(n²) 索敌 +
   尸体收口（死亡即停 AI/物理，战场 96 人不越打越卡）。
2. **"对象池怎么设计"（勇仕真题）** → 先答通用结构（空闲队列+在用集合+归还重置），
   再接"我项目里的待改造点就是箭矢"——现状 instantiate/queue_free，插身箭 4s 存活窗口
   放大 churn，池化方案如上（讲出"物理注册/注销才是大头"这层就是加分）。
3. **"事件系统会不会泄漏"** → EventBus 退订防 freed 悬垂 + lambda 捕获两个实战案例。
4. **"Update 和 FixedUpdate 区别"（勇仕原题）** → 直接用自己的话讲相机为什么挂在物理帧：
   语义=Unity 的 LateUpdate 抉择，理由=跟随目标位置在物理帧写入，避免渲染重影。
