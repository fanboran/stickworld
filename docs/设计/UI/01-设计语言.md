# 01 · 设计语言

> 视觉系统的设计原则与 token 总表。所有常量的**代码真相源**是
> `modules/ui_global/scripts/templates/theme/stick_tokens.gd`（StickTokens），
> 本文是设计意图与使用纪律；数值以代码为准。

---

## 一、视觉哲学

### 1.1 窗户不是海报

界面是一块**纯黑半透明的玻璃窗**：游戏画面从面板底下透出来，玩家永远不"离开"世界。
参考《僵尸毁灭工程》——面板没有海报式的美术底图，只有黑底、细描边、文字。

**为什么**：
- 本作是"无缝缩放"游戏，玩家在 Micro↔Strategic 间连续滑动，界面若是不透明海报，
  每次开合都是一次"出戏"；玻璃窗让观察与操作同时成立。
- 世界观：火柴人由**黑色沥青**构成，黑是世界观底色，黑底 UI 是天然延续而非风格选择。

### 1.2 一个强调色

全套 UI 只有**一个强调色：琥珀**（火光色）。用于且仅用于：

| 用途 | 例子 |
|------|------|
| 主行动点 | 新游戏 / 确定 / 应用 |
| 选中态/激活态 | 当前标签页、当前速度档、选中列表项 |
| 关键数值 | 资源图标、摘要统计数字 |

危险（红）、警告（黄）、信息（蓝）、成功（绿）是**语义色**，只出现在反馈场景
（通知、删除按钮、不足提示），不参与装饰。强调色滥发会导致玩家无法一眼找到"该点哪"。

### 1.3 信息密度服从层级

- 微观层级（L1/L2）：UI 稀疏、字大、只显示个体相关信息
- 宏观层级（L4/L5）：UI 密集、字小、允许报表式排布
- 快捷栏等"操作区"鼓励**密集堆叠**（《博德之门3》技能栏式满足感）

## 二、色彩 Token

### 2.1 基底

| Token | 值 | 用途 |
|-------|-----|------|
| `WINDOW_BG` | 黑 88% 不透明 | 大面板/弹窗底（主窗体） |
| `WINDOW_BG_LIGHT` | 黑 72% 不透明 | HUD 横条/内嵌区块（更透的玻璃） |
| `MODAL_DIM` | 黑 60% 不透明 | 全屏模态遮罩（压暗游戏画面） |
| `GROOVE_BG` | 黑 45% 不透明 | 输入框/滑条凹槽底 |

### 2.2 描边

| Token | 值 | 用途 |
|-------|-----|------|
| `BORDER` | 白 16% 透明 | 常规 1px 描边 |
| `BORDER_STRONG` | 白 38% 透明 | 悬停/聚焦态 |

### 2.3 文字

| Token | 透明度 | 用途 |
|-------|--------|------|
| `TEXT` | 100% | 正文/按钮 |
| `TEXT_DIM` | 55% | 辅助说明 |
| `TEXT_FAINT` | 32% | 占位符/角标 |
| `TEXT_DISABLED` | 25% | 禁用态 |

### 2.4 语义色

| Token | 色 | 纪律 |
|-------|-----|------|
| `ACCENT` | 琥珀 | 唯一强调色，见 §1.2 |
| `DANGER` | 红 | 删除/战败/错误通知 |
| `WARN` | 黄 | 资源不足/警告通知/数量徽标 |
| `INFO` | 蓝 | 信息通知/链接 |
| `SUCCESS` | 绿 | 完工/增益 |

### 2.5 按钮态底色

按钮底色 = 白色叠加：`BTN_BG` 7% / `HOVER` 15% / `PRESSED` 4% / `DISABLED` 3%。
在黑玻璃上叠加白色薄层产生"浮起"感，不引入新色相。

## 四、形状与间距

| Token | 值 | 说明 |
|-------|-----|------|
| `RADIUS` | 3 | 通用圆角（接近直角的"冷"感） |
| `RADIUS_PANEL` | 6 | 大面板圆角 |
| `BORDER_W` | 1 | 描边宽度（始终 1px，不用粗边框） |
| `PAD_X` / `PAD_Y` | 12 / 6 | 控件内边距 |
| `BTN_H` 系列 | 26 / 32 / 44 | 小/标准/大按钮高度 |
| `ROW_H` | 36 | 设置/菜单行高 |

间距系统：容器 separation 只取 4 / 6 / 8 / 12 / 16 五档。

---

## 五、动效

| Token | 值 | 用途 |
|-------|-----|------|
| `T_FADE` | 0.12s | 悬停/渐隐渐显 |
| `T_PANEL` | 0.18s | 面板开合 |
| `T_TOAST` | 3.0s | 通知停留 |

纪律：动效只做**透明度和位移**，不做缩放弹跳（与"玻璃窗"气质冲突）；
缩放渐隐渐显（连续缩放时 UI 按层级淡入淡出）是核心动效，见
[04-游戏内HUD](04-游戏内HUD.md) §四。

## 六、图标

现状：`assets/ui/` 为空，模板用**单字占位**（木/石/铁/沥/剑/盾…）。

图标资产规范（入库时执行）：

| 项 | 规范 |
|----|------|
| 风格 | 单色（白）线性素描，火柴人式极简线条 |
| 尺寸 | 16×16 基准，导出 16/24/32 三档 |
| 着色 | 运行时用 `modulate` 上语义色，资产本身纯白 |
| 存放 | `assets/ui/icons/`，命名 `ic_<域>_<名>.png`（如 `ic_res_wood`） |

## 七、与"按层级演变的美术风格"的关系

上游规范提出 L1-L2 石头面板 → L3 羊皮纸 → L4-L5 全息投影的风格演变。
落地方案：**结构上永远只有这一套黑窗 UI**，层级风格做成**主题变体**
（换 token 包 + 描边/底纹材质包），不另起组件体系。详见
[08-拓展性](08-拓展性.md) §二。
