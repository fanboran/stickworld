# benchmark_brains —— 自对弈迭代选手库

「下一版算法必须稳定战胜上一版」的选手脚本都放这个目录。设施构成：

- `bench_brain_base.gd`：选手基类 = 战场观察助手 + 个人级/编制级命令门面（协议与自由度分层见其头注释）。
- `../diag_arena_benchmark_driver.gd`：胜负判定（有效战力先归零方负、超时按剩余战力）、换边轮换（挑战者一半场次在攻方一半在守方）、稳定战胜线（默认 65%）。
- `../diag_arena_metrics_driver.gd`：过程指标（疲于奔命率/追逐翻转/均匀度 CV），胜率之外看打法是否真变好。

## 迭代流程

1. 把现任卫冕者的脚本路径填进 driver 的 `BRAIN_B`（首任卫冕者 = 内嵌默认 AI，即 `BRAIN_B` 留空）。
2. 写挑战者 `my_brain_v2.gd`（继承/duck 复用 base），填进 `BRAIN_A`。
3. **并行跑 Benchmark（正用形态，多核并行纯后台）**：

   ```bash
   python stick-world/tests/dev/benchmark_brains/run_parallel.py --battles 8 \
       --brain-a res://tests/dev/benchmark_brains/my_v2.gd
   ```

   每场一个无头 Godot 进程（剔除全部视觉装配：`char_sprite_3d` headless 豁免 +
   `--headless` 无 GPU + battle_sim 批模拟内核），半数场次换边消除占位偏差，
   结束输出胜率/左右偏置/稳定战胜线判定。
4. 胜率 ≥ 65% → 挑战者接替卫冕者（`BRAIN_B` 换成它），否则回炉。
5. 接受者把脚本路径登记进本 README 的「历任卫冕者」表，形成可追溯的进步链。

## 封装层铁律

选手与**附身玩家同权**，分两面：【观察面全开】玩家画面上能看到的一切（单位位置/
血量/旗点/战局）选手都能经观察接口拿——信息面与玩家等价，不算作弊；【操作面只走
接口】只能经基类命令门面下指令，禁止直改内部状态（玩家做不到的事都不行）。改封装
层内（接口语义不变）随便改；改封装层外（改变可做之事）必须先立接口契约。
