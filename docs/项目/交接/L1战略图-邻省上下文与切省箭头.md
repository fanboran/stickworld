### R1 邻省 = 地形 + 暗一阶政权色

- **取色**：`MapRenderer._Geo.neighbor_block_color()`（在 `map_renderer_geo.gd`）= `侧表色.darkened(L1_NEIGHBOR_DIM)`；侧表无该省 → 回退 `L1_NEIGHBOR_COLOR` 平灰。
- **绘制**：邻块 mesh 与本省同 alpha（`POLITICAL_FILL_ALPHA` 0.55）——周边是"地形上的政权色"，与本省连成一张图。
- **数值自证**（渲染图反推覆盖色，见 §五 命令）：邻省 #68 实测覆盖色 `(170,97,59)` vs 期望 `(169,96,60)`；#67 实测 `(1,73,91)` vs 期望 `(0,72,93)`；本省城邦5 实测 `(183,130,0)`（未压暗，与 #68 拉开一档）。

### R4 「色块与地图严丝合缝」

第一轮落地的是**渲染侧治标**（其判据解释已被审计推翻，真因与治本方案见 §3.0）：

1. **沿岸溢出**：地块多边形边界在地形可见水线之外——第一轮实测 median 8px / max 39px（zoom 1.15 屏幕像素）。
2. **湖河被吞**：地块多边形含地块内水体，政治覆盖层把地形里的湖/河一起染色。
3. **收敛手段 = 水面回贴 pass**：后台线程从地形贴图烘一张 RGBA 贴图（RGB = 地形原色、A = 判水量），政治模式在覆盖层之上原样贴回。
   - 判水用绿-蓝差（阈值 `L1_WATER_GB_MID=-0.06` ± `0.03` 过渡带）——**该判据把"源流"群系的浅蓝河湖沿岸带也判成水，是复审仍有缝的直接原因**。
   - **步长必须为 1**（`L1_WATER_STRIDE=1`）：抽样后线性过滤会把水色与邻近陆色混出一道浅带。
   - 逐字节自证：真水像素回贴后与地形**完全相同**（dev=0）。
4. **邻界缝**：地块多边形各自平滑后相邻边有 1~2px 不共线 → 政治界宽 `L1_POLITICAL_TILE_BORDER_WIDTH=3.0`（比常驻灰界 2.0 粗一档）盖住缝。

### R2b（第二轮新增）邻块多边形轴序缺陷 —— 「色块像被对角轴翻转」

**症状（创始人原话）**：「国家染色地块甚至方向反了，像是被左上右下的对称轴翻转后的效果」。

**根因**：`export_l1_view_context.py` 写邻居块时**漏了 `to_xy`**——mesh_extract 输出的环是 `(y,x)` 角点，而 L1 数据格式全仓统一 `[x,y]`（`l_world_bake.gd`「L1：原样序列化 [x,y]」、`L1TileDef._polygon_from`）。所以每包的 `neighbors[].polygons/holes` 是 `[y,x]`，渲染端按 `[x,y]` 读 → **邻块整体沿主对角轴（左上↔右下）翻转**。涂灰时只是形状不对看不出来，本轮邻省上色后立刻暴露。

**跨包确认**：抽 8 包 26 个邻块，全部「读作 `[y,x]` 才落在按全球裁窗的期望 bbox 内」（读作 `[x,y]` 全错）；全量自证 435 个可判邻块。

**修复（两层）**：
1. 导出器：`polygons/holes` 都过 `to_xy`（防再犯）；
2. 既有数据：`tools/worldgen/l1/fix_neighbor_axis_l1.py` 对 70 包逐点换序（含被启发式漏判的 3 包 l1_004/l1_034/l1_041 单独补修）→ 重烤 `l1_world.bin` 70+1 份（`l_world_bake.gd`，L2/L3 的 bin 重烤后字节不变）。
3. 同一类坑的第二处：`l3_l1.json` 的 **centroid 字段也是 `[y,x]`**（与 polygons 同序）——侧表首版照 `[x,y]` 读，导致箭头方位也沿对角轴翻转（创始人同一条反馈的另一半）。已在 `export_province_politics.py` 换序并重出侧表；`test_province_politics` 加了守门断言（出生省质心必须落在本包 context 窗口内 + 三邻省方位为东北/西北/正西）。

**验证**：修复后出生省三邻省落位 = #67 西北 / #68 正西 / #18 东北，与世界地理一致（见 §五 新图）。

### R2 切省箭头环（第二轮定稿形态）

- `modules/world_map/ui/province_switch_arrows.gd`（`class_name ProvinceSwitchArrows`）：根 = 全屏 Control（`mouse_filter=IGNORE`，不挡地图拖拽），**每邻省一个**箭头子控件（`MOUSE_FILTER_STOP`）。
  - 形：**扁等腰**（高 16 / 底 34，≈1:2）——底高比接近 1 的等边三角形旋转后读不出朝向（第一版 22×26 就被我本人误读成反向），扁形才有明确指向。
  - 位：**地图内虚拟圆环**——圆心 = context 中心、半径 = 边长 × `ARROW_RING_RATIO`(0.40)；箭头随地图缩放/平移跟随（`screen_pos_fn` 每帧把地图坐标换屏幕坐标），始终在地图内、不压中心内容。
  - 向：**背离圆心**，即按 `angle = atan2(dy, dx)`（该省全局质心相对本省）旋转，箭头指向该省真实方位。
  - 色：填充 = 该省主导政权色（与邻块暗一阶色同源族），悬停提亮；tooltip「切到相邻省份 #N · 政权名」。
- **方位判定**：控制器 `_arrow_ring_config()` 用侧表**全局质心**（`l3_l1.json` 尺度）——不用被 context 裁过的局部多边形，避免方位偏心；侧表无该省 / 无包数据 → 不出该箭头（不留死箭头，数量随邻省集走：出生省 3 个、大包最多 17 个）。
- **切省**：`StrategicMapController.switch_province(label)`：`api.open_l1(label)` → 重置视角适配新 context → 刷新指示器/名牌/图例/据点/箭头环。
  - **语义约束**：切省**不改** `_drill_from_l2` —— ESC 行为跟着"从哪进来的"走（Tab 直开切省后 ESC 仍关闭地图；L2 下钻后切省 ESC 仍返回 L2）。
  - `open()` 拆出 `_reset_view_for_current_l1()` / `_refresh_view_meta()` 两个复用件（切省与打开共用，行为不变）。
- **api 契约新增**：`has_l1_data(label) -> bool`（出生省=根数据、其余=查 l1_packs 包），箭头只列可打开的目标。

### 3.1 R3 残余：三岔口"灰线分叉"未完全消除

已查清的事实（都在下面命令里可复现）：

- 三块边界在交汇点**几何上严丝合缝**：`city_1036/1039/1040` 三块多边形共享同一顶点 `(330.25, 599.61)`（距 J 0.000px），近 J 边的最小线段距也 0.000px；`l1_polygon` 距 J 100px、无邻居/湖介入。
- 因此分叉**纯属渲染层**：三条闭合环各自在交汇处成折角，折角**外侧倒角沿各自方向外凸**（90° 折角外凸 ≈ 0.7×线宽），三条外凸尖并排 → 读作"分叉"。
- 已试：① 成链（`draw_polyline`，替代 `draw_multiline` 的逐段端点外伸）——**症状未消失**；② 交汇点同色补圆（`L1_JUNCTION_DOT_RATIO=0.8`，半径 0.8×线宽）——**明显减轻**（外凸尖被盖住），但交汇处仍有约 1px 的"双线重叠"感（两条相邻边界近平行进入交汇点，各自笔画略错开）。
- **候选解法（按代价升序，下会话择一验证）**：
  1. 补圆半径提到 ≥1.0×线宽并改用圆角端（把"双线重叠"也吃掉）——1 行常量，先试；
  2. 交汇点附近把重叠段**合并为单条**（构建期按顶点邻域裁掉 1~2 段）——需要几何处理，改动中等；
  3. **笔画并集**路线：`Geometry2D.offset_polygon` 把地块环外扩/内缩 w/2 求差得"描边带"，再 `clip_polygons` 求并集直绘一个多边形——几何上完美（无外凸尖、无重叠），但线宽是屏幕像素（÷zoom）→ 只能固定成**地图绝对宽**（放大时变细）或按 zoom 分档缓存；
  4. 反向：承认它是手绘折角风格，改为**圆角连接**（每段加圆点 → 视觉同 3.1.1）。

> 建议下会话把 R3 作为独立子任务派一个 agent：先按 1 试，不行就走 3（并记录 zoom 口径裁决）。

## 四、关键决策

| 决策 | 结论与理由 |
|---|---|
| 邻省色源 | 用**新烘侧表**（69 省主导政权 + 质心）而不是运行时加载 `l3_l1.json`（4MB）/8192 ID mask（67MB）；侧表 ~7KB，一次读盘 |
| 主导政权判定 | 块内政权 ID mask **众数**（去保留码 0/253/254/255；同票按 code 升序稳定取）；不做面积加权（像素众数即面积众数） |
| 方位判定基准 | **全局质心**（`l3_l1.json` 8192 尺度）：局部多边形被 context 裁切后质心偏心，会把方位带歪 |
| 「暗一阶」实现 | `Color.darkened(0.28)`，覆盖层 alpha 与本省**相同**（0.55）——"暗"落在色上，地形透出程度一致，两省才像同一张图 |
| 水面回贴口径 | 第一轮：判水 = 绿-蓝差阈值（**该判据已被 §3.0 推翻**——源流群系浅蓝带与真水同号）；**逐字节原样回贴**（不做抽样）。**该口径整体退役**：治本方案改为几何贴陆 + 水体矢量后处理，回贴整段删除（方案 §L3） |
| 切省 ESC 语义 | 切省**不改** `_drill_from_l2`（"从哪进来的"决定 ESC 行为），避免 Tab 直开切省后 ESC 误跳 L2 |
| 邻块轴序 | 以 `[x,y]` 为唯一口径（同地块/同全仓 L1 约定）；**改导出器 + 换序既有 70 包数据**，不在渲染端加"兼容读取"（否则下次重导出会双重翻转） |
| `l3_l1.json` 字段轴序 | 该文件 polygons 与 centroid **同为 `[y,x]`**（与 L2/L3 一致），消费侧一律转成 `[x,y]` 再存/再用；已在侧表导出器与测试里各留一处显式注释/断言 |
| 箭头数量与位置 | **一邻省一箭头**（表达"周围有多少邻省"），排在**地图内虚拟圆环**（锚地图坐标系、随缩放平移跟随）而不是屏幕左右——按创始人 2026-09-22 复核口径 |
| 三角体量 | 高 16 / 底 34（≈1:2）：底高接近 1 的三角形旋转后读不出朝向（第一版 22×26 实测被误读成反向） |
| 补圆 vs 并集 | 先上代价最低的补圆（外凸尖可见度最高）；笔画并集（`offset_polygon`）留作下会话候选（线宽÷zoom 口径需裁决） |
