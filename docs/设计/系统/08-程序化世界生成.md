## 〇、设计原始要求（创始人输入存档）

> 本节逐条记录创始人对程序化世界生成的原始设计要求，作为后续实现的约束真相源。任何实现偏离本节需经创始人确认。

### 0.1 素材策略（取代"AI 直出大图"）

- **不采用** AI 一次性生成完整世界大地图：太随机、粗糙、美术风格不统一、反复抽卡。
- **改为**：AI 生成可拼接的小素材 → 人工挑选（当质检员）→ 程序当装配工。
- 程序化生成各城镇/城市的**游戏内地图**，以及整个世界用于观看的**世界地图画布**。

### 0.2 三级地图层级

| 层级 | 名称 | 对应现实 | Demo 进度 |
|------|------|----------|-----------|
| L3 | 大世界（World） | 一个大陆 + 周围海洋 | 纯线条/文字可视化，验证算法 |
| L2 | 地区（Region）/ 城市群 | 省级 / 城市群 | 程序化生成 |
| L1 | 地块（Tile） | **地级市**（不是省） | **Demo 优先解决**：一个城市 + 周围乡村 |

- 三个层级**都需要程序化生成**。
- **子地图外边界轮廓必须与母地图该地区的轮廓保持一致**（层级细分一致性）。

### 0.3 地块划分方式

- **自然、不规则**的地块划分（非固定网格）。参考 P 社 / Azgaar 的不规则省份。

### 0.4 地区层级（L2）要求

- 整个地区**基本上是一个气候**，但不排除局部变异（南草北水）--气候变异**天然形成**（温湿噪声局部极值），不强制。
- 地区类似**行政区划**：在大世界地形图上切割为若干地区，**尽量山地归山地、平原归平原**（地形同质化）。
- 但**经济耦合**优先：如水乡难以单独存在、与背后平原紧密联系（彼此经济互赖），即便分属不同政权互相战争，也应**划入同一地区**。
- 地区是游玩时**相对完整的行政区划单位**。
- **地区-政权关系**（见 §5.5、§15.7）：
  - 小政权：占一个地区，或几个小政权**挤在一个地区**（相似度高=同文化=联盟候选）。
  - 大政权（帝国）：横跨多个地区；多数时候拥有完整地区，或地区边界与帝国相符。
  - 若一个地区被**两个大政权**分割 -> 沿政权边界**切分为两个地区**。
  - 几个小政权共占一地区 -> **不切分**（本就是碎的预期状态）。
- 地区界面：在对应地块中心显示 **Q 版小缩略图标**，对应地块的主要建筑/景观（大矿坑、魔力源泉等）。

### 0.5 地块层级（L1）要求

> 本节"地块"指 **L1 地图**（玩家第一阶段世界图，= L2 的下辖地块，含 8 个 L1 地块/聚落）。"1 个 L1 地块只有 1 个聚落"见 §0.19。

- 一个 L1 地图内只有**一个中心城市聚落**，通常占据 L1 地图的中心 L1 地块。
- 中心城市位置例外：若靠山 → 可能是矿山城市（位于 L1 地图边缘）；若靠河 → 可能是渔业城市（位于 L1 地图边缘）。
- 中心城市**有城墙**。
- 周围有次级聚落（镇/部落/村落），**聚落数量不固定**，取决于周围资源禀赋和 L1 地图实际大小：可能一两个，也可能大平原上七八个（如 8 城邦标准样本：1 城 + 2 镇 + 5 部落）。
- **相当一部分资源禀赋够的地方也没有聚落**（有资源但无人定居 → 空 L1 地块）。
- 玩家有需求（如军事需求）时**可建造新聚落**（在空 L1 地块上，沿用现有建设系统）。
- 次级聚落一般很小（部落/村落规模），**偶尔出现一个大部落级别的聚落**。
- 部分地区过于贫瘠：**一个城市级别的聚落都没有**（全部是村落级，或干脆有聚落但无城市）。
- 部分地区过于富庶：**有两个城市级别的聚落**，但中心城市仍然只有一个（对标辽宁沈阳 vs 大连）。
- L1 地图对标的是**地级市**而非省：一个 L1 地图内可能有多个县城级聚落，部分县城发展程度可能和地级市差不多。

### 0.6 聚落规模与级别

- 常规建筑有 **4 种**，分别对应 **4 种级别的聚落**。
- **帝国首都的建筑另行单独设计**（不走常规 4 级）。
- 生成时先**计算聚落的大概规模**；规模大到一定程度就是城市。
- 不同规模的聚落可能是**数量级级别的差距**。
- **先预设好聚落级别**，再在该级别内部的规模上下限内生成。
- **绝大部分聚落偏向下限**（现实中大人口聚落很少）。

### 0.7 城市级聚落的支柱产业

- 一个城市级别的聚落通常有**一个或多个支柱产业**：采矿、贸易等。
- 甚至可能**单纯作为帝国的前线战争堡垒和要塞**、重要的前哨站、或一个考察点。

### 0.8 地形对聚落的影响

- 部分地形（如高原）可能使**整个地块或地区的整体聚落规模甚至密度都偏小**。

### 0.9 核心设计疑问（待本文档回答）

> "该怎么科学地生成自然的？从资源开始生成层层叠叠上去然后再根据资源禀赋生成城市吗？那由于绕了很大一弯子很难让我前面的约束设计出来；直接按照我的约束生成吗？那可能太不自然了，即便我的约束已经考虑了一部分自然条件，但我很难穷举。虽说是程序化生成，但其实毕竟不是开放世界，对应的随机生成其实更一次性的。"

→ 本文档 §三 给出答案：**分层适宜度模型 + 可注入设计意图**（既不纯资源推、也不纯约束摆）。

### 0.10 大世界层级（L3）Demo 要求

- 大地图 Demo 版**所有元素用纯线条和文字描述可视化**，勉强可视化即可，用于检验生成算法打磨到位。
- **只需把地形、地块群系、河流、海洋生成明白**即可。
- 大世界是一整个大陆，**周围一圈海洋**。
- 大陆地形**最好复杂一点**。
- 最高层级的程序化生成**随机味不要那么重**。
- **先给一个随机程序批量生成大陆轮廓，创始人选定一个大致构型作为后续细化的模板**。
- 参考网上自制架空世界地图的方案和开源程序方案。

### 0.11 边界一致性

- 子地图生成的**外边界轮廓要和母地图该地区的轮廓保持一致**。

### 0.12 聚落间道路

- 聚落间需要生成道路连接。

### 0.13 政权与联盟（神罗式碎国）

- 生成各政权的大致规模和边界。
- 国家规模**略小**；整块大陆要有**多个联盟或单一政权**。
- **联盟** = 同文化的多个小王国集合，外人视为完整单一国家（神罗式）；便于初期扩张。
- 不排除有**庞然大物的单一政权**，但也没多大，**不可能有占小半块大陆的初始国家**。
- **Demo 出生地区内一定要有好几个小政权**，要更碎一点。

### 0.14 后处理与多职能

- 生成完国家后**后处理微调**各聚落的规模和职能。
- 确定聚落在该国家内的**大致重要程度**，影响其他细节生成。
- 部分城市可**多个职能**（如水城 + 河军事重镇）。
- 部分地区**不需要堆军事力量**（如一片难以跨越的地形保护的内部）。
- 贫瘠地块（沙漠等）可能整地块就一两个小村庄级聚落，**这两个小村庄当"首富"**（地块事实中心）。

### 0.15 每局轻微随机（仅规模）

- 位置扰动、控制区边界重划、±1 聚落：**全部作废**。
- 仅聚落**规模**可在 ±15% 范围内扰动（出生村落+中心城市免疫）。
- 地形/政权/聚落数量/位置/级别/控制区边界：开发期抽卡定死后**永不再变**。

### 0.16 出生点规格

- 出生地区：**标准平原**，有河流、小点的山、贸易。
- 出生 L1 地图：**偏标准**——1 个中心城市聚落 + 6-7 个次级聚落（共约 7-8 个聚落，各占一个 L1 地块，对标 8 城邦标准样本）。
- 出生聚落：其中一个次级聚落（村落），位置/规模固定（免疫每局扰动）。
- 出生地区政权：强制多个小政权（更碎），便于初期扩张。
- 地块层面实际游玩时，以**行政区划（聚落）为单位**进行操作。

### 0.17 地图结构（已确认）

- 世界地图上聚落是 L1 地块内的唯一子单元（1 个 L1 地块 = 1 个聚落或空聚落，§0.19）；进入聚落后抽象为纯横版世界（横向卷轴矩形）。边界一致性作用于 L3->L2->L1 领土多边形，可玩聚落地图为矩形游戏投影。

### 0.18 生成定位（开发期工具，非运行时）

- 程序化生成是**开发期工具**：用程序化方法保证生成更自然，不是为了反复生成。
- 开发者抽卡（不满意可重抽几次），定下来后**永不再改**，随包发布。
- 送到玩家手里的地图已**几乎完全定死**，起码地形固定。

### 0.19 聚落模型（地块-聚落关系）

> 聚落模型没有推翻"1 中心城市 + 若干村落"的旧模型，而是明确了它作用的层级。注意区分两个概念：**L1 地图**（玩家第一阶段世界图，= L2 的下辖地块）与 **L1 地块**（L1 地图内部的聚落领地，= 战略图上的最小地块）。

**层级关系（省市区式，逐级下辖）**：

- **L3 大世界（省）** = 若干 L2 地区的集合
- **L2 地区（市）** = L3 的下辖地块；L2 内部 = 若干 L1 地图
- **L1 地图（县/郡级）** = L2 的下辖地块（用户原话："L1 是 L2 的地块，L2 也是 L3 的下辖地块"）；**L1 地图 = 玩家第一阶段的世界图**，玩家出生并统一的整张战略图视图
- **L1 地块（乡镇级）** = L1 地图内部的最小地块 = **聚落领地**；P0 战略图上程序化随机边界画出的"地块"即 L1 地块
- **世界观揭晓**：统一 L1 地图后才揭晓"L1 地图只是 L2 的一个小地块"（L1 ⊂ L2 ⊂ L3）

**聚落模型**：

- **1 个 L1 地块永远只有 1 个聚落（或空聚落）**：聚落与 L1 地块一一映射，一个聚落独占一个 L1 地块，L1 地块之间不共享聚落。
- **"1 中心城市 + 若干村落"旧模型的作用范围是 L1 地图**：整个 L1 地图（第一阶段世界图）作为一个"中心城市 + 若干小聚落"的复合体——L1 地图内有 1 个中心城市聚落 + 若干次级聚落（镇/部落/村落），**每个聚落各自占一个 L1 地块**。
- **8 城邦整体 = 一个标准的 L1 地图**：8 个聚落规模各异，标准构成样本为 **1 城市规模 + 2 镇规模 + 5 部落规模**（= 8 个 L1 地块，作为标准 L1 地图内部分布样本）；实际构成由当前 L1 地图的规模和资源禀赋决定（适宜度模型自然涌现，§三），但**终归要有一个中心城市**——极端贫瘠时，"没几个人的小村落"即充当中心城市。
- **8 个聚落相互独立、无更高级公共首领**：彼此是相互依存的松散文明（类似古希腊城邦），属于早期文明形态。
- **玩家 = 搅动混乱的角色**：出生在其中一个聚落，第一阶段目标是统一整个 L1 地图（8 个城邦）。
- **贫瘠 L1 地块**：可能没有聚落（无聚落、无建筑、无人）；或在代码层面是一个 **"空聚落"占位**（有 ID/位置、无人无建筑、不可进入）。
- 一个聚落只对应 **1 张可玩主场景图**（横向卷轴），无"聚落周边小场景/附属场景"。超大建筑室内（MEGA_INTERIOR）作为独立场景图类型保留，但不属于聚落的附属场景。
- 玩家运行时只有：聚落规模 ±15% 扰动（§0.15）+ 按需生成可玩聚落地图（从锁定种子，确定性）。

## 一、核心理念

程序化生成的铁律是**确定性**：同一 `world_seed` 必须产出同一世界。一切生成器从根种子派生子种子，形成种子树。

```
WorldSeed (根)
├── continent_seed      -> 大陆轮廓 + 板块 + 地形
├── world_map_seed      -> L3 划分（地区）+ 生物群落 + 河流
│   └── region_seeds[]    -> 每个地区一个子种子 -> L2 划分（地块）
│       └── tile_seeds[]    -> 每个地块一个子种子 -> L1 聚落布局
└── settlement_seeds[]  -> 每个聚落一个子种子 -> 横向卷轴可玩地图
    └── chunk_seeds[]     -> 每个 chunk 一个子种子
```

## 二、三级地图层级总览

| 层级 | 几何形态 | 内容 | 生成产物 | 可视化（Demo） |
|------|----------|------|----------|----------------|
| **L3 大世界** | 大陆轮廓 + Voronoi 地区多边形 | 大陆/海洋/山脉/河流/生物群落/地区划分 | `continent_mask.png` + `WorldMapData` | 纯线条+文字 |
| **L2 地区** | 地区多边形内受限 Voronoi 地块多边形 | 地块群系/气候/Q版地标图标/聚落点位 | `RegionData` + 地块多边形 | 纯线条+图标 |
| **L1 地块** | 地块多边形内聚落布局 | **1 个 L1 地块 = 1 个聚落（或空聚落）**；L1 地图 = 1 中心城市 + 若干次级聚落的复合体（各聚落各占一个 L1 地块） | `TileData` + 聚落列表 | 纯线条+图标 |
| **可玩聚落** | 横向卷轴矩形（游戏投影） | 建筑三层/装饰/障碍/Chunk | `MapDefinition.tres` → `VillageMap` | 现有渲染 |

**地图结构（已确认）**：三个"世界地图"层级（L3/L2/L1）是多边形领土的鸟瞰图，**1 个 L1 地块 = 1 个聚落（或空聚落）**，聚落是 L1 地块内的唯一子单元；**进入聚落后抽象为纯横版世界**（横向卷轴矩形，沿用现有 VillageMap），**1 个聚落 = 1 张主场景图**（§0.19）。边界一致性约束作用于 L3->L2->L1 的领土多边形细分（§八），可玩聚落地图为矩形游戏投影，不强制多边形边界。

> **聚落模型速查**：L1 地图（= L2 的下辖地块，内含若干 L1 地块/聚落）⊂ L2 地区 ⊂ L3 大世界。L1 地图 = 玩家第一阶段世界图 = "1 中心城市 + 若干次级聚落"复合体（§0.19）。

## 三、生成哲学：分层适宜度模型 + 可注入设计意图

### 3.1 回答创始人的核心疑问

既不"纯资源推聚落"（绕弯子、约束难施加），也不"纯约束直接摆"（不自然、难穷举）。

**答案是：自然层驱动适宜度场，约束作为可注入的偏置/保证叠加其上，聚落从偏置后的场中采样涌现。**

这是 Dwarf Fortress / RimWorld 世界生成 / Azgaar 聚落生成的通用范式：
- 地理（地形/气候/河流/资源）是**纯自然层**，确定性生成，不含任何聚落。
- 聚落位置由**适宜度场**决定，适宜度从自然层派生——所以"自然"。
- 设计约束（"这地区要有前线要塞""这地块中心城市靠山"）作为**偏置**或**保证项**注入，不替代自然，只扭曲概率——所以"约束可施加"。
- 聚落从偏置后的场采样，带间距约束 + 级别分桶 + 下限偏置——所以"涌现且可控"。

### 3.2 适宜度场

每个候选位置计算一个连续 `suitability` 分数：

```
suitability = w1 * water_access        # 近河/湖/海岸
            + w2 * arable_score        # 可耕地（平原+适宜温湿）
            + w3 * resource_score      # 周边资源禀赋（矿/沥青/魔力泉）
            + w4 * defensibility       # 防御性（背山/扼守隘口/高地）
            + w5 * trade_access        # 贸易可达性（河口/道路交汇/沿海）
            - w6 * harshness           # 恶劣度（高原/极寒/荒漠惩罚）
            - w7 * hazard              # 灾害（火山/沼泽/洪水）
```

权重 `w*` 放在 `biome_rules.tres` / `settlement_rules.tres` 数据表，调"手感"只改表。

### 3.3 设计意图注入

两种注入方式，互斥可叠加：

| 注入类型 | 语义 | 实现 | 示例 |
|----------|------|------|------|
| **偏置（Bias）** | "这里更可能出某类聚落" | 给某区域某产业适宜度加权 | 高原区 harshness 加倍 → 聚落稀疏 |
| **保证（Guarantee）** | "这里必须有一个某类聚落" | 强制放置 + 锁定级别/产业 | 边境地块强制 1 个要塞城市 |

保证项优先于采样，偏置项融入采样概率。创始人约束大多可表达为"地区级保证 + 地块级偏置"。

### 3.4 采样与级别分桶

```
1. 保证项先放置（强制聚落，锁定级别/产业/位置约束）
2. 在剩余区域按 Poisson-disk 间距采样候选点（避免聚落簇拥，除非意图如此）
3. 每个候选点采适宜度 -> 连续 population_score（长尾分布，幂律）
4. 分桶：
   score < v1            -> 不定居（有资源也无人）
   v1 ≤ score < v2       -> 村落 T1
   v2 ≤ score < v3       -> 镇/大部落 T2
   v3 ≤ score < v4       -> 城市 T3
   score ≥ v4            -> 中心城市候选 T4
5. 地块内最高分聚落若达 T4 阈值 -> 升为该 L1 地图中心城市（仅 1 个）；未达阈值 -> 该 L1 地图无城市级聚落（最高级聚落充当事实中心，§0.5）
   未达阈值 -> 该地块无中心城市（贫瘠地块）
6. 帝国首都：覆盖规则，指定聚落升为 T5（单独建筑集）
```

**下限偏置**：每个桶内的 `population_score` 用 `lower + (upper-lower) * u^k`（k>1，如 k=2）映射，使大部分聚落贴近下限，少数逼近上限——符合"大聚落稀少、数量级差距"。

## 四、聚落系统设计

### 4.1 聚落级别

| 级别 | 名称 | 数量级特征 | 出现频率 |
|------|------|-----------|----------|
| T1 | 村落 | 最小，最常见 | 高 |
| T2 | 镇 / 大部落 | 偶尔一个村落长成大部落 | 中低 |
| T3 | 城市 | 有支柱产业，数量级大于村落 | 低 |
| T4 | 中心城市 | 地块首要城市，有城墙，0或1个/地块 | 极低 |
| T5 | 帝国首都 | 特殊，建筑另行设计 | 手动/特殊放置 |

> 注：常规 4 级建筑对应 T1–T4；T5 单独设计。

### 4.2 支柱产业

T3+ 聚落分配 1+ 支柱产业，依据自然层 + 意图：

| 产业 | 触发条件（自然或意图） |
|------|----------------------|
| 采矿 | 周边有矿脉/沥青矿 |
| 渔业 | 靠河/靠海岸 |
| 贸易 | 河口/道路交汇/沿海良港 |
| 农业 | 大平原高可耕地 |
| 魔力 | 邻近魔力源泉 |
| 军事要塞 | 边境/扼守隘口（多为保证项） |
| 前哨站 | 文明边缘（保证项） |
| 考察点 | 特殊地标附近（保证项） |

### 4.3 中心城市位置规则

> 每个聚落独占一个 L1 地块（§0.19），本规则描述**聚落在其 L1 地块内的位置**。默认取 L1 地块内相对靠近中心的位置选点；中心城市与次级聚落均适用（中心城市位置由 §0.5 例外规则偏置）。

- 默认 L1 地块几何中心附近（"从地块内相对靠近中心选一个点当聚落位置"）。
- 若 L1 地块靠山且资源为矿 → 聚落靠山侧边缘，产业=采矿。
- 若 L1 地块靠河/海 → 聚落靠水侧边缘，产业=渔业/贸易。
- 由 `settlement_rules.tres` 的位置偏置函数实现，不写死。

### 4.4 地块聚落构成规则

> **1 个 L1 地块永远只有 1 个聚落（或空聚落）**。聚落规模分桶（T1~T4）决定该聚落是村落/镇/城市/中心城市，而不是决定一个 L1 地块内聚落数量。本节其余规则描述 **L1 地图（多 L1 地块的集合）** 的聚落构成。

- **1 个 L1 地块 = 1 个聚落（或空聚落）**：中心城市聚落占 1 个 L1 地块，次级聚落各占 1 个 L1 地块；空 L1 地块无聚落（无人定居）。
- L1 地图内中心城市聚落 0 或 1 个（取决于最高分是否达 T4；贫瘠 L1 地图可能没有城市级聚落，此时最高级聚落充当事实中心）。
- 城市级聚落（T3）可 0~多个；富庶 L1 地图可出现第二个 T3（沈阳/大连型），但中心城市仍唯一。
- 村落/镇/部落级聚落（T1/T2）数量 = `f(资源禀赋, L1 地图大小, harshness)`，可能 0~8+（标准样本 1 城 + 2 镇 + 5 部落）。
- 玩家可在适宜度够但无人定居的空 L1 地块上新建聚落（沿用现有建设系统）。

## 五、大世界层级（L3）生成管线

### 5.1 大陆轮廓批量生成器（模板挑选工具）

**目标**：批量生成大陆轮廓候选，创始人选定一个作为后续细化的锁定模板（满足"随机味不重 + 可挑选"）。

**算法**（距离场 + 多倍频噪声 + 径向海洋衰减）：

```
ContinentSketcher.batch_generate(count, seed):
  for i in count:
    s = derive(seed, i)
    # 1. 基础陆地 blob：椭圆/多焦点引力场
    base = elliptical_continent(a, b, focus_jitter=s)   # 参考 Unciv 椭圆大陆
    # 2. 边缘扰动：多倍频 Simplex 扰动海岸线
    coast = perturb_edge(base, noise_freq, noise_amp)
    # 3. 径向海洋衰减：边缘 5~15% 强制海洋（保证"周围一圈海洋"）
    landmask = coast * radial_ocean_falloff(margin=0.1)
    # 4. 输出纯线条 SVG 轮廓
    render_outline_svg(landmask, "candidate_%d.svg" % i)
  # 创始人挑选 -> locked_continent_mask.png
```

参考：Unciv 的 8 种大陆模式（泛大陆/群岛/两大陆/分形…）、Azgaar 的 heightmap 策略。

### 5.2 大陆地形生成（锁定模板后细化）

**采用板块构造简化模拟**（参考 World-Synth BFS 板块生长 + Experilous + Benedetti 碰撞位移）：

```
1. 板块划分：在陆地 mask 内撒 Voronoi 种子 -> BFS flood-fill 生长板块
   （cost function 控制形状自然）
2. 板块类型：陆壳 / 洋壳
3. 边界分类：汇聚/离散/转换
4. 地形抬升：
   - 汇聚边界（陆-陆）-> 山脉（沿边界脊状抬高，参考 Benedetti 高斯位移）
   - 汇聚边界（洋-陆）-> 海沟 + 火山岛弧
   - 离散边界 -> 大洋中脊
5. 全局高度场 = base + plate_displacement + 多倍频细节噪声
6. 阈值化：陆/海/湖；高度分级：平原/丘陵/山地/高原
```

**为什么用板块**：纯噪声大陆"随机味重"且山脉分布不真实；板块构造让山脉沿边界成带、海岸线自然复杂——符合"地形复杂 + 随机味不重"。

### 5.3 气候与生物群落

参考 Azgaar / Unciv 的温湿矩阵（Whittaker 图表）：

```
temperature = f(latitude) + noise              # 纬度主导 + 扰动
precipitation = simplex_noise(octaves) + ocean_proximity_bonus
biome = whittaker(temperature, precipitation, elevation)
```

生物群落对应 GDD §五：平原/火山/源流/荒漠/海洋/森林/冰原。

### 5.4 河流水文

标准水文模型（Azgaar / Dwarf Fortress 同款）：

```
1. 每格 flow_direction = steepest_descent(高度场)
2. flow_accumulation = 自身降水 + 上游来水累加
3. flow > threshold -> 河流；沿流向追踪至海/湖
4. 河流跨地块边界一致（继承自高度场，天然连续）
```

### 5.5 L3 地区划分（地理优先 + 经济耦合）

地区是**地理-行政单位**，地理优先划分，再由政权后处理调整（§15.7）。

**划分方法**（cost 加权 Voronoi，让边界贴合地形）：

```
1. 目标地区面积 = 大陆面积 / 期望地区数 -> 种子数 N 涌现自大陆大小（非固定）
2. 撒 N 个地区种子 + Lloyd 松弛 2~3 轮 -> 不规则自然多边形
3. cost 加权：跨地形特征（山脊/大河/荒漠边界）切割 cost 高
   -> 边界倾向沿山/河走，山地归山地、平原归平原（地形同质化）
4. 经济耦合覆盖：水乡+背后平原等经济互赖区域强制并入同一地区
   （检测：水体的相邻低地且共享流域/贸易路径）
5. 裁剪到大陆轮廓；邻接图：共享边界弧段的地区互为邻接
```

每个地区继承主导生物群落（§0.4 "基本一个气候"），但允许内部局部变异（南草北水）——**天然形成**（温湿噪声局部极值，不强制）。
- 小高原 -> 小地区；大平原 -> 大地区（地区大小涌现自地理）。
- **地区数不固定**：涌现自大陆面积与目标地区面积之比。
- **地区-政权交互**：地区先按地理定，政权生成后做一次后处理切分（详见 §15.7）。

### 5.6 Demo 纯线条可视化

L3 Demo 渲染器（不改现有 [MapRenderer](../../../stick-world/modules/world_map/scripts/map_renderer.gd)，新建简化版）：

- 大陆轮廓：黑色折线
- 海洋：浅蓝填充或留白 + "海"字
- 生物群落：纯色平涂多边形 + 图例文字
- 山脉：沿边界脊线的折线/三角符号
- 河流：蓝色折线
- 地区边界：灰色虚线 + 地区名文字
- 无贴图、无纹理、无图标——只验证算法

## 八、边界一致性：受限 Voronoi 层级细分

**核心技术**：受限 Voronoi（a.k.a. bounded/restricted Voronoi），Azgaar 同款。

```
L3 大陆轮廓
  └── 地区种子(在大陆内) -> Voronoi 裁剪到大陆轮廓 -> 地区多边形（精确铺满大陆）
        └── 地块种子(在地区内) -> Voronoi 裁剪到地区多边形 -> 地块多边形（精确铺满地区）
```

保证：子层多边形的并集 = 父层多边形，边界逐像素一致。河流/道路跨层继承时按多边形裁剪，天然连续。

## 九、可玩聚落地图（横向卷轴）与地块的关系

- 地块多边形是**领土/政治边界**（鸟瞰图用）。
- 可玩聚落地图是 L1 地块内聚落的**游戏投影**：横向卷轴矩形（沿用现有 [VillageMap](../../../stick-world/modules/world/scenes/maps/village_a.tscn) + [PlacementGrid](../../../stick-world/modules/world/scripts/placement/placement_grid.gd)）。
- **1 个聚落 = 1 张主场景图**（§0.19）：空聚落 L1 地块无可玩地图（不可进入）。
- 聚落地图由 `SettlementGenerator` 从 `settlement_seed` + `biome` + 聚落级别/产业生成 `MapDefinition.tres`，交 [SceneLoader](../../../stick-world/modules/world/scripts/loading/scene_loader.gd) 实例化。
- 与现有建筑三层架构（[地形/初始/玩家](../../技术/架构/场景与战斗架构.md)）无缝衔接：生成器产出的初始建筑直接喂 `InitialBuildingsList`。

> **需确认**：可玩地图是否必须多边形边界？文档假设"否"（横向卷轴矩形）。若"是"，需重构 VillageMap，成本高。

仅当某步骤需要**运行时按需生成**（如玩家首次进入聚落 -> 生成可玩地图）时，才考虑 GDScript 运行时实现，并从锁定数据派生。

### 11.4 工程备忘（踩坑记录）

1. **class_name 冲突**：早期 GDScript 版曾定义 `class_name WorldMapData`，与 `modules/world_map/data/world_map_data.gd` 已有的同名类冲突，导致生成器解析失败。迁移 Python 后此问题消失，但 GDScript 侧新增类名前务必全局检索。
2. **沙箱内存上限**：本机沙箱对子进程有内存限制（曾测约 256MB）。numpy 大数组（8192² float32 = 256MB/个）极易超限被静默 OOM-kill（exit code 0xC000013A，无 Python 堆栈）。
3. **分块(slab) + gc.collect()**：landmask/world_map 全部按行分块（slab_h=128）处理，每块后 `del` + `gc.collect()` 强制释放。否则 numpy 临时数组累积不归还 OS，几块后就 OOM。此方案使内存峰值恒定（不随图片尺寸增长），4096 实测稳定。
4. **float32 全程**：所有 numpy 运算用 `np.float32` 字面量（`np.float32(0.5)` 而非 `0.5`），避免 Python float 自动提升为 float64 导致内存翻倍。
5. **分辨率**：4096×4096 已验证可生成。8192×8192 需沙箱内存 >512MB（输出数组 biome+river+mask 共 192MB + 临时量）。沙箱调高后可跑。
6. **河流低分辨率追踪**：河流在 1024 分辨率高程上追踪再最近邻放大到全尺寸，避免全尺寸高程数组占内存。

## 十二、数据流总览

## 十五、政权与联盟生成（L3）

### 15.1 生成时机

**地形 + 聚落之后**生成政权。顺序：自然层 -> 聚落 -> 文化圈 -> 都城 -> 政权扩张 -> 联盟 -> 后处理。

### 15.2 文化圈（联盟的基础）

```
1. 撒若干文化种子点（数量 > 预期政权数，保证同文化内能碎成多国）
2. 每种子 flood-fill 扩张，cost = 距离 + 地形难度（山/河/荒漠抬高 cost）
   -> 文化边界自然贴合地理，但不完全（人口压力偶尔跨越）
3. 同文化 = 同语言/传承 -> 后续可结成联盟
```

### 15.3 都城选定

从 T3+ 聚落选都城：
- 偏好：高人口、文化圈中心位置、防御性好。
- **都城密度高 -> 国家小**（满足"碎"）。
- 出生地区都城密度再加成 -> 保证多个小政权。

### 15.4 政权扩张（贴山靠河但不完全）

每都城从自身地块 flood-fill 扩张，cost 函数：

```
expansion_cost(tile) = w_dist * 到都城距离
                     + w_terrain * 地形难度（山/河/荒漠高）
                     + w_culture * 文化摩擦（跨文化 cost 高）
                     + w_pop * (1 / 聚落人口)  # 贫瘠地块扩张慢
```

- 停止条件：遇到他国已占地块 / 扩张预算耗尽（预算调小 -> 小国）。
- **贴山靠河但不完全**：靠 cost 权重实现，非硬规则。山/河 cost 高但**有限**（非无限屏障）-> 边界多停在此，偶尔穿过（人口/距离压力足够时跨越）。
- 难以跨越地形（高山脉/大荒漠）cost 极高 -> 常成天然国界，但其内部的聚落仍归某国（§0.14 不堆军事）。

### 15.5 联盟与单一政权

| 实体 | 构成 | 政治地图表现 |
|------|------|-------------|
| **联盟（Alliance）** | 同文化相邻多个小政权 | 一色外框 + 内部细边界（神罗式），外人视为一国 |
| **单一政权** | 独立一国 | 单色实心 |
| **大单一政权** | 偶有，但硬性 cap | 单色，规模受限 |

- 联盟是**元实体**：内部各王国独立运作（便于玩家初期蚕食扩张），外交上可视作整体。
- **规模上限**：硬性 cap 单政权地块数 -> 无半大陆巨无霸。
- 出大陆构成：多联盟 + 多单一政权混合，以联盟为主（碎）。

### 15.6 碎度保证

- 全大陆：都城密度高、扩张预算小 -> 默认碎。
- 出生地区：额外加成都城密度 -> 强制多个小政权。

### 15.7 地区-政权交互（后处理切分）

地区先按地理定（§5.5），政权生成后做一次后处理：

| 情形 | 处理 | 理由 |
|------|------|------|
| 一个地区被**两个大政权**（帝国）分割 | 沿政权边界**切分为两个地区** | 大政权应贴合地区边界，不被地区切碎 |
| 一个地区内含**几个小政权** | **不切分** | 本就是碎的预期状态；小政权同文化 -> 联盟候选 |

**结果**：
- 大政权（帝国）-> 贴合地区边界，横跨多个完整地区。
- 小政权 -> 在单个地区内细分；多个小政权共占一地区。
- 地区作为"游玩时相对完整的行政区划单位"保持稳定，仅在两大帝国交界处才分裂。

**互不矛盾**：大政权的扩张成本让它天然倾向填满整个地区再外扩；小政权预算小、挤在一地区内。后处理切分只处理少数被两大帝国同时分割的边界地区。

## 十六、聚落间道路生成

### 16.1 地块内道路

- 连接 L1 地图内所有聚落（每个聚落一个 L1 地块）。
- 算法：**最小生成树**（MST，保证全连通）+ 少量额外贸易路（高重要度聚落对）。
- 路径偏好平地，避山（除非有隘口），沿河谷（共用 §五 高度场，天然协调）。

### 16.2 跨地块道路

- 都城/重镇间的主路。
- 经**山口**（山脉低点）穿越山系，不在山顶硬穿。
- 沿河、沿海的贸易路优先。

### 16.3 道路与政权

- 同政权内道路密度高；跨国道路稀疏（多在边境口岸/山口）。
- 后处理（§十七）按重要度决定哪些路升级为"官道"。

## 十七、后处理：聚落重要度与职能微调

### 17.1 重要度评分

政权生成后，每聚落算 `national_importance`：

| 级别 | 来源 | 影响 |
|------|------|------|
| 都城 | 政权首都 | 最高驻军/规模/道路枢纽 |
| 重镇 | T3+ 高人口 | 高驻军、贸易枢纽候选 |
| 边境要塞 | 接壤他国/扼守隘口 | 军事职能、要塞化 |
| 贸易枢纽 | 路口/河口/沿海 | 贸易职能、道路优先 |
| 内地城镇 | 政权腹地 | 中等，多农业/手工业 |
| 村落 | 一般 | 低，资源采集 |

### 17.2 职能分配（多职能可叠加）

职能是**标签集合**，条件叠加即可：

```
functions = []
if 近矿脉:        functions += [采矿]
if 河口/沿海/路口: functions += [贸易]
if 边境/隘口:     functions += [军事要塞]
if 魔力泉:        functions += [魔力]
if 大平原高耕地:   functions += [农业]
# 多职能：贸易城 + 军事重镇（条件同时满足即叠加）
```

### 17.3 军事力量分配

- **边境/前线**聚落 -> 军事职能、要塞化、高驻军。
- **被难以跨越地形保护的内部安全区** -> 边境压力低 -> 军事职能少（不堆兵，§0.14）。
- 判定：若某政权腹地被高山/大荒漠与其他政权隔离 -> 该腹地聚落 military_weight 衰减。

### 17.4 规模微调

- `national_importance` 微调聚落 `population_score`（都城/重镇上浮，村落基本不动）。
- 仍受级别桶上下限约束，不越级。

### 17.5 贫瘠地块特例

- 仅 1-2 个村落级聚落的地块：其中**最高者作地块事实中心**（"首富"），虽非城市级仍承担该地块首要职能（如该地块的贸易/行政节点）。

### L3-K：L2 描边/补丁感修复（同源重烘焙，2026-08）

**背景**：L2 渲染两类问题——(1) 描边"毛边/像素感"（Chaikin 后曲线上 90% 是冗余分点，放大显现台阶）；(2) 色块边缘与描边"补丁感/对不齐"（填充三角剖分用 DP 简化、描边用独立 Chaikin，**两套不同多边形**，最大偏差 20px）。

**根因**：`mesh_extract.simplify_mesh` 的 `simplify_collinear` 在 Chaikin **之前**做，Chaikin×3 后又产生大量近平共线冗余分点 → ring 顶点爆增至 14505 → earclip O(n²) 卡死 → 被迫用 DP(tol=1.0) 砍形状，与描边分道扬镳。

**修复**（`l2_export/mesh_extract.py` / `l2_export/l2_bake.py`）：
- **共用金标准多边形**：填充三角剖分与描边都用 `simplify_mesh` 的同一份多边形。`_triangulate_ring` 移除 DP 简化；`_ring_to_border_segs` 取消 `_angle_merge_light`（其 max_dev=0.3 > DP tol=0.2，会误删关键点导致描边跨过凸起）。填充↔描边 **Hausdorff = 0.0px**。
- **顶点压缩**：`simplify_mesh` 处理顺序改为 `simplify_collinear → Chaikin×3 → _near_collinear_merge(DP tol=0.2)`。DP tol=0.2（亚像素）只删"肉眼不可见"的近平共线点，面积偏差 0.0012%。顶点 107K→30K（3.5×），大湖剖分卡死→~68s。
- **平滑保留尖角**：Chaikin×3 只切两边都 <3px 的像素台阶；任一边 ≥3px 的真实地形尖角不切，保锐度。
- **数据重烘焙**：13 地区 `l2_geom.bin`/`l2_world.json` 全量重生成。

### L3-L：全大陆 L1 蒙版划分（V 键叠加查看）

**工具**：`tools/worldgen/l1/l1_world_split.py`（L3 层直接划分全大陆为若干 L1 地块）

**算法 v2（细胞质膨胀，2026-08 修订）**：
1. **城市点 = 网格平铺 + 细微扰动**（jittered grid，`--spacing 70 --jitter 0.4`，2048 级默认 389 个点）——网格铺满陆地 bbox，每格点加 ±0.4 格距的独立均匀扰动；海里的点剔除。
2. **每岛至少 1 个城市点**：陆地连通分量（8 连通，83 个岛）中无点的岛屿补点（取离海岸最远的内点，EDT 最大处）。
3. **岛屿 = 独立计算单元**（"孤立的岛屿上的城市单独算，当成单独的 L2 地块"）：以 `(岛屿 × L2 地区)` 分组（组内再按连通分量细分），每组的像素**只由组内城市点竞争**，岛屿/大陆互不干扰，也不跨 L2 边界（子层并集 = 父层多边形，§八 层级一致性）。
4. **细胞质膨胀**（flat watershed 多源同步生长，8 连通，mask=组陆地）：细胞在陆地内生长、被海阻挡——**单个细胞不跨海、不跨湾，一个大陆的两个半岛不会共用地块**；城市点贴近陆地边缘时细胞向陆内均匀膨胀到与其他细胞相近的大小（边缘不吃亏，替代 v1 欧氏 Voronoi 被海"切半"的缺陷）。
5. **地块面积下限**（`--min-tile-area 400`）：膨胀后面积低于下限的细胞并入（同岛同 L2）面积最大相邻细胞；无同组相邻细胞可并的（极小岛/互不相邻碎块）豁免并标注 `small_exempt`。
6. **蒙版配色**：每个 L2 地区一个基色（黄金角色相，与 `export_l3_view.unique_colors` 同源），区内 L1 按面积排名取明度阶梯 —— 同 L2 的 L1 色系相似、可辨但不混。

**产物**（`output/l1/` + 复制到 `stick-world/config/strategic_map/`）：
- `l1_labels_2048.npy`：全局 L1 蒙版（int32，0=海洋，1..N=L1，389 个）

## 二十二、分形大陆生成器（fractal_continent.py）

> **状态**：已完成
> **文件**：[`tools/worldgen/l3/fractal_continent.py`](../../../tools/worldgen/l3/fractal_continent.py)
> **参考**：Prusinkiewicz & Hammel 1993 "A Fractal Model of Mountains with Rivers"

### 22.1 概述

`fractal_continent.py` 是当前**实际使用**的地形生成器，替代了原 Azgaar 模板法方案。核心思路：

- 从锁定的 8192 掩码（`locked/locked_continent_8192.png`）直接生成地形
- 在三角网格（Delaunay，~100k 顶点 / ~205k 三角形）上计算高度，**不在像素网格上**
- 河流在三角网上连续空间追踪（最陡下降），用 Squig curve 分形弯曲
- 只有最终渲染才映射到 8192 像素

### 22.2 完整管线

```
掩码 PNG → 二值化 → 分离外海/内部水域 → 采样点 → Delaunay 三角剖分
  → 两阶段高度合成 → 邻接表 → 河流追踪 → 流量计算
  → Squig curve 分形弯曲 → 渲染（三角面填充 + 河流绘制）
```

### 22.3 两阶段高度合成（核心创新）

**问题**：大陆内部有封闭水域（天池/内湖），不连通外海。这些内湖不应像外海一样海拔=0，而应继承周围地形高度。

**解决方案**：两阶段合成

#### 阶段1：仅外海贡献

```
elev_ocean = dist_o^1.5 × 0.60 + noise × dist_o × OCEAN_NOISE_COEF
```

- `dist_o`：到最近外海的距离（EDT 距离场，归一化到 [0, 1]）
- `OCEAN_DIST_SCALE = 250`（1024 网格像素）
- 产物：`elevations_init`（归一化到 [0, 1]）

#### 内池 H 计算

对每个内池连通分量：
1. 取边缘外扩 1px 陆地的最高海拔作为上限 `edge_max`
2. `H = random.uniform(0, edge_max)`（每个内湖独立取随机值，用独立种子 `SEED+7777`）
3. 用 EDT 索引图把 H 扩展到全图（每个像素 = 最近内池的 H）

#### 阶段2：外海 + 内池合成

```
elev_lake = H + dist_i^LAKE_DIST_POW × LAKE_DELTA + noise × dist_i × LAKE_NOISE_COEF
w_lake = (1 - dist_i)^LAKE_FALLOFF_POW  # 非线性衰减
elevation = elev_ocean × (1 - w_lake) + max(elev_ocean, elev_lake) × w_lake
```

最终取阶段1和阶段2的**算术平均**作为最终高度场。

### 22.4 岛屿连通分量限制（内池不跨海）

**关键约束**：每个内池只影响本岛屿的陆地，不跨海影响其他岛屿。

**实现**：
1. 对陆地+内水做连通分量标记（`scipy.ndimage.label`），每个岛屿一个 label
2. EDT 计算 `dist_interior` 时同时获取最近内池的像素索引
3. 比较像素所在岛屿 label 与最近内池所在岛屿 label
4. 不同岛屿 → `dist_interior = 9999`（被 clip 到 1，权重 w_lake = 0）

**验证**：无内池岛屿（如岛屿4，2850 像素）的 `w_lake = 0`（全部 2850 像素），验证通过。

### 22.5 河流追踪（三角网格连续空间）

**方法**：在 Delaunay 三角网格上做最陡下降追踪（非 D8 网格）：

1. **邻接表**：过滤跨外海的边，内部水域的边保留（河流可穿过湖泊）
2. **流向计算**：每个顶点找邻接顶点中高度最低者
3. **流量累积**：拓扑排序，每顶点流量 = 自身降雨 + 上游来水
4. **河流提取**：从海岸出口回溯，流量 > 阈值的路径构成河流
5. **主干河数**：`N_MOUTHS = 200`，分支深度 `BRANCH_DEPTH = 6`

**优势**：连续空间追踪，天然避免 D8 的横平竖直/锯齿问题。

### 22.6 Squig Curve 分形弯曲

河流路径在三角网上追踪后，用 Squig curve 做分形弯曲：

- 递归细分层级：`SQUIG_LEVELS = 3`
- 每次递归中点偏移（随机扰动），偏移量随层级衰减
- 采样三角网高度场确保弯曲后的路径仍贴合地形
- 河流路径存储为浮点坐标列表，栅格化只在渲染时

### 22.7 渲染管线

1. **三角面填充**（2048 分辨率）：遍历三角形，按平均高度着色
2. **高度场插值**（2048 分辨率）：`LinearNDInterpolator` 插值到像素网格
3. **蒙版裁剪**（2048 + 8192 双重）：外海深蓝 (25,55,105)，内水湖泊色 (60,100,140)
4. **放大**：BILINEAR 放大到 8192
5. **8192 精确裁剪**：用原始掩码重设三类区域像素（避免放大模糊边界）
6. **河流绘制**：
   - 蒙版裁切：任一端点在水域（外海+内水）则跳过该线段
   - 统一颜色：(40, 100, 140, 220)
   - 宽度 = `sqrt(sqrt(ratio)) × 4`（四次根号，大部分细，主干粗）
   - 过滤 1px 细支流（width < 2 跳过）

### 22.12 参数调优历史

| 版本 | LAKE_DIST_SCALE | H 计算 | 内池 H 均值 | 阶段2 均值 | 备注 |
|------|-----------------|--------|-------------|-----------|------|
| v1 | 250/3 ≈ 83px | mean（边缘平均） | 0.164 | 0.207 | 影响范围大 |
| v2 | 250/8 ≈ 31px | mean | 0.145 | 0.158 | 范围太小，影响弱 |
| v3 | 250/2 ≈ 125px | min（边缘最低） | 0.112 | 0.192 | 范围过大，条带变直线 |
| v4 | 250/4 ≈ 62px | random(0, edge_max) | 0.090 | 0.124 | 当前版本，非线性衰减 |

**关键教训**：
- 线性衰减 `w_lake = 1 - dist_i` 导致内池影响从一端到另一端
- 非线性衰减 `w_lake = (1 - dist_i)^2.5` 让影响快速收敛
- 外海噪声系数从 0.25 提高到 0.40 解决"条带变直线"问题
- 河流蒙版裁切从"两端都在水域"改为"任一端在水域"才能彻底清除海里的河流像素

### 22.14 已知问题与待改进

1. **trae-sandbox 截断**：`Start-Process -Wait` 方式运行脚本时，日志在 Squig curve 阶段可能被 sandbox 截断，但 PNG 实际已完成保存。手动在 cmd 中运行不受影响。
2. **归一化副作用**：阶段1和阶段2各自归一化到 [0,1]，取平均后可能低于单独一张。无内池岛屿的"受影响"实际是归一化导致的全局高度重映射，非跨海影响 bug。
3. **河流追踪用 min 高度场**：当前用 `elevations_min`（阶段1+阶段2取最低）作为河流追踪的地形，更保守，但可能导致部分河流路径不够自然。
