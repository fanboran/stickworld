# 任务图维护规范

> 本文档持久化任务依赖图（[`任务依赖图.txt`](任务依赖图.txt)，可视化 [`任务依赖图.html`](任务依赖图.html)）的
> 规划理念与维护纪律，由创始人 2026-09-03 系列审计逐步确立。**任何 AI 编辑任务图前必读**；
> 工具：`python tools/deptask/gen.py --check`（校验）/ `python tools/deptask/gen.py`（生成可视化）。

## 一、任务的存在资格（前后沿理念）

一个任务能作为独立节点存在的条件——**两者缺一不可**：

1. **前沿（为什么现在/将来做）**：前置是它**技术上真正需要的东西**。校验器规则：
   - 阻塞/冻结必须有前置（阻塞无因 = ERROR）
   - 可开工/进行中/待验收/完成 的前置必须全部完成（豁免=1 须写理由）
2. **后沿（产出被谁消费）**：完成的产出必须有明确的消费方——下游任务、玩家体验、或发布收口。
   校验器规则：未完成且无后沿 = WARNING（逐条确认；琐碎修复类应合并进有后沿的任务，
   或降级为其他任务的附属步骤，或移出规划图降级到待办随手清单）。

反例（历史上犯过的错误）：文档勘误拆成 5 个独立任务、各只有一行改动、无后沿——
已合并为"文档校准批次"并连到消费方（input_refactor/tech_rebuild 开工前校准）。

## 二、前置 = 工作内容依赖，不是执行顺序

- **git 提交顺序 ≠ 依赖**：同一天提交的两个任务可能互不依赖（行为 AI 依赖 StickmanEntity
  实体与动画，与同期的建筑禁放区毫无关系）。
- **阶段门 ≠ 依赖**："Alpha 启动了所以能做科技重建"是排期不是因果。阶段划分是依赖拓扑
  **推导出来的结果**（从 root 出发的分层深度），不是写在图里的原因。图上不放
  alpha_start/beta_start 这类纯阶段门；launch/live_ops 保留是因为"游戏已发布才有 DLC"
  是真实因果。
- **设计任务的前置 = 它所描述的内容在游戏中的成型进度**（不是"GDD 文档在上游"）：
  - 法律分支树 ← 窗口系统成熟（业务面板迁移）+ 国家存在（Region 建模+组织驱动）
  - 文明差异化 ← 大世界地图制作中后期
  - 剧情/主角/帮手 ← 基础循环可玩 + 各文明彻底设计好
  - 宫殿内部 ← 建筑系统深化（材质→B3/B4→参数化成熟）之后
  - 加工品列表 ← 物品系统完善（经济→采矿→循环→队列→建造过程化链条之上）
  - 战场两端模式 ← 多局循环转起来（跨图行军+编制）
  - 宣发材料 ← 美术告一段落 + 至少单局（最好多局）循环；此前只能准备账号（mkt_accounts）
- **设计先行例外**：纯设计任务（无代码依赖）前置=root 即可随时动笔，但标注
  "验收后修订"（如村落定义对照原型验收反馈修订）。

## 三、粒度规范

- **任务 = 单一可验收交付物**（约 1 次派活的量）；名称写**具体内容**，批次/编号一律进 `注=`
- 不合并：`0.1 和 0.2 算一个任务`这类阶段合并是错的（已拆分）
- 不过拆：**没有独立后沿的碎任务**不单独成节点（见 §一）；同类小活合并进有后沿的任务并在注里列明细
- **簇 = 语义功能团（高度耦合、边界清晰的一团），成员 ≤ 8**（超限 ERROR，按语义边界拆成多簇）；
  阶段打包簇（"P0 验证期"这类）禁止——簇按"功能团"划分，不按"时间期"划分

## 四、跟随最新设计（任务列表是活的）

任务列表映射的是**当前设计**，不是历史考古：

- 设计推翻某成果时，同步移除/改写对应完成节点（先例：河流追踪一版被推翻 → 从完成区移出，
  river_gen 阻塞承接重做；Azgaar 模板法被分形大陆方案替代 → 从名称中移除）
- 已完成区的每个节点都应是"当前设计下仍然成立的成果"
- git 历史只用于**还原脉络**（哪些阶段做成了什么），节点内容以最新设计为准

## 五、发布收口的完整语义

`release_gate`（发布收口）的前沿 = **发布所需要的内容全集**，按领域收口门分层：

```
econ_loop_done    经济循环收口（资源产出→队列→建造过程化→物流→市场→持久化）
map_refactor_done 地图重构收口（扩张/城墙/城外/出城/城镇朝向/地面贴图/建筑深化）
battle_modes_done 战场类型收口（遭遇/攻城/守城/spawn 动态/持续战/工程战/跨度/道路遭遇）
gdd_systems_done  GDD 系统补全收口（科技/扩张模块/外交/成就/组织驱动/室内/上帝视角/天气）
sim_units_done    模拟与个体收口（个体属性/装备/寻路/实体拆分/AI 数据驱动/战斗收敛）
ui_mature_done    UI 成熟收口（tscn 迁移/小地图样式/存档界面/附身完整版/读档完整性）
    ↓ 六门齐 → content_freeze（内容冻结 = GDD 预想的游戏本体状态齐）
    ↓ + 打磨群（平衡/UX/本地化/Steam/商店页/定价）
release_gate → launch → live_ops
```

"发布前要做什么"= 点开 release_gate 逐层展开前置；"什么能提前做"= 收口门成员中
前置已满足的节点（图上读拓扑深度与状态）。

## 六、并行管理语义（工具）

- **分区布局 + 分隔墙**：自动重排严格保持左（完成）右（未完成）；墙可拖动（右区整体平移）；
  节点拖动被墙约束，唯一穿越方式 = 状态变为完成
- **聚拢聚焦**：双击泳道胶囊 → 该线居中，前沿（外部前置）列左、后沿（外部被依赖）列右，
  无关淡出——用于观察任务组的依赖边界
- **封装簇**：语义功能团可折叠/展开；折叠卡片聚合状态与进度，边自动重定向
- **校验闸门**：派活前 `--check` 必须通过（环/悬空/阻塞无因/前置未完成/簇超限 = ERROR；
  域冲突/无后沿叶子 = WARNING 审计线索）
