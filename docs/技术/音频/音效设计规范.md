# 音效设计规范

> 本文规定**单个音效自身的设计**：它是什么语义事件、多长、多大声、占用哪个频段、
> 有几个变体、能不能重叠。**触发侧**（什么时候响、节流合并、优先级、空间化）见
> [音效触发规范.md](音效触发规范.md) + [音效触发改动清单.md](音效触发改动清单.md)。
>
> **依据约定**（全文贯彻）：
> - 标 **【实测】** 的来自直接读表/量测，附命令；
> - 标 **【判断】** 的是音频工程经验推断，给出理由，可被观感验收推翻；
> - 标 **【提案/待定】** 的是尚未经创始人观感验收的数值目标。
>
> **表格来源**：本文的逐件表由 `tools/sfx/sfxlib/design.py` 的配方表**脚本导出**
> （`<PY> tools/sfx/export_design.py`），改配方后重跑即可，**不要手改表格**。
> 量测环境：worktree `agent/music-overhaul`，2026-09-13。

## 一、一件音效是怎么来的（管线全貌）

```
tools/sfx/sfxlib/design.py    配方表：这是什么声音/由哪些成分构成/为什么（唯一真相源）
        │  build(fs, seed)
        ▼
tools/sfx/sfxlib/synth.py     合成原语（向量化）：瞬态/模态/FM 铃/噪声扫频/拟音/闷响
        │  raw 单声道 float64
        ▼
tools/sfx/sfxlib/post.py      母带链：去直流 → 裁剪 → 音色整形 → 混响 → 立体声化
        │                     → 软削峰 → 归一到 L_evt 目标 → 真峰值守卫 → 淡边
        ▼
stick-world/assets/audio/sfx/<name>.wav    交付件：48kHz / 立体声 / PCM_16
        │
        ├── tools/sfx/qa_sfx.py --check     客观质检（削波/真峰值/分层/时长/变体/2–5kHz）
        └── tools/sfx/preview.py            试听样带（按类别串成 MP3）
```

复现（Windows 用 `C:\Users\fanbo\AppData\Local\Programs\Python\Python312\python.exe`，
下文记作 `<PY>`）：

```bash
<PY> tools/sfx/selftest.py                    # 原语/母带链/指标的自检（已知答案）
<PY> tools/sfx/gen_sfx.py                     # 全量生成（幂等：同 seed 同字节）
<PY> tools/sfx/gen_sfx.py --verify            # 重渲染并逐字节比对
<PY> tools/sfx/qa_sfx.py --check              # 客观质检（退出码非 0 即不通过）
<PY> tools/sfx/preview.py                     # 试听样带 → temp/sfx_preview/
```

三条设计纪律（都是实际踩出来的，细节写在对应代码注释里）：

1. **合成原语全部向量化**：样点轴走 numpy/FFT，只对"模态数/谐波数/共振峰数"
   做循环。600 万样点的逐样点 Python 循环要跑几分钟。
2. **时长就是衰减**：一件音效的时长定义是"衰减到 -60dB 所需时间"
   （`design.tau_for`），**不是往缓冲里填静音**。填静音会让事件响度被无谓稀释。
3. **交付统一 48kHz 立体声 PCM_16**：BS.1770 的 z 是各声道均方**求和**，所以
   "双单声道文件"比"单声道文件"数值上高 3.01 LU，而听感一样响。全部交立体声，
   "文件 LUFS = 实际回放响度"才成立，数字才能直接与音乐（-15 LUFS 立体声）比。

## 二、响度分层（核心设计）

音效与音乐**同时响**，所以音效不能"谁录得响谁赢"，必须有一套相对关系。
本管线用**事件响度 `L_evt`**（K 加权、整段均方、无门限）作交付口径，
理由与定义见 `tools/sfx/sfxlib/post.py` 模块头（关键：短于 400ms 的信号测不出
BS.1770 积分响度，而本包最高频的三件只有 60~95ms）。

| 层（`category`） | `L_evt` 目标 | 包含事件 | 为什么是这个值 |
| --- | --- | --- | --- |
| `ui` | **-25.0** | hover / click / confirm / denied | 最高频反馈（鼠标扫过一排按钮会连响十几次），任何一次都不该打断玩家；且界面音**离耳朵最近**（无距离感），数值上要比"场景里的声音"再低一档。 |
| `harvest` | **-20.0** | harvest_hit（3 变体）/ wood / gain | 玩家主动触发、需要即时确认，但同样高频（按住采集连响），且与音乐的中频区重叠，压在音乐（-15）之下 5dB。 |
| `lifecycle` | **-20.0** | game_started / game_saved / quest_done / build_complete | 低频但重要，**与音乐同时响**；目标是"听得清仪式感、但音乐仍是主角"。与采集同值：区别在时长与仪式形状，不在响度。 |
| `combat_fx` | **-18.0** | swoosh ×4 / thump ×2 / bodyfall ×3 / headbutt | 战斗单位拟音**密集**（一场几百次），必须给"整体不糊"留余量，所以比 sting 低 3dB。 |
| `battle` | **-15.0** | battle_started / battle_ended_win / battle_ended_lose / victory_fanfare / magikill_blast ×2 | 它是"宣告/收束"，必须站得住；代价是**时长短**（0.9~2.5s）且只在战斗/结算这一瞬出现，不会长期占听觉。与音乐持平，靠时长与和声密度而不是音量。 |
| `ambient` | **-24.0** | （本批不重写）鸟鸣 3 件；雨声按 id 单独 -20 | 最轻，且常被引擎按距离/强度缩放。 |

**两处有意偏离**（`design.LAYER_OVERRIDE`，不是调参，是语义）：

| 文件 | 层目标 | 实际目标 | 理由 |
| --- | --- | --- | --- |
| `clang_a/b` | -18 | **-16** | 格挡是战斗里最关键的正向反馈（"我挡住了"），比单位拟音高 2dB，仅次于 sting。 |
| `unit_hurt_a/b/c` | -18 | **-17** | 受击是最密集的单位拟音，再低 1dB，给"几十个声音同时响"留余量。 |

**分层规则**（`qa_sfx.py --check` 逐条验证）：

1. 层内一致：同一层内跨度 ≤1.5 dB（实测最大 0.44 dB，见质检报告）。
2. 层间单调：`UI ≤ 采集 ≈ 生命周期 < 战斗拟音 < sting`（两个覆盖件的独立目标
   也分别校验，不混进层内跨度去平均掉）。
3. 音乐是 -15 LUFS。音效的"地板"由此确定：偶发音效一律不高于音乐，
   只有场景确定、时长有限的战斗 sting 与音乐持平。

## 三、时长与衰减规则

交付件会被 `post.trim_to_event()` 裁到"衰减到 -60dB（相对峰值）"附近，所以
**设计时长 T 与衰减时间常数 τ 是同一件事**：

```
τ = T / 6.908          （design.tau_for；6.908 = 60/20·ln10）
```

- **统一用 exp 衰减**。`synth.decay_env(curve='power')` 的 -60dB 出现在 30.62τ，
  同一个 τ 会得到 4.4 倍时长；本管线不混用两条曲线，"T 与 τ 的换算"才有单一规则。
- **不要用"填静音"实现时长**：静音会稀释 `L_evt`（同一件音效前垫 0ms 还是
  300ms 静音，测出来差 6dB 以上），响度目标就变成"文件的填充长度"。
- **号角/持续段必须把 `hold` 传给包络**：`synth.perc_env(hold=...)` 里衰减从
  hold 处起算。漏传会让"保持 0.5s 的号角"从 t=0 就开始衰减，一个设计 1.2s 的
  宣告变成 0.7s 的短促音（已固化成 `selftest.py` 的用例）。

每件的 `dur_ms` 是**质检窗口**（不是渲染长度）：`gen_sfx.py` 与 `qa_sfx.py`
都会把裁剪后的实测时长与它比对，越界即报。

## 四、调式关系：偶发音效的"三音禁忌"

游戏里音效与音乐同时响，而音乐有明确的调（见 `music_manifest.json`）：
`menu_title/field_day/sting_victory` = D 大调，`field_night/sting_defeat` = B 小调，
`village` = G 大调，`interior` = F 大调，`strategic` = C 大调，`battle` = D 小调。

一个**偶发**音效（UI、降生、采集）可能在任意一首曲子下触发，若它带明确的大/小
三音就会和当时的和声打架。做法：

1. **调心取 D**：六首曲子里三首以 D 为中心，B 小调是 D 大调的平行小调，G/F/C
   大调里 D 与 A 也都是调内音。
2. **偶发音效只取 1 度与 5 度（D 与 A），不含三音**：纯五度/八度在六种调式下
   全部协和——这是"不知道当时播哪首曲子"时唯一站得住的选择。
3. **三音只出现在"场景确定"的战斗 sting 里**：胜利接 D 大调凯旋曲（用 F#）、
   失败接 B 小调折戟曲（用 F，且只作 0.13s 的**经过音**，落音回到开口五度）。
4. **`victory_fanfare` 刻意不含三音**：通关那一刻在播哪首曲子**不确定**（战略曲
   C 大调、主菜单 D 大调都可能），所以它用"慢速 1/5/8 度上行 + 开口五度收束"
   表达完满，而不是靠大三和弦。这条与 `battle_ended_win`（场景确定为 D 大调，
   可以给 F#5）的差别就是"三音敢不敢用"的边界。

不含音高的音效（挥击风声、倒地、受击拟音的语音带）不受此约束。

## 五、变体设计：差异要有客观门槛

同一事件的多个变体若只是音量/音高微差，密集触发时会听成"机关枪"。所以：

- 变体差异必须来自**材质/动作的真实变化**（不同的模态比例、不同的共振峰、
  不同的动作时长），不是随机抖动；
- `post.variant_diff()` 给出可执行判定：两两之间至少要在某条轴上超过"可察觉差异"
  （时长 22ms / 谱质心 15% / 平坦度 0.05 / 频段占比 6 个百分点），打分 ≥1.0；
- `qa_sfx.py --check` 逐对计算，`selftest.py` 用"同一条音频打 0 分"作反例验证
  检查本身有效。实测最弱一对 1.93（`unit_hurt_a vs unit_hurt_b`，见质检报告）。

变体数：采集敲击 3、受击 3、挥击 4、倒地 2、尸体落地 3、格挡 2，其余单件。
**变体池由 `AudioManager` 的数组抽取**（表驱动），不在调用点各自 `randi()`。

## 六、2–5kHz：与音乐共存的物理约束

2–5kHz 既是人耳最刺耳的敏感区，也是音乐"存在感"区（钢琴 2.5kHz 微凸）。
所以本管线把"刺耳"定义为**这个频段被占用得太久**（听觉疲劳按时间累积），
度量方式是 `post.band_busy_ms()` 输出的**时间量**（累计占用 / 最长连续占用），
而不是能量占比——音效本来就短促明亮，一个 40ms 的石头敲击能量占比必然高，
但它不刺耳。

由此的设计约束（逐件落实）：

- 受击拟音的能量集中在 **300~1.5kHz 的语音带**，不在 2–5kHz：密集触发时
  像"人声嘈杂"（有生命感）而不是"金属刮擦"（疲劳），音乐也仍浮得出来。
- 生命周期/礼炮类长音的**弦垫与气声不上 2kHz**（低通 1.2~1.5kHz），把存在感区
  让给音乐；高频只留铃的瞬态（短）。
- 入账音放在 1.2k/1.8k 而不是 3~5kHz。
- 质检门槛：`busy_run_ms ≤ 240`、`busy_ms ≤ 320`；**长音（≥900ms）的连续占用
  ≤80ms**。实测最长连续占用 168ms（`swoosh_d`，一件 279ms 的亮挥击），
  长音里最长 48ms（`magikill_blast_a`）。

## 七、立体声与单声道策略

| `width` | 得到的东西 | 用在 | 理由 |
| --- | --- | --- | --- |
| `0.0` | **双单声道**（左右逐样点相同） | UI 全部、采集全部、受击三变体 | 这类音是"被点出来的/贴在耳朵上的"，加宽度只会让它在耳机里偏移；双单声道折叠单声道**零损失**（`selftest.py` 逐条断言）。 |
| `>0`（0.2~0.55） | 侧信号注入少量去相关噪声 + 200Hz 以下折回单声道 | 生命周期、sting、礼炮、武器拟音 | 需要"空间/体量"的场合。折叠单声道后 `(L+R)/2` 仍**逐样点等于原单声道**（内容零损失），代价只是去相关带来的额外亮度极小的损失（实测 ≤0.53 LU）。 |

交付件固定 48kHz / 立体声 / PCM_16，`gen_sfx.py --verify` 以**逐字节**比对
保证"同参数同字节"。

## 九、维护流程（改一件音效的完整动作）

1. 改 `sfxlib/design.py` 的配方（`what/components/why/dur_ms/band_center/overlap`
   是"设计"，必须写；`tone/rev/width/clip/tp` 是"校准"，按需要）。
2. 若引入了新的随机来源，确认它**只依赖 `design.seed_of(文件名, 变体号)`**
   （CRC32，跨进程稳定），否则 `--verify` 会失败。
3. `<PY> tools/sfx/selftest.py` → `<PY> tools/sfx/gen_sfx.py` →
   `<PY> tools/sfx/gen_sfx.py --verify` → `<PY> tools/sfx/qa_sfx.py --check`。
4. 新增/改动事件名时，同步 `core/services/audio_manager.gd` 的 `SFX_EVENTS`
   与 `SFX_POLICY`（键名是两边的契约；资产侧不碰代码）。
5. `<PY> tools/sfx/preview.py` 出样带送观感验收，并把实测值写进
   [音效质检报告-2026-09.md](音效质检报告-2026-09.md)。
