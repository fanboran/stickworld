## 一、本批做了什么

曲库从 **9 首扩到 17 首**（54 个分层），并补上运行时接线：

| 新曲 | 类型 | 补的缺口 |
| --- | --- | --- |
| `field_day_b` 原野·昼·竖琴 | 循环 4 层 | **变奏族轮换**：主奏从钢琴换到竖琴，钢琴退成纯伴奏 |
| `village_b` 小镇·木琴 | 循环 4 层 | 变奏族轮换：主奏换到马林巴，吉他更活跃 |
| `battle_b` 出征·弦乐 | 循环 4 层 | 变奏族轮换：推进音型从钢琴换到弦乐，定音鼓更疏 |
| `village_night` 夜镇 | 循环 3 层 | 村落没有夜曲（昼夜手法此前只做了野外） |
| `interior_hall` 厅堂 | 循环 3 层 | `MEGA_INTERIOR` 此前复用"小房间独奏钢琴"，缺大空间与编制 |
| `battlefield` 余烬 | 循环 3 层 | `BATTLEFIELD` 地图在**非交战**时此前放的是战斗曲 |
| `sting_conquest` 入主 | 一次性 3 层 | 占领/通关只有音效礼炮，缺音乐上的"落定"（8 小节 ≈25s） |
| `sting_arrival` 抵达 | 一次性 3 层 | 跨图抵达缺音乐标点（2 小节 ≈4s） |

运行时接线：

- `CUE_FOR_MAP_TYPE`：`BATTLEFIELD → battlefield`、`MEGA_INTERIOR → interior_hall`
  （`battle` 仍由 `battle_started` 情境优先命中，语义更准：事件归事件、环境归环境）。
- 昼夜：`VILLAGE + night → village_night`。
- **变奏族轮换**：`compose/cues.py` 的 `VARIATION_SETS` → 清单 `variation_sets` →
  `MusicDirector._pick_variant()`。按**进入场景的轮次**轮换（不进循环点硬切）。
- 标点：`travel_started` 后的首次 `map_loaded` 打 `sting_arrival`；
  `demo_quest._show_victory()` 打 `sting_conquest`。
- 标点的音乐压限**按短句自身长度**释放（此前固定 2.5s，长标点后半句会被音乐盖住）。

## 二、几个关键决策（为什么这样做）

1. **战场与战斗分家**：两者共用同一套和声骨架（i-VI-III-VII / D 小调），
   只降速度（104→66）、撤打击乐、把主题压成骨架音。同一材料，事件与环境两种讲法。
2. **变奏族"换主奏"而不是"生成一版只有伴奏"**：都能抗疲劳，但换主奏不额外占曲目位、
   也不会让玩家觉得"音乐少了点什么"。族成员**同调同速同长、层名一一对应**，
   这是运行时整层替换无缝的前提（由测试守住）。
3. **变奏 B 组的主奏层降一档 tier**：基础曲里竖琴/马林巴是点缀（tier 2），
   在变奏里它们是主奏——若仍按 tier 2 处理，低强度下整首会没有旋律。
4. **按进入轮次而不是按循环轮换**：按循环要在循环点硬切（会切掉折回处理过的循环尾巴）
   或交叉淡化（双套播放器 + 逐帧对齐），代价与风险都大；按进入轮换零时序风险，
   效果同样是"每次回到这里听到的不一样"。
5. **主奏换人必须同步改混音的层配平**：`LAYER_BALANCE_DB` 是按钢琴自动配平的
   （竖琴 -8dB、马林巴 -9dB），变奏里它们当主奏就会被压没。新增
   `LAYER_BALANCE_BY_CUE`（`compose/cues.py` 声明 → `mix.mix_cue(balance=...)`）
   作为"编曲意图进混音"的唯一入口。

## 三、验收与证据

- 客观质检：`qa_audio.py --check`（母带）与 `--check --delivered`（交付件）
  均退出码 0；17 首全部 −15.00~−15.06 LUFS、真峰值 ≤ −1.77 dBTP、无削波、
  循环接缝 −9.1~−37 dB。
- 运行时：`tests/integration/test_music_director.tscn` 16 项全绿，其中新增
  「变奏族同调同速同长同层名」「再次进入换一版」「抵达打点」「压限按短句长度释放」。
- 本批顺带修的运行时缺陷：**多层短句只播了第一层**（`play_stinger` 原先取
  `layers[0]`，字母序第一层常常是 bells）——既存的胜利/失败短句一直只响了一层。

## 四、下一步

1. **观感验收**（人耳，见样带）：变奏族轮换是否真的抗疲劳；`battlefield` 的"凭吊"
   是否成立；`village_night` 与白天是否听得出"同一个镇子换了口气"；
   `interior_hall` 的空间感；两首新标点的长度与庄重程度。
2. 未做（提案）：按聚落规模分化音乐（小村/镇/城邦）、"只伴奏版"交替、
   每次循环轮换、领地主题——见 [音乐设计文档.md](../../设计/音乐/音乐设计文档.md) §八。
3. 收线：全量测试 + 报错自检 → 合并 `agent/music-expand` 进 `main`。

## 五、踩坑（本批实测）

1. **渲染"空轨"守卫不能只看开头**：晚进的层（`field_day` 的钟琴从第 16 小节 ≈53s
   才进）前 30s 安静，读一段会把正常层误判成空轨——必须取**整曲**峰值。
2. **双簧管别写高八度**：`THEME_B` 自身已升八度（落点 D5~B5），再 `transpose=12`
   会顶到 B6——又薄又刺，实测整曲刺耳度从 0.08 跳到 0.24。改回后回落。
3. **`travel_started` 是三个参数**（from/to/mode）：回调签名不一致时 Godot 报参数错、
   回调静默不执行，"抵达标点从不触发"。
4. **新建 worktree 必须先跑一次编辑器导入**（`godot --editor --quit`）：
   否则 `load()` 拿不到刚写出的 OGG（`.godot/imported/` 是 per-worktree 的），
   测试会以"层播不起来"的形式失败。
5. **worktree 里可复用主工作区的工具链**：`MUSIC_TOOLCHAIN_DIR=F:/VSCode/game-2/temp/music_toolchain`
   （否则要重下 515MB）。
6. 单曲重渲（`--only X`）会把中间报告与清单一并写成单曲版——要保留全量清单就得
   重跑全量，或先备份清单再还原。
