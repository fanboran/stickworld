## 六、运行时风险与代码卫生

### 6.1 await 后已释放对象风险（本轮最重要发现）

- **`modules/world_map/scripts/strategic_map_controller.gd:286-292`（真崩溃风险，已亲验）**：`await create_timer(0.8s).timeout` 后对 `map_renderer` 只判 `!= null`——Godot 4 中已 freed 对象非 null，`has_method` 直接抛 "previously freed"。快速旅行高亮展示期间地图视图重建/释放即触发。应改 `is_instance_valid()`。
- **`modules/combat/scripts/command/command_chain.gd:88,137`**：传令延迟（秒级 await）后对 `org_api`/`_formation` 零复验、无 tree_exiting 取消机制，战斗解散后协程恢复即崩。
- 次级：`loading_screen.gd:35` await 后换场景无实例复验（脚本错误级）。

### 6.2 上轮崩溃点复核——防护有盲区，问题实际未修复

- `_is_trackable` 的三重防护写在**函数体内**（unit_lod_director.gd:236-241），但函数签名为 `u: Node`——**GDScript 对 previously freed 对象在传参阶段就做类型检查并抛错**，防护代码根本执行不到。本轮 conquest_flow 实测复现：`SCRIPT ERROR: Invalid type in function '_is_trackable' … argument 1 (previously freed)`（日志 L261）。修法：参数类型改为 `Object`（或不标注）后在体内首行 `is_instance_valid`。
- battle_instance、crowd_renderer、arrow_projectile 的有效性检查成体系，未发现同类问题。

### 6.3 代码卫生

- **生产裸 print 25 处**：hd2d_world.gd 21 处（演示 harness 流程日志）、**`world/scripts/setup/initial_content.gd:93,99,107` 3 处为生产路径**（每次开局村民落位刷屏，应改 print_debug）、hd2d_street_map.gd:573 1 处。
