## 二、质检口径（为什么这么量）

1. **响度用事件响度 `L_evt`，不是积分响度**。本包最高频的三件是
   `ui_hover ≈60ms`、`ui_click ≈90ms`、`harvest_hit_a ≈60ms`，都短于 BS.1770
   要求的 400ms 分块，`integrated_lufs` 对它们**没有定义**（返回 -inf）；强行补
   静音再测，得到的是"文件的填充长度"而不是音效的响度。`L_evt` = K 加权、整段、
   不定长、无门限的均方响度，对任意长度有定义、且是线性的（一步归一即精确闭合）。
   定义与推导见 `tools/sfx/sfxlib/post.py` 模块头 §一。
2. **交付一律 48kHz 立体声**，所以"文件 LUFS = 回放响度"，数字可直接与音乐
   （-15 LUFS 立体声）比较。双单声道文件比单声道文件数值高 3.01 LU，但听感一样——
   口径统一是这里唯一的正确做法（见 post.py 模块头 §二）。
3. **刺耳用"占用时长"而不是"能量占比"**。音效本来就短促明亮，一个 40ms 的石头
   敲击的高分位必然高，但它不刺耳；刺耳是 2–5kHz 被占得太久（听觉疲劳按时间累积，
   且这一带是音乐的存在感区）。见 `post.band_busy_ms()`。
4. **时长窗口来自配方**（`design.py` 的 `dur_ms`），不是事后统计出来的区间——
   否则"窗口"会跟着实测漂移，失去发现回归的能力。
5. **"中间断音"而不是"静音空洞"**。音乐的 `count_silence_holes` 是为循环体设计的
   （尾部静音也算）；一次性打击音的时长定义就是"衰减到 -60dB 为止"，尾巴最后
   几十毫秒**按定义**在 -60dB 以下（实测 `ui_confirm` 的 251~270ms）。所以本管线
   只数"静音段之后**还有声音**"的中间断音（`qa_sfx.interior_dropouts`），
   并用合成用例验证过：真断音抓得到、正常衰减尾不误报。

## 六、与前包（提取件）的对比

前包 = 2026-09-05 从 Terraria XNB / SWL Unity AudioClip 提取的 33 件
（登记见 [`素材替换清单.md`](../../项目/素材替换清单.md) §一）。为了让对比
**同口径**，前包的数值是在替换**之前**对原文件直接量测得到
（`tools/sfx/out/old_pkg_baseline.json`）。

| 维度 | 前包【实测】 | 本包【实测】 | 结论【判断/提案】 |
| --- | --- | --- | --- |
| 采样率 | 44100 与 48000 混用 | 全部 48000 | 混用会让引擎逐个重采样，且重采样后的真峰值不可预期 |
| 声道 | 单声道 17 / 立体声 16 混用 | 全部立体声（`width=0` 时为双单声道） | 统一后 `L_evt`/LUFS 数字才与音乐可比（否则差 3.01 LU） |
| 采样峰值跨度 | 18.65 dB（-18.65 ~ 0.00） | 14.38 dB（-16.16 ~ -1.78 dBTP） | 本包的跨度**全部来自分层**（UI 最低、sting 最响），而不是"谁录得响" |
| 削波 | 8 个样点 / 4 个文件（`bodyfall_a/c/b`、`magikill_blast_b`） | **0** | 硬门槛；音效削波即"炸耳朵"，不接受 |
| 响度口径 | 无（积分响度跨度 14.14 dB，且 8 件短于 400ms 根本测不出） | 每件有显式目标，偏差 ≤0.45 dB | 前包的问题不是"不好听"而是"无法验收" |
| 最短 / 最长 | 32ms（`harvest_hit_a`）/ 4.00s（`rain_loop`） | 60ms / 2.52s（`victory_fanfare`） | 本包时长全部落在配方声明的窗口内 |
| 变体差异 | 无判定 | 18 对 ≥1.93 | 密集触发不会被听成"机关枪"这一点**可客观验收**了 |

**结论【判断】**：前包的资产是"能听、但不可控"——响度、格式、峰值都是历史遗留的
偶然值；本包把这三件事变成**声明式目标 + 可执行判定**。至于"好不好听"，客观指标
只能保证"不刺耳、不炸、能分辨、与音乐不打架"，其余见 §九 的待观感验收清单。

## 七、2–5kHz 占用与音乐的关系【实测】

| 项 | 数值 |
| --- | --- |
| 全部 34 件最长**连续**占用 | 168 ms（`swoosh_d`，一件 279ms 的"极短而亮"挥击） |
| 全部 34 件最长**累计**占用 | 221 ms（同上） |
| 长音（≥900ms，7 件：3 个 sting + `victory_fanfare` + 2 个法术 + `game_started`）最长连续占用 | **48 ms**（`magikill_blast_a`） |
| 生命周期/礼炮 4 件 | 连续占用 ≤19 ms（弦垫低通 1.2~1.5kHz，高频只留铃的瞬态） |

音乐是 -15 LUFS、72BPM 的钢琴/弦乐/钟琴，其"存在感"主要在 2–5kHz。本包把
**长音**的 2–5kHz 连续占用压到 ≤48ms，即"高频只在起音一瞬间出现"，其余时间把
这一带让给音乐。【判断】这与 [音效触发规范.md](音效触发规范.md) §9.2 的
"采集不压音乐、sting 压音乐"是同一件事的两个方向。

## 九、仍然没有做的事（诚实清单）

以下每一项都是**本批明确未做**，不是"忘了"：

1. **战斗氛围层（人群声场）**：大战场里"几百人接战"的听感仍只能靠逐单位
   `unit_hurt`；本包**未产出**氛围层资产（金属撞击/甲片/低语的短 loop）。
   按 [音效触发改动清单.md](音效触发改动清单.md) C4，那是"用声场代替逐单位发声"
   的独立立项，涉及 `crowd_renderer` 热路径，资产侧无法替代。
2. **per-unit 发声链改造**：`weapon_mount` 的 `Sound` 事件白名单过窄、战斗中非附身
   单位走小兵代理根本不发动画事件——**本包只产资产，不碰任何 `.gd`**。
   这两条（B1 / C2 / C3 / C4）在主线的改动清单里，资产到位后仍需代码侧接线。
3. **空间化所需的单声道资产**：【判断】`AudioStreamPlayer2D` 的 pan 用立体声素材
   会变糊，触发侧希望空间化音效是**单声道文件**；本包按既定交付口径一律交
   48kHz **立体声**（`width=0` 时左右逐样点相同 = 双单声道，折叠单声道零损失），
   **没有**改产单声道文件。这条留给空间化（C3）立项时一并决定。
4. **`build_hit` 的专属资产**：主线让 `build_hit` 复用 `harvest_hit` 的变体池
   （`SFX_EVENTS` 已如此接线），本包**未**为建造敲击另做一套材质音。
5. **弓手 / 矿工的挥击、箭矢命中插地、面板开合、脚步**：这些在
   [音效触发规范.md](音效触发规范.md) §10.3 列为缺口，本批未产出资产
   （其中脚步被该文明确建议"不做"）。
6. **环境层 4 件（鸟鸣 ×3 / 雨声）的格式统一与重制**：仍是 44.1kHz 单声道，
   本批不动（见 [音效资产登记与来源.md](音效资产登记与来源.md) §四）。
7. **实机（引擎内）验证**：本报告全部是**离线**量测 + 样带试听。没有进游戏听、
   没有验证混战下的实际叠音、没有验证与 BGM 同播时的掩蔽——**这一条需要创始人
   观感验收**，且本任务明令不改 `stick-world/` 下任何代码，无法自行实机验证。
8. **运行时侧链/限幅**：BGM 侧链压缩机与 SFX 总线硬限幅器属运行时架构
   （改动清单 C2'），不在资产包内。
9. **`SFX_POLICY` 的数值标定**：表中的 `min_ms/merge_slots/jitter` 全是
   【提案/待定】，需实机听感标定；本包只保证"资产够不够格进那套策略"
   （变体差异、响度分层、峰值）。

## 十、需要人耳才能定的事【待观感验收】

样带：`temp/sfx_preview/`（`00_全部` / `10_UI反馈` / `20_采集劳作` / `30_生命周期` /
