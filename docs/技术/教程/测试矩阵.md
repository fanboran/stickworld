# 测试矩阵（功能 ↔ 场景 ↔ 覆盖）

> 单一事实源：**功能改动后查此表**——改了什么系统，跑对应场景；新增功能，在此登记。
> 运行（bash）：`bash tests/run_all.sh`（unit 批量 61 套 + integration 39 可跑 + smoke 2，另 7 套悬置见 §一 表注；清单以 `run_all.sh` 为准）。

## 〇、执行架构

| 命令 | 用途 | 典型耗时 |
|---|---|---|
| `bash tests/run_unit.sh` | unit 层批量（单进程 61 套纯逻辑） | **<2s** |
| `bash tests/run_all.sh -Changed HEAD~1` | 只跑 git diff 影响到的套件（unit 层必跑；core/config/project.godot 改动自动全量） | 1-3min |
| `bash tests/run_all.sh -Match <pattern>` | 按套件名过滤（如 combat / world_map / conquest） | 按需 |
| `bash tests/run_all.sh -Parallel 8` | 调整并行度（默认 3，integration/smoke 进程池） | — |
| `bash tests/run_all.sh -Filter unit\|integration\|smoke` | 分层执行 | — |
| `bash tests/run_all.sh -Report <json>` | 输出 JSON 报告（套件/耗时/结果） | — |
| `bash tests/run_all.sh` | 全量（提交前） | **~2-4min** |

**架构要点**：
- **unit 层准入标准**：纯逻辑、不碰 autoload、不进场景树、确定性；违反则移出 `batch_runner.gd` 清单（回退独立进程）
- integration/smoke 保持**进程隔离**（GameRoot/autoload 状态隔离是设计选择），以进程池并行补偿
- 每套件耗时打印于 `[PASS] xxx [Ns]`，可据此监控慢测试回归
- pre-commit hook 自动跑 unit 层（<2s）

## 二、启动参数速查（dev_playtest）

```
godot --path stick-world res://tests/dev/dev_playtest.tscn -- --map battlefield --party 3 --enemies 4 --follow
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--map` | hd2d_street | 目标地图（hd2d_street / battlefield / village_b） |
| `--party N` | 0 | 随行战斗班人数（跨图自动携带） |
| `--enemies N` | 4 | 遭遇战敌方数量 |
| `--follow` | 关 | 队伍自动开启跟随玩家 |

## 三、新增功能登记规范

1. 新功能 = 新集成测试（`tests/integration/test_<功能>.gd` + `.tscn`），注册进 `run_all.sh` 的套件清单
2. 本表"系统 ↔ 自动化场景"追加一行
3. 需要手动体验的（打击感/走位/节奏）→ dev_playtest 追加参数或注明"游戏内 XXX 按钮"
4. 纯逻辑改动 → unit 测试优先（进 batch_runner 清单，须满足准入标准）
