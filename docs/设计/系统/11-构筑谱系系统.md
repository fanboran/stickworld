# 构筑谱系系统（蓝图树）

> 对标体量游戏的"构筑树"在本作的落点。树**由玩家行为长出来**，不是预设路径树。

## 目的

对标游戏（异星工厂/缺氧/RimWorld/小兵步枪等）商店截图里"必备的树界面"，承担的是三个职能：**进度可视化**（我到哪了）、**构筑规划**（接下来点什么）、**晒图**（商店页/社区分享）。本作保留这三个职能，但不照抄"预设技能树"——它与两条既有设定冲突：科技是征服获得制（[`04-科技系统.md`](04-科技系统.md)）、组织架构完全自由不预设（[`01-组织系统.md`](01-组织系统.md) §2.3）。在自由系统旁边塞一棵传统树，等于让玩家玩一棵假树。

本作的构筑树 = **谱系（genealogy）**：节点是玩家自己封装出来的东西，边是"从谁派生而来"的源流关系。玩家搭出的组织、设计出的建筑、颁布的章程，都可以"定名"为蓝图节点——这棵树就是帝国知识封装的历史，也是玩家构筑的身份证。

## 一、两个落点界面

| 界面 | 位置 | 内容 |
|------|------|------|
| 技术谱系图 | 科技面板（`tech_tree` 占位升格） | 已获科技的源流图谱：每项技术是一枚拓片节点，标注流入路径（征服/人才/事件）与知识携带者；人才流失则对应知识褪色（[`04-科技系统.md`](04-科技系统.md) §2.1 知识随人走的可视化） |
| 蓝图谱系树 | 组织管理面板「谱系」标签页 | 玩家自制蓝图的定名-派生-融合树（本章主体） |

两界面共用同一套谱系图组件（缩放/点开节点/源流线），一次开发两处受益。

## 二、蓝图机制（组织模板的进化）

组织系统 §六已有"预设模板 + UGC 导出"。蓝图谱系是它的深化——把模板从"配置文件"升级为**有历史的活节点**：

| 动作 | 机制 | 权衡 |
|------|------|------|
| **定名** | 任何自建编制/建筑型号/部门章程可封存为蓝图（盖章动画） | 占用蓝图槽位（上限 [PLACEHOLDER]） |
| **复用** | 从蓝图批量实例化编制/建筑 | 熟练度随使用累积，效率加成递增、封顶——复用稳定但收益有天花板 |
| **派生** | 以某蓝图为母本创建变体：继承属性 + 受控变异（改良方向可预览） | 每代基础效率 +[PLACEHOLDER]%、容错 -[PLACEHOLDER]%——代数收益递减，玩家自然停在合适的广深比 |
| **融合** | 双母本插值出子蓝图（各取所长） | 熟练度清零重练——"用熟"与"试新"的核心取舍 |
| **退役** | 不删除，归档进荣誉档案（博物馆叙事），界面折叠不膨胀 | 蓝图可重新启用 |

树形是 **DAG** 而非链：一个蓝图可多母本（融合）、可多子代（派生），不存在唯一"下一格"——这是与线性技能树的本质区别。

**能力随阶段解锁（推而非拉）**：复用 → 派生 → 融合依次解锁（挂制造/管理科技门槛），前期复杂度不爆炸，封装深度随帝国规模自然到来——与组织系统的封装递进同构。

## 三、防两退化的数值骨架

**防线性退化**：没有预设路径；派生代数惩罚把深度收益压平、融合清零成本把收益转向"广而浅"的自选组合；蓝图槽位上限逼玩家做取舍而非全都要。

**防随机退化**：变异不是抽卡——派生/融合前可**预览**子蓝图属性区间（母本插值 + 小幅扰动）；可在试验场（训练部门/试做车间）实测后再定名。随机被转化为"可观察的微观试验"（支柱 3：放大看是真的）。

## 四、美术方向：纹章墙（全程序化生成）

美术硬约束：零手绘资产，全部由简单算法生成。质感来自**全局约束**而非特效堆叠——统一光源、统一色板、统一噪声参数、统一描边规格（"免费素材拼贴感"的病因正是缺全局约束）。

### 4.1 布局：满铺纹章墙

- 谱系图是一面**密集满铺的格子墙**（错位砖砌式网格），一屏几十至上百格——内容量是商店截图的核心卖点：满墙的徽记+名字+数字 = 可见的内容深度，收集预期直接拉满游玩时长预期
- 缩放分级：远看是墙 → 中看源流连线 → 近看单格详情；点开节点跳转它实例化的全部编制/建筑/部门（树 ↔ 实例双向，无缝缩放支柱）
- **未获得 = 灰暗剪影格**（沿用图章墙语言，[`07-成就系统.md`](07-成就系统.md)）：技术谱系图的大片剪影墙就是"看得见的内容量"；蓝图侧未来节点显示当前可派生的虚影建议

### 4.2 节点：程序化纹章生成

借纹章学的**组合学理念**（底形 × 分区 × 母题 × 配色 = 指数级独特徽记），但母题库不抄经典纹章图案——狮子鹰十字太熟悉、数量也少。母题全部换成**游戏内元素与可爱元素**：手推车、旗帜、印章、锤子、面包、狗尾巴草、心形气球、按按钮的小手、火柴人姿态简笔（推车/敲锤/举旗/敬礼/传令跑）……可爱优先于庄重；母题库可持续扩充，每次版本加母题 = 可宣传的内容量更新。

> **[提案/待定]** 首批 64 枚母题已按本节方向开产（脚本 `tools/icon_pipeline/motifs.py`，成品 `samples/motifs_batch1/`，覆盖生产工具/物流/经济/组织/科技/战斗/扩张/可爱生活/火柴人姿态九类）。**具体清单与中文命名为 AI 提案**，待创始人过目增删后转正；cel 色带家族由 5 族扩至 10 族（新增叶绿/米白/墨炭/金/蓝）同为提案。

纹章 = 底形（盾/菱/圆…）× 分区（纵分/四分…）× 母题（首发 ≥60，持续增长）× 有限色板填色，**由蓝图属性 hash 确定性生成**——同一蓝图永远同一纹章，不漂移、不重复。母题图标统一经 **3D 模板 → 手绘滤镜图标管线**产出（见 [`../程序化美术升级提案.md`](../程序化美术升级提案.md) B）——风格统一且质量可控。每格信息塞满：纹章 + 名字（StickHand 手写字）+ 熟练度小进度条 + 代数角标 + 实例数徽标——密集且每格不同，是"堆料感"的正确来源。

### 4.3 质感三件套（算法清单）

| 层 | 做法 | 质感来源 |
|----|------|----------|
| 底纹 | 黑玻璃底（`WINDOW_BG`）+ 低频纸纹噪声（极低透明白 fbm） | 微不均匀 = 材质感；纯均匀 = 塑料感 |
| 做旧 | 纹章金属底色 + 全局统一左上光源的边缘高光 + 边缘磨损（距离场 mask 处露出亮底）+ 稀疏划痕 | 磨损出现在物理上该磨的地方（边角）= 旧而干净；随机撒磨损 = 脏 |
| 光 | 源流连线 = 暗底上的发光墨线（细光晕，琥珀/白）；定名时盖一枚墨黑印章 + 短促一圈微光（一次性） | 暗底上少量发光 = 氛围（极光原理）；到处发光 = 廉价 |

格子边框/分隔线直接复用 `SketchDraw` 手绘扰动与全局 0.12s 沸腾节拍——谱系图与血条、按钮同一种"活"，不另起皮肤。

### 4.4 色彩纪律

沿用现有 token 体系（黑玻璃 + 白描边 + 琥珀唯一强调色），纹章填色用一套低饱和历史色板（每个组织标签一个点缀色，全局 ≤12 色）——暗底亮主体、有限色板。语义色不参与装饰。

## 五、与其他系统的关系

- **组织系统 §六**：官方预设模板 = 官方母本蓝图，与玩家自制蓝图同树共存、同样可被派生
- **科技系统**：技术谱系图是"知识随人走"的展示面；派生/融合能力由制造/管理科技解锁（门控）
- **建筑系统**：自设计建筑型号（材质×模块正交）也是蓝图节点，形成型号谱系
- **成就系统**：定名第一枚蓝图、融合出稀有能力组合、谱系达到 [PLACEHOLDER] 代等可挂图章
- **UGC**：组织架构 JSON 导出升级为导出谱系子树（不含熟练度，防社区倒卖练满存档，见边缘情况）

## 边缘情况

- **母本退役**：子代保留，源流线指向荣誉档案
- **蓝图实例全灭**：蓝图（知识）仍在，可重新实例化——蓝图是知识不是编制
- **槽位满时定名**：必须退役一枚旧蓝图，退役有确认提示
- **跨存档**：蓝图谱系存档绑定，不跨档继承（与图章同规则）
