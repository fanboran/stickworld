## 2. 用户诉求演变史（按时间线，每条都是明确的用户原话结论）

1. **白边**：旧管线"白底参考图→拟合→色距抠图"抠不干净 → 用户指出**本不该有抠图，
   应在透明画布直绘**。结论：结构参数化直绘 + 数学精确的结构蒙版。
2. **多样性与高度**：单张贴图个个一样、树太矮 → 变体池（树10/石6/铁4）+
   显示高度提到火柴人（身高 260px，碰撞体 38×262.5）的 ~4 倍（570×998）。
   参考基准：Terraria 反编译源码 `F:\VSCode\Terraria\Terraria\WorldGen.cs:27290`
   `GrowTree`：树干 5-16 段、顶帽 +4-6 格、树=人高 3-7 倍。
3. **分布要树墙**：逐格均匀撒点不像树林 → 生态群落聚簇（树成林/石成场/铁矿露头，
   高斯散布+最小株距 72px），**密度要密（树墙），不要稀疏**。
4. **同树同貌**：树的外观参数要确定性——位置随存档持久化，以位置哈希为种子
   选变体/缩放/翻转/色偏（resource_node.gd `_visual_rng()`），读档同一棵树长得一样。
5. **笔触原子化（核心审美决策，用户强调"一个多月前就想让你这么画"）**：
   每一笔要么完整存在要么完全不存在，**alpha 只有 0 和 255，禁止任何渐变/
   羽化/半透明**；树的轮廓=笔触圆头的并集。
6. **流场**：mona-3 参考里有流场系统（结构张量+螺旋注入），用户指出必须用。
7. **枝**：笔触原子化后枝曾消失（笔判定过滤）→ 枝不参与拟合，程序化圆头笔直接绘制。
8. **干要整根**：不要一截一截（段堆叠是 Terraria tile 机制，手绘风格不需要），
   一根连续干+微倾角+底部一段裸干延长（"延长出去的主干部分没有枝干，
   原来的部分不用动"）。
9. **笔触粗细**：用户要过 1/3 细（对齐参考画布比例），实时版后又嫌太细，
   最终默认 stroke_w=3.5、密度要铺满画面。**结论：笔宽必须做成实验室滑条让用户自己拧。**
10. **实时生成**：用户最终强烈要求**实时**（"我就要实时生成"）——Python 拟合
    （7800 笔≈10 秒）退出调参环路 → 实验室 v3 全 GDScript 实时直绘。
11. **渲染过程可视化**：3 排×3 棵预览 + 逐笔生长动画 + 顶部参数面板。
12. 颜色要"混乱"（HSV 全面抖动）、冠笔方向不要纯切向圆环（随机+切向混合 0.55）。

   PIL 位图笔是平头（stamp_canvas 已加圆头 ellipse）；ndarray.ptp 在 NumPy 2.0 移除
   （用 np.ptp(arr)）。
6. 大量 replace 改代码时**必须验证替换生效**（旧串不匹配会静默失败，本会话两次中招）。
