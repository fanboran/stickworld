# 加载屏双进度条与分帧装配 —— 进度与交接

> 任务：治加载画面卡顿（创始人反馈「每次进游戏都得卡个不知道多久」）+ 两级
> 进度条（Minecraft 式：上条 = 总阶段，下条 = 当前阶段内部细分）。
> 分支 `agent/loading-ux`，worktree `.temp/loading-ux`。

## 一、现状（批次 1 + 批次 2 第一项已完成，待创始人观感验收）

**批次 1 已落地**：

1. **两级进度条**：`WorldLoadingOverlay` 上下两条（上 = 总阶段 9 段；下更窄
   更矮更暗 = 当前阶段内部细分；无细分时下条隐藏）。API
   `show_loading(message, ratio, sub_ratio)` / `set_sub_progress(ratio)`，
   旧两参调用点行为不变。
2. **启动装配分帧**：`system_setup._step_table()` 抽出 30 步，
   `setup_steps(root)` 供分帧执行（`setup()` 走同一张表，语义不变）；`game_root`
   逐步执行、每步让一帧、副条随步推进。
3. **世界生成逐项细分**：`initial_content.spawn_initial_buildings/spawn_npcs`
   增可选 `on_progress(done, total)` 回调（逐栋/逐村民）。
4. **dev 探针静音后置底**：`tests/dev/dev_quiet.gd`，env `STICK_DEV_QUIET=1`
   → 静音 Master + 窗口 NO_FOCUS + 取消置顶。battle_perf / bar_probe / 探针已接线。

**批次 2 第一项已落地（`_ready` 之前那块最大冻结）**：

5. **分块预热器** `modules/ui_global/scripts/loading/boot_warmup.gd`：从
   `game_root.gd` / `system_setup.gd` 两个聚合入口出发，扫描源码 `preload("…")`
   展开编译闭包（`get_dependencies` 对 .gd 返回 0 条，脚本必须走源码扫描；
   场景走引擎依赖表，`uid://…::::res://…` 形式归一化），按依赖深→浅排序，
   每积 150ms 让一帧地全量 `load()`。挂进 `loading_screen._ready`：先预热
   （上条 = 「正在准备资源…（n/total）」），再 `change_scene_to_file`——
   冷加载实测 **10.6s 冻结 → 12.7s 分块（转圈不断、有计数）+ 0.3s 残留**。
   回滚：`STICK_BOOT_WARMUP=0`。导出构建（二进制 token）下源码不可读时
   扫描退化 → 预热缩水但不出错；导出构建脚本加载本身快得多。
6. **渲染后端 Windows 改 vulkan**（`rendering_device/driver.windows`）：D3D12
   下世界首次绘制（154 棵程序化树的第一个画面帧）触发管线编译，把主线程
   冻 **32~127s**；Vulkan 同机同刻 **3.8~7.6s**，且管线缓存落盘可复用、越跑越快。
   看门狗 `test_project_render_settings.gd` 已同步锁 vulkan。回滚：改回
   `d3d12` + 改看门狗断言即可。
7. **常驻量测工具**（`tests/dev/`，窗口态跑，配合 `STICK_DEV_QUIET=1`）：
   - `boot_timeline_probe.tscn`：量 load 场景 / instantiate / 世界就绪 / 最长单帧。
   - `closure_probe.gd`（`--script` 模式）：闭包归因，`--stage=none|maps|setup|
     warmup` 对照预热效果。

## 二、实测数据（窗口态=真实体验；headless 纯工时；绝对值随机负载浮动，看倍率）

| 块 | headless | D3D12 窗口态 | Vulkan 窗口态 |
| --- | --- | --- | --- |
| 进程启动→首个 GDScript（引擎引导） | — | 1.5~3.0s | 4.9~9.6s（冷缓存） |
| autoload 全部就绪 | — | 0.7~1.5s | 0.9~1.2s |
| **主菜单可交互（点开游戏→菜单）** | — | **3.3s** | ~6s（引导含在内） |
| `load(game_root.tscn)`（场景+编译闭包） | 9.6~23s | 10.6s → **预热后 0.3s** | 同左 |
| 装配 stage 1~7（已分帧） | 2.2~3.2s | ~3.7s | ~4s |
| 子阶段「初始建筑」 | 1.2~3.3s | 0.6~1.9s | 同量级 |
| 子阶段「村庄设施」其余部分 | 1.2~2.7s | 79ms + 1.4~1.7s | 同量级 |
| **树木首次绘制那一帧（管线编译）** | **不发生**（无渲染） | **32~127s，且随机器发热恶化** | **3.8~7.6s**，缓存复用 |
| 村民生成 | — | ~0.9s | ~0.9s |

归因实验（closure_probe，同进程先预热再量残留）：只预热 15 张地图 → `game_root.tscn`
仍 16.8s；只预热 `system_setup.gd`（45 个 preload 的传递闭包）→ 残留 **0.8s**。
⇒ 冻结主体是 **GDScript 编译闭包**，场景文件本身几乎免费（15 张地图在闭包编译后
合计 ~0.3s）。

进世界全程（点继续游戏→可玩）：D3D12 实测 **~152s**（其中 127s 是那一帧）→
**vulkan + 预热后 ~30s**，且全程有进度文字/转圈。

## 三、下一步（批次 2 剩余，按实测性价比排序）

1. **「村庄设施」子阶段的树木首绘帧仍是一次性阻塞**（vulkan 下 3.8~7.6s，
   D3D12 下曾 32~127s）：现在它落在副条「村庄设施→村民」的切片边界里，文字
   会定格那几秒。可把 `generate_resource_nodes` 拆成每帧一小批（每批让一帧），
   让首绘帧摊到多帧里——bar 常转，代价总时长微增。
2. 「村庄设施」子阶段（`spawn_initial_warehouse` 等）尚无逐项上报，可补。
3. 若观感验收要求「副条也覆盖装配段」，需给 stage 1/3~7 补细分步。
4. 引擎引导（vulkan 冷缓存 4.9~9.6s）无进度提示：属引擎侧，项目内能做的只有
   引导 splash 期文案（Godot boot splash 图），收益有限。

## 四、关键决策与约束

- **加载不同步化是已文档化的主动放弃**（`loading_screen.gd` 头注 2026-09-11：
  线程加载 game_root 实测三次事故——死锁/资源风暴/场景切空壳）。本任务的
  预热同样全程主线程、只 `load` 不实例化，无竞态面。
- **分帧/预热会把总时长略增**（每帧 ~16ms × 块数 + 扫描 ~0.4s，实测 +2~3s），
  换来转圈不断、可解释的等待。这是刻意取舍。
- 预热闭包清单**从源码抽取，不维护第二份清单**：漏了只会退回旧冻结行为，
  不会出错；`warmup.prepare()==0` 时静默跳过（如导出构建源码不可读）。
- **渲染后端换 vulkan 的代价**：引擎引导比 d3d12 慢 ~2s（缓存暖后），观感
  （抗锯齿/着色器成色）需创始人验收；D3D12 路径随时可一行改回。
- ⚠ **启动自动写存档 slot 0**：世界就绪路径会把资源点等写进 `saves/save_0.db`
  （本任务量测期间多次实跑启动，slot 0 已被刷新为新开局世界）。编辑器里
  F5 每次都会覆盖它——「继续游戏」前先确认，或后续任务考虑给 dev 启动加
  「不落盘」开关。
