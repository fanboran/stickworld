## 五、关键决策

| 决策 | 结论 |
|---|---|
| 战略图染色 | **实装**（创始人 2026-09-22 裁决）——推翻 P0 期「`region_owner_changed` 只发信号、地图表现层不做」的旧口径；P4 落地时把 `region_owner_changed` 接到 `political_lut.set_state_color`（接口已就绪） |
| 出征入口形态 | 两入口并存共用一份数据面：城门出门框（入口一，传统）+ 战略图双击敌聚落（入口二）；确认框先给情报（守军编成/敌将/战利品）再动身 |
| 车轮战扣减 | 剩余配额从 garrison **头部条目填满**（前满后缺，前排主力优先满编）——刷军与情报展示同一函数，禁止两处分叉 |
| 装配可见性 | expansion 实例经组 `expansion_api` 查找（不出全局 class_name，防 preload 链解析失败） |
| 解锁台账落点 | **core 的 `WorldState.unlocks`**（不是各系统自建表）：科技系统实装前的通用池，任何模块可读（core 为 L0，无反向依赖）；门禁的显示名表留在 expansion（奖励声明方），门禁判定留在 construction（门槛声明方），两侧 id 用测试对齐 |
| `unlocked_by_tech` 字段复用 | 不新开字段：该字段本就是"需已解锁 id"位，据点奖励解锁项 id 直接填进去；`tech_*`（未实装的科技线）与 `unlock_*`（据点奖励）**同池查询**——所以开局基线必须把现役可建建筑所需 id 摆平 |
| 开局基线形态 | `WorldState.STARTING_UNLOCKS` 常量（非配置表）：Config 侧两个候选（`variables.tres` / `buildings.tres`）都是 Excel 导出的，手写会被下次导出抹掉；基线的生命周期只到科技系统实装，落常量并注明迁移条件 |
| 奖励提示形态 | 复用既有 `EventBus.ui_notification` → 左下通知 feed，一条通告说全（谁臣服 + 战利品明细）；不新开奖励弹窗面板 |
| 解锁项命名 | 展示名=它打开的建筑名（`UNLOCK_LABELS`），奖励预览与通告都不暴露 `unlock_*` 原始 id；悬空/漂移由用例兜底 |

## 六、P4 开工指引（下个会话直接开工）

**已就位的上游**：归属真值写好了（`WorldState.territories[id].owner/faction` + `TerritoryRegistry.get_owner/get_faction/get_record` + `api.list_targets()` 每项带 owner/faction + `region_owner_changed(tile_key, owner)` 广播）。

1. **先定染色粒度（P4 第一个决策点）**：`region_owner_changed` 发的是 L1 地块 id（配置里的 `tile_key`，如 `city_1035`），而 `political_lut` 的 LUT 表键是 L3 政权 sid（`state_r7_*`，见 `config/strategic_map/l3_city.json` 顶层 `states`，80 国）——两者之间**没有现成映射**（这正是 §〇 盘点的"战略图政治层用 worldgen 80 政权，与 factions.tres 无关联"）。先读 [`世界地图数据流.md`](../../技术/架构/世界地图数据流.md) §7.3/§8.5 与 `modules/world_map/scripts/l3_map_renderer.gd`（LUT 采样）、`l1_*` 聚落 blob 渲染，裁定"染聚落色块（L1，不改政权）还是染政权色（L2/L3）"——前者更贴近"占一座据点"的语义，后者才需要 tile→state 映射。**这是需要创始人拍板的口径分歧，先问再动手。**
2. **接收端落点**：world_map 侧新增消费端（订阅 `EventBus.region_owner_changed`）→ 读真值 → `PoliticalLut.set_state_color(sid, 玩家色)`（接口 `modules/world_map/data/political_lut.gd:119`，已就绪零调用）。玩家色需要一个定值（`MapTokens` 里若无，先落常量并标注提案）。
3. **tooltip 读真值**：`SettlementTooltip`（`modules/world_map/scripts/strategic_map_controller.gd:115` 取的兄弟节点）文案加归属行——真值来源 `TerritoryRegistry.get_owner/get_faction`（""=原主 / "player"=我方）。
