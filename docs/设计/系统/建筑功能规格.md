# 建筑功能规格（首版）

> **状态：提案 / 待定** —— 本档是 [`待办事项-建筑系统.md`](../../项目/待办事项-建筑系统.md) `FUN-1` 的首版交付物（AI 起草），**未经创始人定稿前不是已确认设定**；定稿走决策闸门 `DEC-14`（总账 §十）。其它文档引用本档数值时须带「提案」标注。
>
> **首版范围**：5 个核心族——民居 / 仓库 / 集市 / 兵营 / 铁匠铺。其余 def（farm / grand_hall / manor / 学院赌场等批 2 族）滚入后续版，不在本档。
>
> **数值纪律**：一切数字落 [命名与数值口径](命名与数值口径.md) 的刻度——成本 ≤78、产出每拍个位数、无三位数、不扎堆整十；「已有实值」一律实录自 `config/buildings/buildings.tres`，不重造。
>
> **经济口径占位（`DEC-15`，创始人 2026-09-26 定序）**：经济系统将在地图系统重构完成后**整体重做**。本档涉及经济结算的段落——§3.2 真扣料、§3.3 价差表、§3.5 配方结算、§五账面 tick——**仅作占位参考，以重做后口径为准**；`DEC-14` 定稿范围收窄为**非经济字段**（工位 / 容量 / 住房 / 交互项 / 模数列 / 管线映射列）。建筑线不碰经济代码（价格供需 / 产出结算 / 账面）。

## 一、这份规格回答什么

「每栋建筑干什么」六个问题，逐 def 给出：

**产出与消耗 / 工位数量 / 容量（库存·住房·驻军）/ 可交互项 / 科技解锁 / 世界模型账面口径**

上游关系：本档字段名目与 [完整版蓝图](完整版蓝图.md) 的统一数据契约对齐（CityState 建筑台账可直接用本档字段，见 §五）；下游消费者是总账 `FUN-2`~`FUN-9` 的实现（映射表见 §六）。

## 二、通用规格：def 数据表结构提案（FUN-1 + DYN-1 + INT-4 三合一）

`config/excel/建筑数据.xlsx → buildings sheet` 在现有列基础上**新增一批可空列**，一张表同时服务功能（FUN）、动态尺寸（DYN）、管线映射（INT），不开第二张表。

### 2.1 现有列盘点与三处既有数据问题（定稿时一并修）

现列：`id / name_zh / type / tier / width / build_time / build_cost_wood|stone|metal / max_hp / workers_required / interior_mode / mega_interior_map_id / description / unlocked_by_tech / wall_tier / can_stand_on / is_gate`。

| # | 问题 | 提案处置 |
|---|---|---|
| 1 | `width` 单位不统一：`house=2`、`farm=3`、`market=2` vs `barracks=16`、`smithy=16`——前者是 32px 艺术格、后者像「标准建筑格」，两套口径混写 | 统一为**格数**（1 格 = 32px 艺术格 / 24px 运行格），全表按 DYN-1 的 `modulus` 重标 |
| 2 | `smithy_lv4.interior_mode=0` 与 `lv1=1` 矛盾（Lv4 反而进不去？） | 全系 `interior_mode=1`（铁匠铺一族都可进屋剖视） |
| 3 | `workers_required` 与场景 `WorkSlots` Marker 是两套数、无人对账 | `workers_required` 定为**工位数单一真相源**；场景 Marker 由它生成/校验（总账 `INT-6` 的收口方向） |

### 2.2 新增列提案

| 列 | 类型 | 语义 | 服务的任务 |
|---|---|---|---|
| `housing` | int，可空 | 居住位（村民床位），村人口上限 = Σ housing | `FUN-6` |
| `storage_capacity` | int，可空 | 库容（资源件数上限），村仓按建筑聚合 | `FUN-2`/`FUN-12` |
| `production` | str，可空 | 配方 `"矿:5>铁锭:3"`（输入:量>输出:量）；无消耗产出写 `"木:9>"` | `FUN-5` |
| `production_beats` | int，默认 1 | 配方周期（拍）；快慢配方的差异落这里 | `FUN-5` |
| `garrison_cap` | int，可空 | 驻军编队容量 | `FUN-3` 延伸 |
| `interactions` | csv | 菜单交互项：`recruit` / `storage` / `workshop` / `trade` / `interior` | `FUN-8` |
| `modulus` | int | 动态宽度模数 N（村舍 4 / 仓库 6 / 大型 8，详见总账 `DYN-1`） | `DYN-1` |
| `width_min` / `width_max` | int | 可建宽度区间（格），建造菜单按模数步进出选项 | `DYN-1` |
| `max_storeys` | int | 层数上限（1~4，按材质档） | `DYN-1` |
| `pipeline_def` | str，可空 | Blender 管线 def 名（如 `smithy1`↔`smithy_lv1`），内景/卡片取图用 | `INT-4` |

**为什么一张表**：总账 §九共享件 2 明确要求 def 表全系统一张（`FUN-1`/`DYN-1`/`INT-4` 共用），开多张表就是「同一建筑三处记」的老毛病复发。

## 三、分族规格（首版 5 族）

> 「实录」= `buildings.tres` 现值；「提案」= 本档新增/修改，待 `DEC-14`。产出节奏单位沿用现有「拍」（游戏内经济结算节拍）。

### 3.1 民居（house / timber_cottage）—— 人口容器

| 项 | house 民居 | timber_cottage 木骨民居 |
|---|---|---|
| 定位 | 村民居住位，人口上限的唯一来源 | 同左，高档体（石基木骨） |
| 成本/耗时/耐久（实录） | 木28 / 石12；30s；hp200 | 木26 / 石21 / 铁11；100s；hp450 |
| `housing` 基准（提案） | **4**（内景落地后按床位派生） | **6**（同左） |
| 工位 | 0（实录，维持） | 2（实录；提案改 **0**——民居不该有生产工位） |
| 交互 | 进屋（`interior`） | 进屋 |
| 解锁 | 无（开局可建） | 无 |

- **人口规则（提案；容量口径为创始人 2026-09-26 定）**：住房容量是**建筑结构属性——能住几人由内景布局（床位数）决定**，不是抽象数字：def 表 `housing` 列给基准值（上表），内景卡片化（总账 `INT-8`）与内景编辑器（`INT-9`）落地后按实际床位派生——**玩家摆一张床就多一个居住位**。容量与村民入住绑定是建筑系统的事，世界模型只消费 Σ容量。村人口上限 = Σ容量；迁移锚点：初始村配 2 民居 = 8 位，与现硬编码 `POP_CAP_DEFAULT=8`（`recruit_manager.gd:29`）无缝衔接，实现侧删除硬编码改求和。
- **昼夜（提案）**：夜晚窗户点亮（`FUN-14`）、村民夜里归巢（`FUN-15`）——民居是这两条的挂点。

### 3.2 仓库（warehouse / stone_warehouse）—— 物流枢纽

| 项 | warehouse 仓库 | stone_warehouse 石造仓库 |
|---|---|---|
| 定位 | 村仓实体：存建材、工人取货运往工地 | 同左，厚墙重货档 |
| 成本/耗时/耐久（实录） | 木29 / 石14；60s；hp300 | 木23 / 石58 / 铁17；120s；hp650 |
| `storage_capacity`（提案） | **220** | **360** |
| 工位 | 0（实录，维持） | 0 |
| 交互 | 开仓（`storage`，翻包界面取放） | 开仓 |
| 解锁 | 无 | 石造科技 |

- **取数依据**：单棵树储量 35~75，220 ≈ 4~6 棵树的吞吐缓冲；石造档容量×1.6 换来耐久×2.2（战时仓储不易被打掉）。
- **真扣料规则（提案，⚠️ 经济口径占位/`DEC-15`，以经济重做后为准）**：施工交付从「`material_progress +=` 计数」改为真扣村仓库存（`FUN-2` 的核心）；仓库本身不产不耗。
- 区域粒度（`FUN-12`）定稿前，村仓仍是全村聚合视图。

### 3.3 集市（market）—— 价格出口

| 项 | 值 |
|---|---|
| 定位 | 资源买卖的唯一建筑出口（价格后端已在：`resource_manager.gd:157-212`，现唯一消费者是调试面板） |
| 成本/耗时/耐久（实录） | 木22 / 石11 / 铁7；50s；hp250 |
| 工位（提案） | **1**（摊主；实录 `workers_required=2`，集市不需要两个工位，改 1） |
| 交互 | 交易（`trade`） |
| 解锁 | 无 |

**价差规则（提案，⚠️ 经济口径占位/`DEC-15`，以经济重做后为准）**：买入 = 基准价 ×1.25 向上取整，卖出 = 基准价 ×0.8 向下取整——买卖价差是集市的「摊位费」，玩家贸易赚的是产地差不是刷差价。

| 资源 | 基准价 | 买入 | 卖出 |
|---|---|---|---|
| 木 | 3 | 4 | 2 |
| 石 | 4 | 5 | 3 |
| 矿 | 8 | 10 | 6 |
| 沥青 | 15 | 19 | 12 |
| 铁锭 | 20 | 25 | 16 |
| 丝绸 | 50 | 63 | 40 |

### 3.4 兵营（barracks）—— 兵力入口

| 项 | 值 |
|---|---|
| 定位 | 招兵与驻军宿营 |
| 成本/耗时/耐久（实录） | 木45 / 石32 / 铁14；90s；hp500 |
| 招兵价（实录维持） | 木12 + 石9 / 人（= 一次占领奖励量级） |
| `garrison_cap`（提案） | **2 编队** |
| 工位 | 5（实录；提案改 **0**——招兵走交互不走工位，5 个工位是旧「运营工人」残留） |
| 交互 | 招兵（`recruit`，从 InteractionController 直通收口进建筑菜单，`FUN-8`） |
| 解锁 | 无 |

### 3.5 铁匠铺（smithy_lv1→lv4）—— 加工链枢纽

| 项 | lv1 | lv2 | lv3 | lv4 |
|---|---|---|---|---|
| 成本（实录） | 木27/石19/铁9 | 木42/石31/铁17 | 木55/石44/铁26 | 木78/石58/铁42 |
| 耗时/耐久（实录） | 60s / hp350 | 90s / hp500 | 120s / hp700 | 180s / hp1000 |
| 工位（实录=提案单一源） | 2 | 3 | 4 | 5 |
| 配方 `production`（实录维持） | `矿:5>铁锭:3` /拍/工位，全级同配方 | | | |

- **等级差异 = 工位并行度**（2→5），不提单工位效率——一拍同产出倍率会撞数值膨胀红线，加人手是唯一放大器。工位数与升级路径**不受经济闸门影响**（`DEC-14` 可定稿）。
- 配方的**结算与消耗流动**（5 矿进、3 锭出的账怎么走）属经济口径，⚠️ 占位（`DEC-15`），以经济重做后为准。
- lv4 描述「传说品质装备」留给 `FUN-9` 工坊制造（配方把资源品转化为装备/消耗品），本版只锁「锭」一档，且 `FUN-9` 已挂 `DEC-15`。
- 升级路径（提案）：**拆旧建新、不原地升级**（材质升级路径是 GDD §十待补充项，首版不给原地升）。
- 交互：工坊（`workshop`，现灰显）+ 进屋（`interior`）。

### 3.6 首版外一档的记账（farm）

`farm` 农场（实录 木18/石9、工位 2、描述「生产食物资源」）**暂不入首版**——资源表现无「食物」资源（木/石/矿/沥青/铁锭/丝绸），食物链是 `FUN-20` 加工品清单的悬案；定稿本档时把 farm 挪进哪一族（食物族新建 or 改产别的）随 `DEC-14` 一并拍。

## 四、数值锚点速查（提案新数一览，DEC-14 一次过目）

新引入的数值共 9 个：`housing 4 / 6`、`storage_capacity 220 / 360`、`集市买入 ×1.25↑ / 卖出 ×0.8↓`、`兵营 garrison_cap 2 编队`、`铁匠工位 2/3/4/5`、`招兵 木12+石9（实录）`。全部在现有刻度内：最大提案值 360（容量，计数类）＜ 资源点储量上限 75 的 5 倍；成本侧零新增。其中**集市价差属经济占位**（`DEC-15`），其余为建筑结构类数值。

## 五、世界模型账面口径（对齐 M1/M2）

[完整版蓝图](完整版蓝图.md) 统一数据契约：CityState 含建筑台账；**离屏 AI 城只做账面级 tick（人口/经济/建军），不做建筑清单级细算**。⚠️ **经济侧（产出/库存折算）以 `DEC-15` 经济重做后口径为准，本节相应部分仅占位**；人口侧照常（容量由建筑系统供，见 §3.1）。本规格字段因此分两层用：

- **实体层（玩家村/焦点城）**：逐 Building 实例持 `def_id / width / hp / 库存（ItemContainer）/ 居住占用 / 工位占用`，配方按拍真结算。
- **账面层（离屏 AI 城）**：按 `def_id × 数量` 聚合，产出/住房/招兵潜力直接用 §二 def 字段当**每单元系数**折算——def 表既是建造菜单的数据源，也是离屏折算的系数表，一份两用、不开平行账（总账 `SPN-1`/`SPN-2` 的落点）。

字段命名沿用 buildings 表 snake_case，`FUN` 组实现时不自造同义词（`housing` 就叫 housing，不再出现 `house_capacity`/`dwelling` 第二个名字——现状 `modules/**` 零命中的搜索习惯保持住）。
