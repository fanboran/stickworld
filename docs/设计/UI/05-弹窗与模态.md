# 05 · 弹窗与模态

> 模态栈的使用规则，以及三类"打断式"反馈组件：确认框族、Toast、Tooltip。
> 世界内弹窗（头顶进度条/交互提示）不在本篇，见
> [`../../技术/架构/场景与战斗/UI.md`](../../技术/架构/场景与战斗/UI.md) §10.6。

## 一、模态栈规则

| 规则 | 说明 |
|------|------|
| 压栈而非互斥 | 设置上可再开确认框；ESC 逐层退栈 |
| 同类单例 | 同一模态只开一个实例（重复触发 = 提到栈顶） |
| 强/弱两级 | 强模态（载入/向导）屏蔽 ESC 与输入；弱模态（设置/读档）ESC 可关 |
| 遮罩 | 每层模态自带 `MODAL_DIM` 遮罩，点击遮罩是否关闭见表白名单 |
| 时间 | 开 L4 模态自动暂停；栈空恢复原速度 |

**点遮罩关闭白名单**：设置 ✅、读档 ✅、组织面板 ✅、确认框 ❌（必须显式选择）、
载入屏 ❌、新游戏向导 ❌。

### 挂点

现状：模态挂 `ModalOverlay` 槽，`UIRoot.open_modal()` / `close_all_modals()`。
规划：新增 `SystemLayer` 槽（L5）专挂确认框/Toast——确认框不应被
`close_all_modals()` 连带清掉（例如"删除存档"确认框开在存档面板之上）。

## 二、确认框族

工厂：`StickKit.confirm(layer, title, message, on_confirm, confirm_text, kind)`。

| 变体 | 视觉 | 用途 |
|------|------|------|
| 普通确认 | ACCENT 确定钮 | 新游戏覆盖、离开未保存 |
| 危险确认 | DANGER 确定钮 + 文案写清后果 | 删除存档、拆除建筑、解散编制 |
| 输入确认（P1） | 需输入名称才解锁确定钮 | 删除帝国级不可逆操作 |

设计纪律：
- 文案 = 动作 + 后果（"拆除后将返还 50% 材料"），不写"确定吗？"式空话
- 确定钮文案 = 动作本身（"拆除"），不写"是/否"
- 取消永远是左钮、确定右钮；ESC 等效取消（确认框内）

## 三、Toast 通知

工厂：`StickKit.toast(layer, text, kind)`。

| 属性 | 设计 |
|------|------|
| 位置 | 底部居中（SystemLayer）；游戏内持久通知走左下 feed（04 §六） |
| 停留 | `T_TOAST` 3s → 0.36s 淡出 |
| 等级 | info 蓝 / warn 黄 / error 红 |
| 堆叠 | 同屏 ≤3 条，超出顶掉最旧 |
| 纪律 | Toast 只用于**即时反馈**（点了按钮的回响）；世界事件走通知流 |

## 四、Tooltip

| 属性 | 设计 |
|------|------|
| 触发 | 悬停 0.4s 后出现，跟随光标右上偏移 (12, -8) |
| 结构 | 标题（BODY）+ 描述（HINT，DIM）+ 数值行（图标+值）+ 快捷键角标 |
| 底 | `WINDOW_BG` 黑玻璃 + 1px 描边（StickTheme 已配 TooltipPanel） |
| 上限 | 宽 ≤320px，超出折行 |

内容数据驱动：控件注册 `tooltip_data`（Dictionary），统一渲染器装配——
与按钮的 `tooltip_text` 纯文本并存（简单场景用后者）。

## 五、世界内 vs 屏幕内

| 类型 | 挂在哪 | 例子 |
|------|--------|------|
| 世界内 | Node2D / BuildMaskLayer（随世界坐标） | 头顶进度条、"按 E"交互提示 |
| 屏幕内 | UIRoot 槽位（屏幕坐标） | 本目录规划的一切 |

判别标准：信息指向**世界中的某个实体**→ 世界内；指向**玩家/系统**→ 屏幕内。
