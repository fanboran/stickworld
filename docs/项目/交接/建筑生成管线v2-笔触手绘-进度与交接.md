## 架构速记（细节见设计文档）

- 数据流：`spec.gd 预设 + width_cells + seed → layout/solver.gd 开间求解 → comps.gd 构件 → builders.gd 类型编排 → draw_node._draw → gen_buildings.gd 出 PNG+JSON`。
- **开间（bay）参数化**：建筑 = 端件 + N 个开间，宽度变化 = 开间数变化，永不拉伸纹理；开间宽按中段宽均分（浮点 px 合法）。
- **确定性**：seed = `hash(["building_v2", def_id, width])`，构件级子流走 `painter.branch(tag)`；禁全局随机/时间。
- **环境红线**：本机 Polygon2D/draw_polygon 带 UV 的采样坍缩为平涂——纹理一律 `draw_texture_rect`/仿射 `draw_set_transform_matrix`（Sprite 同款采样路径）；纯色才用 `draw_colored_polygon`。
- **纸纹后处理**：CanvasLayer+ColorRect 必须用 `render_mode blend_mul` shader（普通 alpha 混合会整屏盖一层不透明灰白，第一轮翻车点）。
- 屋顶 rise 随宽度增高（solver 内动态计算并推导 img_h，防止宽建筑屋顶出画）。

## 关键决策记录

| 决策 | 理由 |
|---|---|
| 离线烘焙 PNG 而非运行时生成 | 风格上限（笔触质感随便堆）、运行时零成本、旧管线 CPU 纹理拖慢 smoke（138s）根除、同 seed 确定性 |
| Godot 2D 渲染域而非 Blender | 正面立面是纯 2D 问题；与图标管线同构的流程纪律（注册表/确定性/拼页验收），但不引入 3D 依赖 |
| 开间体系替代旧"左固定+右固定+中间拉伸" | 拉伸会让中段纹理/窗距变形，与手绘感冲突；开间增减是建筑学正确且视觉自然的参数化 |
| 元数据 JSON 随图入库（barrier/front_wall/workslots/interact_cells） | 运行时装配只做"贴图+挂节点"，消费方（建造/攻城/职业工位/近墙透明化）契约不变 |
