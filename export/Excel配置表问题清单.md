## 一、建筑数据.xlsx — 🔴 严重偏离

### 问题 1：建造消耗食物
```
当前: build_cost_food = 50/20/30/80/100/150
```
**为什么错**：火柴人不吃饭，不需要食物维生（创始人原话："把食物这种资源删掉吧，火柴人不需要进食维生"）。

**修正**：删除 `build_cost_food` 列。

### 问题 2：建造时间是固定数值
```
当前: build_time = 30/45/60/90/50/120（天数？）
```
**为什么错**：建造时间应该取决于施工队的组织水平和工程资质，应该是"工程量"的形式。

**创始人设想**：工程量细分为多种——板材切割、结构完成（大梁/穹顶/地板/墙壁独立计算），不同建造工艺需要不同资质的施工队（木工做木结构等）。

**决策**：创始人说"暂时不做了"——demo 阶段保留简化版工程量，但删除 `workers_required`（有工程量就不需要工人数了）。

**修正**：
- 列名 `build_time` → `build_workload`（工程量，单位待定）
- 删除 `workers_required` 列（有工程量，一个人理论上可以建全部）

### 问题 3：建筑需要科技解锁
```
当前: unlocked_by_tech = none/tech_agriculture/tech_crafting/tech_military_1/tech_trade/tech_education
```
**为什么错**：建筑不需要科技解锁。创始人原话："这些都不需要科技解锁"。

**修正**：删除 `unlocked_by_tech` 列。

### 问题 4：新设计补充（不在 GDD 中）
- 工程量可以分多种（板材切割、结构完成进度等）
- 不同建造工艺需要不同资质和架构的施工队
- **以上暂不实现**，demo 用简化版

## 四、平衡变量.xlsx — 🔴 大量无用变量

### 需删除的变量及原因

| 变量 | 为什么删除 |
|------|-----------|
| `var_attack_base` | 攻击力写在单位数据里了 |
| `var_defense_base` | 防御力写在单位数据里了 |
| `var_tax_rate` | 基础税率完全无用 |
| `var_trade_efficiency` | 贸易效率完全无用 |
| `var_research_speed` | 科技不是靠研究倍率驱动的 |
| `var_tech_cost_scale` | 科技消耗具体看科研行动动用了多少资源 |

| `var_supply_range` | 补给线范围看运输编制实际位置，理论上无限 |
| `var_transport_speed` | 运输速度看单位移动速度 |
| `var_pop_growth_rate` | 人口增长按个数算，不是百分比；且主要靠召唤 |

## 七、运输数据.xlsx — 🔴 设计理念完全不同

### 问题 1：运输速度是固定值
```
当前: speed = 20/40/60/80/100/999
```
**为什么错**：运输速度取决于**单位的移动速度和耐力**，不是载具自身的速度。

**创始人设想**：
- 人力运输：耐力越大的火柴人送得越多，巨人火柴人很能一次性运输很多
- 其他生物运输：看其他生物的耐力
- 器具（驼兽+车=马车，船）本质是**节省耐力**的工具，不决定速度
- 成员可以通过两班倒驾驶载具实现 24 小时移动

### 问题 2：补给线最大范围
之前平衡变量表的 `var_supply_range` 和运输表的独立速度模式都错误。

**正确逻辑**：运输编制实际在什么位置，补给就到什么位置。理论上无限，纯看玩家组织协调能力。

### 问题 3：运输载体表需要重设计
**当前列**：id / name / speed / capacity / cost_per_km / terrain_penalty / unlock_tech

**应该改为**：
- 不以"载具"为中心，以"运输方式"为中心
- 速度引用单位耐力/移动速度
- 器具是耐力节省倍率而非速度值
- 地形惩罚保留（合理）

### 关于巨人奴隶的新世界观
- 巨人生活在高山地区
- 可用铁链和军事人员押送奴役
- 巨人运输能力极强（4人高，耐力大）
