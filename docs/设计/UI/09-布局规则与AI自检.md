# 09 · 布局规则与 AI 自检

> 写给 AI 与开发者的 UI 摆放规则 + 提交前自检清单。
> **目的**：UI 摆放事故（贴边、屏幕外、不居中）大多是"手写位置"造成的，本文件给出唯一正确姿势与可机械执行的自检流程。

---

## 一、布局铁律（违反必出事）

| # | 规则 | 违反后果 |
|---|------|---------|
| 1 | **禁止 `Control.new()` + set_script 当 UI 根**（会丢 anchor 致控件静默不可见） | 控件消失/跑屏幕外 |
| 2 | **禁止手写 `position =` / `offset_*` 绝对坐标摆放控件** | 换窗口/分辨率就跑偏 |
| 3 | 浮层/HUD 部件离屏幕边缘 ≥ `SCREEN_MARGIN`(12px)，**不得贴边** | 贴边=视觉事故 |
| 4 | 弹窗/面板必须**居中**，且四周留 ≥ `MODAL_MARGIN`(48px)，不得铺满 | 弹窗出屏/覆盖全屏 |
| 5 | 全屏 UI 根用 `UIKit.full_rect()`；角落 HUD 用 `StickKit.dock()` 落位 | 布局随窗口乱跑 |
| 6 | 场景（.tscn）是布局唯一真相源；代码只装配内容、不摆位置 | 位置散落各处 |
| 7 | **弹窗/浮动窗口初始定位必须夹进安全矩形**（`StickKit.clamp_to_safe_rect`，HUD 预留区避让） | 弹窗盖住常驻 HUD 按钮 |

## 二、唯一正确的摆放 API

| 场景 | 用什么 |
|------|--------|
| 全屏界面/面板根 | `UIKit.full_rect(script, name)`（FULL_RECT + 双向 grow） |
| 居中面板/弹窗 | `StickKit.center_on_screen(panel, size)`（anchor 方案，不受窗口尺寸影响） |
| 角落 HUD 部件（小地图/缩放条/建造按钮/资源条） | `StickKit.dock(node, Corner.XXX, size)`，自动留 `SCREEN_MARGIN` |
| 弹窗/浮动窗口定位 | `StickKit.clamp_to_safe_rect(control, desired_rect)` 夹进安全矩形（HUD 预留区避让） |
| 模态弹窗 | `BaseScreen` 或 `StickKit.confirm()`（内部已确定性居中） |
| 通栏条（顶栏/底栏） | 允许铺满（anchors_preset TOP_WIDE / BOTTOM_WIDE），但内容内边距 ≥ PAD_X |

**通栏条是唯一允许"贴边"的例外**；其余一切浮层都必须留安全边距。

## 三、统一弹窗骨架（StickScreen）

所有弹窗（设置/存档/占位等）共用 `StickScreen`（`modules/ui_global/scripts/stick_screen.gd`）：
全屏遮罩 + 居中 PanelContainer（`StickStyle.window_panel`，统一 24px 内边距）+ 标题 / 内容区 / 底栏。

- 子类设 `panel_size` / `panel_title`，往 `_body`/`_footer` 加内容（Container 布局）
- **禁止在弹窗内手写 `position`/`offset` 绝对定位**（旧 BaseScreen 的坑，已弃用）
- 居中走 anchor 方案（`open()` 内 `PRESET_CENTER` + 半尺寸 offset），不受窗口尺寸/时序影响
- 底栏动作按钮右对齐（`_footer.alignment = ALIGNMENT_END`）
- 标题一律 `StickTokens.FONT_TITLE` 居中

HUD 部件标准（顶栏/资源条/角落部件）：
- 顶栏 = 通栏黑玻璃（`StickStyle.window_panel_light`），内容统一内边距 16
- 角落部件一律 `StickKit.dock()` + `SCREEN_MARGIN`，不得贴边
- 资源条等条状部件用 `PanelContainer` + `window_panel_light`（与顶栏同质感），
  不用裸 `ColorRect` 手画背景

## 四、常见事故清单（AI 自查：有没有踩这些坑）

- [ ] 用了 `Control.new()` 当根，没走 `UIKit.full_rect()`
- [ ] 手写 `position = Vector2(...)` 摆按钮/标签
- [ ] 角落部件 `offset_*` 是 0 或负数（贴边/出屏）
- [ ] 弹窗尺寸 ≥ 屏 90%（应居中且留边距）
- [ ] 依赖 `get_viewport().get_visible_rect()` 手动居中（应用 anchor 方案）
- [ ] 新增 UI 前没先确认父容器是 FULL_RECT（父为 0 尺寸 → 子控件全跑原点）

## 八、分层与输入屏蔽（RTS 标准）

### 8.1 UIRoot 层序（z 从低到高）

```
z=0    GlobalHUD / ModePanel / ContextPanel / ResourceBar / HudOverlay
z=50   ModalOverlay   ← 模态遮罩（BaseScreen/StickScreen 打开时盖住全部 UI）
z=100  UiInspector    ← F3 调试：悬停 UI 显示控件名+脚本路径
```

**关键**：`ModalOverlay` 必须排在 `HudOverlay` 之后（绘制在上）+ `z_index=50`，
否则建造按钮/悬停反馈等 HudOverlay 部件会盖在模态遮罩之上（历史 bug）。

### 8.2 模态打开自动暂停

`StickScreen.open()` 自动暂停（记原速度），`close()` 恢复（仅最外层恢复，嵌套安全）。
暂停同时冻结：世界/AI 更新、玩家移动、相机缩放（遮罩 STOP 消费滚轮）、
悬停角色反馈（hover_indicator 检查 `TimeManager.is_paused()`）。

### 8.3 ESC 语义（统一模态栈退栈，GameRoot._handle_escape 仅保留 POSSESS 特判）

```
有模态 → 逐层退栈顶（设置/存档/占位/确认框→取消）；无模态 → 开暂停菜单
附身模式（POSSESS）→ 不消费，ESC 留给退出附身
```

暂停菜单（`PauseMenuPanel`）：继续游戏 / 设置 / 存档管理 / 保存并回主菜单。

### 8.4 调试辅助

F3（DebugApi 可见）时鼠标悬停任意 UI 控件，右下角浮层显示：
`控件名（类型）` + `脚本来源路径`——排查"这是哪个控件/来自哪个场景"。

## 九、弹窗定位与避坑经验（踩过多次的坑，必读）

### 9.1 Godot 弹窗居中的正确姿势

**坑**：`control.position = ...` 与 `set_anchors_preset(PRESET_CENTER)` 混用会**失效**——
实测窗口被摆到父容器左上角原点（`win.center=(0,0)` 而 `dim.center=(960,960)`）。
这是反复犯的错（confirm 确认框曾跑到屏幕左上角）。

**正确做法（二选一，都可靠）**：

| 方式 | 代码 | 说明 |
|------|------|------|
| A. 绝对居中 | `anchor 归零(PRESET_TOP_LEFT)` + `position = (parent.size - self.size)*0.5` | 不依赖 anchor，最直观 |
| B. offset 半尺寸 | `PRESET_CENTER` + `offset_left/top/right/bottom = ±size/2` | 直接设 offset，不用 position setter |

**禁用**：`PRESET_CENTER` + `position = -size/2`（position setter 配 anchor 在 Godot 失效）。

**已封装**：`StickKit.confirm` / `StickKit.toast` 已用方式 A 修正；新弹窗照抄它们，
不要重新发明定位。全屏居中也可用 `StickKit.center_on_screen`。

### 9.2 UI 元素重叠（抢位置）

**教训**：材料条曾放进"顶部中央"——与既有的**小地图**（顶部中央 240×80）重叠；
材料条（ResourceBarHost）曾压在顶栏按钮行底部（y=46 与按钮 y=12~52 重叠 6px、
并探出 60px 顶栏外），2026-08 修复为顶栏下方独立横条（y=64 起）。

**规则**：
- 新增 HUD 部件前，先看 `04-游戏内HUD.md` §一 布局分区图（小地图=顶部中央、
  缩放=右下、材料=顶栏下方、通知=左下），**别去占领已占用的区域**。
- 角落部件一律 `StickKit.dock()` + `SCREEN_MARGIN`；通栏条只允许顶栏/底栏本体。
- 若两处都需要顶部中央，先合并成一块或挪走一个，不要叠放。

### 9.2a HUD 预留区与安全矩形（防 UI 重合的通用方案）

> **行业惯例**：常驻 HUD 占据屏幕固定区域（顶栏/底栏/角落），弹窗与浮动窗口的
> 初始定位**夹进"安全矩形"**（viewport 减去 HUD 预留区），从机制上杜绝"弹窗盖住
> 常驻按钮"（如材料窗口/编制窗口压住顶栏按钮）。同类做法：MMO/策略游戏把
> HUD 视为不可侵占区，弹窗自动避让（safe area / reserved zone）。

- 预留区常量单一真相源：`StickKit.HUD_TOP_RESERVED`（顶栏 60 + 材料条 35，=104）/
  `HUD_BOTTOM_RESERVED`（底部 ModePanel 80，=88）——**改 HUD 尺寸时同步改这里**。
- `StickKit.safe_rect(control)` 返回安全矩形；`clamp_to_safe_rect` 把期望矩形平移夹入
  （过大窗口缩到安全区大小）。
- `StickWindow`（FLOATING/POPOVER）初始定位已自动夹紧（`_position_panel`），
  新弹窗只需继承 StickWindow 或调用 `clamp_to_safe_rect`，不必手写避让。
- **回归测试**：`tests/integration/test_ui_layout.tscn`（headless 可跑）固化两条不变式——
  ① 顶栏按钮与材料条不重叠；② 任意 FLOATING 窗口在 1080p/720p 下都不盖顶栏。
  新增/改动任何面板布局后跑它，重叠即失败。

### 9.3 GDScript freed 实例判断

**坑**：`if obj` 对**已释放**的 Object 仍为真（引用非 null），访问其方法会报
"Trying to assign invalid previously freed instance"（曾致"保存并退出"回主菜单后
自动存档崩溃：game_root 被释放但 SaveManager 模块注册表仍持有旧引用）。

**规则**：凡是可能持有跨场景对象的引用，判断存活一律 `is_instance_valid(obj)`，
freed 时顺带清理持有它的容器（如注册表 `erase`）。
