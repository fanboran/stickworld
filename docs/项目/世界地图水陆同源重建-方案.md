# 世界地图「水陆同源」重建方案

> **用途**：创始人 2026-09-22 要求「根本性修复」，针对战略图反复出现的「色块与地图不严丝合缝」（已出现三次、每次修的都是症状）。本方案给出**口径级**的根治路径与验收线。
> **上游诊断**：`docs/项目/交接/L1战略图-邻省上下文与切省箭头-进度与交接.md` §3.0 / §3.0b（真因 + 两代图盘点，全部带实测数字）。
> **状态**：**决策全部拍板并已实施**（D1~D6 见 §五决策台账；P1 出生包完成 + 创始人识图复检九条根因全部修掉），创始人已验收观感；进度详见 [`docs/项目/交接/世界地图水陆同源重建-进度与交接.md`](docs/项目/交接/世界地图水陆同源重建-进度与交接.md)。
> **与主线的关系**：本档是 **L1 战略图支线**移交出来的治本轨（该支线原派生于 [`扩张循环`](交接/扩张循环-国家疆域与战斗结算-进度与交接.md) 的 P4 政治图观感）；**主线（扩张循环 P5 国家层数据接入）不因本档受阻**。

## 一、根因一句话

**"哪里是水"在管线里被定义了三次，且各自漂移**：

| 定义者 | 依据 | 后果 |
|---|---|---|
| 地形上色 | `locked_continent_8192` + 湖/河掩膜，**另加**「源流」群系的河湖沿岸膨胀带（浅蓝 `95,160,195`，与真水同色） | 视觉水线 = 海岸线**再往内 4~11px** |
| 政治几何 | 城块/老 L1 标签场（另一条 lineage：区域 tiles → 城块生长 → 细化场） | 与上者的差 = 缝 |
| 政治渲染的「水面回贴」 | 对地形贴图做**绿-蓝差猜色**判水 | 把源流带也判成水 → 色块被挖到带内缘，而描边画在外缘 |

叠加效应：**同一条海岸线上有三条互不重合的线**（地形水线 / 色块填充边 / 描边），差 3~19px。历次修复（把回贴步长改成 1、把政治界加宽到 3px 盖缝、把邻块轴序换回来）都是在**症状层**加补丁，因此每加一层就多一条线。

## 二、目标与不变量（修复后必须成立）

| # | 不变量 | 量法 |
|---|---|---|
| **I1** | 只有**一个**水/陆真相：`locked_continent_8192`（海）× `fractal_lake_mask_8192`（湖）× `fractal_river_mask_8192`（河），三者同一次生成 run 产出 | 产物 mtime 同一批；`check_mapdata_consistency` 断言 |
| **I2** | 政治几何**严格贴陆**：`几何 ∩ 海 = 0 px` 且 `陆地 \ 几何 = 0 px`（无内缩毛边） | `geometry ∩ ocean`、`land \ geometry` 两项归零 |
| **I3** | 政治渲染**不再自己判水**：色块填充边、描边、地形水线三者**几何同源**，逐像素重合（容差 ≤1px 抗锯齿带） | 色块边界→水掩膜边界距离 p90 ≤1px |

推论：I1+I2 ⇒ 换任何一代标签场都不会破 I2（因为几何先贴陆再提轮廓）；I3 ⇒ 删掉"颜色猜水"这条口径，管线里只剩一份"水"的定义。

## 三、方案分层

### L1｜水真相前移：生成期产出「水面覆盖贴图」

> **2026-09-22 创始人定向后的修订**：本层的「水面覆盖贴图」在 **L2 落地后不再必需**——几何严格贴陆（`labels[水]=0`）时色块根本盖不到水面，地形里画的水自然原样可见。故本层降级为**可选保险**（用于"几何暂时没贴陆"的过渡期或异常包），主路径改为 **L3 的水体矢量后处理**（见下）。

- `l1_terrain_bake.py` 在同一次 run 内**同时**产出 `<pack>/l1_water_overlay.png`（RGBA：RGB = 地形像素原样、A = 掩膜判水量，8192 原生、与该包 `l1_terrain.png` 同窗口同代）。
- 运行时 `bake_water_restore()`（颜色判水 + 逐像素扫描）**整体退役**，改为直接解码这张贴图。
  - 收益：判水口径回到生成端且**只有一份**；运行时零启发式；顺带省掉每次进政治模式的像素扫描。
- 湖/河用哪一代：**必须与地形上色同一份**（当前地形用原始 `fractal_lake_mask_8192`）。若将来升级到 `audit4_refined_lake_8192`，地形与 overlay 一起重烘——纪律写进工具 CLI（不允许分两次跑）。

### L2｜几何贴陆：导出前统一后处理

- 在轮廓提取**之前**对标签场做两步（`tools/worldgen/l2_export/mesh_extract` 调用点统一接入，L1/L2/L3 导出器共用）：
  1. **贴陆**：`labels[locked_continent == 0] = 0`（含湖/河一并归 0，水面不进地块）；
  2. **回填**：陆地内的 `0` 空洞按 EDT 最近标签回填（消除内缩毛边，保证 `陆地 \ 几何 = 0`）。
- **这一步是"用精细版"的前置**：现行细化场越海 0.79%~3.22%（距陆地 p50 3px/p90 7px/max 12px，与其自身注释矛盾），**贴陆后处理一挂上就合规**，因此不必改细化脚本本身（其第 2 步注释需同步订正，避免继续误导）。修好后两代标签场都满足 I2，选哪一代只是观感取舍，不再牵动对齐。

### L3｜水体改矢量后处理：渲染不再碰像素

**创始人 2026-09-22 定向**：「后处理再画河流，用精细的」——政治模式的水体改为**声明式矢量 pass**，绘制在色块之上、描边之下：

| pass | 数据源（包内已有） | 画法 |
|---|---|---|
| 地形底 | `l1_terrain.png` | 照旧（含海；内陆水的描画被矢量 pass 覆盖/接替） |
| 色块 | tiles 多边形（L2 贴陆后） | 半透明国色，**只盖陆地** |
| **河流** | `rivers`（`river_export.py` 骨架化折线 + **EDT 实测宽**，与底图河流掩膜同源） | `draw_polyline`，宽 = `w + 1px`（多 1px 盖住底图 `gaussian_filter(0.9)` 的羽化边），色 = `MapTokens.L1_RIVER`（与地形同 token） |
| **湖泊** | `lakes` 多边形（若用精细湖光栅则**同批重提**多边形） | `draw_colored_polygon`，色 = `MapTokens.L1_LAKE` |
| 描边/轮廓/城市点 | 几何 | 照旧 |

- **收益**：① 水体与几何同一套矢量语言、同源同代；② 放大到 3× 时不再糊（贴图是 8192 原生，矢量无分辨率上限）；③ 运行时**彻底不判水**——`bake_water_restore` 整段删除，`L1_WATER_*` 四个 token 退役；④ 河湖边界与其在底图里的位置由**同一个掩膜**决定，不存在"矢量湖与贴图湖不一致"的旧顾虑（旧顾虑的前提是底图也画了湖——现在两者同源且矢量在上层）。
- 代价：政治模式多两条绘制调用（零数据增量）；河流折线是骨架化抽稀结果，边缘比底图的手绘感更"干净"（观感取向，P1 出图对比确认）。
- 纪律：河流折线宽度必须继续取自 EDT 实测（`w`），**不得改用固定像素宽**——否则与底图河带宽度不再对应，"同源"就断了。

### L4｜消除"口径可以悄悄漂移"的结构（根本性的一半）

1. **双代二选一**：`refined_city_labels_8192.npy`（现落在 `output/diag/l1_v2/`）与 `city_labels_8192.npy` 只留一份，另一份删除；湖光栅同理。
2. **产物路径归位**：`biome_labels_2048.npy` / `biome_hot_zone_2048.png` / `refined_city_labels_8192.npy` 回到脚本读取的 `output/` 下；导出器/烘培器**缺输入一律报错退出**，不再静默回退（本轮"L1 悄悄用了旧代"就是这么来的）。
3. **守门断言进测试矩阵**：新增 `tools/worldgen/check_mapdata_consistency.py`（或并入 `tests/` 矩阵，纯 Python 读产物，不需要 Godot）：
   - 逐包：`几何越海 = 0`、`陆地漏盖 = 0`、`色块边界→水掩膜 p90 ≤1px`、`l1_water_overlay` 与 `l1_terrain` 同尺寸同窗口、`neighbors/tiles/l1_polygon` 轴序自证；
   - 失败即非零退出 → 接进 `tests/run_all.sh` 的既有门禁。
   - **这条是防止"第四次复发"的关键**：把"对齐"从人工审计变成构建期断言。

## 附录 A｜诊断证据（自交接档 §3.0/§3.0b 迁入，2026-09-22/23 审计）

### A1 R4 真因：**「哪里算水」被算了三遍，三个口径各画一条边**（2026-09-22 第三轮审计）

创始人复审「还是没严丝合缝」，并问「是图像的数据源没对齐吗 / 是不是某次重构出问题了」。审计结论：**图像数据源是齐的，错在"水"的定义在三个环节各一套**。

**先排除的（实测，都是零位移）**

| 判据 | 结果 |
|---|---|
| 地形贴图 ↔ 全局政治栅格（裁剪窗内） | 一致率 94~98%，平移搜索 ±3px 最优恒为 **(0,0)** |
| `l1_base.png` ↔ `l1_terrain.png` 海岸线 | 双向距离 p90 ≤2px，最优平移 **(0,0)**；两贴图在校验重叠区**逐字节相同** |
| 包几何 ↔ `l3_l1.json` 权威多边形（69 包全量） | own IoU **0.999**、质心偏移 ≤0.3px（仅 #19~#62 一簇 10~200px 偏移，是 R3 批「l1_polygon 改城块并集」的**语义差**，非错位） |
| 轴序（tiles / rivers / lakes / roads / neighbors） | 69 包全量无轴序反（换序打分全面更低）；邻块环修后 IoU 0.98~1.0 |
| 游戏渲染 ↔ 数据真值离线复刻（同变换采样逐像素比） | 中值差 3.6，>40 的像素 **1.88%**，且全部落在**描边/箭头/城市点**上——渲染忠实于数据 |

**真因（像素级定位，可复现）**

在地图坐标 `(371,285)` 一行横切（`python tools/worldgen/l1/audit_l1_fit_coast.py --labels 69` 同族判据）：

| 地图 x | 地形色 / g-b | `city_labels` | `legacy_l1` | `fractal_river_mask` | 源流群系 |
|---|---|---|---|---|---|
| 356~358 | 绿(109,143,78) 陆 | 1034 | 69 | 0 | 否 |
| **360~362** | **(76,127,150) g-b −0.09** | 1034 | 69 | 0 | **是** |
| **364~368** | **河色(46,102,140) g-b −0.149** | 1034 | 69 | **1** | **是** |
| 370+ | 海色(51,91,131) | **0** | **0** | 0 | 否 |

即：**几何（城块/省界/邻块环）走的是陆地蒙版 `locked_continent_8192` 的海岸线（x≈370）**；而**地形上色在岸线以内 4~11px 还画了一条浅蓝带**——它是 `biome_generate.apply_source` 的「**源流**」群系（河湖沿岸膨胀带，`source_band_px=1`@2048 → 8192 上 4~8px，色 `(95,160,195)`），沿这条入海河铺开，**视觉上与真水同色**（该带 g-b ≈ −0.13，与海水同号）。我第一轮的**水面回贴用绿-蓝差判水**，把这条带也判成水 → 把色块**涂掉**到浅蓝带内缘；描边仍沿几何画在外缘 → 两者之间露出 **p50 3px / p90 10px / 最大 19px** 的带（#69：边界落水点 1640 个，其中 >4px 者 610 个），这就是创始人看到的"不严丝合缝"。

> 结论一句话：**视觉水线（源流浅蓝带外缘）= 几何水线（陆地蒙版），但回贴线（颜色判水）在它内侧 → 色块边与描边错开一条浅蓝带。**

**修法（三档，按代价升序）**

| 档 | 做法 | 代价 | 效果 |
|---|---|---|---|
| **F1** | 回贴判水只认**真水色族**（海 near/far、湖 `72,116,158`、河 `46,102,140`）＋色相容差，排除源流浅蓝 `95,160,195` 及其与陆地混色 | 改 `map_renderer_tex_jobs.bake_water_restore` 一处 + 单测 | 色块回到陆地蒙版岸线，与描边重合 → 缝消失；河湖本体仍被回贴（第一轮诉求不回退） |
| **F2** | **判水改用量掩膜**：生成期把 `fractal_lake_mask\|fractal_river_mask` 按包窗口裁成 `l1_water_mask.png` 入包，运行时按掩膜 alpha 回贴，颜色口径退役 | 70 包各加一张掩膜 + 回贴读掩膜 | 彻底不猜颜色；湖河边界与地形同源（地形上色用的就是这两张掩膜） |
| **F3** | **口径收口**：源流膨胀带不再画成浅蓝（只在湖/河本体保留水色，沿岸带改陆地色或收窄到 2~3px），让"蓝=水"在全图成立 | 改 `biome_generate` + 重烘 70×2 张地形贴图（几何不动） | 地形水线 == 几何水线 == 回贴线，三源合一；L2/L3 同规则受益 |

**建议**：F1 先上（一小时级、立刻消观感），F2 随后（把颜色口径彻底退役）；**F3 需要创始人拍板一件设计口径**——「源流（河湖沿岸浅蓝带）」是要保留视觉表达，还是不再画成浅蓝？选前者就只做 F1+F2（浅蓝带会显示为"被色块盖住的浅蓝"，但与描边齐平，不再有缝）；选后者做 F1+F2+F3（"蓝=水"全图成立）。

> **F1/F2/F3 是症状层的三档；"根本性修复"另立方案**：[`docs/项目/世界地图水陆同源重建-方案.md`](../世界地图水陆同源重建-方案.md)（水真相前移生成期 + 几何贴陆 + 渲染同源 + 双代清理与构建期守门断言；待创始人拍板该方案 §五 三项决策）。

**顺带查出的"重构对齐"遗留（供决策，不等于立即要修）**1. **轴序是"按包族分两套"，靠 loader 各自记，不是文档错**（复查结论）：L1（出生包 + `l1_packs`）几何/河流/道路/湖 **`[x,y]`**（逐包实测：河流落水率 `[x,y]` 0.72~0.77 vs 换序 0.32~0.50，无一路反）；L2·L3 老字段 **`[y,x]`**（`l2_packs` 河流实测换序 0.82~0.92 vs 直读 0.30~0.62，确认 `[y,x]`）；`l3_l1.json` 的 polygons/centroid 亦 `[y,x]`。两套写法在 `l_world_bake.gd` 头部与 `世界地图数据流.md` 都注明了，且两个 loader 各自转序（`L1WorldData._polygon_from` 直读、`L2WorldData._to_vec2` 换序）——**实例自洽，但同一字段名两套轴序是长期隐患**（上一轮邻块环踩的就是它）。`世界地图数据流.md` §121/§126 两处备注与此一致，无需改。
2. **S1 细化场连通性断了**：`export_l1_view_context.py` 优先读 `output/l1_v2/refined_city_labels_8192.npy`，该文件实际在 `output/diag/l1_v2/`；`terrain_render.load_inputs()` 要的 `biome_labels_2048.npy` / `biome_hot_zone_2048.png` 同样只在 `output/diag/`。**导出器静默回退到未细化标签场；今天复烘地形会直接报错**——即"上一批对齐清账之后，全链没再复跑过"。
3. **L2 有海岸裁切步骤、L1 没有**：`tools/worldgen/l2_export/update_tiles_coastline.py`（按 8K 蒙版裁海岸线）只服务 L2/L1 tiles 链；L1 视图包几何直接沿用标签场（=沿用蒙版）。所以**只要地形侧口径统一（F1/F3），L1 不必重导几何**。

### A2 创始人 2026-09-22 追问复核：「有些图我超分过，会不会和旧图不对齐」

盘点结论：**确实存在"两代图"并存，且消费方分叉；但它不是当前这条缝的原因，切到新代反而更糟。**

| 资产 | 旧代（在用） | 新代（超分/细化） | 谁在用 |
|---|---|---|---|
| 城块标签场 | `output/l1_v2/city_labels_8192.npy` | `output/diag/l1_v2/refined_city_labels_8192.npy` | **L1 = 旧代**（导出器首选新代但路径断了，静默回退）；**L2/L3 弧拓扑 = 新代**（`arc_topology.py --labels`） |
| 湖光栅 | `output/fractal_lake_mask_8192.png` | `output/diag/audit4_refined_lake_8192.npy`（"含海湾案修正"，全图 +10575 / −47973 px 水） | L1 贴图实测 = **旧代**（`--lake-refined` 未启用） |
| 大陆蒙版 / 地形贴图 | `locked_continent_8192.png` 唯一一份 | —（"超分同族算法"只落在上面两项的细化场） | 地形与政治几何都读它 |

实测两代城块场差异（全图抽块 + 4 包窗口）：98.4%~99.2% 像素相同；不同处**只有"细化版多出城块"一个方向**（旧陆新水 **0 px**、旧水新陆 6.7k~31k px/窗），即细化场是**单向外扩**。后果：细化场岸线落水点显著增多（#69 460 → 1451；#59 1446 → 7079），**海岸比旧代更伸进水里**。
→ **所以"把 L1 切到细化场"不是修法**（会把 F1 要修的那条缝加宽）；正确顺序是先把水口径统一（F1/F2），再评估要不要让 L1 与 L2/L3 同代。

**地形贴图侧实测没有超分错位**（重要，推翻了本轮中途的一次误判）：把 `l2_packs/region_013` 的地形贴图窗口原点解到像素级（**CX=4814、CY=2240**——注意该包 context 在 x 上有 158px 边距、y 上为 0，是个不对称的坑；按"bbox 四周等边距"推会错 152px 并得出"L1 与 L2 是两张图"的假结论），解出后 L1 贴图与 L2 贴图在同一窗口**平均差 0.67 / 中位 2** = 同一张图。L1 的 `biome_blend_sigma=1.2` 平滑是唯一可见差别（细节能量 1.51 vs L2 的 1.79，mod4 无周期）。

**另一处"看起来不对齐、实为设计如此"（已排除）**：#19~#62 一簇省的 `l1_polygon` 与其城块并集差得多（#59 省轮廓 42841px vs 城块 75393px，IoU 0.568）——因为 `l1_polygon` **只取主环**（多岛省丢岛，见 commit `e3ba957e`），而城块含各岛城市；色块越出省界线是合理的。

**创始人 2026-09-22 追加追问：「伸进水里就把水也跟新一代对齐不就得了？新一代不是水和陆地一起改的？」——实测答案是「不行，因为不存在"新水"」（以陆地蒙版为尺子量）**

| 量 | 旧代（L1 在用） | 细化场（新一代） |
|---|---|---|
| 相对 `locked_continent_8192` **越海**（几何伸进海里） | **0 px**（4 包窗口全为 0，严格贴陆） | **0.79%~3.22%** 面积（#69 5791px / #18 7679 / #67 10676 / #59 27070），距陆地 **p50 3px / p90 7px / max 12px** |
| 未盖陆地（几何内缩留下的缝） | 0.24%~0.96% 陆地面积 | 0.14%~0.45%（略好） |

- **新一代只产出了「城块标签场细化版 + 湖光栅细化版」两件，没有任何配套的新陆地/新水蒙版**。全仓陆地真相仍只有一份 `locked_continent_8192.png`（2026-08-09 12:30，与 lake/river 两张 mask 同一次 `fractal_continent` 产出）；region 的 `mask_8192_full.png`（08-19）与它海岸线一致（region 岸线→locked 陆地距离 p50 0 / p90 2 / max 3 px），region `tiles_8192.npy`（08-08）**严格包含在 locked 陆地之内**（越海 0）。→ **没有"把水对齐过去"的对象**；把水跟细化场的几何走 = 把海面涂成陆地，海岸线会缺角。
- 细化场越海的 5253px（region_013 窗内）**既不在 locked 陆地内、也不在 region tiles 内**，与 `refine_city_labels.py` 头部第 2 步"海岸贴合：`refined[原生海岸蒙版==0]=0`"的声明矛盾——**是那一步没做到位（缺陷，非设计）**。
- **正确落法**（比 F1/F2 更完整的目标态）：**几何与水都听同一代真相——`locked_continent_8192` + 湖/河掩膜**：
  1. 几何侧：对城块场做一次"贴陆地"（`labels[locked==0]=0` + 陆地空洞按最近城块回填）——即修细化脚本第 2/3 步该做对的事，两代都可套用，做完越海归 0、漏盖归 0；
  2. 水侧：判水只用量掩膜（= F2；F1 是其快版）；
  3. 源流带不再画成水色（= F3），否则几何贴陆后那条带仍会被判水从色块里挖掉。
- 因此**当前缝全部来自水侧**（源流带 + 颜色判水），L1 现用几何越海为 0 不背这个锅；要不要把 L1 切到细化场，得先把第 1 步做掉（否则越海 3~12px 会把缝加宽）。
