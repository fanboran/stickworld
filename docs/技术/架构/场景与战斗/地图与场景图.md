## 三、地图与 Chunk 系统

### 3.1 地图类型分类

| 类型 | 用途 | 特征 | 进入方式 |
|------|------|------|---------|
| `VillageMap` | 村落/定居点 | 水平卷轴 + 垂直显示范围限定（ground_y 约束，详见 [场景宿主架构.md](场景宿主架构.md) §2.4.3），重复地面纹理 | 战略图进入 / 快速旅行 / 步行 |
| `BattlefieldMap` | 战场 | 更长更空旷，两端各有建筑/阵地，同样垂直显示范围限定 | 触发战斗进入 |
| `RoadMap` | 村落间道路 | 水平卷轴 + 垂直显示范围限定，可亲自步行 | 步行走出村落末端 |
| `IndoorMap` | 小型室内（铁匠铺） | 挂载在建筑内，墙面透明化，独立 ground_y（可能地面占比更大） | 走进建筑交互区 |
| `MegaInteriorMap` | 大型建筑（宫殿） | 独立完整场景，独立 ground_y | 传送切换 |
| `SlopeMap` | 山坡/阶梯地形 | **独立逻辑**：相机可倾斜旋转、ground_y 按 X 变化、台阶处需工程队搭爬梯，不复用 VillageMap 卷轴算法 | 特定区域传送 |

**关键**：
- `VillageMap` 与 `BattlefieldMap` 共用同一套 Chunk 系统，区别仅在数据配置（chunk 数量、地形空旷度、建筑密度）
- **所有地图类型都遵循"水平卷轴 + 垂直显示范围限定"原则**：相机 Y 不跟随角色 Y，由 `ground_y` + `ground_ratio` 计算（详见 [场景宿主架构.md](场景宿主架构.md) §2.4.3）；火柴人脚部锁定在 `ground_y`（详见 [战斗与AI.md](战斗与AI.md) §7.1）
- 每张地图可在 Inspector 调整 `ground_ratio`（默认 0.33，室内可能 0.5）

**`SlopeMap` 独立原则（重要）**：
山坡/阶梯/倾斜地形走独立 `SlopeMap` 类型，**不污染通用 VillageMap 架构**：
- `SlopeMap` 不复用 CameraRig 的水平卷轴算法，有自己的 `SlopeCameraRig`（可旋转/倾斜跟随）
- `SlopeMap` 有自己的 `SlopeStickmanController`（Y 跟随地形高度查表，不能自由上下移动）
- 火柴人在 SlopeMap 中只能沿斜坡前进/后退
- **台阶断崖**：火柴人无法直接跨越，需工程队搭建"爬梯"建筑（一种特殊建筑类型 `ladder`）才能通过
- 普通地图（VillageMap/BattlefieldMap/RoadMap/IndoorMap/MegaInteriorMap）**保持简单**，不为山坡让步
- 实施时机：山坡地图实际开发时再实现，P0 阶段不涉及

### 3.2 Chunk 流式加载

每张地图由若干 **Chunk**（固定宽度的可游玩片段）拼接：

```
Village_A 地图：
  Chunk[0] | Chunk[1] | Chunk[2] | ... | Chunk[N]
  ← 旧     当前激活   预加载         末端 ->

玩家接近 Chunk[i] 末端触发器
  -> SceneLoader 预加载 Chunk[i+1]
  -> 玩家跨入 Chunk[i+1]
  -> SceneLoader 卸载 Chunk[i-1]（保留过渡缓冲）
```

**Chunk 规格**：
- 一个 Chunk ≈ 1~2 屏宽（约 1920~3840px）
- 每段含地面段 + 该段的建筑/装饰/触发器
- **跨 Chunk 边界**：地面纹理连续，建筑不能跨边界
- **Chunk 末端出口**：地图末端 Chunk 有"出口触发器"，跨入后 -> `SceneLoader` 加载相邻地图

> **⚠️ 实现状态（实现状态审计）**：当前 Chunk 流式加载**仅为占位**。`SceneLoader.preload_chunk()` / `unload_chunk()` 只有 TODO 注释，直接 emit 信号不实际加载（见 [scene_loader.gd:236-246](file:///f:/VSCode/game-2/stick-world/modules/world/scripts/scene_loader.gd)）。当前每张地图是**整张一次性加载**的完整场景（`test_village_map.tscn` / `test_road_map.tscn` 等），未拆分为 Chunk。
>
> 阶段 0.8 的"多场景衔接"通过**地图末端出口触发器**（`ChunkTrigger` 节点，`target_map_id` 字段）实现**地图间切换**，而非地图内 Chunk 流式加载。这是两个不同层级：
> - **地图间切换**（已实现）：村落 A 末端 -> RoadMap -> 村落 B
> - **地图内 Chunk 流式**（未实现）：同一张地图内的分段加载
>
> P0 阶段单张地图足够小，整张加载性能可接受。真正需要 Chunk 流式时（大地图、长道路），再补全 `preload_chunk` / `unload_chunk` 实现。

### 3.4 MapInstance 节点结构

```
MapInstance (Node2D)
├── PlacementGrid                 ← 占地网格（见 [建筑与定居点.md](建筑与定居点.md) §4.2）
├── TerrainLayer                  ← 地面纹理重复渲染
│   └── GroundPolygon             ← 地面多边形（顶点从 ground_y 开始向下）
├── GroundLine (Marker2D)         ← 地面线标记（y = ground_y，供调试可视化）
├── DecorationLayer               ← 装饰物（草、石头、墙）
├── BuildingHost                  ← 当前激活的建筑节点容器（运行时所有建筑实例都在此）
├── TerrainBuildings (Node2D)     ← 地形建筑（只读，随场景打包，不可拆除，见 [建筑与定居点.md](建筑与定居点.md) §4.5）
├── InitialBuildingsList (Node)   ← 初始建筑数据列表（def_id + cell_x + width，见 [建筑与定居点.md](建筑与定居点.md) §4.5）
├── WalkBarrier (Node2D)          ← 地图级透明障碍容器（悬崖/高楼边缘，见 [战斗与AI.md](战斗与AI.md) §7.1.2）
│   └── BarrierRect[] (Area2D)    # 矩形障碍区域，火柴人不可穿越
├── BuildMaskLayer (Node2D)       ← 不可放建筑区域（大石头/山坡阶梯处，见 [建筑与定居点.md](建筑与定居点.md) §4.2）
│   └── BuildMaskRect[] (ColorRect) # 设计时绘制，运行时注册到 PlacementGrid.blockage_mask
├── ForegroundLayer (Node2D)      ← 前景层（z_index=10，室内支柱/天花板，火柴人经过被遮挡）
├── EntityHost                    ← 当前激活的火柴人节点容器
├── ChunkTriggers                 ← 末端触发器
└── BattleAnchor                  ← 战斗实例挂载点（城镇被袭时启用）
```

**z_index 层级约定**（各宿主层固定，按此表）：
- TerrainLayer = 0（地面最底）
- DecorationLayer = 1
- BuildingHost = 2（动态建筑）
- TerrainBuildings = 2（地形建筑，与动态建筑同层）
- EntityHost = 3（火柴人）
- ForegroundLayer = 10（前景支柱最高）

**y-sort 约定**（`MapBase._ready` 统一开启）：
- `EntityHost.y_sort_enabled`：火柴人按 Y 排序——**Y 越大（越靠下）渲染越靠顶层**
- `BuildingHost` / `TerrainBuildings` 也 `y_sort_enabled`：建筑按基线排序（根位置 ≈ 地平线+96px，差 `collision_bottom_local` ≤5px）
- 子节点（如武器）**继承父级 z，不做强制抬升**——武器与角色同图层

**同层约定**：
- 武器挂载后随角色图层（不设 `z_index`/`z_as_relative`）
- 地面硬化（土路 `_dirt_road_poly`）与地面同层（z=0，晚于 TerrainLayer 绘制故盖在草地上方）

> **地图场景迁移方向**：`maps/*.tscn` 除初始场景（village_a）与旅行系统必需场景（village_b/road_a_b/battlefield/forest_zone/mega_interior）外均视为占位符；
> 后续全部转换为 JSON/二进制（程序化生成 + 存储系统落地后废弃 tscn 存地图信息）。已删 l1_settlement_00~07 等无引用占位场景。

#### 3.4.1 MapInstance 关键字段

```gdscript
# 所有 MapInstance（VillageMap/BattlefieldMap/RoadMap/IndoorMap/MegaInteriorMap）共用
@export var ground_y: float = 300.0       # 地面线 Y（世界坐标），火柴人可走区域顶部
@export var ground_ratio: float = 0.4     # 地面占屏幕高度比例（Inspector 可改，默认 2/5，室内可能 0.5）
@export var ground_bottom: float = 1024.0 # 地面底部 Y（火柴人可走区域底部）
@export var map_left: float = 0.0         # 地图左边界 X
@export var map_right: float = 2048.0     # 地图右边界 X
```

- `ground_y`：地面顶部，火柴人可走区域上边界（详见 [战斗与AI.md](战斗与AI.md) §7.1.1）
- `ground_bottom`：地面底部，火柴人可走区域下边界（对应 GroundPolygon 底部）
- `ground_ratio`：相机计算用，让地面线在屏幕下方此比例处（详见 [场景宿主架构.md](场景宿主架构.md) §2.4.3）
- `map_left`/`map_right`：相机水平边界 + 火柴人 X 活动范围

#### 3.4.2 公共方法

```gdscript
get_ground_y() -> float                  # 返回 ground_y
get_ground_ratio() -> float              # 返回 ground_ratio
get_camera_bounds() -> Vector2           # 返回 Vector2(map_left, map_right)
get_entity_walk_bounds() -> Vector2      # 返回火柴人 X 活动范围（通常同 map_left/map_right）
```

### 5.1 两种室内进入方式

| 方式 | 适用建筑 | 触发 | 场景变化 | 模式切换 |
|------|---------|------|---------|---------|
| **透明化** | 小型建筑（铁匠铺、住宅、仓库） | 玩家进入 `InteractionZone` | 前墙半透明 + 显示内部，**不切场景** | EXPLORE -> INDOOR |
| **传送切换** | 大型建筑（宫殿、地下城、堡垒） | 玩家进入 `EnterTrigger` | 加载 `MegaInteriorMap`，**切场景** | EXPLORE -> INDOOR（新地图内） |

**分类依据**：建筑数据 `.tres` 的 `interior_mode` 字段（见 §5.7）：
- `NONE` -> 无室内（装饰物、城墙、地形建筑）
- `TRANSPARENT` -> 透明化
- `TELEPORT` -> 传送，需指定 `mega_interior_map_id`

### 5.2 小型建筑 - 墙面透明化（不传送）

#### 5.2.1 透明化状态机

每栋建筑独立维护透明化状态，互不影响（多建筑重叠见 §5.5）：

```
状态 TRANSPARENT_OFF（默认）：
  Exterior.visible = true
  WallFront.modulate.a = 1.0
  Interior.visible = false

  ── 玩家进入 InteractionZone ──>

状态 TRANSPARENT_ON：
  Exterior.visible = true（屋顶仍可见，保持空间感）
  WallFront.modulate.a = 0.3（前墙半透明，Tween 渐变 0.2s）
  Interior.visible = true（内部显示）

  ── 玩家离开 InteractionZone ──>

状态 TRANSPARENT_OFF（反向恢复，Tween 渐变 0.2s）
```

**关键**：
- 只调 `WallFront` 的 alpha，**不调整个 `Exterior`**（屋顶始终可见，保持空间感）
- 渐变用 `Tween` 实现 0.2s 过渡，避免硬切
- `Interior` 含工作位 NPC、打铁动画、内部装饰，透明化时才渲染

#### 5.2.2 InteractionZone 触发机制

`InteractionZone` 是 Building 的 `Area2D` 子节点（见 §5.3），检测**玩家附身实体**进入：

```gdscript
# Building._on_interaction_zone_body_entered(body)  —— 实际实现见 building.gd
# 以下为设计规范，非当前实现（实现细节参见代码注释）
func _on_interaction_zone_body_entered(body: Node2D) -> void:
    if not _is_player_entity(body):
        return  # 非玩家实体（NPC）不触发，避免全图半透明
    if state != State.OPERATIONAL:
        return  # 建造中/被破坏不触发
    _set_transparent(true)
    EventBus.interior_entered.emit(get_instance_id())
    # GameRoot 订阅 interior_exited 信号统一做全局退出检查（§5.5.1 方案 A）

func _on_interaction_zone_body_exited(body: Node2D) -> void:
    if not _is_player_entity(body):
        return
    _set_transparent(false)
    EventBus.interior_exited.emit(get_instance_id())
    # GameRoot._check_indoor_exit() 递归遍历全部 Building 判定是否退出
```

**`_is_player_entity` 判定**：检查 body 是否为当前附身实体（`PossessionInterface.get_possessed_entity()`）。非附身 NPC 走进建筑**不触发**透明化，避免视觉混乱。

#### 5.2.3 优点

- 室外正常显示，玩家能看见"师傅在打铁"
- 进入是连续的，无传送感
- 多个建筑可同时透明化（玩家跨越多个交互区时，见 §5.5）

> **🔄 模块化重构后（B1+ 阶段，详见 [建筑模块化设计.md](../建筑模块化设计.md)）**：
> 本节描述的操作对象 `Building.WallFront` 将改为**遍历所有层的 `FrontLayer.Walls_Front`** 批量 alpha→0.3，含 `Pillars_Front`（稻草材质）一起半透明。
> 模块占位格的前景墙在生成时已挖洞，透明化时无需额外处理（那些格本就没墙）。

### 5.4 INDOOR 模式行为契约

#### 5.4.1 与 EXPLORE 的关系

INDOOR 是 EXPLORE 的**子模式**，玩家仍控制角色移动（WASD），区别仅在：

| 维度 | EXPLORE | INDOOR |
|------|---------|--------|
| 角色移动 | WASD | WASD（相同） |
| 相机跟随 | 水平卷轴 + 1/4 区域 | 水平卷轴 + 1/4 区域（**不变**） |
| 相机 ground_y/ground_ratio | 地图级 | 地图级（**不变**，不用建筑级） |
| 相机手动控制 | 拖动 + 边缘滚动 + 缩放 | 拖动 + 边缘滚动 + 缩放（相同） |
| UI | VillagePanel | VillagePanel（**不变**） |
| 输入路由 | ExploreHandler | ExploreHandler（**复用**，不新建 IndoorHandler） |

**关键决策**：INDOOR 模式**不新建 handler**，复用 ExploreHandler。INDOOR 仅作为"当前在室内"的标记，供 UI/音效系统查询（如室内混响、UI 提示"按 E 交互"）。

> **为什么不用建筑级 ground_ratio**：建筑内地面 Y 与地图地面 Y 相同（建筑贴地建造），无需独立相机参数。若未来室内有不同高度（如二楼），再考虑建筑级相机偏移。

#### 5.4.2 模式切换规则

```
EXPLORE ──进入 InteractionZone──> INDOOR
INDOOR ──离开所有 InteractionZone──> EXPLORE
INDOOR ──进入战斗（城镇被袭）──> BATTLE
INDOOR ──打开战略图──> UI（战略图关闭后恢复 INDOOR）
```

**禁止从 INDOOR 直接到 BUILD/POSSESS**：建设需先离开交互区回 EXPLORE；附身需通过 BATTLE 模式。

### 5.5 多建筑重叠与边界情况

#### 5.5.1 多建筑同时透明化

玩家可能同时处于多个建筑的 InteractionZone 内（如两个紧邻的铁匠铺）：

- **每个建筑独立维护透明化状态**：进入各自 InteractionZone 各自变透明，互不影响
- **INDOOR 模式只切换一次**：首个进入的建筑触发 `enter_indoor_mode()`，后续建筑不再重复切换
- **退出时检查全局**：离开某建筑 InteractionZone 时，检查是否还在其他建筑的 InteractionZone 内。**仅当所有交互区都不含玩家时**才 `exit_to_explore()`

```gdscript
# Building._maybe_exit_indoor_mode() —— P0 实现建议
# 方案 A：通过 EventBus 信号让 GameRoot 统一检查（推荐，解耦）
#   Building 离开时 emit EventBus.interior_exited
#   GameRoot 收到后调用 _check_indoor_exit() 遍历所有 Building
#
# 方案 B：Building 直接遍历（简单但需知道地图引用）
#   在 _on_interaction_zone_body_exited 中：
#     var map = get_parent()  (Building 父节点通常是 BuildingHost 容器)
#     var any_inside = false
#     for child in map.get_children():
#         if child is Building and child._interior_is_transparent:
#             any_inside = true; break
#     if not any_inside: input_dispatcher.exit_to_explore()
```
> **建议方案 A**，因为 GameRoot 已经持有 `input_dispatcher` 引用，无需 Building 持有。Building 只需 `EventBus.interior_exited.emit(building_id)` + 自身透明化恢复。

#### 5.5.2 边界情况

| 场景 | 处理 |
|------|------|
| 玩家附身时进入交互区 | 正常触发透明化（附身实体就是玩家实体） |
| 玩家取消附身时在室内 | 透明化保持，模式回 EXPLORE（附身->EXPLORE 不强制退出 INDOOR） |
| 建造中建筑（UNDER_CONSTRUCTION） | InteractionZone 不激活（未完工无内部可看） |
| 被破坏建筑（DESTROYED） | InteractionZone 不激活 |
| 战斗中进入交互区 | 透明化仍生效，但模式切到 BATTLE（BATTLE 优先级高于 INDOOR） |
| 传送进入 MegaInteriorMap 后 | 新地图是独立场景，无 InteractionZone 概念，模式为 INDOOR（新地图默认） |

### 5.6 大型建筑 - 传送切换（MegaInteriorMap）

#### 5.6.1 传送流程

```
玩家走到大型建筑旁，进入 EnterTrigger (Area2D)
  ↓

  ↓

  ↓

  ↓

  ↓

  ↓

  ↓

```

#### 5.6.2 返回机制

MegaInteriorMap 内部有 `ExitTrigger`，触发后：
```
SceneLoader.load_map(return_map_id, TELEPORT)
  ↓
玩家出现在原建筑旁（记录的 spawn 点）
  ↓
模式回 EXPLORE
```

`return_map_id` 和 `spawn_point` 在传送时由 SceneLoader 记录到 GameRoot 临时成员（`_return_map_id`、`_return_spawn_point`），不依赖存档。因为传送是瞬时操作（进入→离开），不需要跨 session 持久化。**不用 WorldState**（WorldState 管理持久实体状态，不适合存瞬态旅行参数）。

### 5.5.5 城镇朝向与道路方向（创始人确认）

> **设计决策**：大世界地图是俯视角 2D 地图（上北下南左西右东），游戏地图是横版线性。城镇在大世界地图上的朝向是随机的（大部分城镇不是正南正北），城镇朝向决定了从场景图左/右边界走出时分别能到达哪些道路。

#### 朝向与道路分界

```
大世界地图（俯视角，上北下南）：

         北
         ↑
    ┌────┼────┐
    │  朝向线  │
    │  /  ↘   │
    │ /    城镇│  ← 城镇朝向线（NE->SW）
    │/   ↙    │
    ┼─────────┼
    │         │
    │  垂直分界线
    │  (⊥朝向线)
    └─────────┘
         ↓
         南

左出 = 朝向线在北半面的道路（NE 方向的道路）
右出 = 朝向线在南半面的道路（SW 方向的道路）
```

**核心规则**：
- 每个城镇在大世界地图上有一条**朝向线**（随机生成，表示城镇的主轴方向）
- 垂直于朝向线的线条作为**分界线**，将城镇周围的道路分为左右两半
- **默认**：地图往左走 = 偏北方向的半面道路，往右走 = 偏南方向的半面道路
- 大世界地图上北下南左西右东

**举例**：
- 一个朝向 NE->SW 的城镇：往左走到达 NE 朝向半面的道路，往右走到达 SW 朝向半面的道路
- 一个朝向 E->W 的城镇（正东西）：往左走到达北侧道路，往右走到达南侧道路
- 一个朝向 N->S 的城镇（正南北）：往左走到达西侧道路，往右走到达东侧道路

#### 实现要点

1. `SettlementRef` 新增 `orientation: float` 字段（弧度，0=正东西，π/2=正南北）
2. 程序化生成时为每个城镇随机分配朝向
3. 城镇场景图的两个出口（左/右 ChunkTrigger）根据朝向计算可到达的道路列表
4. 玩家走到出口时弹出道路选择 UI（列出可到达的道路/目的地）
5. 道路选择 UI 显示大世界地图缩略图，标注当前城镇位置和朝向，高亮可到达的道路

#### 依赖

> ⚠️ 此功能**依赖大世界地图（战略图）完成**。当前战略图尚处设计阶段（见 [战略图架构.md](../战略图架构.md)），城镇朝向和道路数据需要从程序化世界生成导入。P0 阶段用硬编码测试，正式实现需等战略图模块重构完成。

### 5.5.6 战场地图垂直跨度（创始人确认）

> **设计决策**：战场地图的垂直方向跨度应**非常大**，类似《米拉奇战纪》，方便设置排兵布阵。

**与城镇地图的差异**：
- 城镇地图：`ground_y` 到 `ground_bottom` 跨度适中（约 270px，占屏幕下方 25%），火柴人在地面带上活动
- 战场地图：`ground_y` 到 `ground_bottom` 跨度**大幅增加**（可能占屏幕 60-70%），提供纵深感，方便排兵布阵

**实现方式**：
- `BattlefieldMap` 的 `ground_ratio` 设为更大值（如 0.6-0.7，城镇为 0.33）
- `ground_y` 上移，`ground_bottom` 不变，地面带变宽
- 战场地图可设置多层高低差（前线/中线/后方），利用 Y 轴跨度做阵型纵深
- 相机 `ground_ratio` 随地图类型调整

**参考**：《米拉奇战纪》的战场有较大的垂直空间用于排兵布阵，前排/中排/后排有明显的 Y 轴位置差异。

### 5.5.7 道路遭遇战（创始人确认）

> **设计决策**：我方部队在道路上行军时遭遇敌方，会发生遭遇战。行军系统类似"低自由度的全面战争系列"。

**设计概念**：
- 道路地图（RoadMap）是连接城镇的横版场景
- 玩家部队在道路上行军时，可能遭遇敌方部队
- 遭遇触发后，道路地图**就地变战场**（GDD §6.7 原始设计：城镇就地变战场）
- 或切换到遭遇战战场地图

- 全面战争的行军是低自由度的（在战略图上移动，不是手动走）
- Stick World 的行军也是低自由度的（在大世界地图上下令行军 -> 自动沿道路移动）

## 5.6 地图系统架构重构需求（创始人原始设计诉求记录）

> **背景**：当前地图场景架构（VillageMap/RoadMap/BattlefieldMap 固定场景 + ChunkTrigger 切换）无法支撑创始人的动态城市扩张预想。以下为完整原始设计诉求记录，后续将基于此重新设计地图系统架构。
>
> **状态**：原始需求记录（待重构）。P0 收口范围因此扩大，当前设计根本支撑不起创始人预想。

### 5.6.1 城镇的动态扩张

- 城镇地图大小**随城镇规模增长**：小村落地图小，大城市地图大，地图边界 `map_left`/`map_right` 是动态的
- 城墙**不在地图边界**：城墙是城镇内的建筑，距离地图边界有一定距离
- 城墙**可能有多层**：随着城市扩张，旧城墙保留，新城墙在外围新建（类似现实古代城市，如北京的内城/外城）
- 城墙**可能有可能没有**：取决于城市的发展程度，小村落无城墙，大城市有多层城墙
- 城墙是**普通建筑**：与工坊/兵营一样通过 ConstructionManager 建造，建造时不需要特殊对待
- 城墙**用料扎实程度可自定义**：从不能站人的村子级别低矮小墙，到上面能放一堆器械的大墙
- 城墙作为建筑可以被建造、破坏、修复
- **多层城墙 = 连续多次攻城战**：攻破外城墙后，战场无缝扩大到下一道城墙作为守城方新据点，直到所有城墙被攻破或攻城方撤退

### 5.6.2 城外环境

- 城墙外（或无城墙时的城镇边缘外）是**广阔的自然环境**：森林、草原、绿洲等，一望无际
- 离开城市后需走约 **100 个格子（3200px）** 才到达地图边界
- 城外环境可以有资源点（树木/石头/铁矿）、装饰物、随机事件触发点
- 城外地面贴图与城内不同（城内是硬化地面，城外是自然地面）

### 5.6.3 出城与道路选择机制

- **不再使用 ChunkTrigger 直接切换地图**
- 走到地图边界附近（约 **20 个格子** 范围）-> 弹出按钮提示"打开大世界地图选择出城道路"
- 或者顶着地图边界走几秒也会触发大世界地图弹出
- 打开大世界地图后 -> 根据城镇朝向选择要去的道路/城镇（见 §5.5.5 城镇朝向）
- 选择道路后 -> 切换到道路场景或快速旅行

### 5.6.4 战场类型扩展

战场不只是遭遇战，至少有三种类型：

| 战场类型 | 触发条件 | 我方位置 | 特征 |
|---------|---------|---------|------|
| **遭遇战** | 大世界地图上双方部队在道路上相遇 | 取决于行军方向（见 §5.6.5） | 空旷战场，两端临时阵地/掩体 |
| **攻城战** | 进攻有城墙的敌方城镇 | 城墙外 | 我方面对城墙，需攻破城门/城墙才能入城；城墙上有敌方防守 |
| **守城战** | 敌方进攻我方有城墙的城镇 | 城墙上/城内 | 利用城墙防御，敌方在外攻城；我方在城墙上有地形优势 |

**攻城战/守城战的城墙利用**：
- 如果城镇有城墙 -> 攻城/守城时城墙成为战场阵地的一部分
- 如果城镇没有城墙 -> 没有城墙阵地，退化为野外遭遇战
- 城墙上的单位有高度优势（射程/视野加成，待数值设计）

### 5.6.5 我方位置不固定

- 我方**不总是在战场左边**
- **行军方向决定 spawn 位置**：
  - 从南面任意一个角度往北走 -> 我方在战场**右侧**（南面）
  - 从北面任意一个角度往南走 -> 我方在战场**左侧**（北面）
  - 从正东往正西走 -> 我方在战场右侧（正东面也算北面）
  - 从正西往正东走 -> 我方在战场左侧（正西面也算南面）
- 敌方位置同样取决于其行军方向，也就是和我方相反
- 攻城战：我方在城墙外（行军方向侧），敌方在城墙内/上
- 守城战：我方在城墙内/上，敌方在城墙外（行军方向侧）

### 5.6.6 战场战斗持续性

- 走回撤退点 -> **主控角色返回城镇**，但**战场上战斗不停止**
- 战斗持续到以下任一条件：
  - 敌方全灭或溃散
  - 我方主动撤退逃跑
  - 直接和谈（外交系统，P1+）
- 这意味着战场是**持续的**，玩家可以离开再回来查看战况
- 玩家离开后战场由 AI 自动指挥（基于编制默认战术 + 自主决策权限）

### 5.6.7 当前架构问题与重构方向

**当前架构问题**：

| # | 问题 | 影响 |
|---|------|------|
| 1 | VillageMap 是固定大小的 `.tscn` 场景 | 无法动态扩张城镇地图 |
| 2 | ChunkTrigger 是硬编码的地图出口 | 无法支撑"走到边界选道路" |
| 3 | 城墙被设计为地图边界 PassageBarrier | 实际应该是城内可穿越/可破坏的建筑 |
| 4 | 没有攻城战/守城战概念 | 战场类型单一 |
| 5 | 地图大小固定（`map_left`/`map_right` 写死） | 无法随城镇规模增长 |
| 6 | 出口触发器在地图末端 | 无法支撑"边界附近弹按钮" |
| 7 | 战场 spawn 位置固定左方 | 无法根据行军方向动态调整 |
| 8 | 无战场持续/AI 自动指挥 | 玩家离开战场后战斗无法继续 |

**需要重构的方向**（详细方案待定）：

1. **VillageMap 动态尺寸**：`map_left`/`map_right` 可变，城镇扩张时地图边界外扩
2. **出城机制**：改为"靠近边界 + 按钮提示"或"顶边界走几秒"，不再用 ChunkTrigger
3. **城墙改为 Building 类型**：可建造/可破坏/可穿越，不是地图边界障碍
4. **战场类型系统**：遭遇战/攻城战/守城战，不同类型有不同的阵地布置
5. **战场 spawn 动态计算**：根据行军方向决定双方位置
6. **城镇扩张 + 多层城墙**：旧城墙保留 + 新城墙可建，城镇地图随建设向外扩展
7. **战场持续 + AI 指挥**：玩家离开后战场由 AI 接管

> ⚠️ **后续工作**：基于以上诉求重新设计地图系统架构。当前仅记录原始需求，重构方案待创始人确认后开始设计。P0 阶段可先用简化版（固定地图 + 基础城墙建筑），正式重构属 P1。

## 5.7 地图系统架构重构方案（（阻塞 P0））

> **状态**：架构方案（待创始人确认后实施）
> **定位**：此重构**阻塞 P0 原型验证**。当前地图架构无法支撑动态城市扩张，必须先重构再继续 P0 阶段 E。
> **关联**：需求来源见 [§5.6](#56-地图系统架构重构需求创始人原始设计诉求记录)，现有架构见 [§三](#三地图与-chunk-系统)

### 5.7.1 核心理念转变

| 维度 | 当前架构 | 重构后架构 |
|------|---------|-----------|
| 地图载体 | 固定 `.tscn` 场景 | **动态数据驱动**的 MapInstance |
| 地图边界 | `map_left`/`map_right` 写死 | **动态扩展**，城镇扩张时边界外推 |
| 地形 | 单个 GroundPolygon 固定大小 | **可动态调整大小** + 地形区域遮罩 |
| 城墙 | 地图边界 PassageBarrier | **普通 Building**，可建造/破坏/站立 |
| 出城 | ChunkTrigger 硬编码出口 | **边界检测器** + 大世界地图选择 |
| 战场 | 独立 BattlefieldMap 场景 | 遭遇战=生成场景；**攻城/守城=城镇地图本身** |
| 战斗持续性 | 离开战场=战斗结束 | **战场持续**，AI 接管指挥 |

### 5.7.2 动态地图模型

#### MapInstance 重构

**坐标系统：城镇中心为原点（创始人确认）**

所有存储用**相对坐标**（城镇中心 = cell 0，可正可负），运行时渲染/物理用绝对坐标转换：

```gdscript
class_name DynamicMap extends Node2D

# ── 坐标系统 ──
var town_center_cell: int = 0          # 始终为 0（存储原点）
var town_center_world_x: float = 4096.0 # 运行时绝对坐标（加载时确定）
# 转换：world_x = town_center_world_x + relative_cell * 32.0
#       relative_cell = (world_x - town_center_world_x) / 32.0

# ── 动态边界（相对坐标） ──
var map_left_cell: int = -128          # 可动态扩展（负方向）
var map_right_cell: int = 128          # 可动态扩展（正方向）
var walkable_margin: int = 128         # 最外围建筑外推 128 格为可移动范围

# ── 地形区域 ──
var biome: int = 0                     # 群系（决定城外自然地面贴图）
var ground_texture_type: String = "stone" # 城内硬化地面类型
var wall_layers: Array = []            # 每层城墙的 cell 列表

# ── 附属区域 ──
var affiliated_zones: Array[String] = [] # 附属区域 ID 列表（如 "forest_01"）

# ── 地面 ──
var ground_polygon: Polygon2D          # 可动态调整大小的地面多边形
var terrain_mask: Image                # 地形遮罩（1px/cell，city/natural）

# ── 已有节点（保留） ──
var placement_grid: Node
var building_host: Node2D
var entity_host: Node2D
```

**存储格式**：存档中所有建筑/资源点用相对 cell_x 存储。加载时由 `town_center_world_x` 转为绝对坐标。城镇中心是数据坐标点（不是建筑），固定不变。

#### 地图扩展机制

```
玩家放置建筑在 relative_cell = +50
  ↓
可移动范围 = max(所有建筑 cell) + 128 = +50 + 128 = +178
  ↓
当前 map_right_cell < +178 ?
  -> 扩展 map_right_cell（以 64 格为单位向上取整：+178 -> +192）
  -> GroundPolygon 顶点更新
  -> PlacementGrid 扩展
  -> terrain_mask 扩展（新增区域标记为 natural 地形）
  -> 生成自然地形（树木/石头随机分布）
  ↓
玩家可走到 +178（开阔地带，无建筑，只有自然地形）
  ↓
在 +178 附近（20 格内）触发边界提示
```

- 有建筑触发就扩张到够用（以 64 格为单位向上取整）
- 可移动范围 = `max(所有建筑 cell_x) + 128`（右）/ `min(所有建筑 cell_x) - 128`（左）
- 扩展时生成自然地形（城外：树木/石头/草地，按 biome 随机分布）

### 5.7.3 地形系统重构

#### 地形区域与贴图

```
城镇地图地形俯瞰（水平卷轴，X 轴展开）：

  ←map_left                    town_center                    map_right→
  │                                                              │
  │  自然地形  │  城外过渡  │████│  城内硬化地面  │████│  城外过渡  │  自然地形  │
  │ (草地/森林) │  (混合带)  │城墙│  (石板/泥土)   │城墙│  (混合带)  │ (草地/森林) │
  │           │           │    │                │    │           │           │
  │  ~100格   │  ~10格    │ 1格│     城镇内     │ 1格│  ~10格    │  ~100格   │

  ████ = 城墙建筑（如果有）
```

**三种地形区域**：
1. **城内硬化地面**：城墙内侧，石板/泥土/碎石纹理（按 `ground_texture_type` 决定，见 [建筑与定居点.md §4.4](建筑与定居点.md)）
2. **城外自然地形**：城墙外侧到地图边界，草地/沙地/雪原（按 `biome` 决定）
3. **过渡带**：城墙两侧 ~10 格范围，两种贴图混合渐变

#### 地形遮罩 Shader

```
GroundPolygon 使用自定义 Shader：
  uniform sampler2D city_texture;     # 城内硬化地面
  uniform sampler2D natural_texture;  # 城外自然地面
  uniform sampler2D terrain_mask;     # 1px/cell 遮罩（R=0=natural, R=1=city）
  
  fragment:
    vec2 mask_uv = UV * mask_size;
    float city_factor = texture(terrain_mask, mask_uv).r;
    vec4 city = texture(city_texture, UV * city_tiling);
    vec4 natural = texture(natural_texture, UV * natural_tiling);
    COLOR = mix(natural, city, city_factor);
```

**遮罩更新**：
- 城墙建造时 -> 城墙内侧 cell 标记为 city（mask.r = 1.0）
- 城墙破坏时 -> 对应区域恢复为 natural
- 地图扩展时 -> 新区域默认 natural

#### 5.7.3.1 土路 1D 地块带

> **设计决策**：村庄土路用 1D cell 标记（`_terrain_types` 字典），不依赖城墙，出生时即生成。

**实现**：
- `VillageMap._terrain_types: Dictionary`（cell_x -> 地形类型常量）
- `TERRAIN_GRASS=0`（默认）、`TERRAIN_DIRT_ROAD=1`（土路，全速）、`TERRAIN_FOREST=2`（林地，-20%）
- `set_dirt_road_range(start_cell, end_cell)` 标记 cell 范围为土路
- 土路视觉：`DirtRoadPolygon`（Polygon2D，土黄色，z_index=2）覆盖土路 cell 的地面区域
- 草地 shader `city_bounds` 同步土路范围，`city_fade=1.0` 硬边界（无渐变）
- shader `world_pos` 用 `MODEL_MATRIX * vec4(VERTEX, 0, 1)` 确保与世界坐标对齐

**移动速度修正**：
- `get_move_speed_mult_at_x(world_x)`：土路=1.0，非土路=0.8
- `StickmanEntity._terrain_speed_mult()` 查询脚下地形，影响 WALK_SPEED/RUN_SPEED

**出生点与土路范围**：
- `PLAYER_SPAWN_X = 0.0`（世界原点），`spawn_cell = 0`
- 土路 = cell -40 到 40，正负各 40 格对称
- `set_dirt_road_range` 自动扩展 `map_left`/`map_right` 覆盖土路范围（含负坐标）
- 扩展时同步更新 GroundPolygon、PlacementGrid、实体约束、相机/小地图边界

**资源生成**：
- `generate_resource_nodes` 内部跳过 `TERRAIN_DIRT_ROAD` cell，硬化路面永远不长资源
- 土路外 cell 按 density=0.65 生成（树林密、石头次之、铁矿稀有）

**存档**：
- 土路范围通过 `city_left_x`/`city_right_x` 持久化（已有 maps 表字段）
- `load_from_db` 从 city_bounds 反推 cell 范围，恢复 `_terrain_types` + 视觉
- 启动时自动读取存档槽位 0，玩家在上次保存位置复活

- 每次放置 1 段城墙（1 cell 宽）
- 玩家连续放置多段连成线
- 城门单独放置

#### 城墙作为战斗阵地

| wall_tier | 视觉 | 站人 | 器械 | HP | PassageBarrier |
|-----------|------|------|------|-----|----------------|
| 1 低矮土墙 | 矮墙 64px | ❌ | ❌ | 200 | 全高阻挡 |
| 2 标准城墙 | 中墙 128px | ✅ | ❌ | 800 | 全高阻挡 |
| 3 大型城墙 | 高墙 192px | ✅ | ✅ | 2000 | 全高阻挡 |
| 城门 | 带门的中墙 128px | ❌ | ❌ | 500 | 可开关（己方开/敌方关） |

**城墙上的单位**：
- tier >= 2 的城墙有 `StandPlatform`（Area2D），单位可以走到城墙顶部
- 城墙上单位有**高度优势**：射程 +X%、视野 +Y%（数值待定）
- 攻城方需要攻城器械（云梯/攻城塔）才能登上城墙（P1+）

#### 护城河（特殊 Building）

护城河是城墙外侧的特殊建筑，通过 ConstructionManager 建造：

```json
{
  "id": "moat",
  "name_zh": "护城河",
  "type": "moat",
  "tier": 1,
  "width": 1,
  "build_time": 20,
  "build_cost_wood": 0,
  "build_cost_stone": 0,
  "max_hp": 9999,
  "description": "城墙外侧的沟渠，减缓/阻挡敌方移动"
}
```

- 护城河不阻挡己方单位（PassageBarrier 仅对敌方阵营生效，或减速效果）
- 护城河不是实体墙，是地面改造（改变地形属性：减速/不可通行）
- 可与城墙配合形成防御纵深

### 5.7.4.5 资源模型与建造清场（创始人确认）

#### 城内有限资源 vs 附属区域无限资源

| 资源来源 | 位置 | 储量 | 再生 | 说明 |
|---------|------|------|------|------|
| 城内树木 | 城镇地图城外区域 | **有限**（几十棵） | **彻底不再生** | 砍完就没了，逼玩家去森林区域 |
| 森林区域 | 附属区域 | **无限** | 砍后再生 | 持续木材供应，产率有上限 |
| 城内矿井 | 部分城市城内 | **无限** | 开采后再生 | 只有矿业城市有 |
| 矿井区域 | 附属区域 | **无限** | 开采后再生 | 持续矿石供应，产率有上限 |
| 城内石头 | 城镇地图城外 | **有限** | 不再生 | 有限石料 |

> **关键设计**：城市附近只有有限的树木/石头，逼玩家开发附属区域获取持续供应。矿业城市例外（城内可挖矿）。

#### 建造自动清场

建造城墙/建筑时，如果选址范围内有树木/石头等自然资源点：
- 火柴人**自动清理**出空地（不需要玩家手动砍树）
- 清理掉的树木**给木材**（回收资源）
- 清理掉的石头**给石料**
- 清理完成后建筑正常施工

### 5.7.4.6 城市附属区域（创始人确认）

> **设计决策**：每个城市拥有附属资源区域（森林/矿井/采石场等），是独立场景，提供无限资源供应。附属区域在 L1 战略图上有真实坐标和边界。

#### 附属区域属性

| 属性 | 说明 |
|------|------|
| **归属** | 每城独有，属于该城市领土 |
| **初始状态** | 空无一物（和初始城镇一样），需玩家手动建设 |
| **扩建方式** | 与城镇扩张相同 -- 放置采集建筑（伐木场/矿井等）触发地图扩展 |
| **大小上限** | 不超过城镇规模的一半，或 32 格（城镇 <64 格时） |
| **资源储量** | 无限（但产率有上限，由采集建筑数量决定） |
| **数量上限** | 每城最多 16 个（大部分城市 1-2 个，首都/资源型城市更多） |
| **战略图表示** | 在 L1 战略图上有真实坐标和边界线，是地图上的真实区域 |

#### 附属区域类型

| 类型 | 产出 | 采集建筑 | 说明 |
|------|------|---------|------|
| 森林区域 | 木材 | 伐木场 | 无限树木，砍后再生 |
| 矿井区域 | 金属矿 | 矿井 | 无限矿脉，开采后再生 |
| 采石场 | 石料 | 采石场 | 无限石矿，开采后再生 |
| 渔场 | 食物 | 渔船码头 | 水域附属区域，永远无限 |
| 农田区域 | 食物 | 农场 | 可耕种区域 |

#### 进入附属区域

- **随时可打开大世界地图**（Tab 键），选择附属区域 -> 直接切换场景
- 走到城市地图边界附近 -> 边界提示中包含附属区域选项
- 进入附属区域 = **直接切场景**（无行军过程，与去其他城市走道路不同）

#### 附属区域地图结构

```
森林区域地图（简化版 VillageMap）：

  ←map_left              采集区               map_right->
  │                                             │
  │  自然森林  │  伐木场  │  更多树木  │  自然森林  │
  │ (无限树木) │ (建筑)   │ (待开采)   │ (无限树木) │
  │           │          │            │           │
```

- 结构与城镇地图相同（DynamicMap），但更简单
- 初始空无一物，玩家放置伐木场等采集建筑触发扩展
- 资源点（树木/矿脉）在扩展时自动生成
- 采集建筑（伐木场）自动派工采集 -> 产出资源进入城市库存

### 5.7.5 出城与旅行系统（创始人确认，替代 ChunkTrigger）

#### 核心原则

- **随时可打开大世界地图**（Tab 键），不限于走到边界
- **左边界 = 北方向**，**右边界 = 南方向**（基于城镇朝向，见 §5.5.5）
- 走到边界只是**额外便利提示**，不是唯一出行方式
- 去其他城市 = 道路场景（有行军/遭遇战可能）
- 去附属区域 = 直接切场景（无行军过程）

#### 出行方式

```
方式 1：随时按 Tab 打开大世界地图
  ├── 查看帝国版图（真实地图，真实边界，路线画在地图上）
  ├── 选择道路 -> 亲自前往（切道路场景）/ 快速旅行
  ├── 选择附属区域 -> 直接切场景进入
  ├── 指派部队行军 -> 部队标记在小地图上移动（P1+，不在 P0 实现）
  └── 管理物流队 -> 帝国城市间运输（P1+）

方式 2：走到地图边界附近（额外提示）
  ├── 左边界（北方向）-> 提示北方向的道路 + 附属区域
  └── 右边界（南方向）-> 提示南方向的道路 + 附属区域
```

#### 边界提示 UI

```
玩家走到左边界附近（20 格内）：
  ┌───────────────────────────┐
  │  📜 前往...（北方向）       │
  │  ───────────────────────  │
  │  🛣️  [道路] 去北口村 (北)   │  ← 切换到道路场景
  │  🌲  [区域] 进入森林        │  ← 直接切换到森林场景
  │  📜  打开大世界地图          │  ← 打开完整战略图
  └───────────────────────────┘

玩家走到右边界附近（20 格内）：
  ┌───────────────────────────┐
  │  📜 前往...（南方向）       │
  │  ───────────────────────  │
  │  🛣️  [道路] 去河口村 (南)   │  ← 切换到道路场景
  │  ⛏️  [区域] 进入矿井        │  ← 直接切换到矿井场景
  │  📜  打开大世界地图          │  ← 打开完整战略图
  └───────────────────────────┘
```

- 左边界只显示北方向选项，右边界只显示南方向选项（基于城镇朝向）
- 顶边界走 3 秒 -> 自动打开大世界地图

#### 大世界地图（战略图）是真正的地图

> **创始人强调**：L1 战略图不是概念图，是**真正的地图**：
> - 有真实的边界线（多边形）
> - 附属区域在地图上有**真实坐标和边界**

### 5.7.6 战场系统

#### 三种战场类型

| 类型 | 地图 | 触发 | 我方 spawn | 敌方 spawn |
|------|------|------|-----------|-----------|
| **遭遇战** | 生成的 BattlefieldMap | 大世界地图行军相遇 | 行军方向侧 | 对侧 |
| **攻城战** | 敌方城镇的 VillageMap | 进攻敌方城镇 | 城墙外（行军方向侧） | 城墙上/城内 |
| **守城战** | 我方城镇的 VillageMap | 敌方进攻我方城镇 | 城墙上/城内 | 城墙外 |

#### 遭遇战战场生成

```
大世界地图上双方部队相遇
  ↓
BattlefieldGenerator.generate(march_direction, biome, attacker_units, defender_units)
  ↓
生成空旷战场地图：
  - ground_ratio = 0.6（大垂直跨度，方便排兵布阵）
  - 两端临时阵地/掩体（CoverMarker）
  - 我方 spawn 在行军方向侧（从南往北 -> 右侧）
  - 敌方 spawn 在对侧
  - 撤退点在我方 spawn 侧
```

#### 攻城战 = 城镇地图即战场

```
进攻方到达敌方城镇
  ↓
加载敌方城镇的 VillageMap（含城墙建筑）
  ↓
BattleDirector 启动攻城战：
  - 攻城方 spawn 在最外层城墙外侧（行军方向侧）
  - 守城方在城墙上/城墙后方
  - 战斗在城镇地图上进行，城墙是可破坏障碍
  - 攻破城门/城墙段 -> 攻城方涌入 -> 继续向内推进
```

**关键**：攻城战**不切换场景**，直接在城镇 VillageMap 上进行。城墙是 Building，可以被攻击破坏。这与 GDD §6.7"城镇就地变战场"一致。

### 5.7.7 多层攻城战

#### 连续攻城流程

```
城镇有多层城墙（cell_x: [外城墙=200, 内城墙=100, 城中心=50]）

Phase 1: 攻城方在 cell_x > 200 区域
  ├── 攻击外墙（cell_x=200）：破坏城门或城墙段
  ├── 守城方在外墙上防守（射箭/投石）
  └── 外墙被突破 ──────────────────────┐
                                       ↓
Phase 2: 攻城方涌入 cell_x 100~200 之间区域
  ├── 攻击内墙（cell_x=100）：破坏城门或城墙段
  ├── 守城方退守内墙
  └── 内墙被突破 ──────────────────────┐
                                       ↓
Phase 3: 攻城方进入城中心（cell_x ~50）
  ├── 守城方最后抵抗
  └── 守城方全灭/溃散 -> 攻城胜利
```

**关键设计**：
- 整个攻城战在**同一张城镇地图**上进行，**不切换场景**
- 每层城墙被突破后，战场自然扩大到下一层（无需加载）
- 攻城方可以选择**绕过城墙**（如果有未被堵住的侧翼，但侧视角地图通常两端封闭）
- 守城方可以**主动放弃外墙**退守内墙（战术撤退）
- 攻城方可以**选择撤退**（走回行军方向侧边界 -> 返回大世界地图）

#### 城墙破坏机制

- 城墙是 Building，有 HealthComponent
- 攻城方攻击城墙 -> 城墙 HP 下降 -> HP=0 时城墙段破坏
- 城墙段破坏后 -> PassageBarrier 消失 -> 攻城方可通过该 cell_x
- 城门可被攻击破坏（HP 通常低于城墙）
- 守城方可以修复城墙（需要工人 + 材料）

### 5.7.8 战场持续性

```
玩家在战场上指挥战斗
  ↓
玩家走到撤退点 -> 主控角色返回城镇
  ↓
但战场战斗不停止：
  - BattleDirector 继续运行
  - 我方单位由 AI 指挥（编制默认战术 + 自主决策权限）
  - 敌方单位继续进攻/防守
  ↓
玩家可以在城镇继续建设/采集
  ↓
玩家可以重新进入战场（通过大世界地图 -> 战场位置）
  ↓
战斗持续到：敌方全灭/溃散 | 我方全灭/溃散 | 和谈
```

**实现要点**：
- 战场地图在后台保持运行（不被卸载）
- BattleDirector 持续 tick
- 玩家不在战场时，相机/输入不路由到战场
- 玩家重新进入时，恢复战场相机/输入

## 六、旅行系统

### 6.1 三种旅行方式

| 方式 | 触发 | 实现 | 限制 |
|------|------|------|------|
| 步行 | 玩家走到村落末端出口 | 加载 RoadMap → 末端走出 → 加载下一村落 | 无限制 |
| 快速旅行 | 大世界地图选目标 | 显示"行进中"过场 + 消耗游戏内时间 → 加载目标 | 战斗中禁止 |
| 传送 | 大建筑进入触发器 | 切换到 MegaInteriorMap | 战斗中禁止 |

### 6.2 步行流程

```
Village_A 末端出口触发器
  → SceneLoader.load_map("road_A_to_B")
  → RoadMap 加载，玩家从左端进入
  → 玩家走完 RoadMap
  → 末端出口触发器
  → SceneLoader.load_map("village_B")
```

`RoadMap` 也支持 Chunk 流式加载，可长可短。后期可加入路上事件（伏击、商人、流民）。

### 6.3 快速旅行流程

```
玩家打开战略图 (Tab)
  → world_map 模块（战略图模块）显示已探索村落/城市
  → 玩家选择目标
  → 校验：当前不在战斗中？目标已探索？
  → UIRoot 显示"行进中"过场
  → WorldClock.advance(time_cost)  # 推进游戏内时间
  → SceneLoader.load_map(target_id)
  → 玩家出现在目标村落的入口
```

**设定合理性**："快速旅行"在游戏内解释为"主角走过去了"，只是省略了过程。消耗的游戏内时间按距离计算。

### 6.4 旅行封锁条件

- 当前 Map 挂载了 active `BattleInstance` → 禁止
- 玩家正在被攻击（HP < 阈值且最近受击 < 5s）→ 禁止
- 目标未探索 → 不可选
