# 创始人批评总集与协作规约

> **用途**：创始人历次批评的完整集合与由此固化的协作规则。**任何会话开工前必读；每次收到新批评先对照本表，禁止重复犯已记录的批评**。产品/美术类批评（编号续接交接档 §0.2 台账的 1~23 条）与协作流程类批评分开管理。整理于 2026-09-14 凌晨（持续追加）。

## 一、协作流程规约（最高优先级，违者即返工）

| # | 创始人批评（原意） | 固化规则 |
|---|---|---|
| P1 | "你 TM 以后不要磨蹭，我时间紧任务重；简单修改别拖几小时" | 简单修改立即执行；复杂任务立即并行派出；等待期主动轮询（TaskOutput），不干等通知 |
| P2 | "每个事情不要让我反复说很多遍；你记性怎么这么差" | 每次收到批评：①当场对照本表 ②本表追加或强化 ③执行动作里显式引用编号（如"按 P3"）。**不靠记性靠本表** |
| P3 | "我纠正后你不跟我对齐就开干；你不得说出你的理解给我过目吗" | **纠正后必须先陈述理解 → 创始人过目点头 → 才能启动 agent/动代码**。对齐用创始人原话复述，不加我的术语 |
| P4 | "停停停指的就是杀掉 agent；'你为什么**全**停了'重点是全字" | 指令要听准**范围**：停/启/改只作用于被点名的那一路，禁止广播到全部 |
| P5 | "我只纠正了其中一两个 agent 的问题" | 被质疑的线路停下对齐；未被质疑的线路继续跑，不动 |
| P6 | "拿不准先问" | 模糊指令（尤其带情绪的短指令）先一句话确认意图；不可逆动作（杀 agent/删文件/重派）必须先确认 |
| P7 | "你为什么反复误解，我反复提醒你也误解" | 误读后禁止"立刻做点什么"补救——先停下复述理解，确认后再动；禁止连环相反动作 |
| P8 | "不要拆东墙补西墙" | 改 A 时必须验证 B 没坏（回归自检：check_spec 集不扩大、既有资产逐位/逐像素对齐是既有惯例，流程上同样适用） |
| P9 | "几个 agent 干完了你为啥不交接/不接收" | agent 完成（含机器重启后）主动用 TaskOutput 拉取、验收、提交；完成一批收一批 |
| P10 | "该文档化的东西都文档化了吗" | 决策、方案、调研、口径、素材产出**当场落档**，不留"回头补" |
| P11 | "为啥不多个 AI 一起干" | 默认多 agent 并行；文件所有权切分干净，零冲突 |
| P12 | "你用更好听的说法重新说一遍？有什么区别吗" | 禁止把批评"换皮"成交接口径——改就是实质改（改做法/改产物），不改说法 |
| P13 | "蓝色地垫你是挑不出毛病硬挑的吧；屋顶占屏过高不是这时候该管的" | 看图验收**先抓基础问题**（重叠/落位/穿模/比例锚），不硬凑毛病、不越阶段挑次要项 |
| P14 | "最基础的建筑互相重叠你没看到吗" | 验收顺序固定：**排布与落位 → 结构穿帮 → 比例 → 材质观感 → 风格**，基础项没过不谈后面的 |
| P15 | "我批评完下一句你上一句就忘了" | 任何新对话/新任务开始时，本表 + 交接档 §0 台账为第一输入；新批评发生即在两处登记 |

## 三、对齐模板（收到批评后的标准动作）

1. 复述创始人原话（不加工）
2. 列出我打算做什么（哪一路、哪个文件、验收标准是什么）
3. 创始人点头 → 启动；改哪条 → 改完再过目
4. 执行完：图/数据 + 本表状态列更新 + 提交入库
