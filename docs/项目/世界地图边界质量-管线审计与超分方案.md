# 世界地图边界质量：生成管线审计与「超分」方案

> **定位**：回答创始人 2026-09-11 诉求——「8192 地图是超分出来的，能不能从当初的算法推出一种超分算法让边界更自然，并从根源造出最符合需求的数据格式，把生成各环节按最高标准打通」。
> **结论先行**：这不是分辨率不够的问题，是**边界表示形式**的问题。真·超分（SR 网络类）是在没有源头信息时去猜；我们的源头是**连续场**（8192 原生分形陆地、城块种子、MCP 代价场），信息是够的——丢质量的是中间两次「矢量化 ↔ 栅格化」往返。正确做法是把边界的权威表示从「采样栅格」换成「解析矢量 + 共享弧拓扑」，一次打通，任意缩放都自然。

---

## 一、现状链路审计（信息在哪里丢的）

| 环节 | 工具 | 分辨率/表示 | 损失 |
|---|---|---|---|
| 大陆/河湖 | `l3/fractal_continent.py` | **8192 原生**连续高度场 + mask | 无（源头质量够） |
| 群系/地区 | `l3/biome_generate.py`、`region_split.py` | 2048 标签场 | ① 4 单位/纹素 |
| 老 L1（69 块） | 13 地区 `tiles_8192.npy` → `city_split_v2.build_legacy_l1_mask` | 8192 → NEAREST 降采样 2048 | ② |
| 城块（1040 块） | `l1/city_split_v2.py`（`--res` 2048/8192） | 标签场 → `find_contours` 出多边形 | ③ 独立逐块取轮廓 |
| 政权 ID mask | `state_expand_lite.rasterize_id_mask` | 多边形 **fill+outline 回填 8192 栅格** | ④ 矢量→栅格，1 单位台阶 |
| 运行时政治层 | `political_mask_colorize.gdshader` + NEAREST | 栅格逐纹素查 LUT | ⑤ L2 视角近 1:1 采样，台阶全暴露 |

**实测佐证**（2026-09-10，`l3_city.json` 1040 城块）：34433 条多边形边里只有 **2192 条（6%）** 能在相邻块两侧找到同一 key —— 城块多边形是**各自独立取轮廓 + 独立平滑**的，不是共享弧拓扑。后果：① 相邻块边界互有 1~3 单位错位（接缝裂缝/重叠，所以 L3 界线不能用共享边配对画全）；② 每个块自身是栅格台阶的平滑化，细节上限就是标签场的纹素尺寸。

**结论**：边界质量的天花板在 ③④⑤ 三步，而不在 8192 这个数字。把 mask 提到 16384 只是让台阶小一半，且显存翻倍——方向就错了。

## 二、方案：去采样化（三步，按依赖顺序）

### S1 标签场原生 8192（打通源头）
`city_split_v2 --res 8192` 全链在 8192 上跑（陆地 mask 本来就是 8192 原生分形，不需要超分）；地区/群系标签场同步升到 8192（或对城块生成改用 8192 陆地 + 2048 群系双线性采样），消掉表里 ①② 的 4 倍降维。
**验收**：城块最小特征宽度 ≥ 4 单位的块数显著下降；无「一条 3 单位宽的走廊被抹平」。

### S2 共享弧拓扑（TopoJSON 式，接缝根治）
标签场 → **一次** `skimage.find_contours(field, 0.5)`（亚像素等值线）→ 建**弧图**：每条弧恰属两个标签，多边形由弧拼装；R3 的 Visvalingam 抽稀 + Chaikin 平滑**只作用于弧**；三界交点顶点锁定。
- 产出即「水密」多边形：相邻块共享同一串顶点，接缝零裂缝零重叠；
- L3 界线（国界/地区界/城界）直接取弧，**几何天然单一来源**（现在那套 mask 探针判界可以退役）；
- 弧结构 = 我们要的「最符合需求的数据格式」的核心，见 S3。
**验收**：共享边配对率 6% → 100%；任意三块交界点逐坐标相等。

### S3 运行时格式换代：ID 栅格 → ID 矢量 mesh + LUT（本次真正的「超分」）
新数据格式（L3/L2 通用）：
```
political_mesh.json/bin
  arcs:    PackedVector2Array           # 共享弧顶点（8192 坐标）
  arcs_id: PackedInt32Array             # 每弧两侧 (lut_a, lut_b)
  tiles:   [{lut, arc_ids[], holes[]}]  # 多边形 = 弧引用（不重复存顶点）
```
运行时：三角剖分一次 → 顶点色 R = lut/255 → 新 shader `political_vertex_colorize.gdshader` 用 `COLOR.r` 查**同一张 PoliticalLut**（保留「改 LUT 即换色零重烘」的 R9 硬指标）；界线 = 弧直接画（宽度屏幕口径），与色块逐像素贴合。
- 边界变成解析折线，**缩放任意大都不出像素台阶**（这就是「超分」想要的效果，而且是精确的不是猜的）；
- mask 路线降级为回退（数据缺失/低端机）；
- L2 窗口只需按 bbox 裁弧引用，不再各自烘一张 PNG。
**验收**：L2/L3 政治图 1:1 放大无马赛克；城界线与色块边界重合；改 LUT 全图即时换色。

### S4（可选，仅在确需栅格处）
F8 缩略图等确需栅格的场景，用 4×4 覆盖率超采样烘「coverage + ID」双通道，或直接从矢量离线烘焙——不再作为运行时权威格式。

## 三、工作量与顺序

| 步 | 内容 | 级别 | 依赖 |
|---|---|---|---|
| S2 | 共享弧提取器（`tools/worldgen/l3/arc_topology.py`）+ 城块/地区多边形重建 + `l3_city.json` 换源 | Pro | S1 |
| S3 | `political_mesh` 导出 + 顶点色 shader + L2/L3 渲染器接入 + 界线改弧源 | Pro | S2 |
| S1 | `--res 8192` 全链重跑（城块/地区） | Pro | 无（可与 S2 并行） |
| — | mask 管线与 shader AA 退役 | Flash | S3 验收后 |

风险：城块重跑会改变城块形状（领土/政权归属不动——归属来自 `city_owners` 表，按 label 回填即可）；L1/L2 视图包的城块相关产物需同步重导。建议在 worktree 新分支上做，`locked/` 金标准先备份。

## 四、一句话回答「能不能超分」

能，但不是对结果做超分，而是**回到源头把「边界」从采样值升级成解析值**：源头（8192 分形场 + 城块种子 + MCP 场）本来就是连续的，中间两次栅格化是唯一的信息洼地；把洼地填掉（S1 原生分辨率 + S2 共享弧 + S3 矢量运行时格式），边界在任何缩放下都自然，且比任何 SR 算法都精确——因为没有一句是猜的。

## 五、S2/S3 实施落点（生成端工具与数据格式契约）

> 2026-09-11 会话实施。范围 = S2 共享弧拓扑 + S3 运行时矢量格式换代；**S1（标签场 8192 重跑）暂缓**——城块形状语义不变优先，避免一次换掉已验收观感；S2/S3 管线对输入场无假设，S1 落地时重跑本工具即可。

### 生成端（tools/worldgen/l3/arc_topology.py）

- **弧提取**：`mesh_extract.extract_smooth_mesh_with_arcs`（R3 同源管线扩展）——环提取/T 形焊/切段/平滑与 `extract_smooth_mesh` 逐位一致（region 013/008/011 烟测对拍通过），差异只在拼装：每条弧一个全局 id，label 环 = 弧引用序列（负 id = 反向）。平滑方向锚定首个出现段（Visvalingam 的 tie-breaking 对折线方向不对称，动方向会产出不同插值点）。
- **入口**：`arc_topology.py`——输入 `output/l1_v2/city_labels_8192.npy`（1040 城块标签场，与 l3_city.json 逐 label 对齐）。`--smoke N` 单 region 自检、缺省干跑出指标+预览、`--write` 落地。
- **验收指标**：弧数/顶点数、城块间弧占比、跨块配对错配（目标 0，按「不同 label 环出现次数」计）、面积守恒（弧拼装/标签像素）、端点唯一格。
- **已知瑕疵（S1 待办）**：8192 标签场的对角接触伪影经 T 形焊链式聚类产出病态重复点环（单点最高 96 连），约 5% label 面积偏差超 ±5%、5 个 label 无环（保持原样不换源）——根治在标签场质量（S1），非表示层问题。

### earcut 剖分前置清洗（实测踩坑）

mapbox_earcut 对含重复点/自接触的环**静默丢三角形**（50 个连续重复点 → 面积丢一半），是 fill 空洞的根因。`build_fill` 统一走「相邻重复去重 → shapely `buffer(0)` 拆自接触 → 有效简单环逐环 earcut + 面积校验」。

### 数据格式（political_mesh，坐标 [x,y]@8192 新约定——与老字段 [y,x] 不同，bin 侧直转无交换）

```
l3_political_mesh.json/bin（config/strategic_map/）
  arcs:      PackedFloat32Array  # 弧顶点平铺 x,y
  arc_ptr:   PackedInt32Array    # 每弧起始 float 偏移（n+1，末位哨兵）
  arc_code_a/b: PackedInt32Array # 每弧两侧 lut code（1..80 / 253 自由城邦 / 0 海洋）
  arc_border: PackedInt32Array   # 界类型 0 非界 / 1 国界 / 2 地区界 / 3 自由城邦界
  tiles:     [{label, rings, holes}]  # 弧引用（运行时暂不消费，留派生/编辑）
  fill_verts: PackedVector2Array  # earcut 预剖分三角网（运行时零几何计算）
  fill_code:  PackedInt32Array    # 顶点 lut code（1..80 / 253 / 254 湖）
  fill_idx:   PackedInt32Array

l2_world.json 注入字段 political_mesh（context 坐标 [x,y]）：
  verts/code/idx + borders_national/borders_region/borders_free（折线列表）
```

### 运行时链路（实施后修订：draw_mesh 直烘 RGB，shader 路线退役）

- **fill 顶点色直烘 PoliticalLut 最终 RGB**（`MapMeshBuilder.build_political_fill_parts` 采样 `color_of_code`），渲染器 `_draw` 内 `draw_mesh` 直绘——fill 先画即垫底，界线/光流/hover 自然压其上。
- ⚠️ **渲染怪癖实录**（d3d12 / Godot 4.7，矩阵实验 19 轮定位）：ShaderMaterial 的 canvas MeshInstance2D 在 L3 真实场景**整体不渲染**——与 z_index（±1/0）、挂载点（renderer 子/Content 兄弟）、show_behind_parent、顶点数（4~34 万）、分块数均无关；独立场景同样代码正常、L2 场景正常、无材质正常。`draw_mesh`/`_draw` 与无材质顶点色是唯一可靠路径，故弃 vertex colorize shader（`political_vertex_colorize.gdshader` 已删）。
- 「改 LUT 即换色零重烘」（R9 硬指标）改由**信号重烘**保持：`PoliticalLut.set_state_color` 发射 `state_color_changed` → 渲染器 `rebake_colors` 重写顶点色（调试低频操作，18 块重建 <100ms）。
- mask（ID PNG + NEAREST + 查表 shader）降级为回退路线，数据缺失自动回退（集成测试验证兼容）。L3 界线改弧源（`_build_political_borders` 矢量分支，按 `arc_border` 分类），mask 外法向探针降级为回退；L2 政治界线同步三级（国界 casing+墨线 / 地区界长虚线 / 自由城邦界灰短虚线），虚线经 `MapSketch.chain_polylines` 串链保证相位连续长短统一；旧「地块界 1px」仅存于 mask 回退路径。
- 界类型码表：`MapTokens.ARC_BORDER_*`（渲染端零字面量）。
- **验收实拍**（1033% 深放大）：解析边界放大 10 倍零马赛克、界线与色块逐像素贴合——「超分」目标达成（`tools/worldgen/output/feedback3_l3_political_zoom.png`）。
