# 09-输入与操作复刻

> 目标：把原版 Stick War: Legacy 的操作方式复刻到键鼠，并在其上做键位可配置、
> 键盘可视化配置、手柄适配。本文档是立项依据 + 缺口清单 + 方案调研结论。
> 状态：**立项待排期**（F 键空挥已先行落地，见 §3.1）。
>
> 职责边界：本文档管**输入方案设计**（操作映射、键位配置、调研结论）；
> **操作层复刻缺口**（动画/骨骼/事件/皮肤等对账结论）以
> [`审计/总账/翻译缺口总账.md`](../../审计/总账/翻译缺口总账.md) 为唯一出口，
> 新发现缺口一律先补总账，不在本文档另立清单。

## 一、原版操作方式（复刻基准）

原版分两层操作（来源：Stick War Wiki "User Control" + 游戏实测对照）：

### 战略层（主玩法，鼠标为主）
- 底部兵种卡出兵（点卡 → 花金币在雕像处生成单位）
- 左键点选 / 拖框选单位；右键/左键点地移动、点敌攻击
- 阵型命令按钮（防御/集结/推进等，全局生效）
- 全局技能按钮（兵种解锁后：箭雨、治疗、矛兵狂暴、召唤等法术）
- 矿工自动挖矿循环，无需指挥

### 附身层（User Control，点单位接管）
- 方向键 / WASD 移动（含 y 轴纵深）
- 攻击键出招，**无目标可空挥**（纯动作，无伤害）
- 弓箭手自动瞄准攻击范围内最近目标
- 部分兵种有附身技能（矛兵举盾等）

## 二、现有操作盘点（stick-world 现状）

| 层 | 操作 | 键位 | 实现位置 |
|---|---|---|---|
| 附身 | 移动 | WASD/方向键 | stickman_entity._physics_process |
| 附身 | 切战斗模式 | Q | stickman_entity._input |
| 附身 | 点敌攻击 | 鼠标左键 | stickman_entity._input |
| 附身 | **空挥** | **F**（2026-08-30 新增） | stickman_entity._input → weapon_mount.perform_swing |
| 附身 | 搬运/建造交互 | E | stickman_entity._unhandled_input |
| 附身 | 退附身 | ESC | possession_interface |
| 探索 | 移动/框选/命令 | WASD + 鼠标 | explore_handler + command_chain |
| 全局 | 帝国面板/战略图/武器调试 | K/O/J/L、Tab、M、T/B | game_root._input |

## 三、缺口清单（按优先级）

### 3.1 已落地
- [x] **F 键空挥**（2026-08-30）：`weapon_mount.perform_swing()`——出对应武器攻击动作、
  进冷却、无目标无结算（弓 = 拉弓不放箭，与原版一致）。单测
  `test_strike_frame._test_swing_no_target` 钉死行为。

### 3.2 P1 —— 键位数据化（后续一切的地基）
现状全部键位**硬编码 keycode**（KEY_Q/KEY_F/KEY_T…散在 6+ 个文件）。先迁到
Godot **InputMap action**（project.godot input 区声明 action，代码改用
`Input.is_action_pressed` / `event.is_action_pressed`），才有重绑定的操作对象。
迁移清单：附身 5 项、探索 4 项、全局 8+ 项、武器面板/调试键。

### 3.3 P2 —— 设置面板键位重绑（含鼠标左右键）
- 设置面板新增"按键"页：action 列表 + 当前绑定 + 点击监听新输入（键/鼠标键）
- 冲突检测（同键多 action 警告/交换）、恢复默认
- 持久化：ConfigFile 存 override，启动时覆盖 InputMap
- 开源参考：
  - [KoBeWi/Godot-Input-Remap](https://github.com/KoBeWi/Godot-Input-Remap)（资源式，键+手柄）
  - [dastmo Runtime Controls Remap](https://store.godotengine.org/asset/dastmo/runtime-controls-remap/)（Asset Library，带现成 UI）
  - [Godot 官方 demo：重构键位的 Input Mapping UI 思路](https://www.reddit.com/r/godot/comments/170834y/how_do_you_let_the_players_change_the_controls_of/)

### 3.4 P3 —— 键盘可视化配置（用户点名的方案）
设置页里画一把键盘（QWERTY 键帽网格 + 鼠标示意图），每个键帽上标注绑定的
action 名；点击键帽 → 按下新键即替换；鼠标左右/中键单独一块。实现要点：
- Control 自绘（GridContainer 键帽按钮，104/87 键布局常量表）
- 键帽文案 = `InputEventKey.as_text()`（自动处理修饰键）
- 无需第三方库，纯自绘约 300~500 行；P2 的重绑逻辑复用

### 3.5 P4 —— 手柄适配
- Godot 4 内建 SDL 手柄映射（Xbox/PS/Switch Pro 免配置），InputMap 里给每个
  action 加 JoypadButton/JoypadMotion 绑定即可
- 左摇杆移动（带死区）、按键 glyph 提示（社区资产
  [Kenney Controller Prompts](https://kenney.nl/assets/controller-prompts) 等免费包）
- 鼠标语义操作（框选/点地）在手柄下需要光标虚拟化方案——参考
  Godot 资产库 "virtual mouse" 类插件，或战略层专为手柄设计轮盘菜单
- 开源参考：KoBeWi 库原生支持 joypad；Godot 官方文档
  [InputEventJoypadButton/Motion](https://docs.godotengine.org/)

### 3.6 P5 —— 原版操作细节补全（依赖对应系统立项）
- **弓的键鼠微调**：现在点谁打谁；可加"左键点地向鼠标方向抛射"或保持自动瞄准
  （原版即自动瞄准范围内最近敌）。倾向保持自动瞄准 + 空挥已够，观察手感再定
- 兵种出兵卡 / 阵型命令按钮 UI 化（现在靠键盘，原版是底部按钮）——依赖战斗生产 UI 立项
- 全局技能按钮 —— 依赖法术系统立项（未移植清单 §7-B）
- 附身技能键（矛兵举盾等姿态）—— 依赖姿态格挡扩面（已有 seek_cover 一处）
- 教程提示（原版 InGameTips 类）—— 依赖新手引导立项
