# 音效重制（SFX 替换 + 触发时机优化）—— 任务书与交接

> **本文是给下一个会话/子代理的任务书**。音乐部分已完成并合入分支，见
> [音乐重制-进度与交接.md](音乐重制-进度与交接.md)；本文只管**音效（SFX）**。
>
> 工作分支 `agent/music-overhaul`，worktree `.temp/music-overhaul`（与音乐同一条，因为
> 音效与音乐共用 `AudioManager` 与音量体系）。

## 零、为什么做这件事

1. **现役音效大多是提取件，公开前必须替换**。已登记在
   [`项目/素材替换清单.md`](../../项目/素材替换清单.md)：
   - **Terraria 提取件（10 个）**：采集敲击三变体、树木、入账、UI 悬停/点击/确认、
     对局开始、阶段目标完成、建造完成、存档完成
   - **SWL（Stick War: Legacy）提取件（7 个）**：开战号角、胜利/失败、火柴人受击三变体
   - 这两类都是**别人游戏的音频资产**，Demo 阶段可暂用，**发布前必须换掉**。
2. **另有 17 个是项目自研程序合成的**（`stick-world/tools/ai/gen_sfx.py`），
   无版权问题，但质量参差，且与新音乐（-15 LUFS、柔和取向）未必协调。
3. **触发时机没有系统性设计过**。目前是"哪里需要就 `play_event("x")`"，
   缺少全局视角：什么该响、响多大声、响几次、会不会叠、要不要让位给音乐。

| 战斗反馈 | `swoosh_a..d`、`thump_a/b`、`clang_a/b`、`bodyfall_a/b/c`、`headbutt`、
  `magikill_blast_a/b` | 自研合成 | 否（可升级） |

> ⚠ **待核实**：`AudioManager.SFX_EVENTS` 的 `unit_hurt` 指向
> `res://assets/audio/sfx/unit_hurt_a/b/c.wav`，但目录列表里没有这三个文件。
> `play_event` 对"全部变体都缺失"是静默返回的（只 `print_verbose`），
> 所以**受击音可能一直没有响过**。这是第一个要查的点。

### 1.2 接线方式（现状）

- `core/services/audio_manager.gd` 的 **`SFX_EVENTS` 表**：语义事件名 → 路径或路径数组
  （数组 = 随机变体池）。这是**音效的唯一真相源**，加音效不用改调用点。
- `play_event(name)`：同事件重触发**先停旧实例**（防叠成音墙）+ **±5% 音高抖动**
  （`PITCH_JITTER`，避免机关枪式机械重复）。
- EventBus 自动接线：`game_started` / `game_saved` / `battle_started` / `battle_ended`。
- UI 点击/悬停：由 `sketch_button.gd` 直接调 `play_event`。
- 播放器：每次 `play_sfx` new 一个 `AudioStreamPlayer`，播完自毁（挂 `SFX` 总线）。

### 1.3 已知问题（待逐条确认）

1. `unit_hurt` 资产疑似缺失（见上）。
2. 提取件与新音乐的响度体系不匹配：音乐是 -15 LUFS 精细母带，音效却没有统一的
   响度标准与真峰值上限 → 有的音效比音乐还响、有的听不见。
3. 没有事件优先级 / 节流：密集采集或人群战斗时同一音效会高频触发。
4. 没有与音乐的关系设计：什么时候该让位（duck）、什么时候该盖过音乐、战斗音效
   与音乐是否打架，均未设计。
5. 缺少"音效也要能客观验收"的机制（音乐那边有 `selftest.py` + `qa_audio.py`，
   音效这边没有对应物）。

## 二、任务分解

### 批次 S1：建"音效管线"（对应音乐管线的做法）

**产出**：`tools/sfx/`（新目录），复用音乐管线的成熟做法：

| 模块 | 复用自 | 作用 |
| --- | --- | --- |
| `musiclib.loudness` | 直接 import | 音效的 LUFS / 真峰值 / 刺耳度 / 削波 |
| `musiclib.dsp` | 直接 import | 滤波/包络/饱和等合成原语 |
| `sfxlib/synth.py` | 新写 | 音效合成原语（瞬态噪声、共振体、模态打击、拟音） |
| `sfxlib/design.py` | 新写 | **每个音效一个"设计配方"**（这是什么声音、由哪几个成分构成、为什么） |
| `gen_sfx.py` | 重写 `stick-world/tools/ai/gen_sfx.py` | 一键生成全部音效 |
| `qa_sfx.py` | 仿 `qa_audio.py` | 音效客观质检（响度/真峰值/时长/刺耳度/单调性） |
| `selftest.py` | 仿 `tools/music/selftest.py` | 管线自检 |

**音效的设计规范**（新写 `docs/技术/音频/音效设计规范.md`）：
- 每个音效定义：语义事件名、用途、时长区间、LUFS 目标、真峰值上限、频段重心、
  变体数、是否随机、是否允许重叠。
- **响度分层**（关键，目前完全没有）：UI 反馈最轻、采集反馈中等、
  战斗反馈最响但短。给出分层的 LUFS 目标与理由。
- **与音乐的关系**：音乐是 -15 LUFS；音效需要在地板上留出层级，
  且**不能占据 2-5kHz 太久**（那是刺耳的敏感区，也是音乐的"存在感"区）。

### 批次 S2：替换提取件

优先级（按"必须替换 + 影响最大"排序）：

1. **UI 三件套**（hover/click/confirm）——最高频，最影响手感。要求：极短（<120ms）、
   干燥（几乎无混响）、音高明确（点击可以有音高感）、响度统一。
2. **采集四件套**（stone hit 三变体、wood、gain）——高频。要求：三变体之间
   有明显音色差异（避免"机关枪"），敲击有"材质感"（石=硬+短促、木=中空+稍长）。
3. **生命周期四件套**（game_started / game_saved / quest_done / build_complete）
   ——低频但重要。要求：有"仪式感"但与音乐不打架（它们和音乐同时响）。
4. **战斗 sting 三件套 + 受击三变体**——要求：与音乐同调性或至少同调式
   （音乐战斗曲是 D 小调），避免"音效和音乐打架"。
5. 自研合成的 17 个：**保留但重新过一遍质检与响度统一**（不重写）。

**来源策略（与音乐一致）**：
- 优先**程序化合成**（可控、可复现、零版权）；
- 可**上网采集 CC0/PD/CC-BY** 的真实素材作为融合层（如真实的木头/石头敲击）；
- **记录来源与许可**到 `docs/技术/音频/音效资产登记与来源.md`（仿音乐的登记文档）。
- 明令禁止：任何商业游戏的提取件（Terraria/SWL 等）继续留在最终包里。

### 批次 S3：触发时机与放置优化（动用工程与游戏手感经验）

要系统性地过一遍**所有调用点**，产出一份"音效触发规范"。要点：

1. **审计全部调用点**：`grep play_event` 找出所有位置，逐个评估：
   - 触发时机对不对（是"动作发生时"还是"动作完成时"？）
   - 该不该有随机延迟（避免同一帧多个单位同时触发造成"拍手"效应）
   - 该不该限流（同一音效在 N 毫秒内最多响几次）
   - 该不该有变体（>2 个才不机械）
2. **音效分层与优先级**（HDR 思路的简化版）：
   - 关键反馈（UI 点击、建造完成）> 战斗反馈 > 环境/装饰音
   - 高优先级事件触发时，对低优先级做**短暂压低**（侧链或音量闪避）
3. **与音乐的关系**：
   - 战斗音效密集时，音乐是否已经被压？（音乐那边已有 `duck` 接口：
     `MusicDirector.duck(db, fade)`）
   - 反之，音乐的高潮段是否应该压低某些环境音？
4. **空间化**：目前音效全是 2D（`AudioStreamPlayer`）。场景内的音效（采集、
   受击、脚步）按经验应做**距离衰减 + 立体声定位**（`AudioStreamPlayer2D`），
   否则"远处有人打架"和"耳边有人在打架"听起来一样。评估改造范围。
5. **节流与合并**：人群战斗时 50 个火柴人同时受击 → 50 个音效叠成噪声。
   经验做法：**同一帧同类音效合并成 1~2 个**（取最近/最强的），或按数量调整音量。
6. **音高抖动**：现有 ±5% 是全局常量。按经验：UI 音效抖动应更小（±2%，保持手感
   稳定）、采集/战斗可更大（±8~12%）且**每个变体不同**。

### 批次 S4：验收与文档

## 四、踩过的坑（音乐任务的血泪，别再踩）

1. **PATH 里的 `python` 不是你要的解释器**。必须用
   `C:\Users\fanbo\AppData\Local\Programs\Python\Python312\python.exe`。
2. **下载一律用 `curl -sL`**；Python 的 requests 在本机访问 github.com 会挂起
   （raw.githubusercontent.com 可以）。
3. **别用"字符串切片"改 Python 源码**——切片顺序搞反会变成空串替换、把文件炸掉
   （音乐任务里真炸过一次，只能重写）。要改就整段 `Write` 或精确 `Edit`。
4. **逐样点 Python 循环在音频上不可用**：600 万样点要跑几分钟。全部走
   `scipy` 的向量化（`lfilter` / `maximum_filter1d` / `fftconvolve`）。
5. **限幅器/压缩器的检测信号要取"声道最大值"，不是左右求和**——去相关立体声下
   求和会严重低估峰值（音乐任务里因此白丢了 13~24dB）。
6. **单极点包络的初值必须设成当前值**，否则起振漏限（实测开头过冲 +9.5dB）。
7. **接缝指标不能拿"两窗相减"**——两个不同音乐瞬间天然不等，会误报。
8. **改完必须跑 `bash stick-world/tools/check_godot_errors.sh`**（退出码 1 = 有报错）。
