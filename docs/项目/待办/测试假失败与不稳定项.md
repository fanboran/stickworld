## unit(batch) 批跑失败集轮转（2026-09-16 立案，2026-10-22 定案销项）

> 现象：同一份代码多次运行 `run_all.sh -Match unit(batch)`，`[BATCH-FAIL]` 集在两次运行间轮转——曾报 `test_suppression`（该套件已随压制机制删除；伴随 `-s` 编译错误 `Identifier not found: TimeManager`），合并前后双环境交叉复测时又分别轮换成 `political_data/political_mesh/townlife_save_persistence`、`map_camera_clamp/river_parse/settlement_entry`。子套件断言层全绿（3/3、7/7、13/13…），失败发生在脚本加载/编译层。已排除：性能批次（agent/perf-pareto）合并回归——失败集与代码版本无关、只与环境/时序相关。
>
> **定案（2026-10-22，双根因，均已修）**：
>
> 1. **类缓存残缺（load/编译层轮转主因）**：GDScript 编译期解析 `class_name` 标识符依赖 `.godot/global_script_class_cache.cfg`；该文件缺失/被截断/陈旧时，引用类名的产品脚本编译失败（`Identifier "MapModeManager" not declared` 等成片 Parse Error → 套件 `load()` 失败 → `[BATCH-FAIL]`）。删除该文件实测 53/80、成片 `Failed to compile depended scripts`；删 `uid_cache.bin` 则 80/80 全绿（uid 缓存无关）。多会话共用工作区时编辑器/`--import` 会重写该文件（导入中途崩溃则长期缺失），并行测试进程恰好踩中残缺窗口——失败集随残缺程度轮转，「并行 3 不同槽位/缓存状态下结果轮转」即此。修复：`tests/lib/class_cache_guard.sh`（盘上 class_name 全集 ⊆ 缓存注册集预检 + `--import` 重建自愈 + 目录锁防多实例并发 import），`run_all.sh`/`run_unit.sh` 起跑前统一接入。
> 2. **共享 user:// SQLite 路径（townlife 家族成员）**：`test_townlife_save_persistence` 在固定路径 `user://temp/test_townlife_save_persistence.db` 上"删除重建+开库"，多实例同毫秒并行时 Windows 文件锁互撞（并行 3 验证轮 4/6 复现，错峰 8s 即不复现）。修复：库路径带进程号隔离 + 套件收尾自清。
>
> 排查工位（留在树上）：`batch_runner.gd` 的 `SW_BATCH_TRACE` 环境变量逐套件起止/耗时/退出码落盘观测位（stdout 重定向下全缓冲，长跑期间黑盒——排查并行问题看它）；`tools/dev/repro_batch_parallel.sh`（同 worktree 自并行 N 实例错峰复现台）、`tools/dev/repro_unit_vs_pool.sh`（unit 批 + 集成并行池交叠复现台）。验证口径：同一提交并行 3 × 3 轮 `-Filter unit` 失败集为空（含首轮投毒类缓存的自愈路径）+ 全量 run_all 绿。
>
> 排查中证伪的干扰项（防回头路）：`.godot` 运行期只读不写（plain 批跑零写盘）；单进程批跑与错峰并行批跑在健康缓存下稳定全绿；`--user-data-dir` 隔离非必要（user:// 唯一实质冲突点即上述 SQLite 临时库）；`--path` 指向无 project.godot 的目录（如误指 tools/）Godot 4.7 会原地挂死不退出——排查台曾因此自伤，已在脚本注释里立牌。

## 环境剧变制造的假失败（识别指南）

磁盘满/恢复、导入缓存损坏这类环境剧变会制造一轮"假失败"，恢复后首跑的红要多重跑再定性。已发生的实例：

- **ctex 空壳**（2026-10-21 C 盘满事故时段）：`.godot/imported/` 里个别 png 的 ctex 只有 56 字节头无数据体（导入器写盘失败残留），运行时 `Failed loading resource` → `test_l2_strategic_map`「13 地区应全部加载成功」稳定 11/13。识别特征 = ERROR 链 `Condition "size <= 0"` → ctex 加载失败；修复 = 删坏 ctex 再 `--import`（9/1334 空壳，精确删即可，无需全清）。
- **孤儿套件文件**：删测试套件只删 `.gd` 漏删 `.tscn`，按目录扫 tscn 的工具（census 普查/直跑）会加载失败空转至看门狗超时，伪装成挂死（exit=124、零断言、引擎 teardown 报错齐全）；batch_runner 清单自检只查「盘上 .gd 在清单」方向，.tscn 残留不在覆盖面。实例 = test_ai_morale.tscn（已清）。
- **run_all bash 挂死**（2026-09-16 立案，2026-10-21 销项）：`-Changed` 起 Godot 前即卡死多日不退。当前树 `-Changed`/全量/`-Match` 三形态复验均正常跑完正常退出，未复现——与当时多会话堆积的未退实例及 C 盘满（临时文件/日志写不出卡死）环境态吻合，按环境性假失败结案。
- **worktree 缺 gitignored 生成产物**：`tools/worldgen/output/**/*.npy` 不进 git，新 worktree 缺水陆掩码 → mapdata 守门必红（`FileNotFoundError: 水陆真相缺输入`）。修复 = 从主工作区拷贝对应掩码产物。

## 框架级盲区：用例内 SCRIPT ERROR 截断计假绿

TestRunner 对用例执行中途的 SCRIPT ERROR（如调用不存在的方法）无感知——当前函数即止，其后断言全部不执行，用例凭前段断言以 OK 收场。实例：test_strategic_map_ui 自 2026-09-22（917a3ff2 引入 assert_eq 死调用）起「邻省上下文」用例后半截从未执行，假绿一个多月，2026-10-21 assert_eq 修复后才暴露。候选增强：runner 加「用例内零 SCRIPT ERROR 守卫」（推送 Godot 报错到 runner 计数），属测试框架增强，待排。
