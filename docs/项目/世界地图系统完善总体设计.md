## 〇、目的与范围

本文档统筹「世界地图系统完善」这一跨系统工程的**总体架构与分期计划**，把散落在 GDD / 程序化生成 / 战略图架构 / 场景图旅行四处的既有设计串成一条可实施的链路。范围覆盖：

- 战略图观感修复（毛刺、UI 设计语言）
- 地形图（默认模式）+ 群系 + 河流
- 玩家位置指示、城市规模表现
- 聚落进城闭环（0.9b）、道路生成、步行/快速旅行
- 全大陆政权简化版（政治图）

不在本轮范围：动态聚落建筑群渲染（进城后由场景图承担）、拼接预览、LOD 分级、联盟/外交、扩张系统运行期对接。

```
┌────────────────────────────────────────────────────────────────┐
│ 生成端（开发期 Python，tools/worldgen/，一次性，产物随包发布）    │
│                                                                │
│  fractal_continent.py ──→ 高度场/河流/湖泊（已有）              │
│  biome_generate.py  ★新 → Whittaker 温湿 → 群系标签图（七群系） │
│  state_expand_lite.py ★新 → 文化圈 flood-fill → 城市归属       │
│  road_generate.py   ★新 → MST + A*(坡度cost) → 道路折线        │
│  terrain_render.py  ★新 → 程序着色地形底图 PNG（分层色+山影）   │
│  settlement_mapgen.py 补完 → 8 城邦场景图 .tscn + map_id 回填  │
│  export_*_view.py   扩展 → 上述新数据进 L3/L2/L1 视图包         │
└──────────────────────────┬─────────────────────────────────────┘
                           ▼  config/strategic_map/（JSON+bin+PNG）
┌────────────────────────────────────────────────────────────────┐
│ 消费端（运行时 GDScript，modules/world_map/）                    │
│                                                                │
│  渲染：烘焙描边（l1_geom.bin 补齐）+ 地形底图 + 河流/道路叠加    │
│        + 政治着色 + 城市 blob + 玩家图钉                        │
│  模式：MapModeManager 实装（TERRAIN 默认 / POLITICAL）          │
│  交互：点击聚落 → 旅行弹窗（走过去/快速旅行）→ travel_requested │
└──────────────────────────┬─────────────────────────────────────┘
                           ▼  EventBus
┌────────────────────────────────────────────────────────────────┐
│ 场景图（modules/world/）                                        │
│  SceneLoader.travel_to_map：聚落场景（0.9b 产物）/ 道路场景     │
│  道路场景生成器 ★新：按路长+地形参数产横向卷轴道路图（seed 确定）│
│  快速旅行过场 + time_manager 时间消耗                           │
```

**模块边界约束**（沿用架构原则）：
- world_map 不做场景图生成；场景图内容（建筑群/道路场景）由生成端工具 + scene_loader 侧承担
- 所有跨模块交互走 EventBus / 模块 api.gd，禁止跨模块 get_node
- 生成端→消费端只通过 `config/strategic_map/` 文件契约（沿用现有视图包机制）

## 五、关键技术方案

### 5.1 像素感根因与最小修复

**现象**：全游戏自绘线条（`_draw()` 的 `draw_arc/draw_circle/draw_line`）观感像素化，而原生 UI（滑块圆头等）圆滑。

**根因**（2026-09 定位）：原生控件的圆角走 StyleBoxFlat 的 **CPU 侧抗锯齿**（与渲染后端无关），而 `_draw()` 线条的圆滑依赖调用处的 `antialiased` 参数（Forward+ 下生效）与 viewport 的 2D MSAA。项目中：

1. 5 处 `draw_arc` **没传 `antialiased`**（缺省 false）且**段数偏低**（16~36 段的圆=可见多边形化）：城市圆圈 16 段、建造涟漪 32 段、战斗选中环 36 段、加载转圈 24 段、滚屏指示 32 段。对照样板：时钟部件 48 段 + `antialiased=true`，圆滑。
2. `msaa_2d` 为 2x，对 1px 级细线的边缘质量提升有限。
3. 地图多边形轮廓源自栅格标签提取，本身带像素台阶（L2 烘焙做过 Chaikin 平滑，L1 没有）——台阶感是几何属性，AA 只能缓解不能消除。**按创始人裁定，本轮不做几何平滑级修复**；若 AA 修复后台阶感仍不可接受再评估。

**修复**（参数级，已完成）：

- 全部病灶调用统一为 48 段 + `antialiased=true`（对齐时钟部件的验证参数）
- `project.godot`：`anti_aliasing/quality/msaa_2d` 2 → 4

**注意**：`antialiased` 参数在 Compatibility 渲染器下不生效（项目桌面/Mobile 均为 Forward+，不受影响）。MSAA 4x 若在低端集显上引起性能问题，回退 2x 仅损失边缘质量、无功能影响。

### 5.2 群系生成（Whittaker 温湿矩阵）

新工具 `tools/worldgen/l3/biome_generate.py`，输入高度场 + 大陆掩码 + 纬度：

```
temperature(px) = base(纬度梯度：北极→赤道) + fBm 噪声(幅度±) − 海拔递减(高山更冷) + 超自然炎热大陆增益
precipitation(px) = fBm 噪声 + 海洋邻近加成(EDT 离海距离衰减) − 副热带干旱带 − 雨影(可选, 山背风面)
```

> 实现定标补充（B1 落地）：副热带干旱带 = 以纬度为中心的高斯干旱槽（哈德莱环流下沉区，真实地球荒漠成因）——大陆地形平缓、单靠雨影撑不起荒漠带时由它保证「赤道雨林→亚热带荒漠→温带草原」条带成形；温湿判定前做高斯平滑（σ3）消阈值椒盐碎斑。

**超自然炎热大陆**（火焰火柴人领地，§5.11.1）：整块 L2 地块（region_008）温度 +0.45、边界羽化过渡——region 内群系按炎热重判（温带草原→热带草原、森林→雨林，标签语义保留不摧毁原地形），暖色调表现留给 B2（`biome_hot_zone_2048.png` falloff 蒙版）。

温湿 → 群系映射（对齐 GDD §五 七群系）：

| 群系 | 温度 | 降水 | 备注 |
|------|------|------|------|
| 冰原（雪地） | 低 | 任意 | 高山顶部同映射为冰雪 |
| 荒漠 | 高 | 低 | |
| 平原（草原） | 中 | 中低 | 默认出生群系 |

### 5.7 城市团块（卫星图式覆盖 + 地形调制生长）

**模型**：逐方向生长场。每城市取 K=16 个方向扇区，每方向半径是**加性**组合——基础形状 + 地形调制的方向生长量：

```
r(θᵢ, s) = base(θᵢ) + capacity(θᵢ) × g(s)

base(θᵢ)     初始形状（村落期轮廓的凹凸特征），谐波叠加生成，相位由 settlement_id 种子确定
capacity(θᵢ) 该方向的生长容量 ∈ [0,1]（地形决定，见下）
g(s)         全局生长曲线 = G_MAX × s^γ（s = population_score 归一化 [0,1]；γ<1 先快后慢）

capacity(θᵢ) = slope_cap(θᵢ) × water_cap(θᵢ) × jitter(θᵢ)
  slope_cap(θᵢ) = clamp(1 − max_slope(θᵢ)/SLOPE_REF, 0, 1)   # 沿方向射线的最大坡度：平地→1 陡坡→0
  water_cap(θᵢ)  = 遇河湖 0.15 / 遇海 0 / 无水 1.0           # 水体阻挡（河边城不往河里长）
  jitter(θᵢ)     = 0.6 + 0.4 × hash_noise(settlement_id, θᵢ)  # 不规则感

轮廓输出：16 方向半径 → Catmull-Rom 插值 → 固定 72 采样点闭合折线
```

**行为保证**（创始人要求的三点，数学上如何成立）：

| 要求 | 保证机制 |
|------|---------|
| 规模变化时**在原轮廓上扩张**（非等比缩放） | 生长项是**加性**的：`Δr(θᵢ) = capacity(θᵢ)×Δg(s)`，base 的凹凸形状特征全程保留，轮廓只朝各方向「蔓延」出增量 |
| **不同方向不均匀扩散**（依地形） | 各方向增量 ∝ capacity(θᵢ)：平地方向长满、缓坡少长、陡坡停住（slope_cap→0）、水面挡死——扩张形态由该城周边地形唯一决定 |
| **参数化** | 全部系数外置 `blob_params.json` 数据表（见下），调参不动代码 |

附带性质：`g(s)` 单调 → 收缩可逆（规模回落时轮廓回到此前同形状）；γ<1 → 前期扩张快、后期饱和（符合城市生长直觉）。

**确定性契约**（存档读档形状一致 + 数据量可控，2026-09 创始人要求）：

- **纯函数生成，零存储**：形状 = `F(settlement_id, capacity[16], s)` 的确定函数，blob 多边形不落盘、不进存档，每次展示时重算。s 的来源 = population_score（存档字段）× 每局扰动（run_seed 派生，存档保存 run_seed）→ 读档后逐点一致
- **跨版本稳定**：解析式轮廓，不受分辨率/栅格化影响；公式变更时按版本号冻结旧公式
- **规模恒定**：固定 72 采样点/城，全大陆 1040 城约 7.5 万点，单次重算毫秒级

**数据与参数**：

- 视图包新增每城 blob 参数：16 个 capacity 值（float）。生成期由 `blob_bake.py`（Phase C 产出）沿 16 方向射线采样高度场坡度 + 水体 mask 预计算——**地形数据不进运行时**，运行时纯查表。全大陆 1040 城 ≈ 100KB（JSON，bin 更小）
- 参数表 `blob_params.json`：`SLOPE_REF`（坡度敏感度）、水体系数（河 0.15/海 0）、`G_MAX`（最大生长量）、`γ`（曲线弯度）、`K`（方向数）、`jitter` 幅度、T1-T5 的 base 半径表——全部可调，对齐「权重放数据表」原则

**验收方式**：同一城市取两个不同 s 值生成轮廓叠加对比——凹凸特征一致、各方向增量不均、朝山/朝水方向被地形卡住；同 s 重复生成与读档后生成逐点一致。

| 级别 | base 基准半径（地图 px，L1 视图） | L2/L3 表现 |
|------|------------------------------|-----------|
| T1 村落 | 12-20 | 单像素点/不画 |
| T2 镇 | 25-40 | 小点 |
| T3 城市 | 50-90 | 明显团块 |
| T4 中心城市 | 100-150 | 大团块 + 白描边 |
| T5 首都 | 150-220 | 最大团块 + 特殊描边 |

- **实时变动**：population_score 变化（建设/扰动）→ 重算 s → 重生成 blob（EventBus `settlement_updated` 触发局部重绘）
- **语义区分**：行政区划多边形（城市领地边界，描边）与建成区团块（实际覆盖面积，填充）是两层，叠加显示

| 6 | 上方小地图与原 Tab 显示地图间切换；本城市地图和 L1 地图并列 | 顶部小地图区**双窗并列**：①本城市地图 = **现有场景俯视 Minimap**（`modules/ui_global minimap.gd`）②L1 世界缩略窗（战略图缩略） |

#### 5.12.2 技术锚点（现状勘查结论）

- **L3 悬浮现状**：`l3_map_controller.open()` 固定 `set_zoom(0.36)` 居中；`strategic_map_l3.tscn` 的 CanvasLayer 无背景层，场景图透出。全屏化 = CanvasLayer 底加全屏背景 ColorRect（海洋蓝 `OCEAN_COLOR`，z 最低、不挡输入）+ 初始缩放按视口/地图尺寸适配计算
- **相机限位**：`map_camera.gd` 已有 `_bounds` + `set_bounds()` clamp 机制（默认大范围 `Rect2(-4096,-2048,8192,4096)`）；L3 open() 时设紧——上下 = 地图边界外扩 buffer（裁切贴陆地，具体像素实施时定标），左右 = 宽松（仅防移出屏幕）
- **灰色邻居块**：`map_renderer.gd`（L1）分层注释「邻居老 L1 块(灰色)」。空心化 = 该层改描边（`draw_polyline` 轮廓）不填充；黑线边框同视图一并画（内容区外缘）
- **顶部小地图**：`modules/ui_global/scripts/hud/minimap.gd`（场景俯视、P0 纯色填充、点击跳相机、GameRoot 创建挂 UIRoot，240×80 顶部中央）。双窗并列 = 在其旁边再加 L1 缩略窗（倾向直接缩放显示 `config/strategic_map/` 底图 PNG，零运行时生成）
- **Tab 三态**：`system_setup.gd` 现硬编码 Tab 开关 L1、M 开关 L3；三态循环在此改造（P1 迁 InputMap 时统一）

#### 5.12.3 实施定标（A3 落地记录）

| 项 | 定标 | 说明 |
|---|------|------|
| 全屏适配缩放 | `fit_zoom = (视口高 − 2×64px) / 地图边长`，即 OCEAN_MARGIN=64 | **初始整图可见**：完整地图居中 + 上下各留 64px 海洋带（地图数据贴陆地裁切，显示时向外放出海洋）；同时锁定为相机 `min_zoom` 与 HUD 100% 基准 |
| 相机限位语义 | 视野不越出"**地图 + 外扩海洋带**"矩形（bounds 上下各外扩 64px 对应的地图单位，STRICT buffer=0） | 创始人语义修正（初版做反成"地图边界锁在屏外"= 向内裁切）：平移最多露出一条海洋带，不许把地图移出到空背景；区间空兜底居中 |
| 左右宽松保留量 | keep=96px | 地图两端至少各留 96px 在屏内（防完全移出）；宽屏两侧露同色海洋视觉无缝 |
| 下钻 L2 时的背景 | **保留**海洋底 | 背景显隐跟 M 会话而非 Content.visible；L2 层号 102 > L3 的 101，内容盖其上，下钻链全程全屏 |
| L1 缩略窗底图 | `l1_base.png`（798²，与 `l1_world.json` 同源同色） | `player_start_l1_cities_preview.png` 虽构图更完整（岛屿全景）但出自 archive 老脚本，有过时风险；若创始人嫌缩略观感，后续可在 `export_l1_view_context.py` 补全景 preview 输出 |
| 缩略窗交互 | 点击 = 切到 L1 大图（Tab 三态第二步等效） | 尺寸 120×120 贴 Minimap（360×120）右侧 8px 并列，同高同款边框 |
| 边界自动触发 | 直接开 L1 大图（保留原"出城看图"语义），仅手动 Tab 走三态 | 信号 `open_world_map_requested(full_map)` 参数区分 |
| HIDDEN 态 | 顶部只收起 **L1 缩略窗** | 三态作用对象 = 仅 L1 缩略窗；当前城市 Minimap **常驻恒显**（进游戏即显示，Tab/大图/边界触发均不动——创始人反馈修订）；进游戏默认 HIDDEN，按一次 Tab 出缩略窗 |
| M 会话互斥 | M（L3/L2）打开期间忽略 Tab/边界开图请求 | 互斥原则"新开视图=玩家所见"；否则三态机在海洋层下悄悄切态，M 一关 L1 意外弹出 |

#### 5.12.4 当前位置标记（A3 验收增补，2026-09-05 创始人两轮反馈）

第一轮反馈："Tab 小地图要标志当前位置，蓝光流动描边 + 城市中心 UI 标记；M 地图也标记当前所在地区（不同色调蓝色流动光描边）"。第二轮修正："M 里应是**整个 L2 地区**范围描边且**不透明**——靠两种蓝色调区分，不做透明度衰减；Tab 大图（L1）当前所在地块也要描边"。属于 C 期"玩家位置"的**静态部分**提前实现：

- **公共动画**：`flow_outline.gd`（FlowOutline）——闭合折线均匀弧长重采样（缓存）+ 沿线**双色色调**流动（亮青蓝 ↔ 深蓝正弦往返，均不透明；波谷仍保留 35% 过渡量，~5.5s 一周）
- **M 大世界**（`l3_map_renderer.gd`）：玩家所在 **L2 地区**（`player_region_label`，出生=13）**全部陆地多边形**（`land_polygons`，含 5 块）整体描边，宽 10 地图单位/20px 屏幕上限；`set_player_region()` 为 Phase C 动态跟踪预留入口
- **Tab 大图 L1**（`map_renderer.gd`）：当前所在**城市地块**（含当前聚落的块，出生 = `spawn_settlement_id` 所在块）描边，4px 屏幕像素固定，画在纸边框内层；`set_current_tile()` 为 Phase C 预留
- **Tab 缩略窗**（`l1_thumbnail.gd`）：出生 L1 权威轮廓（`l1_polygon`）描边 + 出生城市中心标记（白点 + 蓝色脉冲扩散环 1.4s 周期）；数据由装配层从 L1 api 喂（`set_map_data`）
- **C 期剩余**：玩家跨 L1/跨城移动后经事件动态更新三处标记（`set_player_region` / `set_current_tile` / `set_map_data` 已备）+ 战略图玩家图钉 UI（图标类，唯一允许的图标素材场景）
