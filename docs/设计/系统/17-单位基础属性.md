# 单位基础属性

## 一句话

每个火柴人自带五项基础属性，域 0~10；属性怎么长、技能怎么学会，背后是同一条内部进度积累。

## 目的

给「这个人行不行」一个物理底座：谁能扛、谁聪明、谁手巧、谁能带兵，都写在人身上，组织与生产按这些数值真实运转——训练就是把数值练上去、把技能练会（见 [`04-科技系统.md`](04-科技系统.md) §三）。

## 一、五项基础属性

| 键 | 属性 | 是什么 |
|----|------|--------|
| str | 力量 | 负重、挥砍、体能类活计的底子 |
| int | 智力 | 学习、研究、复杂工序的理解力 |
| agi | 敏捷 | 动作速度、闪避、精细操作 |
| cft | 工艺 | 造物手艺——制造技能的天然亲和 |
| cmd | 指挥 | 带兵、组织运转的才干——组织职能的关键岗位吃它 |

- 域统一 **0~10**，整数。
- 出生分布 [提案/待定]（占位：全域均匀掷骰）。
- 消费方按需读取：指挥类排序/门槛吃 cmd（补位引擎先例），制造类吃 cft，学习快慢吃 int——具体哪些消费哪项由各系统定义标注，无全局绑定。

## 二、内部进度制（怎么涨）

属性涨点与技能获得同轨，背后都是一条**内部进度**：

- 每项「+1 属性点」或「获得 1 项技能」= 攒满 **100 点内部进度**。
- 进度靠**速率**积累：速率 = 基础速率 × 修正。
- 修正吃各种因素 [公式待定]：目标值越高越难涨（数值越高越难提升）、其他属性可加成（如 int 高学得快）；想要纯线性增长，把修正设 100% 即可。
- 界面上没有成功率概念——高频判定本质是变相的涨条速度，用户可见的只是进度与结果。
- 进度天然保留：中断（受训组织开走、职能停转）只是停涨，攒下的进度不丢；满 100 才落地涨点/得技能。

## 三、与技能的关系

技能是会/不会的二元记录（04 §一），属性是 0~10 的连续底座；两者都经训练积累内部进度获得（04 §三），并在明面前提（01 §2.5 的属性阈值）与职能运转（关键岗位降速）处被消费。
