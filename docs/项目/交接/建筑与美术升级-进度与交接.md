## ⚠️ 渲染环境关键发现（批次 2/3/5 必读）

- **Polygon2D 的 uv 纹理采样在本环境坍缩为纹理平均色**（整面平涂、无笔触）。已排除：uv 越界、seed、filter、纹理内容、4/6 点几何、新建节点——均无效；`texture=null` 显示 vertex color、`make_solid` 显示纯色（即 uv 常数化）。Sprite2D 路径采样完全正常。
- **材质路径六格矩阵实测（批次 2，实验脚本留档 `tools/baking/render_stone_probe.gd`，复跑可重现）**：① Polygon2D + 纹理 uv 全 0..1 → 平涂（格内亮度 std=0.0000）；② Polygon2D + uv 收窄开区间 (0.005,0.995) → **同样平涂**；③ Sprite2D + CPU 纹理 → 有笔触（std=0.16）；④ Sprite2D + stone_wall ShaderMaterial → 有笔触（std=0.07，输出偏暗）；⑤ Polygon2D + ShaderMaterial → 平涂；⑥ Sprite2D + region 平铺 ×2 → 有笔触。**结论：Sprite2D 是唯一可靠显示路径；石作定案 CPU 纹理（StoneBrickGen）+ Sprite2D，GPU stone shader 仅作 Sprite2D 载体的备选。**
- **批次 1 的「uv 收窄开区间」补救法经实测无效**（上格 ②）——smithy_lv1 的 `BackWallTop`（直接设 texture 未设 uv）疑似同样在平涂，批次 5 茅草迭代时顺手核查修正。
- **绕过方案（已落地于 smithy_lv1）**：`smithy_lv1.gd` 的 `_make_slope_thatch_tex()`——按坡面梯形/平行四边形逐行裁剪 layered 茅草图、坡外透明，Sprite2D 显示；`RoofMain/RoofLeftGroup1` 已 visible=false 由 RoofRightSlope/RoofLeftSlope 顶替。**坡面 mask 边界必须与原 Polygon2D 几何一致**，否则盖住烟囱前桁架（第 3 轮评审的回归教训：底行右缘收进后桁架才可见）。
- **茅草纹理用 `TextureGenAPI.make_thatch_layered(w,h,seed)`**（层叠茅草束，自带金色系配色），不要用 `make_straw_thatch`（笔触太弱近似平涂）；seed 决定行色序列。
- **视觉验收渲染工具**：`tools/baking/render_smithy.gd`（`godot --path stick-world --script res://tools/baking/render_smithy.gd`，非 headless，输出 user://smithy_render.png）。注意：① 场景默认 PLANNED 态 alpha=0.3，验收图须 `set_state(2)` 切落成态；② `--script` 模式下别引用全局类名（class_name 解析不可靠，用 duck typing）；③ 改完 .gd 先 `--import` 再渲染，否则卡死。
- **测试编排**：`run_all.sh -Match` 是**子串匹配**不是正则，多目标要循环单跑。
