## 三、主循环挂接点（谁每 tick 调它）

**总调度**：`MapBox.Update()` → `MapBox.updateSimulation(float pElapsed)`（MapBox.cs:1809）。未暂停时按序调用：

```
updateCities / updateActors / updateBuildings   ← 批次系统（JobManagerBase.updateBase）
drop_manager.update          ← 掉落物物理与落地
cultures / clans / subspecies / languages / religions / plots.update  ← 元文化族实体
updateWorldBehaviours        ← 世界级行为（era 灾难等）
armies.update                ← 军队
kingdoms.update              ← KingdomManager.update → 每王国 updateCiv（timer_action 节流后 ai.update()）
diplomacy.update             ← DiplomacyManager.update（外交 tick）
alliances.update / wars.update ← 同盟与战争
projectiles / statuses / era_manager.update
```

**关键节流机制**（摸底确认）：

| 挂接 | 位置 | 机制 |
|------|------|------|
| 个体 AI | `Actor.b6_updateAI`（Actor.cs:9672）← BatchActors b6 桶（BatchActors.cs:70） | 批次三段式（JobType.Pre/Parallel/Post）；`asset.has_ai_system` 才跑 |
| 效用决策 | `Actor.b6_0_updateDecision` ← 独立容器 `c_make_decision`（BatchActors.cs:67） | 事件驱动：每帧只对被塞进该容器的 Actor 决策，跑完 `Clear()` |
| 王国 AI | `Kingdom.updateCiv`（Kingdom.cs:540）← KingdomManager.updateCivKingdoms | `timer_action > 0` 时跳过；ai 为 null 则整体跳过 |
| 城市 AI | City.cs:1228 附近 | 同王国：`timer_action` 节流 + `ai.updateSingleTasks` 附加 |
| 自然死亡 | `b55_updateNaturalDeaths`（BatchActors.cs:69） | 每 20 帧跳（addJob 第 5 参 skip） |
| 找敌人 | `b3_findEnemyTarget` | 每 5 帧跳 |

> BatchActors.addJob 的第 5 参是「跳帧数」（如 b55 填 20）——**WorldBox 的分帧不是 CoH 的固定 0.5s 节拍，而是「桶 + 跳帧 + 事件容器」三件套**，比 CoH 更细粒度。【提案/待定：是否值得作为本项目 L1 调度参照，阶段 2 验证】

## 五、高价值深挖点清单（阶段 2 深读文件，按优先级）

> 排序依据：与本项目「游戏 AI 系统」设计（`docs/设计/系统/12-游戏AI系统.md` L4/L3/L2/L1）的可借鉴强度 × 信息密度。

1. **`UtilityBasedDecisionSystem.cs`（334 行）+ `DecisionAsset.cs`（168）+ `DecisionsLibrary.cs`（2188）** —— L1 效用决策内核 + 全部 weight 真值表。重点：NeuroLayer 优先层与跳层概率、softmax 温度、cooldown 语义、only_* 过滤族、代表性决策的 weight_calculate_custom 写法。**这是 WorldBox 对本项目的头号参照**（对应 12 文档 C7 效用打分的第二家业界先例）。
2. **`AiSystem.cs`（403）+ `BehaviourTaskActorLibrary.cs`（3265，可分段）** —— L1 任务状态机内核与任务编排全景。重点：Job→Task→Action 三层流转、BehResult 各态语义（尤其 StepBack/ActiveTaskReturn/ImmediateRun）、single_interval 间隔、任务让位标记（cancellable_by_*）、条件守卫用法。
3. **`War.cs`（1026）+ `DiplomacyHelpers.cs`（239）+ `DiplomacyManager.cs`（374）** —— L4 战争与外交调度。重点：开战判定链（isWarNeeded→getWarTarget）、main_attacker 重选、War.update 内部节奏、endForSides 的战果结算、观感因子清单（OpinionLibrary）。
4. **`KingdomBehCheckKing.cs`（266）+ `DiplomacyHelpersRebellion.cs` + `Plot.cs`（418）+ `SuccessionTool.cs`（76）** —— L3 组织存续与权力交接（本项目组织深化最缺的一块）。重点：王室氏族/首都领袖/城市分家三级 fallback、叛乱走 Plot 的推进链。
5. **`BatchActors.cs`（521）+ `JobManagerBase.cs`（270）+ `Batch.cs`（210）** —— 横切调度架构（对应本项目战斗规模化 30fps 任务）。重点：桶编排清单（30+ 桶的顺序与跳帧参数）、事件容器（c_make_decision）模式、Parallel 边界（哪些桶敢并行）。
6. **`CityBehBuild.cs`（813）** —— 城市建造规划算法（选地/放建筑/道路），对应本项目建设 AI。
7. **`City.cs`（3192）** —— 城市经济/军事上限/粮食/占领全套接口（配合 CityBeh* 11 个行为）。
8. **`DropsLibrary.cs`（2159）** —— 掉落表工厂（战利品/宝箱/资源生成逻辑），对应本项目物品管线。

（次级：ActorTraitLibrary 1671、StatusLibrary 1483、ActorAsset 1386——特征与状态是决策 only_* 与 weight 的重要输入。）
