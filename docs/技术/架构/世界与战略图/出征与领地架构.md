## 一、战斗收束管道（combat）

`BattleInstance` 的结束判定与结算次序（消费方 = 任何战斗监听端）：

- **结算载荷先行**：`_end()` 先发 `EventBus.battle_settled(battle_id, summary)` 再发 `battle_ended(battle_id, victory)`——结算数据先到，监听方免回查已 `queue_free` 的实例。summary 携带 result/reason/duration/player_wins/player_faction/casualties/alive，字段契约见 [`../数据与契约/系统交互与EventBus.md`](../数据与契约/系统交互与EventBus.md) §2.3。
- **victory 语义 = 玩家阵营胜**：以 `player_faction` 为基准（`start_battle`/`add_unit` 链路传入）；未设置时回退攻方胜（旧 attacker 语义兼容）。
- **超时收束**：`duration_limit > 0` 时战斗超时判负收束；常规战斗默认 0 = 只有全灭一路判定。
- **离场计非存活**：单位带 `departed` 标记（撤至地图边缘离场）计入非存活清点；标记跨战斗复位（实体跨战斗存活，上一场的 departed 不带入本场）。

## 二、敌将撤仗（combat / TeamAi）

- **ROUT 姿态**（stance=3，单向终态，本作扩展）：撤仗不回头，维持期每决策周期重发撤离号令（单位溃逃会清空命令，重发保撤离不中断）。
- **撤仗评估阈值**：`retreat_casualty_rate`（伤亡率超阈）/ `retreat_loss_ratio`（敌我战损比超阈）/ `retreat_timeout`（相持超时秒数），默认全负 = 不评估——普通战斗维持全灭判定；据点战类场景按战术档注入阈值（来源 `team_ai_profiles.gd`，注释锚点 出征与领地架构-历史实施记录 §4.2）。任一满足即全军 `RETREAT`（`behavior_retreat` 有序后撤，非溃逃）。
- **战役撤离口径**：撤退方向被可走带夹死且已贴边时，改按己方出生侧边缘脱离战场，抵达边缘带即登记 `departed`（存活清点得以收敛）；"带内夹死"（未贴边）仍按脱战重整处理。

## 三、守军生成管道（expansion）

`GarrisonSpawner.spawn_garrison(map, row)`（`modules/expansion/scripts/garrison_spawner.gd`，零出向纯管道，暂无装配调用方）：

- **只刷军不开战**，接敌开战编排归调用方；编成数据源 = 调用方传入 `row = {garrison: [{profile, count, tier}], commander: {profile}}`。
- **布阵**：优先读图上 `ConquestAnchor`（GarrisonSlots/CommanderSlot/RallyX，对齐 MapInstance.BattleAnchor 先例）；无锚点按程序化 fallback（右侧半区横排，不阻断玩法）。
- **兵种档案**：profile 为 `config/units/stickmen.tres` 行 id，经 UnitsApi 场景常量 + MapBase.spawn_entity 刷单位（进树前写 def_id，实体 _ready 拉数值）；variant → 武器类型映射内置于 spawner。
- **来源标记**：`META_GARRISON_UNIT` / `META_GARRISON_COMMANDER`（敌将属指挥层不计入伍额）/ `META_GARRISON_TIER`（战术档位透传）。

## 四、归属易手与疆域染色（world_map）

- **信号契约**：`region_owner_changed(tile_key, new_owner)`——region_id 发 **tile 级 id**（归属按面建模，据点=地块入口）；new_owner = 控制者 id，玩家约定 `"player"`。发射方 = 世界模型政权归属变更（接入前测试可代发驱动染色管道）。
- **染色链**：`world_map/api.gd` 订阅信号后写内部归属累积表 `{tile_key: owner_id}` → 整表重取 `get_owned_tile_keys()` 喂渲染器 `set_owned_tiles`（幂等，与读档读回归属同一路径）→ 变更即重烘填充 mesh 重绘。
- **取色唯一出口** = `MapRenderer.tile_fill_color`：地块在已占集合内 → `MapTokens.L1_PLAYER_TERRITORY_COLOR`（纯白——全政权色板走 OKLCH 全色环，唯一无政权分到的白色即我方疆域），否则所属政权色；占多少格染多少格，不整国变色。

## 五、解锁台账（core / construction）

- `WorldState.unlocks` 台账 + 开局基线 `STARTING_UNLOCKS`（现役可建建筑所需 id 恒视为已获，门禁引入前后开局可建集不变）。
- `unlock_granted(unlock_id)` **只发新获项**（重复授予/读档重放不再广播）；消费端 = 建筑可建集门禁（`ConstructionManager.is_def_unlocked` 按 def 的解锁 id × 台账判定，`BuildMenu` 灰显并随信号重刷）；装备/科技等系统接自己的消费端即插即用。
