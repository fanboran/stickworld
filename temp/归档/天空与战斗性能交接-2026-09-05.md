## 一、天空系统现状（本轮成品）

### 代码
- `modules/world/scripts/map/sky_decor.gd` **全量重写**：
  - **地形组** `BIOME_SETS`：`"mountains"`（远山×2，村落/战场/道路默认）与
    `"forest"`（远山×2+树线×3，forest_zone.tscn 显式 `sky_biome="forest"`）。
    地形组由 `MapBase.sky_biome`（新 @export）→ VillageMap/road_map 注入
  - **层定义 = Terraria 反编译直译**（Main.cs DrawSurfaceBG）：bgScale 1.0/1.15/1.25/1.31/1.34，
    层顶距地平线 525/440/540/417/295px（magic=-0.85、地平线 540px 时的 bgTopY 公式值），
    运行时整体乘 `sky_ratio = horizon_y/540` 适配任意地图构图比例
  - **平铺 = modulo 回绕**（Main.cs:53724 同构）：sprite 开 texture_repeat，region 覆盖
    视野宽+2tile，每帧 `position.x = view_left - fmod(cam_x*parallax - view_left, w)`。
    注意：sprite 原始 position 以 (2-parallax) 速率含 w 回绕跳变（视觉内容视差 (1-p) 正确），
    verify_parallax.gd 已改测"内容相位 (position-cam_x) mod w"
  - **云三档穿插**：distant(scale<1.0 山后)/closer(两山间)/closest(≥1.15 树线远后)，
    重生换 pass 换父；云池 32、出生带 [1.08H, 0.25H]（H=天空高）、风驱 ×9×视差、
    alpha 0.06/s 软生灭、±0.01rad 摆动——Cloud.cs 直译（本就落地，本轮换原版贴图+加 pass）
- 贴图 9 张在 `assets/sky/`：bg_mountain_far/near、bg_trees_far/mid/near、cloud_a~d
  （旧 mountains/treeline_*/fog_band 已删；walker_f0/1 菜单彩蛋保留）

### 提取管线（可复现）
- `tools/ai/extract_terraria_sky.py` + `tools/ai/xnb_lzx_extract.js`
- 源：`E:/Windows_steam/steamapps/common/Terraria/Content/Images/*.xnb`（LZX 压缩）
- LZX 解码用 external XnbCli（github.com/LeonBlade/XnbCli，默认 F:/tmp/XnbCli，
  环境变量 XNBCLI_DIR 可改；其 dxt-js 在 node22 解析失败、lz4 需原生编译——本脚本只
  require 它的纯 JS Presser/Lzx，绕开两个坏依赖）
- 已登记 `docs/项目/素材替换清单.md`（正式版前替换）

### 坑（重要，别再踩）
1. **XNB Color 是预乘 alpha**：反预乘除法在低 alpha 区放大 8bit 舍入 → 渲染成
   "一排排横灰线"。提取器 alpha 下限 96 封顶放大
2. **顶边回绕渗色**：sprite 开 texture_repeat 且 region 高=贴图高时，顶边线性采样
   垂直回绕"吃"到底部不透明行 → 每层层顶 1px 灰缝。提取器顶部垫 2px 全透明行
3. **战场构图**：battlefield ground_ratio=1.15/ground_bottom=1674 是刻意的 SWL 大纵深
   （相机 0.55 时天空在屏顶 ~22% 可见），别当 bug 改回去

## 三、战斗性能（96v96：模拟 30/30 满速；渲染 1.4→16.4 FPS@安静窗口）

### 诊断方法（battle_perf.gd 内置二分开关，复跑就能用）
`tests/dev/battle_perf.tscn`：渲染 FPS 采样 / `--headless-measure` tick 速率；
开关 `--anim-off / --rig-hidden / --bodies-ghost / --freeze-entities`。
**结论链**：冻结实体全部物理处理 → 59.9/60 满速 ⇒ 瓶颈 100% 在实体逐 tick GDScript；
渲染/动画/单位互撞各自关掉都不动 ⇒ 别再去渲染侧找模拟瓶颈。

### 已落地优化（按收益排序）
1. **物理 tick 60→30Hz**（`TimeManager._ready` 强制 `Engine.physics_ticks_per_second=30`；
   project.godot 同名配置**实测不生效，原因未明**——坑留档）逐 tick 成本减半，delta 语义自适配
2. **AI 半频**（stickman_entity `_ai_rate_div`：60Hz 物理时隔帧=30Hz 决策，30Hz 物理时逐帧；
   相位按 instance_id 奇偶错开均摊）
3. **空间网格**（`MapBase.query_neighbors`，cell 64px，每物理帧重建+进出树失效）替代：
   动/静态分离 O(n²) 扫描、AI 威胁/被围判定、push_apart、TargetFinder 短程预筛
4. **单位间物理互撞关闭**（stickman_entity.tscn mask 3→1，防叠人全权交网格软分离）
   ——用户拍板的"点状距离碰撞"方向；Godot 无内置点距碰撞，网格+距离判定即自研实现
5. **每帧实体列表缓存**（get_entities 不再每次 get_children 分配）
6. battle 存活列表按物理帧缓存（get_alive_enemies_of/get_alive_allies_of，消每次候选判死）
7. 飘字 Label 池化（fx_library 静态池）、阴影纹理全单位共享（stickman_entity 静态缓存）、
   箭矢场景 preload、血条 wobble 仅掉血后重画+死亡停 _process、rig 动画检测 30Hz 采样、
   胜负清点 0.5s 节流、演练场 HUD 0.25s 节流
