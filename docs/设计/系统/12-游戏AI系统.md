# 游戏 AI 系统（集大成）

> **定位**：火柴人世界的分层 AI 总设计——把各大游戏验证过的 AI 机制复刻进本项目，与本游戏独有的组织层级纵贯轴合成为一体的 AI 体系。本文是「是什么 / 怎么设计 / 为什么」，批次进度见 [`../../项目/交接/游戏AI集大成-进度与交接.md`](../../项目/交接/游戏AI集大成-进度与交接.md)。

## 一、愿景：分层各取一招，层级是纵贯轴

业界已验证的 AI 强项各在一层；本项目全部采用**分层架构**，每一层选一个业界最强的范式做骨架，再由**组织指挥链**（本项目独有，CoH 没有）把各层纵贯起来：

```
L4 战略层   ← CoH 遭遇战 AI（任务槽+预算+攻击比例）      → 域：战役/世界
L3 组织层   ← 本项目原创（逐层指挥链+补位，见组织系统架构）→ 域：organization
L2 小队层   ← CoH squadai（角色相位计划）+ 效用打分技能    → 域：combat
L1 个体层   ← 现状行为机（move/idle/retreat/seek_cover）  → 域：units/AIController
```

**为什么不是把每家游戏整套搬进来**：机制堆砌会互相打架（决策权、CPU、玩家心智三重成本）。集成原则：**每层一个范式骨架**，其余机制以参数/插件形式挂进该层；层间只经 EventBus 与组织数据通信，玩家的每次干预永远只落在其中一层。

## 二、知识产权红线（必守）

- 复刻对象是**机制与参数思想**（不受版权保护），不是代码与数据（受保护）。
- CoH 逆向件只存 `temp/`（gitignored），**永不入库**；实现代码全部原创 GDScript，命名/结构按本项目惯例。
- 数值不抄原值——按本项目量纲（px/s、士气、编制）重定，用 BalanceConfig 行校准。
- 逆向分析笔记（`docs/审计/`）只记结构与语义，不含可再分发源码。

## 四、设计原则（继承三铁律，新增四条）

1. **惩罚来自模拟因果**（铁律继承）：压制=行为禁令、无主=命令停驻，禁止 ×1.5 类数值折扣。
2. **延迟=物理传播**（铁律继承）：C 层机制一律不得引入「层级数生延迟」的抽象公式。
3. **概率是执行机制不是因果**（CoH 启示）：掷骰只用于消除阈值边界的机械感（撤退/技能），因果仍是真实战况。
4. **决策有节拍**：AI 不逐帧思考；每层一个固定节拍（L4 0.5s 级 / L2 事件驱动+低频校验），分帧防尖峰。
5. **任务槽解耦**：下令方（战略/组织 AI）只声明意图槽，匹配与执行归下层——禁止上层点名单位。
6. **难度不等于资源作弊**：难度差异走参数曲线（时机/概率/方差/上限），数值公平。
7. **一切数值进 BalanceConfig**：AI 与平衡同表（category=command / ai），热重载可调。

## 五、与组织系统批次 3 的关系

- 批次 3-F1/3-F2（dispatcher/transport/补位/issue_to_org）是 L3 层基建，**先行不变**。
- C3 任务槽与逐层指挥链在 `issue_to_org` 汇合：战略 AI 的任务槽是对「同级直控小队」的模式；组织化小队（挂在 L2+ 下）的号令走指挥链吃传播延迟——**同一战局两模式并存**（散兵直控 vs 编制行军），这正是集成点而非冲突点。
- A2 起的任务槽实现须消费 3-F2 定稿的 `issue_to_org`（对 L1 散兵用既有 `issue`，对组织化编制走 org 入口），避免两套下令路径分叉。
