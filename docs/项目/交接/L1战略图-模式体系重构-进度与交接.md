## 二、设计定稿（2026-09-23 摸底后成稿，待创始人过目）

### 2.1 目标形态：底图 + 四开关

底图（`l1_terrain.png`）恒在，**不再存在任何「整图替换」式模式**；叠加层全部开关化，可任意组合：

| 开关层 | 内容 | 默认态 | 数据源 |
|---|---|---|---|
| 政治染色 | 本省政权色半透明 mesh（α=0.55）+ 邻省暗一阶 | 开 | 包 states + `l1_province_politics.json`（现状沿用） |
| 城市建成区 | blob 三档贴图 + 城市描边链 | 开 | 包 blob 贴图（现状沿用） |
| 交通道路 | 矢量折线（土路/官道两 tier），**含跨包段** | 关 | 包 roads（扩展后） |
| 资源点 | 资源图标 | 关 | 包 `resources` 字段（**新增**，见 2.3） |

- 现三模式映射：地形模式删除（底图恒在）；政治模式 → 政治开关；交通模式 → 交通开关（`l1_travel.png` 整图退役——交通层改矢量折线，与跨包道路正解统一）。
- 原仅地形模式可见的建成区 blob 与城市描边，改随「城市」开关；原政治模式不描城的例外随之消失。
- 快捷键 1/2/3/4 = 四开关 toggle（不再互斥选模式）；HUD 模式条改四联 toggle 开关条；开关状态会话内持久（static，沿用 MapModeManager 现状），存档化暂不做。

### 2.2 模式管理器改造

`map_mode_manager.gd`：`enum Mode` + `static current_mode` → `enum Layer {POLITICAL, CITY, TRAFFIC, RESOURCE}` + `static` 开关表 + `layer_toggled(layer, on)` 信号（订阅方：HUD 开关条 / 图例 / 渲染器 / 各控制器）。`map_renderer.gd _draw()` 的 4 处 `if map_mode == …` 分发改按开关分层绘制，绘制顺序：底图 → 政治色（本省+邻省）→ 城块界链 → blob → 道路 → 资源图标 → 城市描边/hover/路由 → HUD 层。

### 2.3 资源点数据源（分布规则为 AI 提案/待验收）

包数据与生成端产物均无资源点字段（场景图资源点是运行时随机的，不可复用）。方案：**生成端新增派生步骤**——按群系 + 城市确定性种子产出资源点列表写入各包 JSON `resources` 字段（种类对齐经济口径：木/石/铁/钻/金/沥青；森林→木、山地丘陵→铁/石、稀有山矿→金/钻、特定矿带→沥青）。渲染端画图标（复用图标管线成品）。分布规则属提案，随渲染验收一起看。

### 2.4 跨包道路（需求 4）

生成端重跑步骤 5：`roads_global.json`（8192 全局坐标，含 L1 内边 + 跨 L1 边）为单一真相；**逐边裁剪进各包 context 窗口**，跨包段的落入部分随包内 `roads` 交付（包数据自包含显示段，交接档原倾向；运行时零新增文件加载）。渲染照常画折线（本地坐标，跨包段 `from/to` 为邻包聚落 ID 不影响绘制）。bin 重烤（`l_world_bake.gd`）+ submodule 双仓提交。当前 `output/roads_global.json` 不存在（仅旧 `road_v2/roads_v2_global.json`），重跑即生成。

### 2.5 道路连通度（需求 5）

L1 内骨架从「MST（n−1 条边）」改为**邻接图全连边**（Delaunay 邻接——每个城市连其几何邻城，≈「周围有几个城市就有几条路」），逐边贴地形 Dijkstra 搜路，山/海不可达才断；跨 L1 主路与 T3+ KNN 补边维持现状。落 `road_generate.py` + 重跑步骤 5（与 2.4 同批）。

### 2.6 邻省完整信息（需求 7）

邻包**按需装载**（`l1_packs/l1_%03d/`，后台分帧逐包装载，装载完成前现有「暗一阶一层」兜底不动），装完后邻省画完整内容：城块界（tiles）+ 城市 blob + 政权色。政权色**保持暗一阶**（区分主次，延续现有视觉语言；观感细节随渲染验收）。装载顺序按切省箭头环距离，内存口径 = 只装视野相邻包。

### 2.7 层级切换按钮化（需求 8）+ 政权列表侧栏（需求 9）

- MapHUD 增加层级按钮组 **[本省 L1] [地区 L2] [世界 L3]**（当前层级高亮；点击切到对应视图；Tab/M 快捷键保留）。
