# 建筑生成管线 v3——写实 PBR（Blender 3D）

> v2（Godot 2D 手绘笔触）**废弃**：用 2D 程序化绘制（polyline + CPU 噪点纹理）模拟材质存在天花板，做不出砖石/茅草/木料的物理真实感。
> v3 改用项目既有的 **Blender 管线**（与 `tools/icon_pipeline` 同构的生产纪律），用 PBR 材质 + 真实光照渲染正面立面。
> v2 可复用部分：建筑谱系清单与宽度约束（单位宽度 4 格 = 128px 的整数倍）、布局元数据契约（PNG + JSON）、验收工具形态（拼页/街景/确定性）。

---

## 一、方向与定位

### 1.1 风格定位：Stylized-Realistic（风格化写实）

**材质与光照走物理正确（PBR），造型与配色走风格化**——不是照片写实（会与矢量火柴人冲突），而是 Northgard / Townsmen / Graveyard Keeper 那类商业游戏的建筑做法：稻草看起来像稻草、砖看起来像砖、木头有木纹与体积，但构图干净、比例卡通、色彩统一。

判断标准（验收用）：**缩到游戏内实际显示尺寸（建筑高 200~400px）时，一眼能认出材质，且与火柴人同屏不违和。**

### 1.2 为什么 Blender（而非继续 Godot 2D）

| 维度 | Godot 2D 程序化（v2） | Blender 3D + PBR（v3） |
|---|---|---|
| 材质真实感 | 上限低（自绘线条 + 噪点） | Blender 节点材质（Brick/Noise/Wave/Voronoi + Bump/Displacement）＝ 工业级 |
| 光照 | 无（假阴影） | 真实太阳光 + 环境光 + 阴影 + 间接光 |
| 体积感 | 平面剪影 | 真实几何厚度、出檐、凹凸 |
| 复用 | — | 与 `tools/icon_pipeline` 同构（注册表 + 多 pass + 拼页验收 + 网页 review） |

### 1.3 与 v2 的资产关系

- **废弃**：`stick-world/tools/building_pipeline/`（Godot 2D 绘制域）不再演进；其产物 `temp/buildings/` 作废。
- **保留语义**：建筑 def 清单与宽度档（单位宽度 4 格 = 128px 的整数倍）、meta JSON 字段（barrier/front_wall/workslots/interact_cells/can_stand_on/wall_tier）、城市分级（hamlet→metropolis 八档）与功能区配比思路。

## 二、技术管线（环节 / 输入 / 输出 / 门禁）

```
tools/blender_buildings/（共 40 个 .py，逐文件职责见 §10.2 模块地图）
├── city_layout.py   城市平面求解：TIER_SPECS 8 档 + DEFS 44 def → lots/walls/roads/plaza（纯 Python，零 bpy）
├── buildings.py     建筑装配：ASSEMBLERS 40 种 + Builder 原语/倒角/窗表/屋顶（立项期的独立"模块库"已并入其中）
├── materials.py     材质库：PBR 节点图 65 key（M_PER_UV=0.42 米制标定）        → 门禁：样片渲染通过
├── props.py         道具/街具约 115 件 + dress 挂载 + dress_street 沿街节奏
├── interiors.py     内景 34 def 前后两层（对接游戏"前墙 alpha 0.3"机制）
├── nature.py / field_dist.py                 野外自然物 16 类 + 三级密度场分布
├── ground_tiles.py / ground_transitions.py   地面真无缝贴图 12 种 + 材质交接过渡件
├── daynight.py      昼夜分层：夜 = albedo × tint + glow（发光层分离）
├── bake_export.py   烘焙入库：四件套 PNG + meta.json 对齐游戏内 1x 坐标      → 门禁：实机对照通过
├── export_city_layout.py / gen_initial_city.py   布局 JSON 导出 / 离线参考
├── validate.py      自动校验六项（出厂门禁，§10.3）
└── probe_*.py（26 个）                        各环节验收/交付探针（渲染代码内联于探针，无独立渲染器）
```

**流程（每个环节产出必须过门禁才进下游）**：
1. **材质**：单个材质样片（平面 + 球体）渲染 → 审"是否像该材质、是否与参考图同档"
2. **构件**：屋顶/烟囱/门窗等构件级探针渲染（`probe_roof2` / `probe_facade`…）→ 审"造型与比例"
3. **单体建筑**：每 def × 宽度档 → 审"材质搭配/比例/细节/可读性"
4. **城市**：规模档街景 → 审"城市设计（分区/天际线/街道/构图）"
5. **入库**：全量拼页 + 游戏内实机对照

## 三、规格规范（硬数据，禁止即兴）

### 3.1 尺寸基准

| 项 | 值 | 出处/依据 |
|---|---|---|
| 1 格 | 32px | `PlacementGrid.CELL_SIZE` |
| **火柴人身高** | **130px ≈ 4 格** | `arrow_projectile.gd:23` BODY_HEIGHT=130；命中盒 131.25 |
| **门高** | **150px（≈1.15 身高）** | 人能通过 + 视觉合理；**层高必须 > 门高 + 楣梁** |
| 单层层高 | 196~212px | 米制层高带 `STOREY_H_BAND`（§8.7）；门 150 + 楣梁 |
| 单位宽度 U | 2 格 = 64px | **建筑宽度档一律 U 的整数倍**（创始人 2026-09-15 拍板：由 4 格步进放宽为 2 格步进；存量 4/6/8/12/16 档保留不动） |
| 建筑宽度域 | 4 / 6 / 8 / 12 / 16 格（存量） | 新增档按 2 格步进补（如 w10/w14）；小物件（井/摊/塔/城墙段）例外，1~8 格 |

### 3.2 长宽比约束（本轮返工重点）

**立面宽 : 总高（含屋顶）= 1 : 0.75 ~ 1 : 1.15**（参考图 `smithy.png` 近方形饱满构图）。
- 4 格宽(128) → 总高 110~170（单层矮房）
- 8 格宽(256) → 总高 220~340
- 12 格宽(384) → 总高 330~500
- 16 格宽(512) → 总高 440~680
- **超出上界 = 竹竿，必须降层高或加宽**；低于下界 = 趴地，加层或加屋顶。

### 3.3 建筑规格总览（def × 宽度档 × 层 × 高 × 材质）

现行规模：**DEFS 44 def**（`city_layout.py`）+ **装配器 40 种**（`buildings.py` `ASSEMBLERS`）。逐 def 的宽度档 / 墙高 / 屋顶 rise / 进深 / 材质档以 `city_layout.py` 的 `DEFS` 字面量为唯一真相源；个别 def 经映射共用装配器——chapel / church / cathedral 三档同源（cathedral[8/12/16]），city_hall 过渡期由 guildhall[16] 兼任，well / market_stall 走道具聚簇。

- **全量清单**（逐 def 参数、识别元素、装配器对应）：《建筑资产清单》§一/§八。
- **家族 × 级别窗口**（哪族在哪档出现/消亡）：《聚落等级与建筑分级》§三。

分类概览（44 def）：

## 四、城市设计规范

### 4.1 规模分级（8 档等级链）

**hamlet 小村落 → village 大村落 → townlet 村镇过渡 → town 大村镇 → burgh 城镇过渡 → city 大城市 → capital 行省首府 → metropolis 帝国首都**。

| 档 | 主街长（格） | 建筑数 | 城墙 |
|---|---|---|---|
| hamlet 小村落 | 80 | 10~12 | 围栏/矮墙 140 |
| village 大村落 | 96 | 14~16 | 木栅 220 |
| townlet 村镇过渡 | 112 | 16~18 | 木栅+土墙 270 |
| town 大村镇 | 128 | 18~22 | 石墙 320 |
| burgh 城镇过渡 | 160 | 22~26 | 石墙 370 |
| city 大城市 | 192 | 26~32 | 石墙 420+马道 |
| capital 行省首府 | 256 | 40~48 | 砖墙 520 |
| metropolis 帝国首都 | 384 | 60~72 | 砖墙 640+瓮城 |

- 每档完整显式参数（width_px、街道 street、广场 plaza、支路 side_roads、街具数 n_props、塔距 tower_gap、地面区带 ground_bands、天际线地标 landmark、行政建筑 admin…）唯一真相源 = `city_layout.py` 的 `TIER_SPECS` / `TIER_META`。
- 等级链定位、天际线地标与行政阶梯的完整表见《聚落等级与建筑分级》§一/§二。
- hamlet / village / town / city 为基线四档（既有 seed 布局零漂移）；townlet / burgh / capital / metropolis 为扩展档（**提案/待定**，分级文档 §一 标注）。

### 4.2 功能分区（由中心向两侧，权重固定）

核心 8%（市政厅/教堂/礼拜堂）→ 市场 22%（酒馆/面包房/商铺/摊/井）→ 工匠 22%（铁匠铺/马厩/草棚顶民居）→ 居住 34%（民居/街屋/抹灰街屋/农舍）→ 生产 14%（谷仓/风车/草棚）。

### 4.3 街道与广场

- **街道宽度** = 2~3 格（64~96px，可容火柴人群）
- **建筑退线**：建筑前进线与街道边线对齐，不得侵入道路
- **广场**：市场区中央留 6~10 格空场，中心放水井/雕塑/市集摊群
- **小巷**：每 4~6 栋留 1 格缝隙（打破"梳子齿"）

### 4.4 天际线与视觉重心

- 唯一最高点：**教堂钟楼**（或市政厅塔），位于城市中心偏后
- 次高点：城墙塔楼（等距 800~1200px，高低错落 ±15%）
- 城墙 = 城市轮廓基线，墙顶高于 80% 建筑
- **禁止等高建筑连排**：相邻建筑高差 ≥ 15%，或材质/颜色不同

### 4.5 街景构图

- 单排 = 街道立面（本项目）；可另出"俯视城市图"用于战略图参考
- 前景元素（桶/摊/树/井）打破平直，但必须落在街道内
- 左右两端以城墙转角收边，中央以广场/教堂形成视觉焦点

### 5.2 光照方案

- 主光：太阳（暖白 1.0/0.95/0.85），方位**左上前**（仰角 50°、方位 -35°），强度 3.0~3.5
- 环境：天空冷蓝（0.62/0.70/0.82）+ 地面反射暖棕，强度 0.8~1.0
- 补光：右后方弱冷光（0.15），压暗比 ≤ 2.5:1
- 阴影：柔和（sun angle 3°），接触阴影必须可见

### 5.3 相机与渲染

- 正交相机，**纯正面（水平偏航 0°）+ 俯角 20°** 微俯视（§8.1）；城市总览图另开 ~34° 俯角读出行深（配图用，非游戏内视角）
- 分辨率：2x（1 格 = 64px）；输出透明底 PNG
- 色彩管理：`Standard` 视图变换（保证与游戏内 2D 一致），不用 Filmic
- 采样：EEVEE Next 64 / Cycles 视需要
- 输出：烘卡入库 `stick-world/tests/dev/proto_hd2d/tex/proto25d/cards/`（`<def>_w<W>.png` + 同名 `_glow.png` + `cards.json`，§10.1⑩）

### 5.4 配色

- 木/茅草：暖棕黄系（主体积）
- 石/砖：冷灰 + 砖红（对比体积）
- 点缀：旗帜/招牌/窗帘用饱和暖色（红/金/蓝），**每栋 ≤ 2 处**，作为视觉焦点
- 禁止：高饱和纯色大面积、荧光色、纯黑（最深用 0.08 灰）

## 八、规范修订决议（对 §3~§5 冲突的拍板，与上文冲突时以本节为准）

前三章的规范在实施中被三个并行小组证伪了若干处，本节为**裁决结果**：

### 8.1 视角（重要变更）

**纯正面 + 俯角 20° 微俯视：相机水平偏航 0°（YAW=0，建筑正面朝观众），俯角 20°。**
理由：本项目是横版卷轴的侧视微俯视游戏，建筑正面朝观众；水平偏航会让同排建筑朝向分歧，镜像使用又会破坏光照一致性，均禁止。俯角用于露出坡屋面——零俯角下屋面会被压成一条线，失去"大面积屋面"这一参考图核心特征；20° 是"保住屋面可见面积"与"仍是侧视游戏"之间的取舍点。
- 探针统一口径：`probe_buildings.py` / `probe_city_scene.py` / `probe_delivery.py` 均 `YAW=0.0, TILT=20.0`。
- 游戏内 Sprite 用同一套图，方向感由玩家视角统一理解。
- **城市总览图**另开 ~34° 俯角（`CITY_TILT=34`）读出行深——那是配图，不是游戏内视角。

### 8.2 宽度与长宽比（修正 §3.1/§3.2）

- **带门建筑最小宽度 = 8 格**（裁决实施后的修订：6 格实测已是长宽比天花板 1.49、屋面占比仅 27%；
  「门 150 + 门框 8 + 有坡度的屋面」在 6 格（192px）内算术上必然超标，且加宽本身正是"别太窄"的正解）。
  4 格档仅用于小物件（水井/市集摊/城墙段/柱撑棚），6 格档保留给无门/矮体量（草棚、马厩开口、遮棚）。
- 长宽比统一口径：**网格宽 : 剪影总高 = 1 : 0.85 ~ 1 : 1.5**（单层）；**超出上界 = 竹竿，必须加宽或减层**。
- 双层建筑单列：**层高 196~212**（`STOREY_H_BAND`，§8.7 米制层高带；门 150 + 楣梁），总高 = 层高×层数 + 屋顶 rise；不得用单层长宽比约束双层。
- 民居/商铺/草棚等单层：6 格宽 → 高 190~230；8 格 → 高 230~300；12 格 → 高 300~420。
- 出檐：**每侧绝对封顶 60px**（EAVE_ABS_MAX；≤9 格的小建筑维持 宽×20.5% 现状=39~52px）。旧「宽×18~23%」百分比口径在大建筑上檐绝对长度过大（w16 达 105px），2026-09-16 创始人过目裁决改封顶。

### 8.3 门与洞口的例外（修正 §3.1）

- 门净高 **150**、单扇宽 45~60。
- **复合门洞豁免**：谷仓大门（双扇合宽 ≤ 140）、马厩前檐开口、开放棚（无门）、城门拱洞——按各自 def 语义实现，不受 45~60 限制。

### 8.4 光照定标（修正 §5.2，以实测定标为准）

| 项 | 值 |
|---|---|
| 太阳 | 仰角 40°、方位 -38°，强度 3.0~3.5，暖白 (1.0, 0.95, 0.85)，sun angle 3°（柔影） |
| 环境光 | **强度 0.60**、天空冷蓝 (0.62,0.70,0.82) + 地面反射中性暖（0.8~1.0 会把暖色洗成橄榄绿，实测证伪） |
| 补光 | 右前弱冷光 0.15（背光对正对相机的立面无贡献） |
| 阴影 | 接触阴影必须可见；压暗比 ≤ 2.5:1 |

### 8.5 材质禁令（补充 §5.1）

- 抹灰墙**禁止锈褐色斑块**（只允许：颗粒、抹刀痕、泛潮斑、边缘剥落）；实测出现锈斑判不合格。
- 石砌偏蓝灰需校正（目标中性灰 0.60/0.58/0.54）。
- 缩到 25%（游戏内实际尺寸的量级）后必须仍能辨认材质类型——这是每个材质的**出厂门禁**。

### 8.6 城市规范豁免与修正（修正 §4.1/§4.4）

- **hamlet/village 豁免**"墙顶高于 80% 建筑"（矮墙档与单层房齐平即为合格）。
- 城墙塔楼：高度上限绑**教堂顶 - 30**，下限为"次高建筑 + 20"；同城塔高极差 **≥ 15%**（防等距发假）。
- 小档焦点：hamlet/village 使用**矮教堂档**（塔顶 400~480），风车/谷仓等高体量压到 ≤ 340，保证教堂为唯一最高点。
- 城市立面渲染时，**后城墙只画低矮背景轮廓**（按平面深度画完整后墙会夺走教堂钟楼的视觉重心 —— 布局组实测）。

### 8.7 层高与长宽比口径（修正 §3.1/§3.2/§8.2 的对应条目）

**换算基准**：火柴人 130px ↔ 1.70m → **1 米 ≈ 76px**（1px ≈ 1.31cm，换算锚细则见 §8.8）。所有尺寸按现实建筑换算，禁止凭感觉定：

| 现实项 | 现实值 | 游戏像素 | 依据 |
|---|---|---|---|
| 门高 | 2.0m | **150** | 人高 1.70 + 门楣余量（`DOOR_H`） |
| **层高** | **2.8m** | **205~210** | **门占层高 71%**；代码层高带 `STOREY_H_BAND=(196,212)` |
| 屋顶高（单层） | 1.5~2.0m | 110~150 | rise ≈ 层高 × 0.5~0.6 |
| 民居开间 | 5~6m | **12 格（384px）** 为主力 | 8 格（256px≈3.5m）只做附属矮房 |

**长宽比口径（说明含义，避免再误解）**：写作 **立面宽 : 剪影总高 = 1 : X**。
- X = 0.85 表示"总高只有宽度的 0.85 倍"（宽扁）；X = 1.5 表示"总高是宽度的 1.5 倍"（偏高）。
- 分支判定：**单层建筑：X = 0.6 ~ 1.15**（允许宽长屋，禁止畸高）；**多层建筑：X = 1.2 ~ 1.6**（层数越多越高，属正常；二层 5.6m + 屋顶 2m 对 5.2m 开间 ≈ 1.46）。
- 校验时按层数分支判定，不再用单一口径卡所有建筑。

### 8.8 比例改米制（修正 §3.2 的"1:0.85~1.5"比例口径）

**换算锚**：火柴人身高 130px ↔ 真人 1.70m → **1px ≈ 1.31cm；1 格（32px）≈ 0.42m**。
所有尺寸按现实建筑尺度标定（废除"宽:总高"这种生硬比例）：

| 项 | 现实 | 像素（1x） | 备注 |
|---|---|---|---|
| 门高 / 宽 | 2.00m / 0.6~0.8m | **150（`DOOR_H`）** / 45~60 | 单扇；复合门洞（谷仓/城门）另计（§8.3） |
| 单层层高（净） | 2.40m | 183 | 门占层高比例偏大，**取 2.6~2.7m 更自然** |
| 单层檐高（墙顶） | 2.6~2.7m | **200~207** | 6 格小屋可 2.4m=183 |
| 屋顶高 | 1.3~1.6m | 100~122 | ≈ 檐高的 0.5 倍 |
| 单层总高 | 3.9~4.3m | 300~330 | |
| 两层檐高 | 5.2~5.4m | **400~413** | 层高 2.6m × 2 |
| 三层檐高 | 7.8~8.1m | 600~620 | |
| 窗台高 | 0.90m | **69** | 窗台不得低于此（临街一层 1.0m=76，`WINDOW_SPEC`） |
| 窗高 | 1.20~1.30m | **92~100** | 占层高约 45%（严禁窗高 ≈ 层高） |
| 窗宽 | 0.80~1.00m | 61~76 | |
| 民居面宽 | 6~8m | 458~610px（**14~19 格**） | 8 格(3.4m)=现实中"小屋"，4 格=棚 |
| 联排/长屋面宽 | 10~14m | 763~1068px（24~33 格） | 城市主街建筑 |

**结论**：单层层高（176~220px = 2.3~2.9m）本就在现实区间；观感"层高不对"的病因是
①**门占层高比例过大**（现实约 74%）——单层檐高取 200~207；②**窗高偏小/窗台偏低**的观感源自窗框细、缺少内外层次，按上表统一（窗表真相源 `WINDOW_SPEC`，§10.1②）。
**墙体比例仍按 §8.2 的"宽扁优先"**，但用米制解释：房屋宽度宜 ≥ 4m（≥10 格），小于此只能做棚/附属物。

## 十、管线流程总览与模块地图（现行实态）

> 本章按 `tools/blender_buildings/` 代码实态提取（**40 个 .py**），只写"是什么 / 怎么跑"。
> §一~§九 为立项期与历轮评审期的规范文本，凡与本章冲突处，**现行实态以 §10 为准**。

### 10.1 端到端流程链

#### ① 城市规划 —— `city_layout.py`

- **做什么**：按规模档 + seed 确定性求解城镇平面：分区配额、地块排布、行政槽位、特殊建筑摆位、城墙/道路/广场/巷道、天际线。纯 Python，零 bpy 依赖。
- **代码入口**：`plan_city(tier, seed=611036, width_px, depth_cells, has_gate, has_plaza, n_buildings, wall)`；CLI `python tools/blender_buildings/city_layout.py --tier <档> --seed <n> [--out x.json] [--selftest]`。
- **关键数据**：`TIER_SPECS` **8 档**（hamlet / village / town / city / townlet / burgh / capital / metropolis）；`DEFS` **44 def**（宽度档/墙高/屋顶 rise/进深/材质档）；`SPECIAL_DEFS` 7 个浮动摆位（mage_tower / library / barracks / warehouse / alchemy / belfry / observatory）。
- **产出**：JSON-able plan dict——`lots` / `admin_slots`（行政"充当档"指认既有 lot，零漂移不改既有排布）/ `specials` / `yards` / `props` / `walls` / `roads`（main + branches + lanes + plaza）/ `anchors`（gate / plaza_center / core / main_street）/ `skyline` / `leftover_units`，附带 `verify_plan()` 自检结果。
- **确定性保证**：`_rng_for(tier, seed)` 分域随机流，同 tier+seed 逐字节一致（`--selftest` 断言同 seed 一致、异 seed 有差异）。

#### ② 建筑单体 —— `buildings.py`

- **做什么**：`ASSEMBLERS` **40 种**装配器（4 个 dict 字面量 + 36 个行注册），`ASSEMBLERS[name](wc) → (对象, spec)` 按 def × 宽度档装配完整建筑。
- **Builder 原语**：box / 棱柱 / 倒角体系——`bevel_faces()` 真 chamfer，半径档 `BEV_BIG=2.0`（梁柱檐口）/ `BEV_MID=1.5`（木骨门框）/ `BEV_SMALL=0.8`（小件）/ `BEV_SEG=1`；倒角面写 `edge=1` 几何属性供材质混磨白层（规则见《美术品控-硬边与材质边缘》§2.1）。
- **窗规格表**：`WINDOW_SPEC` 为立面窗参数唯一真相源（窗台 69/临街 76、窗高 92~100、按开间比例收窄），装配器一律走 `win_rect()` / `put_window()`，禁止写死窗尺寸。
- **屋顶结构**：`roof_gable()`（椽 / 檩 / 封檐板 / 屋脊 / 泛水 `_roof_flash`）、`chimney()` 落地穿顶、`gable_infill()` 山墙封填；`timber_frame` / `plank_siding` / `plinth` 木骨与板条体系。
- **比例锚**：人体锚 火柴人 130px=1.70m（1px≈1.31cm）→ 门 `DOOR_H=150`（1.15×人）→ 层高带 `STOREY_H_BAND=(196,212)` 为民居基准，**公共/宏伟类一层按真实挑高上浮至 221~275**（2.9~3.6m，2026-09-17 层高真实化）、教堂中庭 345/535；出檐 `EAVE_ABS_MAX=60` 绝对封顶（≤9 格维持 20.5%）；`MIN_DOOR_CELLS=6`（带门建筑最小宽）、`U_WIDTHS=(4,8,12,16)`（小物件除外；三段式拼接批次将扩展 w24~w40 半屏档）。

#### ③ 材质 —— `materials.py`

- **做什么**：PBR 节点图材质库，`_BUILDERS` 注册表 **65 key**（茅草/瓦/石板/木板/木骨/抹灰/石/砖/铁/麻布 + 玻璃系/魔法系/地面系/自然物系/端面封端 `wood_end`），`ORDER` 定样片序列。
- **现实尺寸标定**：`M_PER_UV = 0.42`（1 UV = 1 格 = 32px = 42cm），入口 `px()` / `uv_m()` / `uv_cm()` / `uv_mm()`；`FEATURES` 每族现实特征尺寸表供 texel density 对照。
- **观感机制**：`glazing_win` 真透明窗玻璃（`ALPHA_KEYS` 三件之一，alpha 透视）；`AGE_OFF = True` 做旧层观感基准开关（`_aged` 近地溅泥/雨渍/日照褪色）；`OBJ_VAR` 逐体色变。
- **被消费**：`buildings`（`set_material_resolver` 注入）、`ground_tiles`（只读 `M_PER_UV`）、全部材质/建筑探针。

#### ④ 道具与街具 —— `props.py`

- **做什么**：约 115 件道具/街具构造器（桶/箱/货堆/工具/家具/玻璃器/魔法摆件/宗教件/街道家具），`GAME_SCALE ×1.45` 挂载口径（与火柴人同屏比例）。
- **代码入口**：`dress(b, kind, W, front_y, seed, door_x, door_w, …)` 门口避让挂载（`pack_sides()` 左右排布、门口净空）；`DRESS` **14 族**配方（house / tavern / smithy / cathedral / alchemy…）；`dress_street(W, seed, lamp_every, group_every)` 沿街节奏（路灯/长椅/花坛按组配方布点）。
- **被消费**：`probe_city_scene`（街面 props 层）、`bake_export`、`tests/dev/proto_hd2d/bake_props.py`。

#### ⑤ 内景 —— `interiors.py`

- **做什么**：34 def 内景前后两层（`_WIDTHS` 34 项，含 3 个别名 def：plaster_house / church / chapel 经 `_FRONT_ALIAS` 解引用到真实装配器，与 `probe_city_scene.DEF_MAP` 同源）；`layout()` 净尺寸从 `buildings` 的 tier 表读取（不复制数字）。
- **分层契约**：back 层（后墙/地板/楼板/家具/暖光）+ front 层（复用装配器成品 `crop_back_half` 切掉后半栋、窗玻璃换 `thin_glass(alpha=0.07)` 真透明）——对接游戏"前墙 interact 时 `modulate.a → 0.3`"机制；逐 def 清单与坐标契约见《建筑室内结构》。
- **被消费**：`probe_interiors`、`bake_export`（四件套中的 `back.png` / `front.png`）。

#### ⑥ 野外 —— `nature.py` + `field_dist.py`

- **做什么**：`nature.py` 野外自然物 **16 类**（`TABLE`/`NOMINAL`：阔叶/高阔叶/针叶/枯树/树桩/灌木/芦苇/草簇/蘑菇/铁矿/铜矿/金矿/水晶簇/巨石/碎石/矿脉带；`LOD_KINDS` 5 类 LOD），米制比例锚 `M = 130/1.70`（1 米 = 76.47 世界单位）。
- **分布**：`field_dist.generate(seed, region, cell_m=3.8, …)` 三级密度场——`cluster`（林区在哪）→ `subclump`（簇内哪最密）→ 逐点接受概率（核心密边缘疏），显式留白（clearing + 噪声开天窗）；成组—过渡—留白，严禁均匀撒点。纯 Python 可脱离 Blender 跑（`plan_png` 俯视分布图）。
- **被消费**：`probe_nature`（含 field_dist 总览图）、`tests/dev/proto_hd2d/bake_nature.py`、HD-2D 野外树/矿采集点。

#### ⑦ 地面 —— `ground_tiles.py` / `ground_transitions.py`

- **做什么**：`ground_tiles.py` 真无缝可平铺贴图库，`SPECS` **12 种**（鹅卵石/砖/石板/夯土/车辙泥地/砾石/草坪/砂/木栈道等）；周期域定义图案保证边缘精确无缝；一张贴图 = 4 格 = 128px = 1.68m，游戏档 128 + 高清档 512 同图案重取样；分带生成 `b_shoulder` / `b_kerb` / `b_road`（路肩/路缘/道路）与 `b_street_strip` / `b_segment` / `b_newold` 分段体系；`d_*` decal 8 种（污渍/水洼/苔/裂/碎屑/磨损/补丁/门口踏路）+ `m_mottle` macro 大尺度斑驳；变体靠种子偏移。`src/` 下导出**未打光**反照率/法线/粗糙度三件套（光照中性，游戏可直接打光）。
- **过渡件**：`ground_transitions.py` 手工预制材质交接过渡（两侧材质直接调 `ground_tiles` 同源生成器），`load_ground_tiles()` / `build_chart()` / `export_all()`。
- **被消费**：`probe_ground`、`probe_transitions`、HD-2D 地面（高清源贴图入库）。

#### ⑧ 昼夜 —— `daynight.py`

- **做什么**：昼夜分层光照与发光层分离。合成公式：**夜 = albedo × tint_night + glow × strength**；标定值 `tint_night=(0.11,0.14,0.26)`（≈环境压到白天 10~12% 偏冷蓝）、`GLOW_STRENGTH=1.0`（glow 按 1:1 加法设计，bloom 阈值建议 0.75 起）、光晕 `HALO_NIGHT=0.55` / `HALO_GLOW=1.00`、夜景双太阳 `NIGHT_SUNS`。
- **关键机制**：`collect_emissive()` 扫网格找 `Emission Strength > EMIT_MIN(0.05)` 的面按连通性分簇（一簇 = 一盏灯/一处炉火/一扇彩窗，不靠材质名靠节点真值）；点光源放簇前方 -Y（防灯具自遮挡）；`blacken_non_emissive()` 对象级材质替换 + 黑世界 + 灭灯出纯 glow 层（可无损还原）。
- **被消费**：`probe_daynight`、`bake_export`（夜档合成与 glow.png）。

#### ⑨ 渲染出图 —— `probe_*.py`

- **做什么**：各环节验收/交付探针（材质样片、单体比例、屋顶、立面、道具、内景、街景、地面、昼夜、品控、交付图等），全部可复跑；另有 `probe_city_plan.py` 纯 PIL 平面示意图（不依赖 Blender）。
- **跑法**：统一命令清单见交接档《建筑生成管线v3-写实PBR-进度与交接》**§四**（`docs/项目/交接/建筑生成管线v3-写实PBR-进度与交接.md`），本档不复制。

#### ⑩ 烘焙入库与运行时 —— `proto_25d` / `proto_hd2d`

- **建筑烘卡**：`stick-world/tests/dev/proto_25d/blender_proto.py` 只读导入 `buildings.py`，逐栋烘 **albedo 卡 + glow 卡**（双层像素对齐、透明白底），写 `cards.json`（anchor = 卡中心对应世界点）。入库副本 `stick-world/tests/dev/proto_hd2d/tex/proto25d/cards/`。
- **道具/自然物烘卡**：`tests/dev/proto_hd2d/bake_props.py` / `bake_nature.py`，与建筑卡同相机口径（正交 / 2x / 透明底；坐标 Blender (x,y,z) → Godot (x,z,-y)/32，1 格 = 32 Blender 单位），产出 `<name>.png` / `<name>_glow.png` + `props.json` / `nature.json`。
- **布局 JSON**：`export_city_layout.py` 把 `plan_city` 平面换算成 HD-2D 场景布局（cell 1:1；row 0 → 前排、row ≥1 → 背景层；def → 卡名按卡库实际档位挑选，特殊映射 church→cathedral_w16、plaster_house→house；market_stall/well 走道具卡）；`gen_initial_city.py` 为新裁决语义的生成器（长度按建筑数量、中心向两侧、五带不对称——**运行时真相源已移交 `stick-world/modules/world/scripts/map/city_gen.gd`**，本脚本仅离线参考，重启用前须对表）。
- **运行时消费**：Godot HD-2D 场景（主街/算法村）。运行时系统（卡落位/双渲染路径/batch_rig 开关）的真相源 = **《HD-2D街景系统.md》**。

### 10.3 校验与门禁

- **自动校验**：`validate.py`（`blender -b --factory-startup -P tools/blender_buildings/validate.py`；退出码 0=全 PASS / 1=有 FAIL；`VALIDATE_ONLY` / `VALIDATE_SEEDS` / `VALIDATE_PROPS_W` 可选覆盖）六项：
  1. **def↔装配器覆盖表**：`city_layout.DEFS` × `DEF_MAP`/`PROP_LOTS` 逐 def 对账，缺口逐条列出；
  2. **地块合规**：8 档 × 5 seed 跑 `plan_city`——同排 lot 不重叠 / 装配宽不超 lot / 每 lot 有可装配宽度档；
  3. **装配适配**：逐映射实调装配器，实测网格宽 ≤ lot 宽 + 基线比对；
  4. **窗规格 lint**：`WINDOW_SPEC` 全档位窗台/窗高/分立面窗型 ≤2 约束；
  5. **纹素密度纪律**：UV 标定入口唯一引用 `M_PER_UV=0.42`，源码级排查硬编码比例；
  6. **道具挂载回归**：`DRESS` 每套配方跑 `pack_sides`/`dress` 无异常、无负宽、道具名已注册。
- **美术品控门禁**：规则 = 《美术品控-硬边与材质边缘》**§2.4**——棱线高光检查图（可见棱必须呈高光渐变带，死线打回）/ 1x 可见性（游戏 1px/单位下 ≥1px 可辨，不可见的白不做）/ 交接缝扫描（材质交接必须有过渡件或 AO 缝，裸切打回）；落地探针 = `probe_bevel.py`（`pbr_bevel_specular.png` / `pbr_bevel_game1x.png` + stdout 数字自证）。
- **确定性门禁**：`plan_city` 同 seed 逐字节一致（`--selftest`）；烘卡与布局 JSON 全部随包入库，新机器 clone 后无需先跑烘焙即可玩。
