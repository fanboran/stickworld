# 组织系统（通用项目管理系统）

## 目的

这是整个游戏**最核心的系统**。让玩家用同一套工具，搭建帝国里的一切组织——军队、科学院、工程队、行政体系、商队。每个组织的底层逻辑完全相同——把一群火柴人按照你设计的层级组织起来，向某个目标运作。

## 玩家体验目标

- **一通百通**：学会了搭军队编制，就学会了搭科学院架构——逻辑一样，只是名字和用途不同
- **亲手设计**：每个组织之间的层级关系、每个层级的编制配置，都是你亲手设定的
- **看到效果**：好的架构高效运转，差的架构处处卡壳
- **随时回落**：你已是皇帝，但缩放到某个排长身上去微操绕后——像《戴森球计划》缩放一样自然

---

## 一、五层级框架

帝国里所有的组织都共享同一套五层级深度：

| 层级 | 行政语境 | 军事语境 | 科研语境 | 工程语境 | 物流语境 |
|------|----------|----------|----------|----------|----------|
| **L5** | 帝国 | 帝国最高统帅部 | 科学院 | 工程院 | 全国物流中心 |
| **L4** | 区域 | 师 | 研究所 | 区域工程所 | 地区物流中心 |
| **L3** | 行省 | 团 | 研究室 | 项目组 | 中转站 |
| **L2** | 城市/郡县 | 连 | 课题组 | 施工队 | 运输队 |
| **L1** | 镇/村 | 排/班 | 实验员 | 施工分队 | 运输分队 |

编制有层级，编制内的具体人也各有层级——如同现实中的机构级别与个人职级：副省级市高配半级，中央直属大学、省科学院各有级别，机构里的人也有对应的职级。

### 1.1 层级弹性

**加层级**：标准层级之间可以额外插入一层。例如：
- 在"团"(L3)和"师"(L4)之间插入"旅"
- 在"连"(L2)和"排"(L1)之间插入"火力组"

**减层级**：可以跳过某一层级。例如：
- 去掉行省(L4)，中央(L5)直接对接全部城市(L3)——中国某些朝代草创和快灭亡时常这样干
- 现实中装甲部队用"旅"取代"团"，直接对接营

**最底层宽松**：第1层可以额外向下塞**两层**。例如：
- 火力组 → 班 → 排，三个子层都挤在第1层内
- 班是最小编制，但在实际指挥中班长发现直接管单个步兵太难——于是手动分了两个火力组

**灵活命名的意义**：火力组不是正式编制，是班长在战斗中为了方便指挥临时分的——游戏里玩家的层级也是这样：正式的编制层级和临时的指挥分组可以共存。

### 1.2 集团军怎么办？

玩家本身是一个**虚拟层级**。当你的帝国足够大，你需要同时指挥多个"师"时——你是 L5+，下辖多个 L5 组织（多个师）。这个虚拟层级不算在标准五层级内，它是"你"。

就像周天子不过几个师——在游戏里，你作为皇帝管的可能就是几个 L4 级别的军事组织，它们并排放在你的名下。

玩家层级是**成长出来的**：从小卒起步（开局≈班长级），随你实际统辖的指挥链增长而逐步成为更高统帅——不存在生来就有的"最高统帅"位置。

## 二、组织即全能

**每个组织理论上什么都能干。** 军事编制可以施工（工程兵），科研单位可以被拉去打仗（虽然打得不好），行政机构可以经商（腐败风险大但理论上可以）。

### 2.1 标签系统

玩家给每个组织打上一个**标签**，决定了该组织的主界面默认展示什么：

| 标签 | 主界面默认显示 | 底层仍然可以做的事 |
|------|---------------|-------------------|
| 军事 | 进攻、防御、行军、呼叫支援、部署 | 施工、科研、运输…… |
| 科研 | 分配课题、审核论文、调拨经费、实验 | 打仗、施工、运输…… |
| 工程 | 开工、验收、材料调度、质量检查 | 打仗、科研、运输…… |
| 行政 | 征税、户籍、司法、治安 | 打仗、科研、施工…… |
| 运输 | 采购、销售、定价、物流 | 打仗、科研、施工…… |

UI 上——军事标签的面板显示进攻/防御按钮，科研标签的面罩显示课题管理。但点开**"完整功能"展开箭头**，你会发现所有标签下的组织都有一样的底层能力列表。就像 Blender 的 Modeling、Sculpting、Layout 工作区——功能一样，常用工具不同。

### 2.2 特化

虽然全能，但**特化决定干得好不好**——而且差的是机制，不是数值折扣：

- 科研单位被拉去打仗：没配武器、没受过训练、没有指挥经验——打得烂是"人不专业"，不是"战斗力 -30%"
- 军事编制做研究：没有课题积累、没有图书与器械——产出低同理
- 特化程度取决于：（1）你给这个组织配置的编制模板（2）人员的资质匹配度（3）装备配置

### 2.3 部门不预设与元层级

哪些部门存在、哪个是"最高部门"没有标准答案——像现实中各国结构五花八门一样，玩家可以随心所欲地设置国家架构，甚至"封一只狗为上将"。但**虚衔自由 ≠ 运行自由**：任命了不合适的首脑、挂了空有其名的部门，实际运转立刻出问题——如同你有喝毒药水的自由，但你真的会死。组织是为解决具体问题而涌现的：运输太累 → 封装运输主管；仗打不赢 → 组建训练组织；科研停滞 → 组建科研攻关指挥部。

**元层级**：组织可以管理"建立组织"这件事本身——后期玩家设计出能批量产出编制的编制、能组建部门的部门，把"搭组织"这件事也自动化掉。

### 2.4 槽位与机构（组织的组成方式）

组织是**纯机制系统，不带数值**——它的全部结构是功能槽位：

- **组织 = 功能槽位的集合**：每个槽位承担一项职能（指挥、传令、参谋、后勤、征兵……），槽位集合决定这个组织能做什么
- **每个槽位至少由一名人员激活**：空槽 = 该职能不运转
- **槽位也可以放一个机构**：机构是组织的组成单位（组织嵌套组织）——把一个运输处整个塞进集团的"物流槽"，即运输处以组织形态运转该职能
- **岗位按用人分三类**：**必须**（至少一人该组织才能开工，人数可弹性——越多越快）、**半必须**（需人运行但不必时刻有人，可由本组织别岗移调顶岗）、**增益**（无人也行，只是缺失/未解锁该功能——如探测、记录一类）。类属由标签色表达，说明文字不重复
- **任意职能槽都可下辖组织**，不只系统级大槽——信息、库管一类具体岗位同样可以放专门组织（矿石信息内设矿务所、农情信息内设农务所、库管内设库务所——收发+盘点），三采集线的信息岗同构，构筑逐层精细化
- 组织的强弱来自"哪些槽位被什么激活"，不来自隐藏数值加成——评估一个组织，看它的结构与人，不看面板数字

组织职能既作用于自身管辖的事务，也可以对其他组织实施——**组织对组织的服务**。物流是这一关系最广的载体（运输组织为各方跑货，见 [`06-物流系统.md`](06-物流系统.md)）；训练组织接收整只编制组织前来受训（[`04-科技系统.md`](04-科技系统.md) §三）是同一形态。

### 2.5 建组织的前提

前提分两层：**明面**与**隐形**。

- **明面前提**：显式标注在职能定义上的硬条件（如「在编有人会某技能」「在编有人某属性 ≥ N」——技能与属性口径见 [`04-科技系统.md`](04-科技系统.md) §二、[`17-单位基础属性.md`](17-单位基础属性.md)），一般**最多一两条**；加职能槽或塞机构时逐条校验，不满足即拒绝。没标注的职能无明面前提——门槛是特例不是默认。
- **隐形前提**：不写表、不做建立校验的运转物理——职能要在对应建筑里运转（无建筑 = 空转，不拒绝建立）；要有人占槽（空槽 = 不运转）；关键岗位（主管、教官）属性不足 = 降速运转而非停摆；支撑组织不存在 = 链条断。它们以「运转不起来」表现，不以「不许建」表现。

空白组织人人能搭。以征兵处为例：明面 = 在编有人组织能力达标（一条）；隐形 = 有带前台模块的办公室它才运转（场所需求见 [`03-聚落与建筑.md`](03-聚落与建筑.md)）。后期的重要机构可叠加多条明面前提——想搭什么，先攒什么。

### 2.6 市政厅与开局形态

- 每座城市必有一个**市政厅组织**——城市一切组织的根（定居点初名**聚落**，人口达规模后升格更名市政厅，见 [`03-聚落与建筑.md`](03-聚落与建筑.md) §八）。市政厅自带**固定职能槽板**（市长、军事、生产、运输、科研、情报——市政厅本身即行政，不单设行政槽；空槽 = 该职能未运转；**情报槽**负责给玩家生成一站式信息总览）；出生城的**市长**是玩家本人，其余人员与组织皆是玩家的下辖。槽的激活方式二选一：人员顶岗或机构入驻。
- **选中空槽即构筑**：点开一个空槽位，就地弹出选项——**放一个人顶岗**，或**构筑对应的子组织**负责该职能（更系统高效地自动化完成任务）；子机构可不断递归（如生产局的采集槽放采集队，采集队内再分伐木/采矿/农垦槽各放专门队）。
- **生产槽与一级子节点**：采集、建造、制造合并为市政厅的一个**生产**槽；其形态是一级子节点**生产局**——内部有采集、建造、制造三个槽位。**工程队**（建造类组织：测量、施工×多、质检）是典型的编制大而开局仅需少量人员的组织——建材运输归运输系统，工程队不设材料岗。
- **下辖即嵌套**：专门组织以机构形态入驻上级组织对应的职能槽（组织对组织，同 §2.4 机构入槽一条线，不另设隶属关系）——采集队入生产局的「采集」槽、军事组织入市政厅「军事」槽，逐层下沉。
- **训练是军事组织下辖的槽**：军事组织（常备军等）入驻市政厅「军事」槽，训练职能长在军事组织内部；训练营一类组织再入驻军事组织的「训练」槽——嵌套逐层下沉。训练营编制：训练管理、教官×多、器材管理。
- **组织树即构筑树**：每个槽位的子节点类型选项（可放什么组织）就是游戏的构筑选项——构筑方式可以有很多种，玩家根据实际需求搭自己的组织结构。后期工程队想按建筑种类提升特化效率，可为每种建筑设一种子结构。
- 开局没有专门军事组织——**耕战一体**：村民平时生产、战时皆兵，军事存在是一名**动员官**（常备军成立后入其军事槽）；常备军与专门军事组织是后来的事。
- **槽位分同质化与异质化**：同质化槽一个标签多坑位（如搬运×5，坑位上限随建筑规模变动）；异质化槽常见于制造——每个槽对应一道实际加工工序、各需一台对应设备（古代冶炼厂的分工与工作流）。
- **厂内半成品不出厂**：铁水、毛坯、淬火件一类中间物是工厂内部物品，无法离开工厂；外购原料与厂内流转并存（锻造坊可吃铁矿化铁水，也可直接吃铁锭）。
- **借调**：组织内岗位缺人时，由本组织在岗者自动临时借调补齐以维持运转——被借调者仍占原槽，只能借调人员不能借调组织；一人也能靠逐工序轮转撑起整间工厂，只是不如流水线高效（现实中的一人铁匠铺同理）。
- **组织与建筑独立**（见 [`03-聚落与建筑.md`](03-聚落与建筑.md)）：组织无对应建筑也能基础运转，建筑与室内配置解锁进阶槽位与工序。
- 各系统的专门组织随需求组建、入驻对应槽：采集、运输、建造、**制造**（资源加工流水线——把基础资源加工成木材、木板、铁锭、铁剑、战车、药水等制品，缺氧式上下游）、训练、教育研究（带明面前提，偏后期）。农田产物为农作物——战粮与炼药原料同源。组织模拟台（`tools/org_sim_web/sim.html`，网页版设计草稿）即这些形态的可玩原型。

## 三、编制管理

在每个层级的节点上，玩家配置该节点的**具体编制**——这个班/连/团/师里具体有什么。

### 3.1 可配置项

| 配置项 | 说明 | 示例 |
|--------|------|------|
| **人员组成** | 该层级包含的角色类型和数量 | 1 个弓箭手 + 4 个矛兵 + 1 个法师 + 2 个工兵 |
| **装备配置** | 标配武器、护甲、工具 | 制式长弓、皮甲、工兵铲 |
| **指挥官** | 任命或留空 | "铁拳张三" 或 系统自动填补 |
| **自主决策权限** | 该层级可以自行决定什么 | 攻击/防御/撤退/调兵/征用物资 |
| **默认战术** | 无指令时的自动行为 | 主动进攻 / 坚守阵地 / 游击骚扰 / 自主判断 |
| **补给优先级** | 物资分配的权重 | 高 / 中 / 低 |
| **编制士气与溃逃线** | 士气以编制为单位（个人无士气，全战三国式，见 [`02-战斗系统.md`](02-战斗系统.md) §2.2）：编制损失超过溃逃线即**集体溃逃**——这是编制 AI 的决策，不是系统强制触发 | 伤亡 >40% 或 指挥官阵亡 |

### 3.2 玩家自定义自由度

- 人员组成可以**自由拖拽组合**——这班3个法师2个步兵，那班全是步兵
- 装备可以**从帝国库存中选择分配**（如果帝国物资不够，系统会提示缺货）
- 预设几个模板方便快速搭建，但随时可以拆零件重组

### 3.3 命名规则

- **军事/科研/工程组织**：层级名称可以自由修改（"这个师叫'大队'，下面的团叫'小队'"）
- **行政区划**：部分锁定，不能随便改（"甲市"不能改叫"甲哈基米"）

## 四、AI 行为与自动化

### 4.1 逐层指挥

每一层级的 AI 只能**直接指挥向下的一层**。它看不到下属的下属在干什么——只是下达任务，下属自己分解执行。

```
帝国统帅(L5) → 只告诉师长(L4)："拿下这个区域"
师长 → 只告诉团长(L3)："你的团攻这个方向"
团长 → 只告诉连长(L2)："你的连守住这个高地"
连长 → 只告诉排长(L1)："你的排从右边绕"
排长 → 具体指挥每个火柴人
```

**这意味着**：你想让帝国自动化运转起来——必须精密地设计每一层。层级设计得好，命令顺畅传达。层级设计得烂，上面下的命令传不到下面，或者下面自己乱搞。

### 4.2 信息上报

反向也一样——下层的问题向上汇报，每层自己判断什么需要上报、什么自己处理。自主决策权限越高，往上报的越少。

### 4.3 玩家干预

你随时可以"**接管**"到任意层级的指挥官：

- **操纵模式**：真的控制那个角色在战场上移动/战斗
- **管理面板模式**：打开该层级的管理面板，下达指令、调整编制
- 两种模式随时切换

当你接管到低层级微操时，高层级帝国继续运转（或自动暂停/减速——取决于你的设置）。

### 4.4 信息与物资的物理传递

指挥系统**有个人实体**，不是抽象的箭头连线：

- **命令靠信使真实跑动传递**——需要时间、可被截杀；部门首脑被刺杀后，该部门运转立刻受影响
- **物资靠载具一车一船真实移动**——不存在点击即达，工序之间的物料搬运同样占用真实编制
- **信息上报同样吃传递时间**——后方看到的报表永远是延迟快照，前线可能已经崩溃
- **战场指挥半径**——指挥官只能直接影响附近的单位，超范围依赖传令与编制自主（见 [`02-战斗系统.md`](02-战斗系统.md)）

### 4.5 军事组织的嵌合

军事组织不另起炉灶——它就是本系统的一个**标签实例**（§2.1）：同一套五层级（§一）、同一套逐层指挥（§4.1）与信息上报（§4.2）、同一套补位原则（§九）、同一物理传递（§4.4）。战争是主循环里的一环，组织平时就在运转（招兵、补给、上报、默认战术），**战场 = 运转的焦点视图**——把这套运转放到镜头前，而不是切出去另开一套规则。

| 组织原语 | 军事实例化 |
|----------|-----------|
| 层级树节点 / 编制配置（§三） | 班、排、火力组 |
| 逐层指挥任务式（§4.1） | 军师给意图、班长分解、士兵执行 |
| 补位原则（§九） | 军衔继任 |
| 命令 / 物资物理传递（§4.4） | 信使传令、补给线 |
| 信息上报（§4.2） | 战报 = 延迟快照 |
| 首脑被刺（§4.4） | 斩首 |

层级口径：火力组 / 班 / 排全在 L1 内（§1.1 最底层宽松）。

- **逐层指挥映射战场号令**：对军事组织根下令，命令沿树物理传播到 L1 小队执行——下令吃传播延迟、战报延迟快照、编制生成战场实体，军事指挥嵌在游戏循环里自然发生，没有独立的"战斗模式"开关。
- **编制生成战场实体**：L1 节点的编制配置投影为战场小队与成员——编制是账面，战场实体是投影；改编制即改战场。
- **默认战术 = 驻防**：无指令时军事组织按默认战术行动（§3.1），军事默认 = 驻防 / 巡逻。

号令类型、战场指挥半径、小队执行等战斗侧细节见 [`02-战斗系统.md`](02-战斗系统.md)；编制投影与传播链的技术契约见 [`../../技术/架构/组织系统架构.md`](../../技术/架构/组织系统架构.md)。

---

### 4.6 建造与组织自动化的三阶段（究极模拟目标）

- **前期**：建筑自动化程度很低——哪个工地分配多少人、不同分工各多少人，全靠玩家手动指派
- **中期**：像 RTS——玩家作为主管只需确定建筑位置，施工组织自动配人
- **后期**：城市级乃至地区级规划——玩家画大方向，下属各组织自己把细节补全（自适应扩建、改编）；**组织规模越大，自动化程度越高**

### 5.3 指令面板

**每个组织有自己的指令面板**——该组织专属的运行操作所在地：兵役制度（常备兵役/动员兵役）、载具选择、装卸规则（均匀分运/大宗优先——搬运次序的物理差异）、原料偏好、运行方式预设（§六）一类高级玩家操作全部收在各组织自己的指令面板里，不放全局设置。各组织的指令面板**结构各异**（常备军的指令面板与训练营的完全不同），实际游戏中是围绕该组织职能定制的复杂、精美界面；早期界面只承基础功能。

组织功能的相当大比例，就是让玩家指令面板的**数据可视化与控件数量增多**：各建筑/组织的面板数据由它们**自己的信息位**收集（本地实况，没有人在收集就看不到——上帝视角由组织劳动撑起）。市政厅的一站式总览不亲自产信息——它是把各处文书**运回汇总**的快照：情报组织的规模只影响总览的**更新效率**（需要真的有单位把文书拿回市政厅），不影响信息量。哪些面板置顶、哪些挂在主菜单，由玩家自己设置。

## 八、部门首席与头衔承认

### 8.1 首席面板

各部门的首席（首脑）集中显示在专门面板——谁掌哪个部门、能力如何、部门运转状态。**他国政权的部门首脑信息不直接可见**：由玩家派出的**情报组织**获取（通用组织系统的又一应用）——情报组织的编制与投入决定情报的覆盖面与新鲜度，情报本身也是一种需要传递的资源。

### 8.2 头衔需承认

从部落到大帝国，头衔跃升（部落首领 → 城主 → 国王 → 皇帝）不是自动升级，而是一次**承认检定**：

- **条件**：足够多已持有头衔者（政权/组织）的认可
- **时机**：检定需要特定时机——如一场多国会议，或战争胜利后的谈判（战胜方可在谈判中**强制**对方承认）
- **效果**：检定通过即完成头衔跃升，影响外交地位、可任命的编制层级上限与界面称谓（UI 不预设"帝国"字样）

## 九、边缘情况

- **指挥官死亡**：「现实中两个排一起去攻打一个地方，然后一个排长阵亡或者两个排长都阵亡了会发生什么和怎么办？」——按该组织的**补位原则**自动补位（如"班内军衔最高者顶上"，规则可配置；P0 军衔未建时以指挥属性代理排序）——补上的人就是真指挥官；无人可补时该节点挂起，下级越级请示或自主行动，上级也可越级直管
- **小档指挥口径**：火力组 / 班 / 排全在 L1 内（§1.1 最底层宽松）——每侧 ≤1 排时**排长即前敌指挥**（指挥链顶层，不另设指挥层）；有两个排则**两个排长都是指挥官**（后方各领一排）。一个排长阵亡只动该排（排内自补，另一排不受牵连）；两个都阵亡则两排各自自补，补不上者挂起——上级越级直管 / 下级自主，与补位原则同口径
- **机构重叠**：两个同层组织职责重叠 → 效率下降
- **过宽管理幅度**：一个指挥官管太多下级 → 每个下级获得关注减少
- **推翻重建**：大规模重组 → 过渡期混乱 [PLACEHOLDER] 天
- **组织解散**：所有人员回归待分配池

## 十、参数口径

组织系统是**纯机制系统，不带数值调优杆**——组织的能力来自"哪些槽位被什么激活"（§2.4），不来自隐藏数值加成。唯一的物理参数：

| 参数 | 说明 |
|------|------|
| 传令媒介速度 | 命令延迟 = 传播距离 ÷ 媒介速度——层级数不直接生延迟（层级深的树路径长、跳数多，延迟是涌现结果非公式惩罚；技术契约见组织系统架构文档） |

"过宽的管理幅度""机构重叠"这类问题是**机制后果**（下属被关注的频次下降、职责打架），不表现为百分比惩罚。

## 十一、招兵与人口（P0 占位）

> **【AI 提案/非设计定稿】**本章机制与数值（兵营招兵交互、消耗、人口上限）均为 P0 占位闭环的工程脚手架——兵营运作方式、资源单位体系、人口规则均未定稿。正式征兵设计待创始人给出后整章重写，届时代码侧 RecruitManager 同步改造；引用本章内容时一律不得当作已确认设定。

> P0 切片：兵源闭环的最小形态（核心循环 §7.1 断点 1/6 的修复）。完整的人事/征兵体系（征兵消耗、岗位匹配、指挥链）随组织系统后续批次演进。

### 征兵设计

**核心语义**：兵源是个难题，具体怎么征兵要有真实的过程。像**世界盒子**那样——征兵设施出来抽调；**征兵建筑就是征兵人员的办公室**：有切实的小人到处跑、和人交谈，花费若干秒才能征到一个，征到满名额为止。征兵建筑的具体人数和运行方式都可以调整。

- **征兵处 = 组织节点**：办公模块 + 几名征兵员编制——征兵组织就是通用组织系统的一个普通实例（§4.5：一套共通底层逻辑，"征兵"只是它的词表）。
- **兵源 = 未入编的待业村民**：待业池细则见 [`13-小镇生活与美术.md`](13-小镇生活与美术.md) §七，此处不重复。

**运行方式预设（首批三档，预设集随实装补全）**：

| 预设 | 运行方式 |
|------|----------|
| 街头征募队 | 征兵员满城走、和人交谈——若干秒征一人 |
| 办公室登记 | 待业者自己上门登记 |
| 战时征召 | 快，带士气代价 |

**组织方式与建筑关系（已定）**：

- **预设组织方式**：每种建筑若干个预设组织方式（可复用 §六 预设模板）——预设集内容与切换时机随实装调研补全；
- **建筑和功能不分离 = 组织接管建筑**：组织只要建筑具备它需要的模块就能接管实现（征兵处就是接管在具备办公模块建筑里的征兵组织，不是抽象开关）；组织可换址，建筑不与功能绑定。整体口径见 [`03-聚落与建筑.md`](03-聚落与建筑.md)：空建筑与功能建筑混排、功能后置挂载（模块+陈设+机构）、场所需求三类清单（结构/材质/构型）约束什么组织能接管什么建筑。

**力不从心 → 待办提醒**：到了一定规模，当前组织开始力不从心时，游戏弹窗待办提醒更换方案——像**缺氧**的待办那样；触发阈值随实装实测定（属校准不属设计开放）。其信息链路 = 组织信息上报（§4.2）的游戏化出口：组织自己把"管不过来了"报上来，待办替玩家盯着。
