## 一、架构基线（锁死项）

以下为已验证成立、**所有新代码必须遵守**的既有决策。总纲不重新论证，只声明效力：

1. **模块垂直切片**：新功能 = `modules/<模块名>/`，内按类型分二级目录；对外唯一入口 `api.gd`（信号 + Result 模式方法 `{"ok": false, "error": "..."}`）；禁止跨模块 `get_node` 或引用非 API 内部方法。
2. **EventBus 解耦**：跨模块异步通信用 `core/autoload/event_bus.gd` 信号；查询用同步 api 调用。跨模块信号不得形成循环。
3. **集中装配**：`modules/world/scripts/setup/system_setup.gd` 是 composition root——跨模块依赖汇聚于此，**这个集中制本身是决策**；越界的是它直接 preload 大量模块内部类（见 AR-1）。
4. **State 对象 + 集中容器**：运行时状态放 `core/entities/` 的 State 类；游戏数据注册进 WorldState 容器由其统一序列化（组织模块为范例：`set_world()` 注入 → 容器同步 → 存档走 WorldState 直写表）。
5. **场景是布局唯一真相源**：禁止 `Control.new()` 当 UI 根；全屏走 `UIKit.full_rect()`、角落 HUD 走 `widget()` + `UIRoot.add_to_slot()`。
6. **配置三轨**：静态平衡数值 = `.tres`（Excel 管线导出）；程序化产物 = 离线生成 bin/json（bin 优先）；运行时状态 = State 对象。禁止把配置堆进 project.godot。
7. **质量门**：`check_godot_errors.sh` 干净 + `tests/run_all.sh`（与 main 基线对照零回归）+ 中文提交 + 交接档回填。测试四层（unit/integration/smoke/dev）。

world_map。词汇本身是共享的，放在两个互环模块之一都必然成环 → 拆解见 AR-2。

## 三、目标架构（阶段 1 Alpha 终态）

### 3.1 四层结构

```
L3 组装层      world (GameRoot + system_setup 编排)          —— 唯一 composition root
L2 玩法层      combat / construction / organization / inventory /
               units / player_control / world_map / debug_gui
L1 基础设施层  ui_global / fx / texture_gen / building_gen / environment
L0 核心层      core/ (autoload 8 件套 + entities/ + ui_framework/)
共享词汇       core/ 中的静态契约类（AR-2 落地后承接 MapType 等）
```

规则：**只允许高层依赖低层**；同层互依须走 EventBus 或经 L3 注入；L1 内部 ui_global 为最底。
audit_deps.py 的豁免制延续（行内 `audit-exempt` 标记 + 理由注释）。

### 3.2 装配收敛：编排与实例化分离【提案/待定】

保持 system_setup 的**编排职责**（顺序、注入关系），下沉**实例化细节**到各模块：

- 每个被装配模块提供 `modules/<m>/setup.gd`：`static func assemble(root: Node, ctx: Dictionary) -> Dictionary`
  （返回本模块 api/关键节点引用，供后续模块注入）。模块内部类的 preload 全部收进模块自己的 setup.gd。
- system_setup 收缩为 ~30 个 assemble 调用 + 模块间注入的编排表；**不再出现 `res://modules/<m>/scripts/...` 深路径 preload**。
- **新模块必走新规**；存量 12 模块**随改随迁**——某模块首次大改时其
  装配代码顺手下沉（首个迁移模块兼立样板，建议挑装配面小的如 resources/organization 先行），不单独立大爆炸批次。
- **只读红线**：system_setup 的 preload 总数只降不升（CI 可用 audit_deps 守护）。

### 3.3 共享词汇下沉（拆环）【提案/待定】

`WorldAPI` 中的纯词汇（`MapType / TravelMode / EntrySide / PATH_*` 节点路径约定）迁至
`core/shared/map_contracts.gd`（静态常量类，零依赖）。world/api.gd 可临时 re-export 保持兼容，
消费方（world_map、game_root、siege 系列）随改随切。拆完 `audit_deps.py` 应报**零环**。

### 3.4 EventBus 信号生命周期

- 新信号立项时必须同时登记发射方与首个消费方（在 `系统交互与EventBus.md` 参数表）；**零消费超 30 天的信号进入清理候选**。
- `balance_changed` 类"预留信号"须在声明处注明预留目的与启用条件，不计入死信号。
- 上游消费方变更（如 chunk 流式加载实装）时同步复活或删除对应信号。

### 3.5 数据与存档定型

- 存档统一 SQLite `save_<slot>.db`（buildings 表 + world_state 表 + schema `user_version` 版本化迁移）；
  模块数据经 WorldState 容器直写表，**不再注册 SaveManager 模块接口**（组织模块范例）。
- 待补强（非本纲立项，随各任务带）：编队/编制存档、背包装备持久化、faction_id 读回——归属「出征与领地循环」与物品栏后续。

## 五、新模块/新面板接入规约（checklist）

1. `modules/<name>/` 建目录，二级按类型（scripts/ scenes/ ui/ data/）；根放 `api.gd`（信号 + Result 方法）。
2. 被 system_setup 装配 → 写 `setup.gd::assemble(root, ctx)`，模块内 preload 不外泄（§3.2 规约）。
3. 跨模块通信：异步 = EventBus 新信号（**同时登记参数表与首个消费方**）；同步 = 调对方 api.gd。
4. 运行时状态 = `core/entities/<x>_state.gd` + WorldState 容器注册（照 organization 范例）；存档走容器直写。
5. 配置进 `.tres`/Excel 管线；程序化产物走离线生成 + bin 优先装载。
6. UI：布局进 .tscn 或 UIKit 合规出口；主题只用 StickTokens/StickKit；图标走 StickIcons 注册表。
7. 自检：`bash stick-world/tools/check_godot_errors.sh` + `bash stick-world/tests/run_all.sh`（零回归）+
   `python tools/audit_deps.py`（无新环、无未豁免跨模块 preload）。
8. 文档：README 速查表 + 模块API契约.md 补章 +（涉信号时）EventBus 参数表；交接档回填 + 中文提交。
