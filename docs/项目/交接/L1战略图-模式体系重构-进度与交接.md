## 一、需求清单（创始人口决，逐条登记）

| # | 需求 | 现状 | 涉及 |
|---|---|---|---|
| 1 | **地形图模式分支关闭**：全部图都是地形图打底了，地形这个独立模式没有存在意义 | `MapModeManager.Mode.TERRAIN` 仍是独立模式 | `map_mode_manager` / 各渲染分支 |
| 2 | **交通 / 城市 / 资源 = 3 个开关**：不再是模式，是底图上的叠加层开关（可同时开） | 三者各自是模式（RESOURCE 独立模式；城市 blob 随地形/政治走） | 模式管理器 → 层开关状态机 |
| 3 | **物流与交通共用一个界面** | 物流（物流图模式）与交通分离 | 同上 + 物流渲染分支 |
| 4 | **跨 L1 地块道路显示**：现在只画本地块内部道路联通，跨到别的 L1 地块的路也要画 | 路网按包注入（roads 字段），跨包段缺失；全局路网数据 `roads_global.json` 已存在（数据流 §5.2 步骤 5） | 数据侧：包内 roads 扩到跨包段；渲染侧：画全段 |
| 5 | **道路连通度口径**：一般情况下周围有几个城市就有几条道路，除非被山脉切断 | `road_generate.py` 的生成策略未必全连通 | `l1/road_generate.py`（生成端） |
| 6 | **邻包城市重做**：别的 L1 地块城市还是旧观感 | P2 全量重烘覆盖（本批跑完即解决） | 水陆同源 P2 |
| 7 | **邻省完整信息**：周围其他 L1 地块也显示完整信息（地块+城市+政权色），政权图看起来更方便 | 邻包只画「邻块灰色/政权色暗一阶」一层 | 渲染端多包叠加（复用 `l1_packs/` 按需装载） |
| 8 | **层级切换按钮化**：别只能靠快捷键上下切层级，要屏幕按钮 | 只有快捷键 | UI_global 按钮族 + 战略图 HUD |
| 9 | **政权列表侧栏**：本地区的政权列表显示在旁边 | 图例只有全局政权色块 | 政权列表 UI（读 `l1_province_politics.json` / 当包 states） |

## 二、设计要点（开工前先定，写入设计文档后再动代码）

1. **模式体系目标形态**：底图（地形贴图）恒在；`政治染色`、`交通`、`城市`、`资源`、`物流`（并入交通界面）为**独立开关层**；`TERRAIN` 模式删除（底图即地形）。层级（L1/L2/L3）切换与层开关解耦。
2. **跨包道路数据口径**：`roads_global.json` 为单一真相，包内 `roads` 改为「本包段 + 跨包延伸段」或渲染端直接读全局路网按窗口裁剪——设计时定（倾向后者，包数据保持自包含显示段）。
3. **道路连通度**：road_generate 按邻接城市全连通生成，山体（坡度/水体排除）才断——重跑生成链步骤 5。
4. **邻省完整信息**：政权图下，邻包按需装载（同 L1 包体系 `l1_packs/`）画完整 tiles+blob；性能口径 = 只装载视野相邻包、分帧装配（参照现有 blob 分帧纪律）。
5. **开关持久化**：层开关状态进存档/会话（待设计定）。
