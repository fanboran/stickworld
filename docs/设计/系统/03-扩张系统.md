# 扩张系统

## 目的

让玩家体验从"在一小块区域里打拼"到"整个世界都在你视野里"的尺度扩张——参考《合战忍者村》和《史前埃及》。

## 玩家体验目标

- **逐步展开**：先统一小区域→该区域变成基地→地图扩大到更大范围
- **有代价的扩张**：每块地都有管理成本
- **两种手段**：军事征服、外交合并

---

## 一、扩张的阶段式地图展开

参考《合战忍者村》和《史前埃及》：

| 步骤 | 类似 | 说明 |
|------|------|------|
| **1. 村内扩张** | 合战忍者村统一村子 | 在一个小区域（村/部落范围）内占领地块、建造建筑。统一后该区域成为你的"基地" |
| **2. 地图扩大** | 合战忍者村→日本全国 | 原基地缩小为地图上的一个点，更大的区域（国家/大陆）展开 |
| **3. 再次扩大** | 史前埃及→全埃及 | 你统一的区域成为核心领土，地图继续扩大 |
| **4. 世界级** | — | 最终地图范围：整个已知世界 |

**关键**：每次地图扩大，你已控制的区域不会消失——它变成了更大尺度下的一个色块/图标。就像 Google Maps 缩小，你的城市从街道变成一个小点。

## 二、地块系统

### 2.1 地块属性

| 属性 | 说明 |
|------|------|
| 地形 | 平原/山地/森林/沙漠/沼泽/冰原 |
| 资源 | 矿产/黑色沥青等 |
| 人口 | 火柴人数量 + 种族构成 |
| 控制方 | 当前势力 |
| 控制度 | 100%（完全控制）→ 0% |

### 2.2 地块状态

| 状态 | 说明 |
|------|------|
| 完全控制 | 控制度 100%，正常产出 |
| 交战地块 | 控制度 <100%，持续消耗，无产出 |
| 附庸 | 名义独立，部分税收+军队 |
| 同盟 | 独立友好 |
| 中立 | 未接触 |
| 敌对 | 战争中 |

**防碎机制**：交战地块不会立即变色——必须完全控制（100%）后才纳入版图。

## 三、扩张方式

### 3.1 军事征服

宣战（需宣战理由或承受声望惩罚）→ 进攻 → 占领（控制度逐渐上升）→ 完全控制后吞并。

### 3.2 外交合并

附庸吞并、联邦统一。

---

## 四、扩张代价

地多了本身就有天然代价——国境线变长需要更多驻军、管理起来更复杂。这些不需要刻意设计为独立机制。

---

## 五、世界政权演化（碎 → 合）

开局世界政权**非常碎**——城邦、部落林立。随游戏推进，AI 政权通过征服与外交合并互相吞并，政权数量持续递减：从上百小政权 → 几十个 → 最后可能只剩两三个超级政权。

这塑造后期体验：

- **多线作战**：同时与多个政权交战，各前线都要稳定——驻军或谈判
- **管理体系脆弱性**：扩张中的管理体系受一点冲击（首脑被刺、补给被断、部门瘫痪）就可能溃散
- **非军事路线**：不费一兵一卒瓦解敌国（断补给、刺杀其首脑、挑拨其部门）乃至亲自当刺客，都是可行路线

**合并节奏不专门设计**：政权数量的递减是 AI 政权微观行为（征服、外交合并、吞并，见 §三）自然涌现的宏观结果——把微观规则调好，宏观演化自己跑出来。

## 六、P0 实装：出征与领地循环（创始人确认方向，参照《合战忍者村》）

> 本章是扩张系统在 P0 原型里的**可玩循环**设计——把"定居点建设 + 小队编制 + 小规模战斗"（GDD §十一第一个可玩原型）焊成一个闭环。技术架构见 [`../../技术/架构/出征与领地架构.md`](../../技术/架构/出征与领地架构.md)。

### 6.1 为什么是"出征"而不是"守家"

解包分析《忍者村物语》（com.kairogame.android.Ninja，`temp/hezhan_extract/extracted/` 有完整产物）确认其循环骨架：**村庄经营 → 部队编成 → 主动出征（行军有成本）→ 横版战斗 → 占领领地（解锁产出）→ 收益反哺村庄 → 敌人变强 → 循环，直到击败最终势力**。

主动出征是扩张的引擎：每场战斗都是玩家的选择（打哪块、带什么兵、值不值），战斗的产出回流经营。玩家被动挨打的"敌袭守城"是支线体验（§6.6），不是循环正轴。

### 6.2 循环图（P0）

```
村A 经营（已有）──→ 编队/号令（已有）──→ 出征：选择征伐目标（新）
                                                  │
                                                  ▼
战略图政治模式变色 ←── 占领：状态流转+奖励发放 ←── 抵达敌据点，守军战
（归属反馈，新）          （新）      ▲              （战斗引擎已有，收束新修）
      │                              │                      │
      │                              └── 敌将评估撤仗 ←──────┘
      ▼                                  （人机 AI，新）
回村 → 下一个目标 →……→ 全部据点臣服 → 通关结算（改写演示目标链）
```

### 6.3 领地（P0 形态）

| 设计点 | P0 方案 | 说明 |
|---|---|---|
| 领地实体 | **敌据点**（3 座起步，配置驱动可扩） | 每座据点 = 场景图一张 + 守军配置 + 奖励配置 + 战略图聚落关联 |
| 可见性 | 全部可见，**守军强度做软门槛** | 不做强制解锁顺序（合战忍者村的邻接展开属 P1） |
| 状态 | `HOSTILE（敌对）→ CAPTURED（臣服）` 两态 | 预留 `VASSAL/REVOLTING`（附庸/叛乱）等后期态 |
| 守军持久化 | **打死一个少一个**，允许车轮战 | 打不过就回村养兵再来——自然的难度曲线，也是合战忍者村的手感 |
| 占领后形态 | 守军清除、可自由进出、战略图聚落染玩家色 | 据点旗帜/装饰变化属润色 |

### 6.4 一场征伐的玩家体验

1. **选目标**：村A 城门出城选项列出敌据点（名称 + 守军规模情报 + 战利品预览）
2. **行军**：部队随玩家出发跨图（带队出征已有）
3. **接敌**：进据点后守军列阵，战斗开打（横版真实交战，非数值结算）
4. **胜负**：守军全灭，或**敌将判断"这仗不能打了"下令撤退**（敌将 AI 评估伤亡率/战损比，下令全军后撤离场）——两者都算攻陷
5. **战果**：占领通告 + 战利品入账（资源包 + 解锁）+ 战略图上这座聚落变成你的颜色
6. **败仗**：玩家部队全灭不判负——传回村A 重整，守军保留战损，卷土重来

### 6.5 奖励与解锁

- 每座据点配置：**资源包**（木/石/钱，入账现有资源系统）+ **解锁项**（建筑型号/武器型号，走解锁信号，各系统自听）
- 数值与解锁内容 Excel 配置（`config/excel/扩张数据.xlsx` 新增 `territories` sheet，与现有 regions/factions 同管线），首版数值为 AI 提案、待实测定稿
- 通关条件：全部据点 `CAPTURED` → 通关结算（占领数/用时/伤亡统计）

### 6.6 守城的定位（支线，非本循环）

现有守城 Demo（村A 城墙 + 城郊战场波次战）定位为**被反攻支线**：P1 起已占领据点可配置"反扑事件"触发守城战。守城资产（城墙/弓手/波次导演）全部保留复用，不在 P0 循环正轴上。

### 6.7 P0 明确不做（归 P1+）

- 邻接展开的领地解锁树（合战忍者村 `neighbors_` 式）
- 敌人成长（占领越多敌将增兵——合战忍者村 `UpdatePower`）
- 战略图上直接发起出征（P0 出征入口在城门，战略图只做归属显示）
- 外交合并/附庸（GDD §3.2，依赖组织系统深化）
