> [音乐设计文档.md](../../设计/音乐/音乐设计文档.md)；资产许可见

## 一、为什么要有管线（而不是"找个音源随手录一遍"）

游戏音乐和单曲的音乐在工程上不是一回事：它要**循环**、要**分层**、要**被音效压**、
要**在几十小时里反复听**。这些要求落到工程上就是若干硬约束（循环长度必须是整数
小节、所有层必须等长同循环点、响度要留 headroom、混响尾巴必须归位）。手工做一次
可以靠手感，做九首要靠流程——**流程的价值在于让"每次都做对"不依赖当天状态**。

具体地说，这条管线要解决的问题：

| 问题 | 解决办法 |
| --- | --- |
| 程序化作曲容易变成"随机但有调性"的噪声 | 主题手写、级数化、变奏复用（见设计文档 §三） |
| 合成钢琴"电子味" | 真实采样音源（Salamander Grand Piano V3）+ 三个真实细节层 |
| 循环点听到"断裂"或空间塌陷 | 渲染时多写尾巴，混音时把尾巴**折回开头** |
| 响度不统一、忽大忽小 | 总线增益分级 + 归一化到统一目标 LUFS |
| 听着累、刺耳 | 显式的刺耳度指标 + 中高频收敛的混音配方 |
| 层对不上、加起来破音 | 分轨离线渲染 + 统一母带链 + 自检脚本 |
| 素材版权不明 | 逐条登记来源与许可（含公有领域判定依据） |

## 二、管线全貌

```
 ┌ 作曲 ──────────── tools/music/compose/          主题 + 变奏（级数化谱面）
 │      common.py  THEME_A/B/C、和声进行、编曲助手
 │      cues.py    九首曲子的定义 + 分层/混音覆盖
 ↓
 ┌ 谱面 ──────────── tools/music/musiclib/score.py  Stem/Cue 数据结构 → 每轨一个 MIDI
 ↓
 ┌ 渲染 ──────────── tools/music/musiclib/render.py 分轨离线渲染成 WAV（干声）
 │      sfizz + Salamander SFZ   → 钢琴
 │      fluidsynth + GM SoundFont → 弦乐/竖琴/钟琴/木管/定音鼓…
 ↓
 ┌ 混音 ──────────── tools/music/musiclib/mix.py
 │      每轨：高通 → 搁架 EQ → 峰值 EQ → 轻压缩 → 卷积混响 → M/S 展宽
 │      总线：增益分级 → 胶合压缩 → 倾斜 EQ → 软饱和 → 归一 LUFS → 限制真峰值
 │      循环：把循环体之后的尾巴折回开头
 │  └─ musiclib/reverb.py  程序化合成脉冲响应（IR）
 │     musiclib/dsp.py     滤波器/压缩/限制/饱和/M/S
 ↓
 ┌ 导出 ──────────── tools/music/musiclib/export.py
 │      ffmpeg(libvorbis q=6) → OGG  •  music_manifest.json（循环点/分层/音量）
 ↓
 ┌ 质检 ──────────── tools/music/musiclib/loudness.py
 │      LUFS（BS.1770 双门限）/ 真峰值 / LRA / 刺耳度 / 接缝 / 单声道兼容
 ↓
   交付：stick-world/assets/audio/bgm/<cue>/<layer>.ogg + music_manifest.json
```

一键跑通：

```bash
python tools/music/setup_toolchain.py      # 一次性：拉渲染引擎与音源（约 490MB）
python tools/music/selftest.py             # 管线自检（DSP/响度/循环/导出）
python tools/music/render_all.py           # 全部曲目
python tools/music/render_all.py --only field_day     # 单首
python tools/music/render_all.py --skip-render        # 只重混音（改混音参数后用）
python tools/music/qa_audio.py             # 质检报告
```

> PATH 里的 `python` 可能是别的发行版（本机曾踩到 Inkscape 自带的解释器缺库）。

## 三、各环节的做法与理由

### 3.1 作曲：级数化谱面 + 手写主题

主题手写（`THEME_A/B/C`，见设计文档 §三），**不交给算法生成**。算法负责的是
"把这一条旋律正确地铺到九个场景里"：移调、换调式、选织体、配和声、分配到各层。

`musiclib/theory.py` 提供这套语法：

- **级数 → 和弦**：`roman_chord("D","major","IV") → G`。判定和弦性质用的是
  "调内自然和弦"（按音阶取 i/i+2/i+4 级音算出实际音程），而不是"vii 就一定是减"
  这类硬规则——后者在大调/小调/多利亚上会翻车。小调写大写 `V` 会得到和声小调的
  属和弦，大调写小写 `iv` 会得到下属小三，这是有意的"用大小写强制指定性质"。
- **声部连接**：`nearest_voicing()` 枚举全部转位，用"相对前一排列的逐声部移动量"
  打分取最优。这就是古典和声写作里"保持共同音、其余声部就近移动"的机械化表达，
  听感上表现为内声部平滑，不会出现整块和弦上下乱跳的业余感。
- **织体**：`arpeggio_8th()` 等音型函数，外加编曲助手 `add_piano_accompaniment()`
  / `add_pad()` / `add_bell_accents()` / `add_harp_figures()`。

### 3.2 渲染：分轨 + 双引擎 + 干声

**分轨是刻意的**：每个层一个 MIDI、一次渲染、一个 WAV。只有分轨才能对各层做
不同的 EQ 与混响（弦乐垫必须让出 2~6kHz 给钢琴），也才能在游戏里按强度开关某一层。

- **钢琴**：sfizz + Salamander Grand Piano V3 的**裁剪版 SFZ**。裁剪只裁 region 表
  （去掉用不到的音区与 v15/v16 两个最强力度层），**琴弦共鸣、制音器释放、踏板噪声
  三个细节层整份保留**——它们是"这台钢琴听起来像真钢琴"的重要来源。
  裁剪的原因是"原始 region 表引用了不存在的采样时，sfizz 是**静默丢音**"
  （某个音突然没有，极难排查），所以宁可生成一份只引用已下载采样的 region 表。
- **编制声部**：fluidsynth + GM SoundFont。
- **一律干声**（不加引擎混响/合唱）：空间感统一由混音阶段的一条卷积混响给出，
  避免"引擎混响 + 我们的混响"叠成两团。

### 3.3 混响：程序化合成脉冲响应

`musiclib/reverb.py` 用噪声合成 IR，而不是加载外部 IR 文件。理由：外部 IR 有版权，
而合成 IR 可复现（同 seed 同结果）、可进版本库、可 A/B 对比。

合成方法（音乐厅近似）：

1. 把白噪声按四个频段切开，每段给**自己的指数衰减**——真实空间里高频被空气与
   材料吸收，衰减比低频快，这是"自然"的核心；
2. 叠加**早期反射**点阵（左右错开时间以获得宽度），决定"房间多大、多近";
3. 给整体加一个 build-up（指数起振），避免"啪"地一下全响；
4. 左右声道用不同噪声（去相关），才有立体声宽度而不是居中一团。

两个必须做对的细节，都是自检抓出来的：

- **IR 长度要按"衰减最慢的频段"算**。按最快的频段算会把低频尾巴截断，
  耳朵听到的是不自然的骤然中断。
- **频谱要从白噪拉向粉噪**（`tilt_db_per_oct`，默认 -2.5dB/oct）。各频段用等方差
  噪声合成会得到白噪频谱——高频能量远大于真实房间，混响发"嘶"、发亮，
  这正是"刺耳"的元凶之一。真实空间的余响接近粉噪（-3dB/oct）。

### 3.4 混音：显式配方表

`musiclib/mix.py` 的 `STEM_RECIPES` 是每个声部的处理配方（高通/搁架/峰值 EQ/
压缩/混响发送/展宽/摆位）。**参数写死在表里而不是自动**：混音是审美决策，
"钢琴亮一点、弦乐垫必须让出中高频给旋律"这类判断无法由算法推出；写成显式配方
既保证可复现，也让"为什么这么调"留在代码里可查、可改。

几个有依据的取舍：

| 决策 | 理由 |
| --- | --- |
| 钢琴 8.8kHz 以上 -1.8dB | Salamander 是 Yamaha C5，偏亮；收敛高频保"柔和" |
| 钢琴 2.5kHz +1.0dB | 中频"存在感"区微凸，让旋律浮出来（而不是整体提亮） |
| 弦乐垫 145Hz 高通、6.5kHz -3dB | "宽而不厚"：低频让路、高频让给钢琴 |
| 钟琴 6.8k/9.1kHz 窄带 -2.4/-1.8dB | 点状音的共鸣峰会刺，必须窄带压掉 |
| 低频段单声道化（M/S） | 耳机上宽、音箱与单声道上依然稳；低频只留一条承重梁 |

**总线母带分两步增益**（`master_bus`）：先测一次响度把电平抬到比目标高 3dB
再进压缩链，处理完再精修到目标。压缩器、软饱和都是非线性环节，输入电平不同
结果就不同；分轨求和后的电平取决于这一首用了几个声部、多轻的力度，浮动很大。
不分级的话，"安静的小编制曲子"会被压得毫无反应，"大编制曲子"又被压死。

### 3.5 循环：尾巴折回

无缝循环最关键、也最容易被忽略的一步。

渲染时 MIDI 末尾留了 8 拍余量，让最后一个音的衰减与混响渲完。于是音频在循环
结束点之后还有一段"尾巴"。**如果直接截断，每次循环到结尾都会听到断裂与空间感
塌陷。** 正确做法是把 `[loop_end, ...)` 这段尾巴**加到** `[loop_start, ...)` 上——
上一遍的余音正好成了下一遍开头的铺垫，接缝在物理上就消失了
（`mix.wrap_loop_tail()`）。

配套约束：循环长度必须是**整数小节**（本项目统一 32 小节 = 128 拍），否则每次
循环相位漂移，几遍之后就完全错位。

### 3.6 导出：OGG + 清单

- **编码**用 imageio-ffmpeg 自带的 ffmpeg（`libvorbis -q:a 6`，约 190kbps），
  不用 soundfile：libsndfile 的 Vorbis 编码器不暴露质量参数，默认码率偏低
  （约 130kbps），对这种以钢琴弱奏细节为主的音乐不够用。
- **循环信息不进 OGG 文件**。Godot 的 `AudioStreamOggVorbis` 把循环点放在
  `loop_offset` / `beat_count` / `bpm` 上，且不读取内嵌元数据。所以循环信息统一
  写进 `music_manifest.json`，由代码在加载时赋值——单一真相源，避免"文件里的信息"
  与"代码里的信息"两处不一致。

### 3.7 质检：能算的都算

`musiclib/loudness.py` 实现全部客观指标（口径见 [音乐质检规范.md](音乐质检规范.md)）：
BS.1770 积分响度（K 加权双二阶 + 400ms/75% 重叠分块 + 绝对/相对双门限）、
4× 过采样真峰值、EBU Tech 3342 的 LRA、STFT 频段能量比/谱质心/谱平坦度构成的
刺耳度评分、循环接缝跳变、单声道兼容性。

实现上有两处必须小心，都被自检脚本抓到过：

- **积分响度的 z 是各声道均方值按权重"求和"，不是求平均**。用平均会让立体声
  少算 3 LU——只测单声道信号时完全看不出来，必须用"双声道应比单声道大 3 LU"
  和"与独立实现交叉验证"两条一起验。
- **接缝指标要按整段节目电平归一化**，不能用局部窗口 RMS。循环结尾如果是自然
  衰减到静音（这是好写法），局部窗口也接近零，用它做分母会让指标失去意义。

## 五、扩展方式

### 加一首新曲

1. 在 `compose/cues.py` 写一个 `build_<cue_id>()`，放进 `BUILDERS`；
2. 若要新的声部名，在 `musiclib/mix.py` 的 `STEM_RECIPES` 加一条配方，
   在 `musiclib/export.py` 的 `cue_tier_map()` / `TIER_DEFAULT_DB` 登记分层；
3. `python tools/music/render_all.py --only <cue_id>`。

### 调混音

改 `STEM_RECIPES` 里对应声部的参数，然后 `--skip-render` 重跑（复用已渲染的分轨，
省掉几十分钟的采样渲染）。

### 换音源

- 钢琴：改 `render.piano_sfz()` 指向的 SFZ；或改 `setup_toolchain.py` 的下载源。
- 编制：把任何 `.sf2/.sf3` 放进 `temp/music_toolchain/soundfonts/`，或设
  环境变量 `MUSIC_SOUNDFONT` 指向它。

## 六、已知限制

- **音乐好不好听无法量化**。管线保证的是"没有做坏"（响度、接缝、刺耳度、
  单声道），"是否动人"只能靠人听。质检报告里的刺耳度是**相对排序**工具，
  不是"优美的度量"。
- **刺耳度评分的权重是经验值**，标定基线见质检规范；首次成曲后应按实测重新标定。
- 环境音层与音乐的**侧链闪避**目前未在离线管线里做（战斗音效压低音乐的 ducking
  在引擎侧实现）。
- 天气只换环境音、不换音乐；"无旋律变奏交替播放"（抗疲劳）尚未实现，
  两者都在设计文档 §八 标为提案/待定。
