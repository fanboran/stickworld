# 音效触发改动清单

> 本文是 [音效触发规范.md](音效触发规范.md) 的**可执行落地版**。每条都能照着改。
> 规范讲"为什么"，本文只讲"改哪里、改成什么、风险是什么、怎么算改好了"。
>
> **分级**：
> - **A 一行级**：改一行/一个常量/表里一项，不动逻辑（可当天做完）
> - **B 局部级**：改一个函数体（≤30 行），不引新机制
> - **C 机制级**：新表/新参数/新节点/新总线效果器（需设计与自测）
>
> 所有 `文件:行` 为 2026-09-13 本 worktree 实测行号。**改动前先重跑 `grep` 核对行号**
> （音效资产正被并行改造，行号可能已漂移）。
>
> **并行冲突提示**：本清单的代码改动集中在 `core/services/audio_manager.gd`、
> `modules/units/scripts/entity/weapon_mount.gd`、`modules/units/scripts/stickman_entity.gd`；
> 资产侧（`assets/audio/sfx/*.wav`）不在本清单范围内，由音效资产批次负责（见 §五 协作边界）。

## 二、A 级（一行级，立刻可做）

### A1 补 `unit_hurt_a/b/c.wav`

- **位置**：`core/services/audio_manager.gd:307-311`（表）／`assets/audio/sfx/`（资产）
- **现状**：表引用了 `unit_hurt_a.wav` / `_b` / `_c`，**三个文件都不存在**。`play_event` 对"变体池全部缺失"走 `print_verbose` 静默返回（`audio_manager.gd:339-341`）→ 事件永不发声，且无任何报错。
- **改成**：由资产批次生成这三个文件（或改表指向新的命名），保持"3 变体 + 数组"形态不变。
- **为什么**：这是唯一一处"代码对、资产缺"的缺口。修完 `stickman_entity.gd:1389` 的调用点立刻生效，零代码改动。
- **风险**：低。**注意**若 S2 换了文件名，改表时**不要删掉数组**（数组 = 变体池随机，是抗机械感的第一手段）。
- **验收**：`ls stick-world/assets/audio/sfx/unit_hurt*` 有 3 个文件；跑一次战斗能听到受击音；`SFX_EVENTS` 里不存在"任一键的全部变体都缺失"的情况。

### A2 `bird_chirp` 三键合一

- **位置**：`audio_manager.gd:313-315`（表）、`modules/world/scripts/map/sky_birds.gd:75-77`、`modules/ui_global/scripts/menus/menu_birds.gd:29`、`:73`
- **现状**：三个事件键 `bird_chirp_a/b/c` 各指一个文件，调用点自己 `randi() % 3` 选变体。`play_event` 的抗叠靠"同名事件停旧实例"（`:343-345`）→ 三个键 = 三个独立槽位 → **鸟叫可同时叠 3 路**，抗叠机制完全失效。
- **改成**：
  ```gdscript
  # audio_manager.gd 表内
  "bird_chirp": ["res://assets/audio/sfx/bird_chirp_a.wav",
                 "res://assets/audio/sfx/bird_chirp_b.wav",
                 "res://assets/audio/sfx/bird_chirp_c.wav"],
  ```
  三个调用点统一为 `AudioManager.play_event("bird_chirp")`。
- **为什么**：变体抽取是 `play_event` 的职责（表驱动），不是调用点的；拆键同时破坏了去重。一行表 + 三行调用点。
- **风险**：低（听感等价，只是不再叠）。
- **验收**：`grep -rn "bird_chirp_a\|_b\"\|_c\"" --include="*.gd" stick-world/` 不再有事件名拼接。

### A3 `harvest_gain` 发声上移（玩家专属）

- **位置**：删 `modules/world/scripts/map/resource_node.gd:291`；在 `modules/units/scripts/entity/interaction_controller.gd:90-92` 之后补一行。
- **现状**：`resource_node.harvest()` 是**模型方法**，玩家手采（`interaction_controller.gd:90`）与 NPC 自动劳作（`modules/units/scripts/ai/behavior_harvest.gd:248`）共用它 → **NPC 伐木/采矿也在放"玩家入账"的奖励音**，城镇里会一直叮咚。
- **改成**：`gain`（入账/微奖励）是玩家反馈，上移到玩家控制器；`harvest_hit` / `harvest_wood`（材质敲击）保留在模型层（它是"世界里的敲击声"，NPC 劳作该有），但随 #10 空间化 + #2 节流一起受控。
- **为什么**：区分"世界的声音"与"给玩家的反馈"。规范 §四明确禁止在模型层发"反馈类"音效。
- **风险**：低。上限风险是"NPC 劳作变安静"——但那部分由 `harvest_hit/wood` 保留，只是少了入账音，正是想要的。
- **验收**：开局观察 NPC 伐木 30s，不出现 `harvest_gain` 音；玩家按 F 采集仍能听到完整三段。

### A4 `demo_quest` 借用战斗结算音改键

- **位置**：`modules/world/scripts/setup/demo_quest.gd:281`、`:422`
- **现状**：两处（征服通关、Demo 目标全达成）都调 `play_event("battle_ended_win")` —— 2.84s 的 fanfare。若与真正的 `battle_ended`（`audio_manager.gd:362-363`）在 3 秒内先后发生，`play_event` 会把前一个**掐断**。
- **改成**：新增事件键 `victory_fanfare`（资产可由资产批次产出或先用 `quest_done` 垫），两处改键。
- **为什么**：一个事件名只承载一种语义；长音共用 = 互相掐断。
- **风险**：低。若暂无新资产，临时指向 `quest_done` 也比掐断 2.84s 长音好。
- **验收**：连打一场战斗并在 3 秒内触发通关结算，两声都完整。

## 三、B 级（局部改动）

### B1 `weapon_mount` 的 Sound 事件白名单放宽（本清单收益/代价比最高的一条）

- **位置**：`modules/units/scripts/entity/weapon_mount.gd:349-357`
- **现状**：
  ```gdscript
  func _on_rig_anim_event(anim_name: String, event_name: String, value: String) -> void:
      if anim_name != _attack_anim_name():
          return                       # ← 一刀切：非攻击动画的一切事件都丢
      weapon_anim_event.emit(anim_name, event_name, value)
      match event_name:
          "Hit":   _try_strike_frame()
          "Sound": _play_event_sfx(value)
  ```
  后果（**实测**）：`Sound` 声明在非攻击动画上的全部失效——
  - `dead.tres`(`[[1.9,"Thump"]]`)、`dead_v2.tres`、`dead_headshot*.tres`(`"fall"`) → **死亡音效（`bodyfall_a/b/c`、`thump_a/b`）从不播放**；
  - `idle_spear_v2/v3.tres`(`[[0.5667,"clang"]]`) → **盾/矛格挡金属声（`clang_a/b`）从不播放**。
  合计 **7 个 wav（全包 21%）在运行时永久静音**。
- **改成**：白名单只约束 `Hit`（命中帧结算**确实**只属于攻击动画），`Sound` 不做动画名过滤——动画作者在某一刻写了 Sound，就该在那一刻响：
  ```gdscript
  match event_name:
      "Hit":
          if anim_name != _attack_anim_name():
              return
          _try_strike_frame()
      "Sound":
          _play_event_sfx(value)       # 动画元数据本身即白名单
  ```
- **为什么**：`Sound` 的"何时该响"已经写在动画的 `anim_events` 元数据里（由 `tools/baking/spine_import.gd` 从 Spine 导出）——**引擎侧再拿动画名裁一刀，就是把数据侧的真相源覆盖掉**。这是本项目"命中帧事件驱动"设计的延伸，不是新增机制。
- **风险**：中。①解除过滤后，单位死亡会同时有"痛叫（实体级 `unit_hurt`）+ 倒地（动画级 `fall`）"，这是**想要的**，但声部数上升 → **强烈建议先做 #2（C1）**，否则死亡瞬间可能叠 2~3 声。②`clang` 在 `idle_spear_v2/v3`（站姿）里，会变成"站着偶尔叮一下"，需听感确认是否喧闹；若过密，正确做法是**在动画数据侧删掉那条 Sound**（画蛇添足的数据），而不是恢复引擎侧过滤。
- **验收**：打一场战斗（附身单位即可），能听到倒地声；`grep -c "sound_events" attack_*.tres` 里有 Sound 的动画播放时都有声。

### B2 建造过程中（敲击）补音效

- **位置**：`modules/units/scripts/entity/interaction_controller.gd:49-59`（`project` 分支）
- **现状**：敲一下加进度 + 播 `build` 动画 + 设 1.8s 动作锁，**零音效**；玩家连敲 8 下，只在最后听到 `build_complete`（`system_setup.gd:224`）。
- **改成**：与 `_try_harvest_resource_node` 同款，`_entity.set_player_build_timer(1.8)` 前后加一次材质敲击音（先复用 `harvest_hit` 变体池；S2 之后可换成专门的 `build_hit`）。
- **为什么**：长动作（>1s）必须有"过程反馈"。参照物就在同一个类里——采集有、建造没有，这不一致。
- **风险**：低。要注意**不要与 `harvest_hit` 共用事件键**（否则玩家同时采集+建造时互相掐断）→ 建 `build_hit` 键（可先指向同一批 wav）。
- **验收**：按住 F 建一座建筑，每 1.8s 一拍能听到敲击，且 8 拍之间不互相掐断耳朵。

### B3 招兵音 + 操作被拒音

- **位置**：`modules/units/scripts/entity/interaction_controller.gd:66-70`（招兵，零音效）；被拒路径（`_try_harvest_resource_node:91-92` 的 `gained <= 0` 直接 return，无反馈）
- **现状**：花资源招兵无任何听觉确认；采不到（枯竭/超距）也无反馈。
- **改成**：招兵 → `play_event("ui_confirm")`（**资产已存在，当前全仓库无调用点**，见规范 §10.4）；被拒 → 新增 `ui_denied`（短、干、非乐音）。
- **为什么**：负反馈是 UI 音效里收益第二高的项（第一是 click）。`ui_confirm` 是"接线漏了"而非"没用"。
- **风险**：低。`ui_denied` 需要新资产（S2）；在资产到位前，招兵音可以先做。
- **验收**：`grep -rn "ui_confirm" --include="*.gd" stick-world/` 至少 1 个调用点；招兵/采空有明确听觉差异。

### B4 暂停态处置 SFX 与天气（**先实测再改**）

- **位置**：`core/services/audio_manager.gd:186-206`（SFX）／`:219-241`（天气）；暂停源 `core/autoload/time_manager.gd:73`（`get_tree().paused = true`）
- **现状**：`MusicDirector` 明确声明"暂停不中断音乐，只压 9dB"（`music_director.gd:30-31,93`）；但**没有任何代码处置 SFX 播放器与天气播放器**。`weather.gd:44` 的注释假设"本节点随地图 PAUSABLE，雨滴/天气机一并停"——该假设对**音频节点不成立**：`_weather_player` 挂在 autoload `AudioManager` 下，`weather.gd` 停止 `_process` 只是不再刷新音量，**已经播放的雨 loop 会继续响**。
- **改成**（两步）：
  1. **先实测**：写一个 dev 探针，`pause()` 后检查 `AudioManager` 的 `_weather_player.playing` / 任一 SFX 是否仍在响（Godot 4 中 `AudioStreamPlayer` 是否随 `SceneTree.paused` 自动暂停，本地文档未给出明确结论，必须实测）。
  2. 按实测结果处置：若仍在响，则在 `AudioManager` 订阅 `EventBus.game_paused/game_resumed`，对 `_weather_player` 与在播 SFX 设 `stream_paused`（**不要 stop**，恢复时接得上）。附带修 `music_director.gd:183-187` 与 `:256-266` 的压限覆盖问题（见 C1'）。
- **为什么**："暂停时世界停住但雨声继续"是很明显的破绽，而当前的实现是**默认它不会发生**（未验证的假设）。
- **风险**：中。`stream_paused` 的实现路径对 `AudioStreamPlayer2D` 是否同样有效需一并验证；若实测发现引擎已自动暂停，则本条**只需删掉过期注释**（零改动）。
- **验收**：暂停后静音（或按设计只留音乐），雨天暂停/恢复无爆音、无残留。

### B5 `attack_bow` / `attack_pickaxe` 补 `Sound` 事件

- **位置**：`modules/units/animations/attack_bow.tres`、`attack_pickaxe.tres`（`metadata/sound_events = []`，**实测为空**）
- **现状**：弓手与矿工/建筑工的攻击动画**没有任何 Sound 事件**（不是被过滤，是数据里就没有）→ 这两类单位的挥击完全无声。
- **改成**：在动画元数据里补 `sound_events`（弓 = 弦振/放弦，镐 = 石/木材质音）。**注意**这是数据侧改动（`anim_events` 由 `spine_import.gd` 从 Spine JSON 导出），需确认是重导还是手改 `.tres` 元数据更稳（后者会在下次重导时丢失）。
- **为什么**：矿工挥镐是"看着世界运转"里最高频的画面之一；弓是天平倾斜的关键兵种。
- **风险**：中（重导会覆盖手改）。**必须在同一处记录改法**，否则下次重导静默丢失。
- **验收**：附身一个弓手/矿工（或临时把一个近战单位改成弓），能听到挥击声。

## 四、C 级（机制级）

### C1 `SFX_POLICY` 表 + `play_event` 内建节流 / 同帧合并 / 声部预算

- **位置**：`core/services/audio_manager.gd`（`play_event` 族，`:328-350`），新增 `SFX_POLICY` 常量与一个 30ms 累加器
- **现状**：唯一策略是"同事件重触发先停旧实例"（`:343-345`）+ 全局 ±5% 抖动（`:322`）。
  - 对高频事件（`unit_hurt` 每次受击都调，`stickman_entity.gd:1389`）→ 每 30~50ms 一次 stop+restart，听感是**机关枪顿挫**而不是"一群人在受伤"；
  - 对 `harvest_hit/wood` 的 3 变体池 → 密集采集时变体池形同虚设（每次都被前一个掐断）；
  - 对绕过者（`weapon_mount`）→ 策略完全不生效。
- **改成**：按规范 §6.2/§6.3 落地——
  1. 新增 `SFX_POLICY`（与 `SFX_EVENTS` 并列，同一真相源），字段 `prio / min_ms / merge_slots / jitter / spatial`；
  2. 事件级最小间隔（`Time.get_ticks_msec()` 记账，未到即丢弃）；
  3. 30ms 窗口同帧合并：`N` 次请求 → `min(merge_slots, ...)` 路，每路增益按规范 §6.3 公式；`N > 6` 时两路间插 20~35ms 随机延迟；
  4. 全局声部预算 `MAX_VOICES`（【提案】24），超限按 `prio` 抢占最低者；
  5. `AudioManager.process_mode = PROCESS_MODE_ALWAYS`，累加器用 `Timer/Tween` 的 `*_PAUSE_PROCESS` 语义（与 `MusicDirector` 同款纪律），避免暂停时窗口卡死。
- **为什么**：这是**唯一能同时看到三条入口的地方**（规范 §二）。写在这里，加音效依旧不用改调用点（表驱动），收益是全局的。
- **风险**：中。①窗口累加引入了"最多 30ms 的触发延迟"——**UI 事件必须走直通路径**（`prio ≥ 10` 不经窗口，直接播），否则点击手感可感知地"发闷"；②`min_ms` 值需听感标定（表里默认值全是【提案】）；③与 `weapon_mount` 收口（#6）必须同批做，否则只治一半。
- **验收**：（无声音的单元测试，仿 `tests/integration/test_music_director.gd` 的 `set_enabled(false)` 思路，注入假播放器）同帧 50 次 `play_event("unit_hurt")` → 实际播放 ≤2 次、总增益 ≤+2dB；跨 500ms 均匀 50 次 → 触发次数 ≈ 500/`min_ms`。

### C1' 音乐压限改具名请求集（修"战斗+暂停只压 6dB"）

- **位置**：`core/services/audio_manager.gd:45`（`_music_duck_db` 单标量）、`:125-141`（`set_music_duck_db`）；请求方 `core/services/music_director.gd:441-448`（`duck`）、`:183-187`（战斗档 `-6`）、`:256-266`（暂停档 `-9`／恢复）
- **现状**（**实测**）：所有压限请求写同一个标量，"最后写赢"。
  autoload 连接顺序（`project.godot:24-31`：`TimeManager` 先于 `MusicDirector`）导致 `battle_started` 时：`TimeManager.pause()`（`time_manager.gd:50-56`）→ `game_paused` → `duck(-9)`；紧接着 `MusicDirector._on_battle_started` → `_apply_context` → `duck(-6)` → **净结果 -6dB**。即**"战斗中暂停"没有拿到暂停档的 9dB**。
- **改成**：`_music_duck_db` 换成具名请求集合：
  ```gdscript
  var _duck_requests: Dictionary = {}        # source: StringName -> db
  func request_music_duck(source: StringName, db: float, fade_s := 0.0) -> void
  func release_music_duck(source: StringName, fade_s := 0.0) -> void
  func _effective_duck() -> float            # = minf(values)（相加深者胜）
  ```
  `MusicDirector.duck/unduck` 保留为兼容入口（转发 `source = &"music_director"`）。`_apply_volumes_to_buses()`（`:109-112`）改取 `_effective_duck()`。
- **为什么**：单标量无法表达多个独立请求，现在**已经**错了（不算将来的第三个请求方）。改成集合后，C2 的"音效密集压音乐"才有位置可写。
- **风险**：低。3 个调用点语义不变；唯一行为变化是"暂停中的战斗"从 -6 变 -9（**这就是修 bug**），需听感确认 -9 在战斗中是否过轻。
- **验收**：`test_music_director.gd` 现有压限断言（`:257` 附近）需同步为"请求-合并"语义；新增一条断言：同时请求 `-9` 与 `-6` → 生效值 = `-9`。

### C2 武器音效收口到 `play_event`（消除第二真相源）

- **位置**：`modules/units/scripts/entity/weapon_mount.gd:369`（`SFX_PITCH_JITTER`）、`:371-388`（`_play_event_sfx`，`:386` 直接 `am.play_sfx()`）
- **现状**：动画 Sound 事件绕过 `play_event` 直调 `play_sfx` → **无去重、无节流、无优先级、无合并，且自带第二份 `PITCH_JITTER = 0.05`**（与 `audio_manager.gd:322` 重复）。
- **改成**：`SFX_PATHS` 的 6 个键并入 `SFX_EVENTS`（键名如 `weapon_swoosh`/`weapon_thump`/`weapon_clang`/`weapon_fall`/`weapon_headbutt`/`weapon_blast`），`_play_event_sfx` 改为一行 `AudioManager.play_event("weapon_" + name, position)`；删除本地 `SFX_PITCH_JITTER`。
- **为什么**：规范 §六.4 —— 有绕过者则合并策略形同虚设。收口后，`weapon_*` 自动获得节流、同帧合并、声部预算与空间化。
- **风险**：中。①`weapon_mount` 属 L2 玩法层，`AudioManager` 是 L0/L1 —— 经 autoload 调用**不引入新的模块依赖**（现有的 `get_node_or_null("/root/AudioManager")` 已经是这个方向，改成直接 `AudioManager` 更干净，但注意 `weapon_mount.gd:376` 用的是字符串查找，改时统一口径）；②键名迁移要一次到位，避免两表并存。
- **验收**：`grep -rn "play_sfx(" --include="*.gd" stick-world/modules/` 为空（除测试）。

### C3 空间化（`AudioStreamPlayer2D`）

- **位置**：`core/services/audio_manager.gd:186-206`（播放器工厂）、`:328-350`（`play_event` 签名）
- **现状**：**全项目 0 个 `AudioStreamPlayer2D`**（实测 grep 无命中）→ 屏外 40 人混战与耳边采集等响。
- **改成**（三步，**第一步不写业务代码**）：
  1. **最小验证**（半天）：做一个 dev 场景，放 `Camera2D` + 三个 `AudioStreamPlayer2D`，循环播一个 `harvest_hit`，在屏内/屏外移动，确认①有没有声②距离衰减方向对不对③是否需要显式 `Listener2D`（grep 现状：**场景内无 `Listener2D`**，Godot 4 是否由 `Camera2D` 自动充当**必须实测**）。
  2. `play_event(name, world_pos := Vector2.ZERO)` 增参；`SFX_POLICY.spatial == true` 的事件走 `AudioStreamPlayer2D`（`max_distance ≈ 900~1200px`、`attenuation ≈ 1.5`、`panning_strength = 1.0`，【提案/待定】）。
  3. **宿主**：`AudioManager` 是 `Node`（非 `Node2D`），`AudioStreamPlayer2D` 挂它下面会触发引擎告警 → 由世界侧注册宿主 `AudioManager.set_sfx_host(node)`（`modules/world` 在地图 load 时调用，unload 时清空）。
- **为什么**：收益不只是"更好听"——**定位衰减会自动消掉屏外叠音**，是 C1 合并策略的廉价前置解（规范 §8.4）。
- **风险**：中高。①无监听器会导致"声音位置不对或听不见"（必须先验证）；②宿主在场景切换时会被释放，需处理悬空引用；③**所有做空间化的音效必须是单声道资产**——现状 33 个 wav 里 **16 个是立体声**（实测），立体声明暗会削弱 pan，需资产侧配合（S2 顺手改 mono，成本≈0）。
- **验收**：把镜头拉到战场一端，另一端的受击声明显轻/听不见；同一屏内左右两侧的音源有可辨的左右定位。

### C4（可选替代 C3+#15）战斗氛围层：用小兵代理的"出声"换"人群声场"

- **位置**：新增（`AudioManager` 或 `music_director` 的环境层机制可复用）；驱动源 `modules/combat/scripts/battle/battle_instance.gd` 的接战单位数
- **现状**：战斗中非附身单位走小兵渲染代理（`battle_instance.gd:146-149` 注册所有非附身单位；`crowd_renderer.gd:679-684` 的 `_on_rig_play` **只改渲染状态，不发任何事件**）→ 代理档单位的动画 Sound 事件**根本不触发**，所以大战场只剩 `unit_hurt` 一个声部。
- **改成**（二选一）：
  - **贵的**：让小兵代理档也派发 `Sound` 事件（改 `crowd_renderer._on_rig_play` 或新增一条"每拍按攻击节拍调度"的轻量通道）——**风险高**（碰 crowd/sim 热路径，性能与正确性都要重测），建议单独立项；
  - **便宜的（推荐先做）**：按**接战单位数**驱动一条"战斗氛围层"（金属撞击/甲片/低语群的短 loop，随 `_units_attacker.size() + _units_defender.size()` 分档调音量，4s 淡化，复用 `MusicDirector` 环境层那套写法 `music_director.gd:392-419`）。**用"声场"代替"逐单位发声"**。
- **为什么**：玩家感知的是"那里有很多人在打"，不是"第 37 号单位挥了剑"。逐单位发声既贵又必然变成噪声墙；氛围层是行业里表达人群的标准做法。
- **风险**：中（新资产 + 一条新的自适应层，需观感验收）。与 C3 空间化有协同（氛围层也可做 2D 定位，跟随战场质心）。
- **验收**：单位数 40 的战场能听出"规模感"，且不出现噪声墙（对比方式：关掉氛围层，确认差异）。

## 六、不要做的事（反模式）

1. **不要在调用点各自写节流**。调用点应保持哑巴（只报"谁/在哪/发生了什么"），策略集中在 `AudioManager`。现有 `stickman_entity.gd:1389` 式"哪里需要哪里响"正是要收敛的对象。
2. **不要用"加大全局 `PITCH_JITTER`"治叠音**。抖动治的是"机械重复感"，治不了"同时响 50 个"。两者是不同的问题。
3. **不要给 UI 音效加随机延迟**。延迟直接变成手感劣化；UI 用 `min_ms` 丢弃，不用延迟排队。
4. **不要靠"停旧实例"治高频音**（`audio_manager.gd:343-345`）。它在高频下=机关枪，会把变体池也一并废掉。正确做法是合并（C1）。
5. **不要对 hover/click 压音乐**。高频压限会让 BGM 持续"喘息"，暴露抽吸感且听觉疲劳。
6. **不要在模型层发反馈类音效**（`resource_node.harvest()` 的 `harvest_gain` 就是反例）。模型层只发"世界的声音"，反馈音上移到控制器。
7. **不要为补音效而放宽"命中帧由动画事件驱动"**这条既有纪律。本项目现在最正确的音频设计就是命中帧事件（`weapon_mount.gd:349-357`）；B1 放宽的是 `Sound` 的过滤，不是 `Hit` 的时机。
8. **不要在没有实测 `Listener2D` 行为之前铺开空间化**（C3 第一步不能跳）。
   —— 已实测完毕：**只要场景里有 `Camera2D` 就有距离衰减，不需要 `Listener2D`**；
   但有个规范没预料到的坑：**监听点是"屏幕中心"，不是相机节点**，所以半径必须随缩放走。
   证据与距离扫描见 [音效触发规范.md](音效触发规范.md) §12.3 与探针 `tests/dev/audio_2d_probe.tscn`。

9. **不要假设"暂停会顺带停音频"**。实测（`tests/dev/audio_pause_probe.tscn`）：`SceneTree.paused`
   期间播放位置照常推进（INHERIT 与 ALWAYS 无差别）→ 必须显式 `stream_paused`。
