## 六、阶段 C：资源系统接入（P0-9）

### C.1 任务 C1：GameRoot 装配 `ResourcesApi`

**背景**：`modules/resources/api.gd` 和 `resource_manager.gd` 已实现，但 GameRoot 未装配，导致 P0 完整循环（GDD 核心循环第 5 层"资源层"）未跑通。

**`resources/api.gd` 的 setup 签名**：`func setup(resource_manager: ResourceManager) -> void`。`resource_manager.gd` 是 RefCounted，直接 `new()` 即可。

**改动文件**：`stick-world/modules/world/scripts/game_root.gd`

**具体改动**（4 处修改 `game_root.gd`）：

1. **const 区**追加 `_ResourcesManagerScript` 和 `_ResourcesApiScript` 两个 preload
2. **字段区**追加 `var _resources_api: Node = null`
3. **`_ready()`** 中在 `_setup_combat_system()` 之后插入 `_setup_resources_system()`
4. **新增两个函数**：`_setup_resources_system()` 和 `_setup_resources_api_deferred()`，遵循与 Combat 一致的装配模式；新增 `get_resources_api()` 供测试用

**注意**：
- `ResourceManager` 是 RefCounted，`new()` 后由 api.gd 持有引用，不会被 GC
- `add_child(api)` 后 api 的 `_ready` 触发，`call_deferred` 确保 setup 在 _ready 之后
- 不在本任务初始化初始库存（初始库存来源属 P1 设计）

### C.2 任务 C2：建造系统扣减资源

**背景**：ConstructionManager 当前不检查资源，P0-9 完整循环需要"建造前检查资源 + 建造后扣减"。

**`construction_manager.gd` 当前硬编码位置**：line 112-114 硬编码 `var width: int = 2`、`var total_work: float = 10.0`。

**`buildings.tres` 中 bld_workshop 的建造费用**（A1 改动后）：`"build_cost_wood": 120, "build_cost_stone": 60, "build_cost_metal": 20`。

**改动文件**：
- `stick-world/modules/construction/scripts/construction_manager.gd`
- `stick-world/modules/world/scripts/game_root.gd`（注入引用）

**具体改动**（3 处修改 `construction_manager.gd` + 1 处修改 `game_root.gd`）：

1. **ConstructionManager 顶部**新增字段 `var _resources_api: Node = null` + setter `set_resources_api(api)`
2. **`start_construction_at()`** 中在 scene registry 校验之后、创建项目之前，加资源检查（调用 `_check_and_consume_cost`）
3. **新增 `_check_and_consume_cost()`** 函数：从 `_building_defs_cache` 读取费用，先检查库存再扣减
4. **`game_root.gd` 的 `_setup_resources_api_deferred()`** 末尾注入 ResourcesApi 到 ConstructionManager（`_construction_manager.set_resources_api(_resources_api)`）

> **注意**：`_setup_construction_api_deferred` 和 `_setup_resources_api_deferred` 都用 `call_deferred`，执行顺序按 `_ready` 中调用顺序。`_setup_resources_system()` 在 `_setup_construction_system()` 之后调用，但 deferred 调用是按注册顺序入队，所以 `_setup_construction_api_deferred` 会先执行。需要确保 ConstructionManager 注入 ResourcesApi 时后者已就绪。
>
> **解决方案**：把注入逻辑放到 `_setup_resources_api_deferred()` 末尾（此时 ResourcesApi 已就绪，ConstructionManager 也已在更早的 deferred 中就绪），而非放在 `_setup_construction_api_deferred()` 中。

**EventBus 信号**：`event_bus.gd` 已声明 `resource_changed(resource_name, amount, delta)` 信号。`resources/api.gd` 的 `consume()`/`produce()` 会发射本地 `resource_changed` 信号，但不会自动转发到 EventBus。如需全局监听，需在 `_setup_resources_api_deferred` 中连接（注意 api.gd 的信号签名是 `(resource_id, amount, delta, region_id)`，EventBus 是 `(resource_name, amount, delta)`，签名不完全匹配，C1 阶段先不转发）。

### E.5 任务 E4：双进度条（材料进度 + 建造进度）

**现状**：建造进度只有 `ConstructionProject.tick()` 推进 `remaining_work`，无 UI 反馈。

**设计**（创始人 2026-07-29 确认）：进度条分两层：
- **材料进度**：材料从资源点/仓库运到工地，运输完成度
- **建造进度**：工地施工完成度
- **约束：建造进度 ≤ 材料进度**（材料没运到不能施工）

**流程**：
```
玩家下令建造 → 扣减库存资源 → 创建项目
  ↓
工人分配为"搬运工" → 从资源点/仓库搬运材料到工地
  ↓ 材料进度 0% → 100%
建造工在工地施工 → 建造进度推进
  ↓ 建造进度 ≤ 材料进度（材料不足时建造暂停）
建造进度 100% → 完工
```

**P0 简化实现**：
1. `ConstructionProject` 新增 `material_progress`（0.0~1.0）和 `build_progress`（0.0~1.0）
2. 工人分为搬运工（推进 material_progress）和建造工（推进 build_progress，受 material_progress 限制）
3. 建筑头顶显示双进度条：上方材料条（蓝色），下方建造条（绿色）

**涉及文件**：
- 修改 `construction/scripts/construction_project.gd`：新增双进度字段 + tick 逻辑
- 新增/修改建筑头顶进度条 UI（`build_progress_bar.gd` 或挂到 Building 场景）
- 详细设计见 [建筑与定居点.md](file:///f:/VSCode/game-2/docs/技术/架构/场景与战斗/建筑与定居点.md) §9.5
