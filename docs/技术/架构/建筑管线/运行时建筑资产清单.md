# 运行时建筑资产清单（Godot 实装侧）

Godot 运行时侧全部建筑资产的台账：场景、脚本、调色板、def 数据表、参考纹理与它们的装配关系。与《[建筑资产清单.md](建筑资产清单.md)》（Blender 离线管线侧）分工——那册登记"**管线能产什么**"（装配器/材质/道具/内景），本册登记"**游戏里实装了什么**"（def→场景→脚本→调色板，及数据表差集）。

**生成基准**：本清单提取自 main `0f43a7dc` 的代码实态；一切以代码为准，增删资产须同步改本清单。**分工**：管线产出能力看《建筑资产清单.md》；运行时消费（前墙 alpha、z 序、双路径）看《HD-2D街景系统》；分级规则与级别窗口看《聚落等级与建筑分级》；建造流程运行时（施工/放置/目录）看《场景与战斗/建筑与定居点》。本清单只登记"资产实态"。

## 一、def 数据流四层（从表到场景）

| 层 | 位置 | 角色 |
|---|---|---|
| ① 人工源 | `config/excel/建筑数据.xlsx`（buildings sheet） | 策划维护的建筑数值表（成本/血量/宽格/interior_mode/解锁科技） |
| ② def 表 | `config/buildings/buildings.tres` | BalanceResource，**自动生成**自 ①（meta.source_sheet=buildings），**20 条 def**；装载侧经 `BalanceResource.sanitized_rows` 消毒（Excel 空单元格 null 剥除） |
| ③ 场景注册表 | `modules/building_gen/api.gd` `_BUILDING_SCENE_PATHS` | def_id → 模块内 .tscn 路径，**12 条**；`load_building_scene()` / `get_default_building_def_ids()` 是唯一出口，外部模块不得硬编码内部路径 |
| ④ 运行时装载 | `modules/construction/scripts/catalog/building_catalog.gd` | `register_defaults()` 经 ③ 装 PackedScene 进 `_building_scene_registry`；`load_defs()` 装 ② 进 `_building_defs_cache`；均由 ConstructionManager 持有 |

- 命名约定：def_id 与存档 SQLite 的 `def_id` 字段一致（见 `modules/building_gen/buildings/README.md`）。
- 建筑实体类型契约：`Building`（`modules/building_gen/scripts/building.gd`，全局 class_name）是对外公共类型，construction/world 可 `is/as` 判型并读写 `Building.State`；除此之外禁止引用模块内部脚本。

来源：`modules/building_gen/api.gd`、`modules/construction/scripts/catalog/building_catalog.gd`、`config/buildings/buildings.tres` meta。

**装配两种模式**：

- **外壳分离（房屋类 8 def）**：tscn 是 22~32 行薄壳，只做两件事——绑专属脚本（`@tool extends BuildingExterior`）+ 给 `palette` export 挂 `BuildingPalette`（`.tres`，19 行 Resource，C_* 色键契约）；几何与纹理全部程序化生成（CPU 贴图走 `modules/texture_gen/`）。def 只要有 id 即可映射到任意外壳场景（"def 不要求与场景同名"）。
- **城防耦合（wall_* 4 def）**：场景内手绘几何 + `wall_segment.gd` 共用段逻辑，同走 palette 机制，不走外壳分离。

来源：`modules/building_gen/buildings/*.tscn` ext_resource 绑定逐个核对、`config/buildings/buildings.tres` variables。
