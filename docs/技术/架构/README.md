## 二、文档清单（按性质）

**核心架构（长期维护）**：`场景与战斗/场景与战斗架构.md`（主架构导读）+ `数据与契约/` 全部七篇（模块依赖关系、模块API契约、系统交互与EventBus、核心实体与状态机、自动加载依赖、数据流全景、存储架构设计）。

**专项架构（垂直域，一篇一域，随对应任务演进）**：
- 子目录：世界与战略图/（5 篇）、场景与战斗/（主架构 + 6 篇子系统 + 火柴人战斗系统设计留档）、建筑管线/（见其 README）。
- 根目录：组织系统架构.md、武器装备与个人库存.md、武器挂载系统.md、平衡框架.md、音乐系统.md；UI 运行时专项 → `../UI/UI运行时架构优化方案.md`。

**调研报告（决策前置，拍板后归档或并入正式文档）**：寻路避障调研.md、RL层级指挥训练v3.md（搁置待启）。

## 三、维护约定

1. **新架构文档进本目录须在本 README 登记**（清单加一行 + 场景表按需加行）；新子目录须在「目录结构」表登记。
2. 每份文档头部标注**状态**（如：设计基线 / 部分实装 / 调研报告 / 已实施留档）与**关联文档**——既有惯例，新文档延续。
3. 摘要迁移模式：modules/README.md 承载模块视角速查（依赖图/数据流/autoload 摘要），架构目录承载深度细节；两边定位重叠时以"摘要指向正文"处理，不双写。
4. 调研报告类拍板后：结论并入对应正式文档，原报告删除（同"审计快照用完即删"约定）。
