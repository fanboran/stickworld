## 侦察结论（2026-09-09 已完成，勿重复摸底；详细证据见核心循环.md §7.1）

- **兵源零实现**：全库无 recruit/招兵/hire/人口代码；全村 2 NPC；编队=零消耗组织已有单位（`formation_system.gd:217-275` 只调 organization assign）。
- **兵营空壳**：buildings.tres barracks 写"训练战斗单位"，无消费逻辑。
- **经济**：产出=玩家手采+开局发放+征服一次性奖励；消耗=仅建造；零持续 sink（upkeep/工资/食物全库零命中）。
- **战斗规模**：守军 3/5/8+敌将；守城波次 3 起步封顶 9（`siege_director.gd:17-19`）；引擎按 196 人混战优化（性能注释基准，无硬上限）。

- **终局**：3 据点全占即内容终点。
- **存量可复用件**：守城战整套（siege_director 波次+TownSiege 出城选项）、territories 配置管线（Excel 化路线已定）、编队/指挥链、ConquestManager 状态机。

## 设计方向（AI 提案；创始人已定向"循环必须转起来、战斗要有规模"，数值待实测定稿）

**最小闭合集 = 批次 1 + 2 + 3**（兵源→sink→规模）：

1. **兵源闭环**：村民 → 兵营（资源+时间消耗 → 训练成士兵）。士兵=带装备的 StickmanEntity（现有编队直接可编）。人口池与 C 线共用（村民=待业人口，入伍消耗）。装备由铁锭驱动（C 线打铁产物）——**打仗赢资源→招兵买马→再打仗**的回路由此闭合。
2. **军饷/维护 sink**：编队按人头发饷（资源 tick 流出）+ 占领据点驻军维护费；付不起→士气/逃兵（P0 可简化为编队自动解散警告）。
3. **战斗规模抬升**：守军编成 3/5/8 → 10/15/20（territories.tres 调整，注意车轮战语义仍成立）；玩家军团目标 30~50（编队人数上限评估+跨图随行）；攻城波次抬升；50v50 压测。
4. **敌方反扑**：被占据点原势力定期反攻（retaliation 字段启用：计时器→敌军开赴我方城镇→守城战接线）——防御建筑获得存在意义，玩家不能只攻不守。
5. **终局长线**（批次 5+，依赖 B 线）：多 L1 区域/新据点动态生成/王朝式目标。
