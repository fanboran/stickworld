# 任务图维护规范

> 本文档持久化任务依赖图（[`任务依赖图.txt`](任务依赖图.txt)，可视化 [`任务依赖图.html`](任务依赖图.html)）的
> 规划理念、维护纪律与调度纪律，由创始人系列审计逐步确立。**任何 AI 编辑任务图前必读**；
> 工具：`python tools/deptask/gen.py --check`（校验+调度报告）/ `python tools/deptask/gen.py`（生成可视化）。

## 一、任务的存在资格（前后沿理念）

一个任务能作为独立节点存在的条件——**两者缺一不可**：

1. **前沿（为什么现在/将来做）**：前置是它**技术上真正需要的东西**。校验器规则：
   - 阻塞/冻结必须有前置（阻塞无因 = ERROR）
   - 可开工/进行中/待验收/完成 的前置必须全部完成（豁免=1 须写理由）
   - 前置已全部完成却标"阻塞" = WARNING 状态滞后（阻塞专指前置未齐，见 §七）
   - 前置可经其它前置传递到达 = WARNING 冗余前置（图保持最小，假深度误导读图与并发评估）
2. **后沿（产出被谁消费）**：完成的产出必须有明确的消费方——下游任务、玩家体验、或发布收口。
   校验器规则：未完成且无后沿 = WARNING（逐个确认；琐碎修复类应合并进有后沿的任务，
   或降级为其他任务的附属步骤，或移出规划图降级到待办随手清单）。
   例外：launch 的后代是终局交付（发布后的产出即终点），天然无后沿，不告警。

反例：文档勘误拆成 5 个独立任务、各只有一行改动、无后沿——
已合并为"文档校准批次"并连到消费方（input_refactor/tech_rebuild 开工前校准）。

## 二、前置 = 工作内容依赖，不是执行顺序

- **git 提交顺序 ≠ 依赖**：同一天提交的两个任务可能互不依赖（行为 AI 依赖 StickmanEntity
  实体与动画，与同期的建筑禁放区毫无关系）。
- **阶段门 ≠ 依赖**："Alpha 启动了所以能做科技重建"是排期不是因果。阶段划分是依赖拓扑
  **推导出来的结果**（从 root 出发的分层深度），不是写在图里的原因。图上不放
  alpha_start/beta_start 这类纯阶段门；launch/live_ops 保留是因为"游戏已发布才有 DLC"
  是真实因果。
- **域互斥 ≠ 依赖**：两个任务写同一批文件（同 域= token）不能并行，这是**调度约束**——
  先后由协调者派活时裁决（工具的域冲突检测与派活组合建议管这个），不得写成 前置=。
  反例：units/combat 工程债群（寻路/实体拆分/AI 数据驱动等）全部假挂
  "复刻收尾"巨门——真实原因只是域被复刻主线占用，巨门把"主线批次间隙可插入的活"
  锁成了"复刻全部完成后才能做"。
- **设计任务的前置 = 它所描述的内容在游戏中的成型进度**（不是"GDD 文档在上游"）：
  - 法律分支树 ← 窗口系统成熟（业务面板迁移）+ 国家存在（Region 建模+组织驱动）
  - 文明差异化 ← 大世界地图制作中后期
  - 剧情/主角/帮手 ← 基础循环可玩 + 各文明彻底设计好
  - 宫殿内部 ← 建筑系统深化（材质→B3/B4→参数化成熟）之后
  - 加工品列表 ← 物品系统完善（经济→采矿→循环→队列→建造过程化链条之上）
  - 战场两端模式 ← 多局循环转起来（跨图行军+编制）
  - 宣发材料 ← 美术告一段落 + 至少单局（最好多局）循环；此前只能准备账号（mkt_accounts）
- **设计先行例外**：纯设计任务（无代码依赖）前置=root 即可随时动笔，但标注
  "验收后修订"（如村落定义对照原型验收反馈修订）。
- **外部依赖建模为门节点**：美术资产采购、音频录制、创始人验收窗口这类"图外产能"
  建显式门任务承载（先例 ext_art=外部美术资产通道，豁免=1）——它阻塞下游素材替换群，
  让"为什么现在不能做"在图上可见可查，而不是用"阻塞"空挂（空挂会触发状态滞后告警）。

## 三、粒度规范

- **任务 = 单一可验收交付物**（约 1 次派活的量）；名称写**具体内容**，批次/编号一律进 `注=`
- 不合并：`0.1 和 0.2 算一个任务`这类阶段合并是错的（已拆分）
- 不过拆：**没有独立后沿的碎任务**不单独成节点（见 §一）；同类小活合并进有后沿的任务并在注里列明细
- **簇 = 语义功能团（高度耦合、边界清晰的一团），成员 ≤ 8**（超限 ERROR，按语义边界拆成多簇）；
  阶段打包簇（"P0 验证期"这类）禁止——簇按"功能团"划分，不按"时间期"划分
- **文档= 可选字段**：任务关联的设计/架构文档路径（仓库根相对路径，如
  `文档=docs/设计/系统/04-科技系统.md`）——看板详情面板渲染为可点链接，是"图 ↔ 文档系统"
  的联动通道；系统类任务应挂，纯执行/治理类可不挂

## 四、跟随最新设计（任务列表是活的）

任务列表映射的是**当前设计**，不是历史考古：

- 设计推翻某成果时，同步移除/改写对应完成节点（例：河流算法一版被推翻 → 该成果移出完成区，
  river_gen 承接重做；旧地图模板法被分形大陆方案替代 → 从节点名称中移除）
- 已完成区的每个节点都应是"当前设计下仍然成立的成果"
- git 历史只用于**还原脉络**（哪些阶段做成了什么），节点内容以最新设计为准

## 五、发布收口的完整语义

`release_gate`（发布收口）的前沿 = **发布所需要的内容全集**，按领域收口门分层：

```
econ_loop_done    经济循环收口（资源产出→队列→建造过程化→物流→市场→持久化）
map_refactor_done 地图重构收口（扩张/城墙/城外/出城/城镇朝向/地面贴图/建筑深化）
battle_modes_done 战场类型收口（遭遇/攻城/守城/spawn 动态/持续战/工程战/跨度/道路遭遇）
gdd_systems_done  GDD 系统补全收口（科技/扩张模块/外交/成就/组织驱动/室内/上帝视角/天气）
sim_units_done    模拟与个体收口（个体属性/装备/寻路/实体拆分/AI 数据驱动/战斗收敛）
ui_mature_done    UI 成熟收口（tscn 迁移/小地图样式/存档界面/附身完整版/读档完整性）
    ↓ 六门齐 → content_freeze（内容冻结 = GDD 预想的游戏本体状态齐）
    ↓ + 打磨群（平衡/UX/本地化/Steam/商店页/定价）
release_gate → launch → live_ops
```

"发布前要做什么"= 点开 release_gate 逐层展开前置；"什么能提前做"= 收口门成员中
前置已满足的节点（图上读拓扑深度与状态）。

## 六、并行管理语义（工具）

- **分区布局 + 分隔墙**：自动重排严格保持左（完成）右（未完成）；墙可拖动（右区整体平移）；
  节点拖动被墙约束，唯一穿越方式 = 状态变为完成
- **聚拢聚焦**：单击泳道胶囊 → 该线居中，前沿（外部前置）列左、后沿（外部被依赖）列右，
  无关淡出——用于观察任务组的依赖边界
- **封装簇**：语义功能团可折叠/展开；折叠卡片聚合状态与进度，边自动重定向
- **🚦 就绪集高亮**：工具栏"可派 N"chip 点击后只高亮前置全齐的任务（调度视角，
  数据由 gen.py 注入，与终端调度报告同源）
- **🛤 关键路径高亮**：工具栏"关键路径 N 跳"chip 点击后高亮未完成子图最长链
- **校验闸门**：派活前 `--check` 必须通过（环/悬空/阻塞无因/前置未完成/簇超限 = ERROR；
  状态滞后/冗余前置/域冲突/无后沿叶子 = WARNING 审计线索）
- **视觉语义**：看板视觉层与调度语义同构，颜色读法=电平读法——
  - **状态色=电平隐喻**（与 §7.1 状态语义一一对应，一眼可辨"电走到哪一站"）：
    **绿**=完成（信号已达终点，健康）；**琥珀**=待验收（刚到达尚待确认，余晖）；
    **亮黄**=进行中（正在传播）；**天蓝**=可开工（待传播，就绪等发车）；
    **灰**=阻塞/冻结（未上电——前者前置未齐自然无电，后者有意断电）
  - **关键路径=琥珀蚂蚁线**：🛤 高亮以琥珀虚线流光（dash 滚动+辉光）呈现最长链，
    隐喻"信号正在传播"——蚂蚁线流经的任务即当前瓶颈链，压缩手段见 §7.2
  - **泳道色即领域色**：8 色循环分配（LOGIC-8 ACCENT 系：紫/蓝/橙/亮绿/黄/粉/青/灰），
    跨视图一致——先认颜色再认线名，降低多线并行时的识别负担

## 七、调度纪律（铁路调度模型）

多 AI 并行开发按铁路调度运转：**图管轨道拓扑（什么必须先于什么），调度管发车
（现在派哪几班）**。两者分离，图才不会为了表达排期而长出假依赖。

### 7.1 状态语义（由 DAG 派生，不是手填愿望）

- **可开工**：前置全部完成。协调者**只可派「可开工」**——这是唯一派活闸门
- **阻塞**：前置未齐。前置齐却标阻塞 = W 状态滞后（改 可开工，或说明真实原因：
  补前置/挂外部门/冻结）。"没排期"不是阻塞的理由——排期先后是协调者在就绪集内的裁量
- **冻结**：有意延后（冻结令/占位），注须写明解冻条件或缓做理由
- **外部门**：外部产能（美术/音频/创始人窗口）建门节点（如 ext_art），豁免=1 + 注明
  等待物；下游挂它而不是空挂阻塞

### 7.2 调度报告（每次 gen.py 运行输出）

- **就绪集**：前置全齐可立即派活的全集（按线分组）——协调者的候选菜单
- **建议派活组合**：就绪集内"关键路径优先 + 域互斥贪心"选出的 ≤N（默认 6，`--lanes` 调）
  个并行任务，域两两不相交（合并冲突安全）。无 域= 声明的任务不进组合（范围不明，
  保守处理——派它前先补域声明）
- **波次**：未完成子图拓扑分层。波 n = 某任务最少还要等 n 道串行工序；
  各波宽度 = 该阶段的潜在并行度上限
- **关键路径**：最长链。**加并发只能压缩非关键路径**；关键路径要靠拆依赖（域互斥代替假依赖）、
  拆任务（大任务拆成可并行的子交付物）、或外购（外部门提前启动）来压缩

### 7.3 派活协议（协调者）

1. 派活前跑 `--check`：ERROR 清零 + 无状态滞后，就绪集即当前合法派活范围
2. 从建议派活组合出发微调（优先级/创始人窗口/工作树容量），同域任务绝不并行派出
3. 决策/设计类任务（零代码成本、解锁下游一大片）在就绪时**优先派发**——
   它们是图上杠杆率最高的节点
4. 收线时更新状态（完成/待验收），重跑报告——就绪集自动前移，无需手工推排期
5. 新任务立项先问三件事：真实前置是什么（前沿）？产出谁消费（后沿）？写哪些文件（域）？
   三者写清才可入图

### 7.4 看板编辑闭环（浏览器端）

看板（任务依赖图.html）不只是视图，也是轻量编辑器：

- **可做**：框选批量改状态、端口拖线建依赖（幂等防重/防自环）、点边 Del 删依赖、
  右键新建任务（含前置/域/文档字段）、泳道聚拢观察依赖边界
- **回写流程**：编辑后节点亮 ● 角标 →「⬇ 导出源」下载完整 txt →
  **覆盖 `docs/项目/任务依赖图.txt`** → 跑 `--check`（导出前前端做悬空/自环快检）
- **纪律**：导出文件是唯一回写通道（浏览器不能直写仓库）；覆盖后必须校验，
  有 ERROR 禁止派活；复杂变更（拆任务/改里程碑结构）仍建议直接编辑源 txt
- **岗位视图**：全图 / 制作人（派活台）/ 程序 / 策划 / 美术 / 测试——同一份 DAG 的过滤投影，
  URL `#view=producer` 可直达分享；视图不复制数据，源 txt 仍是唯一真相源

### 7.5 评审节奏

- 每次收线批次后重跑 `--check` + 生成看板，里程碑燃尽与关键路径变化记入
  [`规划评审.md`](规划评审.md)（制作人视角评审文档：阶段打法/瓶颈/风险/覆盖率）
