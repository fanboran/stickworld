# 通用项目管理系统

## 目的

这是整个游戏**最核心的系统**。让玩家用同一套工具，搭建帝国里的一切组织——军队、科学院、工程队、行政体系、商队。每个组织的底层逻辑完全相同——把一群火柴人按照你设计的层级组织起来，向某个目标运作。

## 玩家体验目标

- **一通百通**：学会了搭军队编制，就学会了搭科学院架构——逻辑一样，只是名字和用途不同
- **亲手设计**：每个组织之间的层级关系、每个层级的编制配置，都是你亲手设定的
- **看到效果**：好的架构高效运转，差的架构处处卡壳
- **随时回落**：你已是皇帝，但缩放到某个排长身上去微操绕后——像《戴森球计划》缩放一样自然

---

## 一、五层级框架

帝国里所有的组织都共享同一套五层级深度：

| 层级 | 行政语境 | 军事语境 | 科研语境 | 工程语境 | 物流语境 |
|------|----------|----------|----------|----------|----------|
| **L5** | 帝国 | 帝国最高统帅部 | 科学院 | 工程院 | 全国物流中心 |
| **L4** | 区域 | 师 | 研究所 | 区域工程所 | 地区物流中心 |
| **L3** | 行省 | 团 | 研究室 | 项目组 | 中转站 |
| **L2** | 城市/郡县 | 连 | 课题组 | 施工队 | 运输队 |
| **L1** | 镇/村 | 排/班 | 实验员 | 施工分队 | 运输分队 |

### 1.1 层级弹性

**加层级**：标准层级之间可以额外插入一层。例如：
- 在"团"(L3)和"师"(L4)之间插入"旅"
- 在"连"(L2)和"排"(L1)之间插入"火力组"

**减层级**：可以跳过某一层级。例如：
- 去掉行省(L4)，中央(L5)直接对接全部城市(L3)——中国某些朝代草创和快灭亡时常这样干
- 现实中装甲部队用"旅"取代"团"，直接对接营

**最底层宽松**：第1层可以额外向下塞**两层**。例如：
- 火力组 → 班 → 排，三个子层都挤在第1层内
- 班是最小编制，但在实际指挥中班长发现直接管单个步兵太难——于是手动分了两个火力组

**灵活命名的意义**：火力组不是正式编制，是班长在战斗中为了方便指挥临时分的——游戏里玩家的层级也是这样：正式的编制层级和临时的指挥分组可以共存。

### 1.2 集团军怎么办？

玩家本身是一个**虚拟层级**。当你的帝国足够大，你需要同时指挥多个"师"时——你是 L5+，下辖多个 L5 组织（多个师）。这个虚拟层级不算在标准五层级内，它是"你"。

就像周天子不过几个师——在游戏里，你作为皇帝管的可能就是几个 L4 级别的军事组织，它们并排放在你的名下。

玩家层级是**成长出来的**：从小卒起步（开局≈班长级），随你实际统辖的指挥链增长而逐步成为更高统帅——不存在生来就有的"最高统帅"位置。

## 二、组织即全能

**每个组织理论上什么都能干。** 军事编制可以施工（工程兵），科研单位可以被拉去打仗（虽然打得不好），行政机构可以经商（腐败风险大但理论上可以）。

### 2.1 标签系统

玩家给每个组织打上一个**标签**，决定了该组织的主界面默认展示什么：

| 标签 | 主界面默认显示 | 底层仍然可以做的事 |
|------|---------------|-------------------|
| 军事 | 进攻、防御、行军、呼叫支援、部署 | 施工、科研、运输…… |
| 科研 | 分配课题、审核论文、调拨经费、实验 | 打仗、施工、运输…… |
| 工程 | 开工、验收、材料调度、质量检查 | 打仗、科研、运输…… |
| 行政 | 征税、户籍、司法、治安 | 打仗、科研、施工…… |
| 运输 | 采购、销售、定价、物流 | 打仗、科研、施工…… |

UI 上——军事标签的面板显示进攻/防御按钮，科研标签的面罩显示课题管理。但点开**"完整功能"展开箭头**，你会发现所有标签下的组织都有一样的底层能力列表。就像 Blender 的 Modeling、Sculpting、Layout 工作区——功能一样，常用工具不同。

### 2.2 特化收益

虽然全能，但**特化有加成**：

- 军事编制的战斗力远高于科研单位被拉去打仗
- 科研编制的产出远高于军事单位做研究
- 工程编制的施工效率远高于商队修路

特化程度取决于：（1）你给这个组织配置的编制模板（2）人员的资质匹配度（3）装备配置。

### 2.3 部门不预设与元层级

哪些部门存在、哪个是"最高部门"没有标准答案——像现实中各国结构五花八门一样，玩家可以随心所欲地设置国家架构，甚至"封一只狗为上将"。但**虚衔自由 ≠ 运行自由**：任命了不合适的首脑、挂了空有其名的部门，实际运转立刻出问题——如同你有喝毒药水的自由，但你真的会死。组织是为解决具体问题而涌现的：运输太累 → 封装运输主管；仗打不赢 → 建训练部门；科研停滞 → 组建大科学工程指挥部。

**元层级**：组织可以管理"建立组织"这件事本身——后期玩家设计出能批量产出编制的编制、能组建部门的部门，把"搭组织"这件事也自动化掉。

## 三、编制管理

在每个层级的节点上，玩家配置该节点的**具体编制**——这个班/连/团/师里具体有什么。

### 3.1 可配置项

| 配置项 | 说明 | 示例 |
|--------|------|------|
| **人员组成** | 该层级包含的角色类型和数量 | 1个机枪手 + 4个步枪兵 + 1个法师 + 2个无人机飞手 |
| **装备配置** | 标配武器、护甲、工具 | 标准步枪、皮甲、工兵铲 |
| **指挥官** | 任命或留空 | "铁拳张三" 或 系统自动填补 |
| **自主决策权限** | 该层级可以自行决定什么 | 攻击/防御/撤退/调兵/征用物资 |
| **默认战术** | 无指令时的自动行为 | 主动进攻 / 坚守阵地 / 游击骚扰 / 自主判断 |
| **补给优先级** | 物资分配的权重 | 高 / 中 / 低 |
| **溃退纪律** | 编制的纪律线：士气是实际状态（目睹伤亡、指挥官在场与否、情绪标签）的累积，跌破纪律线时部队自主溃退——这是部队 AI 的决策，不是系统强制触发 | 伤亡 >40% 或 指挥官阵亡 |

### 3.2 玩家自定义自由度

- 人员组成可以**自由拖拽组合**——这班3个法师2个步兵，那班全是步兵
- 装备可以**从帝国库存中选择分配**（如果帝国物资不够，系统会提示缺货）
- 预设几个模板方便快速搭建，但随时可以拆零件重组

### 3.3 命名规则

- **军事/科研/工程组织**：层级名称可以自由修改（"这个师叫'大队'，下面的团叫'小队'"）
- **行政区划**：部分锁定，不能随便改（"甲市"不能改叫"甲哈基米"）

## 四、AI 行为与自动化

### 4.1 逐层指挥

每一层级的 AI 只能**直接指挥向下的一层**。它看不到下属的下属在干什么——只是下达任务，下属自己分解执行。

```
帝国统帅(L5) → 只告诉师长(L4)："拿下这个区域"
师长 → 只告诉团长(L3)："你的团攻这个方向"
团长 → 只告诉连长(L2)："你的连守住这个高地"
连长 → 只告诉排长(L1)："你的排从右边绕"
排长 → 具体指挥每个火柴人
```

**这意味着**：你想让帝国自动化运转起来——必须精密地设计每一层。层级设计得好，命令顺畅传达。层级设计得烂，上面下的命令传不到下面，或者下面自己乱搞。

### 4.2 信息上报

反向也一样——下层的问题向上汇报，每层自己判断什么需要上报、什么自己处理。自主决策权限越高，往上报的越少。

### 4.3 玩家干预

你随时可以"**附身**"到任意层级的指挥官：

- **操纵模式**：真的控制那个角色在战场上移动/战斗
- **管理面板模式**：打开该层级的管理面板，下达指令、调整编制
- 两种模式随时切换

当你附身到低层级微操时，高层级帝国继续运转（或自动暂停/减速——取决于你的设置）。

### 4.4 信息与物资的物理传递

指挥系统**有个人实体**，不是抽象的箭头连线：

- **命令靠信使真实跑动传递**——需要时间、可被截杀；部门首脑被刺杀后，该部门运转立刻受影响
- **物资靠载具一车一船真实移动**——不存在点击即达，工序之间的物料搬运同样占用真实编制
- **信息上报同样吃传递时间**——后方看到的报表永远是延迟快照，前线可能已经崩溃
- **战场指挥半径**——指挥官只能直接影响附近的单位，超范围依赖传令与编制自主（见 [`02-战斗系统.md`](02-战斗系统.md)）

### 4.5 军事组织的嵌合

「我指的是指挥军事体系与游戏循环的自然嵌合怎么做，同时得把军事组织做的就像游戏内无数其他组织类似，有一套共通的底层逻辑」

军事组织不另起炉灶——它就是本系统的一个**标签实例**（§2.1）：同一套五层级（§一）、同一套逐层指挥（§4.1）与信息上报（§4.2）、同一套补位原则（§九）、同一物理传递（§4.4）。对照游戏的五级系统与游戏设计文档的扩张逻辑和游戏循环设置：战争是主循环里的一环，组织平时就在运转（招兵、补给、上报、默认战术），**战场 = 运转的焦点视图**——把这套运转放到镜头前，而不是切出去另开一套规则。

共通底层逻辑 → 军事实例化 → 已有对应物：

| 组织原语 | 军事实例化 | 已有对应物 |
|----------|-----------|-----------|
| 层级树节点 / 编制配置（§三） | 班、排、火力组 | formation API（建队 / 任命排长） |
| 逐层指挥任务式（§4.1） | 军师给意图、班长分解、士兵执行 | 号令通道：对组织下令 → 沿树传播 → L1 执行（架构文档批次 3） |
| 补位原则（§九） | 军衔继任 | 补位引擎 + succession_rule（架构文档 §4.3.1） |
| 命令 / 物资物理传递（§4.4） | 信使传令、补给线 | 传输层 v1 抽象传播（v2 信使实体另立任务） |
| 信息上报（§4.2） | 战报 = 延迟快照 | report_filed 上报骨架（架构文档 §4.4）；延迟快照由批次 4 上报通道补齐 |
| 特化收益（§2.2） | 集火、士气光环 | 集火 = 小队共享目标分配（既有）；士气光环待接 |
| 首脑被刺（§4.4） | 斩首 | rank≥3 指挥官留守后方行为守卫（[`02-战斗系统.md`](02-战斗系统.md) §八-A） |

层级口径：火力组 / 班 / 排全在 L1 内（§1.1 最底层宽松）；军衔 rank3 指挥官 = L2 的出场代表（留守后方守卫已落地，见上表末行）。

- **逐层指挥映射战场号令**：对军事组织根下令，命令沿树物理传播到 L1 小队执行——下令吃传播延迟、战报延迟快照、编制生成战场实体，军事指挥嵌在游戏循环里自然发生，没有独立的"战斗模式"开关。
- **编制生成战场实体**：L1 节点的编制配置投影为战场小队与成员——编制是账面，战场实体是投影；改编制即改战场（投影架构位与观察场硬编码阵容的迁移路径见架构文档批次 4）。
- **默认战术 = 驻防**：无指令时军事组织按默认战术行动（§3.1），P0 军事默认 = 驻防 / 巡逻（挂点契约见架构文档批次 4 默认战术钩子）。

号令类型、战场指挥半径、小队执行等战斗侧细节见 [`02-战斗系统.md`](02-战斗系统.md)；
三原语、编制投影与灰盒验证的技术契约见 [`../../技术/架构/组织系统架构.md`](../../技术/架构/组织系统架构.md) 批次 4。

## 六、预设与分享

各种组织都有**更换预设组织方式**的选项——运行中可切换本组织的预设（如征兵处的运行方式三档，见 §十一），切到一定规模组织力不从心时由待办提醒引导更换（§十一）。

### 6.1 预设模板

游戏提供多个预设架构模板：

| 模板 | 描述 |
|------|------|
| 标准军事编制 | 师→团→连→排（中间可加旅） |
| 科学院架构 | 科学院→研究所→研究室→课题组 |
| 工程指挥部 | 总指挥部→区域→项目组→施工队 |
| 标准郡县制 | 州→郡→县→乡 |
| 商业网络 | 总行→分行→商号→商铺 |
| **空白 + 标签** | 选择一个标签，从零搭建 |

预设模板即**官方母本蓝图**：玩家自建的组织同样可定名为蓝图并派生/融合，形成玩家自己的构筑谱系树——见 [`11-构筑谱系系统.md`](11-构筑谱系系统.md)。

### 6.2 UGC 分享

- 导出/导入组织架构配置（JSON 格式）
- 社区可以分享"最优指挥链"、"最高效科学院架构"
- 不同文明的最优架构不一样——农耕 vs 游牧 vs 商业 vs 海洋

## 七、不同文明的最优组织结构

| 文明 | 组织特点 |
|------|----------|
| 农耕文明 | 层级深（行政体系完整），军事编制正规，中央集权 |
| 游牧文明 | 层级浅（2-3层足够），军事编制灵活，以万户/千户为单位 |
| 商业文明 | 经济组织发达，军事外包/雇佣兵，行政精简 |
| 海洋文明 | 海军编制特殊，殖民地管理体系，物流网络复杂 |

不同地形/气候的火柴人部落自然演化出不同的组织架构——这本身就是文明叙事的一部分。

## 八、部门首席与头衔承认

### 8.1 首席面板

各部门的首席（首脑）集中显示在专门面板——谁掌哪个部门、能力如何、部门运转状态。**他国政权的部门首脑信息不直接可见**：由玩家派出的**情报组织**获取（通用组织系统的又一应用）——情报组织的编制与投入决定情报的覆盖面与新鲜度，情报本身也是一种需要传递的资源。

### 8.2 头衔需承认

从部落到大帝国，头衔跃升（部落首领 → 城主 → 国王 → 皇帝）不是自动升级，而是一次**承认检定**：

- **条件**：足够多已持有头衔者（政权/组织）的认可
- **时机**：检定需要特定时机——如一场多国会议，或战争胜利后的谈判（战胜方可在谈判中**强制**对方承认）
- **效果**：检定通过即完成头衔跃升，影响外交地位、可任命的编制层级上限与界面称谓（UI 不预设"帝国"字样）

## 九、边缘情况

- **指挥官死亡**：「现实中两个排一起去攻打一个地方，然后一个排长阵亡或者两个排长都阵亡了会发生什么和怎么办？」——按该组织的**补位原则**自动补位（如"班内军衔最高者顶上"，规则可配置；P0 军衔未建时以指挥属性代理排序）——补上的人就是真指挥官；无人可补时该节点挂起，下级越级请示或自主行动，上级也可越级直管
- **小档指挥口径**：火力组 / 班 / 排全在 L1 内（§1.1 最底层宽松）——每侧 ≤1 排时**排长即前敌指挥**（指挥链顶层，不另设指挥层）；有两个排则**两个排长都是指挥官**（后方各领一排）。一个排长阵亡只动该排（排内自补，另一排不受牵连）；两个都阵亡则两排各自自补，补不上者挂起——上级越级直管 / 下级自主，与补位原则同口径
- **机构重叠**：两个同层组织职责重叠 → 效率下降
- **过宽管理幅度**：一个指挥官管太多下级 → 每个下级获得关注减少
- **推翻重建**：大规模重组 → 过渡期混乱 [PLACEHOLDER] 天
- **组织解散**：所有人员回归待分配池

### 征兵设计

**核心语义**：兵源是个难题，具体怎么征兵要有真实的过程。像**世界盒子**那样——征兵设施出来抽调；**征兵建筑就是征兵人员的办公室**：有切实的小人到处跑、和人交谈，花费若干秒才能征到一个，征到满名额为止。征兵建筑的具体人数和运行方式都可以调整。

- **征兵处 = 组织节点**：办公模块 + 几名征兵员编制——征兵组织就是通用组织系统的一个普通实例（§4.5：一套共通底层逻辑，"征兵"只是它的词表）。
- **兵源 = 未入编的待业村民**：待业池细则见 [`12-小镇生活与美术.md`](12-小镇生活与美术.md) §七，此处不重复。

**运行方式预设（首批三档，预设集随实装补全）**：

| 预设 | 运行方式 |
|------|----------|
| 街头征募队 | 征兵员满城走、和人交谈——若干秒征一人 |
| 办公室登记 | 待业者自己上门登记 |
| 战时征召 | 快，带士气代价 |

**组织方式与建筑关系（已定）**：

- **预设组织方式**：每种建筑若干个预设组织方式（可复用 §六 预设模板）——预设集内容与切换时机随实装调研补全；
- **建筑和功能不分离 = 组织附身建筑**：组织只要建筑具备它需要的模块就能附身实现（征兵处就是附身在具备办公模块建筑里的征兵组织，不是抽象开关）；组织可换址，建筑不与功能绑定。整体口径见 [`03-定居点与建筑.md`](03-定居点与建筑.md)：空建筑与功能建筑混排、功能后置挂载（模块+陈设+机构）、场所需求三类清单（结构/材质/构型）约束什么组织能附身什么建筑。

**力不从心 → 待办提醒**：到了一定规模，当前组织开始力不从心时，游戏弹窗待办提醒更换方案——像**缺氧**的待办那样；触发阈值随实装实测定（属校准不属设计开放）。其信息链路 = 组织信息上报（§4.2）的游戏化出口：组织自己把"管不过来了"报上来，待办替玩家盯着。
