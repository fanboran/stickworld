# 仓库瘦身与历史去向

主库（stickworld）只保留代码、文档、配置与现役资产；大体量数据与资产的历史按类别分流到附属库或清除。本文是各部分历史去向的登记处，也是找回被清除历史的入口。

## 主库保留

代码、文档、配置、现役音频/字体/图标、`tools/worldgen/output/locked/` 金标准（含 `river_paths.json`），以及历史中仍然现役的部分。

## 附属库

| 库 | 内容 | 接入方式 | 体积 |
|---|---|---|---|
| [stickworld-mapdata](https://github.com/fanboran/stickworld-mapdata)（私有） | `stick-world/config/strategic_map` 战略图运行时数据的全部历史 | **submodule** 挂载回原路径，游戏按 `res://` 原路径直读；数据修正在该库提交，主库只更新指针 | ~983 MB |
| [stickworld-legacy-assets](https://github.com/fanboran/stickworld-legacy-assets)（私有） | `stick-world/tests/dev/proto_hd2d` 迁入 `modules/hd2d` 之前的完整资产历史（含仅旧路径独占的 ~366 MB 贴图/成图） | **纯存档库**，不挂载、不被构建引用，需要考古时单独克隆 | ~465 MB |

克隆主库后须 `git submodule update --init`（或 `git clone --recursive`）补齐战略图数据；存档库按需单独克隆。

## 已清除、不在任何附属库的历史

以下内容从主库历史中抹除、也**不**在附属库里，唯一找回途径是终极备份（见下节）：

- godot-sqlite 的 iOS xcframework 静态库（~243 MB；Windows 开发不可用，移动端需要时从插件源还原）；
- `tests/dev` 顶层的 diag/探针渲染输出图（脚本每次运行重新生成）；
- `tools/worldgen/output/**` 的历史旧版本（tip 中 locked/ 金标准与白名单验收图保留）。

## 终极备份

`F:\VSCode\stickworld-pre-rewrite-20260916.bundle`（2.1 GB，`git bundle verify` 校验完整）——重写前主库的全量历史，上面所有被迁出/清除的内容都可从中找回（`git clone <bundle路径>` 即得完整仓库）。确认瘦身稳定运行后可自行删除以释放磁盘。
