## 1. 背景与目标

用户要求将《药剂工艺》(Potion Craft，Steam 游戏) 的视觉特效"完美复刻"到本项目
（火柴人帝国模拟，Godot 4.7）。最初用"贴图近似 + 粒子参数脑补"的方式交付，
被指出与药工原版不符。随后改为：
1. 反编译药工 C# 源码，确认**系统机制**
2. 破解其资源包，提取**真实参数**
3. 在 Godot 中按原版机制逐条翻译实现

**核心结论先行**：药工的"布灵布灵"（水晶/岩壁闪光）不是贴图效果，也不是复杂
shader——是**一个参数精确的粒子系统 + 脚本驱动的精灵特效**。复刻的关键是
拿到参数，而不是重画贴图。

## 3. 三大特效系统机制详解

药工的视觉特效分三套独立系统，**用途完全不同**，复刻时必须先分清是哪一套。

### 3.1 IngredientVisualEffectSystem —— 交互蹦闪（采集/投掷/碰撞）

文件：`IngredientVisualEffectSystem/IngredientVisualEffect.cs` + `IngredientVisualEffectController.cs`

- 数据脚本（IngredientVisualEffect）：**多张 Sprite 帧集合**（List\<Sprite\>）、
  fadeOutAfter/fadeOutTime（Vector2 随机范围）、canBeMirrored、color、
  randomSpawnRotation、randomRotationDirection、randomSpawnRotationSpeed（范围）、
  rotationAcceleration、accelerateRotationSpeedToZero、gravityAcceleration、
  speedSlowdownCommon/Explosion、spawnAreaRadiusCommon/Explosion
- 执行器（Controller）：**单 SpriteRenderer + 手写 Update 物理循环**：
  - `speed += gravityAcceleration * deltaTime * Vector3.down`（重力）
  - `speed = Vector3.MoveTowards(speed, zero, slowdown * deltaTime)`（衰减）
  - 旋转速度先加速/减速（`accelerateRotationSpeedToZero` → `sign * abs(accel) * delta`）
  - 位移 `position += speed * deltaTime`
  - 淡出 `ShaderEffect().SetEffectValue(value)`（原版用 shader 控制 alpha）
- 池化：静态 `Queue<Controller> effectsPool`，`TakeFromPool/ReturnToPool`，
  预建 N 个（settings.maxVisualEffectsCount）
- 触发：`StackVisualEffects.SpawnEffectsExplosion`（拿起/扔出爆 5 个）、
  移动速度 >20 时按冷却概率持续冒（Common 型）
- **关键**：这是"蹦出来的碎屑闪光"，有旋转有位移，不是墙壁闪烁

### 3.2 CrystalSparks + GlobalMeshParticleSystem —— 岩壁/水晶持续闪光 ✅ 用户要的"布灵布灵"

文件：`ParticleSystemFX/`（GlobalParticleSystemsPool、ParticleSystemsGroup、
MeshParticleSystemEntry）+ `SpriteParticleApplier` + `ParticleAreaMeshCollection`

- `SpriteParticleApplier`（挂在岩壁/水晶 SpriteRenderer 上）：精灵变化时查
  `ParticleAreaMeshCollection`（美术在编辑器手绘的多边形路径表）→
  `SpriteParticleMeshGenerator.CreateMesh()` 把路径转 Mesh → 粒子系统以
  **Mesh 为发射形状**
- `ParticleSystemsGroup.UpdateGroupEmission()`：
  `rateOverTime = areaFactor × mesh表面积 × 全局SpawnRate`（**面积驱动密度**）
- CrystalSparks 是**持续发射的 Unity ParticleSystem**（非 one_shot），
  粒子原地出生、原地闪烁（见第 5 节真实参数）
- 池化：GlobalParticleSystemsPool（按 prefab 分池）
- 全局开关：可访问性"闪光"开关 → `GlobalMeshParticleSystemSettings.particlesEnabled`

### 3.3 结论：用户要的是 3.2，不是 3.1

本项目最初错误地把 3.1（交互蹦闪）当成了墙壁闪光复刻 → 完全不像。
正确路径是 3.2 的机制 + 真实参数。

## 4. 资源包破解方法（大端 bundle 解包）

### 4.1 现象

`StreamingAssets/aa/StandaloneWindows64/defaultlocalgroup_assets_all_*.bundle`
（734MB）用 UnityPy 加载报 `MemoryError`。

### 4.2 根因

**该游戏所有 bundle 的头部整数是大端序（BE）**（UnityPy 按小端读导致字段全乱）：
- rooms 包（128MB）头部验证：ver=8、size=128,456,964 均 BE 精确匹配
- 大包头部：ver=8、size=734,472,611 与文件大小精确一致（BE）
- flags BE = 0x243（LZ4HC + BlocksAndDirectoryInfoCombined + padding）
- blocksInfo 内容（blockCount/块尺寸/目录项）同样 BE

UnityPy 小端读 BE 头 → cbsize 读到 3.8GB → `read_bytes` 吃到文件尾 →
解压 1.7GB 假数据 → MemoryError。rooms 包能读是因为它小，join 没爆内存，
但内部字段同样是 BE（UnityPy 的 EndianBinaryReader 对 bundle 默认大端读取，
恰好匹配！—— 详见 4.4 注意事项）。

### 4.3 破解脚本（本仓库 tools/ 外，位于临时目录，路径见下）

脚本位置：`C:\Users\fanbo\AppData\Local\Temp\opencode\potioncraft\`
- `normalize_bundle.py`：大端头 → 小端归一化（曾用于 UnityPy 直接读，后弃用）
- `stream_extract.py`：**流式解压**（最终方案）

最终方案 `stream_extract.py` 流程：
1. 按 BE 读头部：sig(8B) + ver(4B) + "5.x.x\0" + "2023.1.13f1\0" + size(8B) + cbsize/ucbsize/flags(各4B)
2. blocksInfo 位置 = 头部结束后 16 对齐（50 → 64）
3. `lz4.block.decompress(blocksInfo, uncompressed_size=ucbsize)`（BE 字段）
4. 解析 blockCount(12610) → 每块 (uncomp, comp, flags) → 目录项 (offset,size,flags,path)
5. **逐块 seek + 解压 + 写盘**（不 join！12610×128KB ≈ 1.65GB 流式落盘）
6. 输出 `F:\MyMy\decompressed_cab.bin`，前 303MB 为内层序列化文件
7. `dd` 前 303MB → `cab_main.bin` → UnityPy.load 直接可读

### 4.4 注意事项（踩坑记录）

| 坑 | 教训 |
|---|---|
| 大端头 | 所有整数（ver/size/cbsize/ucbsize/flags/blocksInfo 内）都是 BE；字符串/字节正常 |
| LZ4 重压缩 | `lz4.block.compress(store_size=True)` 会带长度头，UnityPy 按无头解压 → 垃圾；必须 `store_size=False` |
| 16 对齐 | blocksInfo 和数据区都在 64 对齐处；归一化写入前必须先补 padding |
| 内存 | 1.65GB 数据绝不能 `b"".join`，流式写盘 |
| .resS | 纹理等大资源在 `.resS` sidecar（1.29GB），UnityPy 需同目录同名文件才能解析 |
| console 编码 | 中文输出在 GBK 控制台乱码，写 JSON 文件再读 |

### 4.5 临时文件（F:\MyMy\，可删）

- `normalized.bundle`（734MB，归一化版，可留作后续深挖）
- `decompressed_cab.bin`（1.65GB，**建议删除**）
- `cab_main.bin`（303MB，内层序列化文件，深挖时保留）
- `图片/Work/药剂工艺原版闪光贴图_*.png`（若提取成功）

## 5. CrystalSparks 真实参数（出土数据）

来源：`cab_main.bin` 内 283 个 `CrystalSparks*` GameObject 的 ParticleSystem
typetree 反序列化。**参数级真实值**：

| 参数 | 原版值 | 说明 |
|---|---|---|
| rateOverTime | **8.0/s 恒定** | 再由 ParticleSystemsGroup 按 表面积×areaFactor 缩放 |
| startLifetime | **0.72s 恒定** | |
| startSize | **0.13 单位 ≈13px**（@100PPU） | 小而精 |
| startColor | **渐变：出生冷白蓝(0.77,0.88,0.91)不透明 → 渐隐透明** | 快亮慢暗=闪烁本体 |
| gravityModifier | **0** | 不飘落 |
| 初速度 | **0** | 原地出生原地闪 |
| 旋转 | **关**（RotationModule.enabled=false） | |
| 外部力/碰撞/拖尾 | 全部 false | |
| ShapeModule | **type=20（Mesh）** | 运行时塞精灵网格 |
| maxNumParticles | 1000 | |
| 材质 | **Unity 内置 Default-ParticleSystem**（软白点） | 非定制美术！ |
| UVModule | tilesX=1,tilesY=1（整贴图，非翻页动画） | |
| 颜色变体 | maxGradient 后段含橙金/紫/青/粉（a=0，变体储备） | "CrystalSparks - 1..5"、"Goblet1Color1" 等 283 个变体 |

**视觉结论**：药工水晶闪光 = 冷白蓝小点、原地出生、靠颜色渐隐快速亮起缓慢消失。
没有位移、没有金色（金色是我之前脑补的）。

## 6. Godot 复刻实现映射

| 药工组件 | 本项目实现 | 对应关系 |
|---|---|---|
| CrystalSparksBase（挂 5 个 -1..-5 强度变体粒子系统） | `crystal_sparkles.gd`：`attach_to()` 循环创建 5 个 GPUParticles2D 子节点，areaFactor [6.0,4.5,2.25,1.5,0.75] | ✅ 5 子系统结构对齐；配色 [主色,白,金,青,粉] 去重 |
| ParticleSystemsGroup.UpdateGroupEmission（面积驱动速率） | `compute_rate(tier, area, areaFactor, jitter)` = tier × AF × mesh_area × SpawnRate × jitter；mesh_area = clamp(轮廓面积×0.12, 0.008, 0.35) | ✅ 公式对齐原版 UpdateGroupEmission；jitter 按子系统构建时各取一次等价于每帧随机 |
| SpriteParticleApplier（精灵上挂粒子） | `AmbientSparkleSpawner`（每 0.5s 扫描 `resource_node` 组，视野内补挂 CrystalSparkles） | 资源点=水晶洞对应物；增加视野门控防全图数百节点同时挂载 |
| shape.mesh（区域发射） | `emission_shape = POINTS` + `sample_host_points()` 轮廓点集（Sprite2D 按 alpha / Polygon2D 三角化内采样 / ColorRect 网格；空点集回退 RECTANGLE）+ `measure_host()` 面积测量（shoelace） | Mesh→POINTS 点集等价（药工是美术手绘多边形，粒子只出生在轮廓内）；5 子系统共享同一份点集 = 原版共享同一 mesh |
| startColor RandomBetweenTwoGradients（白↔主题色） | `color_initial_ramp`（Gradient 两键 a=1） | ✅ 等价；全程不透明无渐隐 |
| SizeModule 脉冲曲线（Hermite 0→0.97→0.42） | `_build_size_curve()` 七点采样 → `scale_amount_curve`（Curve）× 0.203（贴图 scale） | ✅ 还原"长出→缩回→硬切"脉动 |
| startSize 0.13 单位 | 64px 贴图 × scale_curve 峰值 ≈13px | 一致 |
| 无重力无速度 / prewarm+looping | direction/gravity 全零；preprocess=lifetime（tier20 除外）；one_shot=false | 一致 |
| 池化（GlobalParticleSystemsPool） | `FxPool`（group "fx_pool" + 数组复用） | 一致 |
| IngredientVisualEffect（交互蹦闪，采集/投掷用） | `modules/fx/scripts/ingredient_visual_effect.gd` + `ingredient_visual_effect_controller.gd` | 逐字段逐行翻译——**保留未接入玩法**，待采集系统 |
| 全局闪光开关 | 待接（可参考设置面板"闪光"开关） | |

关键 Godot API 注意（2026-08-29 起水晶闪光用 **CPUParticles2D**，原因见附录 B 表"附带"行）：
- CPUParticles2D 的 `color_initial_ramp` / `scale_amount_curve` 直接吃 **Gradient / Curve**（GPU 版才要 GradientTexture1D / CurveTexture 包装）
- **Godot 4.4+ 把 GPUParticles2D 的点集发射改成了 `emission_point_texture`**：位置编码进纹理像素、配 `emission_point_count` 使用；旧的 `emission_points` 数组属性已删，赋数组直接报 Invalid assignment。CPUParticles2D 的 `emission_points`（PackedVector2Array）不受影响
- CPUParticles2D **没有 rate_over_time 属性**，连续速率 = amount/lifetime（与 GPU 版同）
- CPUParticles2D 默认 `gravity = (0, 980)`，原地闪烁粒子必须显式置零；`direction/spread/initial_velocity` 同理
- `measure_host()` 是公开静态方法，AmbientSparkleSpawner 直接复用避免重复测量逻辑
- 宿主面积→mesh 面积做了上下限截断（MESH_AREA_MIN/MAX），防止巨型宿主把速率顶到失控
  （药工的发射 mesh 是美术手绘的小块区域，大面积宿主在原版里是多挂几个小块而非一个大块）
