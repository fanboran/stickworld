## 二、根因分析（代码侧事实）

> 行号对应当前 main 分支实测，均已核实。

- **A1｜M 图小圆点**：不是运行时画的点，是 L3/L2 渲染器的**城市 blob 团块层**——`l3_map_renderer.gd:500-503`（T2+ 城 ×0.12 缩放，468 个团块缩成点状）、`l2_map_renderer.gd:280-283`（×0.3）。`l3_political.png` 贴图本身干净（都城标注/图例只画在验收预览图上，`state_expand_lite.py:680-703`）。
- **A2｜L1 两模式相同**：`map_renderer.gd` 的 `map_mode` 字段（:22）存而不用——`_draw()`（:307-436）对模式**零分支**，地形模式回退到政权色填充（`_data.get_state_color`，:360/:541），与政治模式同源同色。F1 实装时 L1 无地形底图可用，回退口径遗留至今。
- **A3｜地块边缘马赛克**：L1 地块多边形来自栅格标签提取的**整数像素台阶轮廓**（楼梯状折线），且 Godot `draw_polygon` **没有 antialiased 参数**（官方文档核实，见 §7.4）——数据级锯齿 + 渲染级无 AA 双重叠加。「城市格子」观感同源：每个城市地块一个纯色多边形直边拼接。
- **A4｜建成区显示口径**：blob 层三视图全画（L1 :361-379 / L2 / L3），不区分模式；L1 政治模式也画。
- **A5｜建成区圆滑+灰色**：`settlement_blob.gd` 轮廓 = 16 方向容量射线 + 谐波基底 + Catmull-Rom 插值 72 点——数学上就是一条**光滑径向闭合曲线**，无分形细节、无沿路手指、无多中心；填充色 `BLOB_FILL Color(0.62,0.57,0.50,0.92)`（暖灰，三渲染器同值）。
- **A6｜图钉/大点/描边不重合**：玩家图钉 = 程序绘制拟物图钉（三角尾针+圆头+白点+「你在这里」文字，`map_renderer.gd:488-514`，文字用 `ThemeDB.fallback_font`）；城市中心点 = 白心黑环 3px 圆（:399-410）；当前城市描边 = **整地块多边形**的流动描边（`_build_glow_outline`，:230-237）——与城市本体轮廓（settlement.position 处的 blob）**几何不同源**，所以不重合。
- **A7｜道路虚线+圆滑弧线**：渲染端 DIRT 路按弧长切 dash/gap 画虚线（:327-330、:623-643），PAVED 实线；两者都是单色 `draw_polyline`。生成端 P3.5 的 Dijkstra 代价模型本身没问题（方向性坡度+TPI+噪声，业界同构，见 §7.2），问题在：① DP 抽稀+插值后小尺度弯曲被抹平；② 渲染无 casing 分层、无宽度分级、无贴地形明暗。
- **A8｜UI 不统一**：地图绘制层全部自带色值/线宽字面量（map_renderer :63-129 一批 const），未接入 `StickTokens`（UI 侧 `BORDER_W=1`、`RADIUS=3/6`、`ACCENT` 等 token 体系）；地图标注字体未走 `StickTheme`（StickHand）。
- **A9｜35 国**：`state_params.json` 按文化圈数推导国数（每圈按 cap_per 拆分），35 是参数结果不是上限；扩容需种子策略（城市种子而非地块种子）+ 面积分布目标 + 命名表扩容（世界观 §6.1 现成 35 名）。
- **A10｜技术栈**：现状 = Python 离线生成（numpy/PIL/skimage）→ JSON/bin → Godot 运行时。L3/L2 = 预烘焙 PNG 贴图 + 矢量叠加；**L1 = 纯 `_draw` 运行时矢量**。检讨见 §三。
- **A11｜弹窗 BUG（已修）**：`travel_dialog.gd` 根节点用 `set_anchors_preset(FULL_RECT)` 只设锚点不设偏移，而它是 CanvasLayer 直下的顶层 Control（初始矩形 0 不会被动重算）→ 根与遮罩恒 0 尺寸；窗口居中只挂 `_window.resized` 信号回调，触发时遮罩还是 (0,0) → 居中算出 **负坐标**（复现实测 `win.global=(-200,-378)`，窗口一半在屏幕外左上角）。headless 复现 + 修复 + 回归测试已落地（R0）。

## 三、技术栈检讨

**结论：混合栈方向正确，错在 L1 把「静态观感层」放进了运行时矢量。**（依据 §7.4，业界三重印证：P 社 = 高度图地形 + 每政权一色 province 色图 + shader 边界；Godot 开源大战略项目（OpenGS 等）= ID mask + SDF/JFA shader；程序化地图社区（Red Blob mapgen4）= WebGL 程序化着色。没有一家用运行时 `_draw` 画静态政权/地形层。）

| 层 | 现状 | 问题 | 调整方向（R9） |
|---|---|---|---|
| L3/L2 静态底图 | 离线烘焙 PNG | 无（B2 已验收） | 保持 |
| **L1 静态观感**（地块填色/边缘/河流/道路本体/建成区填充） | **运行时 `_draw` 矢量** | `draw_polygon` 无 AA（引擎无此参数）、无纹理感、观感上限低、色值线宽散落 | **移入离线烘焙管线**：per-L1 分模式烘焙分层 PNG（2x 超采样 AA），运行时贴图 |
| L1 动态交互（hover/选中/路由高亮/玩家标记/tooltip） | 运行时 `_draw` | 无问题 | 保留矢量（可升级政权 ID mask + shader） |
| 数据 | JSON + bin（LWDB） | 无 | 保持 |

`_draw` 性能本就不是瓶颈（绘制命令缓存，官方文档），真正的短板是**观感上限**——这也是创始人观感验收全线不满的技术根源。

## 四、修复方案（R 系列）

> 每项含：目标观感 → 方案要点 → 改动面 → 验收口径。均为「提案/待定」，逐项过创始人观感验收。

### R0 ✅ 旅行弹窗布局 BUG（已完成，本档前置提交）

根因与修法见 A11：`set_anchors_preset` → `set_anchors_and_offsets_preset`（根/遮罩）；窗口居中改锚定方案（PRESET_CENTER + 双向 grow），删 resized 时序回调。P0 集成测试补几何回归用例（遮罩铺满视口/窗口居中不出屏），全过。

### R1｜M 图去城镇标记

- **目标**：L3/L2 上没有任何城镇点状/团块标记；城市信息只靠政区色与（未来的）国名/都城标注表达。
- **方案**：删 `l3_map_renderer.gd` 与 `l2_map_renderer.gd` 的 blob 团块层（含烘焙 mesh 代码）。L2 政治模式贴图本就干净，无数据改动。
- **改动面**：运行时两渲染器；图例条目同步删「城镇建成区」（L3/L2 分支）。
- **验收**：M 键 L3 两模式 + 下钻 L2，画面无点状元素。

### R2｜玩家位置标记与当前城描边重做

- **目标**：抽象「所在地」表达——中心点 + 静态细环 + **向外扩散淡出的脉冲环**（GPS 范式，见 §7.3-4）；无拟物图钉、无文字标注。当前城描边与城市本体轮廓**共用同一几何**（blob 轮廓），彻底重合。
- **方案**：删 `_draw_player_pin`；复用现有 `flow_outline.gd`（A3 期流动描边工具）做脉冲扩散环（半径 1→1.5R、alpha 衰减、周期 ~1.5s）；中心 4px 圆点（玩家色，白描边）。当前城高亮从「整地块多边形」改为「该城 blob 轮廓」流动描边。
- **改动面**：`map_renderer.gd` 单文件；色值走 token（R8 一并做）。
- **验收**：Tab L1 大图看脉冲扩散标记；当前城描边与城市建成区轮廓逐像素重合。

### R3｜L1 地块边缘平滑（数据级根治）

- **目标**：地块多边形边缘无像素台阶，圆滑但不假圆。
- **方案**（§7.4-2.1 管线，Python 生成端）：栅格标签提取从整数轮廓换 **skimage `find_contours` 亚像素等值线**（0.5 阈值线性插值）→ **Visvalingam 抽稀**（保形状减点）→ **Chaikin 切角 2 轮**；关键约束：在**共享边界弧**上统一平滑（边界存弧、多边形由弧拼装，TopoJSON 思路），否则相邻地块独立平滑会开裂/重叠。三区交界顶点锁定。
- **改动面**：生成端轮廓提取工具 + 重跑 L1/L2 视图包烘焙 + 刷 bin；运行时零改动。
- **验收**：Tab L1 大图地块边缘放大无阶梯；相邻地块无裂缝/重叠；特写对比图交验收。

### R4｜L1 模式语义分离（地形 / 政治 / 交通）

- **目标**：L1 三个模式画面截然不同（提案，模式名待定）：
  - **地形**：群系着色底图（B2 同管线 per-L1 裁切烘焙）+ 河湖 + 城市建成区（卫星式，R5）+ 城市名标注。**不显示道路**。
  - **政治**：政权色地块填充 + 分级界线 + 都城标注；**不显示建成区、不显示道路**。
  - **交通**：地形底图 + **道路网（R6）+ 建成区**——对应创始人「建成区在显示道路的模式里才需要」（C2/C18）。
- **方案**：L1 渲染器按 `map_mode` 真分支；静态层走 R9 烘焙管线出 per-L1 分模式贴图（地形/交通两张，政治可矢量或烘焙待实现时定）；`MapModeManager` 枚举从 TERRAIN/POLITICAL 扩为三态（数字键 1/2/3，模式条同步）。
- **改动面**：生成端烘焙扩 per-L1（70 包 ×2 变体，L1 窗口 798~1038px，2x 超采样体积可控）；运行时渲染器分支重写；HUD 模式条。
- **风险**：包体积与加载——L1 按需加载已是现状，增量可接受；实现时量测。
- **验收**：三个模式画面互不相同；建成区只出现在地形/交通模式；图例随模式换内容。

### R5｜城市建成区重做（场叠加管线 + 卫星式填充）

- **目标**：建成区像真实城市——分形粗糙边界、沿道路手指状延伸、多中心粘连、内部空隙；填充有卫星感（建筑噪点/隐约路网/裸土晕圈），从周边群系色派生；**废除暖灰平涂**。
- **方案**（§7.1-3.2 场叠加管线，Python 离线）：`U = a·核场(cap(θ)调制) + b·道路条带场(沿路指数衰减→手指) + 卫星种子高斯 + fBm(2-3八度)`，乘水体/陡坡排除层，阈值 τ 按目标面积（population_score）反解；marching squares 出多环（外环+内环空隙+飞地），形态学清理，shapely simplify。填充纹理分层烘焙（底色派生/泊松盘屋顶噪点/主路方位网格线/边缘晕圈）进 per-L1 烹饪贴图（R9 管线）。L3/L2 不再画任何建成区（R1 已删）。
- **动态生长**（population_score 变化）：提案——每城烘 3 档 s 水平（小/中/大）贴图，运行时按分数档切换+平滑过渡；`settlement_updated` 单城刷新保留。若创始人认为静态一档足够则更简。
- **改动面**：生成端新工具（blob_bake v2）+ 重烘 per-L1 贴图 + 刷 bin；运行时删 `settlement_blob.gd` 径向轮廓的 L1 用法（跨端同源单测随之改写）。
- **验收**：特写四城与真实卫星图（Google/Esri 同比例）并排盲测；「格子感/圆滑感」消失；出生 L1 与 3 个不同群系 L1 抽查。

### R6｜道路重做（生成端自然化 + 渲染端制图化）

- **目标**：道路是「地图上的路」——实线、有宽度分级、贴地形明暗、路口规整；平原近直带微波、山区保留之字折角；**废除虚线**（虚线只保留给快速旅行的路由高亮 UI）。
- **方案**：
  - 生成端后处理（不重搜路，1107 条折线就地加工，新工具 `road_naturalize.py`）：等弧长重采样（步长≈路宽 0.5-1 倍）→ 法向噪声位移（世界坐标采样，低频 80-200px 摆动 + 高频细碎，幅度随等级与坡度衰减）→ 仅滑动平均去毛刺、**禁样条平滑**；陡坡段（>15%）保留之字锐折角锚点；可选按流量重算三级（官道/干道/土路）写入 tier。
  - 渲染端（烘焙进 R4 交通模式贴图）：**casing 双层**（深棕底 + 赭土面，面宽按等级 官道 3px/干道 2px/土路 1.2px @8192 尺度换算），路面乘 hillshade 明暗贴地形，端部在城门处收尖；路口低级让高级。全战 Rome 2 战役图为观感参照（§7.2-§4）。
- **改动面**：生成端新工具 + 重写 roads polyline + 刷 bin；运行时道路层改为贴图的一部分（动态高亮层保留矢量琥珀线，正是虚线/强调线的正确语用）。
- **验收**：交通模式特写三图（出生平原/山地穿行/跨河）对照 §7.2 验收清单：山路之字可见、路面随地形起伏明暗、全图无「圆滑弧线+均码虚线」。

### R7｜政权扩容（35 → 80~120）

- **目标**：政权数量与 1040 城/69 地块的规模匹配，大小悬殊自然（Zipf 型），边界贴河线山脊。
- **方案**（§7.4-1，不换算法族）：种子改**城市种子**（人口 top-N + quadtree 间距），N 按目标两档（80/110）参数化；每国随机 `expansionism` 系数 → 面积幂律分布；扩张代价加高程带重罚（山脊）+ 河流径流罚（边界停驻在河/脊上，无需事后 snap）；`normalize` 多数邻域翻转消飞地；都城星标 + 国名标注兜底可读性（80+ 国不可能纯色相区分，靠界线分级+标签，见 §7.3-2）。
- **命名**：世界观 §6.1 现成 35 名不够。提案——命名生成器（词根/后缀组合，E-1 装备设计已预留接口）批量生成，**全部标「提案/待定」**交创始人审订后入世界观；或创始人直接扩写王国表。**待裁决**。
- **改动面**：`state_params.json` + `state_expand_lite.py` 扩展 + 重跑政权管线（贴图/注入/刷 bin）；L3/L2 标注层（都城星标+国名，R8 字体规范）。
- **验收**：新版 `political_preview_2048.png` + 游戏内 L3 政治模式；抽查 10 国边界是否贴河/山脊；相邻国色可区分（色相×明度双差校验）。

### R8｜地图 UI 统一（token 化 + 标注规范）

- **目标**：地图上的一切线条/颜色/字体与游戏本体 UI 同源，达到「原生 UI」感。
- **方案**（§7.3-6 规范表）：
  - 线 token：`map.line.national`（3px 实线）/ `map.line.region`（2px 长虚线）/ `map.line.plot`（1px 短虚线）/ `map.line.city`（1px）/ `map.line.player`——全部映射到 `StickTokens.BORDER_W/BORDER/BORDER_STRONG` 档位，定义进 map 模块 token 或 StickTokens 扩展，**禁止渲染器内字面量**。

### 7.1 城市建成区轮廓生成与卫星式渲染

#### 结论速览

1. 真实建成区轮廓的本质特征是**分形粗糙 + 沿路各向异性 + 多中心粘连**；圆滑径向多边形三者全缺，这就是「不像」的根源。
2. 不必上完整的 SLEUTH 型 CA 仿真；**离线 Python 里「场场叠加 → 阈值 → marching squares」**一条管线即可同时拿到路手指、破碎边界、内部空隙，代价最低（R5 采用）。
3. 道路折线是现成的最强「形状先验」：把道路做距离场条带（指数衰减宽度）注入密度场，城市立刻「长手指」。
4. 内部空隙（绿楔/裸地洞）**需要**，是卫星观感的关键；飞地（独立小斑块）由轮廓提取自然产生，直接保留。
5. 卫星感 = 分层烘焙：建成区底色脱饱和暖灰、蓝噪屋顶斑块、与主路方位对齐的淡网格线、边缘裸土晕圈——离线烘 PNG，Godot 只贴图+描边。
6. 可复用库全部在 Python 侧现成：skimage(find_contours/morphology) + shapely(union/simplify/interiors) + opensimplex(fBm)，无需引入重型依赖。
7. 政治图隐藏建成区是正确决策（避免政治色+灰斑脏），数据层保留 mask 即可。

#### 1 真实建成区轮廓的可量化形态特征

- **分形（破碎）性**：盒计数法测得边界维数 D_b 典型 1.2–1.5、面积（质量）维数 D_m 典型 1.7–1.9（伦敦/卡迪夫等案例见 Fractal Cities；方法学见 Chen & Fu 2023）。含义：轮廓在多个尺度上都有细节，单频正弦扰动无法复现，需 2–3 个八度的噪声。
- **沿路延伸（手指状）**：路网是城市化骨架。Strano 等 200 年米兰北部路网数据表明：高中心性道路百年稳定充当「骨架」，增长由两个基本过程组成——既有街区内部加密（densification）+ 沿既有干道向外扩张（expansion）。游戏映射：道路折线所在方向必须有建成斑块拖出，且越远离锚点越细。
- **多中心粘连**：真实「一个城市」常是多个簇的并集。JRC DEGURBA/GHS-SMOD 用连通密度阈值定义城市中心（连续 1km 格网 ≥1500 人/km²、总人口≥5 万；城镇簇 ≥300 人/km²、≥5000 人）——「簇合并」是官方方法；对游戏即：卫星城斑块与主城用并集/形态学闭运算粘连，而非单轮廓。
- **受地形与水体制约**：GHSL/GUF 类产品都以「排除层」（水体、陡坡、保护区）硬否决建成像元；SLEUTH 的 exclusion layer 同理。已有 capacity(θ) 的正确用法是把它从「半径调制器」升级为「2D 排除/成本层」，参与逐像元判决。
- **数据集方法学参考**：GHSL built-up surface（多时相光学，30–100m 级）；GUF（TerraSAR-X 雷达 12m，逐像元后向散射判决）；夜间灯光 VIIRS（~500m，城市范围代理，已知过曝光/光晕偏差，勿直接模仿其「糊成一团」的观感）。

来源：Fractal Cities（Batty & Longley 1994，专著）；Chen & Fu 2023（arXiv:2308.04062）；Strano et al. 2012（https://www.nature.com/articles/srep00296 ，DOI 10.1038/srep00296）；GHSL 门户（https://human-settlement.emergency.copernicus.eu/）；GUF：Esch et al. 2017（DOI 10.1016/j.isprsjprs.2017.10.012，开放获取）；VIIRS：Elvidge et al. 2017（DOI 10.1080/01431161.2017.1342050）。

#### 2 程序化生成算法族盘点

- **2.1 元胞自动机城市增长（SLEUTH 谱系）**：格网五系数（坡度/土地利用/排除/城市/交通）驱动扩散-自修改生长。适用性：**方向正确但过重**——其 exclusion+交通层思想必收；完整仿真只在未来要「城市随回合动态生长」时才需要。来源：Clarke, Hoppen & Gaydos 1997（DOI 10.1068/b240247）；开源移植 sostenibilidad-unam/sleuth_automation。
- **2.2 DLA/受限扩散凝聚**：游走粒子粘到聚合体上长出触手状分形（2D D≈1.71）。适用性：**不适合直接用**（无道路先验、纯随机、难控制面积-人口关系），但其「边界概率粘附」可用于给边缘加碎渣。来源：Witten & Sander 1981（DOI 10.1103/PhysRevLett.47.1400）；Batty 系列城市 DLA 论文（DOI 10.1068/a211447）。
- **2.3 先路后城（road network growth → 街区填充）**：先长路网，城市沿路「结块」（张量场/L-system/最短树）。适用性：**我们条件反着来**——1107 条道路折线已存在，只需「沿路结块」（路→密度场→街区）。来源：Chen et al., Interactive Procedural Street Modeling（SIGGRAPH 2008，DOI 10.1145/1399504.1360702）。
- **2.4 Parish & Müller《Procedural Modeling of Cities》/ CityEngine 谱系**：L-system 街道图→块细分→地块放楼。适用性：**不适合 L1 轮廓问题**（3D 城市建模，输出是建筑；我们要 2D 足迹），但「人口密度图驱动路网生长 + 地形否决」思想与 capacity 模型同构。来源：DOI 10.1145/383259.383292。
- **2.5 多中心合并：metaball / Minkowski / 形态学**：每颗种子放高斯，Σ阈值=等值线提取，天然圆滑粘连。适用性：**必用**——卫星城、沿路斑块合并的标准件；圆滑问题由边界噪声与道路手指弥补。`field(x)=Σ A_i·exp(-|x-c_i|²/σ_i²)`，skimage.measure.find_contours 一行出多环。来源：Blinn 1982（DOI 10.1145/357318.357320）。
- **2.6 边界噪声扰动（多倍频角向噪声/中点位移）**：对等值线点列叠加 2–3 八度 fBm，幅度随倍频衰减，逼近分形 D_b。适用性：**必用**，去「圆滑感」的最后一公里；幅度比周期小得多，且在「路手指」段减弱。

#### 3 推荐设计（R5 采纳）：场叠加管线

```
输入: anchor, cap[16θ], roads[](城市周边折线), pop_score, water_mask, slope, biome_id
输出: 建成区多边形集合(含 holes), 供烘焙贴图

1. 本地栅格 W×W (W≈3×R_max, R_max=f(pop_score): T1 大 T3 小)
2. field_core = exp(-d²/2σ²) × cap(θ_d)          # 保留容量调制, θ_d=相对锚点方位
3. field_road = Σ_r exp(-d_r/w_r) × 沿路长度衰减   # 每条路做条带场: 宽随离锚点距离衰减→"手指"
4. seeds      = 主城 + 沿路 2~5 个卫星点(距锚点 0.5~1.5R, 避开水体)   # 多中心
5. U          = a·field_core + b·field_road + Σ seeds(高斯) + 0.15~0.25·fBm(2~3八度)
6. U          *= exclusion                        # 水体/陡坡硬置 0 (SLEUTH 式否决)
7. mask       = U > τ ;  τ 由目标面积反解: area(mask) ≈ g(pop_score)  # 保住数值平衡
8. mask       = binary_opening(1) → binary_closing(2)   # 去孤点/连近斑
9. contours   = find_contours(U, τ)               # 多环: 外环+内环(holes)+飞地
10. polygons  = shapely.Polygon(外环, holes=内环); simplify(1~2px, preserve_topology)
   保留: 面积>阈值的外环全收; holes 面积>2%~4% 城区才留   # 内部空隙=绿楔/裸地
```

关键参数直觉：a:b≈1:1.2（路略强于核，手指才明显）；fBm 倍频 ω≈6/12/24 px⁻¹；T1 城可允许 seeds 生成「卫星镇」。

#### 4 卫星感填充分层

1. **底色调色**：建成区=脱饱和暖灰/米灰，工业区偏蓝灰；**始终从周边群系色派生**（群系绿→城区灰绿调，荒漠→沙灰）；外围 2–4px 更浅裸土/尘霾过渡晕。
2. **屋顶斑块噪点**：蓝噪（Poisson disk）撒 1–3px 矩形，密度∝pop_score 且随距锚点距离衰减，矩形**长边对齐主路方位角**。
3. **隐约路网**：1px 线、8–20px 间距、不透明度 10–20%，方向=主路方位±90°，只在 mask 内绘制。
4. **工业/低密差异**：T1 城外围大尺度蓝灰斑块（仓库区）；T3 村庄只做底色+稀疏噪点。

烘焙 vs 运行时：**离线烘 PNG（R9 管线）**；运行时 shader 噪声可行但性价比不如烘焙。参考：Red Blob Games mapgen4（https://www.redblobgames.com/maps/mapgen4/ ）。

### 7.2 道路生成与制图渲染

#### 结论速览

1. **「圆滑弧线无地形感」的主因不在 Dijkstra，而在后处理与渲染**：RDP 抽稀+样条平滑把代价模型算出的小弯抹掉了；渲染端单色 draw_polyline + 虚线进一步抹平「路感」。业界（Far Cry 5 GDC、Galin 综述）管线与我们同构，差距在「路径自然化后处理」和「制图式分层描边」两步。
2. **土路不该是虚线**：地形图惯例虚线=步行小径/轨迹；OSM 标准样式里土路（track）是**实线棕色 #996600**。土路应改「细+暖棕+低对比」实线。
3. **casing（先粗底后细面双层描边）是让路「像地图上的路」的头号技法**，OSM/Google/纸质地图全在用。
4. **贴地形的立体感来自与 hillshade 一致的光照**：路面乘局部地形明暗 + 路缘定向阴影。
5. **生成端只需重做后处理，不必重算路径**：重采样+低频噪声横向位移（幅度随等级衰减、随坡度缩减），山区保留之字折角。
6. 路网级无需重建：现有路网按「流量」离线重分级为干道/支道/土路三级，纯 numpy 可算。
7. 游戏参照：全战 Rome 2 道路=贴地形浅土色缎带、宽窄渐变、无虚线无 casing；虚线在战略图上只用于「行军路线预览」类 UI。

#### 1 路径生成与自然化

- **真实道路几何**：干线最大持续纵坡约 5%-8%，山区路在等高线间迂回拉长坡距逼出之字形；平原绕行系数（路长/直线距）仅 ~1.1-1.3 近乎直带小弯，山区 1.5-2.0。路沿等高线走、河垂直等高线走，交叉处天然是桥/渡口选址。来源：gamedev.SE 59314（https://gamedev.stackexchange.com/questions/59314/procedural-river-or-road-generation-for-infinite-terrain ，已验证）。
- **cost-based 搜路业界做法**：Galin et al. "Procedural Generation of Roads"（CGF 2010，DOI 10.1111/j.1467-8659.2009.01612.x）——主流管线=地形代价图搜路+几何细化，证明我们生成端方向正确。Far Cry 5（GDC 2018, Etienne Carrier）/Ghost Recon Wildlands（GDC 2018）同样在「坡度+噪声+地物」代价上搜路，**路感来自后续雕刻与贴地渲染**。
- **路径自然化后处理（直接答案）**：
  - 抽稀阈值控制：tol ≤ 最终显示路宽的 1/4，或改「保留弯曲的滑动平均 + 等弧长重采样」。
  - 重采样后**法向噪声位移**：步长≈路宽 0.5-1 倍；value-noise 按世界坐标采样（共线路段/路口偏移一致不穿帮）；低频波长 80-200px 给大摆动、20-40px 高频给细碎弯；幅度按等级衰减（土路 4-6px、官道 2-3px）；坡度大段幅度 ×0.3-0.5。位移后仅一次窗口=3 滑动平均，**不做样条平滑**。
  - 山区之字 = 陡坡段保留 60-90° 锐折角（检测行进方向与等高线夹角 >60° 标记「不可圆滑」锚点）。
  - 手绘地图风「噪声边」：全图线共用同一低频噪声场扰动（Amit Patel trade routes：https://www.redblobgames.com/blog/2025-05-08-mapgen4-trade-routes/ ，已验证；Azgaar FMG：https://github.com/Azgaar/Fantasy-Map-Generator ，已验证）。

#### 2 路网级生成

- MST + 绕行系数加边（未来重生成的基线）；交通流/betweenness 迭代升级（Strano et al. 2012，DOI 10.1038/srep00296）——可离线给现有 1107 条路重算等级，不动几何；等级路网：枢纽城先布干道，其余就近挂接。

#### 3 制图渲染

- **casing**：每条路两层——casing 底（比面宽 +2×(0.3~1)px）+ 面层；路口低级让高级。OSM carto `roads.mss` 实测值（已验证）。
- **宽度随等级**（线宽=有序视觉变量）：官道 3px / 干道 2px / 土路 1.2px（8192 尺度换算）。Axis Maps visual variables（已验证 https://www.axismaps.com/guide/visual-variables ）。
- **实线/虚线语义**：正式道路（哪怕土路）实线；虚线=小径/隧道/行军预览。OSM carto track=#996600 实线（已验证）。
- **配色**：路面色比地形亮一档、casing 比地形暗一档（地形图/古地图用赭、橙棕、红褐——罗马官道惯例用红）。
- **贴地形**：路面乘 hillshade 明暗（0.85-1.15），路缘 1px 定向阴影（Imhof《Cartographic Relief Presentation》原理）。
- **Godot 能力**：Line2D 支持 width_curve 收尖、ROUND joint、渐变色；**不支持原生虚线**（TILE 贴图或 dash shader）；draw_polyline 无宽度变化/圆角连接，不适合当路网主力（官方文档，已验证）。

#### 4 游戏先例

- **Total War Rome 2**（截图已验证）：贴地形浅土色缎带、宽窄渐变、贴等高线绕行、无 casing 无虚线——「地形自然感」的业界样本，模仿对象。
- CK3 1.9+ 旅行系统点线表现（未核）；EU4 基本无道路图层；Mount & Blade 大地图道路极淡（弱表现，不适合我们）；Civ 道路是瓦片附属物（几何不适用）。
- **共性**：战略图道路本体一律实线、有宽度层级、贴地形、低调配色；虚线只出现在 UI 语境（行军/旅行路线预览——恰是我们快速旅行高亮的用法）。

#### 5 落地清单（R6 采纳）

生成端：等弧长重采样 → 法向噪声位移（等级/坡度调幅）→ 陡坡之字锚点保留 → （可选）流量分级。渲染端：casing 双层实线 → 土路改实线暖棕 → hillshade 明暗乘法 → 端部收尖 → 缩放 LOD。验收：平原路近直带微波、山路之字明显、路面明暗随地形、路口规整交叠、全图无「圆滑弧线+均码虚线」。

### 7.3 制图学与地图 UI 最佳实践

#### 结论速览

1. **城镇符号由比例尺决定**：小比例尺（L3）用分级点或不画点，大比例尺（L1）用面符号（建成区轮廓即符号）。创始人的两个判断（M 图去圆点、L1 去大圆点）与制图学惯例完全一致——点和面同时画是双重表达，典型错误。
2. **「当前位置」用抽象动态圈**：业界惯例「中心点 + 精度圈/脉冲扩散圈」（GPS 蓝点范式）；图钉（pin）语义是「待去的目标/收藏点」，不是「我在这里」。
3. **35 国设色可行但已近纯色相区分上限**；80+ 政权必须「色相分组 × 明度分组 + 边界线分级 + 标签」组合编码，颜色只负责大类归属（P 社政治图对数百国即如此）。
4. **边界线是比颜色更强的区分手段**：OSM carto 线宽分级（国 1.2→8px、州 0.4→4px）+ 虚线模式分层 + 白色底衬。
5. **标注**：字号分级（相邻层级差 ≥2pt）+ 白 halo（≈字号 1/6~1/5）+ 缩放显隐阈值；地图标注复用游戏 UI 字体，仅以字重/字号/字距分层。
6. **描边线 token 化**：Design Tokens 思想 + Godot Theme Type Variations（官方机制）。
7. 四色定理只是下界不是规范：4 色保证拓扑可分离，不保证可读性；实践用定性色板 + 相邻冲突检测。

#### 1 城镇符号（点 vs 面）

- 制图学原则：密集建成区「省略单体、用面状色调表达」，仅孤立小聚落用点（USGS 地形图规范原文：dense areas → area tint，https://pubs.usgs.gov/gip/TopographicMapSymbols/ ，已核）。
- 点符号适合「附着于点的数量数据」（人口分级），分 3~4 档而非连续缩放；拥挤时改面表达（Axis Maps Proportional Symbols，已核）。
- 首都惯例：星形符号（OSM carto place-capital 星标 + 标签偏移）或同色系重点+粗字重。
- **映射**：L1 建成区面填充+细内描边即符号，首都加小星标；L2 重镇 2-3 档方点；L3 不画单城点，只画首都/都会点+国名。

#### 2 政区设色（80+ 国）

- 类别区分靠色相，明度/饱和度留给同类有序子集（本土深/占领浅）；类别数 3~7 类；界线粗细比填充色更值得打磨（Axis Maps Choropleth/Using Colors，已核）。
- 色盲安全：Okabe-Ito 8 色板（https://jfly.uni-koeln.de/color/ ，已核）；ColorBrewer qualitative。
- 80+ 国业界做法：邻国强制色相/明度双差；同色相集团用明度阶梯；斜条纹表附庸；界线分级+国名标签兜底。颜色只承诺「区分相邻与归属」，从不承诺唯一标识每国。
- 界线分级数值可抄 OSM carto admin.mss（国界线宽 1.2→8、州 0.4→4、县 1→2.1，配递减虚线 pattern，白色底衬线，已核）。

#### 3 标注

- 两步法：智识分级（国>省>首都>大城>小镇）→ 视觉分级（字号/字重/大写/字距/颜色）；相邻层级字号差 ≥2pt；面要素大写+拉字距；点标签锚点优先序右上>右下>左上>左下（Axis Maps Labeling，已核）。
- 防压盖：碰撞检测+优先级（Mapbox symbol-sort-key/variable-anchor 模式，已核）；显隐缩放阈值表（OSM carto：国家 z3、省 z5、城市 z6-8、村镇 z12-14，已核）。
- halo：白/深 1.5-2px。
- 字体统一：不另配字体，UI 主字体 + 字重/字号/字距三轴变体（Design Tokens，https://www.designtokens.org/ ，已核）。

#### 4 「当前位置」标记

- GPS 范式：中心点+半透明精度圈+方向锥（Apple HIG 系统蓝点）；脉冲扩散圈=「活的位置」通用动画语言（地图 App/小地图雷达/RTS 光环），纯 2D 矢量成本极低。
- 语义区分关键：pin=目标/收藏（输入意图），当前位置=观察者（输出状态）——业界因此用「点+圈」而非图钉。创始人要的「一圈+向外扩散轮廓」正是标准组合。
- 建议形态：中心 4px 圆点（玩家国主色，白描边）+ 静态 1px 环 + 每 ~1.5s 扩散淡出环（半径 0.5→1.5R，alpha 0.5→0）。

#### 5 战略游戏地图 UI 模式

- P 社：地图模式=底图整体重着色，切换条固定位置小图标列，每模式自带图例；附庸=宗主色+斜条纹；地图内 UI 克制到只剩旗帜/数字/标签。
- Civ6：lens 系统同构（左下按钮条+数字键+整图覆色+非 lens 信息淡出）；城市用 banner 非裸圆点。
- 共性规律：①地图内所有控件是游戏本体 UI 同款（同字体/圆角/线宽/色板）；②模式切换=换色不换形，符号层稳定；③图例与模式绑定，非常驻大图例。
- 技术路线：token 化 + Godot Theme Type Variations（官方文档已核）。

#### 6 符号规范建议表（R1/R2/R7/R8 采纳，提案/待定）

城镇表现：L1=建成区面填充+内描边 1px（复用 UI border 色），城市描边与地块描边共用同一折线几何，首都 8px 星标；L2=重镇 6/4px 两档方点（圆角复用 UI token）；L3=只画首都星标+国名。
当前位置：中心 4px 点（玩家国主色+白描边）+ 12px 半径 1px 环 + 1.5s 周期脉冲（12→36px，alpha 0.5→0）；禁拟物图钉与文字。
政区设色：定性主色相 12 组（Okabe-Ito 校验）× 明度 2-3 档；生成后贪心图着色校验相邻色冲突；界线三级（国 3px 实线 / 地区 2px 长虚线 / 地块 1px 短虚线，全部 map.line.* token）。
标注层级：国名 18px Bold 全大写字距 15% / 省名 14px Medium / 城市 12px（首都 13px Bold），白 halo，显隐随层级。
描边 token：`map.line.national`(3px 实线) / `map.line.region`(2px 长虚线) / `map.line.plot`(1px 短虚线) / `map.line.city`(1px) / `map.line.player`(1px 玩家色)——禁止地图模块内硬编码色值与线宽。

### 7.4 领土划分、边缘平滑与 Godot 技术栈

#### 结论速览

1. **「L1 边缘马赛克」根因在数据端**：整数像素台阶轮廓。换 skimage `find_contours`（marching squares + 亚像素线性插值）→ Visvalingam 抽稀 → Chaikin 切角，且在**共享边界图**上统一平滑（独立平滑会接缝开裂），一步消除阶梯（R3 采纳）。
2. Godot 4 `draw_polygon`/`draw_colored_polygon` **无 antialiased 参数**（官方文档源码核实）；只有 `draw_polyline` 有且仅 width>0 生效。填充多边形 AA 只有三条路：MSAA 2D（仅 Forward+/Mobile）、**离线烘焙带 AA 的 PNG**（正解）、SDF/着色器。
3. **政权扩容不需要换算法**：同族算法（多源扩张+地形代价+均衡）加：城市种子 + 每国随机 `expansionism`（自然产生 Zipf 型大小悬殊）+ 面积反馈迭代 + normalize 翻转消飞地。
4. **边界贴地形 = 扩张代价项**：山脊高程带重罚（FMG：山 2200/丘陵 300）+ 河流径流罚——边界自动停驻在河线山脊，无需事后 snap。
5. 业界路线 = 高度图地形 + 每政权一色 province 色图 + shader 邻接检测画边界；开源 Godot 大战略项目（OpenGS JFA-SDF 等）同路。
6. **推荐分工（R9 采纳）**：静态观感层全部离线烘焙 PNG（L1 也不例外，4x 超采样或 pycairo 出 AA）；动态交互层=政权 ID mask（8bit 索引承载 255 政权）+ 片元着色器；`_draw` 只留军队箭头等逐帧动态。
7. 运行时 `_draw` 性能不是瓶颈（命令缓存+预三角化即可）；真正短板是观感上限。

#### 1 领土划分（35→80~120）

- 均衡多源区域生长（现状家族）：FMG `states-generator.ts` 实测同族——`totalCost = p + 10 + cellCost/expansionism`，首都按人口×随机+quadtree 间距，扩张后 normalize() 翻转「≥2 异国邻居且少于同国邻居」的格子消飞地（https://github.com/Azgaar/Fantasy-Map-Generator/blob/master/src/generators/states-generator.ts ，已抓取全文核实）。
- Weighted Voronoi：现状 MCP 测地场 argmin 数学上即 additively weighted geodesic Voronoi；把 w_i 升级为「目标面积驱动」动态项：`w_i ← w_i + η·log(当前面积/目标面积)` 迭代 3-5 轮逼近目标面积（Balzer & Lewerentz SIGGRAPH 2009，DOI 10.1145/1531326.1531392）。
- 分层划分：国→省同一算法跑两遍，省级标签定位用 pole of inaccessibility（FMG provinces-generator.ts 已核实）。
- 数量与尺寸：目标政权数由城市总数按幂律反推；面积 `A_rank ∝ 1/rank^s`（s≈0.8-1.1）；**种子=城市（burg）而非地块**——69 地块支撑 ~100 国的前提。
- **最小改动路径（R7 采纳）**：①种子改城市人口 top-N+间距；②代价加高程带+河流径流；③expansionism 随机系数+w_i 面积反馈；④normalize 翻转；⑤同套代码跑省级。全部生成端，Godot 端零改动。

#### 2 栅格→矢量边缘平滑

- **数据级（治本，R3 采纳）**：`find_contours` 亚像素等值线（注意 fully_connected 对角歧义）→ Visvalingam 有效面积抽稀（保形状，比 DP 更适合地图线；Bostock simplify：https://bost.ocks.org/mike/simplify/ ）→ Chaikin 切角 2-3 次（收敛二次 B 样条，凸角略收缩需轻微外扩补偿；Chaikin 1974，DOI 10.1016/0146-664X(74)90032-8）。
- **共享边界**：边界抽成「弧」结构存储、平滑作用于弧、多边形由弧拼装（TopoJSON 思路），三区交界顶点锁定——否则 69 地块独立平滑开裂/重叠。
- Catmull-Rom 只用于河流/道路线条，不用于政区边界（边界要共享）。
- **渲染级（治标）**：MSAA 2D 仅 Forward+/Mobile（Compatibility 无效，官方教程核实；坑：SubViewport issue #84406）；双层描边遮盖是土法应急；SDF 边界着色器（JFA）是动态层正解（OpenGS：https://github.com/Thomas-Holtvedt/opengs ）。
- **结论：锯齿在数据里，不该在渲染端救。**

#### 3 技术栈对比（R9 依据）

| 路线 | 观感上限 | 性能 | 动态性 | 判定 |
| --- | --- | --- | --- | --- |
| (a) 运行时 `_draw` 矢量 | 低（填充无 AA、无纹理感） | 中（命令缓存够用） | 优 | ⚠️ 仅留动态元素 |
| (b) 离线烘焙分层 PNG | 高（cairo AA、纸纹/晕影） | 优 | 差（静态） | ✅ 静态观感层 |
| (c) Shader 程序化（ID mask/SDF） | 最高（锐利边界、辉光、模式切换） | 优 | 优 | ✅ 动态交互层 |
| (d) TileMap | 中（网格约束与有机海岸冲突） | 优 | 中 | ❌ |
| (e) SVG | 中高 | 差（无原生支持） | 差 | ❌ |

业界实证：P 社=高度图+每政权一色 provinces 色图+shader 边界；开源 Godot 大战略（OpenGS 167★/chriskilinc paradox-like/dementive gsg）无一家用运行时 `_draw` 画政权层；Red Blob mapgen4 = WebGL2 程序化着色+距离场。8bit ID mask 可承载 255 政权，正覆盖 80-120 国需求；8192 烘焙注意显存（RGBA8 ~256MB，需压缩或 LOD 分块）。

#### 4 Godot API 佐证

- `draw_polygon`/`draw_colored_polygon` 签名无 antialiased 参数；`draw_polyline` 仅 width>0 时抗锯齿（官方 CanvasItem.xml 核实）。
- MSAA 2D：仅 Forward+/Mobile；不修着色器内部锯齿（官方 2D antialiasing 教程）。
- 相关 issue：#50387（draw 命令 batching）、#117063（负宽度抗锯齿不一致）、#96573（draw_polyline antialiased 偶发断裂）、#84406（SubViewport+msaa_2d）。
- 性能语义：canvas 命令缓存、`queue_redraw()` 重绘、大量多边形建议预三角化（class_CanvasItem 官方文档）。
