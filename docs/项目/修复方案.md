## 第 2 章 · 批次 A1：测试超时修复

### 2.1 问题

`tests/run_all.sh` 的 `DEFAULT_TIMEOUT=45s`，而集成套件串行实测 33~58s；并行 6~8 下 CPU 争用进一步放大 → 默认配置全量跑出 **12 通过 / 12 失败（全部 TIMEOUT）**，且 `test_formation_presets`（串行 54.3s）在默认超时下**必然红**。文档"全绿"声明因此不可复现。

### 2.2 步骤

1. **串行实测** 12 个默认超时套件的墙钟耗时（当前已实测 3 个：ai_behaviors=33s / melee_combat=41.8s / formation_presets=54.3s；其余待测）
2. **补 `SUITE_TIMEOUT` 表**：`max(实测×1.5, 60)` 向上取整到 5s，给全部集成套件补条目（现有 6 条保留）
3. **`DEFAULT_TIMEOUT` 45→90** 作兜底
4. 保持默认并行度 6
5. 重跑 `bash tests/run_all.sh` 目标 **25 项全绿**

### 2.3 涉及文件

- `stick-world/tests/run_all.sh`（SUITE_TIMEOUT 表 + DEFAULT_TIMEOUT）

### 2.4 验收

- 全量跑绿；输出 JSON 报告存档为基线

## 第 3 章 · 批次 A2/A3：删死代码 + 激活 BalanceConfig

### 3.1 A2 删除 `core/entities/technology_state.gd`

- 连同 `.gd.uid` 一起删除

### 3.2 A3 激活 `BalanceConfig` 装载层

- **现状**：`BalanceConfig.reload()` 在整个代码库**零调用者** → autoload 的 `data` 字典运行时恒空；`config/units/stickmen.tres`（3 兵种）产出了但从未被消费
- **改动**：`modules/world/scripts/setup/system_setup.gd` 的 `setup(root)`（第 52 行）开头加 `BalanceConfig.reload()`
- **安全性**：`reload()` 递归扫 `res://config` 只加载 BalanceResource 型 .tres；config 下 15 个 .tres 全部是 BalanceResource → 零警告零报错；headless 下 `safe_emit("balance_changed")` 有防错守卫
- **效果**：`BalanceConfig.get_value("units.stickmen.stm_plain_001.base_hp")` 等从此有数据可读

### 3.3 涉及文件

- 删除：`stick-world/core/entities/technology_state.gd` + `.uid`
- 修改：`stick-world/modules/world/scripts/setup/system_setup.gd`

### 3.4 验收
