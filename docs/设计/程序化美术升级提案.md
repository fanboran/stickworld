# 程序化美术升级提案（贴图质感层 / 3D 模板滤镜 / 背景纵深）

> **状态：提案**（AI 分析生成，未经创始人定稿）。创始人已确认的前提：
> 现有九宫格贴图烘焙管线（`手绘贴图烘焙管线.md`）很满意、AI 可驾驭；
> 问题在它是"低质感 UI"（纯色大色块、色彩单调），上限一眼望到头；
> 地平线硬截断（地面材质 + 天空二分）是当前观感最烂的点。

---

## A. 九宫格贴图管线的质感层升级（回应"上限低咋办"）

**方案：管线不动、层数升级。** 同一 PIL 烘焙脚本，在底色之上叠三个确定性图层：

| 层 | 做法 | 说明 |
|----|------|------|
| 纹理层 | fbm 纸纹/颗粒（对比度 ≤2%，红线：肉眼盯三秒才隐约察觉的程度） | 消灭塑料感；用管线已有的 cos 周期噪声做无缝平铺 |
| 光照层 | **手绘笔触式，不做渲染式明暗渐变**：断续的白色高光线（手绘高光惯例）+ 排线/叠涂阴影——是"画法"不是"光照算法" | 渲染式光照会带来非手绘感；只画在九宫格边带与角区（中心纯色拉伸区不参与） |
| 材质变体层 | 槽位配方加"材质"字段（纸/木/金属做旧/漆） | 黑玻璃主视觉不变；材质只用于点缀（纹章、大界面框）；每层克制，宁少勿多 |

**色板**：已落地为基础设施 `StickTokens.CONTENT_PALETTE`（20 色，**从游戏贴图盘点派生**——地面草地/背景树线/远山/木建筑/资源图标的实际用色，红紫为补缺并从语义红派生；每色标注来源，派生方法见 01-设计语言 §2.6）。取色 API：`content_color()` / `content_color_at()`；验收图 `temp/palette_review.png`。作用域 = 全局内容色（含 3D→滤镜管线的 LUT 量化目标），非全屏后处理；仍守"琥珀唯一强调色"纪律——内容色不参与操作引导。

每层都是确定性算法 + 离线烘焙 + 三关自检不变——依然是 AI 能驾驭的范围。质感来自全局约束（统一光源/色板/噪声参数/描边规格），不是特效堆叠。

## B. 3D 模板 → 手绘滤镜线（Blender 生图，回应"这种算法好做吗"）

**基础版好做**，是成熟技法的组合：

- Blender 侧：Toon BSDF（色阶量化）+ Freestyle 描边线渲染（直接输出线条感）+ 单一低角度光照
- PIL 后处理（复用烘焙管线哲学与质检）：**色板 LUT 量化**（渲染色吸附到游戏 12 色板——与全游戏统一的保证）+ 线宽扰动（复用沸腾 wobble 公式）+ 纸纹叠加

难点与近似解：真手绘笔触的方向性（笔顺结构走）→ 边缘法向扰动 + 马克笔线宽抖动已够用，追求极致才需手调。

**已验证（2026-09 徽章样张，`temp/gen_badge_3d.py` + `compose_badge_3d.py`，样张 `temp/badge_3d_preview.png`）**：bpy 程序化建模（圆柱令牌+倒角+浮雕环+锤母题）+ 单左上光源 + Principled 直色（视觉色需转线性 `**2.2`）→ 渲染 → PIL 墨线（alpha 轮廓膨胀-腐蚀差 + 复描偏移）+ 纸纹。全链路脚本化可行。**踩坑记录**：① Blender 4.5 已移除 Freestyle，描线必须在渲染后滤镜做；② EEVEE Next 不支持 Shader to RGB（toon 节点静默失效），需 toon 分档时用 Cycles 或干脆 PIL 后处理量化；③ 脚本管线里 ColorRamp/多输入材质颜色偶发不生效，材质越简单越稳（Principled 直改 Base Color 最可靠）；④ `render.film_transparent` 偶尔不生效，背景透明可由后处理抠色兜底（均匀灰底好抠）。

**卡线路线（2026-09 图标样张，`temp/gen_icon_ink.py` + `compose_icon_3d2d.py`，样张 `temp/icon_3d2d_preview.png`）**：手绘质感第一要素是**卡通卡线**，用 **Grease Pencil LineArt 修改器**在渲染时几何生成（轮廓/折痕/交线，非后处理近似）——锤子/爱心样张跑通。管线：建模（3/4 视角可爱比例）→ LineArt 卡线（thickness/noise 抖动）→ EEVEE 渲染 → PIL 裁剪放大 + 色阶量化平涂 + 纸纹。**4.5 API 踩坑**：GP 对象须 `bpy.ops.object.grease_pencil_add(type='EMPTY')` 创建；修改器枚举名是 `LINEART`（非 `GP_LINEART`）；GP 材质用 `materials.new()` 默认节点组改 Principled 基色即可；部分属性（use_noise）需 hasattr 探测。

**小图标规格（终版 v9，分尺寸 LOD 版，`temp/gen_icon_v9.py` + `compose_icon_small_ui.py`，成品 `temp/icons/`）**：① **分尺寸渲染（render-per-LOD）**：每个显示尺寸（64/128/256）独立渲染（2x 超采样）+ 独立线宽/细节参数——**大图缩放是『256 好看缩小糊』的总根因**，线宽/色带宽度是显示像素域概念；② 细节 LOD：64px=3 档色+仅外轮廓零内线（WoW 可读性原则：大色块+单轮廓）、128px=3 档+材质组结合缝、256px=3 档+全部 ID 边界；线宽 1px（64）/1.3px（128）/1.5px（256）；②b **面烘色 cel（手绘铁律：平面一面一色，曲面才渐变）**：平面着色网格在渲染端按「面法线·主光方向」量化三档灰烘进 FACE 域顶点色（单材质+Attribute 节点），每面恰好一色、朝向不同色不同；曲面（球/胶囊/环/曲线管）保持真实光照——sphere 的球形渐变由此而来。compose 侧配套：轮廓 AA 环腐蚀采样域 + 明度 p5/p98 拉伸 + 一维 k-means 三簇分档 + 单面物体（明度展宽<0.15）退化保护走固定阈值；禁止任何「往平面上打渐变」的方案（径向假光等）——会把平面劈成斜向色阶；③ 单主光光向梯度 + 径向假光衰减（光心=左上，`L×(1−k·dist)`，心 k=0.45 锤 k=0.20）——平面朝相机的形体真实光照无内部差，径向衰减使分档边界=围绕光源的圆弧（手绘阴影形态）；k 过大整体掉暗档；④ 明度模糊半径随尺寸（target×0.03）；⑤ 材质 ID 锁色（双 pass：ID 先渲防钳零，shade 后渲）；⑥ 实体二值 alpha（≥128）；⑦ 描边最终尺寸上画+高斯 0.6 AA；⑦b **超分抗锯齿**：保留 2x 渲染原生软 alpha + BOX 面积平均缩放到显示尺寸（无振铃；边缘环填最近部件色防黑边），描边绘制不受影响；描边宽度档 ICON_STROKE（1/1.5/2px 可选，默认 1px）；⑧ 像素级精确居中（四边距打印验收）；⑨ 验收图棋盘格底**图标在底板上居中**（贴左上角会被误判为偏移）；⑩ Blender 5.2 坑清单沿用。

**v9.1 关键修复（黑脸总根因，2026-09）**：`cam.matrix_world` 在设置 location/rotation 后、depsgraph 更新前读取是**陈旧单位阵**——主光被放到世界坐标 (-3,2.6,2)（心形正后方），正面全黑。修复=读矩阵前 `bpy.context.view_layer.update()`；主光位置改为对象坐标系（原点+屏幕左上+相机侧 0.6）。照明类问题的标准定位手段=**头灯实验**（主光置于相机位沿视线打——面向相机的面必亮；亮=位置错，黑=渲染链路断）。心形亮度平衡：主光能量 7.0（平面脸受光少）+ 径向衰减 k=0.45。注意：`gen_icon_v9.py` 曾因多轮 sed 追加残留重复渲染块，**后块覆盖先块输出**（无能量循环覆盖 7.0 版）——脚本尾部需唯一，勿叠块。

**图标分辨率调研（2026-09）**：Steam 成就图标显示尺寸=**64×64**（上传即 64×64 PNG；Steamworks 官方文档页未明示，开发者社区公认值，搜索引擎本轮被过滤未能二次核验）；WoW 接口图标 **32×32**（小图标可读性行业标杆）；主流游戏 UI 图标主力显示尺寸 32/48/64，128/256 为图集母版。→ 结论：**64px 才是这类图标的本体尺寸**，256 只作母版/商店素材；小图标的可读性来自大色块+单轮廓，不来自大图缩小。3D→2D 卡线管线的行业做法（技术常识，未能网验）：线宽定义在目标显示分辨率、每尺寸独立渲染、小尺寸强制简化细节。

**基本体回归测试套件**（`temp/gen_icon_v9_primitives.py`，2026-09）：立方体/正球/圆柱/圆锥/圆环 ×3 尺寸过完整管线，验收=直读 64px 原图（读大图会压缩，小图标看不清——创始人明确的工作方式）。首测结果：cube/sphere/cylinder/cone 全过；torus 首测失败（默认平躺、孔不朝相机→侧边椭圆），旋转 80° 修复——**建模朝向错误与管线无关，但只有套件能暴露它**。此后管线任何改动必须先过基本体套件再上正式图标。

**LineArt 结论（实测证伪）**：Grease Pencil LineArt 修改器在 4.5（GP3 架构）下，无头与带窗口两种模式均不生成笔画（GP-only 渲染 0 可见像素；source_collection 已正确指定）。待 GUI 人工排查；不阻塞图标管线——图像级边缘检测（Sobel+alpha 轮廓边带）完全满足小图标需求，且线宽控制更直接。

**用途定位**：**全部位走此管线**——背景图/城市剪影/宣发插画，以及**小图标（含纹章母题）**。小图标走管线的理由：① 风格统一（同一 LUT/线宽/纸纹）；② 小图标建模简单（模型遍地皆是，转 2D 相当于洗稿出统一风格）；③ 直接让 AI 画 2D 简笔矢量质量不可控。一致性来源 = 同一色板 LUT + 同一线宽规格 + 同一纸纹。建模素材优先复用公共模型库。

## C. 背景纵深与地平线（消灭"地面材质横截断 + 天"）

现状（已核实）：`sky_decor.gd` 已实现 Terraria 反编译直译的多层视差背景（远山×2 + 树线×3 + 云三档穿插 + modulo 回绕平铺）与地平线雾带（GradientTexture2D 大气透视层）；**贴图为 Terraria XNB 提取的占位资产**（已登记素材替换清单）。创始人观感结论仍是"地平线处最烂"——雾带是"盖住生硬交界"的补丁，不是"消灭地平线"的方案；且正式版必须换自有资产。已排除的方向：纯侧视（打架观感退化 + 沉没成本 + 大世界难融入）、纯俯视（不对味）。**方案不动核心视角**：

0. **SWL 背景逆向已完成**（创始人提供 APK，UnityPy 解包，见 [`../技术/参考逆向/SWL背景逆向笔记.md`](../技术/参考逆向/SWL背景逆向笔记.md)）：SWL 每关一张 1024 级**手绘背景板**（地平线/原野/河流画在板内，板内自带雾化衔接）+ 透明条带层（2048 宽树线、512 横条云带、小山条）多实例平铺做视差，背景层还放远景装饰小人。贴图仅逆向参考，不入游戏资产
1. **程序化整板背景（核心修正）**：按生物群系参数离线烘焙整张背景板——"天空渐变 + 远山剪影 + 原野 + 河流 + 地平线雾"画进一张板里（PIL 管线，同九宫格贴图的烘焙+质检哲学）。地平线处有内容物、且内容物边缘自带渐变，才是"消灭地平线"的正解；比多层条带+运行时雾带补丁更接近 SWL 观感
2. **条带层做视差纵深**：树线/云带/山条分层生成（透明底、**底部 alpha 渐变带为固定输出规格**——SWL 的层间衔接画进贴图里，不靠运行时过渡），挂 sky_decor 既有的 modulo 平铺机制
3. **背景层远景小人**（SWL 同款技巧）：程序放置的远景火柴人剪影在背景层走动/劳作——"世界活着"的感知成本极低
4. **城市天际线层**：村落/城地图的板内加程序生成屋顶轮廓（随机高度 + 窗户点光）
5. **纯俯视操作画面（大后期）**："挥斥方遒"的宏观操作走纯俯视战略图直接指挥（战略图是既有架构）；横版伪俯视管微观与战斗——两视角各司其职，对应无缝缩放支柱。不急于做

1~4 全部程序化：剪影 = 多边形 + 噪声扰动（SketchDraw 已有 wobble 公式），天际线/河流 = 参数化随机生成，每关不手绘。
