# 科技系统（技能本位）

## 一句话

科技不是进度条，是长在具体火柴人身上的技能：谁会造剑，剑才能被造出来；谁受过的训练到位，才能上战场。

## 目的

消灭"点按钮等倒计时"的抽象科技——技术跟着任务本身：要有会的人，事情才做得成。科技的全部内容是一张平铺的技能清单（像物品表那样），不构成树。

## 一、核心原则

1. **科技＝个人技能**：没有阵营科技池这种实体，只有"某人会某事"。会/不会二元——无等级、无熟练度（复用收益的熟练度归构筑谱系 [`11-构筑谱系系统.md`](11-构筑谱系系统.md) 管，两系统分工不重叠）。
2. **知识随人走**：人来了技能才来；持有者死光又没人接上，技能就失传。敌人也会获得你的技能——扩散是时间问题。
3. **技术跟着任务**：依赖长在配方与工序里，不长在技能上——造一把剑需要"有人会锻造"＋"有人把料运到"，而不是"先解锁锻造科技"。没有技能树。
4. **技能门槛是特例，不是默认**：多数东西人人能用、粗活人人能干；哪些东西需要哪种技能，由物品/建筑/组织的定义**显式标注**，没标的就是无门槛。
5. **阵营科技＝派生视图**："我国会造什么"＝活人技能清单的聚合查询，不是一份独立状态。
6. **界面＝组织呈报**：技能台账（哪个部门有多少会什么的人、缺口在哪）由具体组织呈报——组织越后期越复杂庞大，台账的操作精细度越高（组织呈报原则，GDD §七）。

## 二、技能三类

| 类别 | 是什么 | 起什么作用 |
|------|--------|-----------|
| **制造技能** | 会制造某物（铁剑、砖、马车、建筑构件） | 配方与工序标注所需技能，由持有者亲手执行——对接"生产到工序"（GDD §1.4） |
| **使用技能** | 会使用某物（战斗、弓、法杖、攻城器械、载具） | 物品定义标注"需技能"才设门槛，默认人人能用；法术是其中一个子类（会施放某法术），消耗液态法力口径不变 |
| **组织技能** | 建立特定组织的前置本领 | 某些组织/架构只能由**拥有相应技能的人**建立；组织另有非技能约束（如需支撑组织已存在），归 [`01-组织系统.md`](01-组织系统.md) 管 |

三类只是清单上的标注，不构成层级。战斗是使用技能的典型：军队的新兵要先经训练才能上战场——但具体哪些武器设技能门槛，由武器定义标注决定。

## 三、技能怎么来

| 途径 | 说明 |
|------|------|
| **出身自带** | 开局追随者各带一点本领 |
| **得人** | 知识随人走的直接面：征服（打下城市→城中人口的技能为你所用）、人才（俘获/招降/投奔名师匠人）、事件（遗迹探索、特殊事件） |
| **训练** | **组织职能**：军队练新兵、教育组织批量教人。教的人与学的人都真实占用编制与时间；学满即会，没有成功率；中途断了就是还没学会 |
| **研究** | **组织职能，任何阶段可用**：早期也可以靠研究组织获得技能，不只是后期。研究产出的新技能先长在研究员本人身上，再经训练扩散 |

训练线（训练营、学校）与研究线（科学院→研究所→研究室→课题组）都是用通用组织系统搭出来的——不存在独立的"科技建筑"或"科技按钮"。研究消耗教育资源；花多少编制和物力在训练与研究上，是帝国的核心权衡：投入不足则无才可用，过度则挤占生产。

超大型技能攻关（高级法术、奇观工艺）不是独立机制——就是把研究组织堆到很大：海量资源与编制持续投入、全国物资可能被挤兑短缺、指挥水平不够则长期停滞。玩家体验的是亲自主持一项超大型攻关组织的难处。

## 四、组织与技能互相咬合

- **组织产出技能**：训练与研究都是组织职能（见 §三）。
- **技能开启组织**：组织技能是建立组织的个人前置——想搭某种架构，先得有人会。这与"组织结构本身就是制度"是同一条脉络。

## 五、阵营查询口径

"会造 X 吗"＝阵营内存在活着的持有者。持有者在不在场、能不能赶到前线，交给物流与组织的物理约束判定——技能系统只回答"有没有人会"。

已获技能的图谱化展示（技能源流、流入路径、携带者标注、谁教谁）见 [`11-构筑谱系系统.md`](11-构筑谱系系统.md) 技术谱系图。

## 七、制度（组织结构本身）

不存在独立的"法律系统"——制度就是组织结构的形态本身（GDD §七）：层级、槽位、章程、头衔怎么搭，制度就是什么。组织技能（§二）作为建组织的个人前置，正是制度与技能互相咬合的一环。
