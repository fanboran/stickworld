# 武器装备系统与个人库存（需求存档·待架构设计）

> **状态**：创始人需求已口述（2026-09-06），**架构设计尚未开始**——本文档只记录需求原文
> 与待答问题，供后续模型做架构设计时从这里起步。设计完成后本文档扩充为正式设计文档。

## 一、创始人原始需求（口述记录）

> 「记载一下武器装备系统了，而且每个火柴人都要独立的特定记录了……就是每个角色现在
> 都有自己背包和穿戴的装备栏了。」

拆解为三条硬需求：

1. **武器装备系统**立项（此前仅有 `StickmanState.equipment_template` 预留字段，无系统设计）。
2. **每个火柴人都有独立的特定记录**——个体不再是纯数值模板的实例，而是有独立档案的实体。
3. **每个角色拥有自己的背包 + 穿戴的装备栏**——库存（背包）与装备（栏位）是个体数据结构
   的一等公民，不是组织/仓库级的聚合资源。

## 二、已知现状（设计前必读）

- `core/entities/` 的 `StickmanState` 已预留：`equipment_template`（装备模板）字段，
  `max_hp`/`attack` 等属性注释了「受种族+装备影响」——新系统需与此对接而非另起炉灶。
- 经济系统（`docs/设计/系统/05-经济系统.md`）与物流系统（06）管理的是**仓库级**资源流动；
  本系统是个体级库存，边界要在架构里划清。
- 战斗系统（02）的装备影响口径：攻击/防具/血量加成进入战斗数值的方式需重审。
- 存档：个体库存会显著放大存档体积（帝国级 1000-10000 个火柴人 × 背包内容），
  存档方案（SQLite/SaveManager）如何承载是硬问题。

## 三、留给架构设计的开放问题（设计时回答，本档不给答案）

1. 装备栏位模型：有哪几个槽位（武器/防具/饰品/弹药？），火柴人种族/畸变个体（巨人/半人马）
   是否有差异化槽位？
2. 背包容量与格子模型：固定格数还是重量/体积制？与组织仓库、物流系统的存取规则？
3. 装备实例化程度：装备是有独立耐久/词条的实例，还是模板+数量？掉落/制造/修理闭环？
4. 「独立的特定记录」的边界：个人档案除装备外还含什么（战绩/伤病/特质/姓名描述法命名？）
   ——与世界观 §3.2 描述法命名规范对齐。
5. 千人级规模的性能与存档：个体库存的数据结构（脏标记/分层存档/惰性序列化？）
6. UI：个体装备面板的组织入口（选中单位面板？），与既有 UI 模板体系的接入点。
7. 与 Demo 剧情的挂钩：剧情稿中「装备/生产链解锁」节拍（story-lab STORY-DEMO.md §5
   生产链）如何消费本系统。

## 四、验收口径（架构设计的完成标准）

- StickmanState 的装备/背包字段定义与读写路径明确，兼容既有存档迁移；
- 战斗数值入口（attack/max_hp 等）消费装备的方式有定稿；
- 10000 个体规模下存档/读档/查询的性能方案成立；
- 与经济/物流系统的边界有明文（谁管仓库、谁管口袋）。
