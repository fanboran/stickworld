### 2. 旋律重写：从"一条主题的十几种讲法"改成"每曲一条自己的旋律"

创始人 2026-09-29 两轮指正：先是"全库共用一条「原野主题」，听下来全是变奏"，
再是"不用有统一性，就全新旋律就可以"——因此连标题画面与白天原野这两处
原本共用「原野主题」的地方也各写了新旋律，那套素材已删除。

改法（口径同步进了 [音乐设计文档.md](../../设计/音乐/音乐设计文档.md) §三）：

- 新增 `tools/music/compose/themes.py`：**14 条原创旋律**，每条带 2~3 种 8 小节乐句、
  32 小节曲式、**自己的和声骨架**，以及**每条乐句自己的推荐八度**（不同乐器的舒适
  音区不同）；
- 标题画面与白天原野的旋律**各自一条**（`menu` / `field_day`），和声骨架也各一条——
  原先共用的「原野主题」（`YUANYE_A/B/C` / `THEME_A/B/C` / `render_form`）随之删除，
  引用一起清干净（见 §五 踩坑 1b）；
- **昼夜不再共用旋律**：`field_night`、`village_night` 各自成篇，亲缘改由
  "同一支钢琴 + 同一族和声骨架 + 相近的速度与呼吸"承担；
- **三个轮换族的两个成员旋律不同**：轮换的意义从"换主奏"变成"换一首歌"；
- 统一性从"共用旋律"移交给**和声骨架 + 编制纪律 + 制作口径**（设计文档支柱 2 已改）。

### 2b. 和声骨架：每首一条，走出"卡农全家桶"

创始人 2026-09-29 三轮指正："不用只卡农吧，还有哪些经典旋律？和声的话也是。"

改法：把和声骨架从"4 条全库共用"改成**每首曲子在 `themes.py` 里自己声明**
（`Melody.harmony`），并按经典套路逐曲分配——14 条旋律用了 **13 条不同的骨架**：
丸サ進行（标题）、三度下行链（白天原野）、カノン進行（仅竖琴那一首）、
自然小調循環（原野·夜）、ポップパンク/axis（小镇）、田园骨架（小镇·木琴）、
自然小調カノン（夜镇）、小室進行 + 变格终止（灯下）、王道進行 + 变格终止（厅堂）、
ドゥーワップ/50s（远望）、出征骨架（出征一族）、アンダルシア（余烬）、
标点骨架（入主）。整个清单与逐曲分配写进设计文档 §四 /
[乐曲清单.md](../../设计/音乐/乐曲清单.md) §三.6 / [作曲技法参考.md](../../设计/音乐/作曲技法参考.md) §二。

换骨架会打破"旋律音在原和弦上的落点"，因此配套加了两件事：

- `compose/check_melody.py` 先查（本批据此改了 9 处真撞音：多数是"四音压三音"，
  一条是荒原的双簧管句 Whole 重排）；
- `compose/annotate_melody.py`（新增）按骨架重写谱面注释里的和弦功能——
  注释里写着"这个音是 III 的五音"这类**结论**，换了和声就成了谎话，
  而谎话的注释比没有注释更坏。本批一次同步 266 行。

源码侧同时收口：`cues.py` 的伴奏一律读 `mel.harmony`（22 处调用点），
换骨架只改 melodies 里的一行；`common.SKELETONS` 保留一份定番条目库供新曲取用。

### 3. 写谱自检（新增，渲染前跑）

`python tools/music/compose/check_melody.py` —— 查四类问题：调外音、和声避讳音
（降九音 / 四音压三音）、音区、留白。本批据此改了 5 处真问题，并刻意放行 3 处
弱拍经过音（有级进解决）。它是"代码能判的错误不许靠渲染发现"这条纪律在作曲侧的落地。

### 4. 运行时接线（本批未动，承接上一批）

`CUE_FOR_MAP_TYPE`（`BATTLEFIELD → battlefield`、`MEGA_INTERIOR → interior_hall`、
`village + night → village_night`）、轮换族（`VARIATION_SETS` → 清单 `variation_sets`

## 二、几个关键决策（为什么这样做）

1. **不追求"全库统一"**。旋律 14 条各自成篇，和声骨架也各写各的（只有同一场景族
   的成员共用骨架，如小镇/小镇·木琴、出征一族/余烬）；全库相通的只剩实用口径——
   响度、高通表、空间配方、编制纪律（钢琴为主、每曲一件独奏木管、打击只做点状）。
   口径统一是为了"混起来不打架"，不是为了风格。
2. **八度写在乐句上，不写成全局常量**。同一个级数在钢琴、长笛、双簧管上的舒适音区
   不同，D 大调又比 G 大调低 5 个半音——全局常量必然让某些声部跑出乐器音域
   （`themes.py` 里每条乐句都带 `transpose` + `register` 说明理由）。
3. **和声避讳音只禁两类**：降九音（根音上方半音）与四音压三音（大三度上方半音）。
   九音、大七音、六音（含小调自然六音）都是本作的常用色彩，禁掉会把好写法也判成错。
4. **交接乐句时主奏整段闭嘴**。小镇的长笛接第 3 乐句时钢琴不唱，荒原的双簧管应答时
   钢琴整段让位——"留白优于铺满"在配器层的用法，比两件乐器一起唱干净得多。
5. **轮换族成员旋律不同，但调性/速度/长度/层名相同**。这是运行时整层替换无缝的前提
   （由 `test_music_director` 的族契约测试守住）；旋律不同正是轮换抗疲劳的意义。
6. **战场与战斗、昼与夜：同骨架不同场合**。它们不共用旋律，共用的是和声骨架与
   调性——D 小调 i-VI-III-VII 既能写成 104bpm 的推进，也能写成 66bpm 的凭吊。

## 五、踩坑（本批实测）

1. **写谱自检的规则不能照"任意半音相邻"写**：第一版把"小三和弦上的九音""小调自然
   六音"这类惯用语汇全判成撞音（13 处误报）。收成两类（降九音、四音压三音）后
   只剩 5 处真问题——**会报案子的检查器比不检查更危险**，因为它逼你改好写法。
1b. **换掉的素材要连引用一起清**：删「原野主题」时，`common.py` 的再导出、
   `check_melody.py` 的招牌适配器、`render_form`、三份文档的旋律表都要同步删；
   留一处就会在别人的会话里变成"这里到底该用哪个"的谜题。
1c. **和声骨架也该由旋律声明**：原先 `cues.py` 把 `C.CANON` 直接递给伴奏，
   而旋律又声明一遍 `harmony`——两处会漂移。改成伴奏一律读 `mel.harmony` 后，
   换骨架只改一个地方（本批 22 处调用点一次性收口）。
2. **`octave` 与 `transpose` 是两件事**：乐句字段本意是"移调半音数"，第一版按
   "八度个数"写成 `12*octave`，钢琴旋律直接被顶到 **D16**（MIDI 206）——
   自检里的音区一栏立刻暴露。字段名已改成 `transpose` 防止再犯。
3. **中文文本里的半角引号会截断 Python 字符串**：`register="…靠长音"打开"）"`
   让文件直接语法错。`themes.py` 里 12 处需改成全角引号（`“打开”`）。
4. **用脚本改文件头时别把 `from __future__` 留在中间**：按行号拼接后两份文件头叠在
   一起，`common.py` 报 "from __future__ imports must occur at the beginning"。
   改大段文件头宁可整段重写，也别做"前半段替换 + 后半段拼接"。
5. **渲染"空轨"守卫不能只看开头**：晚进的层（`field_day` 的钟琴从第 16 小节 ≈53s
   才进）前 30s 安静，读一段会把正常层误判成空轨——必须取**整曲**峰值。
6. **双簧管别写高八度**：主题句自身若已升八度（落点 D5~B5），再 `transpose=12`
   会顶到 B6——又薄又刺，实测整曲刺耳度从 0.08 跳到 0.24。
7. **`travel_started` 是三个参数**（from/to/mode）：回调签名不一致时 Godot 报参数错、
   回调静默不执行，"抵达标点从不触发"。
8. **新建 worktree 必须先跑一次编辑器导入**（`godot --editor --quit`）：
   否则 `load()` 拿不到刚写出的 OGG（`.godot/imported/` 是 per-worktree 的），
   测试会以"层播不起来"的形式失败。改过 OGG 内容之后也要重导一次。
9. **worktree 里可复用主工作区的工具链**：
   `MUSIC_TOOLCHAIN_DIR=F:/VSCode/game-2/temp/music_toolchain`（否则要重下 515MB）。
10. **单曲重渲（`--only X`）会把中间报告与清单一并写成单曲版**——要保留全量清单就得
    重跑全量，或先备份清单再还原。
11. **试听样带必须带"按曲配平"**：`preview.py` 的混音路径同样要吃
    `LAYER_BALANCE_BY_CUE`（已接）。否则轮换曲的层平衡与游戏内不一致——
    会出现"试听好听、进游戏不一样"这种无法对齐的差别（样带存在的意义就是消灭它）。
12. **两处配平触到 ±15dB 钳位**（`field_day_b/bells`、`battle_b/winds`）：这是 mix 的
    保护钳位（"超出说明层渲染有问题，不该靠增益硬补"）。若观感验收觉得 bells 太闷或
    oboe 太抢，正确做法是调**编曲**（力度/音区），不是放宽钳位。
