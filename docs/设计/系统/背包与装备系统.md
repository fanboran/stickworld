# 背包与装备系统

> 模块位置：`modules/inventory/` · 分支：`agent/inventory-equipment`
> 对应执行计划：P9 批次 10（AI复刻执行计划 §P9）

## 一、是什么

玩家（附身主控）拥有一套 RPG 式装备体系：

- **装备栏 5 槽**：头部 / 胸部 / 腿部护甲 + 主手武器 + 副手盾牌。弓是双手武器——装弓时副手锁定、盾自动卸回背包。
- **格子背包**：MC 式 24 格（4 行 × 6 列）。**背包只收三类物品**（用户定稿）：装备（不堆叠，一件一格随意存）、矿物（可堆叠限量：石 50 / 铁 30 / 金 20 / 钻 10）、绷带等消耗品。**建造材料不进背包**——材料是实体搬运物，拿起时占用双手（不能攻击/举盾/空挥），走区域仓库与工地交付链路。
- **底部 Hotbar 常驻物品栏**：三组布局，格子下方标注按键——

```
[主手|左键] [副手|右键]   [1][2][3][4]   [交互F] [脱困H] [背包E] [属性C]
 └── 战斗组(装备镜像) ──┘  └─ 物品组 ─┘   └──── 动作组(快捷键) ────┘
```

- **按 E 开关背包界面**（模态，自动暂停）：左侧装备人形槽位 + 右侧背包格网，点击拿起/放下，右键智能穿脱。
- **按 C 开角色属性面板**（模态）：生命 / 五属性（力量·智力·敏捷·工艺·指挥，出生掷骰 10±3）/ 战场情绪 / 伤痕状态（激活状态效果列表）/ 装备概览。**不显示名字**（火柴人无名氏，用户定稿）。

武器不再由数字键 1-5 直切——**换武器 = 开背包换装备**，战斗端由既有 `WeaponMount.weapon_type` 单点驱动（重挂武器模型/动画/射程/数值校准全链路不变）。

## 二、怎么设计

### 2.1 键位（变更后全表）

| 键 | 语义 | 备注 |
|---|---|---|
| **E** | 开/关背包 | 全局；模态栈有其他面板时不抢占 |
| **C** | 开/关角色属性面板 | 全局；同 E 的模态让位规则 |
| **F** | 交互（取放材料/敲击建造） | 原为 E，E 让位背包 |
| **左键** | 主手武器攻击 | 搬运材料时双手被占不可攻击 |
| **右键(按住)** | 举盾格挡 | 副手有盾时生效；搬运时同样被锁 |
| **1-4** | 使用 Hotbar 物品格 | 消耗品等；背包前 4 格即 Hotbar 物品组 |
| H | 脱困 | 不变（Hotbar 动作组显示） |
| G | 空挥 | 原 F；低频动作降级键 |
| T / B | ~~循环武器 / 盾开关~~ | 删除，被装备系统替代 |

### 2.2 数据层

- **`ItemDef`**（Resource）：`id / display_name / category / icon / max_stack / weapon_type / two_handed / stats:Dictionary / description`。`stats` 键沿用 excel 导出 `weapons.tres`/`armors.tres` 字段语义（attack_mult / speed_mult / damage_reduction / speed_penalty / heal_amount…）。
- **`ItemStack`**（RefCounted）：`def_id + count`。运行时最小单元（耐久度等后置）。
- **`ItemDB`**：静态注册表，内置 GDScript 定义是当前真相源。武器 5 / 盾 1 / 护甲 9（布·皮·锁子 × 头胸腿）/ 消耗品（绷带）/ 矿物 4（石·铁·金·钻，堆叠限量 50/30/20/10）。
  - **为什么内置表而非 .tres**：excel 管线导出的 BalanceResource 是无类型 `variables` 字典，且 `icon_path` 全部悬空；待 excel 管线支持类型化 ItemDef 后迁 `.tres`（迁移路径：ItemDB 的装载函数换数据源即可）。
  - **建造材料是刻意排除项**：材料 = 实体搬运物（`InteractionController` 的 carrying 机制），拿起占用双手（锁攻击/举盾/空挥），不占背包格——与矿物（背包可堆叠携带）是两类语义。
- **图标**：武器/盾用既有战斗贴图（`modules/units/assets/textures/weapons/`）；护甲无美术资产，格子控件按 category 程序绘简笔占位（头=圆盔 / 胸=背心 / 腿=护胫），零外部依赖。

### 2.3 背包与装备模型

**`PlayerInventory`**（RefCounted，纯数据可单测）：

- `slots: Array`（24 格）+ `equipped: Dictionary`（`SlotType → ItemStack`，5 槽）
- 操作 API：`add/remove/move/swap/equip/unequip`，全部有装备规则校验
- 信号：`inventory_changed` / `equipment_changed`

**装备规则**（校验单点在 `can_equip`）：

- WEAPON → 主手；`two_handed`（弓）→ 装入时副手锁死，已装盾自动卸回背包（背包满则整体失败）
- SHIELD → 副手；主手是双手武器时禁止装备
- ARMOR_HEAD/CHEST/LEGS → 对应槽
- 卸装备需要背包有空位/可堆叠位，否则失败并提示

**Hotbar 物品组 = 背包前 4 格**（MC 语义）：背包界面顶部一行高亮显示，两侧移动互通。

### 2.4 桥接层（inventory → units/combat）

**装备应用器**（InventoryService 内部）：监听 `equipment_changed`，写入玩家实体：

| 装备 | 写入点 |
|---|---|
| 主手武器 | `weapon_mount.weapon_type = def.weapon_type`（无武器 = `NONE`） |
| 副手盾 | `weapon_mount.shield_enabled`（有盾 true） |
| 护甲 3 件 | 聚合 `damage_reduction`（加和，硬上限 0.6）与 `speed_penalty`（乘积） |

- **`WeaponType.NONE`（新增枚举值）**：不挂武器场景、`can_attack()` 恒 false、站姿回落通用 idle。AI 单位不走装备系统，行为档案 `get_profile` 对 NONE 回落 BASELINE，零影响。
- **护甲减伤挂点**：`DamagePipeline.apply` 的"单位类型减伤"段——target 有 `get_armor_factor()` 时乘入（与雕像 0.3/巨人 0.66 同语义并列）。
- **护甲移速挂点**：实体 `_handle_acceleration` 的移速乘子链追加 armor 项（与地形/持盾乘子并列）。
- **附身边界**：附身时记录实体原始 weapon_type/shield_enabled，装备全量应用；脱离附身恢复原值。NPC/AI 实体永不感知背包。
- **武器 stats（attack_mult 等）只入数据不应用**：战斗数值由 BalanceConfig 校准管（`_apply_balance_calibration`），乱动会打破 battle_sim 回归；数据化应用留后续批次。

### 2.5 UI 层（`modules/inventory/ui/`）

- **`InventoryScreen extends StickScreen`**：模态背包。左装备区（人形轮廓 + 5 槽）/ 右背包格网（GridContainer）/ 顶部 Hotbar 镜像行。挂 `UIModalStack.Layer.INVENTORY`，白得暂停/ESC/遮罩三件套。
- **`StatsScreen extends StickScreen`**：角色属性面板（C 键）。生命条 / 五属性（实体 `attributes` 字典，出生掷骰 10±3）/ 战场情绪（WeaponMount mood）/ 伤痕状态（`StatusEffects.list_active()` 激活效果 + 剩余秒）/ 装备概览（只读格子，点击跳背包）。打开期间 0.25s 实时刷新；不显示名字。挂 `Layer.STATS`。
- **`Hotbar extends Control`**：HudOverlay 槽底部锚定（ModePanel 80px 上方居中）。战斗组格子 = 装备镜像（点击开背包），物品组 = 背包前 4 格，动作组 = 固定快捷键格（交互 F / 脱困 H / 背包 E / 属性 C，图标 + 按键字母）。每格下缘 caption 显示按键标注（左键/右键/数字/字母）。
- **`ItemSlotWidget extends Control`**：自绘格子（sketch 手绘方框 + 图标 + 数量角标 + 选中高亮 + 键位 caption）。装备槽/背包格/Hotbar 格/动作格共用；图标缺省时按物品大类程序绘简笔占位。
- 交互模型（原型阶段）：左键点击拿起/放下/交换（光标顶图标），右键智能穿脱。拖拽后续批次。
- 装配：`SystemSetup._setup_inventory()` 创建 InventoryService + Hotbar + InventoryScreen + StatsScreen，**移除旧 WeaponPanel**。

### 2.6 服务与持久化

**`InventoryService`**（Node，挂 GameRoot）：持有玩家背包，桥接附身实体，提供 `to_dict()/from_dict()`。存档接线：随存档系统玩家数据段序列化（字段就绪，完整链路验证随存档批次收口）。

### 2.7 初始物品（原型全武器开放原则）

装备：铁剑 + 木盾 + 布头/布胸/布腿。背包：长矛、短弓、铁镐、学徒法杖、绷带×5。

## 三、为什么这么设计

- **weapon_type 单点驱动复用**：换武器的全部下游（模型重挂/动画/射程/命中帧/AI 档案/站姿/数值校准）已被 `WeaponMount.weapon_type` setter 收敛，装备系统只要写这一个属性，战斗端零改动、battle_sim 零回归。
- **背包归玩家不归火柴人**：GDD 规划火柴人个体有装备，但全量 NPC 背包是工厂/物流量级的事；原型阶段背包跟着玩家走（换附身实体装备随身），NPC 侧留组织装备模板（`equipment_template`）既有占位。
- **Hotbar 三组而非纯物品栏**：本作是实时附身动作玩法，主副手绑定左右键是操作主体（泰拉瑞亚式选中-使用不适合）；数字键留给消耗品；动作组把散落快捷键可视化（用户明确要求"角色类快捷键显示图标+按键字母"）。
- **材料不进背包、搬运占双手**：材料的本质是"要被搬到目的地的实物"（SWL 矿工搬金语义）——搬运动作本身就是玩法（护送/风险），塞进背包瞬移会消解它；占用双手的战斗代价（放下才能打）是搬运风险的来源。矿物则不同：高价值采出物，可携带可堆叠，是未来掉落/交易的标准载体。
- **E 开背包 / F 交互**：E 是 RPG 背包肌肉记忆键位（用户点名）；交互降级到 F（原 F 空挥是调试功能，再降到 G）。
- **减伤走 DamagePipeline 单入口**：所有伤害必经 `apply()`，在既有"单位类型减伤"段并列加护甲项，语义一致且无法被旁路。
- **护甲只做减伤+移速**：新系统自带数值只影响玩家实体，不触碰 BalanceConfig 管的武器校准——回归风险隔离。
