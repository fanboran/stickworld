# 战斗系统

> **注意**：编制/指挥链是通用项目管理系统的一部分，见 [`organization.md`](01-组织系统.md)。
> 本文档聚焦于战斗本身的体验——嵌合总纲、编制与指挥的战场侧、战场规模与观感、底层战术、多线并行、附身操控。

## 目的

让玩家在任何层级都能体验真实的战场——不是数值结算，是火柴人在你眼前交战。同时支持多线并行，让玩家不是微操每一场战斗而是设计指挥链让前线自动运转。

## 玩家体验目标

- **真实可观察**：放大能看到每个火柴人的交战、掩体动作、士气动摇
- **战术可调**：掩体、压制、侧翼、撤退——不是全自动，AI 的行为逻辑是玩家可配置的
- **随时附身**：缩放到任意层级指挥官，真刀真枪操控他移动/战斗
- **多线并行**：后期多条战线同时打，你管战略，指挥链管执行
- **观感对齐**：战场观感以《火柴人战争遗产》为对照基准——除动作数据质量本身以外的差距逐项补齐（见「观感对照」一节）

## 一、战斗与层级

战斗的指挥层次由通用项目管理系统的层级决定（[`organization.md`](01-组织系统.md)）：

| 层级 | 军事语境 | 你在战斗中做什么 |
|------|----------|-----------------|
| L5 | 帝国统帅部 | 设定战略优先级、分配多线兵力、看报表 |
| L4 | 师级 | 设定战区作战计划、任命师长、配置战术偏好 |
| L3 | 团级 | 在地图上画作战计划线、布置各团任务 |
| L2 | 连级 | 指挥连队移动/攻击某具体位置 |
| L1 | 排/班级 | 微操火力组、亲自控制角色作战 |

**附身**：你可以"附身"到任意层级的指挥官。附身时你真的**操控那个角色**——WASD 移动，鼠标攻击，看到该角色的 HP/弹药/状态。同时也可以打开该层级的管理面板下达指令。两种模式随时切换。

**兵员链**：军队不是凭空造出来的——从各地征召 → 在合适的地点训练 → 运送到战场，每个环节都吃物流与组织的物理约束。初期框选 A 过去就能赢；对手变强后，训练部门（组织架构、岗位分工都要玩家亲自设计）成为必需。

**战场信息物理传递**：指挥官只能直接影响附近的单位；前后传达消息靠传令兵真实跑动，传令兵可被截杀——前线可能在后方不知情时已经崩溃。

## 一-A、编制与指挥（战场侧）

### 1. 五层级对齐

战场编制严格对齐组织系统的五层级框架（[`organization.md`](01-组织系统.md)）：

- **火力组、班、排都收在 L1 内**（组织系统 §1.1"最底层宽松"：排 ⊃ 班 ⊃ 火力组）——火力组是班内的指挥分组，不是组织树节点
- **连（L2）是直接统辖战场编制的第一层组织，战场指挥官 = L2 在战场的出场代表**
- **小档不设排长层**：每侧最多 1 个排时，排长就是指挥官；编制不足一个排时（如观察场 Tier0 的 1~2 班），指挥官直接统班
- 有两个排时，后方两个排长都是指挥官

### 2. 指挥位阵亡：补位规则

两个排一起去攻打一个地方，一个排长阵亡、甚至两个排长都阵亡了，会发生什么、怎么办？核心原则：**指挥永不断链，只降级**。各级按预定指挥序列自动接替（单排长阵亡 → 副排长/资深班长代理）——接替者就是真指挥官（组织系统 §九：补上即真指挥官），战场表现按代理降级（指挥光环/集火加成减弱）。

| 情形 | 处置 |
|------|------|
| 班长阵亡 | 班内免费顺位继承 |
| 排长阵亡 | 降级继任（代理排长，指挥光环/集火减弱版），不留永久缺口 |
| 全部排长阵亡 | 指挥官越级直管各班，或任命代理 |
| 指挥官阵亡 | 观察场 = 斩首即败；正式实机语义 = 指挥运转受损（不因一人阵亡判负） |
| 无人可补 | 节点挂起，下级自主行动（组织系统 §九） |

### 3. 斩首即败 = 观察场规则

斩首即败（指挥官阵亡 = 该方立即战败，哪怕还有兵）是**观察场的开发态规则**；正式实机中指挥官阵亡走补位规则——指挥链降级、运转受损，不立即判负。收束原因表见「战斗收束原因」一节。

### 4. 指挥官与阵地护卫

双方各自有一个指挥，指挥官后方留守；指挥前方（阵地）配几个护卫：

- 9v9 档可以 0 个
- 人数多时两三个就够
- 96 对 96 的大战场档位目前封存（见「从少数人开始」）

### 5. 号令粘性

号令有粘性，不高频翻改——反面教材：v2 训练环境实测号令翻转 48~289 次/分钟，目标 <20 次/分钟。意图粘性 = 最短保持期 + 事件触发换令，不做周期重判（见「纵深轴目标」）；保持期时长随实装校准。

## 一-B、嵌合总纲（军事组织 × 游戏循环）

指挥军事体系与游戏循环要**自然嵌合**；军事组织要做得就像游戏内无数其他组织一样——**有一套共通的底层逻辑**。军队不是特权系统：它和科学院、工程队一样，是通用组织系统打上军事标签的一个实例（组织系统 §二"组织即全能"）。

### 映射设计

| 组织侧（共通底层逻辑） | 战场侧（军事语境） |
|------|------|
| 军事组织 = 组织系统打军事标签的实例 | 战场 = 组织运转的焦点视图（同科研之于实验室） |
| 班节点（编制） | 生成战场实体：单位 + 班长，装备/训练度从编制读取 |
| 任务词汇 = 组织的工序词汇 | 军事的攻/牵制/绕后 ↔ 科研的课题 |
| 信息上报（延迟快照） | 战报 = 军事出口；观察场实时全知是开发态特权 |
| 默认战术（无指令时的自动行为） | 无令时驻防巡逻 |
| — | 士兵级微观行为（压制/决斗/找掩体）属个体执行层，组织层不关心 |

观察场硬编码阵容 = 开发态脚手架；正式形态是**编制生成战场实体**。

### 与核心循环/扩张循环的衔接

战场是核心循环"接敌开战"环节的发生地（[`完整版蓝图.md`](../完整版蓝图.md) §二）：

- **出征**：选目标（情报：守军/战形/战利品）→ 行军抵达 → 接敌开战——每一仗都是玩家的选择（打哪块、带什么兵、值不值）
- **打赢即易手**：守军战败 = 据点归属变更，战利品/人口/人才回流帝国体系（蓝图 §3.2，详见 [`03-扩张系统.md`](03-扩张系统.md)）
- **规模涌现**：参战兵力是政权经济/人口/装备的自然结果，不设计战斗规模上限（蓝图 §3.1）——现阶段从少数人起步（见「从少数人开始」）

## 二、底层战斗（L1-L2 级）

### 2.1 基本形式

- 2D 侧视角/俯视角（类似《火柴人战争遗产》）
- 火柴人真实交战——你能看到他们在射击、格挡、找掩体
- 不是抽象的"战斗力数值结算"
- 战斗结果取决于实际的火柴人交互——但你可以不亲自看（A 大自动执行）

### 2.2 战术 AI（类似《英雄连》+ 微调）

底层单位的 AI 行为是可配置的（在编制管理面板设定默认战术）：

| 战术行为 | 说明 | 可调参数 |
|----------|------|----------|
| 掩体利用 | 自动寻找掩体，在掩体后射击 | 掩体优先级、离开掩体的血量阈值 |
| 火力压制 | 对敌占区持续射击压制，不让敌方抬头 | 压制火力密度、弹药消耗上限 |
| 侧翼包抄 | 配合正面火力，小组从侧翼迂回 | 包抄半径、参与包抄的人数比例 |
| 交替掩护 | 两个火力组交替前进掩护 | 前进/掩护切换节奏 |
| 撤退纪律 | 有序后撤而非溃逃 | 撤退触发条件（伤亡%/弹药耗尽/指挥官信号） |
| 救助战友 | 拖拽受伤队友到安全位置 | 救助优先级、谁负责救 |

**小兵步枪式 AI 灵动性**：士兵不是完美机器人
- 会自主找更好的掩体
- 在明显劣势时可能犹豫
- 偶尔会追击过深脱离队形
- 但**结果是双面的**——擅自冲锋可能撕开防线，也可能送死

概率受以下因素影响：指挥官能力、部队士气、文化传统、自主决策权限设定。

**士气的消费面 = 行为权重**：士气只影响行为决策（犹豫、撤退纪律、避战倾向），**不作伤害或属性乘子**（2026-09-29 创始人裁决）——士气高的部队敢打敢冲、士气低的犹豫易退，但一刀砍出去的威力不随士气变。**劣势/被压就脱离接火（避战），不是溃逃**（裁决【删溃逃、立避战】）：单位级士气崩溃不再强制逃向地图边缘，而是 RA 压制式战术脱离（短距后撤/就掩还击）；战役级撤仗仍由 TeamAi 指挥层裁决。

## 二-A、战场规模与观感（Tier0「阵地对峙」）

### 1. 从少数人开始

**从少数人开始整**——最多十几个人、二十几个人起步，不是 96 打 96；观感标定基准 = 每侧最多十几二十几人。《火柴人战争遗产》原作常态每侧 10~25 个单位——单位大而少，画面尺度由单位体量撑起来，不靠密度堆规模。96 档目前封存；上限交给规模涌现（蓝图 §3.1），不配置化抬升。

### 2. Tier0「阵地对峙」规格

- **一屏战场**：战场大小就是一个屏幕大——能在视野里看到双方类似战棋一样的人物和阵地单位
- **半屏高**：战场高度约 1/2 屏幕高
- **每侧编成**：1 指挥官（后方留守）+ 阵地护卫（9v9 档可以 0 个，人数多时两三个）+ 战斗员 1~2 班

一屏战场、半屏高、护卫 0~3 为创始人口径；编成组合与「Tier0 阵地对峙」命名为细化规格，随实装校准。

### 3. 纵深轴目标（拉扯感的治理方向）

**单位确实应该向敌方后排走。**拉扯感的来源：目标横向铺开（三旗），指挥层每 0.5 秒重新分配兵力——单位横向来回横移，走不出推进的样子；原作雕像是单轴推进，认定一个方向走很久、走得笃定。治理方向：

- **意图沿 X 轴纵深排布**：中线争夺带 → 敌阵 → 敌后排/斩首线
- **旗改纵深里程碑**：占领目标从横向三旗改为纵深推进的里程碑
- **意图粘性**：最短保持期 + 事件触发换令，不做周期重判

### 4. 分层纪律（多层系统的处理）

多层系统按《英雄连》和《小兵步枪》这种游戏处理——以它们的实现为参照，不作纯推演设计（分层体系详见 [`12-游戏AI系统.md`](12-游戏AI系统.md)）。分层纪律：

- **指挥层管意图**：5~10 秒级
- **士兵层只动手脚不动方向**：0.2~0.5 秒级
- **下层不推翻上层方向，上层不微管下层站位**

决策承诺感是靶心：原作 AI 类极小，单位选定目标就决斗到死；多层系统叠加（指挥规划器+行为档案+压制避战+跟随+遇阻接战）会涌现犹豫。

### 5. 车道制：不设硬车道

车道制能用吗？3~4 条车道够吗？原作的"车道"只是浅车道近似（绕过雕像 = 换 y 车道），《火柴人战争遗产》也只有寥寥几条。作答（依原作实证与参照调研）：**不设硬车道**——

- **纵深浅带**：战场保持一条浅纵深带，推进沿纵深轴，不划分横向车道
- **个性 y 漂移**：SWL `personalityControlledY` 直译——单位按个体个性在带内缓慢 y 漂移，走出自然参差
- **「上中下三路」只作指挥词汇**，不是物理分区

车道内的细部机制：

- **槽位锚定**（英雄连掩体槽思想）：班方阵内固定槽位、静止钉槽、掉队一次性归槽
- **压制锁步**（英雄连 pinned 直译）：被压制的单位原地蜷缩举盾、短距挪向掩蔽、不后撤

### 6. 分批入场（防视觉问题，不是平衡性限制）

原作是经济造兵源源走出、战线是长出来的；开战瞬刷两整块对撞是视觉突兀的来源。分批入场双闸：

- **每秒入场人数上限**——出场每秒单位速度上限
- **同时入场编制上限**——组队列入场，单位时间入场的编制上限和人数上限一起作用

两道闸一起作用，**不是平衡性限制，单纯是防止视觉问题**。

### 7. 松散方阵嵌套与排兵序

**以编制为单位组成较松散方阵，方阵之间再组成松散方阵**：士兵 → 班方阵 → 排方阵 → 战线，槽位松弛跟随。这也就得**排兵序**——以编制为单位排定入场与列阵的次序，方阵按嵌套关系组成战线。

### 8. 战斗物理：补课

**战斗物理感我们学的不好**，要系统性补课。原作近战是成对锁定推挤编排：前摇 → 命中帧 → 击退位移 → 受击方向动画，一对一对咬合；高密度群殴重叠则没有物理叙事。决斗锁定：近战成对互锁、推挤平衡；分离力对锁定对豁免；击退幅度调大 + 前摇带小前冲；第二线站位（SWL `attackRangeSecondLine` 直译）。

**投射物口径**：箭为**单体碰撞命中**（原作反编译实证：无任何范围伤害字段，爆头靠专用碰撞体），本游戏纵深轴有压缩，命中容差按压缩比换算加宽 y 向——视觉上"擦到即中"，等效原作无压缩平面判定的观感。


### 9. 攻速 = 动画变速（系统性修）

**攻速-动画耦合要系统性修：攻速就是动画变速**：

- 攻击间隔 = 动画时长 ÷ 播放速度，动画播完事件驱动下一击
- **命中帧 = 伤害时点**（SWL 反编译实证：命中帧在动画 65%~75% 处；拉弓 Drawn/Hit 差 0.03s）
- 独立冷却退役为下限保护

## 二-B、观感对照（基准：《火柴人战争遗产》）

观感差距**以《火柴人战争遗产》为对照基准**——比的是**除了动作数据质量本身以外的差距**（动作/动画素材质量本身另线）。差距清单与治理：

| # | 差距 | 原作 | 我们的问题 | 治理 |
|---|------|------|-----------|------|
| 1 | 单位数量与画面尺度 | 常态每侧 10~25 个，单位大而少 | 96v96 密度堆规模 | 从少数人开始，96 档封存 |
| 2 | 推进轴 | 雕像单轴推进，走得笃定 | 三旗横向铺开，高频重判横移 = 拉扯感 | 纵深轴目标 + 意图粘性 |
| 3 | 决策承诺感 | AI 类极小，选定目标决斗到死 | 多层系统叠加涌现犹豫 | 分层纪律 |
| 4 | 移动模型 | 浅车道近似（绕雕像 = 换 y 车道） | 全 2D 连续转向 + 分离/让位/聚结多力叠加 | 纵深浅带 + 个性 y 漂移 |
| 5 | 战斗物理 | 近战成对锁定推挤编排 | 高密度群殴重叠 | 决斗锁定 |
| 6 | 入场方式 | 经济造兵源源走出，战线长出来 | 开战瞬刷两整块对撞 | 分批入场双闸 |
| 7 | 攻速-动画耦合 | 攻速 = 动画变速（命中帧 65%~75% 处） | 冷却驱动，偶脱拍 | 攻速 = 动画变速 |

> 各治理项的口径与来源见「战场规模与观感」各节；具体参数随实装校准。

## 三、战术级战斗（L3-L4 级）

### 3.1 作战计划

类似《钢铁雄心》的作战计划线——在地图上画箭头。但区别是：

- **不是摆设**：画好的计划线交给 AI 指挥官执行，他真的会按照箭头推进
- **玩家可随时微调**：发现前线僵持，缩放到 L3/L4 调整作战计划
- **指挥官能力影响执行**：好指挥官灵活执行，差指挥官死板照搬

### 3.2 《英雄连》式战术要素

| 要素 | 游戏中的体现 |
|------|-------------|
| 掩体 | 火柴人自动找掩体，玩家可标记关键掩体/拆除敌方掩体 |
| 压制 | 重火力（机枪/法师 AOE）压制一片区域，被压制的单位命中率下降 |
| 侧翼 | 编制定默认战术时设定侧翼偏好；玩家可临时手动标记"从这里绕" |
| 撤退 | 可设置自动撤退条件；也可手动发出撤退信号 |
| 班组 AI | 一个"排"(L1)在战斗中是作为班组行动的——成员自动协同，不是各自为战 |

**这些战术行为都是可微调的**：你在编制管理面板设好每个层级的默认战术偏好，前线 AI 照此执行。

## 四、战略级（L4-L5）

### 4.1 多线并行

后期帝国国境漫长 → 需要同时处理多条战线：

- 每条战线分配一个 L4 级军事组织（师）负责
- 你可以设定每条战线的战略优先级（主攻/防守/牵制）
- 资源在各战线之间的分配由你决定
- 指挥链自动执行日常战斗——你只在关键节点干预

### 4.2 多线战斗迫使你做好指挥链

你不是在微操每一场战斗——你是在**设计指挥链让它自己打赢**。如果前线一直呼叫你帮忙，说明你的指挥链设计有问题。

## 五、无缝缩放（战斗视角）

缩放是连续的：

```
最远：帝国全图 + 战线色块 + 各L4组织位置
  │  缩放
  ▼
区域：某战区 + L3组织部署 + 作战计划线
  │  缩放
  ▼
战场：某战场实况 + L2连队位置 + 掩体/地形
  │  缩放
  ▼
个体：某个火柴人的脸 + HP条 + 装备栏
```

- 概念上是同一张地图，技术上通过无缝加载实现
- 不同缩放级别自动切换显示的信息密度

## 六、附身操控

"附身"到任意层级指挥官：

- **操控模式**：你真的控制那个火柴人在战场上移动/射击/格挡。类似《小兵步枪》的操控感——但你可以附身到任意层级的关键角色
- **管理面板模式**：打开该层级的管理面板，下达指令、调整编制
- 两种模式**一键切换**

当你附身到低层级时：
- 你可以设置**自动暂停**或**自动减速**
- 或者让帝国继续全速运转——风险是你回来可能发现某条战线崩了

### 武器专属操控（SWL 附身逆向实锤的 PC 翻译）

复刻基准与 PC 键鼠方案详见 [`09-输入与操作复刻.md`](09-输入与操作复刻.md) §一/§二
（机制真值：`docs/项目/审计/SWL拉弓操控逆向_2026-09-19.md`）。要点：

- **弓**：按住左键拉弓蓄力（力度→箭速区间映射）、鼠标指向瞄准、
  抛物线轨迹预览点、瞄准期自动慢放、松手放箭；轻点=最小力度快速平射
- **矛**：按住左键蓄力投掷（独立矛投射物弹道），轻点=近战戳刺
- **杖**：指向施法——落点=鼠标世界坐标，AOE 圈预览，松开施法
- **剑/镐**：点击攻击（自动锁最近敌，原版攻击键语义）
- **附身增益**：附身单位缓慢回血、近战挥击扇形附身溅射
  （SWL Unit 真值 healthRegenPerSecondWhenUserControlled /
  USER_CONTROLLED_SPLASH_*）
- **AI 侧**：自动瞄准是 AI 专属（附身才是手动瞄准，原版同构）；
  AI 附身技能三档熟练度（SWL Personality.UserControlSkill）挂行为档案

## 七、观察模式（看海）

随时可以放大到任意战场、任意定居点、任意工地——**纯观察，不干预**。

- 后期当壁纸看：火柴人在忙忙碌碌，像看鱼缸
- 发现指挥链/物流中的问题——某个节点卡了，回来优化
- 类似看蚁群打仗——这是发现指挥链设计缺陷的核心方式

## 八、边缘情况

- **同时开战过多**：帝国承受能力上限 → "过扩惩罚"
- **无指挥官可用**：部队原地待命，自主防御但不主动进攻
- **补给线被切断**：弹药/替换兵员/液态法力到不了前线——远程单位无弹只能肉搏、编制缺员无法回补；是否溃退由该部队的纪律线自主决定（见组织系统 §3.1）
- **两个 L4 组织任务区域重叠**：可能产生摩擦/配合/冲突

## 八-A、战斗收束原因（reason 表）

> 结算载荷 `battle_settled` 摘要的 `reason` 字段口径（实现：`battle_instance.gd`
> `_check_victory`/`_end`；判定优先级自上而下）。**本表是观察场（开发态观察战场）的收束规则**——
> 正式实机的收束语义随嵌合总纲演进：斩首即败在实机对应"指挥运转受损"（见「编制与指挥」），不立即判负。

| reason | 语义 | 判定条件 | 结果方向 |
|---|---|---|---|
| `decapitation` | **斩首** | 一方指挥官（rank 3，见 `StickmanEntity.rank`）阵亡 | 该方立即战败——哪怕还有兵也是败（观察场规则——指挥链崩 = 战败，不用打到全灭；实机语义 = 指挥运转受损，见「编制与指挥」） |
| `annihilation` | 全灭 | 一方存活清零（含战役撤离离场 departed） | 对方胜 |
| `mutual` | 同归 | 双方同时归零，或双方指挥官同殁 | 平局 |
| `timeout` | 相持超时 | `duration_limit` 到期按剩余兵力判（多者胜，相等/攻方更少按守方胜） | 兵力多者胜 |

指挥官行为守卫（斩首规则的单位侧配套，见 `ai_controller.gd`）：rank>=3 不接推进/撤离类
号令（move/retreat/seek_cover，idle 放行）——留守后方；避战豁免（永不脱离接火，
`is_disengaging` 恒 false）——被近身就地自卫反击（行为层追击 LEASH 内迎击，敌远不追）。
