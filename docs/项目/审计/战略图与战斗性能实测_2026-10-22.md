> ② 48v48 战斗 draw calls 回涨复核与归因。数据供规模化方向裁决。

## 〇、环境与量测纪律

- 机器：RTX 3050 Laptop / 1920×1080 / Dummy 音频 / debug 构建，Godot 4 工具链。
- **环境负载重**：测量期间并行 8 路代理会话，同机 godot 进程峰值 10 个——
  fps/耗时绝对值被压低，全部取多轮中位并在表中注明；**draw calls 为渲染
  管线精确统计，不受 CPU 负载影响**（口径见 [性能量测规范](../../技术/规范/性能量测规范.md)）。

## 一、战略图 L1/L2/L3 三层实测

### 1.1 首开分相（headless，5 独立进程冷轮中位）

| 层 | 相 | 中位 ms | min~max |
|---|---|---|---|
| L1（Tab 大图） | load_scene | **1030.7** | 937~1611 |
| | add_child（进树+UI _ready） | 33.8 | 25~41 |
| | initialize（L1WorldData+渲染器） | 46.1 | 39~57 |
| | 首开合计 ≈ | **1110** | |
| L3（M 大世界） | load_scene | 391.6 | 329~539 |
| | add_child | 13.8 | 10~18 |
| | load_data（l3_world 数据解码） | **814.5** | 743~949 |
| | set_data_mesh（政治网格/blob 构建） | **497.8** | 487~695 |
| | 首开合计 ≈ | **1718** | |
| L2（下钻视图） | instantiate+add_child+接线 | ≈13 | 10~19 |

- 进程内热轮（资源缓存后）：L1.load_scene 0.03ms（纯缓存命中），
  L3.load_data 仍 ~760ms / set_data_mesh ~530ms——**L3 数据解码与网格构建
  每次重建都是全量重算**，无缓存复用。
- 与生产对照：game_root 装配把这些耗时拆进步骤表借加载屏分帧消化
  （当年整段同步曾致启动卡 10s+），分相账与生产路径逐相同构
  （`system_setup_strategic_map._setup_l1/_setup_l3` 同式装配）。

### 1.2 运行时逐帧（PerfProbe 探针，真渲染 world_perf，2 轮合并中位）

| 相位 | fps | 帧ms | p95 | proc ms | phys ms | draws |
|---|---|---|---|---|---|---|
| world_base（三层常驻隐藏+缩略窗） | 44.5 | 22.4 | 34.4 | 53.1 | 4.2 | 438 |
| l1_resident_off（sysoff L1 子树差分） | 44.0 | 23.0 | 36.1 | 50.2 | 3.8 | 438 |
| l3_resident_off（sysoff L3 子树差分） | 43.5 | 23.1 | 33.9 | 51.7 | 4.0 | 438 |
| l2_resident_off（sysoff L2 子树差分） | 42.0 | 23.5 | 33.1 | 49.9 | 4.1 | 438 |
| l1_open（Tab 大图全开） | 49.0 | 20.3 | 21.6 | 27.8 | 0.65 | 829 |
| **l3_open（M 大世界全开）** | **11.0** | **84.6** | 99.6 | **101.7** | 0.74 | **1913** |
| l2_open（地区视图全开） | 66.0 | 15.3 | 19.6 | 24.7 | 0.68 | 1612 |

读数口径：大图打开经互斥暂停世界模拟（phys 4.2→0.7 可证），open 相的
proc 即「世界视觉常驻 + 该层地图」的帧成本；与 world_base 的差分受暂停
影响，跨相 proc 差值只作方向参考，稳态帧时长（fms/p95）与 draws 为硬数。

**结论**：

1. **三层常驻隐藏的闲置 _process 成本 ≈ 0**（sysoff 差分 -3~+1ms，噪声内）——
   常驻装配不拖世界帧率，现行「隐藏常驻+按需 open」结构无性能债。
2. **L1/L2 大图打开稳态便宜**（帧 15~20ms，比世界基线还低——世界模拟被
   暂停省的比地图画的多）；draws 增量 +391（L1）/ +1174（L2）。
3. **L3 大世界打开 = 稳态 84.6ms/帧（11fps），战略图唯一性能大户**。
   归因（代码侧证据）：`l3_map_renderer._process` 的当前位置流动光动画
   （`_glow_outlines` 非空时）**每帧 queue_redraw 全量重录**——注释自称
   「mesh 缓存一次性 draw 命令成本低」，实测 1913 draws 的命令重录就是
   帧成本主体；叠加 l3_political_mesh 193 政权多边形与 blob 层。
   → [战略图性能下一档](../待办/战略图性能下一档.md) 的 L3 LOD 分级/
   异步加载立项有硬数据支撑：先把「每帧全量重绘」改为光效层独立节点
   单独重绘、静态层脏标记，即无观感损失的量级改善。
4. 打开瞬间尖峰（各相首秒均值）：L1 打开 ~178ms、L3 ~285ms——open 触发
   的 blob/标签重算单帧尖峰，量级与首开分相账同源。

## 二、48v48 战斗 draw calls 回涨复核

### 2.1 实测矩阵（battle_perf，13 跑，中位）

| 预设 | 模式 | draws_med | fps_med | char 宿主 | MeshInstance3D | MultiMeshInstance3D |
|---|---|---|---|---|---|---|
| 16v16（32 单位） | base | 260 | 25.4 | 32 | 35 | 8 |
| 48v48（96 单位） | base | **399** | 3.9 | 96 | 99 | 8 |
| 48v48 | --anim-off | 399 | 4.5 | 96 | 99 | 8 |
| 48v48 | --rig-hidden | **304** | 8.6 | 96（已隐） | 3 | 8 |
| 96v96（192 单位） | base | **597** | 2.0 | 195 | 198 | 8 |
| 96v96 | --anim-off | 598 | 2.3 | 192 | 195 | 8 |
| 96v96 | --rig-hidden | 397 | 2.4 | 192（已隐） | 3 | 8 |

### 2.2 归因

- **单位 draw 斜率 ≈ 2.1/单位**（16→48→96 三点线性拟合），构成 = 阴影
  MeshInstance3D 1/单位（rig-hidden 后 MeshInstance3D 99→3 实锤）+ 武器/
  血条桶分摊 ~1.1；身体 15 部件全部进 char_direct_buckets 全局 MultiMesh
  桶（描边/填充/武器各纹理/血条图集共 8 个 MMI，恒定不随单位数涨）。
- 环境常量 ≈ 190 draws（战场街景/地面多层/UI/Line2D 28）。
- **fps 侧**：48v48 rig-hidden 差分 3.9→8.6（单位视觉链 ≈ 帧成本 55%）；
  anim-off 只 +15%（AnimationTree 采样非大头）——单位视觉的 CPU 大头在
  隐藏画布里的**每单位全量 Skeleton2D 求解 + 15 部件折算 + 行写**
  （char_rig_3d 每单位藏一套真 rig 只解算不绘制）。96v96 rig-hidden 仅
  2.0→2.4（残余 2.4fps 墙在世界模拟侧，与 2026-09 基线审计结论一致）。
- worst_frame_ms 全矩阵 216~250ms 恒定触顶——帧时长疑似被钳制在 ~250ms
  （约 4fps 下限），超长帧读数不发散。

### 2.3 与档案历史数字对照（同口径 draw_calls_median，48v48）

| 时点 | 路线 | draws | 出处 |
|---|---|---|---|
| 2026-09-09 | 2D 富管线（30+ CanvasItem/单位） | 4178 | 战斗规模化30fps.md §一 |
| 2026-09-12 | CrowdRenderer 2D 批渲染终态 | 550~588 | 同档 §十四 |
| **2026-09-21** | HD-2D 整卡烘焙/billboard SubViewport | **5242**（96v96 10355） | 战斗渲染规模化.md 立项数 |
| **2026-10-22（本次）** | **HD-2D 关节烘焙直写桶（char_direct_buckets，2026-10-10 转正）** | **399**（96v96 597） | 本报告 §2.1 |

**结论：回涨已治，现为历史最优**。5242 的构成 = 旧路线每单位一个
SubViewport billboard（整版 rig 逐部件绘制 + 视口本身），~53 draw/单位；
2026-10-10 观感验收转正的 char_direct_buckets 路线把身体部件全量收进
全局 8 桶，单位只余阴影 1 draw。观察场（battle_arena→battlefield HD-2D
图）与实战同为 game_root→hd2d_map_base→char_rig_3d 一条链（装配同源），
测量路径与生产路径一致，数据可信。

**遗留（规模化方向数据，待创始人裁）**：draw 侧已无单位数瓶颈（+2.1/单位），
瓶颈移到 CPU——48v48 满编 fps 3.9（并行负载下限值），其中单位视觉链 55%
（每单位隐藏画布全量 rig 求解+折算+行写）。若要 48v48 可玩帧率，方向是
单位视觉链的 LOD/节流（远单位降采样、隐藏 rig 分帧解算）或恢复
CrowdRenderer 式纯数据插值代理，而不是继续压 draw。
