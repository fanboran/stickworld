## 一、结论速览

1. **P0 没有任何一个阶段有可信的"全绿测试"**。文档标注的"✅ 完成 / N/N 通过"多为重构前的旧运行残留或未重跑的结论，与实测严重不符。
2. **测试本身不可信是当前最大障碍**：测试挂死、跨运行结果抖动、用例间共享状态、断言基于重构前的旧数值。在此之上无法判断"失败"是真 bug 还是测试假阳性。
3. **核心假设"层级管理->好玩"的闭环其实是断的**：发令→指挥链→单位执行 这条纵切在测试里失败（tests/integration/test_selection_formation 号令全挂），而"完整指挥链"被划在 P1/P2。这正是"想完成 P0 得先做 P1/P2"的根源。
4. **不要试图"按原 P0 范围全部做完"**——那会继续撞 P1/P2 依赖。正确做法是重新切一条**自包含的最小纵切**来验证假设，把 P1/P2 依赖显式隔离。

## 三、测试架构问题诊断与重新设计

### 3.1 现状诊断

所有 `test_stage_NN.gd` 都是**巨型集成测试**：实例化完整 GameRoot（拉起 combat/construction/organization/resources/UI 全部子系统），用 `for i in N: await process_frame` 等就绪，用例顺序执行且共享 `_game_root`/`_map` 等可变状态，无超时。`TestRunner`（tests/core/test_runner.gd）是个 96 行的 RefCounted，只有 assert_true/equal + 同步 run()，**无超时、无 await 内建、无 fixture、无隔离、无零断言守卫**。

后果：挂死（02/03）、抖动（05/07）、陈旧数值假失败（02）、无法定位真 bug（06）。

### 3.2 重新设计规范（游戏行业常规做法）

**三层测试体系**（按依赖深度与速度分层，而非按"阶段编号"）：

| 层 | 命名 | 依赖 | 特征 | 示例 |
|----|------|------|------|------|
| **Unit 单元** | `tests/unit/test_<模块>.gd` | 无 GameRoot，纯对象 | 快、确定性、隔离、AAA | PlacementGrid、资源扣减计算、指挥链延迟公式 |
| **Integration 集成** | `tests/integration/test_<特性>.gd` | 最小场景树 fixture | await 就绪信号+超时、自建自毁 fixture | SelectionSystem+假地图、建造循环、室内传送 |
| **Smoke 冒烟** | `tests/smoke/test_<流程>.gd` | 完整 GameRoot | 数量少、每条带超时、只验"不崩+关键里程碑" | 新游戏启动跑 60s 零 ERROR、跨图旅行不崩 |

**确定性原则**（消除抖动/挂死的硬规矩）：
1. **等就绪，不数帧**：用 `await TestHelpers.await_condition(cond, timeout)` 或 `await_signal`，禁止裸 `for i in N: await process_frame`。
2. **必带超时**：任何 await 必有超时上限，超时即**判失败**而非挂死。（本次已提供 `tests/core/test_helpers.gd`）
3. **用例隔离**：每个用例自建 fixture、自毁；禁止跨用例共享状态。
4. **AAA 结构**：Arrange-Act-Assert，一个用例只断言一个主题。
5. **确定性输入**：AI/随机类用例固定 `seed`，时间相关用可注入时钟（后续）。
6. **零断言即失败**：用例跑完 0 断言判失败（防 `return` 静默通过）。

**命名**：按模块/行为命名，废除 `test_stage_NN`。一个阶段可对应多个文件，一个文件只属一个模块。

### 3.3 已落地的示范（本次）

- `tests/core/test_helpers.gd`：`await_condition` / `await_signal`，超时返回 false。**这是止住挂死与抖动的最小基建。**
- `tests/unit/test_placement_grid.gd` + `.tscn`：9/9 通过、exit 0、**无 GameRoot、无 await、确定性**。证明纯逻辑可从挂死的 tests/integration/test_village_map 里剥离出来独立验证。

> 用同样手法，0.2 的 PlacementGrid/PlacementValidator、0.4 的资源扣减/选址校验、0.6 的指挥链延迟计算，都应抽成 unit 测试——它们当前被埋在挂死的巨型测试里，等于零覆盖。

### 3.4 GdUnit4 决策（P0-7）

`rule.md` 要求 GdUnit4 但项目未引入，自研 TestRunner 功能有限。**建议**：P0 稳定期暂不迁移 GdUnit4（迁移成本高、会扰动本就不稳的代码），而是给自研 TestRunner 补超时/await/零断言守卫（test_helpers.gd 已起步）。GdUnit4 列为 P1 引入项，待稳定后一次性迁移。需创始人确认。
