## 二、为什么升级（现行架构的两个"非行业实践"病灶）

现行管线在**图像域**做分档和描边（渲染出灰度图后，用 k-means 聚类切三档、用 alpha 阈值+腐蚀找环描边）。这是被反馈追着打补丁的位置：

1. **图像域 k-means 分档**（`compose_icon_small_ui.py` 的拉伸+聚类段）：
   - 分档切在**直方图结构**上而非**3D 形体**上 → 档位边界会随光照漂移，惹出过「椅子糊成剪影」「罗盘盘面噪声劈簇」「Cube 棱变独立色」一系列病，补了采样域腐蚀、p5/p98 拉伸、单面退化保护三层补丁。
   - 行业标准：分档发生在**着色器**（toon ramp / shader-to-RGB），明度断点跟着形体法线走，图像域只负责上色和导出。
2. **图像域描边**（alpha 阈值+MinFilter 腐蚀找环）：
   - 本质是从 mask 的实心区向内画一圈，永远画不出「骑在轮廓上」的线（main `739af76e` 把基线从 alpha>128 挪到 alpha>16 缓解了内缩，但 1px 硬限还在：线宽无法亚像素、高斯 0.6 的糊是模拟而非真 AA）。
   - 行业标准（3D 渲染域）：**反向壳（inverted hull）描边**—— mesh 沿法线膨胀一个壳、翻转法线、纯墨色材质、只渲染背面。线宽由壳的膨胀量在屏幕空间控制，引擎 MSAA/AA 白送，线条质量超过任何图像域合成。

## 三、方案定稿（做什么、怎么做、为什么这么做）

### D. 着色器分档（先做，C 依赖它的输出语义）

1. **渲染端**：`gen_motifs.py` 的 shade pass 弃用「白模受光→图像域聚类」，改用**toon 材质**：
   - 材质节点：`ShaderNodeBsdfDiffuse` → `ShaderNodeMapRange`（或 ColorRamp，5.2 节点输入一律**索引访问+try/except 探测**，见现行管线教训）量化光照为 N 档（默认 3 档，参数 `TOON_STEPS` 环境变量）。
   - **平面物体**（现走 `bake_flat_faces` 面烘色的）保留面烘色语义：面烘色本来就是在渲染端定「一面一色」，D 之后它是 toon 材质的**输入**（顶点色直接乘 ramp 输出），不再需要图像域直方图分档兜底。
   - **曲面物体**（球/胶囊/环/管）： diffuse 光照直接进 ramp，断点建议 `0.35/0.70`（与现行 k-means 三簇均值对齐，先复刻现有观感再谈调优）。
   - 输出语义约定：**shade pass 渲出来的就是最终 cel 灰阶**（三档灰 0.32/0.62/0.92 或对应色带亮度），compose 不再拉伸、不再聚类。
2. **compose 端**：删掉采样域/明度拉伸/k-means/单面退化整段，改为**直接按灰阶查表映射色带**（`RAMPS[pid][band]`，band=灰阶档位查表）。`NO_STRETCH` 豁免表逻辑随之退役——所有图标走同一条 toon 路径。
3. **ID pass 不动**（材质 ID 锁色的机制保留，它是行业实践）。

### C. 反向壳描边（后做）

1. **渲染端**（`gen_motifs.py`，每个母题 build 之后、渲染之前）：
   - 对场景每个 mesh 物体生成壳：复制 mesh → `SOLIDIFY` 修改器（`thickness`=线宽（世界单位，起始值按 64px 图标线宽 ≈ ortho_scale×1.2/64 估算，需实测定）→ `offset=-1`（沿法线向外——Blender 的 Solidify 负 offset 即向外膨胀）→ `flip`（法线翻转）。
   - 壳材质：纯墨色 emission（INK=(18,14,9)），`use_backface_culling=True` 只渲背面（即只露出轮廓外的壳部分）。
   - **壳物体不带 pid、不进 ID pass**（ID pass 前隐藏壳集合，ID 渲完再显示）。
   - **ID 结合缝线保留图像域画法**（现行 `idedge` 段）：部件间缝线是 2D 拼版概念，反向壳只管外轮廓。
2. **compose 端**：删掉外轮廓环段（`vis/ero_vis/ring` 的外轮廓部分），保留 ID 缝线段+居中+导出。壳的 AA 由渲染端 MSAA 白送。
3. **两档线宽**：64px 一档、128/256 一档（现行为），壳厚度按渲染分辨率参数化（`gen_motifs.py` 逐尺寸渲染时给不同 thickness）。

### 顺序与回滚

**先 D 后 C**（D 改变 shade 图语义，C 只动描边）。每步用 git tag 标记：`v2-d-done`、`v2-c-done`。任一步观感不满意可整步回退到 tag，`main` 的现行管线始终可用（分支合并不受影响）。

## 六、风险与已知坑（从现行管线教训直接继承）

- **5.2 API 漂移**：节点/枚举输入一律索引访问+try/except 探测（Base Color→inputs[0] 等）；Solidify 节点若不可用则用 bmesh 手工偏移（备选路径写代码时留 try 分支）。
- **`materials.clear()` 钳零**：壳物体复制后 material_index 可能失效——壳是单材质无所谓，但原物体恢复槽位时必须按法线重指派（现行 `fix_head_faces` 逻辑保留）。
- **黑脸根因**：读 `cam.matrix_world` 前必须 `view_layer.update()`。
- **软 alpha 语义变化**：现行「边缘环填部件色」（防 BOX 混黑底）在 C 落地后**仍需保留**——壳描边改变了边缘 alpha 的构成但 BOX 缩放混底问题依旧存在。删这段前必须做黑边专项检查（深色底图上放成品图目检）。
- **壳与 mask 的轮廓差**：壳膨胀是 3D 等距、屏幕空间线宽在斜视角会有 ±10% 变化（正交相机下均匀，本项目相机全正交，风险低）——accept_sheet 的贴边数值体检能兜住超界。
- **逐字节承诺**：本分支合并即打破豁免 6 枚的逐字节承诺（架构换代不可避免）。留 `temp/baseline_v1/` + accept_sheet 前后对照页给创始人过目，页面里明确标注「v1/v2 对比」。

## 八、阶段 1 实施记录（D 着色器分档，2026-09-08）

### 落地的架构

- **渲染端**（`gen_motifs.py`）：平滑网格（球/胶囊/环/曲线管）挂 `_toon_mat()`——白模漫反射 → `ShaderNodeShaderToRGB`（EEVEE 限定）→ `RGBToBW` → ColorRamp **CONSTANT 插值**量化 N 档 → Emission；平直网格照旧面烘色（`bake_flat_faces`，dot 阈值 0.5/0.2 不变）。两条路都在渲染端定档，shade pass 出图即文件域 cel 灰（三档 0.32/0.62/0.92）。
- **compose 端**：`band = digitize(灰阶, _TH)` 直接查 `RAMPS` 表。`_TH` 硬编码 `(0.35, 0.70)` 只承担「分类三档灰」（含 classic 连续明度 ≈v1 语义），**与渲染端档位轮廓调优解耦**——轮廓断点 `TOON_LO`/`TOON_HI`/`TOON_STEPS`（渲染端 env，默认 0.76/0.95/3，见 §九）怎么移，出图灰阶恒为三档，查表不必跟调。`NIDS`（ID 候选锁 5 色）与假光 `fake` 保留，与分档正交。
- **回退路径**：ShaderToRGB 仅 EEVEE 支持，节点不可用时 `_toon_mat()` 自动回退白模受光——compose 按灰阶分类三档，语义等价（本机 EEVEE_NEXT 5.2 已验证 toon 可用）。

### 新坑（防重踩）

- **`Standard` 视图变换仍做 sRGB 显示编码**：材质里存 0.32/0.62/0.92 线性灰，出图会变成 0.596/0.815/0.970。v1 的 k-means 按排序归带掩盖了这一点；v2 固定阈值查表必须出图恰为文件域三档灰——材质/烘色一律存 `_srgb_inv(文件域值)`（`gen_motifs.py` 的 `_srgb_inv` 助手）。**验证手段**：渲染后直方图应恰见 0.312/0.612/0.913 三个峰。
- **v9 基本体套件必须移植 bake/toon 分路径**：cube/cylinder/cone 是平直面，白模受光的明度全落 0.7+（基线实测 cube p5=0.706），固定断点查表会整枚糊成单色剪影。已把 `_cel_bake_mat`/`_toon_mat`/`bake_flat_faces` 逐字移植进 `gen_icon_v9_primitives.py`。
- **v1 断点 0.36/0.68 是文件域数值**：toon ramp 的输入是线性明度，断点须 `_srgb_inv` 换算后再上站。**但「0.35/0.70≈v1 k-means 切点」的首版校准是错的**（见 §九教训首条）。

- **尖峭处必须「逐面独立位移」而非顶点位移**：顶点平均法线在锥尖/棱尖退化为沿边滑动（描边向尖端渐细消失——圆锥尖复审根因）。终版：每个面按自身法线独立外拓、面间不共享顶点（`from_pydata` 拼离散面），正对相机的面投影近零直接跳过（完全被 cel 覆盖）。

- 心形 REMESH 后的法线涟漪（左下着色脏斑）用 SUBSURF render_levels 3 平滑。
- 长矛/弹弓/短剑/锚等细长件的「主体过小」WARN 为 v1 既有（基线 bbox 实测同级），描边壳只让 bbox 略增不减。

### 4. 256px 双层线/悬空描边根修（idedge 伪边界，2026-09-10 创始人质询后定位）

- **现象**：≥128px 成品上描边出现「贴体外圈第二条墨线」，与壳描边之间夹 cel 边缘 AA 带（=悬空/双层线）；64px 干净。程序化体检：73 枚 256px 中 30 枚有墨线-形体缝（>6px），弹弓/高背椅/心形气球等肉眼可见。
- **定位链**：渲染端 ink/shade overlay 贴合（壳无罪）→ 手工同域 over 合成零缝 → 逐字复刻 compose `cel()` 逐步检测——**漂浮墨全部在 idedge 缝线段后出现**（over 后 1px → 缝线后 307px）。
- **根因**：`idedge = MaxFilter≠MinFilter & op` 在 part 图上一切值变化处画墨。C 阶段外壳改壳描边后，成品 `op` 实心区扩到壳剪影，**「部件 vs 壳墨区（part=-1）」的边界落在 op 内**，被误画成贴体外缘的第二圈墨。v1 时代 op 只含形体，此伪边界被 `& op` 天然排除——**这是 C 阶段改层序后遗留的回归**，六轮「256 描边偏移根修」修的是裁缩对位（另一层），这层当时未暴露。
- **修复**：缝线只在「部件-部件」交界画——`pmin>=1`（3×3 窗内不含 part=-1）才进 idedge。
- **验证**：全量重跑 compose 后 256px 漂浮墨 **73 枚全部归零**、128px 归零（残 1px 为 AA 噪声）、64px 逐字节不变（不画缝线段）；心形气球/高背椅/弹弓/手推车/星章等 8 枚直读确认单线贴体。

### 5. 壳描边方向性/完整性三层修复（2026-09-10 续，创始人报「部分描边亚像素偏移且 64px 同样偏移」）

- **定位**：64/256 全库四向描边厚度对比——27 枚两档**同向**偏差（顶部或底部单侧薄）→ 偏在渲染端壳几何，与合成无关。
- **第一层（view 方向 bug，渲染端）**：`build_ink_shells` 的视线方向误用**物体自身 -Z 轴**（`R @ (0,0,-1)`，R=物体矩阵；无旋转物体即竖直向下）而非**相机世界 -Z**。「去视线分量」实际成了「去竖直分量」——近水平面（顶/底面）壳被整体跳过、斜面壳位移方向跑偏 → 屏幕上/下轮廓描边覆盖不均=单侧偏薄。正交斜视角（el=22°）下水平面投影明显，壳缺失直接可见。三脚本统一改为 `cam.matrix_world.to_3x3() @ (0,0,-1)`。
- **第二层（楔形裂缝，渲染端）**：view 修正后近水平/斜面壳大量激活，暴露「逐面独立位移」的固有缺口——相邻面壳位移方向差异大时，外拓棱之间裂开楔形透明缝（锥面/端帽×侧壁最重，圆柱腿底端呈条纹状破碎）。补 **rim 裙边**：对被两个壳面共享的边加连接两面壳外拓棱的 quad（bmesh 边邻接用顶点索引对做键；BMEdge 无 `.key` 属性）；边界边/跳过面不补。
- **第三层（交叉墨/跨缝墨，compose 端）**：壳几何正确后暴露部件交叉区双方描边叠加出黑块（v1 的描边语义=**合并剪影外轮廓**，重叠区内部干净）。修复：**ink 显示白名单=合并剪影外扩 R 环带**（外轮廓描边+洞缘描边自然保留，R=thickness×2+4px 渲染域），重叠区内部墨由 cel 在上自动覆盖。
- **窄缝压制的取舍反转（创始人报「线条转弯处虚焊」后）**：曾同时做「窄缝墨压制」（闭运算 k=12 清窄缝 ink，想恢复缝透明）——但它把缝两侧部件边缘的贴边描边一并清掉，同 pid 部件间（羽毛笔羽片堆叠）又无 idedge 缝线补位→**描边在缝区断口=虚焊**，且渲染域边缘检测证明壳几何零缺口（缺口纯系压制引入）。已**回退压制、只留环带白名单**：窄缝处壳墨融合成连贯线（描边 join 观感），连续性优先。回退后 64px 边缘断口 65/73→1/73（唯一剩余=篝火火焰区，fire 层无描边系设计行为）；跨缝墨轻度回归为「部件贴边融合」观感，属描边 join 正常形态。

### 6. idege 部件缝线整体退役（2026-09-10 续，创始人三问后）

创始人质询「为什么有的图形有内部线有的没有、内部线为什么比外部线粗、和外部线衔接为什么错位」——三问同源：内部线是 v1 遗留的**图像域部件缝线（idege）**，与壳描边架构从根上不兼容：

- **有/无不齐**：idege 按「部件 pid 色不同才画交界」工作——同色部件间（羽毛笔羽片、高背椅横条）天然无内部线；且只有 ≥128px 画（64px 无）。
- **内粗外细**：idege 靠 MaxFilter 膨胀+高斯模糊画成（半透明 2-3px 散带），视觉比壳的锐利 3px 描边更粗更虚。
- **衔接错位**：idege 画在低分辨率 part 图的 NEAREST 采样边界上（半像素级偏差），且「pmin>=1 排除壳区」的修复让交界线在接近外轮廓处提前终止，与壳描边接不上。

**处置：idege 段整体退役（连同无 ink 回退环与 compose 内 INK 常量）**。内部线条全部由壳描边天然承担：每个部件自己的壳贴部件轮廓，壳墨在合并 cel 的透明区（开口/洞/缝）显示=部件分界线——粗细=外描边、位置精确贴部件几何轮廓、凡部件边缘必有；「贴合型」边界（cel 间无缝隙）靠色差与暗档区分（直读可辨）。管道里不再有任何图像域画的线。

### 7. 新坑（防重踩）

- **检测指标的定义随架构语义失效**：floating-ink/edge-miss 这类指标把「墨=缺陷」当前提，内部线的承担者变化后（idege→壳）合法的内部融合墨会让指标暴涨（69/73）——数字异常时先怀疑指标定义是否还成立，直读复核后再下结论。
- **改渲染架构（层序/实心区语义）时，必须重审 compose 里所有以「实心区/部件图」为输入的下游段**：`op` 与 `part` 的语义在壳描边架构下都变了（op 扩到壳剪影、part=-1 进入 op），每处消费都要重推一遍正确性——idedge 伪边界漏审三轮的原因是它只在 ≥128px 显形且视觉像「描边本身的毛病」。
- **向量的空间语义要查「哪个矩阵的哪根轴」**：`R @ (0,0,-1)` 中 R 是物体矩阵就取的是物体 -Z 轴——相机方向必须用相机矩阵。方向场 bug 的后果是「方向性偏差」而非崩溃，全库平均指标（bbox 对位、覆盖率）测不出来，**必须用方向性指标**（四向描边厚度、同枚跨尺寸同向性）才能暴露。
- **像素级排障用「逐步复现+每步数值检测」**：渲染端/合成端二分（overlay+手工 over 参照）能把嫌疑域砍半；在嫌疑域内逐段 dump 检测，一次定位到引入伪影的精确代码段，比整体猜快得多。
- **观感对比必须先造「同图三联基线」（v1/bug 版/修复版）再下结论**：本轮曾把「修复版描边完整后的交叉墨」误判为「修复引入的劣化」，又在没有修复前成品基线时脑补 view 修复的观感——A/B 实测（临时切回 bug 版渲染再恢复）才拿到判决性证据。
- **改 `motifs.py` 后必须做枚数对账**：本次事故的根因是改枚提交只看了渲染产物没看注册表结构。纪律：任何动注册表的提交，diff 里 `@motif` 行的增删数必须与提交意图一致；交接档状态行的枚数要与 `len(MOTIFS)` 对得上再写。
- **孤儿产物是「注册表漂移」的探头**：`review_server` 只列注册表、`accept_sheet` 按文件系统拼页——注册表删枚后产物目录必然出孤儿文件（「饭团页面残留」同根因的另一表现）。改注册表后跑一遍「文件名集合 vs label 集合」对照即可当场暴露。
- **交接档数字与代码对账**：「72 枚」从六轮提交起就与实际 67（现 73）不符，写了三轮没人核对。状态行里的枚数类声明必须有代码侧出处。
