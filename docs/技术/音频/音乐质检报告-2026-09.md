# 音乐质检报告 · 2026-09 首版

> 对象：`stick-world/assets/audio/bgm/`（九首 / 27 层）与
> `stick-world/assets/audio/ambience/`（八条环境音层）。
> 口径与阈值见 [音乐质检规范.md](音乐质检规范.md)；生成方式见
> [音乐制作管线.md](音乐制作管线.md)。
>
> **本报告只回答"有没有做坏"**。音乐是否动人、是否合意，只能由人听——那是
> 观感验收的事，不在本报告范围内。

## 一、复现命令

```bash
python tools/music/selftest.py            # 管线自检（算法正确性）

python tools/music/tone_check.py          # 音色体检（八度带分布）
```

### 逐项判读

- **响度**：七首循环曲目落在 −16.98 ~ −17.00 LUFS，与总线目标 −17 ±1 一致；
  两首结算短句 −16.00（比循环曲目高 1dB 作事件强调）。分布如此集中，
  说明总线增益分级与归一逻辑工作正常——不需要逐首手调。
- **真峰值**：−1.31 ~ −4.86 dBTP，全部低于 −1.2 的上限，且普遍留有余量
  （因为钢琴是衰减型素材，峰均比本来就大，归一后峰值不会贴着上限）。
- **接缝**：−13.3 ~ −36.2 dB，全部远低于 12dB 的告警线。最差的是
  `field_night`（−13.3）：它是力度最轻、最稀疏的一首，接缝处正好是一次乐句起音，
  并非波形断裂——从"起音本身即是合法事件"的角度看这是正常的。
- **单声道兼容**：相关 0.049 ~ 0.310，全部为正，无抵消。
  `strategic` 最低（0.049）是因为它以大面积 Pad 为主、且展宽最宽——
  已由展宽安全阀（相关低于 0.10 时自动收窄）兜住。
- **刺耳度**：0.060 ~ 0.149，中位 0.077。**这是本作最想看到的数字**：
  2–5kHz 能量占比只有 0.8%~7%，谱平坦度接近 0（不是噪声性音色），
  说明"柔和、不刺耳"这条设计目标在客观指标上成立。
- **短句的 LRA 偏大**（15~18 LU）不是缺陷：一次性短句的短时响度从起音一路
  衰减到静音，LRA 天然大；该指标只对循环曲目有意义，已在阈值检查中豁免。

## 三、分层一致性

同一 cue 的各层必须**等长、同循环点**，否则运行时叠层会错位。已由测试校验：

- 清单中每个 cue 的 `beat_count == bars × bar_beats`（32 × 4 = 128 拍）；
- `test_music_director` 用例「清单: 循环体是整数小节」通过；
- 各层由同一条 MIDI 时间轴渲染、同一混音链处理，长度天然一致。

## 四、环境音层

八条环境音（风/鸟/蝉/夜虫/浪/溪/雨/村落）的指标与来源见
`tools/music/docs/ambience_sources.md`。摘要：LUFS −27.5 ~ −29.0
（比音乐低约 11dB，是"底噪"该有的位置），真峰值 ≤ −9.8 dBTP，无削波、无静音空洞，
循环接缝非离群。

**已知代价**：环境音为满足"左右去相关"用了 8~13ms 微延迟，折叠单声道会有
可闻的响度损失（3~6 LU）。这是立体声宽度的固有代价，对**环境底噪**而言
可以接受（它不承担"必须被听清"的责任）；但如果将来要在单声道设备上认真做
环境音，需要改用不依赖延迟的去相关手段。

## 五、本报告不覆盖的内容

1. **主观听感**：旋律是否动人、编曲是否可信、音色是否合意——全部未验证。
   本报告的所有数字只说明"没有做坏"。
2. **长时间播放的听觉疲劳**：需要真人连续听 10 分钟以上判断，未做。
3. **引擎内的实际听感**：音乐在游戏里与音效、环境音同时播放时的平衡，
   需要在实机上判断（压限档位 -6/-9dB 是工程估计值，待观感验收校准）。
4. **平台导出后的表现**：本报告基于 48kHz 母带与交付 OGG，
   未覆盖各平台音频后端的差异。
