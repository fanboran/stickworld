# 小兵步枪（Running With Rifles）AI 逆向笔记

> **用途**：为「游戏AI集大成」L1 个体层提供参照（补全竞品分析 4.8 之外的机制级信息）；同目录 CoH 笔记覆盖 L4/L2，本笔记覆盖 L1 个体 AI + 支援/编制经济。
> **来源**：`F:\SteamLibrary\steamapps\common\RunningWithRifles`（Ogre3D 自研 C++ 引擎，非 Unity——无 C# 可反编译；**AI 逻辑在原生 exe 内，参数全部外置 XML**，本笔记 = 全量参数 schema + 配置结构 + 引擎侧键名清单）。
> 解包方式：直接读 `media/packages/**`（明文 XML）+ `rwr_game.exe` 字符串扫描提取配置键 schema。

---

## 一、架构总览（三面）

```
┌─ 战略面：commander_ai（每阵营一个，地图 init_match 实例化）────────┐
│  base_defense 0.5 / border_defense 0.15（防守权重）               │
│  soldier_capacity_model（spawn 容量经济：容量/倍率/方差/超容）      │
│  spawn_score 加权出兵 mix（按兵种 rarity 出兵）                    │
├─ 编制面：squad 系统 + 军衔经济─────────────────────────────────┤
│  squad_config/squad_size_xp_cap/squad_member_xp_cost             │
│  军衔 XP 阶梯（faction xml 16 级）→ 解锁 call 容量                │
│  calls 系统（支援=军衔解锁+RP 定价+容量 0~100）                   │
├─ 个体面：.ai 配置（继承链）→ exe 内 C++ 行为机消费────────────────┤
│  default.ai（~120 参数）+ 兵种覆盖档（officer/sniper/banzai…）    │
│  决策节拍/视野/点射节奏/精度/掩体/手雷/治疗/求援/编制加入 全参数化  │
└──────────────────────────────────────────────────────────────────┘
```

**对本项目的定位**：CoH 的深度在「小队内部自主性 + 战略层任务槽」；RWR 的深度在**个体 AI 的参数化颗粒度**——把一个士兵的每个决策（选敌/开火/找掩/扔雷/救人/进班）都拆成可调参数并按兵种覆盖。这正是 L1 层「灵动性」的工程化形态（竞品分析 4.8 说的「士兵 AI 灵动性」的全貌）。

## 二、L1 个体 AI：.ai 参数 schema（default.ai，pacific/factions/）

`.ai` 文件 = XML 参数表，支持**继承**（`<ai filename="default.ai">` 只写覆盖项）。按域分组摘录（实值为 1.94 版默认）：

### 2.1 决策节拍（interval 族——与本设计 A1「决策有节拍」同构）

| 参数 | 值 | 语义 |
|------|-----|------|
| choose_enemy_time | 1.0 | 选敌评估周期（s） |
| monitor_enemies_time / team_member_… | 0.8 / 1.5 | 监视敌人周期（自己/队员） |
| check_supplies_time / check_wounded_time | 5.0 / 3.0 | 检查补给/伤员周期 |
| check_alert_time / check_need_help_time | 1.5 / 1.0 | 警戒/求援检查周期 |
| check_reinforcement_need_time | 22.0 | 评估要不要叫增援的周期 |
| cover_status_recheck_time / deploy_recheck_time | 1.5 / 5.0 | 掩体状态/部署复检 |
| wait_time ± wait_time_variance | 1.2±0.6 | 行为间空档（方差去同步） |

### 2.2 视野与反应

| 参数 | 值 | 语义 |
|------|-----|------|
| leader_sight_range / team_member_sight_range | 35 / 30 | 班长/队员视野（m）——**班长看得更远** |
| sight_range_muzzle_factor / max_sight_range_with_muzzle | 1.7 / 40 | 开火时视野延伸 |
| day_reaction_time_to_fight min~max | 0.3~0.6 | 昼间遭遇反应时间（s，随机区间） |
| night_reaction_time_to_fight min~max | 0.8~1.1 | 夜间反应（**夜战更慢**） |
| choose_enemy_max_dot_range | 1.9 | 选敌视野扇形（dot 阈值） |
| accuracy_offset（兵种覆盖） | 0~0.675 | 精度偏移（狙击手 +0.675） |
| accuracy_penalty_range | 0.07 | 移动/连射精度惩罚量 |
| accuracy_penalty_wear_off_rate | 0.333 | 精度惩罚衰减速率 |

### 2.3 开火节奏（burst 族）

`burst_time 0.3±0.2 / longer_burst_time 2.5±0.5 / wait 1.2±0.6 / in_vehicle_burst 2.0±0.5 / shooting_against_vehicle_burst 0.5`——点射-停顿-点射的节奏模拟，全部带方差。

### 2.4 掩体与部署

`using_cover 2~5s`（掩体内停留）、`fire_open_min_time 12s`（最少露头开火时长）、`minimum_distance_to_consider_deploying_cover 16m`、`deployment_area_utilization_factor 0.4`（区域拥挤度上限）、`recheck_cover_over_shootability_time 3s`、`dive_from_grenade_probability 0.5`（手雷落下扑倒概率）、`prefer_roofs_probability 0.5`。

### 2.5 手雷经济

`throw_grenade_time_interval 5~30s`（个体化随机节奏）、`min/max_distance_to_throw_grenade 13/25m`、`grenade_monitor_range 15m`（监视队友手雷互斥）。

### 2.6 **编制加入的权威值经济（最有借鉴价值的机制）**

士兵对「加入哪个班」有**权威值（authority）博弈**：

| 参数 | 值 | 语义 |
|------|-----|------|
| authority_margin | 0.07 | 班长权威差容限 |
| max_leader_authority_willing_to_join_another_squad | 0.3 | 班长权威高过此值才肯放人 |
| defending_authority_offset_to_join_squad / value_increase_required_to_join_defend_squad | 10.0 / 1.0 | 防守班的加入门槛加成 |
| favor_joining_player_squad_value_increase | 0.2 | 玩家的班有 +0.2 吸引力 |
| favor_staying_in_current_player_squad_value_increase | 0.5 | 已在玩家班里再 +0.5 黏性 |

→ **士兵是自主择班的**：AI 队友会权衡「班长权威/班型/玩家光环」跳槽。这是 L1 自主性与 L2 编制之间的市场式调节机制，CoH 没有这一层。

### 2.7 互助与求援

`check_need_for_help_range 45m`、`fighting_favor_helping_probability 0.7`（战斗中偏离去帮队友的概率）、`maximum_distance_to_consider_for_heal 45m`、`consider_someone_already_healing_wounded_distance 10m`（防扎堆治疗）、`force_comparison_multiplier_to_call_reinforcements 1.15`（敌我力量比 1.15 倍才叫增援——避免滥叫）、`call_reinforcements_max_distance 40m`。

### 2.8 其他域

- 护盾/盾牌协作：`max_active_shields_per_fellows 0.2`（举盾人数比例上限）。
- 警戒传 spread：`leading_inspect_alarm_min_distance 45m / fighting_approach_alarm_max_soldiers 12`（警报传播的距离/人数上限）。
- 车辆：`check_vehicles_interval 1.0 / vehicle_stuck_short_time 5.0 / ai_abandon_when_unsteerable`。
- 情绪彩蛋：`celebrating_shoot/comment/stab_probability 0.3/0.4/1.0`（胜利庆祝行为——灵动性的软表现）。
- 玩家光环：`accuracy_offset_in_player_squad +0.025`（跟玩家同班的 AI 更准）。

## 三、兵种人格 = 覆盖档（继承链实例）

| 档 | 关键覆盖 |
|----|---------|
| officer | `force_as_leader 1.0`、accuracy +0.09、视野 40/45m、手雷 30m——班长是「看得远打得准的普通人」 |
| sniper | accuracy **+0.675**、无移动精度惩罚、分离半径 15m（独行）、掩体内 8~12s（耐心）、不扑雷 |
| banzai（突击） | `willingness_to_charge 1.0`、掩体 0~0.1s（**无视掩体**）、join 权威全 0（不进别人的班）、近战刺刀 4.24m |
| sentry / elite / flamethrower_operator / infected（僵尸） | 同构覆盖 |

## 四、L4/编制面要点

- **commander_ai**（每阵营）：`base_defense 0.5 / border_defense 0.15`——spawn 与攻击流的防守权重；配合 `spawn_score`（按兵种稀有度加权出兵 mix：assault 0.1 / sniper 0.01 / sentry 0.0075）。
- **spawn 容量经济**：`soldier_capacity(_model/_offset/_variance)`、`initial_over_capacity`、`comms_disabled_capacity_multiplier`（**电台被干扰→出兵容量下降**——信息通道直接接入战略产能）、`max_soldiers 220`、`player_bot_compensation 4`（难度补偿）。
- **军衔解锁支援**：faction xml 16 级军衔 XP 阶梯；calls.xml 每个 call 两道门槛——`capacity(source=rank)`（军衔解锁容量 0→100）+ `inventory price`（RP 价格）：mortar 0.05/100、cluster 0.15/150、paratroopers 0.1~0.2/120~200、artillery 0.2/250、cover_drop 0.05/40。**支援不是冷却制而是「军衔×资源」双资源制**。
- **编制玩家侧**：`squad_command`、`squad_size_setting`、`radio_queue_size 3`（指令队列上限）、`commander_radio_reports`。
- **难度**：`ai_accuracy 0.94`（地图 per-faction）、`enemy/fellow/player_ai_accuracy|compensation|reduction`（区分敌我补偿）。

## 五、对本项目的对照启示（接设计文档 12 号 §五）

1. **L1 的颗粒度标杆**：RWR 证明个体 AI 的「灵动」不来自花哨算法，而来自**几十个带方差的决策间隔/阈值/概率**——与我们 A1「节拍+方差」方向完全一致，参数面板可直接照其 schema 设计（BalanceConfig category=ai）。
2. **兵种人格 = 继承覆盖**：default + per-class 覆盖档，与 CoH personality 同构——我们的兵种（枪兵/弓兵/法师…）可各持一个覆盖档，天然挂 SWL 直译的 Ai 类。
3. **权威值择班**（2.6）：L1 自主 × L2 编制的市场调节——士兵会跳槽到权威高/玩家光环强的班。可作为我们小队成员「士气低离队/主动归队」机制的参照（组织 hire/fire 的对面是士兵 own will）。
4. **支援=军衔×资源双门槛**：对我们「呼叫增援/空袭」类机制（竞品 4.8 的「呼叫支援」原型）是现成定价结构。
5. **信息通道接产能**：comms 干扰降出兵容量——与我们「延迟=物理传播」铁律同族：信息不是氛围，是硬产能参数。
6. **班长视野 > 队员视野**（35 vs 30m）：指挥层级的第一性收益不是数值加成而是**信息半径**——与我们指挥链延迟语义互补（班长看得远=本地信息快，下令传递=全局信息慢）。
7. **反应时间昼/夜分段**：环境进入参数（0.3~0.6s vs 0.8~1.1s）——「夜晚更慢」是模拟因果不是数值折扣。

## 六、建议 Pro 深挖清单

1. exe 内 commander_ai 的目标选择逻辑（原生代码不可读，可从 `commander_notifications/commander_radio_reports/spot` 相关键 + 行为观察反推）。
2. AngelScript API 面：`media/packages/*/scripts/*.as` + 社区文档——地图级触发与 AI 指令接口（`squad_command` 的脚本面）。
3. `soldier_capacity_model` 的精确公式（容量-兵员-运输联动）。
4. vanilla 阵营无 .ai 覆盖（用内置默认）——exe 内置默认值表与 default.ai 的差异需运行时观察（console/调试命令）。
5. 武器 xml 的 AI 消费字段（accuracy/burst 如何被武器修正）。
