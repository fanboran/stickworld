## 一、三域架构关系与 tick 序

**持有关系（文字图）**【提案/待定】：

```
World.world
├─ kingdoms (KingdomManager) ─── Kingdom（king:Actor, capital:City, cities[], culture/language/religion, allianceID, royal_clan_id, past_rulers≤30, power）
│    └─ cities[] ──────────── City（leader:Actor, army:Army, status.warrior_slots, _capturing_units, _capture_ticks, loyalty）
│    └─ king（个体 Actor，兼职：有城/有氏族，被 setKing 后 profession=King）
├─ diplomacy (DiplomacyManager) ─ DiplomacyRelation[k1_id<k2_id 唯一键]（双向 KingdomOpinion，timestamp_last_war_ended）
├─ wars (WarManager) ──────────── War（main_attacker/main_defender + list/died/past_attackers/defenders，war_type）
├─ alliances (AllianceManager) ── Alliance（kingdoms_hashset；参战随盟整体 join）
├─ plots (PlotManager) ────────── Plot（author=Actor, units≤15 支持者, progress, target_kingdom/city/war/actor）
└─ armies (ArmyManager) ───────── Army（captain:Actor + 属主 City，纯旗号组，无编队语义）
```

**tick 序（实测挂接点）**【提案/待定】：
- `WarManager.update()`：每帧倒序对每个 War 调 `War.update()`（主攻/主防死亡→lostWar；年龄>10 年且主方 0 城→lostWar；总战只剩 1 国→Attackers 胜）。
- `DiplomacyManager.update()`：暂停跳过；`diplomacyTick` 每 **2 秒真实间隔** 跑一次 `newDiplomacyTick()` = `findSupremeKingdom()`（全王国按 `power = 战士×2 + 城市×5 + 1` 排序取 supreme/second）+ 成就检查。**外交决策不在 Manager 里 tick，而在个体 AI**。
- `Kingdom` AI：`getNextJob()` 恒返回 `"kingdom"` 任务 → 任务序列 `CheckCapital → CheckKing → RandomWait` 循环（KingdomBehCheckKing 即王位继承入口，每次轮到就检）。
- `City` AI 任务序列（BehaviourTaskCityLibrary.cs:22-137）：`CheckLeader → CheckAttackZone → CheckCitizenTasks → CheckLoyalty → … → CheckArmy`，每 tick 轮转。
- `PlotManager.update()`：每帧 `updateProgress`（progress 以 2/s 逼近 progress_target）+ 遗忘检查（超 `forgotten_plot_time` 未推进或 author 死亡 → 取消）。
- **个体 AI**：actor 决策系统选 Plot 并工作（`updateProgressTarget` 按 intelligence+1 加 target）；战士个体轮询 `city.target_attack_zone` 出击（BehCityActorCheckAttack）。

**关键设计判断**【提案/待定】：WorldBox 没有「国家大脑」。宣战/结盟/叛乱全部是 **个体 Plot**（国王/城市领袖的个人野心情节），王国/城市 AI 任务本身极薄；Manager 只做登记（关系表/战争表/霸主排序）和结算（War.update）。这与其「上帝沙盒」定位一致——玩家看的是剧情涌现。

## 三、王位继承与叛乱链专节【提案/待定】

**入口**：Kingdom AI 任务序列每轮调 `KingdomBehCheckKing.execute()`（ai.behaviours/KingdomBehCheckKing.cs:9）。前置：`data.timer_new_king` 倒计时中则跳过（removeKing 时置 5~20 秒随机——继承有「空位期」）。王健在则只做杂务（金牙彩蛋、补建氏族）。

**触发条件**：`hasKing()` 发现王死亡/失格 → `clearKingData()` → 按是否有 `royal_clan_id` 走两条链：

**链 A（有王室氏族）**：
1. `SuccessionTool.getKingFromRoyalClan`（SuccessionTool.cs:15-44）：王室氏族内筛 `fitToRule`（同王国+未废+非现王）→ 有文化用「年龄+特质」文化化排序（ListSorters.getUnitSortedByAgeAndTraits），否则年长者优先 → 当选。
2. **fallback ①（文化特例）**：王室无人，但文化有 `unbroken_chain` 特质**或世界法禁叛乱** → 退到 `getKingFromLeaders`（领袖链，见链 B 1）。
3. **fallback ②（单城）**：王室无人且只 1 城 → 直接提首都领袖为王（removeLeader→stopBeingWarrior→setKing）。
4. **fallback ③（多城=chaos）**：`checkKingdomChaos`：除首都外每个有领袖的城市 `makeOwnKingdom(fellApart)` 分家（随机顺序遍历），分完原王国退盟、logFracturedKingdom；原王国无城即自然消亡。
5. **shattered_crown 文化变体**：王室有人但文化有 `shattered_crown` → 不立王，把王室成员逐一分封到非首都城市各建新王国（每城一王，剩余城按各国城数均衡并入），logShatteredCrown。
6. 王室氏族已灭 → `royal_clan_id = -1`，下次走链 B。

**链 B（无王室氏族）**：
1. `getKingFromLeaders`（SuccessionTool.cs:47-71）：全城领袖集合，`ActorTool.attributeDice` 掷骰最高者为王。
2. 无人（皆无领袖）→ `checkKingdomChaos`（同链 A 4）。

**继承收尾**：`makeKingAndMoveToCapital`（:249-265）——新王辞军职/辞城领袖 → 迁入首都 → `setKing`（professoin=King、total_kings++、past_rulers 追加、happiness "become_king"）→ `trySetRoyalClan` 换旗 → logNewKing。城市级配套：CityBehCheckLeader 用「王室氏族优先→全城掷骰」补城市领袖，与王国链同构。

**叛乱链（组织内部战争）**：
1. 触发：非首都城市领袖个人 plot（rebellion，PlotsLibrary.cs:266），条件见 §2.2；`forced`（玩家作弊强推）跳过 happiness 检查。
2. plot 立满 → `DiplomacyHelpersRebellion.startRebellion`（:3-65）：领袖辞职 → `city.makeOwnKingdom(pRebellion:true)`（City.cs:2250：新城邦复制原国文化/语言/宗教）→ 本人入城。
3. 战争归属：若原王国已是某 rebellion 战争的主攻方 → 新城邦**加入守方**（同一叛乱多城汇流）；否则 `startWar(原国, 新国, WarTypeLibrary.rebellion)`，原国盟友中观感≥0 者入攻方。
4. 裹挟：plot 支持者（≤15 人）所在的原国城市逐个 `joinAnotherKingdom(新国, rebellion)`；再按「邻城优先→随机 unhappy 城、每次 50% 掷骰、上限=原国城数/3」扩募。
5. 失败态：plot 酝酿期超时未推进/author 死亡 → PlotManager 自动 Cancelled（PlotManager.cs:92）；叛后首都陷落走普通 capture 链。

**数据流小结**：身份三字段（king/royal_clan_id/past_rulers≤30）+ 两条 fallback 链 + 一个 plot 系统 = WorldBox 全部继承语义。无血统表、无继承法配置——**候选序硬编码在 SuccessionTool，文化特质只是排序器和开关**。

## 四、值得复刻 Top3 与不建议照搬 Top1【提案/待定】

**Top 1｜观感=具名因子逐项求和 + 结果字典留痕**（KingdomOpinion/OpinionLibrary）：20 个具名因子（战争 −500、休战期 +100、近邻 −25/远邻 +25、异文化/宗教/语言 −15…）全部资产化注册，UI tooltip 能回答「为什么恨你」。本项目组织上报门控（组织系统架构 §4.4）、后续外交与 AI 决策都可复用此模式：**决策依据可解释、权重热调、面板逐项展示**。

**Top 2｜继承 fallback 链 + 空位期 + 分家终局**（KingdomBehCheckKing）：王室→领袖→分家三级 fallback，每级都是「事件化终局」（改朝/新王/碎国），配合 5~20 秒 timer_new_king 空位期与日志（logNewKing/logFracturedKingdom/logShatteredCrown）。本项目补位引擎（succession_rule）目前只覆盖「指挥官伤亡即补位」一个中间态；WorldBox 证明**补位失败分支本身就是内容**——建议补位引擎补「候选空→组织解体/独立」终局事件与空位过渡态，而不是只返回 filled=false。

**Top 3｜城市占领=双方拉锯的 capture ticks 条**（City.updateCapture）：守方战士+瞭望塔每 0.1s 回拉、攻方累积、100 满触发，中途换主按竞争规则；后果链（战士复原/军队解散/第三方归属/双向 happiness）一次配齐。比「占领=踩点判定」更有围城叙事；本项目出征与领地循环（扩张系统 §六）的城池攻占可吸收此模型，数值换成帧率友好的节拍。

**不建议照搬 Top1｜宣战/结盟走个体 Plot 而无国家决策层**：WorldBox 的「外交决策」本质是国王个人野心情节（plot 酝酿→立满执行），国家没有意图状态、没有多目标权衡、盟友只是被动裹挟。它服务于沙盒观测（玩家看戏），本项目是玩家**指挥**组织的大战略+战斗缝合怪：出征决议必须挂在本项目 L3 组织层（指挥链下达、战役意图可被玩家覆写），而非复刻「个体攒进度条替你宣战」。若要 plot 的「酝酿期+中止条件」质感，可将其作为 L3 决议的预热阶段，而非决策主体。
