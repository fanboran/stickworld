## 二、总架构（四层，两层在 Lua 两层在 C++）

```
┌─ Lua 战略层（ai\，0.5s 分帧主循环，玩家级）────────────────┐
│ AI_Think1..4 / AI_Analyze1..4 ← TimeRule_AddInterval 0.5s   │
│  · state_analysis   威胁/军力评估 → military_attackPercentage│
│  · strategy_*       建造序→动态阶段的购买/资源/军事策略       │
│  · targets          攻/防目标打分排序                        │
│  · 只创建「任务槽请求」，不直接指挥小队                      │
├─ C++ 引擎任务系统（无 Lua 源，靠接口反推）──────────────────┤
│  · Request_Combat/Sniper/Goliath...  任务槽 ↔ 空闲小队匹配   │
│  · 任务参数含目标评分权重（threat/clump/distance/inertia）    │
│  · 读 Lua 全局（military_retreatChance 等）执行撤退/后撤      │
├─ squadai 计划层（squadai\*.squadai，小队级）────────────────┤
│  · 相位化动作脚本：按成员角色分相位执行                      │
│  · 蓝图 plan_table 按战斗状态挂接（接敌/被压制/突击/待机）    │
├─ attrib 蓝图层（*.rgd，单兵/武器数值）──────────────────────┤
│  · squad_retreat_ext / squad_suppression_table /            │
│    cover_formation_table / veterancy_odds / reinforce_ext    │
│  · RGD 内嵌 Lua 函数名（如 PositionTargetFilter_Cover）——   │
│    数据→脚本按名桥接                                         │
└──────────────────────────────────────────────────────────────┘
```

**核心结论（先说给 Pro）**：CoH 的「以小队为单位」**没有指挥层级**——玩家/战略 AI 直接对小队下令，小队是命令原子；深度来自小队内部的自主行为系统（squadai 计划 + 引擎掩体/压制模拟），而不是 L1~L5 组织树。它对应的不是我们的 dispatcher 链，而是我们 `FormationSystem`（L1）+ `team_ai`（战略层）的组合。

## 三、战略层细节（ai\ 目录）

### 3.1 主循环（default.ai）

- 8 个分帧函数 `AI_Think1..4` / `AI_Analyze1..4`，全部 `TimeRule_AddInterval(fn, 0.5)` 每 0.5s 一跳——**决策频率固定节拍**，不做 per-frame。
- 两阶段状态机：`s_buildorder_phase`（脚本化开局建造序）→ 被攻击或建造序耗尽后进入动态阶段（`strategy_buildorder.is_done()`）。
- **任务组（TGROUP）+ 固定优先级表**：BuildUnits 90 / Tech 90 / BuildOrder 100 / CaptureHigh 85 / Attack 60 / Defend 50 / DefenceSecure 65 / SpecialUnit 1000 / PlayerAbility 90。
- **预算系统 `ai_budget`**：把资源按比例切给预算账户——Units 42% / Tech 40% / AddOn 6 / Secure 7 / PlayerAbility 5 / SquadAbility 5；各账户有独立 `do_purchase` 回调与购买间隔（3s/5.75s）；「杀掉失效任务→资源回账」循环。
- 玩家技能（指挥官树技能）单独预算 + 弹药锁定：`s_munitionsToLock=150`，锁定后按 25% 递增可用额度。

### 3.2 攻击比例（state_analysis.recalculate_attackpercentage）

`military_attackPercentage` = 战斗小队中应该处于进攻位的比例，动态计算，优先级从高到低：

1. **VP 票危急规则**（最高优先）：票数低于警告线时 `attack% = 0.6 + 危急度×0.4`；**若我方 VP 占优则翻转为防守**（1-x）——领先转防守是写死的。
2. **基地受威胁封顶**：`threat_at_base > 5` 时 `attack% ≤ max(100-threat, 5)/100`。
3. **难度基调**：easy/standard 有 `start_attack_time`（standard = 9min ± 4min 随机）之前攻击% = 0；随后 `默认0.6 + 每分钟+0.01` 递增，封顶 `max_attack_percentage`（standard 0.70）。
4. **军力优势递增**（hard/hardest 用）：军力价值比 > 0.4 时按归一化优势抬升 attack%。

### 3.3 军事任务槽（strategy_military.execute，每 0.5s）

- 期望进攻任务数 = `ceil(attack% × 可战斗小队数)`，防守 = 余量；只增删**空任务槽**，从不指定哪支小队——**小队匹配是引擎侧完成的**（Lua 侧只见 Task_CountEmpty/Task_KillInactiveTasksInGroup）。
- 攻击任务参数：`rally=NearDefendPoint，rally 超时 3min，目标超时 30s（×8 tick）`；防守：`rally=LastPosSafe，目标超时 2min`。
- **目标评分权重**（随任务下发给引擎）：`score_threat 5.0 / score_avoid_clumps_at_no_threat 10.0 / score_distance_to_squad 5.0 / score_distance_to_base 5.0 / score_inertia 1.4`——威胁、脱离敌人集团、距离、惯性（防振荡）四因子加权。
- 特殊单位常驻任务槽：狙击手（60% 防守型/40% 进攻型随机）、Goliath 炸弹车（含 `goforbrokeHealth 0.45 / detonateHealth 0.08` 自毁逻辑）、军官跟随、移动 HQ。

### 3.4 撤退 / 后撤（参数在 personality，消费在引擎）

state_analysis 把 personality 参数灌进 `military_*` 全局，由引擎战斗任务读取执行：

| 参数 | 默认（personality.ai） | 语义 |
|------|----------------------|------|
| retreat_capacity_percentage | 0.49 | 小队容量/血量低于此值 → 撤退候选 |
| retreat_suppressed_percentage | 0.51 | 周边 ≥51% 小队被压制 → 撤退候选 |
| retreat_chance | easy 0.30 / standard 0.30 / hard 0.45 / hardest 0.35 | 每 reevaluate_ticks(20 tick≈2.5s) 的**概率掷骰** |
| fallback_* 系列 | 同构四参数 | 战术后撤（不回 HQ）的概率版 |
| retreat_chance_reevaluate_ticks | 20 | 评估周期 |

**撤退是概率调制而非确定性阈值**——难度越高掷骰概率越高；执行体是小队蓝图上的 `squad_retreat_ext`（撤退目标可配置）。

### 3.5 技能战术 demand 系统（tactics.ai，效用打分制）

每个小队技能（手雷/烟雾/医疗包/坦克绕后/进建筑…）由三件套函数构成，**Lua 函数名被 attrib RGD 按名引用**：

- `TacticFilter_*`（能不能用：`IsBeingAttacked` 查 40 tick 战斗史、`HealthLow < 0.55`、`IsShootingVehicle`…）
- `TacticDemand_*`（情境打分：命中给 `+s_demand_increment(50)`，否则 `-50`；进建筑按距离线性放大 1~6 倍、工事 ×2；`demand_variance` 0.80 给打分加随机扰动防齐套）
- `SquadTargetFilter_* / PositionTargetFilter_*`（选目标/选落点）
  - **PositionTargetFilter_Cover**：`Squad_FindCoverCompareCurrent`（10m 半径 60° 搜索窗）→ 新位置威胁度必须低于旧位（`threatDiff < 1`）→ 不得进任何敌人火力锥（`IsFireConePosition`）→ 不得接近现有攻击目标 25m 内。
  - **PositionTargetFilter_Tank**（坦克绕后）：落点 = `目标位置 − 目标朝向 × 距离`，`TacticUpdateCheck_Tank` 每帧校验失效即取消。
- 坦克绕后开关在 personality（`tankmove_tactic_enabled`，standard 关闭）。

## 四、小队层（squadai\*.squadai）

### 4.1 成员角色与动作词汇

- 成员角色四类：`ET_Core`（核心）/ `ET_Scout`（侦察）/ `ET_RFlank` / `ET_LFlank`（左右翼）——**小队内部的编制分工**，蓝图 loadout 决定谁当什么。
- 动作宏（squadai-util.squadai）：`ACTION_MOVE_POSTURE(_EXT)`（距离基准/比例 + **掩体搜索半径/角度** + 队形文件 + 步速 + 目标姿态 crouch/prone + 最大延迟）、`ACTION_MOVE_LOS`（移到能看见目标处）、`ACTION_WAIT_RANDOM`（**随机等待=去同步化**）、`ACTION_DO_ABILITY/CRITICAL`（放技能/挂状态修正）、`ACTION_SET_PHASE_ANIM_STATE`（压制动画状态机切换）。
- `DT_AWAY_FROM_TARGET / DT_MAX_SQUAD_RANGE / DT_MIN_ELEM_RANGE`——移动基准锚点（背向目标/小队最大范围/组内最小间距）。

### 4.2 关键计划（行为语义）

| 计划 | 触发状态 | 行为 |
|------|---------|------|
| `infantry-plan` | 推进（默认攻击） | **交替掩护跃进**：Core 先跃进找掩体（70% 间距，10m/75° 搜掩体，蹲→趴，停 5s）→ 全队还击等 2~4s → 两翼跟进（再等 2~3.5s）→ 循环；周期性 `MOVE_LOS` 恢复视线 |
| `reaction-plan` | **接敌瞬间** | 全员 `DT_AWAY_FROM_TARGET` 背向敌人极速卧倒（找掩体语义），播战斗喊话（30% 概率） |
| `pinned-reaction-plan` | **被压制（pinned）** | `isInterruptablePlan=false`：锁死动作 + 切换 "suppression→pinned" 动画态 + **等 7.5s**——被压制的实质是定时禁令 |
| `surrender.squadai` | 投降 | （特殊情况计划） |
| `weapon-team-plan` | 武器班 | 武器组展开/收起的相位逻辑 |
| `default-plan` | 待机移动 | 全员快速移动 + 找掩体 |
| `infantry-idle-plan(-no-move)` | 静默待机 | idle 行为 |

### 4.3 挂接机制（attrib 侧佐证）

步枪班蓝图（`attrib/attrib/sbps/races/allies/soldiers/rifleman_squad.rgd`）内含：

- `tables\assault_plan_table.lua` → 引用计划名：`assault-infantry-plan / assault-vehicle-plan / Pinned-reaction-plan / infantry-plan / reaction-plan / infantry-idle-plan`——**蓝图级「状态→计划」绑定表**，引擎按小队当前状态切计划；
- `tables\squad_suppression_table.lua` + `suppression_cover_table/entry`——**压制与掩体类型的交互数值**（不同掩体等级下的压制累积/恢复）；
- `tables\cover_formation_table.lua`——不同掩体下的队形切换；
- `sbpextensions\squad_retreat_ext.lua`（含 retreat_target）、`squad_reinforce_ext.lua`（增援概率 odds）、`squad_veterancy_ext.lua` + 三级 odds/kicker 表；
- 蓝图内嵌 Lua 函数名 `PositionTargetFilter_Cover`——**数据行直接点名 Lua 战术函数**，attrib 与 ai 层的桥。

## 五、对本项目的对照启示（给 Pro 的分析抓手）

1. **CoH 无指挥层级 vs 我们的 L1~L5**：CoH 的全部「深度」在小队自主性（计划+压制+掩体）与战略 AI 的任务槽/评分，不在组织树。我们的 dispatcher 逐跳透传 + 补位是 CoH 没有的增量玩法——设计上要自问：层级带来的延迟/摩擦是否配得上它增加的操作成本？CoH 的答案是「把复杂度放在小队内部，而不是指挥链上」。
2. **任务槽解耦**（strategy_military 只 Request/kill 槽位，引擎做匹配）↔ 我们的 `issue_to_org` 直接逐跳投递。任务槽模式天然支持「小队忙时不接令」「惯性评分防振荡」——可在 team_ai 演进时借鉴。
3. **demand 打分制**（filter/demand/target 三件套 + ±50 打分 + 方差扰动）↔ 我们组织的 `default_behavior`（无指令时自动行为）字段目前只是透传字典。CoH 证明「情境谓词+效用打分」是低成本可调的行为选择器，适合作为 default_behavior 的 v2 实现范式。
4. **撤退/后撤 = 概率调制阈值**（49% 血量 + 51% 周边压制率 + 按难度的掷骰）——不是确定性开关。我们 RETREAT 号令是纯玩家指令；若做「AI 自主撤退」，CoH 的概率制能避免阈值边界的振荡与机械感（对应我们铁律：掷骰是执行机制，因果仍是真实战况）。
5. **压制 = 定时锁死**（pinned 计划 7.5s 不可打断）而非数值折扣——与我们「惩罚来自模拟因果」铁律同构：被压制的小队不是打不准 ×0.5，是真的趴着不动 7.5 秒。可映射到我们士气系统（OrganizationState.morale_threshold 现成字段）。
6. **成员角色分工**（Core/Scout/双翼 + 跃进相位 + 随机等待去同步）↔ 我们 FormationSystem 的槽位与 `_decide_squad_targets`（排长决策）。我们的 L1 小队若要「自主找掩体/交替掩护」，CoH 的相位计划 DSL 是现成蓝本。
7. **难度=参数不=作弊**：CoH 难度差异全在 personality 参数（开局攻击时间 9min±4min、撤退概率、购买延迟 15s、demand 方差）——不送资源不改数值。对平衡调优是重要先例。
8. **决策节拍 0.5s + 分帧**：战略 AI 每跳只做一类事（Think1 清预算→Analyze 算威胁→Think2 购买→Think3 军事），天然限 CPU。我们 team_ai 的更新调度可参考。
