# 建筑生成管线 v2——笔触手绘参数化

> 取代旧 `building_gen` 运行时程序化装配管线（旧管线产物全部废弃，不作为 v2 的任何参照）。
> 关联文档：[`场景与战斗/建筑与定居点.md`](场景与战斗/建筑与定居点.md)（消费契约）、[`设计/系统/03-定居点与建筑.md`](../设计/系统/03-定居点与建筑.md)（尺寸规格）

---

## 一、是什么

一套**离线渲染管线**：用代码（GDScript）对建筑做参数化建模，以**正面立面视角**在 Godot 渲染域中绘制成**笔触手绘风格**的 PNG，连同布局元数据 JSON 一并入库；游戏运行时不再做任何程序化装配，只加载成品图并按元数据挂交互/碰撞/工位节点。

**唯一沿用的旧约束**：建筑宽度范围 **3~16 格**（1 格 = 32px，即 96~512px；16 格 = 1 标准单元）。宽度超出 16 格的需求不存在——需要更长体量时由布局域拼接多个体量段解决，而不是拉伸单栋建筑。

**管线形态与图标管线（Blender）同构**：注册表驱动、确定性 seed、多域拆分、验收拼页闭环；但渲染器用 Godot 2D 自身——正面立面是纯 2D 问题，用 2D canvas 绘制最直接，不引入 Blender/3D 依赖。

### 为什么离线烘焙而不是运行时生成

- 风格上限：笔触质感（抖动墨线、排线、纸纹、溢出线头）在离线域可以堆任意贵的手段，运行时零成本。
- 稳定性：旧管线的运行时 CPU 纹理生成拖慢 smoke 测试（138s/超时线 150s），烘焙后运行时只做 Sprite2D 贴图，问题根除。
- 确定性：城镇生成、观感验收都需要"同一 spec + seed 永远同一张图"，烘焙产物天然满足。

## 二、架构：四域拆分

```
stick-world/tools/building_pipeline/      （res:// 内，godot 弹窗跑，需 GPU）
├── gen_buildings.gd          批量生成入口：godot --script 该文件
├── registry.gd               注册表：def_id → 预设 × 宽度档清单
├── spec.gd                   规格域：建筑类型预设（数据 Dictionary）
├── layout/solver.gd          布局域：spec+宽度 → 体量/开间/构件摆放 + 元数据
├── draw/                     绘制域：风格化绘图原语（无建筑知识）
│   ├── ink.gd                墨线（抖动、变宽、出头、圆头）
│   ├── fills.gd              填充（cel 色块面、笔触纹理、排线）
│   ├── texture_bank.gd       笔触纹理库（CPU 烘一次：排线/干刷/噪点/瓦鳞）
│   └── painter.gd            画笔上下文（把 ink+fills+纹理库包成一套 API）
├── comps/                    构件库：建筑知识全部在这里
│   ├── wall.gd  roof.gd  openings.gd（门/窗） props.gd（烟囱/招牌/棚架…）
├── render/canvas.gd          渲染域：SubViewport + 纸纹后处理 → PNG
└── accept/sheet.gd           验收拼页（全产物一页浏览）

产物：
stick-world/assets/buildings/gen/<def_id>/<def_id>_w<W>.png     （2x 渲染，运行时 1x 显示）
stick-world/assets/buildings/gen/<def_id>/<def_id>_w<W>.json    （布局元数据）
```

数据流：`spec（类型预设）+ width_cells + seed → layout.solver 求解出构件放置清单 → comps 逐构件调 painter 绘制 → render 输出 PNG+JSON`。

### 确定性纪律

- 全管线只允许从 `(def_id, width_cells, seed)` 派生随机流（每构件独立子流，构件顺序稳定），同输入双跑产物逐字节一致（验收脚本 diff 校验）。
- 禁止使用全局时间/全局随机数。

### 环境红线（继承自已验证的渲染事实）

- **Polygon2D / draw_polygon 带 UV 的纹理采样在本机坍缩为平均色**——多边形只画**纯色**（cel 档色），任何纹理一律走 `draw_texture_rect`（Sprite 同款采样路径）或 Sprite2D。
- 渲染域需要 GPU，**不能 headless**：`godot --script` 弹窗短暂运行（与 tools/baking 现有验收脚本同模式）。

## 三、开间（bay）参数化——宽度可变的核心机制

**不用"拉伸模型"**（左固定+右固定+中间拉伸会把中段纹理和窗距拉变形，与手绘感冲突），改用**建筑学的开间体系**：

- 一栋建筑 = `左端件 + N 个中段开间 + 右端件`（+ 可选附体：门廊/棚屋/烟囱/招牌）。
- **开间是固定宽度的完整单元**（宽 2~4 格，含自己的墙段+门窗变体+独立抖动），宽度变化 = **开间数变化**，永远不拉伸任何纹理。
- 求解规则（layout/solver）：
  1. 目标宽 `W` 格，减去左右端件（各 1 格）得中段宽 `W-2`；
  2. 按建筑预设的开间宽档（如民居 2 格/开间）取 `N = max(1, (W-2) / bay_w)`，余数分摊给端件或尾开间（整格分配，不产生半格）；
  3. 每开间从预设的开间变体池中按子 seed 抽样（窗/门/盲墙/木骨填充），保证相邻不重复。
- 下限 3 格 = 端件×2 + 1 开间；上限 16 格同理自洽，无需特判。
- **最小宽度由预设声明**（如铁匠铺要求 ≥6 格才放得下宽棚），solver 校验 `(def_id, W)` 合法性，产出物 JSON 带 `ok: false` 拒绝非法组合。

多楼体量（如 L 形、主楼+副楼）= 同图内多个体量段并排/前后错位，每段独立走开间求解。

## 四、笔触手绘风格基线

风格基线取自 founder 提供的参考图 `stick-world/assets/_raw/建筑/smithy.png`（铁匠铺 Lv1~4 四宫格：茅草棚 → 木屋 → 石砌 → 砖石行会）。目标语言：**干净深褐墨线 + 块面 cel 阴影 + 实材质质感**，色彩高饱和暖调（茅草金黄 / 红棕木 / 亮灰石 / 红砖白饰）。

### 4.1 墨线（draw/ink.gd）

| 参数 | 值（@1x） | 说明 |
|---|---|---|
| 基色 | `#241a12`（深褐墨） | 全库统一 |
| 基准宽 | 2.0~3.4px 按构件层级 | 外轮廓 > 构件分界 > 内部细节 |
| 抖动 | 幅度 0.75px、波长 40px | 参考图线条干净但手绘，抖动克制 |
| 变宽 | ±32% 沿线渐变 | 分段 polyline 逐段调 width |
| 出头 | 转角/交叉处延伸 2.4px | 手绘感来源 |
| 端头 | 圆头（逐段 draw_line + 端点圆） | |

### 4.2 色彩与填充（draw/fills.gd）

- **cel 四档**：每材质（茅草/干草/暖木/深木/木骨/抹灰/草泥/石/亮石/深石/红砖/白石饰/石板瓦/红瓦/铁/红布/金）定义 `shadow / base / lit / highlight`。左上光源。
- **块面**：`draw_colored_polygon` 纯色（规避 UV 红线）。
- **笔触质感**：texture_bank 预烘可平铺小纹理（CPU Image，一次性）：
  - `wood_grain`（纵向木纹+板缝）、`plank`、`stone_block`（大块石+勾缝）、`stone_courses`、`brick`（砖缝）、`slate`（板瓦横排）、`tile`（红瓦垄）、`thatch`（茅草斜束+压束线）、`hatch`（斜排线）、`dry_brush`（干刷横纹）、`plaster_noise`、`paper`
- 填充 = 块面 + 材质质感纹理平铺（或仿射贴到平/斜坡面）。

### 4.3 全图后处理（render/canvas.gd）

1. 纸纹 multiply；
2. 整体色温轻微偏暖；
3. 底边接地投影（一笔椭圆横影，宽≈建筑宽 90%，透明度 18%）；
4. 2x 渲染，输出 PNG 由运行时 1x 缩放显示（缩放抗锯齿）。

### 4.4 透视与构图

纯正面立面（无透视灭点），微规则允许：屋顶坡面、雨棚、悬挑可用 5°~10° 的准轴测倾斜表达进深；底部统一落在 baseline（图内 `y = H - 8px@1x` 预留投影带）。

## 五、产物契约（运行时消费）

### 5.1 PNG

- 路径 `assets/buildings/gen/<def_id>/<def_id>_w<W>.png`，`<W>` 为格数（3~16）。
- 2x 分辨率烘焙（1 格 = 64px 渲染），运行时 `scale = 0.5` 显示。

### 5.2 布局元数据 JSON（同路径同名）

```json
{
  "def_id": "smithy_lv1",
  "width_cells": 16,
  "px": {"w": 1024, "h": 800, "scale": 2, "baseline_y": 784},
  "barrier": {"x": 64, "y": 400, "w": 896, "h": 384},
  "front_wall": {"x": 64, "y": 400, "w": 896, "h": 384},
  "interact_cells": {"from": 1, "to": 15},
  "workslots": [{"id": "anvil", "x": 320, "y": 740}],
  "can_stand_on": false,
  "wall_tier": 0
}
```

坐标均为**图内 1x 局部坐标**（原点=图左上角）。运行时装配（重写后的 `modules/building_gen`）据此前景/内饰分层：

- 外观 Sprite2D（本 PNG）在 `Exterior` 层；`interior_mode=1` 的建筑另烘一张同尺寸**内饰图**（同管线同 seed，绘开间内的室内视角），垫在外观下，玩家进交互区时外观 alpha → 0.3 露出。
- `barrier` → PassageBarrier 矩形；`workslots` → WorkSlot 节点；`front_wall` 供交互判定与近墙透明化；`interact_cells` 对齐"横向中间 (width-2) 格"既有规则。

### 5.3 运行时接入（后续批次）

- `modules/building_gen/api.gd` 的 `_BUILDING_SCENE_PATHS` 重定向到新装配器生成的场景：根 `Building` 脚本契约（`scripts/building.gd` 的字段与分组）保持不变，攻城/职业/建造消费方零改动。
- 宽度取用：玩家建造用 def 的 `width`；城镇生成落位宽度（house 3~4、landmark 6~8）直接命中已烘宽度档，未烘焙的宽度档由 gen 入口按需补烘。

## 八、高度基准与质感规格（第二轮定稿）

### 8.1 高度基准：对标火柴人身高

**火柴人身高 130px ≈ 4 格**（命中盒 131.25px，见 `units/scripts/weapons/arrow_projectile.gd:23`）。所有建筑高度以此为基准标定，禁止再出现"火柴人比房子高"的比例失调：

| 构件 | 高度（1x px） | 折合身高 |
|---|---|---|
| 单层层高 | 120~140 | ≈1.0 |
| 屋顶 rise（民居/街屋） | 76~100 | 0.6~0.8 |
| 铁匠铺棚柱高 | 150~210 | 1.2~1.6 |
| 谷仓（大坡顶） | 150 + 150 | 2.3 |
| 城墙段（tier3 高墙） | 192 | 1.5 |
| 城内背景高墙（城市档） | 460 | 3.5 |
| 教堂钟楼（中殿 260 + 塔身 150 + 尖顶 130） | 540 | 4.2 |
| 瞭望塔 | 400 | 3.1 |

**层数上限由材质决定**（`docs/设计/系统/03-定居点与建筑.md:23-29`）：稻草 1 层 / 木板 2 层 / 石头 3 层 / 砖 4 层。spec 里的 `stories` 必须遵守。

### 8.2 质感规格（对齐 3D 材质球精度）

平铺周期 **128px**（4 格），渲染 **4x**（1 格 = 128px 屏幕像素），纹理内容按"近景可见单像素笔触"标准绘制：

| 纹理 | 精度要点 |
|---|---|
| `straw` / `thatch` | **单像素草茎**：每根 1px 宽、5~20px 长、带弯曲与逐像素渐变；分上下两层（下层深、上层亮）形成层叠遮挡；茅草另有横向压束线 |
| `brick` | **做旧砖**：每块砖独立尺寸（16~27 × 9~13）与色偏；**缺角**（随机挖角）；灰缝宽窄不均；顶部受光亮线/底部压暗；大尺度污渍 + 霉斑 + 苔点 |
| `stone` / `stone_light` / `stone_dark` | **不规则石块**：每块角部随机内缩成不规则轮廓；每块独立色偏；风化（顶亮底暗、裂纹）；苔藓簇 |
| `wood_grain` / `plank` | 纵向纤维（每 2~4px 一条、扭曲断裂）、结节同心椭圆、板缝倒角亮线、裂纹 |
| `slate` / `tile` | 每片瓦独立色偏，瓦垄弧形（红瓦在瓦面加高光条），瓦下缘阴影，苔/水渍 |
| `grass` | **草簇**：约 320 簇 × 每簇 6~14 根 1px 草叶，颜色深绿→黄绿渐变；土壤底 + 枯草点 |
| `dirt` / `cobble` | 泥土：颗粒 + 小石（带亮顶暗底）+ 车辙；石板路：不规则石块铺装 + 磨损 + 缝隙积灰 |

墨线同步细化：基准宽 1.4~2.6px（原 1.8~3.4 的 0.78 倍），抖动 0.65px / 波长 46px，出头 2.0px。

### 8.3 材质 × 功能搭配案例（正交设计）

材质决定外观、功能决定模块，二者自由组合（`docs/技术/架构/建筑模块化设计.md:514-528`）。本管线的搭配案例：

| 功能（模块语义） | 低配 | 中配 | 高配 | 豪华 |
|---|---|---|---|---|
| 锻造 | `smithy1` 茅草棚（柱撑开放） | `smithy2` 木屋工坊 | `smithy3` 石砌工坊 | `smithy4` 砖石行会（白饰+瓦棚） |
| 居住 | `cottage` 茅草农舍 | `house` 抹灰民居 | `townhouse` 木骨悬挑街屋 | `stone_upper` 石基木楼 / `plaster_house` |
| 商业 | `market_stall` 麻布摊 | `shop` 木棚商铺 | `tavern` 酒馆（招牌+灯笼） | `guildhall` 行会馆（钟+旗） |
| 信仰 | `chapel` 小礼拜堂 | `church` 教堂 | — | — |
| 生产 | `shelter` 草棚 | `stable` 马厩 | `barn` 谷仓 / `windmill` 风车磨坊 | — |
| 防御 | `wall_seg`(tier1/2/3) | `tower` 瞭望塔 | `gatehouse` 城门楼 | `lighthouse` 灯塔 |

**组合形态**（`docs/设计/系统/03-定居点与建筑.md:140-154`）：
- **叠加**：一层石砌 + 二层草棚/木骨（`stone_upper`）——低级层承载高级层。
- **桥接（分裂 + 天桥）**：两翼单体（可不同材质）+ 中间天桥，桥下可通行（`bridge_house`，meta 输出 `barriers` 多条障碍矩形）。
- **外挂**：外楼梯（`extras: stairs`）、悬挑（`jetty`）、雨棚（`awning`）、招牌/灯笼/旗/钟。

### 9.2 布局算法

从**市中心**向两侧交替展开，按功能区配比取建筑（避免同型连排）：`核心（市政厅/教堂/礼拜堂）→ 市场（酒馆/面包房/商铺/摊/井）→ 工匠（铁匠铺/马厩/石基木楼）→ 居住（民居/街屋）→ 生产（谷仓/风车/草棚）`。产出可序列化的城市布局（供 批次 4 城镇生成管线对接）。
