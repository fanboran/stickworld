## 二、为什么升级（现行架构的两个"非行业实践"病灶）

现行管线在**图像域**做分档和描边（渲染出灰度图后，用 k-means 聚类切三档、用 alpha 阈值+腐蚀找环描边）。这是被反馈追着打补丁的位置：

1. **图像域 k-means 分档**（`compose_icon_small_ui.py` 的拉伸+聚类段）：
   - 分档切在**直方图结构**上而非**3D 形体**上 → 档位边界会随光照漂移，惹出过「椅子糊成剪影」「罗盘盘面噪声劈簇」「Cube 棱变独立色」一系列病，补了采样域腐蚀、p5/p98 拉伸、单面退化保护三层补丁。
   - 行业标准：分档发生在**着色器**（toon ramp / shader-to-RGB），明度断点跟着形体法线走，图像域只负责上色和导出。
2. **图像域描边**（alpha 阈值+MinFilter 腐蚀找环）：
   - 本质是从 mask 的实心区向内画一圈，永远画不出「骑在轮廓上」的线（main `739af76e` 把基线从 alpha>128 挪到 alpha>16 缓解了内缩，但 1px 硬限还在：线宽无法亚像素、高斯 0.6 的糊是模拟而非真 AA）。
   - 行业标准（3D 渲染域）：**反向壳（inverted hull）描边**—— mesh 沿法线膨胀一个壳、翻转法线、纯墨色材质、只渲染背面。线宽由壳的膨胀量在屏幕空间控制，引擎 MSAA/AA 白送，线条质量超过任何图像域合成。

## 三、方案定稿（做什么、怎么做、为什么这么做）

### D. 着色器分档（先做，C 依赖它的输出语义）

1. **渲染端**：`gen_motifs.py` 的 shade pass 弃用「白模受光→图像域聚类」，改用**toon 材质**：
   - 材质节点：`ShaderNodeBsdfDiffuse` → `ShaderNodeMapRange`（或 ColorRamp，5.2 节点输入一律**索引访问+try/except 探测**，见现行管线教训）量化光照为 N 档（默认 3 档，参数 `TOON_STEPS` 环境变量）。
   - **平面物体**（现走 `bake_flat_faces` 面烘色的）保留面烘色语义：面烘色本来就是在渲染端定「一面一色」，D 之后它是 toon 材质的**输入**（顶点色直接乘 ramp 输出），不再需要图像域直方图分档兜底。
   - **曲面物体**（球/胶囊/环/管）： diffuse 光照直接进 ramp，断点建议 `0.35/0.70`（与现行 k-means 三簇均值对齐，先复刻现有观感再谈调优）。
   - 输出语义约定：**shade pass 渲出来的就是最终 cel 灰阶**（三档灰 0.32/0.62/0.92 或对应色带亮度），compose 不再拉伸、不再聚类。
2. **compose 端**：删掉采样域/明度拉伸/k-means/单面退化整段，改为**直接按灰阶查表映射色带**（`RAMPS[pid][band]`，band=灰阶档位查表）。`NO_STRETCH` 豁免表逻辑随之退役——所有图标走同一条 toon 路径。
3. **ID pass 不动**（材质 ID 锁色的机制保留，它是行业实践）。

### C. 反向壳描边（后做）

1. **渲染端**（`gen_motifs.py`，每个母题 build 之后、渲染之前）：
   - 对场景每个 mesh 物体生成壳：复制 mesh → `SOLIDIFY` 修改器（`thickness`=线宽（世界单位，起始值按 64px 图标线宽 ≈ ortho_scale×1.2/64 估算，需实测定）→ `offset=-1`（沿法线向外——Blender 的 Solidify 负 offset 即向外膨胀）→ `flip`（法线翻转）。
   - 壳材质：纯墨色 emission（INK=(18,14,9)），`use_backface_culling=True` 只渲背面（即只露出轮廓外的壳部分）。
   - **壳物体不带 pid、不进 ID pass**（ID pass 前隐藏壳集合，ID 渲完再显示）。
   - **ID 结合缝线保留图像域画法**（现行 `idedge` 段）：部件间缝线是 2D 拼版概念，反向壳只管外轮廓。
2. **compose 端**：删掉外轮廓环段（`vis/ero_vis/ring` 的外轮廓部分），保留 ID 缝线段+居中+导出。壳的 AA 由渲染端 MSAA 白送。
3. **两档线宽**：64px 一档、128/256 一档（现行为），壳厚度按渲染分辨率参数化（`gen_motifs.py` 逐尺寸渲染时给不同 thickness）。

### 顺序与回滚

**先 D 后 C**（D 改变 shade 图语义，C 只动描边）。每步用 git tag 标记：`v2-d-done`、`v2-c-done`。任一步观感不满意可整步回退到 tag，`main` 的现行管线始终可用（分支合并不受影响）。

## 六、风险与已知坑（从现行管线教训直接继承）

- **5.2 API 漂移**：节点/枚举输入一律索引访问+try/except 探测（Base Color→inputs[0] 等）；Solidify 节点若不可用则用 bmesh 手工偏移（备选路径写代码时留 try 分支）。
- **`materials.clear()` 钳零**：壳物体复制后 material_index 可能失效——壳是单材质无所谓，但原物体恢复槽位时必须按法线重指派（现行 `fix_head_faces` 逻辑保留）。
- **黑脸根因**：读 `cam.matrix_world` 前必须 `view_layer.update()`。
- **软 alpha 语义变化**：现行「边缘环填部件色」（防 BOX 混黑底）在 C 落地后**仍需保留**——壳描边改变了边缘 alpha 的构成但 BOX 缩放混底问题依旧存在。删这段前必须做黑边专项检查（深色底图上放成品图目检）。
- **壳与 mask 的轮廓差**：壳膨胀是 3D 等距、屏幕空间线宽在斜视角会有 ±10% 变化（正交相机下均匀，本项目相机全正交，风险低）——accept_sheet 的贴边数值体检能兜住超界。
- **逐字节承诺**：本分支合并即打破豁免 6 枚的逐字节承诺（架构换代不可避免）。留 `temp/baseline_v1/` + accept_sheet 前后对照页给创始人过目，页面里明确标注「v1/v2 对比」。
