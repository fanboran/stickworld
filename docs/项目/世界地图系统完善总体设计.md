## 〇、目的与范围

本文档统筹「世界地图系统完善」这一跨系统工程的**总体架构与分期计划**，把散落在 GDD / 程序化生成 / 战略图架构 / 场景图旅行四处的既有设计串成一条可实施的链路。范围覆盖：

- 战略图观感修复（毛刺、UI 设计语言）
- 地形图（默认模式）+ 群系 + 河流
- 玩家位置指示、城市规模表现
- 聚落进城闭环（0.9b）、道路生成、步行/快速旅行
- 全大陆政权简化版（政治图）

不在本轮范围：动态聚落建筑群渲染（进城后由场景图承担）、拼接预览、LOD 分级、联盟/外交、扩张系统运行期对接。

```
┌────────────────────────────────────────────────────────────────┐
│ 生成端（开发期 Python，tools/worldgen/，一次性，产物随包发布）    │
│                                                                │
│  fractal_continent.py ──→ 高度场/河流/湖泊（已有）              │
│  biome_generate.py  ★新 → Whittaker 温湿 → 群系标签图（七群系） │
│  state_expand_lite.py ★新 → 文化圈 flood-fill → 城市归属       │
│  road_generate.py   ★新 → MST + A*(坡度cost) → 道路折线        │
│  terrain_render.py  ★新 → 程序着色地形底图 PNG（分层色+山影）   │
│  settlement_mapgen.py 补完 → 8 城邦场景图 .tscn + map_id 回填  │
│  export_*_view.py   扩展 → 上述新数据进 L3/L2/L1 视图包         │
└──────────────────────────┬─────────────────────────────────────┘
                           ▼  config/strategic_map/（JSON+bin+PNG）
┌────────────────────────────────────────────────────────────────┐
│ 消费端（运行时 GDScript，modules/world_map/）                    │
│                                                                │
│  渲染：烘焙描边（l1_geom.bin 补齐）+ 地形底图 + 河流/道路叠加    │
│        + 政治着色 + 城市 blob + 玩家图钉                        │
│  模式：MapModeManager 实装（TERRAIN 默认 / POLITICAL）          │
│  交互：点击聚落 → 旅行弹窗（走过去/快速旅行）→ travel_requested │
└──────────────────────────┬─────────────────────────────────────┘
                           ▼  EventBus
┌────────────────────────────────────────────────────────────────┐
│ 场景图（modules/world/）                                        │
│  SceneLoader.travel_to_map：聚落场景（0.9b 产物）/ 道路场景     │
│  道路场景生成器 ★新：按路长+地形参数产横向卷轴道路图（seed 确定）│
```

**模块边界约束**（沿用架构原则）：
- world_map 不做场景图生成；场景图内容（建筑群/道路场景）由生成端工具 + scene_loader 侧承担
- 所有跨模块交互走 EventBus / 模块 api.gd，禁止跨模块 get_node
- 生成端→消费端只通过 `config/strategic_map/` 文件契约（沿用现有视图包机制）

## 五、关键技术方案

### 5.1 描边烘焙与毛刺根除

**根因**（现状）：L1 `map_renderer.gd` 运行时逐地块逐边生成描边段——相邻地块公共边被画两次，两条抗锯齿线的半透明边缘叠加成深色毛边；且不做共线段合并，像素台阶多边形直接输出锯齿。L3 地区边界 `draw_polyline` 同理双描。

**方案**：照搬 L2 已验证管线（`l2_export/l2_bake.py` + `l2_world_data.gd` 解析 `l2_geom.bin`）：
1. 素材阶段：金标准多边形（mesh_extract 共享网格提取）→ Chaikin×3 平滑（保留 ≥3px 真实尖角）→ DP(tol=0.2) 降顶点 → **填充与描边同源**（Hausdorff=0，无补丁感）
2. 描边段**合并共线段**，相邻多边形共享边只输出一次（拓扑去重）
3. 烘焙为 `l1_geom.bin`（magic 风格与 l2/l3 一致），运行时 `draw_multiline` 单次输出，零剖分零逐边计算
4. L1 顶点序 `[x,y]` 与 L2/L3 `[y,x]` 的不一致在烘焙时统一（bin 内一律 Vector2(x,y)）

### 5.2 群系生成（Whittaker 温湿矩阵）

新工具 `tools/worldgen/l3/biome_generate.py`，输入高度场 + 大陆掩码 + 纬度：

```
temperature(px) = base(纬度梯度：北极→赤道) + fBm 噪声(幅度±) − 海拔递减(高山更冷)
precipitation(px) = simplex 噪声 + 海洋邻近加成(EDT 离海距离衰减) − 雨影(可选, 山背风面)
```

温湿 → 群系映射（对齐 GDD §五 七群系）：

| 群系 | 温度 | 降水 | 备注 |
|------|------|------|------|
| 冰原（雪地） | 低 | 任意 | 高山顶部同映射为冰雪 |
| 荒漠 | 高 | 低 | |
| 平原（草原） | 中 | 中低 | 默认出生群系 |
| 森林 | 中 | 高 | |
| 源流 | — | — | 河流/湖泊沿岸带，从 river_mask 派生 |
| 火山 | — | — | **非气候群系**：独立放置——高海拔 + 低频噪声热点 + 距出生点下限，程序撒 N 个火山区（中心 + 蚀变半径） |
| 海洋 | — | — | 掩码外 |

产出：`biome_labels_2048.npy` + 彩色预览 PNG（人工验收分布自然度，参数表 `biome_params.json` 可调）。

**质量门槛**：出生地区必须为平原群系（违则调噪声种子/偏置直至满足——出生规格 §0.16 的落地）。

### 5.3 地形底图程序着色

新工具 `tools/worldgen/l3/terrain_render.py`，输入：高度场 + 群系标签 + 河流/湖泊 mask：

1. **群系基色**：每像素按群系标签取基色（色板对齐 UI 语义色体系，草原绿、冰原白、荒漠土黄、森林深绿…）
2. **高度调制**：群系基色 × 高度明度曲线（山地上层偏灰白岩石、山顶雪线）
3. **山体阴影（hillshade）**：高度场梯度光照（西北 45° 光源），multiply 0.85-1.15——零贴图获得立体感，这是「哪里是山」一眼可辨的关键
4. **水体**：河流按宽度画深浅蓝折线（宽度=四次根流量×k，沿用生成端现公式），湖泊浅蓝，海洋离岸渐变深蓝
5. **海岸线**：EDT 等值线 1px 深色描边
6. 输出：L3 全图 2048（`l3_terrain.png`）+ L2 每地区裁切（`l2_packs/region_XXX/l2_terrain.png`）。分辨率按「全屏观看无像素块」原则（L3 2048 起，不足再升 4096）

渲染端：各层级渲染器增加「地形底图层」（`draw_texture`，与现有城市栅格模式同管线），描边/交互层叠加其上。

### 5.4 河流显示

- 数据：`river_paths.json`（2048 坐标折线，已有）随视图包导出；L2/L1 包按 `world_bounds` 裁切
- 渲染：L3/L2 用底图内预渲染河流（§5.3 第 4 步，性能零成本）；L1（矢量图无底图时）运行时 `draw_polyline` 叠加，宽度随流量、颜色深蓝→浅蓝
- 湖泊：沿用现有 `lakes` 多边形渲染，色值与底图统一

### 5.5 地图模式系统

实装 `map_mode_manager.gd`（现有文件为设计稿，按此激活）：

### 5.7 城市团块（卫星图式覆盖）

**模型**：城市建成区 = 以聚落中心为核的不规则团块，半径 `R = f(level, population_score)`（映射表见下），形状由极坐标扰动生成：

```
blob(θ) = R × (1 + Σ ak·sin(kθ + φk))    # 3-5 个谐波，ak 递减，φ 由 settlement_id 种子确定
栅格化 → 形态学平滑（闭运算去毛刺） → 轮廓提取 → PackedVector2Array
```

| 级别 | 基准半径（地图 px，L1 视图） | L2/L3 表现 |
|------|------------------------------|-----------|
| T1 村落 | 12-20 | 单像素点/不画 |
| T2 镇 | 25-40 | 小点 |
| T3 城市 | 50-90 | 明显团块 |
| T4 中心城市 | 100-150 | 大团块 + 白描边 |
| T5 首都 | 150-220 | 最大团块 + 特殊描边 |

- **确定性**：谐波相位由 settlement_id 种子确定，同一城市每次渲染一致
- **实时变动**：population_score 变化（建设/扰动）→ 重算 R → 重生成 blob（EventBus `settlement_updated` 触发局部重绘）
- **语义区分**：行政区划多边形（城市领地边界，描边）与建成区团块（实际覆盖面积，填充）是两层，叠加显示
- **生成时机**：谐波参数运行时计算即可（每城市一次三角剖分缓存，数百城规模无压力）；团块不落盘、不进视图包

### 5.9 道路生成（几何）

新工具 `tools/worldgen/l1/road_generate.py`：

1. **图构建**：节点=聚落中心（同 L1 图内 MST 已有连接对为骨架）；跨 L1 主路 = 相邻 L1 的最近聚落对 + 重镇（T3+）间补边
2. **路径搜索**：A* on 高度场网格（降采样至 1024 计算），cost = `1 + 坡度惩罚×|∇h| + 河流惩罚（无桥）`；**山口豁免**：预检测山脊局部低点（沿两城连线方向的鞍点），路径 cost 减免——实现「经山口穿山不在山顶硬穿」
3. **后处理**：路径折线 Chaikin 平滑 ×2（自然弯曲）+ DP 简化；每条路记录 `{from, to, polyline[], tier(DIRT/PAVED/HIGHWAY), length_px}`
4. 产出进视图包：`l1_world.json` 的 roads 扩展为完整结构（向后兼容：无 polyline 时回退直线连线）

分级：MST=土路；T3+ 聚落对+都城方向=官道（PAVED）；tier 影响渲染样式与道路场景参数。

### 5.10 旅行（步行 + 快速旅行）

**交互流**（战略图点击聚落）：

```
点击可达聚落 → 弹窗[走过去 | 快速旅行 | 取消]
  ├─ 走过去：travel_requested(道路场景 id) → 道路场景生成器（§下）→ 端点到达 → 进目标聚落
  ├─ 快速旅行：导航路径高亮（途经聚落/地区依次描边）→ 过场（行进中 UI）→
  │            time_manager 消耗（游戏时间 ∝ 路径长 × 道路 tier 速度）→ 直达目标聚落
  └─ 可达性：目标在当前聚落的路网连通分量内（BFS 图查询）；不可达时按钮置灰并提示
```

- **快速旅行距离规则**（创始人输入的落地）：可达性 = 路网连通即可，不限单跳相邻；长距离自动显示导航路径让玩家看到途经节点；时间消耗随距离增长约束滥用
- **战斗中禁止**：沿用 GDD 约定（battle_active 时弹窗禁用）

**道路场景生成器**（场景图侧新组件 `road_map_generator.gd`）：

- 输入：道路数据（polyline、length_px、tier、两端聚落）+ 沿线群系采样（地形图上按 polyline 逐点取群系）
- 输出：横向卷轴 RoadMap 场景，宽度 = `length_px × 比例系数`（系数表：1 地图 px = N 场景格；官道更短——玩家体感「大路好走」）
- 内容：地面带按沿线群系切换色（草原段/雪原段/荒漠段）、装饰物密度按 tier、两端出口 ChunkTrigger → 端点聚落 map_id
- **确定性**：road_id 作种子，同一条路每次生成一致；首游生成后缓存实例（不落盘，会话内复用）

### 5.11 政权简化版

新工具 `tools/worldgen/l3/state_expand_lite.py`（§十五子集）：

```
1. 文化圈：撒种子点（数量 ≈ 目标国家数×1.5）→ flood-fill（cost = 距离 + 地形难度(坡度/河流)）
   → 文化标签图 culture_labels（同文化 = 后续联盟候选，本轮只存字段）
2. 都城：每文化圈取人口最高 T3+ 城为都城（人口 = population_score 代理）
3. 扩张：每都城 Dijkstra flood-fill（cost = 距离 + 地形 + 文化摩擦 + 贫瘠惩罚），
   遇他国已占即停 → 每城归属 state_id
4. 碎度：出生地区种子加密（保持 8 城邦现状不动）；单国城市数硬 cap（防巨无霸）
5. 产出 political_data.json：{states:{id:{name,capital,culture,alliance:null}}, city_owners:{city_id:state_id}}
   — 字段结构按完整版设计，alliance/后处理切分留空待后续迭代
```

政权色表：程序生成（HSL 黄金角分布保色相分离），存入 `political_data.json`，L1 现有 8 城邦色保持不变。

## 八、风险与开放问题

| 风险 | 缓解 |
|------|------|
| Whittaker 参数定标（群系分布可能不自然，如荒漠过多/冰原越界） | `biome_params.json` 参数外置 + 彩色预览图人工验收循环；出生地区平原作为硬验收项 |
| 火山放置与出生地区冲突 | 距出生点下限约束 + 预览验收 |
| 道路 A* 在 1024 网格全大陆规模耗时 | 只算 L1 内 + 相邻 L1 边界对（不全域），分块跑；工具一次性离线，无运行时压力 |
| blob 与行政区划视觉混淆 | 两层显式分离：领地=描边多边形，建成区=填充团块（色/透明度区分）+ 图例说明 |
| 快速旅行破坏节奏（无成本传送感） | 时间消耗 ∝ 距离 + 战斗中禁用 + 途经路径强制可视化 |
| settlement_mapgen 产 .tscn 的结构漂移（与手工 VillageMap 不一致） | 复用同一 base 场景实例化参数，不另起结构；验收对照 village_a |

**开放问题**（实施中确认，不阻塞开工）：
- 道路场景宽度比例系数（1 地图 px = N 场景格）——E4 时实测手感定标
- 官道（PAVED）覆盖哪些聚落对——E1 时按 T3+ 密度调参
- 出生 L1 内 8 城邦是否接入全大陆政权数据（现状独立城邦不受 F 期影响，维持不变）
